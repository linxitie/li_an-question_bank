# 前端视图双轴目录

```
views/<角色>/<设备>/
```

**两个轴彼此正交，不可互相替代。**

## 角色轴

| 目录 | 归属 | 当前状态 |
|---|---|---|
| `student/` | 学生端 | P3A.2 起逐步迁入 |
| `teacher/` | 教师端 | **空目录**，为后续手写页预留 |
| `admin/` | 管理端 | **空目录**，为后续手写页预留 |
| `system/` | 系统级页面（404 / 401 / 帮助 / 反馈） | 待迁入 |

`teacher/` 与 `admin/` 目前为空是**有意为之**：这两端的全部页面
（`teacher_*` 8 个、`admin_*` 11 个）当前都在冻结区 `.vtj/vue/`，`src/` 中一个都没有。
不预留入口，届时这些页面将无处安放。

## 设备轴

| 目录 | 用途 |
|---|---|
| `shared/` | 三端共用的同一份组件 |
| `pc/` | PC 专属 |
| `tablet/` | 平板专属 |
| `mobile/` | 手机专属 |

**`shared` 不是「默认兜底」**，是「确实三端通用」。设备差异应优先用响应式与
`resolveDevicePath()` 表达，而不是复制出多份页面。

## 红线（AGENTS.md R5 / R12）

- `mobile_*`、`tablet_*` 文件名前缀**不重命名** —— 它与 `.vtj/vue/` 一一对应，
  是建立对照关系的唯一线索
- `/tablet/` 路由中部分直接复用 `@/views/mobile_*.vue`，经 `meta.platform` 区分设备。
  **不为平板新建手机页的重复副本** —— 那会制造双份维护成本
- `.vtj/` 全目录冻结：`src/router/index.ts` 有 **92 处** `import('$vtj/vue/<id>.vue')` 硬绑定，
  移动/改名/删除会直接导致 404 并使 VTJ 设计器失效

## 迁移约定

现有 27 个 `.vue` 平铺在 `views/` 根目录。迁移时：

1. 按角色归入对应目录 —— 现有页面**均为学生端**，故入 `student/`
2. 按设备归入 `mobile/` 或 `pc/`；无设备专用变体的入 `shared/`
3. 每迁一批必须跑 `npm run build`，并核对 `src/router/index.ts` 的引用未断
