# 每日抓取定时任务诊断与修复

> 日期：2026-11-16  
> 范围：每日金句、每日新闻、招考信息

## 诊断结果

### 1. 金句：没有每日定时任务

原 `scheduler.py` 没有 `collect_external_quotes` 的 `add_job`，只有手动 CLI：

```text
python -m scripts.quotes.collect_external
```

另外，`quote_external_collector.py` 自身有两个历史问题：

- 导入不存在的 `QuoteTag` / `QuoteRelation` 模型；
- 构造 `EssayQuote` 时传入了不存在的 `ai_quality` 字段。

因此即使手动执行也无法插入数据。

### 2. 新闻：任务存在，但被系统睡眠错过

原任务：

```text
每日 08:00 / 18:00
```

日志显示 2026-11-15 18:00 的任务在 18:56 才被唤醒，并因为：

```text
misfire_grace_time = 300 秒
```

被直接丢弃。机器睡眠期间 APScheduler 不会执行任务。

### 3. 招考：定时任务已换成官方源，但启动补跑仍调用旧爬虫

定时任务 `_recruitment_with_broadcast` 使用：

```text
recruitment_source_collector.py
```

启动补跑 `_initial_run` 却仍调用旧的：

```text
recruitment_scraper.scrape_all_recruitment()
```

旧源 `rszk.net` 多个分类返回 404，导致启动日志看起来“抓取成功 0 条”。

## 已修复

1. 新增每日 07:00 金句采集任务 `collect_quotes_7`；
2. 金句采集完成后自动导出到 `VAULT_PATH_QUOTE`；
3. 新闻采集完成后自动导出到 `VAULT_PATH_NEWS`；
4. 修正 `quote_external_collector` 的模型导入和字段；
5. 启动补跑改为调用官方招考来源采集器；
6. APScheduler 默认改为：

```text
misfire_grace_time=None
coalesce=True
max_instances=1
```

电脑睡眠后只补跑最近一次，不丢弃整次任务。
