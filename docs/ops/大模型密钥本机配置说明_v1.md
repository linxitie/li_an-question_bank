## 1. 唯一配置位置

```
backend/.env
```

| 变量 | 作用 | 说明 |
|---|---|---|
| `LLM_API_KEY` | 大模型密钥 | 必填；兼容旧名 `DEEPSEEK_API_KEY` |
| `LLM_API_URL` | 服务地址 | 默认 `https://api.deepseek.com/v1`（配基址或完整 `/chat/completions` 均可） |
| `LLM_MODEL` | 模型名 | 默认 `deepseek-chat` |
| `LLM_TIMEOUT` | 超时秒数 | 默认 90 |

- 读取实现：`backend/app/core/config.py`（`env_file` 依次为 `backend/.env`、仓库根 `.env`）；
- 仓库根 `.env` 为历史兼容位置，检测到会启动告警一次；
- `.gitignore:142` 已忽略 `backend/.env`，**不会进 Git**；模板见 `backend/.env.example`（`**/.env.example` 按项目规矩同样不入库）。

## 2. 配置后怎么验证（不打印密钥）

```powershell
# 1) 自检字段（只回布尔与来源名）
curl.exe -s http://127.0.0.1:8001/health
# 期望：{"llm_configured":true,"env_source":"backend/.env", ...}

# 2) 真实调用（后端已启动时）
cd backend
python -c "import asyncio,sys;sys.path.insert(0,'.');from app.services import llm_client;print(len(asyncio.run(llm_client.chat([{'role':'user','content':'你好'}]))))"
```

> 注意：`llm_client.chat()` 的入参是**消息数组**，不是字符串；传字符串会被上游判 422（本次排查踩过）。

## 3. 哪些功能会用到

学习计划生成、AI 调整计划、能力画像文案、AI 作文批改、联考小智对话、模拟面试出题/追问/评分。

## 4. 轮换流程（怀疑泄露时）

1. 在服务商控制台吊销旧 Key 并生成新 Key；
2. 只改 `backend/.env` 的 `LLM_API_KEY`；
3. 重启后端（`uvicorn`）→ 再跑第 2 节验证；
4. 若新 Key 曾出现在聊天记录/文档/截图中，视为已泄露，**轮换是唯一彻底解法**，改写 Git 历史只是附加项（见 AGENTS.md §5）。
