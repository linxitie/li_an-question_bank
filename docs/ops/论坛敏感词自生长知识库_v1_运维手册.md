# 论坛敏感词自生长知识库 运维手册 v1

> 归档：docs/ops/论坛敏感词自生长知识库_v1_运维手册.md
> 适用：管理员 / 审核运营 / 值班运维

## 1. 入口

| 入口 | 地址 / 路径 | 权限 |
|---|---|---|
| Web 运营台 | http://<后端>:8000/api/v1/admin/content-guard/console | 管理员账号密码登录（role_level >= 2） |
| Obsidian 待审队列 | <仓库>/docs/knowledge-vault/敏感词治理/00-待审队列 | 运营人员 |
| API 文档 | http://<后端>:8000/docs 搜索 content-guard | 管理员 token |
| CLI | backend/scripts/content_guard_cli.py | 服务器本地 |

注意：运营台是后端直接提供的单文件页面，不依赖前端构建；登录 token 只存在浏览器 sessionStorage/localStorage。

## 2. 日常操作

### 2.1 新增 / 调整词条
运营台「词条」页：输入词条、等级、类别、置信度 → 新增；
已有词条可直接改等级并保存（写入 cg_term + 版本号 + 审计）。

### 2.2 处理人工队列
运营台「判定」页 → 详情/复核 → 确认违规 或 判定误判；
误判会降置信度，连续 3 次误判自动生成降级/停用提案。

### 2.3 审批知识提案
「提案」页通过/拒绝；通过即在同事务写入词条或变体、追加审计、热加载 DFA。
Obsidian 中也可以打开待审文件勾选「通过/拒绝」，再执行导入。

### 2.4 Obsidian 工作流
1. 用 Obsidian 打开仓库 docs/knowledge-vault；
2. 进入 敏感词治理/00-待审队列，勾选结论并写备注；
3. 运营台「工具 → 导入审阅」或 CLI import-reviews；
4. 文件移动到 07-归档/YYYY-MM，数据库与审计更新。

### 2.5 红队与对账
- 运营台「工具 → 运行红队」：生成规避样本，漏放写法进入提案；
- 「跨层对账」：词条缺条款、任务/判定/边悬挂、审计链断裂、投影缺失；
- 对账只提案不自动修复，避免误判被固化。

## 3. CLI

在 backend 目录执行：

~~~bash
python scripts/content_guard_cli.py migrate          # 建表 + 补种（等价启动迁移）
python scripts/content_guard_cli.py seed             # 幂等补种
python scripts/content_guard_cli.py stats            # 看板
python scripts/content_guard_cli.py detect "文本"     # 检测（不落判定）
python scripts/content_guard_cli.py redteam --limit 50
python scripts/content_guard_cli.py reconcile
python scripts/content_guard_cli.py verify           # 审计哈希链
python scripts/content_guard_cli.py export --vault D:/obsidian/敏感词治理
python scripts/content_guard_cli.py import-reviews --vault D:/obsidian/敏感词治理
~~~

## 4. 定时任务

每日 03:30（北京时间）执行 content_guard_maintenance：
红队 50 词 → 跨层对账 → 导出 Obsidian。失败仅告警，不影响实时审核。

可在 logs/app.log 搜索「内容安全知识库」。

## 5. 监控指标

| 指标 | 位置 | 建议阈值 |
|---|---|---|
| pending 任务 | /overview pending_tasks | > 200 告警 |
| pending 提案 | /overview pending_proposals | > 100 告警 |
| 红队漏放 | /overview redteam_undetected | 环比突增 50% 复核 |
| 审计链 | /audit/verify | 非 ok 立即中断写入并排查 |
| 今日处置 | /overview today | 异常放量/归零都要看 |

## 6. 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 审核全放行 | cg 表未建 / 词库为空 / 开关关闭 | 看启动日志「内容安全知识库 Schema 就绪」；执行 migrate；检查 CONTENT_GUARD_ENABLED |
| 返回 degraded=true | 表未就绪，已回退旧词表 | 执行 migrate 后重启 |
| 403 | 非管理员或 token 过期 | 用 role_level>=2 账号登录 |
| 改了词条不生效 | 多 worker 尚未感知 | 运营台「热加载词库」；版本号会自动传播 |
| Obsidian 文件被覆盖 | 只读投影被手改 | 待审文件只写一次；只读投影请勿手改，冲突会在对账中报告 |
| 导入无反应 | 没有勾选或勾选多于 1 项 | 每个文件只勾选一项后重试 |
| 审计链断裂 | 有人直接改库 | 立即停止写操作，导出 cg_audit_event 取证，按备份恢复 |

## 7. 备份与回滚

- 备份：按 AGENTS.md R10，使用 sqlite3.backup()，同时处理 -wal/-shm；
- 回滚代码：设置 CONTENT_GUARD_ENABLED=false 即回到旧词表行为；
- 回滚数据：cg_* 表可整表删除，旧词表不受影响；审计事件如已对外取证，先归档再删；
- 恢复后执行 migrate + seed，再 verify 审计链。

## 8. 安全边界

- Agent/服务层无删除词条权限；删除是管理员在运营台标记 deprecated；
- 判定只存 content_hash 与脱敏摘要，原文不落 cg_judgment；
- Obsidian 回写必须经过导入接口，不允许脚本直接改库；
- 审计事件只追加，接口不提供修改/删除。
