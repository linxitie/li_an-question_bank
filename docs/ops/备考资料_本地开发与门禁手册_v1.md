## 1. 本地一键重启（推荐入口）

```powershell
cd C:\Users\35709\OneDrive\Desktop\题库\li_an-question_bank
.\scripts\dev-restart.cmd          # 或： powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\dev-restart.ps1
```

脚本固定 5 步：**杀端口 → 等释放 → 分离启动 → 健康自检 → 打印访问地址**。

| 参数 | 作用 |
|---|---|
| `-SkipFrontend` | 只重启后端 |
| `-SkipBackend` | 只重启前端 |

**它替你做掉的三件容易忘的事**

1. **自动对齐 `DEV_BACKEND_ORIGIN`** —— 脚本按 `$BE_PORT`（现为 8000）推导并注入；端口统一后与 Vite 默认值一致，**不再需要手动指定**。若以后改端口而漏设该变量，Vite 会把 `/api` 代理到 8000，全站接口 404（页面能开、登录必失败）
2. **轮询等端口释放** —— 旧 uvicorn 不退时新进程会 `ERROR: [Errno 10048]` 静默退出，表现为"重启了但代码没生效"
3. **LAN IP 自动探测** —— 排除 `VMware / VirtualBox / Hyper-V / vEthernet / Loopback / 169.254.*`，优先取**默认路由所在网卡**，避免给出 `192.168.189.1` 这类连不上的虚拟网卡地址

**自检输出示例**

```
后端 /health            HTTP 200
OpenAPI 端点数          329
前端 /api 代理          HTTP 200 total=34
电脑端：http://localhost:9527/#/
手机/平板：http://10.209.0.188:9527/#/   （同一 Wi-Fi）
```

> 脚本以 **UTF-8 with BOM** 保存：Windows PowerShell 5.1 会把无 BOM 的 UTF-8 当 ANSI 读，中文注释会让语法直接报错。

## 2. 门禁运行（10 层）

```powershell
cd backend
$env:PYTHONIOENCODING="utf-8"
$env:OPENAPI_URL="http://127.0.0.1:8000/openapi.json"   # 端口统一后可省略（默认即 8000）；仅临时改用别的端口才需要
python scripts\gates\gate_all.py
```

| 层 | 关注点 | 常见红灯原因 |
|---|---|---|
| L0 | 红线（`.vtj` 未改名/端点未删/备份未清） | 动了 `.vtj` 文件名 |
| **L1-G** | 逐字段指纹 + **各科目题量护栏** | 题被删/改；基线过期需 `--rebaseline --reason "…"` |
| L1 / L1-H | 解析器 / 行测材料题 | 解析逻辑改动 |
| **L2** | 行测回归 + 材料块守卫 | 见下方白名单 |
| L4 | OpenAPI 快照 + 模块边界 | 新增跨域 import（需走 `catalog/contract.py` 等契约） |
| L5 / L6 | 前端契约 / 模块化约束 | 新增路由要同步 `EXPECTED_DYNAMIC_IMPORTS` |
| L7 | 底座一致性 | 迁移/对账 |

**L1-G 重定基线**（仅在数据事故后、且必须写明理由）

```powershell
python scripts\gates\gate_l1g_field_fingerprint.py --rebaseline --reason "事故善后：库内仅剩 200 题"
python scripts\gates\gate_l1g_field_fingerprint.py            # 复验
python scripts\gates\gate_l1g_field_fingerprint.py --self-test # 证明门禁能失败
```

护栏逻辑：`meta.expected_counts` 与 `expected_total` 记录各科目题量下限，**任一下降即 FAIL**；`QB_DB=<临时副本>` 可用于演练（不碰真实库）。

**L2 伪题号白名单**（已知不一致，签名匹配才豁免）

```powershell
# 刷新白名单（由脚本自行收集，不要手写）
python scripts\verify\verify_xingce_regression.py "..\题库\行测" `
  --cache-dir data\xingce_cache --write-mismatch-baseline
```

白名单文件 `data/gates/xingce_rng_known_mismatch.json`，每条含 `sig`（区间签名）。**签名漂移或出现新套 → 仍 FAIL**，防止退化被藏进白名单。

### 2.1 VTJ 版本一致性（CI 第 1 个作业）

`.vtj/vue/*.vue` 与 `.vtj/files/*.json` 的版本号必须一致，否则设计器打开页面会报版本冲突。

```powershell
python scripts/vtj_version_sync.py --check   # 只读检查（CI 用），不一致 exit 1
python scripts/vtj_version_sync.py           # 同步：把 JSON 的 __VERSION__ 对齐到 Vue
python scripts/vtj_version_sync.py --strict  # 非设计器页面也算失败（人工排查用）
```

**分类口径（2026-11-02 起）**：脚本只对「设计器页面」负责——`.vue` 里有 `useProvider({ id, version })` 且同名 `.json` 里有 `__VERSION__`。以下 6 个是**非设计器页面**，跳过并计数、不算失败：

| 文件 | 原因 |
|---|---|
| `teacher_analytics` / `teacher_classes` / `teacher_messages` / `teacher_profile` | 手写页（`<template>` 直接写，无 `useProvider`），`.vtj/files/` 里的同名 JSON 是历史残留 |
| `TeacherNavHeader` | 手写组件，无 JSON |
| `smart_recommend` | 有 `useProvider`，但缺同名 JSON（无法比对） |

当前基线：**69 个设计器页面一致、6 个非设计器页面跳过**。CI 用 `--check`，**不会替你把漂移自动改掉**，漂移必须本地跑同步后重新提交。

## 3. 分类词表维护

**三层结构**：`sub_categories`（16 子类）→ `knowledge_point`（94 考点）→ `study_material.point_id`

| 操作 | 脚本 | 幂等 |
|---|---|---|
| 补列/补表（`point_id`、分享表等） | `python scripts/init_material_data.py` | ✅ |
| 播种考点级规则（94 条） | `python scripts/seed_material_point_rules.py --apply [--refresh]` | ✅（同名跳过/覆盖） |
| 回填卡片考点 + 游离类目归位 | `python scripts/backfill_material_point.py --apply` | ✅（dry-run 默认） |
| 徽章固定成色回填 | `python scripts/backfill_badge_tier.py --apply` | ✅ |
| 精选徽章表初始化 | `python scripts/init_badge_top.py` | ✅ |

**规则形态**（`material_classification_rules.rule_config`）

```json
{"subject":"xingce","category":"判断推理","keywords":["判断推理","逻辑"]}                 // 子类级
{"subject":"xingce","category":"判断推理","point":"图形推理","keywords":["图形推理","九宫格"]} // 考点级
```

匹配：**标题优先 → 全文兜底**，同级内按 `(命中关键词数, priority)` 取最大；命中考点时自动带出子类。

> 现状（2026-10-30）：规则 110 条（16 子类 + 94 考点），30 样本回归 **考点 100% / 子类 93%**。

## 4. 上传与待审

**两条通道，校验逻辑共用 `material_format_validator.py`**

| 通道 | 端点 | 大小/行数 | 状态 | 配额 |
|---|---|---|---|---|
| 管理员导入 | `POST /api/materials/admin/import/upload` → `confirm` | ≤10MB / ≤200 行 | 默认 `status=0`，可 `publish=true` | 无 |
| 学生上传 | `POST /api/materials/my/upload` | ≤5MB / ≤200 行 | **强制 `status=0` 待审** | 50 张/天、累计 500 |

**错误分级（关键设计）**

| 级别 | 错误码 | 处置 |
|---|---|---|
| 阻断 | E001 缺列、E004 超行、E009 扩展名、E010 体积 | 整表拒绝，不产生半成品 |
| 行级 | E002 空值、E003 超长、E005 重复、E008 危险标签 | 跳过该行并回报行号 |
| 警告 | E006 分类不在词表、E007 考点不存在 | 回退自动分类，`warnings` 回传原值 |

**审核转正**：`PUT /api/materials/admin/{id}/status` body `{"status":1}`。

**批量建卡前置检查**

```powershell
# 三科模板（表头 + 考点预填 + 合法分类页）
C:\Users\35709\OneDrive\Desktop\题库\备考资料\_模板\卡片模板_{行测,申论,公专}.xlsx
# PDF → 卡片 Excel（带质量闸门：正面 4-24 字且中文≥60%、背面≥40 字且中文≥50%）
python scripts\convert_pdf_to_cards.py --src "<PDF目录>" --out "<输出目录>" [--dry-run]
```

> 质量教训：无闸门的机械拆分会把公式碎片、页码、纯数字（`631`、`D.41`）当成卡片正面，产生大量无法阅读的卡。**转卡后必须抽检再导入。**
