### 7.3 启动后端（FastAPI）

快速启动（已装好依赖时）：

```powershell
cd D:\砺安题库\砺安题库\backend
pip install -r requirements.txt
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

输入命令后按 Enter 即可。首次启动建议使用虚拟环境，完整步骤如下：

```powershell
cd D:\砺安题库\砺安题库\backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -U pip
pip install -r requirements.txt
python start.py
```

- 如果 PowerShell 禁止执行脚本，先执行：
  ```powershell
  Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
  ```
- 如果不想用虚拟环境，可跳过前两步，直接 `python -m pip install -r requirements.txt`，再 `python start.py`。
- `start.py` 会自动切到 `backend/`，以 `uvicorn app.main:app --host 0.0.0.0 --port 8000` 启动，并带 3 秒重启、连续 20 次熔断的看门狗。
- 开发时需要热重载，可用：
  ```powershell
  python -m uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
  ```
- 首次启动会自动建表：`Base.metadata.create_all()` 只补缺失表；缺失列由 `app/main.py` 里的“自动迁移”代码补 `ALTER TABLE`。启动日志出现“自动迁移”属正常，不要中途杀掉进程。
- 验证：
  - 健康检查：`http://127.0.0.1:8000/health`
  - Swagger：`http://127.0.0.1:8000/docs`
  - 若 8000 被占用：`netstat -ano | findstr :8000`，找到 PID 后结束旧进程。
- 本地配置以 `backend/.env` 为准（已被 `.gitignore` 排除，禁止提交）。`DEBUG=true` 时 `seed.py` 会自动写入模拟账号；生产环境必须设为 `false` 并手动初始化。

### 7.4 启动前端（Vite + VTJ）

**必须从仓库根启动**（`vite.config.ts` 有 `workspaceRoot` 强制校验，不能从 `backend/` 或子目录启动）：

```powershell
cd D:\砺安题库\砺安题库
npm install
npm run dev
```

- 如果 `npm install` 因 peer dependency 报错，可用 `npm install --legacy-peer-deps`。
- 需要严格按 `package-lock.json` 复现依赖时用 `npm ci`；日常安装依赖用 `npm install`。
- `npm run dev` 实际执行 `cross-env ENV_TYPE=local vite`，端口 **9527**，`host: '0.0.0.0'`，手机/平板可通过局域网访问。
- 打开：
  - 前端：`http://localhost:9527`
  - VTJ 设计器：`http://localhost:9527/__vtj__/`
- Vite 代理默认把 `/api` 转发到 `http://127.0.0.1:8000`；需要连别的后端时设：
  ```powershell
  $env:DEV_BACKEND_ORIGIN = "http://192.168.1.10:8000"
  npm run dev
  ```
- 后端没起来时，前端会收到 `503/502` 和 `BACKEND_UNAVAILABLE`，先回去启动 7.3，不要先怀疑前端页面。
- 端口被占用：
  ```powershell
  netstat -ano | findstr :9527
  taskkill /PID <PID> /F
  ```

### 7.5 手机端 / 平板端访问

1. 电脑和手机连同一个 Wi-Fi/局域网。
2. 在 PowerShell 执行 `ipconfig`，找到“无线局域网适配器 WLAN”的 IPv4 地址（如 `10.213.3.206`）。
3. 手机浏览器访问：`http://10.213.3.206:9527`（英文冒号）。
4. 打不开时依次检查：Windows 防火墙是否放行 Node.js；是否连错 Wi-Fi；IP 是否变化；Vite 是否仍在运行。
5. 前端页面走 9527，API 由 Vite 代理转发；一般不需要在手机上单独访问 8000。

## 8.进行分支独立设计的提示词约束：
```
## 分支拓扑约定（必须严格遵守）

当前项目使用“模块工作域 + 子分支”的链式分支模型：

main（稳定基线）
 └── feature/<模块名>        ← 模块工作域（父分支），只接受经过测试的子分支合并
      └── feature/<模块名>/<子任务>  ← 子分支，每次只做一件优化/测试任务

## 你的当前工作域

- 你当前所在的分支：feature/<模块名>/<子任务>
- 该分支的父分支：feature/<模块名>
- 禁止直接从当前分支向 main 发起合并或 PR。
- 所有代码修改、测试、提交，都只在你当前所在的子分支中进行。

## 操作规则

1. **拉取与同步**：开始工作前，先 `git pull` 当前子分支；如果子分支尚未创建，从 `feature/<模块名>` 拉出，命名格式为 `feature/<模块名>/<子任务简述>`。
2. **只做一件事**：当前子分支只负责一个具体的优化或测试任务。不要在其中混合无关的改动。
3. **测试先行或并行**：每次提交前，至少运行与当前模块相关的测试命令（如果项目有测试套件）。如果测试失败，先修复，再提交；不要提交测试失败的代码。
4. **提交粒度**：一个逻辑变更一个提交，提交信息使用 `feat/fix/test/refactor: <简述>` 格式。
5. **合并回父分支**：当前子任务完成且测试通过后，只向 `feature/<模块名>` 发起合并/PR，不要直接向 main 操作。
6. **如果父分支有更新**：在子分支中 `git rebase feature/<模块名>`（或 merge），解决冲突后再继续，保持子分支建立在父分支最新状态之上。

## 合并顺序（链式分支专用）

如果存在多层嵌套（例如孙分支），合并顺序必须是：
- 孙分支 → 子分支 → 模块工作域 → main。
- 永远从最外层向内合并，不得跳层
```
**不同的编码AI的内置技能不同：**
# 1.Trae
利用“工作树”做隔离，提示词侧重“任务边界”
Trae 内置了工作树（Worktree） 模式，可以为每个任务自动创建独立的分支和目录，并在任务完成后通过“AI 合并”将代码合回目标分支。这意味着你不需要在提示词里让 AI 手动执行 git checkout -b，而是在 Trae 中启动任务时选择工作树模式，然后让提示词聚焦于“这个工作树里做什么”：

text
你当前在一个独立的工作树中，对应分支 feature/<模块名>/<子任务>。
你的任务：<具体优化或测试目标>。
约束：
- 只修改与该目标直接相关的文件。
- 完成后，将变更合并回父分支 feature/<模块名>，不要合并到 main。
- 如果测试失败，在当前工作树中继续修复，不要标记任务完成。

# 2.opencode
用 opencode-worktree 插件自动管理子分支
OpenCode 可以通过 opencode-worktree 插件为每个任务自动创建 agent/<task> 格式的子分支，并在退出时自动合回父分支。提示词需要让 AI 理解 agent/ 分支是“临时执行分支”，它的生命周期绑定于当前任务：

text
你正在一个由 opencode-worktree 创建的隔离工作树中，当前分支为 agent/<task>。
该分支的父分支是 feature/<模块名>。
你的任务：<目标>。
规则：
- 所有改动只提交到当前 agent 分支。
- 任务完成后，通过工作树机制合回父分支；如果合并不需要保留，直接退出即可。
- 在退出/合并前，运行相关测试并确认通过。

# 3.Claude
原生 Git 操作，提示词需明确“禁止直接碰 main”
Claude Code 具备原生 Git 提交能力，也可以被 MCP Git 工具赋予分支、rebase 等完整操作权限。它的风险在于权限较大，可能直接执行 git push origin main。因此提示词必须包含一条硬性禁止：

## 9. 后期拉取分支更新后的操作步骤

> 这一节解决“别人合并了新代码/新设计，我本地怎么安全跟上”的问题。完整的多人协作规则见 `docs/plans/分支使用说明书_v1.md`，这里只给拉取前后必须执行的动作。

### 9.1 拉取前：先保证工作区干净

```powershell
cd D:\砺安题库\砺安题库
git status --short
git branch --show-current
```

- 有未提交改动时，先提交到当前功能分支；不想提交就暂存：
  ```powershell
  git stash push -u -m "wip: 拉取更新前暂存"
  git stash list
  ```
- **不要**用 `git reset --hard`、`git clean -fd` 清工作区；这会直接丢代码和未跟踪文档。
- 确认当前分支：`main` 只做同步，不直接开发；开发在 `feature/<模块>` 或 `feature/<模块>/<子任务>`。

### 9.2 拉取 main 与模块分支

**情况 A：只更新 main**

```powershell
git switch main
git fetch origin --prune
git pull --ff-only origin main
```

`--ff-only` 失败说明本地 main 与远端分叉了，不要强行 merge；先看：

```powershell
git log --oneline --left-right main...origin/main
```

把本地多出来的提交移到功能分支，或找维护者确认后再处理。

**情况 B：更新模块父分支**

```powershell
git switch feature/<模块名>
git fetch origin --prune
git merge origin/main
git push origin feature/<模块名>
```

**情况 C：更新自己的子分支（最常用）**

```powershell
git switch feature/<模块名>/<子任务>
git fetch origin --prune
git merge origin/feature/<模块名>
git merge origin/main
git push origin feature/<模块名>/<子任务>
```

先合父分支，再合 main；不要反过来。合并冲突时：

```powershell
git status
# 手工编辑冲突文件，确认没有残留 <<<<<<< ======= >>>>>>>
git add <冲突文件>
git commit
```

想放弃这次合并、回到合并前：

```powershell
git merge --abort
```

冲突处置细节（保留谁、怎么验证）见 `docs/plans/分支使用说明书_v1.md` 第 7 章。

### 9.3 拉取后：先看“变了什么”，再启动

```powershell
git log --oneline --graph --decorate -20
git diff --stat ORIG_HEAD..HEAD
git diff --name-only ORIG_HEAD..HEAD
```

按变更类型处理：

| 变更文件 | 必须动作 |
|---|---|
| `package.json` / `package-lock.json` | 仓库根执行 `npm ci`；新增依赖期间才用 `npm install` |
| `backend/requirements.txt` | `cd backend` 后 `pip install -r requirements.txt` |
| `backend/app/models/models.py`、`backend/migrations/` | **先备份数据库**，再启动后端观察自动迁移；必要时手工执行对应 SQL |
| `.vtj/vue/`、`.vtj/files/` | 禁止移动/改名 `.vtj/`；用 `vtj_check_consistency` 检查；模板改动只能由设计器完成 |
| `src/router/index.ts` | 检查 92 处 `import('$vtj/vue/<id>.vue')` 是否仍能解析；跑 `npm run typecheck` / `npm run build` |
| `deploy/`、`docker-compose.yml` | 检查 `.env` 变量、卷、端口；`docker compose config` 校验 |
| `docs/` | 读新增/变更的规则与计划；同步 `docs/README.md` 索引和计划状态 |

> 注：合并后要把当前分支推到远端；其他机器仍需拉取对应分支才能看到最新提交。

### 9.4 数据库有变更时：先备份，再启动

```powershell
cd D:\砺安题库\砺安题库\backend
python scripts/admin/backup_db.py --label 拉取更新前
python start.py
```

- 启动日志里出现 `自动迁移: ... 添加列 ...` 是正常现象；如果出现异常，停止启动，用备份恢复后再排查。
- `Base.metadata.create_all()` 只建缺失表，不会改已有表结构；`app/main.py` 里有一段手写的“缺失列自动补齐”，覆盖不到的场景仍需 `backend/migrations/*.sql` 手工脚本。
- `backend/migrations/*.sql` 是历史手工脚本，**不要一次性全跑**；先读脚本、确认目标库、备份后再执行。
- 需要本地模拟账号时：
  ```powershell
  cd D:\砺安题库\砺安题库\backend
  # 确认 backend/.env 里 DEBUG=true
  python -m scripts.admin.seed
  ```
  `seed.py` 会先检查 `DEBUG`，生产环境不会自动灌数据；脚本对已存在用户是幂等跳过。

### 9.5 前端依赖与缓存

```powershell
cd D:\砺安题库\砺安题库
npm ci
npm run dev -- --force
```

- `--force` 让 Vite 重新预构建依赖；也可以删除 `node_modules/.vite` 后重启。
- **不要随手执行 `npm run clean`**：该脚本会删除 `node_modules`、`dist`、`package-lock.json`、`pnpm-lock.yaml`，不是普通的清缓存。
- 浏览器用 `Ctrl+F5` 强刷；设计器页面同样要强刷，避免旧 chunk 缓存。

### 9.6 设计完成后的收尾（合并前）

1. **文档**：设计/方案写入 `docs/plans/` 或 `docs/superpowers/specs/`；更新 `docs/README.md` 索引；按 `AGENTS.md` 归档规则留档。
2. **计划**：把实施计划里的任务勾选、状态、验证结果更新掉；代码提交与计划状态提交分开。
3. **VTJ**：`.vtj/` 不移动、不改名、不删除；`raw: true` 页面禁止 `vtj_sync_vue_to_dsl`；`.vtj/vue/*.vue` 的 `<template>` 只能由设计器改，AI 只改 `<script>` 且先 `dryRun: true`。
4. **验证**：
   ```powershell
   cd D:\砺安题库\砺安题库
   npm run typecheck
   npm run build
   npm run test:unit

   cd backend
   python -m pytest tests -q
   python scripts/gates/gate_all.py --quick
   ```
   全量门禁用 `python scripts/gates/gate_all.py`；行测 L1 等既有 FAIL 以基线为准，**新增失败必须修复**。
5. **提交**：一个逻辑变更一个提交，提交信息用 `feat/fix/test/refactor: <简述>` 或模块前缀（如 `wrongbook: ...`）。
6. **合并顺序**：子分支 → 模块父分支 → `main`，禁止跳层，禁止直接 push `main`；合并前必须再合一次最新 `origin/main` 并重跑门禁。
7. **合并后**：删除已合并的临时分支，切回 main `git pull --ff-only`，确认远端与本地一致。

### 9.7 **不要提交的东西（重要）**

- `backend/data/question_bank.db`、`-wal`、`-shm`、`backend/data/*.bak*`、`backend/data/backups/`
- `backend/uploads/`、`backend/app/static/` 的题图、`题库/` 原始 PDF
- `.env`、`deploy/.env.development`、`deploy/.env.school`、`.obsidian_mcp.json`、`admin_token.txt`
- `node_modules/`、`dist/`、`backend/logs/`、`.vtj/logs/`、`.vtj/histories/`

## 10. 数据库数据的存储说明

### 10.1 默认数据库：SQLite（WAL）

| 项 | 实际值 |
|---|---|
| 类型 | SQLite，`DB_TYPE=sqlite`（默认） |
| 主库 | `backend/data/question_bank.db`（当前约 302.7 MB） |
| WAL | `backend/data/question_bank.db-wal`（当前约 5.4 MB） |
| 共享内存 | `backend/data/question_bank.db-shm` |
| 日志模式 | WAL；已提交数据可能还在 `-wal` 里，**不能只拷主库** |
| 连接串 | 由 `backend/app/core/config.py` 的 `DATABASE_URL` 生成；`start.py` 会先切到 `backend/`，所以相对路径以 `backend/` 为基准 |

`backend/data/` 不是普通缓存目录，里面同时有：

- `backups/`：`backup_db.py` 的新备份
- `audit/`：数据变更追溯凭证（R9，不是垃圾）
- `gates/`：门禁基线与 `last_run.json`
- `refactor_baseline/`：API/模型/耦合/表使用基线
- `snapshots/`、`text_cache/`、`xingce_cache/`：解析缓存与快照
- `question_bank.db.bak_*`：历史备份（R8，禁止清理）

### 10.2 大体积数据放在哪里

| 数据 | 位置 | 体量（实测口径） | 是否进 Git |
|---|---|---|---|
| 原始 PDF 语料 | `题库/` | 约 662 MB | 否（R6，禁止删除/移动） |
| 题图 | `backend/app/static/` | 约 4.3–5.5 GB | 否（R7，禁止删除；新题图已忽略） |
| 用户上传 | `backend/uploads/` | 约 0.8 GB | 否 |
| SQLite 主库 + 备份 | `backend/data/` | 主库约 300 MB，备份数十份 | 否 |
| 示例库 | `backend/data/example_db.sqlite` | 约 13 MB | 否（本地示例库，已被 `.gitignore` 忽略） |

这些数据**不通过 Git 共享**。换机器/多人协作时用移动硬盘、内网共享、`rsync` 或对象存储；Docker 部署用命名卷持久化。

### 10.3 Docker 下的数据库

`docker-compose.yml` 把数据挂到命名卷：

- `db_data:/app/data`：SQLite 主库、WAL/SHM、备份、门禁基线
- `uploads:/app/uploads`：用户上传
- `qimg:/app/app/static`：题图（约 4.3 GB，必须单独导入）
- `parser_cache:/root/.cache`：MinerU 模型权重

**不要 `docker compose down -v`**，否则上述卷会被删除。备份要在容器内执行，再把备份文件取出：

```powershell
docker compose exec backend python scripts/admin/backup_db.py --label docker
docker compose cp backend:/app/data/backups/<备份文件>.db .\backup_from_docker.db
```

### 10.4 MySQL 是可选项，不是当前默认

`config.py` 已支持 `DB_TYPE=mysql+pymysql`，并预留 `DB_HOST`、`DB_PORT`、`DB_USER`、`DB_PASSWORD`、`DB_NAME`、`DB_CHARSET`。但当前生产/开发默认仍是 SQLite；切换到 MySQL 前必须：

1. 建库、建账号、授权；
2. 完成表结构与数据迁移；
3. 重跑全量测试和 L4/L5 契约门禁；
4. 单独验证备份/恢复方案（MySQL 用 `mysqldump`，不是 SQLite 的 `backup()`）。

## 11. 数据库备份、恢复与迁移

### 11.1 备份（必须用 sqlite3.backup）

```powershell
cd D:\砺安题库\砺安题库\backend
python scripts/admin/backup_db.py --label 拉取更新前
```

- 默认输出：`backend/data/backups/`，文件名带时间戳和标签（以脚本打印为准）。
- 脚本会做 `PRAGMA integrity_check`，并抽样统计 `sys_user`、`question_bank`、`exam_paper`、`paper_question_relation`、`study_material`，同时写 `.log`。
- **禁止**用 `shutil.copy2` / 资源管理器直接复制主库（R10）：WAL 模式下会得到缺少最近提交的不完整快照。
- **禁止**删除 `backend/data/*.bak*` 和 `backend/data/backups/`（R8）；`bak_pre_wipe_20261004_102517` 是全系统唯一存世的 10,171 道行测题副本。

### 11.2 恢复（会覆盖主库）

```powershell
cd D:\砺安题库\砺安题库\backend
python scripts/admin/restore_db.py --list
python scripts/admin/restore_db.py --backup "data\backups\<备份>.db" --dry-run
python scripts/admin/restore_db.py --backup "data\backups\<备份>.db" --yes
```

- 先**停止后端**，否则 Windows 下文件被占用会失败。
- 脚本会：校验备份 `integrity_check=ok` → 自动再备份当前库 → 删除 `-wal` / `-shm` → 覆盖主库。顺序不能反。
- `--dry-run` 只校验，不落盘；确认无误再加 `--yes`。
- 旧的在 `backend/data/` 根下的 `.bak_*` 文件不一定出现在 `--list` 里，可直接用 `--backup "data\question_bank.db.bak_..."` 指定。
- 恢复后先启动后端看日志，再跑 `/health` 和关键页面。

### 11.3 什么时候必须备份

- 拉取包含模型/迁移的更新前
- 执行 `backend/migrations/*.sql` 前
- 批量导入、清洗、修复数据前
- 恢复另一个备份前（脚本会自动做，但建议手动再留一份）
- 生产环境按日/按发布窗口备份，并把备份复制到另一块磁盘或对象存储

### 11.4 迁移

- 项目**没有统一的 Alembic 迁移器**；启动时靠 `Base.metadata.create_all()` + `app/main.py` 的缺失列 `ALTER TABLE` 兜底。
- `backend/migrations/*.sql` 是历史手工脚本（如 `20250823_001_add_paper_fields.sql`），执行前先读内容、确认库、备份。
- 新增字段优先走模型 + 自动迁移；重命名/删除/回填数据必须写一次性脚本，并先在备份库上演练。
- 迁移后验证：`PRAGMA integrity_check`、关键表行数、`/health`、登录、题目列表、导入链路。

## 12. 多人协作与数据共享

### 12.1 代码共享：GitHub + 分支

- `main` 是稳定基线，只接受经过验证的合并；禁止直接 push。
- 一人一条活跃功能分支，从最新 `main` 切出：`feature/<模块>` 或 `feature/<模块>/<子任务>`。
- 完成子任务 → 合回模块父分支 → 再合 `main`；不要跳层。
- 合并前必须 `git fetch origin`、合最新 `origin/main`、重跑门禁/构建。
- 提交信息带模块前缀；一个提交只做一件事。
- 冲突处理、模块所有权、域卡模板见 `docs/plans/分支使用说明书_v1.md`。

### 12.2 文档共享

- 统一放 `docs/`：设计/计划在 `docs/plans/`，工作流产物在 `docs/superpowers/`，使用/运维手册在 `docs/ops/`。
- 每次新增/定稿文档，**同时**更新 `docs/README.md` 索引。
- 方案、计划、报告按 `AGENTS.md` 的归档规则留档；不要只在聊天里发。
- 图片放 `docs/plans/` 下并随文档提交；大 PDF、题库原文件不进 Git。

### 12.3 数据库共享：三种方式，按场景选

**方式 A：每人本地 SQLite（开发首选）**

- 每人自己 `seed.py` + 迁移，互不影响。
- 需要同一批数据时，分享**备份文件**而不是正在使用的 `.db`：
  1. 一方 `backup_db.py --label 共享`；
  2. 通过内网/加密云盘把备份文件给对方；
  3. 对方停止后端，`restore_db.py --backup ... --yes`；
  4. 启动后验证。
- 适合题目导入、页面联调、个人开发。

**方式 B：一台共享后端（联调/演示）**

- 由一台机器（或 Docker 主机）跑后端 + 数据库，其他人只跑前端。
- 前端启动时指定：
  ```powershell
  $env:DEV_BACKEND_ORIGIN = "http://<共享主机IP>:8000"
  npm run dev
  ```
- 所有人读写同一套数据，适合联调；但要约定“谁在什么时候导入/改数据”，避免互相覆盖。
- 共享主机上的 SQLite 仍然只允许本机进程访问，**不要把 `.db` 放到 SMB/OneDrive 共享目录**。

**方式 C：MySQL 中央库（多写/长期）**

- 需要多人同时写、或数据量/并发继续增长时，切 `DB_TYPE=mysql+pymysql`。
- 需要 DBA/维护者统一建库、迁移、备份；SQLite 脚本不能直接复用。
- 切换前必须在测试库跑全量测试与 L4/L5 门禁。

**SQLite 共享的硬限制**

- WAL 模式不适合网络文件系统；多人同时通过共享目录打开同一个 `.db` 会锁死或损坏。
- 同一时刻只让一个后端进程写库；出现 `database is locked` 先停重复后端，不要删 `-wal`/`-shm`。
- 共享用“备份文件 + 恢复”，不要共享“正在运行的主库”。

### 12.4 大文件与题图共享

- `题库/`、`backend/app/static/`、`backend/uploads/` 用移动硬盘、内网 `rsync`、对象存储或 Docker 卷同步。
- 不要把这些目录放进 Git；不要为了“方便”把题图打进镜像（R7）。
- Docker 的 `qimg` 卷首次要导入题图；新机器没有题图会全站裂图。

### 12.5 账号、凭据与环境变量

- 本地模拟账号由 `seed.py` 生成：教师 `ycc5678 / ycc5678`，管理员 `cbrycc / cbrycc`；学生账号以本地库为准。
- 这些账号只用于开发/演示，生产必须改密码、关 `DEBUG`、关开放注册（按需）。
- 每人本地一份 `.env`；仓库只提交 `deploy/.env.example`。
- JWT/第三方密钥由使用者本人生成：`python -c "import secrets; print(secrets.token_urlsafe(48))"`。
- 已泄露的密钥必须**轮换**；改写 Git 历史只是附加项，不能代替轮换。

## 14. 常见问题速查

| 现象 | 优先排查 | 处理 |
|---|---|---|
| `npm run dev` 报 workspace 错误 | 是否在仓库根启动 | `cd` 到含 `vite.config.ts` 的根目录再跑 |
| 9527 被占用 | `netstat -ano \| findstr :9527` | 结束旧 Node 进程，或换端口（需同步配置） |
| 8000 被占用 / 后端反复重启 | `netstat -ano \| findstr :8000`；看 `backend/logs/app.log` | 结束旧 uvicorn；修掉启动异常，别让看门狗空转 |

| `ModuleNotFoundError` | 是否在 `backend/`、是否装了 `requirements.txt` | 激活 venv，重装依赖 |
| `database is locked` | 是否有多个后端/脚本同时写库 | 停重复进程；不要删 `-wal/-shm`；必要时备份后恢复 |
| VTJ 页面 404 | `.vtj/` 是否被移动/改名；路由 import 是否存在 | 恢复 `.vtj/` 原位置；跑 `vtj_check_consistency`；看 `src/router/index.ts` |
| 登录后立刻退出 | `JWT_SECRET_KEY` 是否变化；`.env` 是否被覆盖 | 固定本机密钥；多环境不要混用 |
| 手机打不开 9527 | 同一 Wi-Fi？防火墙？IP 变了？ | 放行 Node.js；用 `ipconfig` 重新取 IP；确认 `host: 0.0.0.0` |
| 设计器能开但页面空白 | 旧 chunk 缓存 / 后端接口失败 | `Ctrl+F5`；看控制台 Network；`npm run dev -- --force` |
| `git pull` 冲突 | 本地改动与远端冲突 | 按 9.2 解决；不要 `reset --hard`；必要时 `git merge --abort` |
| Docker 启动后图片全裂 | `qimg` 卷是否导入题图 | 导入 `backend/app/static/` 到 `qimg` 卷；不要重建卷 |
| Docker 起来但前端 404 | `dist/` 是否构建；nginx 挂载是否正确 | `npm run build:prod`；`docker compose config` 检查 `./dist` |
