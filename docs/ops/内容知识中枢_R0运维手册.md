## 4 恢复

1. 停止后端进程，确认没有写入。
2. 备份当前库（即使要恢复，也先留一份现场）。
3. 用备份覆盖 `backend/data/question_bank.db`。
4. 删除同目录 `question_bank.db-wal`、`question_bank.db-shm`。
5. 校验：

```powershell
python -c "import sqlite3; c=sqlite3.connect('data/question_bank.db'); print(c.execute('PRAGMA integrity_check').fetchone()[0])"
```

6. 启动后端，确认 `/health` 正常。

## 6 回填

```powershell
cd backend
# 1) 只统计，不写库
python -m scripts.content_hub.backfill_kg --dry-run

# 2) 人工确认覆盖率 100% 后写入
python -m scripts.content_hub.backfill_kg --apply
```

- 幂等：重复执行 `topics_created / sources_created / edges_created` 均为 0。
- 分类映射：
  - 金句：哲理→哲理思辨、治国→治国理政、民生/民心→民生保障、法治→法治思维、品德→品德修养
  - 新闻：理论→政治理论、党史→党史学习、公安报→公安要闻
  - 招考：6 个分类 → 同名 `exam_type` 主题
- 未命中分类会出现在 `unmapped`，需补映射后重跑；不要静默丢弃。
- `--apply` 前必须先做第 3 节备份。

## 11 故障排查

| 现象 | 处理 |
|---|---|
| `vault_not_found` | 确认 `OBSIDIAN_VAULT_PATH` 指向真实目录；不要指向不存在的盘符 |
| 回填 `coverage < 1` | 看报告 `unmapped`，补分类映射后重跑 dry-run |
| `database is locked` | 停止爬虫/后台任务；SQLite WAL 下避免长事务；备份用 `backup_db` |
| 启动报 `Invalid args for response field` | 检查 FastAPI 安装是否被空壳类覆盖（本机曾出现 `class Request: pass`）；重装或清理 |
| `/api/kg/nodes/...` 404 | 节点不存在或类型不在 8 类白名单 |
| Obsidian 文件重复/冲突 | 检查 `99-系统/导出清单.json` 是否被手工改动；删除后重导 |
