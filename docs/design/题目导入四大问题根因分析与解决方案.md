## 一、根因分析（全部基于实证，证据链完整）

### 问题1：试卷识别了但没保存/前端不显示

**证据链**：
- 导入记录 `#1220/#1221/#1222`（2017多省联考题目docx）状态全部为 **PREVIEW、paper=None** —— 解析预览完成了，但**确认入库从未成功执行**
- 时序：12:45:53 上传答案PDF → 触发扫描件OCR → 12:46 后端崩溃 → 确认入库请求随进程死亡而中断 → 题目未入库、试卷未创建
- 已有试卷 #16/#17（2016多省联考）状态为 **ENDED**（上轮被删除），试卷列表**默认过滤 ENDED**（teacher.py 设计行为）→ 即使看到旧记录也不显示

**根因**：① 崩溃中断了"确认入库"事务（主因，见问题3）；② ENDED 过滤让历史试卷不可见（次因，设计行为需知晓）。

### 问题2：推广图重现（qid 1155 引用 5661de6d/d206d766）

**证据链**：
- 12:24~12:29 导入的题目（qid 1140~1158）**全部 `source=''`、`year=None`** —— 而新代码 A1 元数据注入已验证必填这两字段
- 1155 的推广图未被黑名单拦截 —— 而新代码黑名单已验证必拦（上轮 `_calibrate.py` 实测命中）
- 用户日志：**12:46:48 才首次手动重启 uvicorn**（`python -m uvicorn app.main:app`，无 --reload）

**根因**：**重导入期间运行的是旧代码的后端进程**（上次启动早于本次所有代码提交；Python 不热加载）。新代码（黑名单过滤+元数据注入+回填式更新）在崩溃后重启才首次加载。
**推论**：新代码本身有效；需 ① 用新代码重启后端后继续重导入；② 清理 1155 等残留推广图引用（重跑清理脚本即可，黑名单会命中）。

### 问题3：后端崩溃（最严重）

**证据链**：
- 2017多省联考**答案PDF为纯扫描件**（pymupdf 实测前5页 0 字符文本层）
- 崩溃路径：`/upload` → PyPDF2 提取文本为空 → MinerU 第一级**被跳过**（`MINERU_ENABLED=False`，.env 未配置）→ 第二级 `_extract_text_from_scanned_pdf` → **PaddleOCR 在 HTTP 请求线程内同步处理 15 页（自估 300 秒）**
- 三重致命因素叠加：
  1. **同步阻塞**：300 秒 OCR 在请求线程内执行 → vite 代理超时（ECONNRESET）
  2. **原生崩溃**：本机 **Python 3.13.5**，PaddleOCR 官方支持 ≤3.12 → Paddle 原生层加载模型后进程硬崩（ECONNREFUSED = 端口无人监听，进程已死）
  3. **无守护**：进程死亡后无自动重启，系统瘫痪直至手动干预
- 日志中"信息: 用提供的模式无法找到文件"为 Paddle/子进程的 Windows 输出噪音，无害

**根因**：扫描件 OCR 通道 = "同步执行 + 不兼容运行时 + 无进程隔离 + 无超时熔断"四重缺陷叠加。

### 问题4：仍缺答案解析

**根因**：① 2017 答案PDF导入被崩溃中断（问题3）；② 部分答案文档本身无解析（2025年三份仅答案字母）；③ 扫描件答案PDF（如2017）在 OCR 通道修复前无法导入。修复问题3 + 继续重导入即可解决绝大部分。

### 附：您贴的 `ERROR: Cannot read "...pdf" (this model does not support pdf input)`

这是**某个 AI 模型/工具不支持 PDF 输入**的报错（您可能把 PDF 直接喂给了该模型），与题库系统无关。系统后端用 pymupdf 读 PDF 正常。请改用支持 PDF 的工具，或交由系统导入通道处理。

## 二、解决方案（分四个优先级）

### P1 紧急修复——让重导入立即走通（当天完成）

| # | 措施 | 设计要点（为什么这样做） |
|---|---|---|
| 1.1 | **OCR 子进程隔离**：新建 `services/ocr_worker.py`，PaddleOCR 移入独立子进程执行（复用 MinerU 独立 venv 的成熟模式：subprocess + 临时文件 IPC + 超时强杀） | 主进程**零 Paddle 导入** → 子进程崩溃（3.13 不兼容）绝不拖死后端；超时（默认120秒）强杀并返回明确错误；这是"进程隔离兜底"的运维标准做法 |
| 1.2 | **启用 MinerU 第一级**（.env 加 `MINERU_ENABLED=True`）+ 实测 2017 答案PDF | MinerU 独立 venv 已安装（上上轮部署），版面解析质量高于逐页 OCR；代码已有三级回退链，只需打开开关并验证 |
| 1.3 | **扫描件页数上限+优雅降级**：OCR 页数上限 15→8、单页失败跳过、全部失败返回明确提示"该PDF为扫描件且OCR失败，请改用图片导入或联系管理员" | 失败必须**可见、可理解、可操作**，而非静默超时 |
| 1.4 | **后端守护重启**：`start.py` 增加看门狗循环（子进程退出自动重启+告警日志） | 即使未来再崩，系统自愈而非瘫痪 |
| 1.5 | **清理残留推广图**：重跑 `clean_irrelevant_images_v2.py --apply`（黑名单命中 1144~1158 中的推广图引用） | 旧进程留下的脏数据，一键清除 |
| 1.6 | **重启指引**：明确告知用户"必须重启后端才能加载新代码"，并建议日常使用 `python start.py`（带守护） | 问题2的直接解药 |

### P2 导入链路完善——断点可续、试卷必达

| # | 措施 | 设计要点 |
|---|---|---|
| 2.1 | **PREVIEW 断点复用**：确认入库（batch-parsed）失败/中断后，再次进入预览页时若存在同文档未完成 PREVIEW 记录，前端提示"检测到未完成的导入，是否继续？"并复用已解析结果 | 三次重复解析（#1220/1221/1222）浪费且易错；断点续传把"确认失败"从"从头再来"变为"接着走" |
| 2.2 | **建卷/复活保障**：导入回填发生时，若该批题目原属试卷已 ENDED 或不存在 → 自动创建 DRAFT 试卷并关联（消息明示 paper_id）；`_get_or_create_import_paper` 对同名 ENDED 试卷改为复活（ENDED→DRAFT） | 用户重导入的合理预期是"试卷管理里能看到"；ENDED 复活避免同名试卷堆积 |
| 2.3 | **导入结果可追溯**：完成消息中的 paper_id 增加为可点击跳转（前端试卷管理带 `?paper_id=` 高亮） | 缩短"导入了→去哪看"的路径 |

### P3 识别质量提升——系统性误差趋零

| # | 措施 | 设计要点 |
|---|---|---|
| 3.1 | **题干切分修复**：1144~1158 题干内嵌"六、""八、根据以下情境材料，回答…"等大题号/材料头（切分不净）。在 `extract_question_blocks` 的分节逻辑中增加：`^[一二三四五六七八九十]+、` 大题标题行识别为分节符（不入题干）；"根据以下…回答X-Y题"句独立识别为材料头 | 切分污染是本题批次的系统性误差源；修复后复合题识别（B2）命中率同步提升 |
| 3.2 | **识别功能整合去重**（响应用户要求）：审计现有三条解析路径——前端 questionImport.vue 本地解析、后端 `/parse`、`batch-parsed` 内嵌解析。**统一以后端 `/parse` 为唯一权威解析器**，前端本地解析逻辑降级为"后端不可用时的降级通道"并在 UI 标注；对比各路径的选项提取/答案提取/题号提取实现，保留最强实现，删除弱实现（具体去重清单在实施时逐函数审计输出） | 双轨解析是"同文档不同结果"的根源；单一权威 + 明确降级 = 可预期 |
| 3.3 | **识别结果置信度透出**：/parse 返回每题 confidence，前端预览页对低置信题（<0.5）标黄提示人工核对 | 把"误差"从事后发现变为事前提示 |

### 关于"误差减小到 0.01"的诚实说明

识别误差由两部分构成：**系统性误差**（切分错误/字段丢失/过滤失效/流程中断）与**源材料误差**（扫描件清晰度、原文档排版混乱）。本方案通过 P1~P3 将**系统性误差压到趋近于零**（每类误差都有对应修复+验证）；源材料误差（如模糊扫描件的 OCR 字符错误）无法承诺具体数字——它取决于原件质量，缓解手段是 MinerU 高精度版面解析 + 低置信人工核对（3.3）。**不承诺无法兑现的数字，但承诺每一类可修复误差都有闭环。**

## 四、风险与回滚

| 风险 | 对策 |
|---|---|
| OCR 子进程方案在 Windows spawn 模式的兼容性 | 采用 subprocess+文件IPC（MinerU 已验证的模式），非 multiprocessing；实施时先做 1 份扫描件 PDF 的端到端试点 |
| MinerU 对该扫描件识别质量未知 | 三级回退链保留：MinerU 失败 → 子进程 PaddleOCR → 明确报错；绝不静默返回空 |
| 改动 /upload 主链路影响正常文档导入 | OCR 隔离仅替换"文本提取为空"分支；有文本层 PDF 路径零改动；全量回归测试护航 |
| ENDED 复活逻辑误复活用户主动删除的试卷 | 仅在"同名同批次重导入"场景触发，且复活后状态为 DRAFT 需人工再提交审核 |
