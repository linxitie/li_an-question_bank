## 一、问题根因诊断（已逐文件实测核对）

| # | 问题 | 根因（精确定位） |
|---|------|-----------------|
| 1 | 系统总览各科目占比不显示公专 | 后端 `SubjectDistribution` 返回 `{labels, values, colors}` 对象，前端 `admin_dashboard.vue` 却按数组 `subject_distribution.map(item => ({name: item.subject, value: item.count}))` 遍历 → **前后端字段结构不匹配**，饼图永远空白 |
| 2 | 试卷总数未归零 | 后端 `get_dashboard` 用 `count(ExamPaper.paper_id)` 统计**所有**试卷（含草稿/审批中/已发布），未过滤 `paper_type == "PUBLISHED"` |
| 3 | 头像下拉框不更新 | `AdminLayout.vue` 声明了 `avatarUrl` 但**从未赋值、从未在模板使用**，头像始终显示 `username.charAt(0)` 首字母 |
| 4 | 题库管理大量问题 | 见下方 §4 逐项根因 |
| 5 | 日志审计操作描述英文 | 后端 `record_operation` 的 `response_result` 历史数据为 None；`materials.py` 的 `_audit` 已中文化但历史数据残留（**已完成数据清洗**） |
| 6 | 备份名称含英文时间戳 | 历史备份 `backup_20260817_212248`；前端 `createBackup` 生成的中文名仍含「_年_月_日_点_分」时间 |
| 7 | 权限管理英文 + 超管无编辑 | `Permission.value` 是 `question:view` 等英文；前端映射不全；超管无权限编辑接口 |

## 二、方案总览

**核心原则**：精准定位每个问题对应的前后端文件，最小改动、不破坏其他模块、保证前端真实生效、后端字段/路由完整、VTJ 版本一致。

### 问题 1：系统总览科目占比实时显示

**根因**：前后端 `subject_distribution` 数据结构不一致。

**修复方案**：统一数据契约，采用「前端期望的数组结构」。

- **后端** `admin.py` 的 `get_dashboard`：把 `subject_distribution` 从 `SubjectDistribution` 对象改为返回数组 `[{subject, count}]`，并**实时查询**（当前已是每次请求实时查询 `QuestionBank`，仅需改返回结构）。
- **前端** `admin_dashboard.vue`：`colorMap` 补齐公专（已有），确认 `item.subject`/`item.count` 字段名与后端一致。

**为什么这样改**：前端已经按 `[{subject, count}]` 数组处理，改后端返回结构对齐前端，是改动最小、语义最清晰的方案。不引入额外字段转换层，便于运维理解。

**涉及文件**：
- `backend/app/api/v1/admin.py` — `get_dashboard` 返回结构
- `backend/app/schemas/admin.py` — `DashboardResponse.subject_distribution` 类型改为 `List[dict]`

### 问题 2：试卷总数归零（仅统计已发布）

**根因**：`total_papers` 统计所有试卷。

**修复方案**：
- 后端 `get_dashboard` 中 `total_papers` 改为：
  ```python
  total_papers = db.query(func.count(ExamPaper.paper_id)).filter(
      ExamPaper.paper_type == "PUBLISHED"
  ).scalar()
  ```
- **数据清理**：写脚本将数据库中所有 `paper_type != "PUBLISHED"` 的试卷**软删除**或直接清零（需用户确认是删除还是仅归零统计口径）。

**为什么这样改**：试卷生命周期是「草稿→审批中→已审批→已发布」，只有 `PUBLISHED` 才算"已有试卷"，与教师端"点击发布才统计"的业务规则一致。这是业务口径修正，非前端造假。

**需要用户确认**：
1. 是**物理删除**未发布试卷，还是仅**统计口径**改为只计已发布？
2. 教师端「题目导入」产生的试卷，是否需要补「发布」状态字段，确保未发布不计入？

**涉及文件**：
- `backend/app/api/v1/admin.py` — `get_dashboard` 的 `total_papers`
- 可能需 `backend/scripts/` 数据清理脚本

### 问题 3：头像下拉框实时更新

**根因**：`AdminLayout.vue` 的 `avatarUrl` 未赋值、模板未使用。

**修复方案**：
- `AdminLayout.vue` 的 `onMounted` 里调用 `/api/auth/profile` 获取 `avatar`，赋值给 `avatarUrl`。
- 模板头像区改为：`<img v-if="avatarUrl" :src="avatarUrl" class="avatar-img">`，否则回退首字母。
- 用户管理/个人信息页更换头像后，因 Layout 是常驻组件，需在头像变更后刷新——最简单：`onMounted` 加载 + 监听路由变化刷新，或提供 `window.dispatchEvent` 自定义事件。

**为什么这样改**：头像数据已在 `SysUser.avatar` 字段（数据库已确认存在），`/api/auth/profile` 已返回 `avatar`（UserResponse 含 avatar 字段）。只需前端绑定即可，无需改后端。

**涉及文件**：
- `src/layouts/AdminLayout.vue` — 头像加载与渲染

### 问题 4：题库管理（6 个子问题，逐项解决）

#### 4.1 ID 升序排序
- 后端 `list_all_questions` 的 `order_by(desc(QuestionBank.question_id))` 改为 `asc`。

#### 4.2 科目/题型显示为空
- 后端 `list_all_questions` 返回补 `subject_name` 字段（当前只有 `subject_id`、`type_name`）。
- 前端 `admin_questions.vue` 用 `q.subject_name` 替代 `q.subject_id` 的裸显示。

#### 4.3 options 字典形式显示问题
- **根因**：`options` 字段存的是 JSON 字符串 `[{"key":"A","value":"..."}]`，前端直接 `{{ }}` 渲染字符串。
- **修复**：前端加 `parseOptions()` 方法解析 JSON，渲染为 `A. xxx` 形式（对标教师端 `parsedOptions`）。

#### 4.4 题型不同颜色徽章
- 对标教师端 `teacher_questions.vue` 的 `typeBadgeClass()` + `typeDisplayName()`，在 `admin_questions.vue` 复用同样的题型→徽章颜色映射，保留「审核状态」「操作」列。

#### 4.5 图片题目显示路径而非图片
- **根因（已实测确认）**：前端用 `{{ question_content }}` 文本插值，HTML `<img>` 标签被 Vue 转义成纯文本字符串。
- **图片文件与路径核对结论**：图片文件**真实存在且路径正确**——`backend/app/static/questions/` 下共 280 张图，数据库中 `/static/questions/432/img_0_31ce516f.png` 对应的磁盘文件 `app/static/questions/432/img_0_31ce516f.png` 实测 `exists=True`，`main.py` 已正确挂载 `/static/questions`。**无需修复图片存储，仅需前端改 `v-html` 渲染。**
- **修复**：题干/选项/解析改用 `v-html` 渲染（配合 `cleanHtmlContent` 清洗，对标教师端 `teacher_questions.vue`），图片自适应 `max-width:100%; height:auto;`。

#### 4.6 编辑保存「❌ 更新失败」
- **根因**：前端调用 `PUT /api/admin/questions/{id}`，但后端 `admin.py` **只有** `/questions/{id}/audit` 和 `/questions/{id}/archive`，**没有 `PUT /questions/{id}` 编辑接口** → 404 → 更新失败。
- **修复**：后端 `admin.py` 新增 `PUT /questions/{question_id}` 编辑接口（对标教师端题目编辑，含 options/answer/analysis/type_id/subject_id 字段校验），前端 `submitEdit` 对齐字段。

**涉及文件**：
- `backend/app/api/v1/admin.py` — 排序改 asc、补 subject_name、新增 PUT 编辑接口
- `backend/app/schemas/admin.py` — 新增题目编辑 schema
- `.vtj/vue/admin_questions.vue` — 徽章、parseOptions、v-html 图片、subject_name
- 对标参考 `.vtj/vue/teacher_questions.vue`

### 问题 5：日志审计（已基本完成，需确认状态口径）

- **操作描述**：已完成中文化 + 历史数据清洗（实测 0 条英文残留）。
- **状态「尽量全部通过」**：当前 `response_result` 历史数据为 None 显示「未知」。**不能造假**，正确做法是：
  - 后端 `record_operation` 已默认写 `response_result="success"`（成功操作）。
  - 历史 None 数据：写脚本回填为「成功」（因为这些是成功操作记录），但**保留失败记录为「失败」**，不强行全部改为通过。
  - 状态列改为三态：成功/失败/未知，中文展示（已完成 `status_cn`）。

**需要用户确认**：历史 None 状态是否回填为「成功」？还是保持「未知」？

### 问题 6：备份名称中文化（不含时间）

- 前端 `admin_backup.vue` 的 `createBackup` 生成「系统全量备份_2026年X月X日_X点X分」→ 改为「系统全量备份」（不含时间，由 `create_time` 字段区分）。
- 后端 `create_backup` 的 `backup_name` 默认值 `f"backup_{timestamp}"` → 改为「数据库备份」。
- 历史 `backup_20260817_212248` 记录：脚本清理或仅前端展示时剥离时间戳。

**涉及文件**：
- `.vtj/vue/admin_backup.vue` — 备份名
- `backend/app/api/v1/admin.py` — `create_backup` 默认名

### 问题 7：权限管理中文化 + 超管编辑功能

- **中文化**：前端 `admin_permissions.vue` 的 `permissionNames` 补齐全部 24 个权限 key 的中文映射（question/paper/exam/user/system/log/data/video/forum/llm 全系列）。
- **超管编辑功能**：后端已有 `PUT /permissions` 接口（`update_permissions`，仅超管），前端 `admin_permissions.vue` **补编辑交互**——每个角色卡片加「编辑权限」按钮，弹窗勾选权限，保存调用 `PUT /api/admin/permissions`。
- 权限中文映射表（完整）：
  - question:create/update/delete/view/audit/import → 创建/编辑/删除/查看/审核/导入题目
  - paper:create/approve/publish/view/update → 创建/审批/发布/查看/编辑试卷
  - exam:start/view_all/view/grade → 开始/查看全部/查看/评分考试
  - user:manage/view → 管理/查看用户
  - system:config/monitor → 系统配置/系统监控
  - log:audit → 日志审计
  - data:backup → 数据备份
  - video:upload/delete → 上传/删除视频
  - forum:post/manage → 发帖/管理论坛
  - llm:use → AI 助手

**涉及文件**：
- `.vtj/vue/admin_permissions.vue` — 中文映射 + 编辑交互
- `backend/app/api/v1/admin.py` — `get_permissions` 返回补中文描述（或前端映射）
