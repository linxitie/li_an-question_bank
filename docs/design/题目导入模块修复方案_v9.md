### 1.2 P3 —— `batch-parsed` 500 的真因（与我的改动无关）

日志（`backend/logs/app.log` 20:36:42）：

```
[batch-parsed] 试卷#53 关联1题 成功(累计1)
[batch-parsed] 提交失败: (sqlite3.IntegrityError)
  UNIQUE constraint failed: paper_question_relation.paper_id, paper_question_relation.question_id
```

**根因**：`question_import.py:1230` 用 `all_ids = ok_ids + reused_ids` 作为待关联集合，
但 `:1227` 的去重集合 `existing_rel_qids` **只查了数据库已有行，没有查本批次内部的重复**。
当 `all_ids` 自身含重复 qid 时，第二轮 `db.add` 撞唯一约束，整事务回滚。

**爆炸半径（实测）**：试卷 #53 名为「2025年安徽省公务员录用考试《行测》题（网友回忆版）」，
事务回滚后 `question_count=0`、实际关联行数 `=0` —— **该卷一道题都没入库**。
这正是你遇到的"导入失败/题目丢失"。

**与 P1 的因果关系**：P1（材料被切到上一组最后一道子题）会让同一道题在批内被重复处理，
从而在 `all_ids` 中出现重复 → 触发 P3。**修 P1 能大幅降低 P3 触发率，但 P3 的代码缺陷
独立存在，必须单独修**（不能依赖 P1 修复来兜底）。

**旁证**：库内已有跨卷复用是正常业务（q12 出现在 3 份卷），说明"同题多卷"本身合法，
出问题的是**同一批次内**的重复。

### W1 —— P3 批量入库健壮性

**改动点**：`question_import.py:1230`

```python
all_ids = ok_ids + reused_ids
```
改为批内去重（保序）：
```python
_seen, all_ids = set(), []
for _q in ok_ids + reused_ids:
    if _q not in _seen:
        _seen.add(_q); all_ids.append(_q)
```

**为什么这样写**：不引入新数据结构，`set` 保序去重是最小改动；`existing_rel_qids`
的库内去重逻辑保持不变（它是正确的，只是覆盖不全）。

**安全性**：只减少写入行数，不会写入原本不该写的关联。

**运维便利**：批量导入的 500 从"整卷回滚"降级为"跳过重复"，日志需打印被跳过的题号，
便于定位是哪道题重复。

**验收**：
- 构造含批内重复的导入 → HTTP 200，不再 500
- `paper.question_count` 与实际关联行数一致
- 门禁 3/3 + 6/6 + L1G PASS

### W2 —— P1 材料边界修正（**最高优先级，P3 的上游诱因**）

**改动点**：`composite_matcher.match_xingce_material_groups:359-373`（单处逻辑修正）

原文排列是「材料 → N 道子题 →（下一个材料块）」，但 `:364` 用"下一个材料块起点"
当上界，把中间全部子题都算进了材料。修正为**三者取 min**：

```python
upper = materials[i + 1]['start'] if i + 1 < len(materials) else INF
se = sec_end.get(section)
if se is not None:
    upper = min(upper, se)
# ★ 关键修正：材料必须止于本组首个子题，不能吞掉自己的子题
first_qn_pos = 本组首成员题在 qno_positions 中的位置
if first_qn_pos is not None:
    upper = min(upper, first_qn_pos)
```

**为什么这样写**：
- 首成员题起点是**语义边界**（材料结束、子题开始的天然分界），比字符距离可靠；
- 复用既有 `qno_positions`（已按位置排序，含题号），**不新建任何解析逻辑**；
- 三值取 min 保证材料只会**变短不会变长** —— 误纳风险归零，漏纳风险需 `logger.warning` 兜底。

**安全性**：只收窄上界，不动成员判定逻辑（`:370-373` 的 `start < pos < upper` 保持不变）。
成员名单在收窄后会自动变少（那些本来就不该在材料里的题号本就超出新上界），属预期行为。

**运维便利**：每次截断记 `logger.warning`（原上界 / 新上界 / 被截字数），
后续可用 `fix_composite_groups_r8.py` 的 dry-run 报告复核是否有异常截断。

**验收基线（用上述真实语料，改前 → 改后必须收敛到右列）**：

| 组 | 改前材料长度 | 改后期望 | 判定 |
|---|---|---|---|
| 组1（成员 96-100） | 1038 字 | **≈561 字** | 误吞 85% → 0% |
| 组2（成员 101-110） | 1234 字 | **≈216 字** | 误吞 471% → 0% |

附加断言：**材料文本内不得出现任何成员题号**（这是最直接的自动化判据，
已写入验证脚本 `verify_p1b.py` 的检查逻辑）。
