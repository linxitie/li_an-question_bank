## 0. 一页纸结论

1. **旧分类的核心问题不是“树不够大”，而是“题不在树上”。** 运行态可见题 3410 道，只有 2125 道挂在启用知识点上；这 2125 道里又有 **1979 道（93.1%）挂在名为“其他”的残差桶**，真正落在有意义叶子上的只有 **146 道（4.3%）**。这说明当前分类在“可命题、可诊断”这一层基本没有建立起来。
2. **必须只以启用节点为规范基线。** 知识表共 1049 个节点，其中 **531 个是停用节点**；运行态 API 只读启用节点，实际是 **518 个 = 91 个二级 + 427 个三级 + 0 个四级**。旧库把 1049 个全做成卡片，等于把 531 个历史标签当成了知识。
3. **91 个“其他”不是知识点。** 每个启用二级节点下恰好各挂 1 个“其他”，共 91 个；它们承载了 2127 条题点关联（去重 2126 道题，其中可见 1979 道）。任何科学分类的第一步，都是把这 91 个残差桶从规范节点中剔除，把题重新归位。
4. **四层是“类型”，不是“强制等深”。** 科目、知识域、知识点、考点是四种对象；有的域天然是“域→分组→知识点→考点”，有的域天然是“域→知识点→考点”。为了凑四层而造虚假考点，是伪科学。
5. **分组、大纲条目、题目、能力/情境不是知识节点。** 分组只负责导航；大纲条目是官方依据；题目是证据；能力/情境是属性。把它们混进四层，正是旧分类语义混乱的根源。
6. **大纲是“参考层”，不是“树本身”。** 公专官方三块九目、行测六模块加联考特色与待确认项、申论五种题型加五种能力，必须建立独立的大纲条目层，再用“大纲映射”边连到分类树；不允许把“大纲模块”直接等同于“教学知识点”。
7. **关系仍是 8 类，但禁止自动生成语义边。** 父→子是“包含”，不是“先修”；同父兄弟不是“并行”；题→点是“考查”，不是“实例”。先修、并行、易混、跨科迁移必须有证据、有评审、有日期。
8. **Obsidian 采用“9 个日常区 + 1 个归档区”的中文结构。** 规范卡片规模为 **3 科目 + 16 知识域 + 42 分组 + 220 知识点 + 165 考点 = 446 张**；531 个停用节点和 91 个“其他”只进归档索引，不再做成噪声卡。
9. **迁移以“题”为驱动，分三条线。** 乙类（申论/职业素养/基本能力）先把 771 道可见残差题回链到已有 165 个考点，零新建节点；甲类（行测/公专基础知识）用 1208 道可见残差题做题簇，补建考点；剩下 621 道只挂停用点、664 道无关联的可见题，逐题定性，不强行归类。
10. **本轮只交付设计与可审批计划，不重建 Obsidian、不改数据库、不改代码。** 用户批准 D1–D10 后，先执行 P1（只读建库）；P2/P3 再做题库归位；任何写库动作必须单独立项、备份、可回滚。

### 1.2 本方案要解决的问题

不是“再画一张更漂亮的树”，而是回答四个问题：

1. **一个节点到底是什么类型？** 是科目、域、分组、知识点、考点，还是大纲条目/题目/属性？
2. **它凭什么放在这个父节点下？** 是教学目标互斥，还是仅仅名字像？
3. **它和别的节点是什么关系？** 是包含、实例、先修、并行、易混、跨科迁移，还是考查/大纲映射？
4. **这个分类能不能被题验证？** 每个考点有没有题，每道题有没有考点，没有题的考点是“待命题”还是“不该存在”？

- **本轮不做**：不改 backend/data/question_bank.db，不改 backend/app/**，不改 src/**，不改 .vtj/**，不引入 Neo4j，不删除任何历史数据。

- **本轮不做**：不承诺“100% 大纲原生”。大纲有官方原文、官方转载、历年真题归纳、本地扩展四种证据等级，必须逐条标注。

## 2. 诊断：为什么 v1 的分类不够科学

### 2.1 实测基线（只读，2026-11-05）

数据源：backend/data/question_bank.db（SQLite，WAL，只读连接）。

| 指标 | 数值 | 说明 |
|---|---:|---|
| knowledge_point 总行数 | 1049 | 历史全部节点 |
| 启用节点 status=1 | 518 | 运行态实际使用 |
| 停用节点 status=0 | 531 | 历史标签/残留 |
| 启用二级 L2 | 91 | 全部有子节点 |
| 启用三级 L3 | 427 | 全部是叶子 |
| 启用四级 L4 | 0 | 旧库所谓“考点层”实际为空 |
| 停用二级 L2 | 425 | 其中 21 个无域 |
| 停用三级 L3 | 99 | 含 7 个 L4 的父级残留 |
| 停用四级 L4 | 7 | 全部是历史残留 |
| 启用“其他”L3 | 91 | 每个 L2 下恰好 1 个 |
| 剔除“其他”后的启用规范节点 | 91 L2 + 336 L3 = 427 | 本方案的规范基线 |
| 启用节点无域 | 0 | 启用树结构干净 |
| 启用 L2 无子 | 0 | 与旧口径“377 个 L2 无子”不同，旧口径混入了停用节点 |

**第一层结论**：启用树在“结构”上是干净的：91 个 L2 全部有子，427 个 L3 全部是叶子，没有无域节点。问题不在“树断了”，而在“树的语义层级放错了”，以及“题没有落到叶子上”。

### 2.2 题的现实：93.1% 的启用题在“其他”里

| 口径 | 题数 | 占可见题 3410 的比例 |
|---|---:|---:|
| 可见题总数 | 3410 | 100.0% |
| 只关联启用节点 | 2125 | 62.3% |
| 只关联停用节点 | 621 | 18.2% |
| 无任何知识点关联 | 664 | 19.5% |
| 启用题中挂在“其他” | 1979 | 58.0% |
| 启用题中挂在有意义叶子 | 146 | **4.3%** |

**第二层结论**：旧报告里的“80.5% 覆盖率”是把全部题、全部关联行混在一起算的，掩盖了三个事实：

1. 621 道可见题只挂在停用节点上，运行态等于“有分类但不可用”；
2. 664 道可见题完全没有知识点关联；
3. 2125 道“启用题”里有 1979 道挂在“其他”，真正有意义的只有 146 道。

按“可见题中落在有意义启用叶子”的口径，真实可用覆盖率是 **146 / 3410 = 4.3%**，不是 80.5%。

### 2.3 分域看：公专三个域几乎全部是残差

| 知识域 | 启用可见题 | 其中“其他” | 有意义叶子 |
|---|---:|---:|---:|
| 判断推理 | 109 | 52 | 57 |
| 言语理解与表达 | 72 | 38 | 34 |
| 常识判断 | 30 | 11 | 19 |
| 资料分析 | 21 | 10 | 11 |
| 政治理论 | 22 | 12 | 10 |
| 综合分析 | 8 | 4 | 4 |
| 知觉速度与准确性 | 5 | 2 | 3 |
| 数量关系 | 11 | 9 | 2 |
| 提出对策 | 6 | 4 | 2 |
| 议论文写作 | 10 | 8 | 2 |
| 应用文写作 | 5 | 4 | 1 |
| 归纳概括 | 8 | 7 | 1 |
| 公专职业素养 | 92 | 92 | 0 |
| 公专基础知识 | 1074 | 1074 | 0 |
| 公专基本警务能力 | 652 | 652 | 0 |
| **合计** | **2125** | **1979** | **146** |

这张表说明：**公专三个域 1818 道启用题全部在“其他”**；行测和申论也只是“部分有叶子”。这不是“再补一层 L4”能解决的，而是“题点归属体系没有建立”。

### 2.4 启用树的语义层级不统一

启用树在结构上都是“L2 → L3”，但 L2/L3 的语义在不同域完全不同：

| 域族 | 域 | 启用 L2 是什么 | 启用 L3 是什么 | 缺什么 |
|---|---|---|---|---|
| 甲类：知识树型 | 行测 | 题型/子模块（图形推理、逻辑判断、资料类型） | 知识点（位置规律、翻译推理、增长率） | 缺 L4 考点 |
| 甲类：知识树型 | 公专基础知识 | 法律门类（宪法、民法、行政执法、刑事执法） | 法律制度（行政处罚、行政许可、刑事立案） | 缺 L4 考点 |
| 乙类：任务素养型 | 申论 | 任务/能力项（问题概括、原因概括、观点分析） | 考点形态（单一问题、多重问题、深层含义） | 已有考点，缺“方法知识点” |
| 乙类：任务素养型 | 公专职业素养 | 价值/规范项（政治立场、核心价值观、职业纪律） | 考点形态（两个维护、忠诚、纪律条令） | 已有考点，缺“可教定义” |
| 乙类：任务素养型 | 公专基本能力 | 能力项（宣传教育、接警与处警、合理处置） | 考点形态（宣传方式、接警受理、武力使用） | 已有考点，缺“能力标准” |

**第三层结论**：不能用一个统一的“L2=知识点、L3=考点”模板套所有域。甲类需要“域→分组→知识点→考点”，乙类需要“域→知识点→考点”。强行统一，必然把“题型”当“知识点”、把“考点”当“知识点”。

### 2.5 7 个 L4 是历史残留，不是考点

停用的 7 个 L4：关联词→对策/并列/转折；特殊问法→其他/主题词；生物→其他；物理→其他。

它们不是“可命题的最小形态”，而是旧导入器把某些标签挂到了 L3 下面。把它们当“考点层”会误导后续建设。本方案明确：**启用 L4 当前为 0；甲类考点要新建，乙类考点由现有 L3 升级。**

### 2.6 旧 Obsidian 构建脚本的映射错误

D:/Obsidian仓库/.qpkg_build/data.py 的关键逻辑：

- p['layer'] = '考点' if p['level'] == 4 else '知识点'：把 L2/L3 全部叫“知识点”，把 L4 叫“考点”；
- card_path：level != 4 放 05-知识点/kp_####，level == 4 放 06-考点/ep_####；
- 查询 knowledge_point 未加 status=1：把 531 个停用节点也做成卡片；
- 结果：1042 张“知识点”卡 + 7 张“考点”卡，其中 531 张是停用标签，91 张是“其他”。

D:/Obsidian仓库/.qpkg_build/cards.py 仍用英文前缀与英文 frontmatter 键：sub_、dom_、kp_、ep_，node_type、subject、domain、status、updated、tags。这直接违背“全部中文命名”。

### 2.7 运行态与设计态的口径不一致

backend/app/api/v1/exam/quick_practice.py 在 130/137/162/191/303/390 行过滤 status == 1（科目/域/知识点/题）。所以：

- 运行态：518 个启用知识点；
- 旧 Obsidian：1049 个节点、1042 张知识点卡；
- 两者相差 531 个停用节点。

这不是“多展示一点”，而是设计态把运行态不存在的节点当成了规范。必须 active-only。

### 2.8 图运行态的边是“结构自动边”，不是“学习语义边”

backend/app/foundation/graph_builder.py 生成三类边：

1. 父→子 PREREQUISITE_OF，derivation=hierarchy，533 条；
2. 同父兄弟两两 PARALLEL_WITH，derivation=siblings，1046 条；
3. 题→点 INSTANCE_OF，derivation=question_knowledge，2775 条。

这里有三处语义错误：

- 父→子是“包含”，不是“先修”；把包含当先修，会让 AI 把“科目”当成“知识点的前置”。
- 同父兄弟不是“并行”；兄弟只是同一个父下的并列项，不代表同一场景协同。1046 条兄弟并行边是噪声。
- 题→点是“考查”，不是“实例”；实例化应是“考点→知识点”，题→考点应是“考查”。

默认图存储是 local SQLite，不是 Neo4j；当前 3823 节点/4354 边远未到必须上 Neo4j 的规模。v2 继续用 local，Neo4j 只作为可选适配器，不进入本轮。

### 2.9 根因：四个“类别错误”

| # | 类别错误 | 表现 | 后果 |
|---|---|---|---|
| E1 | 把“停用标签”当“知识节点” | 531 个停用节点做成卡片 | 知识库膨胀、噪声压过信号 |
| E2 | 把“层级深度”当“知识类型” | L2/L3 一律叫知识点，L4 才叫考点 | 题型、法律制度、考点混为一谈 |
| E3 | 把“结构自动边”当“学习语义边” | 父子=先修、兄弟=并行、题→点=实例 | AI 推荐路径被结构噪声污染 |
| E4 | 把“大纲模块”等同于“知识树” | 大纲模块直接当域后不再拆知识点/考点，也不建大纲映射；科学推理未证实也照搬 | 无法回答“到底教什么、怎么考” |

**结论**：v2 不是 v1 的“补丁”，而是分类层的重建；v1 的 Obsidian 基础设施、收件箱、评审、编译、健康度可以保留，但分类模型、卡片生成、命名、题点关系必须换掉。

## 3. 设计原则：十二条不变量

### P1 事实源唯一

SQLite 是唯一事实源；Obsidian、图库、JSONL、Canvas 都是可重建投影。任何在 Obsidian 里改的内容，必须能编译成受控补丁，经评审后写回 SQLite，而不是“以 Markdown 为准”。

**推论**：卡片丢失可以从数据库重建；数据库被 Markdown 覆盖则是事故。编译方向永远是“库 → 卡片”，回写方向永远是“卡片 → 补丁 → 人工批准 → 库”。

### P2 启用优先

规范分类只使用 status=1 的节点。status=0 的 531 个节点进入 99-归档/停用节点索引，不建正式知识卡、不进编译、不进健康度分母。

**推论**：任何统计必须写明是“启用口径”还是“全量口径”。旧报告的 80.5% 就是混用口径的产物。

### P3 类型先于层级

先判断“这个对象是什么”，再决定它放在第几层。科目、知识域、知识点、考点是四种类型；分组、大纲条目、题目、能力/情境是辅助对象。层级深度是结果，不是分类依据。

**反例**：把“图形推理”叫知识点（它其实是分组），把“位置规律”叫考点（它其实是知识点），把“行政处罚”叫考点（它其实是知识点）。这些都是“按深度命名”造成的。

### P4 两种结构族，不强行统一

- **甲类知识树型**：行测、公专基础知识。结构为“知识域 → 分组 → 知识点 → 考点”。分组是题型/法律门类，不是知识节点；知识点是可教学单元；考点是可命题形态。
- **乙类任务素养型**：申论、公专职业素养、公专基本能力。结构为“知识域 → 知识点 → 考点”。知识点是任务/能力项；考点是具体任务形态或行为标准。官方门类只作为域内小节，不单独立卡。

**推论**：不能用同一张模板套所有域；模板必须按结构族选择。

### P5 粒度以“可教学、可命题”为准

知识点是“可教学的最小单元”：能独立讲清一个概念、规则、方法或能力标准。考点是“可命题的具体形态”：能对应至少一种题型、一个作答动作、一个可判分的错误模式。

**推论**：不能因为“大纲里有这句话”就建一个知识点；也不能因为“题库里有这道题”就建一个考点。两者都不满足时，进收件箱讨论。

### P6 语义关系必须有证据

先修、并行、易混、跨科迁移四类语义边，必须写清“依据类型、依据文本、评审人、评审日期”。没有证据的边只能停留在候选区，不能进入规范图。

**推论**：父→子是包含，不是先修；同父兄弟不是并行；题→点是考查，不是实例。结构自动边不得冒充学习语义边。

### P7 大纲是可追溯的参考层

每个知识点/考点至少映射到一条大纲条目；每条大纲条目记录“年度、科目、模块、原文、来源等级”。来源等级分四级：官方原文、官方转载、历年真题归纳、本地扩展。

**推论**：允许“本地扩展”，但必须标注，不得宣称“100% 大纲原生”。公专“基本警务能力”应改称“基本能力”，并在卡片里保留旧名作为别名。

### P8 题是分类的验收器

一个考点是否成立，最终要看“有没有题、题是否能区分、错题能否归因”。每个考点必须有“题数、题簇、典型错因、最近校验日期”；长期无题的考点要标记“待命题”或“待退役”，不能静默存在。

**推论**：分类不是先建完再找题，而是“题簇 → 候选考点 → 评审 → 建卡 → 回链题目”的闭环。

### P9 全中文命名与稳定 ID

目录、文件名、卡片标题、属性键、标签值全部中文；仅 Obsidian 协议键 tags、aliases 保留英文。ID 一旦分配不再改变；改名只改标题，不改 ID。

**推论**：文件名是“类型-编号-名称”，ID 是“类型-科目-序号”；两者分离，避免改名导致双链断裂。

### P10 小步、可回滚、可审计

每次变更只做一类事；每次写库前备份；每次编译产出 manifest、diff、回滚脚本；每次评审留记录。禁止“一次性大洗牌”。

**推论**：P1 只读建库；P2 只建覆盖层；P3 只回链乙类题；P4 只补甲类考点；P5 才写库/改代码，且再次审批。

### P11 自生长不等于自动改库

Obsidian 可以自动发现断链、孤立、粒度异常、题点缺口，也可以自动生成候选边；但“接受候选”必须由人确认。AI 只写 00-收件箱，不直接改规范卡。

### P12 可视化是审计工具，不是装饰

Canvas 用来审“结构是否成立”，Dataview 用来审“数字是否成立”，Mermaid 用来审“关系是否成立”。任何图都必须能追溯到卡片和查询；不能用手绘示意图代替数据。

## 4. 本体：四类节点、两类结构、八个关系

### 4.1 四类知识节点

| 类型 | 定义 | 判定问题 | 例子 | 不应该是 |
|---|---|---|---|---|
| 科目 | 考试科目，分类的最高容器 | 这是不是一门独立考试科目？ | 行测、申论、公专 | 知识域、题型 |
| 知识域 | 科目下的稳定知识板块，通常与大纲模块对应 | 这是不是一组同质知识/能力的集合？ | 判断推理、基础知识、基本能力 | 单个知识点、题型 |
| 知识点 | 可教学的最小单元 | 能不能独立讲 10–30 分钟？ | 位置规律、行政处罚、接警受理 | 题型分组、单道题、宽泛模块 |
| 考点 | 可命题的具体形态 | 能不能对应一种题型/作答动作/错误模式？ | 图形推理-位置规律-平移方向判定 | 知识点本身、题干、解析 |

**辅助对象（不是知识节点）**：

| 辅助对象 | 作用 | 存放位置 | 是否进图 |
|---|---|---|---|
| 分组 | 甲类的导航层（题型/法律门类） | 03-分类/03-分组 | 只作结构属性，不作知识边 |
| 大纲条目 | 官方依据 | 02-大纲 | 通过“大纲映射”边连接 |
| 题目 | 证据 | 不建卡，存题号与统计 | 通过“考查”边连接 |
| 能力/情境/题型 | 属性标签 | 卡片属性或域内小节 | 不作节点 |

**关键区分**：分组是“结构卡”，有卡片、有导航、有排序，但不是“知识节点”，不参与先修/并行/易混等学习语义边。这样既保留导航清晰度，又避免把题型当知识。

### 4.2 两类结构族

#### 甲类：知识树型（行测、公专基础知识）

~~~text

        └── 知识点（可教学单元）
            └── 考点（可命题形态）
~~~

~~~text
行测

    └── 图形推理（分组）

            ├── 旋转角度与方向判定（考点）
            └── 翻转与叠加判定（考点）
~~~

示例（公专基础知识）：

~~~text
公专
└── 基础知识
    └── 行政执法（分组）
        └── 行政处罚（知识点）
            ├── 处罚种类与设定权限（考点）
            ├── 处罚程序与时效（考点）
            └── 当场处罚适用条件（考点）
~~~

#### 乙类：任务素养型（申论、公专职业素养、公专基本能力）

~~~text
科目
└── 知识域
    └── 知识点（任务/能力项）
        └── 考点（任务形态/行为标准）
~~~

~~~text
申论
└── 归纳概括
    └── 问题概括（知识点）
        ├── 单一问题概括（考点）
        ├── 多重问题概括（考点）
        └── 问题表现概括（考点）
~~~

示例（公专基本能力）：

~~~text
公专
└── 基本能力
    └── 接警与处警（知识点）
        ├── 接警受理与登记（考点）
        ├── 处警现场判断（考点）
        └── 警情升级与移交（考点）
~~~

### 4.4 知识点准入标准

一个候选对象要成为知识点，必须同时满足：

1. **可教学**：能独立形成 10–30 分钟的教学单元，有定义、规则/方法、正例、反例。
2. **可命题**：至少能对应一种题型或作答动作；不要求当前有题，但必须能说清“怎么考”。
3. **原子性**：不能再拆成两个都需要独立教学的同级单元；如果能拆，说明它是分组或域。
4. **互斥性**：在同一父节点下，与同级知识点不重叠；重叠部分必须上提到父级或拆成“共同基础”。
5. **稳定性**：不随单道题、单次考试、单个教材版本变化；年度热点应放考点或大纲条目，不轻易升为知识点。
6. **依据性**：至少有一条大纲条目、教材章节或权威规范作为依据；本地扩展须标注。

**不合格的典型**：

- “其他”“综合”“常见”“特殊”“待定”：无定义、无边界，是残差桶；
- “图形推理”“言语理解”：是分组/域，不是知识点；
- “2024 年某会议”：是时事考点，不是稳定知识点；
- “行政处罚法”：是法律/教材单元，可作为知识点；但“行政处罚”本身要拆到“种类/程序/管辖/时效”等可教学单元。

### 4.5 考点准入标准

一个候选对象要成为考点，必须同时满足：

1. **可命题**：能写出至少一种题干形态（单选/多选/情境/材料/写作任务）。
2. **可判分**：有明确的正确答案、评分点或行为标准；情境题要有“关键动作/禁止动作”。
3. **可归因**：学生做错时，能指向一个具体的知识盲区或能力缺陷，而不是“粗心”。
4. **可区分**：与同父下其他考点有可辨识的命题差异；不能只是换数字、换材料。
5. **有边界**：能说出“考什么、不考什么”；不能用“综合运用”一笔带过。
6. **有证据**：至少有一道题、一条大纲样题、一条官方说明或一个题簇支撑；没有证据的只能进候选区。

**考点命名公式**：对象 + 动作/判断 + 限定条件。

- 好：行政处罚-当场处罚-数额上限判定；
- 好：图形推理-位置规律-平移方向与步长判定；
- 差：行政处罚（太宽，是知识点）；
- 差：图形推理（太宽，是分组）；
- 差：其他（无边界）。

### 4.6 基数、深度与宽度

| 关系 | 基数 | 约束 |
|---|---|---|
| 科目 → 知识域 | 1..n | 每个域必须且只属于一个科目 |
| 知识域 → 分组 | 0..n | 仅甲类；分组必须属于一个域 |
| 分组 → 知识点 | 1..n | 仅甲类；一个知识点只属于一个分组 |
| 知识域 → 知识点 | 1..n | 仅乙类；一个知识点只属于一个域 |
| 知识点 → 考点 | 0..n | 允许暂时为 0，但必须标记“待命题” |
| 考点 → 知识点 | 1..1 | 一个考点只能实例化一个知识点 |
| 题目 → 考点 | 0..n | 一道题原则上只挂一个主考点；多考点须标注主次 |

**深度**：甲类知识路径为 4 段（科目/域/分组/知识点/考点中的知识段为 4），乙类为 3 段。超过 4 段说明中间层没抽象好；少于 2 段说明还没拆到可教学单元。

**宽度**：同一父节点下直接子节点建议 3–9 个；超过 9 个先考虑分组，少于 3 个先考虑合并或上提。该数值是评审提示，不是硬拒绝；但连续超过 12 个必须说明理由。

**跨域边预算**：每个知识点最多 5 条语义边（先修/并行/易混/跨科迁移合计），每个域最多 30 条跨域边；超过预算必须走专题评审，防止“关系网”变成“关系噪声”。

### 4.8 生命周期

| 状态 | 含义 | 是否进规范图 | 是否进编译 | 是否可被题引用 |
|---|---|---|---|---|
| 草稿 | 收件箱/评审中 | 否 | 否 | 否 |
| 启用 | 已评审、现行 | 是 | 是 | 是 |
| 停用 | 历史保留、不再教学 | 否 | 否 | 仅历史题 |
| 已合并 | 被新节点取代 | 否 | 否 | 通过别名指向新节点 |
| 待命题 | 启用但无题 | 是 | 是 | 是（空题集） |

**规则**：

1. 停用不删除；卡片移到 99-归档/停用节点，保留原始 ID 与别名。
2. 合并必须写“合并到、合并依据、影响题数”，并生成别名，保证旧链接可跳转。
3. 任何启用节点必须有评审人、评审日期、大纲依据；缺一不可。
4. 任何考点若无题超过一个评审周期，标记“待命题”；连续两个周期无题且无大纲样题，进入退役评审。

| G1 | 每个知识域只属于一个科目 | 父链唯一性 | 域重复、统计翻倍 |
| G2 | 每个知识点只属于一个父（分组或域） | 父链唯一性 | 同一知识多处定义 |
| G3 | 每个考点只实例化一个知识点 | 实例边唯一 | 考点归属不清 |
| G4 | 甲类知识点必须有分组；乙类知识点不得有分组 | 结构族校验 | 结构混用 |
| G5 | 先修边构成有向无环图 | 拓扑排序/环检测 | 学习路径死循环 |
| G6 | 并行边对称且同域优先 | 对称闭包/跨域标记 | 伪并行噪声 |
| G7 | 易混边必须双向且附差异说明 | 双向检查/文本必填 | 易混无教学价值 |
| G8 | 跨科迁移边必须附共享能力与证据 | 证据字段必填 | 跨科关系空泛 |
| G9 | 每个启用考点至少有一条大纲依据 | 大纲映射检查 | 无依据的“野考点” |
| G10 | 每个启用知识点至少有一个考点或“待命题”标记 | 子节点检查 | 教学单元无法验收 |

## 5. 大纲对齐：参考层，不是分类树

### 5.1 来源等级

| 等级 | 定义 | 可用场景 | 必须标注 |
|---|---|---|---|
| A 官方原文 | 公安部/人社部/公务员局发布的当年度大纲原文 | 规范依据、验收依据 | 年度、文号、URL、抓取日期 |
| B 官方转载/改革说明 | 省级公安厅、人事考试网等官方渠道转载，或官方改革说明 | 辅助依据；原则上需两条互证 | 来源机构、URL、日期 |
| C 历年真题归纳 | 对历年真题的统计归纳 | 考频、题型、命题形态 | 样本年份、样本量、方法 |
| D 本地扩展 | 教研团队自建 | 教学补充、本地化 | 负责人、理由、复核日期 |

## 6. 八个关系：定义、方向、证据

### 6.1 关系总表

| 关系 | 方向 | 起点 → 终点 | 含义 | 证据要求 | 是否自动生成 |
|---|---|---|---|---|---|
| 包含 | 有向 | 父 → 子 | 结构归属 | 父链唯一 | 可由结构生成，但不作学习边 |
| 实例 | 有向 | 考点 → 知识点 | 考点是知识点的具体命题形态 | 定义、题型、样例 | 人工确认 |
| 先修 | 有向 | 知识点/考点 → 知识点/考点 | 学 B 前应先掌握 A | 依据文本、评审 | 人工审定 |
| 并行 | 无向 | 同域/跨域节点 | 同一场景协同出现 | 场景说明、题簇 | 人工审定 |
| 易混 | 双向 | 同域节点 | 容易混淆，需对比教学 | 差异点、反例 | 人工审定 |
| 跨科迁移 | 无向 | 跨科节点 | 共享底层能力，可迁移 | 共享能力、题簇 | 人工审定 |
| 考查 | 有向 | 题目 → 考点 | 题目测的是哪个考点 | 题号、主次 | 可由题点关联生成 |
| 大纲映射 | 有向 | 知识点/考点 → 大纲条目 | 官方依据 | 条目 ID、年度 | 人工确认 |

### 6.2 包含（结构边）

- 方向：科目 → 知识域 → 分组 → 知识点 → 考点；乙类为科目 → 知识域 → 知识点 → 考点。
- 语义：只是“归属”，不是“学习顺序”。
- 约束：每个子节点只有一个父；父链必须能上溯到科目。
- 反模式：把包含写成先修；把分组写成知识点；把考点挂到域下跳过知识点。

### 6.3 实例（考点 → 知识点）

- 方向：考点 → 知识点。
- 语义：这个考点是那个知识点的具体命题形态。
- 例子：考点“当场处罚的数额上限判定”实例化知识点“行政处罚”。
- 约束：一个考点只能实例化一个知识点；一个知识点可以有多个考点。
- 反模式：题 → 点叫实例（应为考查）；考点 → 域（跳过知识点）；一个考点挂多个知识点（应拆考点或上提共同知识点）。

### 6.4 先修（学习依赖）

- 方向：A → B 表示“学 B 前应先掌握 A”。
- 例子：法学基础理论 → 宪法 → 行政执法 → 行政处罚；基础运算 → 资料分析-增长率。
- 证据：教材章节顺序、大纲顺序、题簇错误传递、教研评审。至少两项。
- 约束：必须有向无环；跨域先修要标注“跨域”；先修深度建议不超过 3 跳。
- 反模式：父 → 子当先修；同父兄弟互为先修；把“相关”当“先修”；无证据的“常识性”先修。

### 6.5 并行（场景协同）

- 方向：无向，A 与 B 并行。
- 语义：在同一执法场景/同一材料/同一解题流程中协同出现，但不是先后依赖。
- 例子：情报分析 与 警务战术 在情景案例中联合考查；言语-主旨概括 与 判断-削弱加强 共享阅读理解。
- 证据：同一道情境题、同一材料、同一教学模块、同一能力标准。
- 约束：同域优先；跨域并行必须写共享场景；每个节点并行边不超过 3 条。
- 反模式：同父兄弟自动并行；把“同属一个域”当并行；把“先修”反向当并行。

### 6.6 易混（对比教学）

- 方向：双向。
- 语义：两个知识点/考点在概念、程序、适用条件上容易混淆，需要对比教学。
- 例子：行政处罚 与 行政强制；盘查 与 继续盘问；犯罪中止 与 犯罪未遂。
- 证据：差异点清单、反例、常见错因、题簇。
- 约束：必须双向；必须写“差异点”和“判定关键”；不能只写“易混”。
- 反模式：把“相关”当“易混”；只连边不写差异；跨域易混无说明。

### 6.7 跨科迁移（认知共享）

- 方向：无向。
- 语义：两科共享底层能力，学会 A 有助于 B。
- 例子：行测-逻辑判断-假言推理 与 公专-基础知识-执法依据适用；申论-综合分析 与 公专-事态研判。
- 证据：共享能力说明、题簇、教学实验或专家评审。
- 约束：全库不超过 30 条；每条必须有“共享能力、迁移方向、证据、评审”。
- 反模式：为“关系网密集”而连边；把“都考阅读”当跨科迁移；无证据的“相互促进”。

### 6.8 考查（题目 → 考点）

- 方向：题目 → 考点。
- 语义：这道题主要测哪个考点。
- 约束：一道题一个主考点；最多两个次考点；主次必须标注；没有合适考点进“待归类题池”。
- 反模式：题 → 知识点（跳过考点）；一题挂多个主考点；为覆盖率强行挂“其他”。

### 6.9 大纲映射（节点 → 大纲条目）

- 方向：知识点/考点 → 大纲条目。
- 语义：这个节点的官方依据。
- 约束：启用节点至少一条；一条大纲条目可映射多个节点；年度版本必须匹配。
- 反模式：把大纲模块直接当知识点；用旧年度大纲支撑新考点；无原文链接。

### 6.10 边台账字段

每条语义边必须登记在 04-关系/01-边台账.md，字段如下：

| 字段 | 必填 | 说明 |
|---|---|---|
| 关系编号 | 是 | 边-类型-四位序号，如 边-先修-0001 |
| 关系类型 | 是 | 先修/并行/易混/跨科迁移 |
| 起点 | 是 | 节点 ID + 标题 |
| 终点 | 是 | 节点 ID + 标题 |
| 依据类型 | 是 | 大纲/教材/题簇/专家评审 |
| 依据文本 | 是 | 原文摘录或题号列表 |
| 共享能力 | 跨科必填 | 如“假言推理” |
| 差异点 | 易混必填 | 至少 2 条 |
| 评审人 | 是 | 姓名/角色 |
| 评审日期 | 是 | 日期 |
| 状态 | 是 | 候选/启用/停用 |
| 版本 | 是 | 如 2026.1 |

### 6.11 候选边流程

1. 机器生成候选：同题簇、同材料、同错因、同大纲条目。
2. 写入 04-关系/06-候选边.md，状态=候选。
3. 教研评审：接受/拒绝/改写；拒绝要写理由。
4. 接受后写入边台账，状态=启用；拒绝的保留 30 天再归档。
5. 编译进 edges.jsonl；不直接改图谱。

### 6.12 关系反模式

| 反模式 | 为什么错 | 纠正 |
|---|---|---|
| 父 → 子 = 先修 | 包含不是学习顺序 | 用包含边；先修另建 |
| 同父兄弟 = 并行 | 并列不等于协同 | 删除自动并行；按场景重建 |
| 题 → 点 = 实例 | 题是证据，不是实例 | 题 → 考点=考查；考点 → 知识点=实例 |
| 一个考点挂多个知识点 | 归属不清 | 拆考点或上提共同知识点 |
| 跨科边越多越好 | 噪声压过信号 | 全库上限 30，逐条证据 |
| 易混只连边不写差异 | 无法教学 | 必填差异点与判定关键 |
| 先修成环 | 学习路径死循环 | 拓扑排序阻断 |
| 大纲模块 = 知识域 | 参考层与分类树混同 | 建大纲条目层，映射连接 |

### 7.1 数据债全貌

**结论**：当前不是“分类覆盖 80.5%”，而是“可诊断覆盖 4.3%”。v2 的所有迁移动作，都以提高“有意义题点覆盖”为目标，而不是提高“挂接率”。

### 7.2 什么是题簇

题簇不是“按题号分组”，而是“围绕同一考点、具有相同作答动作和错误模式的一组题”。一个题簇至少包含：

- 3 道以上同考点题（情境题可 1–2 道）；
- 同一作答动作（判断/选择/排序/计算/写作/处置）；
- 同一错误模式（概念混淆/条件遗漏/程序错序/计算失误/材料误读）；
- 可命名的考点候选。

题簇的生成方式（按优先级）：

1. 现有题目的显式标签/知识点关联；
2. 题干与选项的规则特征（题型、问法、关键词）；
3. 解析中的“考点句”抽取；
4. 教研人工抽样与聚类；
5. embedding 相似度只作候选召回，不作最终判定。

**边界**：不追求全自动。题簇是“候选生成器”，最终考点由教研评审确认。

### 7.3 三条迁移线

#### 线一：乙类回链（771 道可见残差题）

对象：申论“其他”27 道、职业素养“其他”92 道、基本能力“其他”652 道。

做法：

1. 以现有 165 个规范乙类考点为候选集；
2. 逐题判断“主考点 + 次考点（可选）”；
3. 能归则归；不能归的进“待归类题池”，并给出候选考点与理由；
4. 零新建节点；如确有新考点，进收件箱，不在本轮直接建。

验收：

- 771 道全部有处置结论（已归/待归类/建议新考点）；
- 已归题的主考点必须是启用考点；
- 待归类题必须写“缺什么信息”；
- 不出现“其他”作为答案。

#### 线二：甲类题簇（1208 道可见残差题）

对象：行测“其他”134 道、公专基础知识“其他”1074 道。

做法：

1. 先按分组（题型/法律门类）分桶；
2. 在每个桶内做题簇，命名候选考点；
3. 候选考点必须能写出“题干形态、作答动作、错误模式、大纲依据”；
4. 评审通过后建考点卡，再把题回链；
5. 不能成簇的题进“待归类题池”，不强行建考点。

验收：

- 每个新建考点至少有 2 道题或 1 道情境题支撑；
- 每个新建考点有唯一父知识点；
- 题的主考点不超过 1 个；
- 新增考点数量不预设，以题簇为准。

#### 线三：残差定性（621 + 664 道可见题）

对象：只挂停用点的 621 道、无 qk 的 664 道。

做法：

1. 先判“题是否有效”（重复题、错题、废弃题、无图题）；
2. 有效题进入对应线一/线二；
3. 无法归类的进“待归类题池”，按原因分类；
4. 废弃题不删除，标“停用/重复”，保留题号与原因。

验收：

- 621 + 664 全部有处置结论；
- 不把“停用点”当规范点；
- 不把“无 qk”直接归到“其他”。

### 7.4 题点映射规则

| 规则 | 内容 |
|---|---|
| R1 | 一道题一个主考点；主考点必须启用 |
| R2 | 最多两个次考点；次考点只用于诊断，不用于覆盖率主口径 |
| R3 | 没有合适考点时进“待归类题池”，不挂“其他” |
| R4 | 题的知识点由考点反推，不直接挂知识点 |
| R5 | 情境题可以跨知识点，但主考点只能一个 |

| R7 | 停用题不参与覆盖率，但保留历史关联 |
| R8 | 任何映射变更记录“原考点、新考点、理由、评审人、日期” |

### 8.4 首页设计

首页不是“目录复制”，而是“决策面板”。必须包含：

1. **一句话定位**：这是什么库、给谁用、不是什么。
2. **七个数字**：科目、知识域、规范化知识点、规范化考点、题点覆盖率、待归类题、断链数。
3. **三条入口**：我要找知识、我要改分类、我要看健康度。
4. **今日待办**：收件箱待处理、评审待办、待命题考点、断链。
5. **边界提醒**：AI 只写收件箱；写库需审批；停用不删除。
6. **最近变更**：5 条变更日志。
7. **五张 Canvas 入口**。

**数字必须由编译生成**，不能手填；手填数字视为缺陷。

## 9. 治理与自生长：人机边界、评审、编译、回滚

### 9.1 收件箱三段式

每个请求必须写清：

1. **改什么**：节点 ID、字段、原值、新值。
2. **为什么**：大纲依据/题簇/错因/专家意见；附证据。
3. **影响什么**：影响多少题、哪些考点、是否需要迁移；附回滚方案。

缺任意一段，评审直接退回。

### 9.2 角色与 RACI

| 角色 | 职责 | 能改什么 | 不能改什么 |
|---|---|---|---|
| 教研专家 | 定义、边界、考点命名、题簇判定 | 收件箱提案、评审意见 | 运行库、代码 |
| 知识工程师 | 结构、ID、模板、编译、健康度 | 规范卡、编译配置 | 教研结论、运行库 |
| 题库管理员 | 题点关联、题池处置 | 题点提案 | 分类定义、代码 |

| AI 助手 | 生成候选、检查、编译、报告 | 00-收件箱、06-编译产出 | 规范卡、运行库、删除 |

RACI 简表：

| 动作 | 教研 | 知识工程 | 题库 | 合作伙伴 | AI |
|---|---|---|---|---|---|
| 新增知识点 | A | R | C | C | C |
| 新增考点 | A | R | C | C | C |
| 题点回链 | C | I | A/R | I | C |

| 编译发布 | I | A/R | I | I | R |
| 写运行库 | A | R | C | I | 禁止 |

A=批准，R=执行，C=咨询，I=知情。

### 9.4 变更日志双轨

- 人读：08-治理/02-变更日志/YYYY-MM.md，按日期记录“谁、改了什么、为什么、影响”。
- 机读：08-治理/02-变更日志/changes.jsonl，一行一条，字段：时间、类型、对象、动作、前值、后值、评审人、请求ID。

**规则**：没有机读记录的变更，视为未发生；没有变更日志的发布，视为违规。

### 9.5 编译流水线

~~~text
规范卡（启用）
  → 解析 frontmatter
  → 生成 nodes.jsonl
  → 解析关系文件/边台账
  → 生成 edges.jsonl
  → 生成 graph_plan.json
  → 生成 syllabus_matrix.json
  → 生成 health_report.json
  → 校验（断链/环/基数/大纲/题点）
  → validation_report.md
  → diff_report.md
  → manifest.json（哈希）
  → 评审
  → 发布到 06-编译产出
~~~

**校验阻断项**：

- 断链 > 0；
- 先修环 > 0；
- 启用节点缺大纲依据；
- 考点缺父知识点；
- 甲类知识点缺分组；
- 文件名不符合规范；
- 出现“其他/待定”规范卡；
- 卡片数与本文件口径不一致。

### 9.6 写库与回滚（P5 才允许）

1. 生成 sql_patch.sql，只包含 qp_kg_* 覆盖层或受控字段更新。
2. 备份：sqlite3.backup() 生成带时间戳的备份；校验完整性。
3. dry-run：在副本上执行补丁，跑回归查询。
4. 人工批准：教研 + 知识工程 + 题库管理员三方签字。
5. apply：事务执行；失败回滚。
6. 验证：题点覆盖、断链、API 抽查。
7. 回滚：恢复备份 + 删除 -wal/-shm；记录事故报告。

**禁止**：用文件拷贝代替 sqlite3.backup()；直接改生产库；无 diff 的批量更新；删除历史节点。

### 9.7 AI 边界

- AI 只能写 00-收件箱、06-编译产出、08-治理/03-健康度 的报告。
- AI 不得直接改 03-分类、04-关系 的规范卡。
- AI 不得删除任何卡片/节点/题。
- AI 不得写运行库、不得改代码，除非用户单独批准。
- AI 生成的候选必须标注“AI 候选”，并给出证据与置信度。

### 9.8 冲突解决

证据优先级：A 级大纲原文 > B 级官方转载 > 题簇实证 > 专家共识 > C 级真题归纳 > D 级本地扩展。

冲突处理：

1. 先对齐“问题是什么”（定义/边界/命名/归属）。
2. 找最高等级证据；没有则补证据。
3. 仍不能解决，提交专题评审，记录分歧与理由。
4. 不做“少数服从多数”；以证据和可测试性为准。

### 9.9 版本

- 库版本：2026.1、2026.2；大版本按年度大纲，小版本按季度。
- 卡片版本：随库版本；单卡重大修改可加 .1。
- 编译产物带 manifest 哈希；发布记录写版本、时间、变更数、校验结果。

### 13.3 本方案的证据强度

**强证据（A/B 级）**：

- 数据库结构、数量、题点关联：SQLite 实测；
- 公专三块九目：2026 年度官方大纲；
- 运行态 status=1 过滤：quick_practice.py 实测；
- 图边生成逻辑：graph_builder.py 实测；
- 旧 Obsidian 映射错误：data.py/cards.py 实测。

**中等证据（B/C 级）**：

- 行测“政治理论”为 2025 改革新增：2025 国考公共科目大纲原文 + 公安联考改革说明互证，从常识判断单列，约 15 题/10 分钟（以联考官方原文为准）；联考原文待补，标 B 级，不得标 D 级；
- 申论五种能力与题型映射：基于官方表述与题型归纳，需教研确认；
- 跨科迁移候选：基于能力相似性，需题簇/教学实验。

**弱证据/未决**：

- 行测“科学推理”未在联考大纲中得到证实：暂标 D 级/待确认，不得写成官方模块；
- 甲类考点具体数量与命名：必须由题簇生成，当前不预设；
- 91 个“其他”题的最终归属：必须逐题判断，当前只有总量；
- 合作伙伴的实际使用效果：需试点后评估。

**结论**：本方案在“结构、口径、迁移顺序”上是强证据；在“具体考点命名、跨科边、题簇质量”上必须依赖后续评审。不得把后者写成已确定事实。
