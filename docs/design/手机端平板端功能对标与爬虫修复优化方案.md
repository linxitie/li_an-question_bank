## 二、根因分析（含代码证据）

### 2.1 新闻笔记标注缺失 + 内容为空

**PC 端已实现完整笔记标注**（`.vtj/vue/daily_news.vue`）：
- 5 色划线（`#FFD700/#4CAF50/#2196F3/#EF4444/#8B5CF6`）+ 3 线型（wavy/straight/marker/box）
- 选中文字弹出操作菜单 → 划线/想法笔记 → 自动保存
- 调用接口：`POST /api/news/{id}/note`、`GET /api/news/{id}/notes`、`DELETE /api/news/notes/{id}`

**移动/平板端缺失根因**：
- 移动/平板端页面清单中**没有新闻详情页**（仅有 `mobile_home.vue`/`tablet_home.vue` 的新闻列表 `newsList`）
- `mobile_home.vue` 第 284 行 `viewNews` 跳转 `/news/{id}`，`tablet_home.vue` 第 380 行跳转 `/news/{id}`——**该路由在 `src/router/index.ts` 中不存在** → 点击 404
- 后端 `/api/news` 列表接口**已返回完整 content**（news.py 第 72 行 `"content": a.content or ""`，实测 1927/1934 条非空），故"内容为空"的本质是**前端无详情页渲染 content**

### 2.2 招考信息数据过期

**数据现状**（实测数据库）：
- 6 个分类共 787 条，`create_time` **全部为 2026-09-13 12:42:19**（最近一次成功替换的时间）

**爬虫日志证据**（2026-09-15）：
- `19:14` 开始爬"国考省考"，`19:15` 连接错误 `Read timed out`，`19:16` 详情页请求超时，`19:22` 国考省考"成功 178 条"，`19:23` 事业单位"5/5 页 28 条"……
- 但**数据库数据仍停在 9-13** → 说明 9-15 的爬取**未完成原子替换**

**根因**（`recruitment_scraper.py` 的 `scrape_all_recruitment`）：
1. **"先爬后清"策略**：必须 6 个分类**全部爬取成功**才执行 `DELETE 旧数据 → INSERT 新数据` 的原子替换；任一分类失败/超时 → 整体保留旧数据（第 604 行 `else: 保留现有数据不变`）
2. **详情页逐条串行抓取**：每个详情页 0.5~1.5s 延迟 + 30s 超时 × 3 次重试，6 分类数百条详情页 → 单次全量爬取耗时数小时，期间极易超时中断
3. 因此数据长期停留在某次"恰好全部成功"的 9-13 快照

### 2.3 考试日历数据缺失 + 平板端展示问题

**根因**：
1. **真实日历数据仅 4 条**：`exam_scraper.py` 依赖 Playwright 抓详情页（`shiyebian.com`），且 `cleanup_expired_exams` 会硬删除"注册已截止且超 1 天"的记录 → 数据被清理到只剩 4 条
2. **平板端接入错误 API**：`tablet_home.vue` 第 357 行日历数据来自 `/api/stats/calendar`（`stats.py` 第 200 行的**静态硬编码 5 条**，如"2026-06-15 公安联考"），而非真实接口 `/api/calendar/exams`（`calendar.py` 第 66 行，读 `exam_calendar` 表）
3. **跳转路由 404**：`tablet_home.vue` 第 381-382 行 `viewAllRecruit`→`/recruit`、`viewRecruit`→`/recruit/{id}`，路由不存在

### 2.4 三端通信不紧密

- 后端已有 WebSocket 基础设施（`websocket.py`：`/ws/connect`、房间机制、`broadcast`、`notify`、在线用户），但**前端未接入**用于三端数据同步
- 当前三端数据同步仅依赖：页面切换时的 API 请求 + 手动刷新，无实时推送

### 2.5 风格对标

- PC 端设计令牌（`login.vue`）：主强调色 `#C91F37`（红）+ 品牌深蓝 `#1A365D/#0F3460` + 中性灰 `#F5F7FA/#1a2a3a` + 字体 `PingFang SC/Microsoft YaHei/Noto Sans SC`
- 移动/平板端部分页面仍用旧令牌（金色 `#d4a843`、`#1A365D` 单色），需统一

### 2.6 移动/平板端登录无角色限制（问题 6）

**现状根因**：
1. `/api/auth/login`（`auth.py` 第 91 行）对任何角色一视同仁，无"端-角色"约束；JWT 虽携带 `user_type`/`role_level` 字段，但登录接口本身**不校验端与角色的匹配**
2. `src/router/index.ts` 路由守卫中，`/mobile/*`、`/tablet/*` 路径**直接放行**（`if (to.path.startsWith('/tablet') || to.path.startsWith('/mobile')) return next();`），既不校验登录态也不校验角色 → 教师/管理员用手机访问也可进入移动端
3. `mobile_login.vue`/`tablet_login.vue` 登录成功后无角色校验，教师/管理员可直接登录进入移动端

**关键结论**：JWT token 已含 `user_type`（student/teacher/admin）字段，前端 `getUserRole()` 可解析，后端 `user.user_type` 可直接判断——**无需改数据模型，仅需在登录接口 + 路由守卫加校验**。

### 2.7 移动/平板端功能模块对标缺口（问题 7）

PC 端学生端共 47 页，移动/平板端仅 12 页（6 mobile + 6 tablet）。缺失模块：

| PC 端模块 | 移动/平板端现状 | 对应后端 API（已存在） |
|-----------|----------------|----------------------|
| 答题页（answer_page） | ❌ 缺失（练习页不完整） | `/api/questions/random`、`/api/practice/record` |
| 历年试卷（student_papers） | ❌ 缺失 | `/api/papers/list` |
| 错题集（wrong_questions） | ❌ 缺失（仅入口跳 PC 路由 404） | `/api/wrong-questions` |
| 收藏（favorites） | ❌ 缺失 | `/api/questions/favorites` |
| 笔记（notes） | ❌ 缺失 | `/api/questions/{id}/note` |
| 成绩分析（score_analysis） | ❌ 缺失 | `/api/stats/dashboard`、`/api/stats/practice-trend` |
| 备考资料（materials_*） | ❌ 缺失 | `/api/materials/*` |
| 新闻详情（daily_news） | ❌ 缺失（仅首页列表） | `/api/news/{id}` + note 接口 |
| 考试日历（exam_calendar） | ❌ 缺失 | `/api/calendar/exams` |
| 招考信息（recruitment_info） | ❌ 缺失 | `/api/recruitment` |

> 这些模块的**后端 API 已全部存在**，缺口集中在**前端无移动/平板端页面**——补齐无需后端开发，仅需新建/适配前端页面。

## 三、解决方案（细节下钻）

### 3.1 移动端/平板端新闻详情页 + 笔记标注（问题 1）

**方案**：为移动端/平板端新增**新闻详情页**，复用 PC 端已完善的笔记标注逻辑与后端接口。

**代码改动**：
1. **新建 `.vtj/vue/mobile_news.vue`**（移动端新闻详情，`raw: true`）：
   - 复用 `daily_news.vue` 的笔记标注核心逻辑（5 色划线 + 3 线型 + 想法笔记）
   - 移动端适配：全屏详情 + 底部操作栏 + 选中文字弹出菜单（触控 ≥48px）
   - 调用已有接口：`GET /api/news/{id}`（详情）、`POST /api/news/{id}/note`、`GET /api/news/{id}/notes`、`DELETE /api/news/notes/{id}`
   - 用 `window.__VTJ_AUTH__.apiFetch` 统一认证
2. **路由补齐**（`src/router/index.ts`）：
   - `/news` → `daily_news.vue`（PC）
   - `/mobile/news`、`/mobile/news/:id` → `mobile_news.vue`（移动端）
   - `/tablet/news`、`/tablet/news/:id` → 复用 `mobile_news.vue`（平板端可复用，或按平板断点适配）
3. **修改跳转**：`mobile_home.vue` 第 284 行 `viewNews` → `/mobile/news/{id}`；`tablet_home.vue` 第 380 行 → `/tablet/news/{id}`
4. **移动端/平板端新闻列表数据源对齐**：首页新闻列表已接入 `/api/news`，保持不变

**后端字段确认**：`/api/news/{id}`（news.py 第 189 行）返回 content/images/is_favorited 等，笔记接口已完整注册——**无需后端改动**。

### 3.2 招考信息爬虫修复（问题 2）

**方案**：将"全部成功才替换"改为"**分类独立更新**"，并优化详情页抓取效率。

**代码改动**（`recruitment_scraper.py`）：
1. **分类独立更新**：`scrape_category` 成功后，立即**只替换该分类**的数据（`DELETE WHERE category=该分类 → INSERT`），而非等待 6 分类全部成功。失败分类保留旧数据，成功分类即时更新——彻底解决"一个分类拖垮全局"
2. **详情页并发抓取**：用 `concurrent.futures.ThreadPoolExecutor`（如 4~6 并发）替代逐条串行，缩短全量时长，降低超时中断概率
3. **超时与重试优化**：详情页超时从 30s 降至 15s、重试次数保持 3 次，页间/条间延迟适当降低
4. **过期数据标记**：`_detect_tag` 已能识别"报名结束"，建议列表接口增加 `status_label` 排序（已实现），前端优先展示"正在报名/即将报名"，过期信息折叠到底部

**运维便利**：
- 新增 `RECRUITMENT_CONCURRENCY` 环境变量（默认 5）便于调优
- 新增手动触发接口/脚本（`scrape_all_recruitment` 已可被 scheduler 调用，建议补一个 `python backend/scripts/scrape_recruitment.py` 手动入口）

### 3.3 考试日历爬虫修复（问题 3）

**方案**：
1. **修复 shiyebian.com 爬虫**：用 `curl` 实测当前 HTML 结构，修正选择器（`.rb_news-item` 等）或换数据源（如 rszk.net 的考试时间栏目）
2. **取消过度清理**：`cleanup_expired_exams` 改为**软清理**（`status=0` 而非物理删除），或仅清理超过 30 天的记录，保留近期历史
3. **平板端接入真实接口**：`tablet_home.vue` 日历数据源从 `/api/stats/calendar`（静态）改为 `/api/calendar/exams`（真实），字段映射 `{date→month/day, title→name}`

### 3.4 三端实时通信（问题 4）

**方案**：分阶段，先低成本落地，再增强。

1. **阶段一（低成本，优先）**：统一刷新机制
   - 移动/平板端各页 `onMounted` + 下拉刷新 + 页面切换时重新拉取（已有 API 基础）
   - 顶部导航增加"刷新"按钮
2. **阶段二（增强）**：接入已有 WebSocket `/ws/connect`
   - 登录后建立连接，后端在数据变更（新闻爬取完成、招考更新、练习提交）时 `broadcast_to_room('sync')`
   - 前端监听 `sync` 事件，刷新对应模块（防抖合并）
   - 复用已有 `ws_connection_manager`，**后端基础设施已就绪，仅需前端接入**

### 3.5 风格统一（问题 5）

**方案**：统一三端设计令牌（颜色/字体/图标），仅布局密度不同。
- 主强调色 `#C91F37` + 品牌深蓝 `#1A365D` + 中性灰 `#F5F7FA` + 字体 `PingFang SC/Microsoft YaHei/Noto Sans SC`
- 图标统一 `@vtj/icons`（XIcon），替换移动端部分 emoji 图标为 XIcon 矢量图标
- 触控目标统一 48px

### 3.6 路由补齐汇总

| 路由 | 组件 | 说明 |
|------|------|------|
| `/news` | `daily_news.vue` | PC 新闻列表+笔记 |
| `/mobile/news`、`/mobile/news/:id` | `mobile_news.vue` | 移动端新闻详情 |
| `/tablet/news`、`/tablet/news/:id` | `mobile_news.vue` | 平板端新闻详情（复用） |
| `/recruit` | `recruitment_info.vue` | PC 招考信息（已有，补路由别名） |
| `/mobile/recruit`、`/tablet/recruit` | 复用 `recruitment_info.vue` | 移动/平板招考 |

### 3.7 移动/平板端仅学生登录（问题 6）——三层防线

**设计原则**：后端强制（根本）→ 前端路由守卫（兜底）→ 登录页提示（UX），层层递进。

**第一道防线：后端登录校验**（`auth.py`，最可靠）
- `/api/auth/login` 增加可选 `client_type: str = Form("web")`（取值 web/mobile/tablet）
- 校验：`if client_type in ("mobile", "tablet") and user.user_type != "student"` → 返回 403 "移动端/平板端仅支持学生登录，教师/管理员请使用电脑端"
- 理由：前端可被篡改绕过，后端强制才是安全根本；且复用现有 JWT（`user_type` 字段），无需改数据模型

**第二道防线：前端路由守卫**（`src/router/index.ts`）
- `/mobile/*`、`/tablet/*` 分支：先 `getUserRole()`，非 `student` → `next('/unauthorized')`
- 防止已登录的教师/管理员通过 URL 直达移动端页面

**第三道防线：登录页校验**（`mobile_login.vue`/`tablet_login.vue`）
- `auth.login(username, password, 'mobile'/'tablet')` 传 `client_type`（`src/auth.ts` 的 `login` 增加第 3 参）
- 后端 403 时友好提示；前端再兜底 `getUserRole() !== 'student'` 时提示并 `logout()`

**关于扫码登录**：扫码登录是"移动端（已登录学生）确认 PC 端登录"，移动端本身已受学生限制，扫码确认不改变该约束，无需额外处理。

**关于教师/管理员误入移动端**：路由守卫检测到非学生 → 跳转 `unauthorized` 提示页（而非 PC 仪表盘，因 PC 仪表盘在手机上体验差），提示"移动端/平板端仅支持学生使用"。

### 3.8 移动/平板端功能模块补齐（问题 7）

**方案**：后端 API 已全部就绪，仅需新建/适配前端移动/平板页面，按优先级分批：

**P0 — 核心学习闭环**（复用 PC 端逻辑 + 移动端适配）：
1. 错题集（`mobile_wrong_questions.vue`）→ `/api/wrong-questions`
2. 收藏（`mobile_favorites.vue`）→ `/api/questions/favorites`
3. 成绩分析（`mobile_score_analysis.vue`）→ `/api/stats/dashboard`、`/api/stats/practice-trend`
4. 笔记（并入答题页/新闻详情，复用已有接口）

**P1 — 信息展示**：
5. 历年试卷（`mobile_student_papers.vue`）→ `/api/papers/list`
6. 备考资料（复用 `materials_*`，移动端适配）
7. 新闻详情、考试日历、招考信息（见 3.1/3.3）

**落地要点**：
- 入口：移动/平板端"我的"页 + 底部 Tab 增加对应入口
- 复用 PC 端页面逻辑，按移动端断点适配布局；严格遵循 VTJ 规范（`raw: true` + DSL 同步）

## 六、风险与注意事项

1. **爬虫反爬风险**：rszk.net/shiyebian.com 可能变更结构或增加反爬，需保留历史数据兜底（分类独立更新天然规避"全盘清空"风险）
2. **移动端新闻详情页复用**：需严格遵循 VTJ 规范（`raw: true` + DSL 同步），笔记标注逻辑从 `daily_news.vue` 抽取时注意 `window.getSelection()` 在移动端的兼容性（iOS Safari 需 `selectionchange` 事件处理）
3. **WebSocket 改造**：需处理断线重连、心跳、消息去重，避免频繁刷新造成性能问题
4. **学生端登录限制的后端改动**：`client_type` 需前端登录时正确传递（`application/x-www-form-urlencoded` 表单），否则移动端登录会走默认 `web` 分支而绕过限制——需同步改 `src/auth.ts` 的 `login` 方法，且 PC 端登录不受影响
5. **不影响其他模块**：所有改动精准定位到新闻/招考/日历/登录/路由相关文件，不触碰管理员端、题库等其他功能
