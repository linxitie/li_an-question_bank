|---|---|---|---|
| 1 | 题目/选项里的图片不显示 | `_extract_text_from_pdf()` **只提文本、从不提取 PDF 内嵌图片** | 高 |

## 一、问题 1：图片不显示

### 1.1 根因（已实测验证）

`backend/app/api/v1/question_import.py` L836-900 的 `_extract_text_from_pdf()` 是 PDF 的**唯一**文本入口，
它**只调用 `page.extract_text()` / `page.extract_tables()` / PyPDF2 / OCR，没有任何一处提取图片对象**。

实测证据：

- 该 PDF 逐页 `page.images` 统计：第 6 页 2 张、第 14 页 1 张、第 15 页 2 张、第 16 页 1 张，**共 19 个图片对象**
- 该 PDF 经 `_extract_text_from_pdf()` 后，`[IMAGE:` 占位符数量 = **0**
- 题目目录 10 个 PDF **全部**为 0

对照：DOCX 路径正常，全库 **222 道题**题干含 `<img>`。

### 1.2 关键发现：下游管线已完备，无需新建（对应要求 6「去粗取精」）

后端**已经**有一条完整可用的图片链路，只是 PDF 不产出入口：

| 环节 | 位置 | 能力 |
|---|---|---|
| 占位符生成 | `_extract_text_from_docx` L745-811 | 内联生成 ` [IMAGE:{session}_{题号}_{序号}]` |
| 落盘 | `_compress_and_store` L1495 | 压缩存储，返回路径 |
| 占位符回填 | `_extract_and_save_images` L1435-1448 | 支持 `<img src>` / `[IMAGE:x_y]` / base64，**并明确覆盖 `options`** |
| 无关图判定 | `image_filters.classify_image` | 三级 block/suspect/keep，与存量清理脚本同标准 |
| 安全防护 | 同上函数 | 路径遍历防护、SSRF 检测、`MAX_IMAGE_SIZE` 限制 |
| 静态路由 | `main.py` | 挂载 `/static/questions` |

**因此 PDF 侧只需产出同样的 `[IMAGE:...]` 占位符，下游全部自动打通。**

### 1.3 方案：新增 PDF 图片占位符提取

新增内部函数 `_extract_pdf_images_markers(buf) -> dict[page_no, list[(y_top, marker)]]`，
在 `_extract_text_from_pdf` 的 pdfplumber 分支中：

- 复用 `page.images` 已有的 `top` / `x0` 坐标，把每个图片对象转成 `[IMAGE:pdf_{session}_{page}_{seq}]`
- 按图片 `top` 坐标落到具体文本行之间，**插在图片中心最接近的那一行之后**
- 图片若落在选项行区间内，占位符随该行进入 `options`，从而被 `_extract_and_save_images` 现有的 options 分支接住

**技术选型理由（写码前必须回答的 5 个问题）**

1. **为什么这样写**：复用占位符协议而非新增 `data-pdf-image` 机制 → 下游 6 个环节零改动，回归面最小。
2. **好处**：与 DOCX 产出同构，`image_filters` 过滤、二维码拦截、路径防护全部自动复用；运维只需维护一套图片规则。
3. **安全性**：`session` 用不可预测随机串（复用现有 `_session_id` 机制），marker 不接受外部输入；落盘仍走 `_compress_and_store` 的路径穿越防护与 SSRF 检测。
4. **运维便利**：图片命名沿用 `img_docx_` 同族前缀（如 `img_pdf_`），清理脚本/统计脚本按前缀即可区分来源。
5. **VTJ 影响**：**不改任何 .vue 文件**（除下文 1.5 的选项渲染），`question_import.json` DSL 无需变更。

### 1.4 风险与待下钻确认

- **R1（中）按 y 坐标锚定可能错位**：多栏排版时图片可能跨栏。→ 需在 10 个 PDF 上逐一核对锚点正确性。
- **R2（中）矢量图/表格线不是图片**：`page.images` 只含位图，矢量示意图取不到。→ 需确认题库中是否存在依赖矢量图的题。
- **R3（低）19 张图里有多少是真题图、多少是水印**：需用 `classify_image` 逐张判定后再定锚点。

### 1.5 附带必须修：选项区图片渲染

`.vtj/vue/question_preview_list.vue` L53-54：

```html
<div class="docs-q-options" v-if="q.options && q.options.length">
  <span class="docs-q-opt" v-for="opt in q.options" :key="opt.key">{{ opt.key }}. {{ opt.value }}</span>
</div>
```

题干区 L52 用 `v-html="renderQuestionContent(...)"` 能渲染图片，**选项区是纯文本插值**。
一旦 PDF 图片开始进入 `options`，选项图片会以源码文本显示。
→ 需把选项区改为 `v-html`，并对 `opt.value` 走 `renderQuestionContent()`（该函数自带 `sanitizeHtml`，与题干同等安全等级）。
→ 需确认 `renderQuestionContent` 是否会破坏 `A/B/C/D` 前缀布局（当前 `{{ opt.key }}. {{ opt.value }}` 的 key 仍由模板单独输出，只对 value 用 v-html）。

## 二、问题 2：重复题（致命）

### 2.1 根因（铁证）

`question_import.py` L863-879：

```python
parts = []
for page in pdf.pages:
    text = page.extract_text()
    if text:
        parts.append(text)                    # ① 文本
    tables = page.extract_tables()
    for table in tables:
        for row in table:
            ...
            parts.append(row_text)            # ② 表格行 —— 同一内容再追加一次
return '\n'.join(parts)
```

当 pdfplumber 因版面（多栏 + 水印 + 页眉页脚）把某页**也识别成表格**时，
`extract_tables()` 会把已在 `extract_text()` 里出现过的单元格文本**再输出一遍**。

实测对照（同一 PDF、同一库）：

| 提取方式 | 字符数 | 行首题号个数 | 唯一题号数 |
|---|---|---|---|
| 手工 `pdfplumber` 逐页 `extract_text()` | 14,436 | **70** | 70 |
| 项目函数 `_extract_text_from_pdf()` | **28,873** | **140** | 70 |

- 28,873 ≈ 2 × 14,436 → **全文精确翻倍**
- 140 = 70 × 2，且**每个题号恰好出现 2 次**（`'1': 2, '2': 2, ...`）
- 原始文本中同一段（题 70 全文）**连续出现两次**，中间只夹着页脚/水印/页眉

### 2.2 方案（分级，按风险从低到高）

- **A（必做，最低风险）**：表格提取**仅在 `extract_text()` 为空时**启用；两者都有内容时，
  只对表格行做"是否已存在于本页文本"的判定，已存在则跳过。
  → 直接消除翻倍，且**不损失真正的表格题**（表格题的特征是题干在图/表里，文本层本就少内容）。
- **B（建议）**：`_finish()` 前增加**相邻重复块折叠**——若 `parts` 中存在内容高度相似
  （`normalize_text_for_comparison` 归一后相同）且仅隔 1 个短行的相邻块，丢弃后者。
  作为 A 的安全网，防止其他引擎/版本再次产生同类重复。
- **C（不建议现在做）**：引入 PDF 指纹/页级去重。成本高、收益边际，留作后续。

### 2.3 风险

- **R1（高）直接删掉 `extract_tables()` 会丢失表格题**。→ 采用 A 而非"删函数"，并用 10 个 PDF 回归确认题量不减少。
- **R2（中）`text_cache` 已缓存了翻倍结果**。→ 修复后必须**清空 PDF 文本缓存**，否则改动不生效。

## 三、问题 3：串题（致命，#2 的后果）

### 3.1 根因

全文翻倍后，`extract_question_numbers(text, monotonic=True)` 的单调性约束
（题号必须严格递增）把**第二次出现的题号全部丢弃**（140 → 70），
但**重复的正文文本仍留在题块内容里**。于是第 58 题的题块里塞进了 51~58 整节。

实测（同一 PDF，`extract_question_blocks` 输出 70 块，题号 1..70 严格递增 ✅）：

| 题号 | 题干长度 | 块内其他题号前缀数 |
|---|---|---|
| 7 | 1434 | 7 |
| 15 | 1291 | 8 |
| 23 | 1198 | 8 |
| 32 | 1188 | 9 |
| 40 | 1085 | 8 |
| **58** | **1278** | **8** |
| 65 | 930 | 7 |
| 68 | 694 | 3 |

题 58 开头正是用户报告的原文：
`（多选题）黄某因寻衅滋事罪被判有期徒刑…第 13 页，共 18 页 二. 多项选择题：…51.（多选题）习近平总书记指出…`

### 3.2 方案

- **主修**：修复问题 2（#1 根治手段即在此）。
- **兜底（建议）**：`extract_question_blocks` 切分完成后，对每个题块做
  "内部题号前缀检测"——若块内出现 ≥2 个独立题号前缀，则按内部题号**二次切分**；
  若二次切分不可行，标记该块为可疑并在预览页高亮，交教师用上一轮实现的**逐题删除**处理。
- **不采用**：放宽 monotonic 约束。放宽会引入幽灵题（此前已因 monotonic 修过一次，见 `extract_question_blocks` 注释中"2017国考第100题"案例），得不偿失。
