# 教师端工作台完善 + 题数不一致修复 — 方案存档

> 存档日期：2026-08-15
> 方案状态：已实施并通过验证

---

## 一、需求背景

1. **教师端工作台缺图表**：教师端 `teacher_dashboard` 只有 3 张数值卡片 + 2 个列表，需新增「今日练习人数柱状图」和「三大科目正确率饼图」，数据必须来自后端实时计算，无数据显示空态，不得前端硬编码。
2. **三端题目数量不一致**：教师端/管理员端显示 680 道，学生端显示三百多道。

## 二、根因分析

### 2.1 题数不一致（已彻底查清，含完整交互链路）

| 端 | 数据来源 | 口径 | 结果 |
|---|---|---|---|
| 教师/管理员 | `count(question_bank) WHERE status=1` | 全量 | 680 |
| 学生端子科目卡片 | `/api/quick-practice/sub-categories`，按 `question_knowledge` 关联去重 | 已关联考点 | 三百多 |

- 差额约 380 道 = `status=1` 但从未建立 `question_knowledge` 关联的题目。
- 导入流程（`question_import.py`）只写 `question_bank` + `QuestionDetailCategory`，从不调用分类器建考点关联。
- **关键事实**：学生端「按子科目刷题」走 `/api/questions/exercise/questions`（`questions.py:437`），本就按 `question_bank` 子科目列查题、不依赖 `question_knowledge`、能刷到全量。所以「刷题」没问题，问题只在「计数显示」口径。

### 2.2 结论

「治标」= 一次性回填；「治本」= 让计数口径统一到 `question_bank` 自带的子科目列（稳定、全量、非引擎产物），不依赖 `question_knowledge` 这张「分类引擎产物表」。

## 三、解决方案（两层，治标又治本）

### 模块一：教师端工作台图表

1. **Schema**（`backend/app/schemas/teacher.py`）：新增 `PracticeTrend`（近7天趋势）与 `SubjectAccuracyItem`（三科正确率），`TeacherDashboardResponse` 增加 `practice_trend`、`subject_accuracy` 字段（默认空，向后兼容）。
2. **端点**（`backend/app/api/v1/teacher.py` 的 `get_dashboard`）：
   - 近7天练习人数趋势：复用 `admin.py` 的 `weekly_trend` 写法（`func.count(distinct(user_id))` 按天切片）。
   - 三大科目正确率算法：仅统计 `practice_record`，`join question_bank` 兜底 `subject_id`（因 `practice_record.subject_id` 可空），`subject_id in (1,2,3)` 分组，`accuracy = correct/total×100`。
3. **前端**（`.vtj/vue/teacher_dashboard.vue`）：引入 `@vtj/charts` 的 `XChart`（复用 `score_analysis.vue` 成熟用法），新增 `practiceTrend`/`subjectAccuracy` state + `barChartOption`（bar）/`pieChartOption`（pie）computed，模板新增双图表面板，无数据渲染「暂无数据」空态（零硬编码）。
4. **DSL 同步**：`vtj_sync_vue_to_dsl` + 手动同步 state 字段，`vtj_check_consistency` 校验通过（version `1785750000004` 一致）。

### 模块二：题目数量一致（口径统一 + 归类增强）

**治本层（口径统一）**：`backend/app/api/v1/quick_practice.py` 的 `sub-categories` 端点，子科目级 `total_questions`/`done_count` 由「按 `question_knowledge` 关联去重」改为「按 `question_bank` 子科目列 `== SubCategory.name` 统计」，与 `subcategory-stats`、`exercise/questions` 同口径。考点级计数保留（考点维度合理依赖）。

**增强层（归类回填）**：
1. 全网调研归类标准（WebSearch 公安联考三大科目权威大纲）。
2. 增强关键词表（`question_classifier.py` 补 3 处高频关键词）。
3. 修复导入流程（`question_import.py` 新增 `_link_knowledge_points` 辅助函数，4 个导入入口自动建考点关联，治本防漏）。
4. 回填历史数据（`reclassify_all_questions.py`，475 道题建立考点关联）。

## 四、归类调研结论

现有 `seed.py` 的 15 子科目 + 约 90 考点 + `question_classifier.py` 关键词表，**已与公安联考权威大纲高度一致**（职业素养/基础知识/基本警务能力；行测六大板块；申论五大题型）。

本次增强（补充高频关键词，提升召回率）：
- 行政执法基础知识：补「治安管理处罚」「治安处罚」「突发事件应对」「反恐怖主义」。
- 刑事执法基础知识：补「取保候审」「逮捕」。
- 人民警察法基础知识：补「警务保障」「录用」。

## 六、遗留问题与建议

1. **44 道「无答案残缺题」**：`gongzhuan_subcategory='无'` 的 44 道题，答案均为「待补充」（无答案），部分为图片题，无法自动归类。导致学生端「可刷题」为 636（而非 680）。
   - 建议：人工补答案并归类、或删除、或单独标记为「未分类」类别。**不建议硬塞到某子科目**（违背「归类准确」原则）。
2. **205 道「无法自动归类」题**（含上述 44 道）：多为公安专业科目情境题/案例题，题干无明确考点关键词，关键词匹配的固有局限。
   - 建议：后续接入 LLM 语义分类，或人工审核。
