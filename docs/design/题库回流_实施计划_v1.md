## 四、已知难点

1. **题干跨页断裂**：一题跨两页时，尾行可能被切到下一页页首。当前脚本会把续行接到最后一个选项，可能污染选项文本；建议 S1 后按「选项长度异常」抽样检查。
2. **图解题**（图形推理、资料分析图表）：文本层里没有图，只能拿到题干与选项，需配合题图（`backend/app/static/` 已有 4.3 GB 题图，可能可用于匹配）。
3. **答案来源**：答案在另一册 `答案解析.pdf`，需要 S5 的匹配步骤，匹配不上则 `correct_answer` 为空。
4. **申论与公安题目**：题型不同（主观题/多选），需要单独规则，建议放在行测之后。

## 五、产出预估

- 达成门禁下限（3085 题）所需比例很低，**只要完成前 30 册左右即可让 L1-G 转绿**

## 十二、门禁复跑与科目口径差异（2026-11-17 03:10）

导入 4018 题后跑 `gate_all.py --quick`：

```
PASS  L0  (30.0s)
FAIL  L1-G (0.2s)
      ✅ 护栏/总数: 4018 题（下限 3632）
      ❌ 护栏/公专: 0 题（下限 3085）
PASS  L1  (7.8s)
PASS  L1-H (0.3s)
gate_all: 3/4 通过
```

**总数护栏已过**（0 → 4018）。剩余 FAIL 来自科目口径：

| 项 | 数值 |
|---|---|
| 门禁基线 `expected_counts` | {1: 499, 2: 48, 3: 3085}，总数 3632（2026-11-04 校准） |
| 当前库 `question_subject` 命名 | 1=行测、2=公安专业科目、3=申论 |
| 当前库实际题量 | subject_id=1 有 4018 题，2 与 3 均为 0 |
| 门禁侧命名 | `SUBJECT_NAMES = {1: 行测, 2: 申论, 3: 公专}` |

**结论：编号口径不一致**。门禁要求 subject_id=3 达 3085 题，但库里 3 号是「申论」且为 0；若强行把行测题塞进 3 号，只是骗过护栏，属数据造假，**不做**。

**消解路径（需你选）**：
1. 按门禁口径导入公专/申论题到 2、3 号（语料：公专 10 份 PDF，申论若干，全部有文本层）
2. 核对 `question_subject` 与门禁 `SUBJECT_NAMES` 哪边是对的，改错的一边
3. 用 `--rebaseline --reason` 重定基线（会降低护栏强度，不建议）
