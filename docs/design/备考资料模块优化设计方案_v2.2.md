## 三、数据库设计

### 3.1 重建 `study_material` 主表（幂等 DROP+CREATE，因 0 行数据零风险）

```sql
DROP TABLE IF EXISTS study_material;
CREATE TABLE study_material (
    material_id   INTEGER PRIMARY KEY AUTOINCREMENT,
    subject       VARCHAR(20)  NOT NULL,              -- xingce / shenlun / gongzhuan
    type          VARCHAR(20)  NOT NULL,              -- video_intro / video_advanced / article / card
    category      VARCHAR(50),                        -- 分类标签，如"言语理解"
    title         VARCHAR(200) NOT NULL,
    summary       VARCHAR(500),                       -- 摘要/简介
    content       TEXT,                               -- 文章正文（bleach 消毒后 HTML）；卡片时存背面详细内容
    card_front    VARCHAR(200),                       -- 卡片正面（标题/关键词）
    card_back     TEXT,                               -- 卡片背面（知识点/记忆口诀）
    cover_image   VARCHAR(500),                       -- 封面图 URL（/uploads/materials/images/...）
    video_id      INTEGER,                            -- 关联 video_resource.video_id（外链视频时可空）
    duration      INTEGER DEFAULT 0,                  -- 视频时长（秒）
    read_time     INTEGER DEFAULT 0,                  -- 预估阅读时长（分钟）
    difficulty    TINYINT DEFAULT 1,                  -- 难度 1-3
    badge         VARCHAR(20),                        -- 热门/精华/重要/NEW
    sort_order    INTEGER DEFAULT 0,                  -- 排序权重（小者靠前）
    status        TINYINT DEFAULT 1,                  -- 0下架 / 1上架
    view_count    INTEGER DEFAULT 0,
    study_count   INTEGER DEFAULT 0,                  -- 标记已完成人数
    creator_id    BIGINT REFERENCES sys_user(user_id),
    create_time   DATETIME DEFAULT CURRENT_TIMESTAMP,
    update_time   DATETIME DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_subject_type ON study_material(subject, type);
CREATE INDEX idx_status_sort  ON study_material(status, sort_order);
```

> 旧模型的 `file_path / icon_name / download_count` 字段与新需求无关，重建时移除。

### 3.2 新建 `user_material_progress` 学习进度表

```sql
CREATE TABLE IF NOT EXISTS user_material_progress (
    progress_id      INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id          BIGINT NOT NULL REFERENCES sys_user(user_id),
    material_id      INTEGER NOT NULL REFERENCES study_material(material_id),
    status           SMALLINT DEFAULT 0,               -- 0未学 / 1学习中 / 2已完成
    progress_percent FLOAT DEFAULT 0,                  -- 0-100（视频播放百分比/文章阅读位置）
    is_favorite      BOOLEAN DEFAULT 0,
    completed_at     DATETIME,
    create_time      DATETIME DEFAULT CURRENT_TIMESTAMP,
    update_time      DATETIME DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(user_id, material_id)                      -- ★ UPSERT 幂等的关键约束
);
CREATE INDEX idx_progress_user ON user_material_progress(user_id);
```

### 3.3 新建 `material_import_record` 导入记录表（仿 QuestionImportRecord 先例）

```sql
CREATE TABLE IF NOT EXISTS material_import_record (
    import_id     INTEGER PRIMARY KEY AUTOINCREMENT,
    file_name     VARCHAR(255) NOT NULL,
    file_type     VARCHAR(10),                       -- docx/xlsx/pdf/image
    file_size     BIGINT,
    parse_status  VARCHAR(20) DEFAULT 'pending',     -- pending/processing/success/failed
    parse_mode    VARCHAR(20),                       -- sync(docx/xlsx/pdfplumber) / async(mineru)
    parse_result  TEXT,                              -- JSON 快照：结构化解析产物（章节树/行列数据/图片清单）

    uploader_id   BIGINT REFERENCES sys_user(user_id),
    create_time   DATETIME DEFAULT CURRENT_TIMESTAMP,
    update_time   DATETIME DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_import_status ON material_import_record(parse_status);
```

## 五、文档解析服务设计

### 5.1 `backend/app/services/material_parser.py`（轻量同步解析器）

纯函数式设计，输入文件路径、输出结构化 dict，便于单元测试：

| 函数 | 输入 | 输出 schema | 库 |
|---|---|---|---|
| `parse_docx(path)` | .docx | `{"chapters":[{"level":1..3,"title":str}],"html":str,"images":[tmp_paths],"word_count":int}` — H1/H2/H3→chapters；段落→`<p>`；表格→`<table>`；内嵌图片提取到 tmp 并以占位符标记待迁移 | python-docx |
| `parse_xlsx(path)` | .xlsx/.xls | `{"headers":[col1..colN],"rows":[[...]](最多预读200行),"total_rows":int}` — 不做语义假设，列映射交给管理员 | openpyxl |
| `parse_pdf_text(path)` | 文字型 pdf | 同 parse_docx 输出 schema — 以字体大小聚类推断标题层级（size > 1.3×正文均值 → h2）| pdfplumber |
| `detect_scanned(path)` | 任意 pdf | bool — 平均每页可提取字符 < 100 判定扫描件 | pdfplumber |
| `confirm_cards(rows, mapping)` | 行数据+列映射 | `[{card_front, card_back, category}]` — 空行跳过、去重告警、500 行上限 | — |
| `sanitize_html(html)` | 任意 HTML | 消毒后 HTML（白名单见 6.1）| bleach |

### 5.2 `backend/app/services/mineru_service.py`（异步重型解析）

```text
run_mineru(input_path, out_dir, timeout=600):
  1. subprocess.Popen(["mineru", "-p", input_path, "-o", out_dir, "-b", "pipeline"],
                      env={**os.environ, "MINERU_MODEL_SOURCE": "modelscope"},
                      cwd=MINERU_VENV_DIR,   # 独立 venv 的 Scripts 目录，隔离主服务依赖
                      stdout=PIPE, stderr=PIPE)
  2. wait(timeout=600) → 超时 kill + 抛 MineruTimeoutError
  3. 成功后读取 out_dir 下生成的 *.md 与 images/
  4. md → sanitize_html() 转 HTML；图片 move 至 uploads/materials/images/{import_id}/ 并改写引用
  5. 返回与 parse_docx 同构的 schema
```

- **进程隔离原则**：MinerU 含 torch 等重依赖且体积巨大，装在独立 venv（建议 `backend/mineru_env/`），FastAPI 主进程绝不 import 它，只经 subprocess 调用其 CLI。
- **调用方式**：由路由层经 `starlette.concurrency.run_in_threadpool` 包裹 subprocess 阻塞等待，放入 FastAPI `BackgroundTasks`；期间 import_record.parse_status='processing'。
- **可用性探测**：启动时/首次调用前 `shutil.which('mineru')` 探测；不可用时导入接口对扫描件直接返回明确错误（见 5.3），不影响其他格式。

### 5.3 失败模式与用户话术表

| 失败场景 | 检测方式 | 用户话术（管理端红条展示）|
|---|---|---|
| 加密 PDF | pdfplumber 打开抛 `PDFPasswordError` | 「该 PDF 已加密，请解除密码后重新上传」|
| 扫描件且 MinerU 不可用 | detect_scanned=True 且 which('mineru')=None | 「该 PDF 为扫描图片版且系统 OCR 组件未就绪，请转存为文字版 Word 后重新上传」|
| MinerU 超时（>600s）/崩溃 | returncode≠0 / TimeoutExpired | 「OCR 解析超时或失败，可点击【重试】；若反复失败请拆分文件或转 Word」（保留 import_record，支持重试）|
| 损坏 docx | python-docx 抛异常 | 「Word 文档损坏或格式不受支持，请另存为 .docx 后重试」|
| 空 Excel / 无表头 | total_rows==0 或 headers 全空 | 「表格无有效数据行」|
| Excel 超 500 行 | confirm 时校验 | 「单次导入最多 500 张卡片，请拆分文件」|
| 图片伪装（改扩展名）| magic bytes 校验失败 | 「文件实际格式与扩展名不符」|

所有失败均写入 import_record.error_message，**绝不静默丢弃**。

## 六、安全设计

### 6.1 XSS 防线（富文本是最大攻击面）

- **入库消毒**（唯一信任边界）：所有 article/content HTML 经 `bleach.clean` 白名单清洗后才允许写库：

| 元素 | 允许属性 |
|---|---|
| p, br, strong, em, u, blockquote | — |
| h2, h3, h4 | — |
| ul, ol, li | — |
| img | src（仅允许 `/uploads/` 前缀内部路径）、alt |
| a | href（仅 http/https，加 rel="noopener noreferrer"）|
| table, thead, tbody, tr, th, td | — |

- `script/style/iframe/object/embed/on*事件属性/javascript:URL` 一律剥离；
- **前端 v-html 只渲染库内存量**——学生端与管理端预览均如此，杜绝绕过后端直插恶意 HTML 的可能。

### 6.2 上传安全（吸收 media.py 教训）

1. **UUID 重命名**：服务端生成文件名，永不使用用户原始文件名（防路径穿越 + 防覆盖）；
2. **三重校验**：扩展名白名单（png/jpg/jpeg/webp/pdf/docx/xlsx）+ Content-Type MIME 校验 + **magic bytes 文件头嗅探**（PNG `\x89PNG`、JPEG `\xFF\xD8\xFF`、ZIP 系 `PK\x03\x04` 对应 docx/xlsx、PDF `%PDF-`）；
3. **大小上限**：封面/图片 5MB、文档 20MB、Excel 5MB（视频沿用 videos.py 自身限制）；
4. **目录约定**：`uploads/materials/images/`、`uploads/materials/tmp/`（导入暂存，confirm/failed 后清理）。

### 6.3 权限与审计

- 管理接口统一依赖注入：`current_user = Depends(get_current_user)` + `if current_user.role != 'admin': raise HTTPException(403)`；
- 所有管理变更操作（CRUD/上下架/导入确认）写 `sys_operation_log`（user、action、target、detail JSON、ip、time）；
- 学生端进度/收藏接口仅需登录（get_current_user），浏览接口 get_optional_user。

### 6.4 SQLite 写入保护

- 进度上报：前端 10 秒节流 + 进度跳幅 ≥20% 才立即上报（其余合并进下个周期）；
- 后端 UPSERT 单语句完成，无读-改-写竞态；
- T1 迁移时检查并开启 WAL 模式（`PRAGMA journal_mode=WAL`）提升并发读写容忍度。

## 十一、风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| MinerU 模型下载失败/网络受限 | 高 | T0 最先验证；modelscope 国内源；模型缓存持久化；彻底失败则启用降级话术（D8 兜底），不阻塞其余任务 |
| MinerU CPU 解析慢（分钟级/份）| 中 | 异步+轮询+600s 熔断+重试；管理端显示耗时；文档中注明批量导入建议错峰 |
| SQLite 并发写竞争 | 中 | 节流上报 + UPSERT 单语句 + WAL 模式；监控锁错误日志 |
| wangeditor 拖慢前端包 | 低 | 仅管理页 dynamic import；学生包构建产物体积对比验证 |
| 三页重复代码漂移 | 中 | 接受（D1 既定）；主题常量集中页头注释锚点；后续如抽公共 composable 另立任务 |
| videos.py stream 强制登录与游客浏览矛盾 | 中 | T2 核验后二选一：放宽 stream 为 optional auth / 文档注明视频学习需登录 |
| bleach 过度清洗破坏合法排版 | 低 | 白名单在 T11 联调期按真实素材微调；消毒只在入库边界执行一次 |
| 大 Excel 卡片批量冲击 | 低 | 500 行硬上限 + 分批确认 |

## 十二、运维要点

1. **审计追溯**：所有内容变更查 `sys_operation_log`；每次导入查 `material_import_record`（file_name/parse_status/error_message 可定位失败原因）。
2. **MinerU 运维**：
   - 模型缓存位置随首次下载输出提示记录归档；环境变量 `MINERU_MODEL_SOURCE=modelscope` 需写入服务启动脚本/systemd；
   - 升级只需独立 venv 内 `uv pip install -U mineru[all]`，主服务零感知；
   - 监控点：subprocess 超时次数、平均解析耗时（import_record 时间差可统计）。
3. **数据库**：T1 执行前手动备份 `question_bank.db`；迁移脚本可安全重跑；WAL 开启后注意伴随 -wal/-shm 文件的备份策略。
4. **内容运营 SOP**：新素材 → 管理端智能导入 → 预览确认（status=0）→ 复核 → 上架（status=1）；下架即对学生端隐藏但保留数据。
5. **日志**：解析失败详情双写——import_record.error_message（持久）+ backend logger（实时排查）。
