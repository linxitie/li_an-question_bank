  - `git rev-parse --short HEAD` 与 `git status --porcelain`
  - 三者任一不一致 → 退出码 2，并在页面右下角 BuildStamp 变红（仅不一致时红，答题页不隐藏）。

## 4. 第一性原理拆解：7 条诉求只有 5 个根问题

```
R1 三层分层不合理 ──┐
R2 考点下全是"其他" ─┴→ 根因 A：结构错位（L2/L3 两套考点层并行，80.4% 题挂 L2，UI 只画 L3）

R3 导入不认下划线 ───→ 根因 B：版本错位（修复在 feat/v6-fix，main 没有）

R4 错题集材料/图片/答案/高亮 ─┬→ 根因 C：渲染断链（接口返回，页面不渲染 / 数据物理缺失）
                              └→ 根因 D：数据缺口（13 张缺图、部分申论无解析、选项"待补充"）

R5 艾宾浩斯多通道提醒 ──→ 根因 E：送达缺失（算法有，站内信有，短信/振动/铃声/收件箱没有）

R6 方案丢失 / 联考小智复发 → 根因 F：发布链路无一致性门禁
```

**为什么必须一次性做**：A（数据）不解决，B（导入）补进来的题还会继续挂错；C（渲染）不解决，
A 修好了用户也看不见；F 不解决，A–E 任何一项都可能再次"丢失"。

## 5. 方案正文

### M1 三层分类：把两套考点层收敛成一套（解决 R1、R2）

**目标树（唯一权威）**

    科目(3) → 知识点(16, sub_categories) → 考点(对齐 drawio 73 个) → 训练子项(353 个细分，仅作练习入口，不再叫「其他」)

**M1.1 生成权威对照表（先对账，后改数据）**

- 新脚本 backend/scripts/taxonomy/drawio_tree.py：解析 drawio → {subject: {知识点: {考点: [细分]}}}，输出 docs/design/taxonomy_drawio_v9.json（73 考点 / 353 细分，可人工校对）。
- 新脚本 backend/scripts/taxonomy/verify_tree.py：DB ↔ drawio 三类差异
  ① drawio 有、DB 无（缺考点）② DB 有、drawio 无（多余或脏节点）③ 同名异位（名称同、父不同）。输出 Markdown 表 + JSON，作为导入后门禁（差异未清零不准上线）。
- 已实测可用的几何解析规则（写进脚本注释，不要再用「连线」思路）：drawio 只有 61 条 edge 却有 508 个 vertex，层级靠**几何包含 + y 序**——父 = 面积更大、y 更小、x 区间包含子节点的最近一个盒子；科目宽约 1200、知识点约 550–630、考点约 170–210、细分约 80。

**M1.2 题目下沉：把 2954 道挂错层的题搬回家**

现状：80.4% 的题挂 L2，而 L2 已有 L3 子节点 → L3 视图里「无家可归」→ 显示成「其他（未细分）」。

做法（可回滚、有审计）：
1. 以 drawio 考点名 + 题干语义双通道匹配，把 L2 上的题下沉到对应 L3（复用 v8c 已实现的 classify_cross()，实测覆盖率 83.8%，且已有 point_assign_audit 审计表逐题记录）。
2. 下沉失败的题（预计 <5%）挂到该知识点下唯一的 is_fallback=1 兜底节点。
3. 兜底节点**只做练习入口，不做分类**：学生端在该层显示「未细分类 · 直接练习（N 题）」按钮，点击直接开练，**永不展开第三层**——这条写进前端组件校验，避免以后再被做成可下钻。
4. L2 节点退化为「考点分组」，学生端不渲染；24 个 0 题 L2 直接 status=0 停用（保留数据，不删除）。
5. **红线**：不合并、不删除已有 point_id，只改归属；执行前必须 sqlite3.backup() 备份（R10），并保留映射 CSV 供 --revert。

**M1.3 API 与前端契约（一次改对，杜绝「其他」再出现）**

GET /api/quick-practice/sub-categories?subjectId= 返回结构收敛为：

    {
      "knowledge_point": {"id": 1, "name": "政治理论"},
      "points": [
        {"point_id": 1, "name": "习近平新时代中国特色社会主义思想", "question_count": 15},
        {"point_id": 2, "name": "党的二十大精神", "question_count": 5}
      ],
      "fallback": {"question_count": 27, "action": "practice_directly"}
    }

前端规则（practice_center.vue / question_bank.vue 共用）：
- points.length > 0 → 渲染考点列表，每个考点一个「练习」按钮；
- fallback.question_count > 0 → 渲染**一行**「未细分类 · 直接练习」，无子级箭头；
- points.length == 0 且 fallback.question_count > 0 → 该知识点整卡直接跳练习，不展开。

**M1.4 验收**（A1–A3）
- A1：16 个知识点逐个展开，**0 处**出现「其他」作为可下钻节点（自动化断言：遍历 API 响应，禁止 name == 其他 出现在 points 且带 children）。
- A2：verify_tree.py 输出 drawio↔DB 差异 = 0（或缺项在白名单）。
- A3：挂点覆盖率 ≥95%（现状 80.4% 题挂 L2，目标全部落到具体考点或唯一兜底）。

### M2 教师端「题目导入」：先上线，再补质量闭环（解决 R3、R4 的导入部分）

**M2.1 先把分支合并（P0）**，否则以下模块在 main 里根本不存在：docx_underline.py / pdf_underline.py / xlsx_underline.py / quality.py / image_markers.py。

**M2.2 三入口统一（实测发现的最大风险）**

教师端存在三个上传路径，必须确认全部走 question_ingest 同一管线：

    backend/app/api/v1/catalog/question_import.py    # /api/questions/import/*（主入口）
    backend/app/api/v1/library/materials.py          # /api/materials/admin/import/upload
    .vtj/vue/question_import.vue                     # 教师端页面（前端入口）

执行方式：对每个入口各传 1 份含「空白 + 下划线」的 docx，比对入库题干是否含 ____。
**若某入口绕过了新解析器，直接在该入口补调 docx_reader，不允许维护第二套解析。**
