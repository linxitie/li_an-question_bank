# 题目导入优化策略与持续改进机制

> 版本：v1.0　｜　基线日期：2026-09-25　｜　分支：`feat/question-import-composite-image-optimization`
> 覆盖范围：题目导入全链路（文档提取 → 文本清洗 → 题块切分 → 答案匹配 → 复合题归组 → 图片落盘 → 异常题回流）
> 基线证据：20 份真实试卷（1929 题）全量回归，非推测、非单文档样本

---

## 一、实测基线（优化前 → 优化后）

### 1.1 质量指标

| 指标 | 优化前 | 优化后 | 变化 |
|---|---:|---:|---|
| 解析出题数 | 1949（含 5 道幽灵题） | **1929** | −20（消除虚增） |
| 答案匹配率 | 98.51% | **100.00%** | +1.49pp |
| 缺答案题数 | 26 | **0** | 归零 |
| 缺解析题数 | 127 | **34** | −93（其中 28 为源文档固有） |
| 材料头污染题数 | 4 | **0** | 归零 |
| 重复题号 | 4 | **0** | 归零 |
| 选项缺失题数 | 60 | **49** | −11（30 为主观题固有，19 为待优化） |
| 解析覆盖率 | 92.68% | **98.19%** | +5.51pp |

### 1.2 性能画像（决定优化对象的关键证据）

| 环节 | 单份耗时 | 结论 |
|---|---:|---|
| 解析计算（`smart_match_questions_answers`） | **0.10–0.22 s / 100 题** | 解析器**不是**瓶颈，无需为"更快"重写 |
| docx 文本提取 | 0.09–0.35 s | 快 |
| PDF 文本层提取（pdfplumber） | 5–9 s / 17 页 | 可接受，是主要固定开销 |
| **扫描件 PDF（MinerU OCR）** | **252 s / 24 页** | **唯一数量级瓶颈** |

> 关键判据：**解析 0.2s，提取 252s**。任何"优化解析算法提速"的投入产出比极低；真正的效率杠杆在**提取层**（OCR 成本）。

### 1.3 语料覆盖

20 份试卷，2016–2019，涵盖国考／省考／多省联考／公安院校联考／招警／辅警等 6 类卷型，题量 72–100 题/份。

## 二、已落地的四项解析修复（可复用经验）

每一项都由真实语料驱动，且**在 20 份文档上交叉验证后才提交**，杜绝单样本过拟合。

### 修复 1：Markdown 标题题号（MinerU OCR 输出的必兼容格式）

- **现象**：2017 多省联考答案 PDF，100 题仅识别出 5 个题号，匹配率 74%、解析覆盖率 5%。
- **根因**：该 PDF 无文本层 → MinerU OCR → **MinerU 输出 Markdown**，题号行为 `## 1、正确答案是：D`。而 `num_dot` 题号正则以 `(?:^|\n)\s*` 行首锚定，`\s*` 无法匹配 `# `，导致整段题号漏识别。
- **修复**：行首前缀容忍 Markdown 标题标记 `(?:^|\n)[ \t]*(?:#{1,6}[ \t]+)?`。
- **效果**：该卷 74% → **100%**，解析 5% → **98%**。
- **可复用结论**：**凡引入 OCR，解析器就必须兼容 OCR 的输出方言**。这是接入 MinerU 后必然踩的坑，不是偶发。

### 修复 2：题干内被打乱子项序号被误判为题号（幽灵题）

- **现象**：2017 国考第 100 题解析出 105 题，题号 1/2/3/4 各出现 2–3 次。
- **根因**：原文
  ```
  100、事故发生后…下列安全撤离顺序最恰当的是：
  （1）附近居民
  （2）维持现场秩序的民警
  （3）媒体报道的人
  （4）参与应急的消防人员
  A、（1）（2）（4）（3）  B、…  C、…  D、…
  ```
  `（1）`–`（4）` 是**被打乱顺序的子项编号**（A–D 选项引用它们），被 `paren` 格式误判为第 1~4 题，凭空造出 4 道幽灵题并挤成重题号。
- **修复**：题目侧同样启用 `monotonic`（题号须严格递增）。子项序号必然小于当前题号（1 < 100），违反单调性即被过滤。
- **效果**：幽灵题 −5、重题号归零。
- **可复用结论**：**试卷题号天然单调递增；正文中的任何编号都不递增**。单调性是比关键词更鲁棒的判据。

### 修复 3：图片选择题词表覆盖不足

- **现象**：20 道"选项即图片"的题被判为选项缺失。
- **根因**：首版关键词表只有 `图标|示意图|下图|如图|图中|图表|看图`，而真实语料高频用 **`图示`**（"下列图示中…"）、**`标志`**（"在下列交通标志的区域中…"）。
- **修复**：扩充为 `图标|示意图|下图|如图|图中|图表|看图|图示|标志|标识|图形|图片|如上图|如下图所示|所示`。
- **效果**：无选项 60 → 49。
- **可复用结论**：**关键词表的完备性无法靠推理保证，只能靠语料穷举**。每接入一批新文档就应重跑词表覆盖率检查。

### 修复 4：材料头与正文同行导致污染

- **现象**：4 题题干尾部混入下一题组材料头与材料正文。
- **根因**：三重叠加缺陷——
  1. 只匹配 `情境材料`，遗漏 `情景材料`（两种写法在真题中并存）；
  2. 不支持 `八、请根据以下情景材料…` 的"请"前缀与 `根据以下情境资料…` 的无章节号形态；
  3. 正则以 `$` 锚定，**要求材料头独占一行**，而 docx 文本框／分栏常把材料头与正文挤在同一行 → 同行形态 100% 漏剥离。
- **修复**：三种变体全支持 + 改为"在材料头出现处截断该行"而非整行丢弃。
- **效果**：污染 4 → 0。
- **可复用结论**：**行级正则必须处理"标记与内容同行"这一常态**；锚定 `$` 是脆弱假设。

## 三、高效性策略（Efficiency）

### 3.1 分层降级提取链（已落地）

```
PDF: pdfplumber（文本+表格）→ PyPDF2 → MinerU OCR → PaddleOCR 逐页
DOCX: python-docx 正文 + 文本框 + 图片关系表
任一级成功即返回；OCR 在独立子进程，崩溃/超时被强杀，绝不拖死后端
```

设计要点：
- **快路径优先**：有文本层走 pdfplumber（5–9s），仅扫描件才付 OCR 成本（252s）。
- **失败契约**：`extract_text_sync` 任何失败返回 `None` → 继续下一级，绝不阻断导入。
- **进程隔离**：OCR 独立 venv 子进程（本机 Python 3.13 超出 PaddleOCR 支持，进程内 OCR 会硬崩）。

### 3.2 OCR 结果缓存（**最高优先级待实施项**）

**问题**：同一份扫描件重复导入，每次都重付 252s。

**方案**：按 `文件内容 md5` 缓存提取文本。

```
backend/data/ocr_cache/{md5}.txt   # 提取文本
backend/data/ocr_cache/{md5}.json  # 元数据：页数、引擎、耗时、字符数
```

- 命中：0.02s（比 252s 快 **4 个数量级**）
- 收益随导入次数**线性累积**：同一批 20 份文档二次导入，从 ~5 分钟降到 <1 秒
- 天然契合"导入越多、越快"的要求

**配套**：提取阶段记录 `t_extract`，导入报告按 md5 汇总"OCR 耗时/缓存命中"，让效率可观测。

### 3.3 解析层不做过度优化

实测解析 0.10–0.22s/100 题，**解析层优化无任何意义**。策略上明确：**解析层只求正确，不求速度**。所有性能预算投在提取层。

## 四、稳定性策略（Stability）

### 4.1 20 份真实语料回归门禁（已建成）

- **语料库**：20 份试卷 / 1929 题，落盘为可复现缓存（`{槽位}.q.txt` / `{槽位}.a.txt` / `{槽位}.result.json`）
- **确定性**：回归时**禁用 LLM 网络兜底**（monkeypatch 返回 `{}`），结果可离线复现
- **增量**：`--reparse` 只重跑解析，不重跑 OCR → 改一行解析代码，20 份门禁 **1 秒内**跑完
- **门禁指标**：匹配率、缺答案、缺解析、无选项、污染、重题号
- **提交纪律**：**任何解析改动必须 20/20 全过才允许提交**，防止"修 A 坏 B"

### 4.2 分层防御：任一层失效不影响其他层

| 失效场景 | 防护 |
|---|---|
| OCR 崩溃/超时 | 子进程强杀，降级下一级 |
| 文本层缺失 | 自动进 OCR 链 |
| 答案文档格式异常 | 8 级策略链降级（题号分段 → 嵌入式 → 连续序列 → 内联 → 纯序列 → 宽松正则 → 位置兜底 → LLM） |
| 单题字段缺失 | 不阻断整批，进 `need_confirm_items` 异常清单 |
| 解析结果不可信 | `is_irrelevant_image` 三级分级（block/suspect/keep），存疑放行待复核 |

### 4.3 异常题结构化回流

导入不追求"零缺失"，而追求"**缺失可见、可定位、可修正**"：

- `failed_items` 补 `question_number` → 知道**哪一题**失败
- `need_confirm_items`（含 index / question_number / reason）→ 知道**为什么**可疑
- 前端异常清单面板 + `locateAbnormalItem`（`scrollIntoView` + 高亮）→ **一键跳到出错的题**

## 五、可持续训练完善性策略（导入越多 → 性能越高、误差越小）

这是本方案的核心主张。**"越导越好"不会自动发生，必须显式构建三条闭环。**

### 闭环 1：失败样本分类学 —— 区分"源文档固有"与"解析 bug"

这是**防止过拟合、防止无效调参**的关键。每一次失败都必须归入二选一：

| 类别 | 判定依据 | 处置 |
|---|---|---|
| **源文档固有** | 源文件本身就没有该信息 | **不修**。记为已知边界，避免后人反复调参 |
| **解析 bug** | 源文件有该信息，解析器丢掉了 | **必须修**，并补进门禁语料 |

本轮 20 份实测的分类结果：

- 缺解析 34 题 → **28 题为源文档固有**（论述题/写作题/判断题本无标准答案解析）+ **6 题真待修**
- 无选项 49 题 → **约 30 题源文档固有**（主观题无选项本属正常）+ **19 题图片选项识别待优化**

> 若不做这个分类，最典型的失败模式是：有人为了"消灭"主观题的空解析，反复放宽答案匹配阈值，结果**污染了本已正确的 1900 题**。分类学是规模化导入的安全带。

### 闭环 2：规则沉淀 —— 每个新变体固化为可复用判据

本轮 4 项修复沉淀出 4 条可复用判据（见第二节"可复用结论"），它们的共同特征是**用结构不变式代替关键词猜测**：

- 题号单调递增 → 过滤正文编号
- 行首锚定容忍 `# ` → 兼容 OCR 方言
- "标记+内容同行"常态 → 不用 `$` 独占行假设
- 关键词表靠语料穷举 → 不靠推理完备

**机制**：每接入一批新文档 → 跑门禁 → 新暴露的变体 → 固化为判据 → 回归验证 → 并入语料库。语料库越大，判据越完备，**误差单调下降**。

### 闭环 3：语料库自增长 —— 门禁即语料

- 每个新导入文档**自动加入回归语料**（题号、字段完整率、耗时画像全部落盘）
- 语料库规模 N → 门禁覆盖 N 类排版方言
- 规则在 N 份上交叉验证 → **单文档过拟合在数学上不可能通过门禁**

> 这正是"导入的题目越多，导入性能越高、误差越小"的机制来源：
> **语料库 ↑ → 判据完备性 ↑ → 单份解析准确率 ↑ → 人工修正量 ↓ → 新语料入库更快 → 语料库 ↑更快**。

## 六、待优化项（按优先级，均有实测依据）

| 优先级 | 项目 | 实测依据 | 预期收益 |
|---|---|---|---|
| **P0** | OCR 结果按 md5 缓存 | 扫描件 252s/份，重复导入全额重付 | 重复导入 252s → 0.02s |
| **P1** | 图片选项题兜底识别 | 19 题有图无选项且题干无"图示"类指向词 | 无选项 49 → ~30（全部为主观题固有） |
| **P1** | 6 题真待修解析 | doc3#69、doc4#80/98、doc6#38、doc11#16、doc10 单选 1 题 | 解析覆盖率 98.19% → ~99.5% |
| **P2** | 提取层耗时画像上报 | 当前无法区分"哪份慢在哪一级" | 效率可观测，支撑后续优化 |
| **P2** | 剩余 22 份文档（2020–2025）纳入门禁 | 当前门禁止于 2019，含 7 份 PDF 卷 | 语料库扩容，方言覆盖更全 |

### P1 图片选项兜底识别的风险提示

候选启发式：**题块含 ≥1 个 IMAGE 标记且 0 个文字选项 → 判为图片选项题**。

- 收益：覆盖 19 题
- 风险：可能误伤"引用材料图片的判断题/论述题"（它们同样无文字选项但有图）
- 建议：**先在 20 份门禁上做 A/B 验证**，确认无误伤后再启用；误伤率不达标则退回"仅补指向词词表"方案

## 七、提交纪律（保证长期不劣化）

1. **改动前**：先跑 20 份门禁，记录基线数字
2. **改动后**：门禁必须 20/20 通过，且**不劣化**任何既有指标
3. **交叉验证**：修复必须在 ≥2 份独立文档上同时成立才算成立
4. **分类留痕**：每个失败项标注"源文档固有 / 解析 bug"，前者写进"已知边界"不再追
5. **性能红线**：解析层不得因正确性修复而出现数量级耗时增长（本次 252s 异常即由剖析及时拦截）

---

## 八、一句话总结

> 题目导入的可持续性不来自更聪明的算法，而来自**三件基础设施**：
> **可复现的真实语料门禁**（防劣化）、
> **失败样本的固有/bug 分类学**（防过拟合与无效调参）、
> **提取层结果缓存**（防重复付费）。
> 有了它们，**导入的每一份文档都会让下一次导入更快、更准**——
> 这正是"越导越好"的工程实现。
