### 1.2 关键问题识别

#### 问题1：二维码生成限制
**现状**: 前端无法直接生成二维码（需要后端API支持）
**影响**: PC端扫码登录页面的二维码显示
**解决方案**: 
- 后端已实现 `/api/auth/qrcode/generate` 接口
- 前端调用后端API获取base64格式的二维码图片
- 或使用第三方二维码生成服务（如 `api.qrserver.com`）

#### 问题2：部分功能模块未开发
**现状**: 联考小智模块未开发，智能组卷已完整实现
**影响**: 联考小智功能移动端无法使用
**解决方案**: 
- 智能组卷：复用PC端已有API，完整实现
- 联考小智：在移动端页面中显示"功能还在开发中，敬请期待！"，保留入口但禁用点击

#### 问题3：数据同步依赖
**现状**: 移动端需要与PC端同步数据
**影响**: 需要统一的API接口
**解决方案**: 
- 复用PC端已有的API接口
- 确保Token认证机制一致

## 五、前端二维码生成解决方案

### 5.1 问题分析（根因已实证，2026-09-14 修订）

**现象**: PC 端扫码登录页二维码一直停在"正在生成二维码..."加载不出来。

**真实根因**（此前文档归因"前端无法生成二维码"有误，已修正）:

1. **【决定性】`/api/auth/qrcode/generate` 错误要求已登录**：后端 `auth_qrcode.py` 的 `generate_qrcode` 使用了 `Depends(get_current_user)`，而 PC 端扫码登录页是**未登录**状态调用的，直接返回 401。前端 `download_client.vue` 收到 401 后 `data.uuid` 为 undefined，`if(data.uuid)` 被跳过，二维码永远停在 loading 态。**`generate` 必须是公开接口（无需鉴权）**。
2. **Token 存储键不一致**：`download_client.vue` 用 `localStorage.getItem('token')`，但本项目 `src/auth.ts` 将 token 存在 `__VTJ_AUTH_STATE__` 键下，导致 Authorization 头恒为 `Bearer null`，且确认成功后 PC 端仍无法被应用识别为已登录。
3. **`qrcode` 库未纳入 `requirements.txt`**：`auth_qrcode.py` `import qrcode`，但依赖清单缺失，换环境部署时后端整体启动失败。

**修复方向**: `generate` 改公开接口（移除鉴权）；前端改走 `window.__VTJ_AUTH__` 统一认证（新增 `loginWithToken`）；`qrcode` 纳入依赖；二维码内容由 `liani://` 深度链接统一为**纯 URL**（`{origin}/#/mobile/scan?uuid={uuid}`），使手机相机/微信扫码可直接打开移动端确认页。

### 5.2 解决方案

#### 方案1：调用后端API（推荐）

```javascript
// 前端调用后端API获取二维码
async function generateQRCode() {
  const res = await fetch('/api/auth/qrcode/generate', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ origin: window.location.origin })
  })
  const data = await res.json()
  return data.qr_image_base64 // 返回base64格式的二维码图片
}
```

**优点**:
- 二维码格式统一
- 后端控制过期时间
- 安全性高

**缺点**:
- 依赖后端API
- 需要网络请求

#### 方案2：使用第三方二维码生成服务

```javascript
// 使用第三方服务生成二维码
function generateQRCode(uuid) {
  return `https://api.qrserver.com/v1/create-qr-code/?size=256x256&data={origin}/#/mobile/scan?uuid=${uuid}`
}
```

**优点**:
- 无需后端支持
- 实时生成

**缺点**:
- 依赖第三方服务
- 安全性较低

#### 方案3：前端使用qrcode库

```javascript
// 安装qrcode库
// npm install qrcode

import QRCode from 'qrcode'

async function generateQRCode(uuid) {
  const canvas = document.createElement('canvas')
  await QRCode.toCanvas(canvas, `{origin}/#/mobile/scan?uuid=${uuid}`, {
    width: 256,
    margin: 2,
    color: {
      dark: '#1A365D',
      light: '#FFFFFF'
    }
  })
  return canvas.toDataURL('image/png')
}
```

**优点**:
- 前端独立生成
- 无需网络请求

**缺点**:
- 增加包体积
- 需要npm安装

### 5.3 推荐方案

**综合考虑，推荐使用方案1（调用后端API）**：

1. 后端已实现 `/api/auth/qrcode/generate` 接口
2. 返回base64格式的二维码图片
3. 前端直接显示即可
4. 安全性高，格式统一

### 9.4 扫码登录完整闭环（修订后）

```
PC 未登录访问扫码登录页
  → POST /api/auth/qrcode/generate（公开，body 带 origin）
  → 后端生成 UUID 存 Redis(60s) + 生成 URL 二维码
  → PC 展示二维码 + 轮询 /api/auth/qrcode/{uuid}/status
手机（已登录）扫描二维码（原生相机识别 URL，或网页「扫一扫」jsQR）
  → 打开 /mobile/scan?uuid={uuid}
  → GET /api/auth/qrcode/{uuid}/info（移动端鉴权）取 PC 设备信息
  → 用户点「确认登录」
  → POST /api/auth/qrcode/{uuid}/confirm（移动端鉴权）
PC 轮询到 confirmed + token
  → window.__VTJ_AUTH__.loginWithToken(token)
  → 按角色跳转 dashboard/首页
```
