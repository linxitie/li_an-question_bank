## 二、根本原因深度分析

### 2.1 问题 A：浏览器无法打开整个系统

#### 根因：3 个 .vue 文件 SFC 格式错误

经全量扫描 `.vtj/vue/` 目录下 41 个 .vue 文件，发现 **3 个文件缺少 `<script>` 标签**：

| 文件 | 问题位置 | 具体错误 |
|------|----------|----------|
| `admin_dashboard.vue` | 第 20 行 | `// @ts-nocheck` 和后续 import 语句直接写在 `</template>` 之后，未包裹在 `<script>` 标签中 |
| `teacher_dashboard.vue` | 第 59 行 | 同上 |
| `app_navigation.vue` | 第 29 行 | 同上 |

#### 错误代码示例（admin_dashboard.vue）

```vue
<template>
  <div class="admin-page">...</div>
</template>

// @ts-nocheck                          ← ❌ 这里应该是 <script lang="ts">
import { defineComponent, ref } from 'vue';
import { useProvider } from '@vtj/renderer';

export default defineComponent({
  name: 'AdminDashboard',
  setup() { ... }
})                                      ← ❌ 这里应该是 </script>

<style scoped>
...
</style>
```

#### 影响链路

```
Vite 启动 → 扫描 .vtj/vue/*.vue → 遇到格式错误的 SFC
  → @vue/compiler-sfc 解析失败
  → Vite 预构建报错
  → 开发服务器无法启动 / 浏览器白屏
  → 整个系统无法打开
```

#### 为什么这 3 个文件会导致整个系统无法打开？

1. **Vite 依赖预构建**：Vite 启动时会扫描所有 .vue 文件建立模块图，一个文件解析失败会导致整个构建中断
2. **路由懒加载**：`src/router/index.ts` 中 `() => import('$vtj/vue/teacher_dashboard.vue')` 会在首次访问时触发编译，编译失败导致路由跳转出错
3. **VTJ 静态路由**：`enableStaticRoute: true` 会让 VTJ Provider 自动注册 `/page/{id}` 路由，扫描所有页面时遇到格式错误会中断

### 2.2 问题 B：教师/管理员页面无法正常显示

#### 原因链（5 环）

| 环节 | 描述 | 状态 |
|------|------|------|
| ① 账号名差异 | 用户说的 `yyc5678` 实际是 `ycc5678`（seed.py 第 18 行） | ⚠️ 用户记错账号 |
| ② 登录跳转 | login.vue `getDashboardPath()` 按 role 跳转 `/admin/dashboard` 或 `/teacher/dashboard` | ✅ 逻辑正确 |
| ③ 路由守卫 | `src/router/index.ts` 第 177-188 行，教师/管理员访问 `/` 时重定向到对应仪表盘 | ✅ 逻辑正确 |
| ④ 路由解析 | 跳转到 `/admin/dashboard` → 加载 `admin_dashboard.vue` | ❌ **文件 SFC 格式错误** |
| ⑤ 页面渲染 | Vite 编译 `admin_dashboard.vue` 失败 → 页面白屏 | ❌ **渲染失败** |

#### 结论

**问题 B 是问题 A 的子集**。只要修复 3 个文件的 `<script>` 标签问题，教师/管理员页面即可正常显示。

### 2.3 问题 C：登录后无法回到登录界面，重启无效

#### 根因：login.vue mounted 自动跳转 + token 持久化 + 仪表盘白屏 = 死循环

**问题链路（6 环死循环）**：

```
① 用户登录教师/管理员账号
   ↓
② token 存入 localStorage（key: __VTJ_AUTH_STATE__）
   ↓
③ 跳转到 /admin/dashboard 或 /teacher/dashboard
   ↓
④ 目标页面 SFC 格式错误（缺 <script> 标签）→ 页面白屏/毁坏
   ↓
⑤ 用户尝试访问 /login（手动输入 URL 或点击返回）
   ↓
⑥ 路由守卫放行 /login（第 143-144 行）
   ↓
⑦ login.vue mounted 钩子检测 isLoggedIn() = true
   ↓
⑧ 1 秒后自动跳转回 getDashboardPath()（第 341-345 行）
   ↓
⑨ 回到步骤 ④ → 白屏 → 死循环
```

#### 为什么"重启系统也没用"？

1. **token 持久化**：`src/auth.ts` 第 40 行 `localStorage.setItem(STORAGE_KEY, ...)` 将 token 存入 localStorage
2. **localStorage 不会随浏览器刷新/重启清除**：只有手动清除浏览器数据或调用 `auth.logout()` 才会删除
3. **刷新后路由守卫再次检测**：`src/router/index.ts` 第 153 行 `isLoggedIn()` 读取 localStorage 中的 token
4. **login.vue mounted 再次跳转**：即使访问到 `/login`，mounted 钩子会检测到已登录并跳转走

#### 关键代码定位

**login.vue 第 337-346 行（mounted 自动跳转）**：
```javascript
mounted() {
  if (window.__VTJ_AUTH__ && window.__VTJ_AUTH__.isLoggedIn()) {
    const username = window.__VTJ_AUTH__.getUsername();
    this.showMessage('已登录为 ' + username + '，即将跳转...', 'success');
    setTimeout(function() {
      const dash = this.getDashboardPath();  // ← 返回 /admin/dashboard 或 /teacher/dashboard
      if (this.$router) this.$router.push(dash);
      else window.location.href = dash;
    }.bind(this), 1000);
  }
}
```

**问题**：此逻辑没有提供"退出登录"的入口。已登录用户访问 `/login` 时，无法停留在登录页，也无法清除 token。

**auth.ts 第 186-189 行（logout 函数）**：
```typescript
function logout() {
  localStorage.removeItem(STORAGE_KEY);
  _authPromise = null;
}
```

`logout()` 函数存在且能清除 token，但**仪表盘白屏时无法点击退出按钮**，导致无法触发 `logout()`。

### 4.3 问题 C 修复：login.vue 支持强制退出 + 路由守卫优化

#### 4.3.1 修复方案：支持 `/login?logout=1` 强制退出

**文件**：`.vtj/vue/login.vue` 第 337-346 行

**修改前**：
```javascript
mounted() {
  if (window.__VTJ_AUTH__ && window.__VTJ_AUTH__.isLoggedIn()) {
    const username = window.__VTJ_AUTH__.getUsername();
    this.showMessage('已登录为 ' + username + '，即将跳转...', 'success');
    setTimeout(function() {
      const dash = this.getDashboardPath();
      if (this.$router) this.$router.push(dash);
      else window.location.href = dash;
    }.bind(this), 1000);
  }
}
```

**修改后**：
```javascript
mounted() {
  if (window.__VTJ_AUTH__ && window.__VTJ_AUTH__.isLoggedIn()) {
    // 支持 /login?logout=1 强制退出登录，打破死循环
    const urlParams = new URLSearchParams(window.location.hash.split('?')[1] || '');
    if (urlParams.get('logout') === '1') {
      window.__VTJ_AUTH__.logout();
      this.showMessage('已退出登录，请重新登录', 'success');
      return;  // 留在登录页，不跳转
    }
    const username = window.__VTJ_AUTH__.getUsername();
    this.showMessage('已登录为 ' + username + '，即将跳转...', 'success');
    setTimeout(function() {
      const dash = this.getDashboardPath();
      if (this.$router) this.$router.push(dash);
      else window.location.href = dash;
    }.bind(this), 1000);
  }
}
```

**多角度思考**：

| 维度 | 评估 |
|------|------|
| **为什么这样写** | 已登录用户访问 `/login` 时，默认应跳转到仪表盘（正常 UX）。但需要提供"强制退出"入口，以便在仪表盘白屏时能通过 URL 退出 |
| **好处** | ① 不破坏正常 UX（已登录访问登录页仍会跳转）② 提供紧急退出通道（`/login?logout=1`）③ 用户可自助恢复，无需清浏览器缓存 |
| **安全风险** | 无，logout 操作是前端清除 token，不涉及敏感操作 |
| **运维便利** | 当用户遇到页面白屏时，技术支持可指导用户访问 `/#/login?logout=1` 即可恢复 |
| **VTJ 规则遵守** | 仅修改 mounted 钩子逻辑，符合 VTJ.md 第 3.1 节"Claude Code 维护 `<script>` 业务逻辑"的职责约定 |

### 7.3 紧急恢复方案（用户当前已陷入死循环时）

如果用户当前已陷入"登录后白屏、无法退出"的死循环，在修复代码部署前，可指导用户执行以下操作：

1. **方法一：访问强制退出 URL**
   ```
   http://localhost:9527/#/login?logout=1
   ```
   （此方法在方案实施后有效）

2. **方法二：手动清除浏览器 localStorage**（方案实施前可用）
   - 按 F12 打开开发者工具
   - 切换到 Application → Local Storage → http://localhost:9527
   - 删除 `__VTJ_AUTH_STATE__` 键
   - 刷新页面

3. **方法三：无痕窗口**
   - 打开无痕/隐私窗口重新访问系统
