## 1. N0 — 页面消失的第一性原理归因与找回

### 1.1 第一性原理拆解

"页面不能用"只有四种可能：①代码不存在；②代码存在但没被加载；③加载了但接口报错；④用户看到的不是这套代码。逐项排除：

| 假设 | 检验 | 结果 |
|---|---|---|
| ①代码不存在 | `git show main:`.vtj/vue/ai_chat.vue / study_plan.vue | **存在**，ai_chat.vue 2690 行、study_plan.vue 1895 行（main 比当前多 157 行） |
| ②代码没被加载 | `src/router/index.ts`:98-100 `/ai-assistant`、:104-106 `/study-plan` | 两个路由都在，两分支一致 |
| ③接口报错 | `curl /api/plan/today`、`/api/plan/current`、`/api/llm/sessions` | 全部 **401**（=端点存在、需鉴权），不是 404/500 |
| ④看到的不是这套代码 | `git reflog` + 分支 diff | **命中**：`HEAD@{2026-11-14 09:21:17} checkout: moving from main to feat/teacher-administrator` |

### 2.2 四库职责划分（谁是事实源，谁是可重建）

| 库 | 载体 | 角色 | 存什么 | 可重建 |
|---|---|---|---|---|
| 关系库 | SQLite（`question_bank.db`） | **SoT，唯一事实源** | 题目的结构化字段（subject_id/type_id/point_id/sub_category_id/year/source/难度/全局正确率）、考点主数据、题-考点关系、材料组、图片索引、错题、练习记录、复习计划、用户能力 | 否（有备份） |
| 图库 | `foundation_graph_*`（local_graph：邻接表 + 递归 CTE） | 派生视图 | 考点树 `PARENT_OF`、题→考点 `TAGGED_AS`、考点 `PREREQUISITE`/`PARALLEL`、用户错题 `MISSED_ON` | 是（从 SoT 全量重建） |
| 文档库 | `foundation/stores/local_document`（JSON/JSONL + FTS5） | 派生视图 | 题目文档：题干、选项、解析、材料组全文、图片锚点、段落结构、检索切片 | 是 |
| 向量库 | `local_vector`（`.npy` + ids/meta json，余弦检索） | 派生视图 | `text_questions` 集合：题干+选项+解析的向量 | 是 |

> 派生库**永远不反向写 SoT**。投影失败只影响检索/召回，不影响答题与判分——这是"可降级"的底线。

### 2.3 写入路径（单向数据流）

```
                     ┌──────────── 用户/导入器 ────────────┐
                     ▼                                     │
   [关系库 SQLite] 事务写入 ──► outbox 事件 ──► 投影器 ──────┤
        │                                        ├─ graph_builder      → foundation_graph_*
        │                                        ├─ document_projection→ local_document
        │                                        └─ vector_builder      → local_vector
        │
        └─► reconcile（对账：行数/校验和/孤儿）─► health + gate_l7
```

三条硬规则：
- **R-A** 每次题目/考点变更写一条 outbox 事件（同事务），投影异步消费；
- **R-B** 投影幂等：同一 `(label,key)` upsert，重复消费不产生重复行；
- **R-C** 任一投影可"清空 + 全量重建"，重建期间接口自动回退到关系库直查（降级不报错）。

### 2.4 题目分库分配矩阵（"合理分配"的判定标准）

| 数据 | 关系库 | 图库 | 文档库 | 向量库 | 理由 |
|---|---|---|---|---|---|
| 题目主记录（科目/题型/年份/来源/难度） | ✅ 唯一 | 属性副本 | — | — | 事务与统计需要 |
| 考点层级（L2/L3/L4、父子、排序） | ✅ 主数据 | ✅ `PARENT_OF` | — | — | 下钻与祖先回填是图操作 |
| 题↔考点（一题多考点） | ✅ `question_knowledge` | ✅ `TAGGED_AS` | — | — | 图侧用于聚合与召回 |
| 题干/选项/解析/材料全文 | 保留原始列（兼容旧接口） | — | ✅ 主副本 + FTS 切片 | — | 检索与材料渲染 |
| 图片标记 `[IMAGE:{hash}_{seq}_{idx}]` | `question_image` 索引 | — | ✅ 锚点位置 | — | 锚点必须跟文档结构走 |
| 题干语义向量 | — | — | — | ✅ `text_questions` | 相似题/重复题/错题近邻 |
| 考点先修与并列关系 | — | ✅ `PREREQUISITE`/`PARALLEL` | — | — | 学习路径排序 |
| 用户错题/掌握度 | ✅ | ✅ `MISSED_ON`（用户图） | — | — | 热力与图增强召回 |

### 2.5 "分类绝对准确"的可验证定义（7 个指标，全部可 SQL 复核）

| 编号 | 指标 | 期望 | 查询方式 |
|---|---|---|---|
| K1 | 孤儿题（`point_id` 为空或指向不存在的考点） | **0** | `LEFT JOIN knowledge_point` |
| K2 | 脏引用（`point_id` 指向已删/无效节点） | **0** | 同上 + `level` 校验 |
| K3 | 可下钻节点必须有子节点（否则前端不出箭头） | 100% | 图 `PARENT_OF` 出度 |
| K4 | 同题同考点重复挂载 | **0** | `UNIQUE(user/point/question)` |
| K5 | 图节点数 = 考点数 + 题数（按 label 分） | 恒等 | reconcile 报告 |
| K6 | 文档条数 = 题数 + 材料组数 | 恒等 | reconcile 报告 |
| K7 | 向量条数 = 可向量化题数，dim=1024 一致 | 恒等 | `health.py:115` |

> "绝对准确"在本方案里**不是形容词，是 K1–K7 七条恒等式**；任一不成立则门禁 FAIL，发布阻断。

## 3. M2 — 「其他」收容与下钻治理

### 3.1 为什么"全是其他"（双重成因，缺一不可）

| 侧 | 断点 | 证据 |
|---|---|---|
| 数据侧 | 导入器按"科目下第一个可用叶"兜底，绝大多数落在 L3「其他」 | 3750 题中 `point_id` 为空 630 条（行测 241 / 申论 2 / 公专 387）；91 个 L3 节点名为「其他」，其中 920→706 题、955→529、948→175 |
| 展示侧 | 前端对任意节点都渲染"下钻"，下钻后自然只剩「其他」 | `question_bank.vue` 手风琴（约 :1263）无叶子判定 |
| 记录侧 | 判分服务**从不写** scope 字段 | `backend/app/services/practice_grading.py:153-164` 建 `PracticeRecord` 时不设 `scope_type/scope_id/scope_name/sub_category_id` → 全库 `scope_name` 恒 NULL |
| 统计侧 | 知识点进度按 L3 全量聚合 | `backend/app/api/v1/exam/practice.py:643` 取 `level==3` 全部 → 91 个「其他」各占一行 |

### 3.2 规则引擎（R1–R6，后端唯一实现，前端只读结果）

| 规则 | 内容 |
|---|---|
| **R1 叶子判定** | `is_leaf(node) = (无子节点) or (所有子节点题量为 0)`；`is_fallback(node) = name in ('其他','未分类') and is_leaf` |
| **R2 可下钻** | 接口返回每个节点 `drillable: boolean`（= 有子节点 且 至少一个子节点题量>0）。`drillable=false` 的前端**只显示"练习"按钮**，不显示进入下一级 |

### 4.2 复习单元（把"题目"变成"记忆卡片"）

- **单元 = 1 道错题**（不是考点）：错题才是记忆缺口的最小粒度；
- 若该题属于复合题（`group_id` 非空），复习时**带材料**（材料是记忆上下文，缺材料等于无效复习）→ 与 M5 材料区共用接口；
- 单元上限：单日不排 >60 题（防疲劳，超出顺延）。

### 4.3 记忆模型（可复算的公式）

采用"艾宾浩斯保持率 + SM-2 式稳定度成长"的混合模型：

```
# 1) 难度 D ∈ [0,1]
acc   = 该题历史正确率（无历史则用同考点平均正确率）
lvl   = 题目难度等级 / 5
tr    = min(实际用时 / 该题型基准用时, 1)
D     = 0.45*(1-acc) + 0.35*lvl + 0.20*tr

# 2) 初始稳定度 S0（天）
S0    = 2.2 * (1 - 0.6*D)            # D=0 → 2.2 天；D=1 → 0.88 天

# 3) 复习结果更新
答对：S ← S * (1.5 + 0.9*(1-D))      # 越简单涨得越快
答错：S ← max(0.6, S*0.35)；lapses += 1；间隔固定 1 天并进"当日巩固队列"

# 4) 科目修正系数（信息量越大，保持越差 → 间隔越短）
f(行测)=1.00  f(公安专业)=0.90  f(申论)=0.75

# 5) 下次间隔
I = clamp(round(S * f), 1, days_until_exam - 1)

# 6) 当前保持率（用于 UI 的"遗忘进度"与优先级）
R(t) = exp(-(now - last_review) / S)

# 7) 今日排序优先级
P = (1 - R) * W_subject * (1 + 0.5*lapses) * w_topic
W: 行测 0.45 / 公安专业 0.35 / 申论 0.20      # 由题量×分值混合估得
w_topic: 考纲权重（专业科目按"职业素养 0.2 / 基础知识 0.45 / 基本能力 0.35"，
         行测按"知觉 0.10 / 言语 0.20 / 判断 0.25 / 资料 0.20 / 数量 0.10 / 常识 0.15"，
         申论按"归纳 0.3 / 分析 0.25 / 对策 0.2 / 大作文 0.25"）
```

**基础间隔参考序列**（用于 UI 展示"第 N 次复习"）：1 → 2 → 4 → 7 → 15 → 30 → 60 → 90 天，
实际以公式 ⑤ 为准（同一序列会因 D 与科目浮动 ±40%）。

### 4.4 考试日锚定（本方案的关键创新：复习强度随 D-day 收缩）

| 阶段 | 距笔试 | 排程策略 |
|---|---|---|
| 常态期 | T-∞ ~ T-61 | 全量复习 + 新增练习；配额 = 用户日均可用时长 / 平均单题时长 |
| 强化期 | T-60 ~ T-31 | P < 0.3 的题暂停（已牢固），配额不变 |
| 收敛期 | T-30 ~ T-15 | 只排 P ≥ 0.5；连续 3 次答对的题移出队列 |
| 模拟期 | T-14 ~ T-8 | 复习量降到 30%，让位全真模拟；只保留高危题 |
| 冲刺期 | T-7 ~ T-1 | 只排 `lapses≥2 或 D≥0.6`；每日 ≤20 题；不排新题 |
| 考后 | T+1 起 | 队列归档，生成"复盘报告" |

```

```

## 9. M8 — 答题卡横线丢失（解析层，不是渲染层）

### 9.1 结论修正（重要）

上一版曾判断"3750 题含下划线"，**该结论作废**：`LIKE '%___%'` 中的 `_` 是 SQL 通配符（匹配任意单字符），导致全表命中。

实测真值：
| 检验 | 结果 |
|---|---|
| `GLOB '*___*'`（真实连续下划线） | **2 题** |
| 提到"横线/划线" | 32 题，其中 **30 题没有任何占位符** |
| `（）` 空括号 | 79 题 |
| `<u>` 标签 | 0 |
| 渲染器是否有删线逻辑 | **无**（`src/utils/questionRender.js` 全文：ALLOWED_TAGS 含 `u` :19-23；`INLINE_OPTION_RE` :35；`formatRichContent` :202-257 只按行 trim，不动下划线） |

**根因**：Word 里的横线是 `run` 的**下划线格式**（`w:u`）或带下划线的空格/制表位，`python-docx` 只取 `run.text` → 纯空白被丢弃。实证：题 3666（"编译工作是寂寞的…"）原始题干在"岗位上"与"的写照"之间**只剩一个半角空格**。

### 9.2 修复

1. **解析器**（`backend/app/services/*docx*` 导入链）：遍历 run 时保留格式
   ```python
   for run in para.runs:
       if run.underline and not run.text.strip():
           buf.append("____")          # 下划线空格 → 四个下划线
       elif run.underline:
           buf.append(f"<u>{run.text}</u>")   # 有字下划线 → 保留下划线语义
       else:
           buf.append(run.text)
   ```
2. **渲染器**：`ALLOWED_TAGS` 已含 `u`；补样式 `.rich-content u { text-decoration: underline; text-underline-offset: 3px; }`；
3. **历史回填**：32 题中 30 题无占位符 → 脚本按"填入横线/划线部分"前后文定位，生成 `____` 插入方案，
   **输出 diff 报告人工确认后再 apply**（不盲改 30 道真值题）；
4. **导入侧同源**：教师端导入（`question_import`）与 PDF 重导共用同一 run 解析器，杜绝"新导入又丢"。
