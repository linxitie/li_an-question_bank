## 1. 一句话结论

上传 docx / pdf 试卷后**当场拆题**，结果先落「解析草稿」（待确认清单），管理员在管理端逐题核对（改题号/题型、删误拆、看图片归属），点「确认入库」才写进题库并挂到卷上 —— **错位入库这道关，留在人手这一侧**。

真实数据实测：`#128 2016 江西招警（部分）.docx` → **97 题，题号 1–97 连续，四选项齐全 97/97**；`2024 国考 PDF` → **100 题（单选 70 / 多选 30）、8 组情境材料、25 张图**，题型分布与库里已人工核对过的卷**完全一致**。

## 2. 链路（方案 §3.1 落地）

```
上传原件（docx/pdf，type=paper 且 role=primary）
  └─ readers.read_docx / read_pdf   读文本行 + 抽图（带归属题号）
       └─ splitter.split_questions  题号/选项/题型状态/情境材料/告警
            └─ paper_parse_draft (status=pending, 30 天保留)   ← 草稿，学生与题库都看不到
                 └─ 管理端「导题确认」抽屉：逐题核对（可改题号/题型、删、看图片尺寸）
                      └─ 确认入库：question_bank + paper_question_relation
                         + 图片复制到 static/questions/{qid}/ + 卷 question_count 重算
                         + 若资料已上架 → P5 联动推成 PUBLISHED（学生可考）
```

为什么必须"待确认"：自动拆题在 2024 国考那套卷上验过，但不同来源排版差异极大；一旦错位，学生做到的就是错题，而且**错得很像对的**。

## 3. 拆题规则（`services/paper_ingest/splitter.py`，纯函数）

| 规则 | 说明 | 实测来源 |
|---|---|---|
| 题号 | `1.` `1．` `1、` `第1题`；**"2023 年"不会被当成第 2023 题**（必须带分隔符/第N题） | 2016 江西卷首段就是"2013年3月15日…" |
| 选项 | 一行多个 / 一行一个 / 跨行续接；全角字母也能认 | 2016 江西一行四个、2024 国考多行 |
| 题型 | **段落状态机**：`【题型】多选`、章标题`二、多项选择题`切换后续默认；逐题内联`（多选）`覆盖 | 2024 国考只有 4 处显式标记，其余靠章标题 |
| 内联标记被换行切断 | `（多\n选）` → 去空白后再匹配 | 2024 国考第 92 题 |
| 情境材料 | `根据以下情境材料，回答 91~100 题` → 组内共享；材料正文**不会**被吸进上一题（块在材料标题处截断） | 2024 国考 8 组 |
| 结构行 | 章标题/题型标记/材料标题不算选项续行 | 修 bug：`二、多项选择题（每题2分）`曾被接到 D 选项尾巴 |
| 汉字空格 | 只在汉字之间删（PDF 折行），数字与年月之间也删；英文单词间保留 | `会议指 出`、`2023 年 5 月` |
| 告警 | 题号重复/缺号、选项不全、依赖图、有图待核对、题量与预期不符 | 确认页顶部一次列清 |

图片归属：
- **docx**：按段落顺序 → 图上方的最近题号（正文里"图在段落中"是结构信息，比坐标稳）；
- **pdf**：按版面坐标 → 同页上/下两题取纵向更近者，跨页回退（沿用 `_run/map_all_images_v2.py` 已跑通的规则）；
- 过滤门槛：短边 ≥60 且面积 ≥8000 才算题图（挡掉行内图标）；**不硬猜可疑归属**，而是给该题打「有图待核对」，让管理员在确认页一眼删掉。

## 4. 数据与接口

新表 `paper_parse_draft`（启动期 `create_all` 自动建，实测列已就位）：

| 列 | 说明 |
|---|---|
| `draft_id` / `material_id` / `paper_id` | 草稿、来源资料、目标卷 |
| `status` | `pending` 待确认 / `confirmed` 已入库 / `discarded` 已放弃 / `failed` 解析失败 |
| `item_count` / `items_json` / `warnings_json` | 题目草稿与整卷告警 |
| `message` | 失败原因 / 入库摘要 |
| `images_dir` | 草稿私有图片目录（确认或放弃后即删） |
| `expires_at` | 解析后 30 天（决策 S3） |

新增 6 个管理端端点（API 面 345 → **351**，按 R11「只登记不重算」）：

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/api/materials/admin/{material_id}/parse` | 解析（上传时自动调，也可手动重试） |
| GET | `/api/materials/admin/parse-drafts?status=pending` | 待确认列表 |
| GET | `/api/materials/admin/parse-drafts/{draft_id}` | 明细（题目 + 告警） |
| PUT | `/api/materials/admin/parse-drafts/{draft_id}/items` | 整表保存（改题号/题型/删） |
| POST | `/api/materials/admin/parse-drafts/{draft_id}/confirm` | 确认入库（`replace` 覆盖） |
| DELETE | `/api/materials/admin/parse-drafts/{draft_id}` | 放弃草稿 |

上传回包多一个 `parse` 块（`status` / `item_count` / `hint`），管理端列表每行多一个 `parse_draft` 摘要 → 标题下显示「待确认 97 题」小标签。

## 5. 为什么是"同步解析"而不是后台任务

方案里写的是"上传时后台触发"，实现时改成**同步**，原因是真实存在的风险：

> pytest 的 `conftest` 只覆盖了 `get_db` 依赖（内存库），而 `SessionLocal` 仍指向**真实** `question_bank.db`。
> 后台任务没有请求会话，只能自己 `SessionLocal()` —— 那会在跑测试时**写生产库**。

同步解析用同一个 request session：测试安全、回包能直接告诉用户"拆出几题"、失败也不影响上传（try/except 兜住）。
代价是每个 docx/pdf 上传多 0.2–1.5s（实测 97 题 docx 0.2s、100 题+25 图 pdf 1.5s），批量导入是逐文件请求，进度条照常走。

## 6. 过程中修掉的 4 个真 bug

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| B1 | 选项 D 里混进了下一章的标题「二、多项选择题（每题 2 分）」 | 选项跨行续接规则把结构行也续进去了 | 加 `_is_structural()`，结构行终止续接 |
| B2 | 上一题题干里混进了下一组的**情境材料正文** | 块的边界只按题号切，材料标题在其后 | 块内遇到材料标题即截断 |
| B3 | docx 末尾的二维码/水印图被挂到最后一题 | 尺寸无法可靠区分"小图/真图" | 门槛放宽到短边 60 + 面积 8000，同时打「有图待核对」交人工 |
| B4 | 入库后卷还是 DRAFT（资料本来就已上架）→ 学生看不到 | 只写了题目，没触发 P5 联动 | 确认入库后调 `material_paper_sync.sync_material` |

B1/B2 是单测抓出来的（`test_parses_...` / `test_shared_material_attached_to_group` 先红后绿）。

## 9. 已入库会怎样（给"确认"这一步的预期）

点「确认入库」后：

1. 97 道题写入 `question_bank`（`status=1 / audit_status=1 / answer 空`，答案按决策⑤等 P4 补）；
2. 建 97 条 `paper_question_relation`，`exam_paper.question_count = 97`；
3. 图片复制到 `app/static/questions/{qid}/`，正文 HTML 里是 `/static/questions/{qid}/...`；
4. 资料 #128 已是「已上架」→ P5 联动把卷 #5 推成 **PUBLISHED**；
5. 考试开关默认开 → **学生列表立刻多出第 4 套卷**（这就是"定时放考 + 上传即导题"合起来的完整效果）。

所以这一步是**面向学生的数据变更**，我没有替你点：等你确认"97 题可以入库"再执行。

## 10. 已知边界

1. **答案不入库**（决策⑤）：卷里 97 题答案为空，交卷时客观题会按"错"计分 —— 导题后请尽快跑 P4（答案上传）。
2. 判断题按单选处理（`question_type` 只有单选/多选两种），`question_level=1/2` 用"是否情境组"区分。
3. 表格型选项（Word 表格里 A/B/C/D 四列）目前按"行拼成一行"读，可能粘在一起；确认页可改，但极端排版仍需人工。
4. 扫描版 PDF（图片型）不在本轮：需要 OCR，走既有 MinerU 链路。
5. 题库去重没做（同内容重复导题会产生两道题），靠"卷里已有题就 409"兜住重复导入同一份原件。
