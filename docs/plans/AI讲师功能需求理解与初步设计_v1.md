| **3** | 研究真人视频是**怎么把一段知识拆开讲、再统一逻辑**的，总结成可用于 AI 讲师的设计，但**不要一模一样** | 要沉淀一套**讲解结构模板**（引入→概念→拆解→例子/场景→易错→小结）和**分镜规则**（一句话一个镜头？一个要点一段？），并允许参数化变化 | 参考而不照抄：模板可配置节奏/口吻/长度 |

## 3. 我打算怎么学「真人讲解」（这里要说实话）

**我无法直接“看”视频**（没有视频理解能力）。我能做的是：

1. **你给素材我拆解**：给我 2–3 个参考视频的链接/文件，最好是**带字幕或逐字稿**，我可以按时间轴拆出「分句 → 镜头 → 动作 → 强调点」，归纳成模板；
2. **不给素材就用成熟范式**：按讲授法/微课结构（引入—目标—概念—拆解—例证—易错—小结）+ 常见讲解节奏（每 20–40 秒一个要点、每 3–5 分钟一个互动）产出模板，再让你按截图/观感修订；
3. **肢体动作做成参数化库**（不是逐帧动画）：指向（board/left/right/self）、手势（open/point/count/emphasis）、表情（neutral/smile/serious/surprise）、节点头部微动——由讲稿里的语义标签触发（`action: point_board` / `expression: serious`）。

> 结论：**能做得像“讲课”**，但“像某位真人老师”需要你提供参考素材或明确风格描述。

## 4. 关键技术取舍（需要你拍板）

| 方案 | 说明 | 依赖 | 优点 | 缺点 |
|---|---|---|---|---|
| **A. 网页交互播放器（推荐先做）** | 讲师/场景/板书全部是 SVG+CSS 动画，播放器按「讲稿 JSON」驱动；互动题同一页面右侧面板 | 无外部服务 | 现在就能开工；交互体验与截图完全一致；后期导出视频也不难 | 不是“真视频文件”，画面精细度受 SVG 限制 |
| B. 真视频（数字人/TTS 合成 mp4） | 需要数字人平台 + TTS + ffmpeg | 外部付费服务 + 本机 ffmpeg（**当前未安装**） | 更“像视频” | 成本/周期高，形象不可即时改，互动需另做叠加层 |
| C. A 先做 + 后期录制导出 | 先用 A 跑通内容与互动，再用播放器自动录制成 mp4（MediaRecorder / ffmpeg） | A 全部 + ffmpeg | 兼顾“可交互”和“有视频文件” | 中期工作量多一步 |

**我的建议：A 先落地**（也是你“预留底座”的最佳形态：播放器只认脚本，不认来源），等视觉/脚本稳定后再决定要不要真视频。

## 5. 初步架构（底座）

```text
知识点清单（你给：科目/标题/要点/易错/题目）
        │
        ▼
讲稿生成（LLM 或手工）→ lecture_script.json（DSL）
        │   segments[]:
        │     { type: intro|concept|demo|scene|checkpoint|summary,
        │       speech, board[], avatar:{gesture,expression}, 
        │       scene:{kind: classroom|police|formula, props[]},
        │       duration_hint,
        │       question?: { stem, options[], answer, analysis } }
        ▼
播放器（前端组件）── 状态机：playing → paused(checkpoint) → answering → feedback → resume → ended
        │
        ├── 讲师层（SVG 形象 + 动作/表情）
        ├── 板书层（要点逐条出现）
        ├── 场景层（卡通情景/公式动画）
        └── 互动层（题目面板 / 正误反馈 / 粒子动画）
```

**为什么是这套**：以后「按题/按卡自动生成」时，只需把「生成器」的输入从知识点清单换成题目/卡片，DSL 与播放器一行不改 —— 这就是你要的**底座**。

**后端形态**：先做 `lecture_script` 的**静态 JSON**（放前端 public 或后端表里），不急着加新端点；等自动生成时需要 `POST /api/lectures/{id}/generate` + 任务表（原评估报告里第①步）。

## 8. 风险与边界

1. **版权/肖像**：AI 讲师形象与场景画风必须原创（不能用真人照片/影视截图）；参考视频只做风格分析，不复制画面。
2. **无障碍与性能**：SVG/CSS 动画要控制帧率与节点数，低端平板也要流畅；字幕必须可关。
3. **内容准确性**：讲稿由 LLM 起草时必须人工审（法条/公式错一个就是事故）；建议在脚本里加 `review_status` 字段。
4. **与现有约束的关系**：新增页面可用手写页（`src/views/...`）避免动 `.vtj` 模板；若入口要放进 VTJ 页，走 DOM 注入（守 R3）；新增端点需登记 R11 白名单。
