# C3 试卷筛选（年份 / 地区 / 卷别）交付记录 v1

- 日期：2026-11-08
- 分支：`feat/material-multi-format-import`（**未合并 main、未推送远端**）
- 对应方案：《资料管理 v3.1》§5 **C3**（科目+试卷筛选 + 年份/地区/时间范围）
- 一句话：资料管理页在「类型=试卷」时多出 **年份 / 地区 / 卷别** 三个下拉，能直接筛到「2019 · 北京 · 题本」这一份。

---

## 1. 做了什么

| 层 | 内容 |
|---|---|
| 后端 | `GET /admin/list` 新增 `paper_year`（1900–2100）、`region`（地区代码 `BJ` 或中文 `北京`）、`book_kind`（`T/A/J`） |
| 口径 | 与预览一致：**`paper_meta` 人工订正 > 文件名解析**；带试卷筛选时**非试卷类一律排除**（问的是"2019 年的试卷"，卡片/讲义不该出现） |
| 实现 | 年份/地区有两种来源（JSON 订正 / 标题解析），SQL 表达不了"订正优先"→ **SQL 预筛 + Python 精筛 + 手动分页**；资料是百级，全量取回可接受（超过 ~5000 条应改落库列+索引，接口不变） |
| 行字段 | 每行回传 `paper_year / paper_region / paper_book_kind`（前端回显与调试用） |
| 前端 | 「类型=试卷」时显示三个下拉（年份 12 年滚动 / 地区 33 项 / 卷别 T·A·J）；切回其它类型自动隐藏并清空；支持地址栏深链 |
| 深链 | `#/admin/materials?type=paper&year=2019&region=BJ&book_kind=T` —— `materialListQuery` 白名单新增 `year/region/book_kind` |

## 2. 实测（真实数据 3 套试卷）

```
全部试卷        : 3 → 127(2024,国考,T) 126(2017,江苏,T) 125(2019,北京,T)
paper_year=2019 : 1 → 125
paper_year=2017 : 1 → 126
region=BJ       : 1 → 125        region=江苏(中文) : 1 → 126
book_kind=T     : 3 → 全部（三套都是题本）
year=2019+region=BJ : 1 → 125
year=2020（无）  : 0
不限定类型 + year=2019 : 1（只有 125），非试卷被排除
```

```
下拉：全部科目 / 试卷 / 全部状态 / 2019 年 / 北京 / 题本 / 全部时间
列表：共 1 条 → 125  GZ-2019-BJ-T·历年真题
```

## 4. 过程中自查出的一个坑

前端 `fetchAdminMaterialList()` 是**手工拼参数**的（不是透传整个 query 对象），
我只在 TS 类型里加了 `paper_year/region/book_kind`，**没有把它拼进 params** →
深链/下拉都不生效（首次实测"共 3 条"没变）。补上后深链与下拉都正常。
教训：给列表加筛选，三处必须同时改 —— **后端 Query 参数 / 前端类型 / 前端拼参数**。

## 5. 遗留

| 项 | 说明 |
|---|---|
| **年份下拉是静态 12 年** | 从今年往前 12 年；更早的年份用地址栏 `?year=2013` 仍可筛（后端范围 1900–2100） |
| **筛选项没有"可选值"统计** | 不会只有存在数据的年份才可选；后续可加 facets 接口（需 R11 +1） |
| **C 批剩余** | 只剩 **P5 上下架联动**（写 `exam_paper.paper_type`，需先定实现方式：`exam/contract.py` + 基线登记（需批准）或事件） |
