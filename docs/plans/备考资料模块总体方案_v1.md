```

├── feat/Study-Material-Management-doc-content      ← (2) 科目说明文档
├── feat/Study-Material-Management-card             ← (1) 资料卡片（视觉）

├── feat/Study-Material-Management-growth-link      ← (6) 成就/金币/徽章
├── feat/Study-Material-Management-upload-format    ← (3) 格式规范 + 分类机制【专利】
└── feat/Study-Material-Management-ai-lecturer      ← (4) AI 讲评/视频【专利·外部阻塞】
```

**为什么子分支用 `-<子任务>` 而非 `/`**：Git 里 `feat/X` 一旦是分支文件，就不能同时是目录，`feat/X/Y` 必然报 `cannot lock ref`（本会话已两次实测）。`feat/Study-Material-Management-card` 与父分支互不为前缀，可共存。

**依赖顺序（我的建议）**

| 序 | 子分支 | 依赖 | 理由 |
|---|---|---|---|
| 1 | `-doc-content` | 无 | 先定"资料长什么样"（科目说明结构），后面卡片与格式都以此为准 |
| 2 | `-card` | doc-content 的字段口径 | 视觉基础，其它两个视觉任务都复用其组件 |
| 3 | `-multi-device` | card 的组件抽象 | 三端差异建在卡片之上，晚做返工少 |
| 4 | `-growth-link` | 无（奖励引擎已存在） | 可与 2/3 并行 |
| 5 | `-upload-format` | 1、2 定稿（需要知道字段与分类） | 出规范 + 校验器 + 专利材料 |
| 6 | `-ai-lecturer` | 外部能力确认 | 阻塞项，最后 |

**合并纪律**：子分支 → `feat/Study-Material-Management`（父）；六个就绪且你在父分支验收后才可由你指示合 `main`。**不跳层。**

## 3. (1) 资料卡片

**现状**：`study_materials.vue` 只有"科目卡"（3 张），资料本身是列表项。

**方案**
1. **资料级卡片**复用表字段：`card_front`（正面：标题/封面/难度/时长）、`card_back`（翻转为详情摘要 + 入口按钮）、`cover_image`、`badge`（如"新/热/精品"）。
2. **分类准确性**不靠前端硬编码，而由 `material_classification_rules` 驱动（§6），前端只消费 `subject/type/category` 三元组。
3. **流畅性**：分页（`page_size`）+ 骨架屏 + 图片懒加载；卡面动效只用 `transform/opacity`（走 GPU，不触发重排）。
4. **模板改动归属**：卡片 DOM 结构由你在设计器绘制（如"封面区/标题区/角标/进度条"容器），我给每个容器绑定数据与交互（`@click`、`:style`、`v-for` 的 script 侧逻辑）。

**验收**：`/materials/xingce` 出现资料卡；点卡片可看背面；3 条以上数据时滚动不卡（Performance 面板无长任务 > 50 ms）。

## 4. (2) 科目说明文档

**方案**：不新建表，用 `study_material` 自身承载——`type='GUIDE'`、`subject=<科目>`、`content` 存结构化说明（建议 Markdown 子集）、`summary` 存一句话摘要。

**内容结构（模板固定，便于批量生产）**

```
1 考试定位（这场考什么、与其它科目的关系）
2 题型与配比（题型 / 题量 / 分值 / 建议用时）
3 高频考点（Top-N，按 `knowledge_point` 94 条对齐）
4 备考路径（3 阶段：基础→专项→冲刺，各阶段资料引用）
5 常见误区（≤5 条）
```

**前端**：在 `materials_{subject}.vue` 顶部加"科目说明"入口（模板由你拖拽），详情用现有 `/{material_id}` 接口取。

**验收**：三科各有 1 篇说明；正文 ≤ 2000 字；含 Top-10 考点且都能在 `knowledge_point` 找到同名字段。

## 5. (3) 上传格式规范 + 分类机制【专利材料 A】

### 5.1 现状缺口
`material_classification_rules` 有表无数据；导入只校验"能否解析"，**不校验内容格式是否合规**，也没有自动分类落点。

### 5.2 方案：三层

| 层 | 内容 |
|---|---|
| **格式层** | 定义"备考资料包"最小规范：单文件（`.md/.docx/.pdf`）或资料包（`.zip` 含 `manifest.json`）。`manifest.json` 必填 `subject`/`type`/`title`/`category` 候选/`source`/`version`；选填 `tags`/`knowledge_point_codes`/`cover` |
| **校验层** | 导入 `preview` 阶段返回 `format_report`：必填缺失、字段超长（`title≤200`、`summary≤500`）、`content_hash` 重复、图片尺寸/体积、视频编码与时长上限；`confirm` 仅在 `format_report.blockers=0` 时放行 |
| **分类层** | `material_classification_rules` 种子规则：按 `subject`（行测/申论/公专）+ `type`（DOC/VIDEO/GUIDE）+ 标题关键词/考点编码 → 产出 `category`；规则按 `priority` 顺序命中，`enabled` 可灰度 |

### 5.3 拟新增端点（**R11 需你显式批准**）

| 方法 | 路径 | 用途 | 是否必需 |
|---|---|---|---|
| `POST` | `/api/materials/admin/import/{import_id}/validate` | 返回 `format_report`（不改现有 `/preview` 语义） | 建议 |
| `GET` | `/api/materials/admin/classification-rules` | 规则列表与试跑 | 建议 |
| `POST` | `/api/materials/admin/classification-rules/reload` | 规则热加载（免重启） | 可选 |

> 若你不同意新增端点，替代方案：把 `format_report` 塞进现有 `/preview` 响应的新字段（**不改端点**，仅扩字段）——这是**零端点新增**的备选，我倾向前者更清晰，但两者都可行。

### 5.4 专利材料要点（A）
1. 一种面向考试备考资料的**结构化文档格式**（manifest + 内容 + 元数据三元组）；
2. **规则优先级驱动**的自动分类方法（`subject × type × 关键词/考点码 → category`，含冲突消解）；
3. **导入前格式合规校验**与阻断式闸门（blockers 语义）；
4. 与去重（`content_hash` + 相似度）联动的**增量更新**机制。

## 6. (4) AI 数字人讲评 + AI 视频生成【专利材料 B】

### 6.1 现状：外部能力缺失
- 表里只有 `study_material.video_id` 指向既有视频表，**没有任何 AI 生成链路**；
- 本机无 TTS / 数字人 / 视频合成服务的证据（与 DeepInfer 同族问题：不许虚构）。

### 6.2 方案：契约优先 + 可插拔 provider（先不写实现）
```
POST /api/materials/{id}/ai-lecture   （拟新增，R11 需批准）
  入参: { style: "real-person-teacher", language: "zh", avatar?: id, duration_hint?: sec }
  出参: { job_id, status: "queued|rendering|done|failed", video_id? }
依赖 seam: ctx.lectureProvider（默认 null → 端点直接 501 Not Implemented）
```
**分三步走**：① 契约 + 任务表 + 状态机（可先落地，无外部依赖）；② 接 TTS/字幕（音频先行，成本最低）；③ 接数字人与视频合成（最高成本）。

### 6.3 专利材料要点（B）
1. 由**结构化讲稿（§4 的科目说明 + 考点）自动生成分段讲解脚本**的方法；
2. 讲解风格参数化（语速/停顿/强调词/板书节奏）映射到 TTS 与数字人动作的**映射表**；
3. 视频与资料卡背面的**双向锚点**（视频时间码 ↔ 卡片知识点）；
4. 生成任务的状态机与失败降级（音频可用、视频失败时回落图文）。

### 6.4 明确不做
在你提供可用服务（`base_url`/协议/模型/限额）之前，**不写任何生成代码**，只落契约与 501 占位。

## 7. (5) 三端适配（翻页 / 3D / 字号）

### 7.1 现状
`mobile/materials`、`tablet/materials` 路由已存在但**复用桌面页**（R12 禁止复制新页）。因此三端差异必须在**同一页面内**按 `meta.platform` 适配，而不是新建页面。

### 7.2 技术选型（含降级，必须可关）

| 效果 | 实现 | 降级条件 |
|---|---|---|
| **翻页** | CSS 3D `rotateY` + `transform-style: preserve-3d` + `perspective`；手势用 pointer events（统一鼠标/触摸） | `prefers-reduced-motion: reduce` → 直接切换无动画 |
| **裸眼 3D** | 视差：`mousemove`/`deviceorientation` → `translate3d` 微位移；**不用 WebGL**（包体与耗电不划算） | 低端设备（`hardwareConcurrency ≤ 4` 或 `deviceMemory ≤ 2`）→ 关闭 |
| **字号适配** | 根级 `--sm-font-scale`（0.9/1.0/1.15/1.3 四档）+ `clamp()` 流式字号，档位存 `localStorage` 与用户偏好 | 无 JS 时回落 `rem` 基准 |
| **布局** | 断点：`<768` 单列、`768–1199` 双列、`≥1200` 三列；卡片宽高比固定避免 CLS | — |

### 7.3 性能预算（硬指标）
- 首屏卡片 ≤ 20 张、图片 `loading="lazy"` + `decoding="async"`；
- 单卡动效 DOM 节点 ≤ 40，动画只用 `transform/opacity`；
- 三端同一份 JS，不做平台分支打包（避免包体翻倍）。

### 7.4 VTJ 协作规程（R3 落地，必须遵守）
1. 你负责：在设计器里放置容器与视觉结构（卡片正反两面、翻页容器、字号切换按钮）；
2. 我负责：`<script>` 内的状态/手势/档位逻辑 + `<style>` 变量（`design-token`），**先 `dryRun: true` 预览**；
3. 每次改 script 后由你在设计器回存，**再由我跑 DSL 漂移检查**（避免同步器覆盖）；
4. 改完必须 `npx vue-tsc --noEmit` 与 `npm run test:unit` 通过。

## 8. (6) 成就 / 金币 / 徽章联动

### 8.1 复用既有引擎（不新建体系）

| 联动 | 落地方式 |
|---|---|
| **阅读即得** | 学习进度 `POST /api/materials/progress` 完成后发事件 `material.read`（含 material_id/subject/首次或重复） |
| **成就** | 新增 `achievement.condition_code`：`MATERIAL_READ_COUNT`（累计 N 篇）、`MATERIAL_SUBJECT_COVER`（某科全覆盖）、`MATERIAL_VIDEO_WATCH`（看完 N 个视频）；`threshold` 复用现有列 |
| **金币** | 经 `coin_record`（`source_type='MATERIAL'`、`related_id=material_id`），**幂等键**防刷（同一 material 同一用户只计一次） |
| **徽章设计** | `badge_name_bank`（prefix/body/suffix + `style_seed` 决定图形）+ `badge_title`（3 级称号）已具备"生成式命名"能力，只需按资料主题填入词库 |
| **任务** | `badge_task` 新增 `metric='material_read'` 类任务，`user_task_progress` 复用（含 `period_key` 日/周/月） |

### 8.2 防刷与公平
- 事件去重：`(user_id, material_id, action)` 唯一；
- 阅读时长校验：`duration_used ≥ read_time × 0.5` 才计"已读"；
- 每日上限：资料类金币每日封顶（与既有 `coin_record` 日汇总对齐）。

## 9. 分阶段计划

| 阶段 | 内容 | 验收 | 依赖 |
|---|---|---|---|
| **P0 数据与规范** | 分类规则种子（≥10 条）+ 1 篇科目说明 × 3 + 格式规范文档 | 规则命中率 ≥ 90%（拿 20 条样例试跑）；三科说明全文可读 | 无 |
