# AI 讲师 · 获取「看视频」能力的方案 v1（工具选型 + 实测）

> 日期：2026-11-05　｜　状态：📋 待你批准后落地（本机环境改动，不碰仓库代码）
> 你的问题：**哪个插件能让我获得视觉能力、能观看视频学习讲解方式和风格**
> 一句话回答：**不需要"视觉插件"——我的视觉通道（`read_image`）本来就是通的；缺的是把视频解码成图片序列的解码器。** 这个解码器 ffmpeg，实测 **1 分钟内就能装好并出图**（见 §2 证据）。

---

## 1. 先厘清概念：插件 vs 工具链

| 能力 | 现状 | 说明 |
|---|---|---|
| **看图** | ✅ 已有（内置 `read_image`，支持 PNG/JPEG/WebP/GIF） | 不需要任何插件。你给我截图、我截屏、我抽帧，都能读 |
| **从视频取图** | ❌ 缺（本机无解码器） | 这才是真正的缺口：需要 ffmpeg 或 PyAV 把 mp4 变成 png |
| **听声音/台词** | ❌ 缺（无 ASR） | 需要 faster-whisper 之类的语音识别 |
| **读板书文字** | ❌ 缺（无 OCR） | 可选：rapidocr；但我看图也能读到板书文字，OCR 只是结构化提速 |
| **视频理解（整段语义）** | ⚠️ 可选 | 云端 VLM（通义/智谱/豆包/硅基流动）或本地 VLM（Qwen2.5-VL） |

> 我查了当前装着的 DSH 插件：`dshmarket`、`dsh-context`、`dsh-obsidian`、`@jasonfreelab/dsh-superpowers` —— **没有任何一个提供视频解码能力**；市面上也没有"Dsh 视频插件"这种东西。能力要靠**本机工具链**，不是靠装插件。

## 2. 实测证据（今天已经跑通，未改系统环境）

| 步骤 | 做法 | 结果 |
|---|---|---|
| 装解码器 | `pip install --target %TEMP%\ffmpeg_poc imageio-ffmpeg`（**隔离目录，不动系统、不动 PATH**） | 得到 `ffmpeg-win-x86_64-v9.0.2.exe`（100.5 MB） |
| 取帧 | `ffmpeg -ss 00:02:00 -i "…p06 06传唤…mp4" -frames:v 1 -vf scale=1280:-2 out.png` | 3 帧成功（582 / 643 / 815 KB） |
| 我读图 | `read_image` 打开 `00:12:00` 那帧 | ✅ 完整读出：标题「调查取证——传唤」、表格三行（传唤对象 / 口头传唤和书面传唤 / 如何理解"现场发现的违法嫌疑人"）、老师**红色手写标注**（圈住"传唤"、多处下划线）、底部大字幕「其他发现嫌疑人的地点」、右上角水印与印章 |
| 时序对比 | 同一集 `00:02:00` 与 `00:12:00` 两帧对比 | 看出**老师在原位逐条加红笔标注**、字幕随讲稿换行、表格是静态底图 → 这就是"讲解方式"的直接证据 |

**结论：视觉能力现在就有；把 ffmpeg 正式装好之后，就能批量、连续地看。**

## 3. 三条路线（按推荐度）

### 路线 A：本机 ffmpeg + 我读图（推荐，零 API 成本）

| 环节 | 工具 | 实测/预估 |
|---|---|---|
| 解码、抽帧、场景切分、拼图 | **ffmpeg**（`winget install Gyan.FFmpeg` → 9.0.2，winget 源实测可用） | 装 1 分钟；抽帧 ~1–2 秒/帧 |
| 场景切换点 | `ffmpeg -vf "select='gt(scene,0.3)'"` | 找出"翻页/切场景"的时刻，避免抽到重复画面 |
| contact sheet（拼图） | `ffmpeg -vf "tile=4x6"` 或 ImageMagick | 24 帧/张 → 我一次读一张就能看 24 个时间点 |
| 台词 | **faster-whisper 1.2.1**（pypi 可达）+ uv 的 **Python 3.11** + `HF_ENDPOINT=https://hf-mirror.com`（hf 主站 000、镜像 200） | 90 分钟音频 GPU 约 8–15 分钟 |
| 板书文字（可选） | **rapidocr-onnxruntime 1.2.3** | CPU 约 1–2 秒/帧 |
| 成本 | 0 元；磁盘约 2 GB（模型 + 抽帧） | — |

### 路线 B：云端视频理解大模型（省事，但花钱 + 要 key）

| 服务 | 端点实测 | 用途 | 限制 |
|---|---|---|---|
| 智谱 GLM-4V | `open.bigmodel.cn` → **200** | 单帧/多帧画面描述 | 需 key；视频要自己切片上传 |
| 火山方舟（豆包视觉） | `ark.cn-beijing.volces.com` → **401**（可达） | 同上 | 需 key |
| 通义千问 VL | `dashscope.aliyuncs.com` → **404**（可达） | 同上 | 需 key |
| 硅基流动 | `api.siliconflow.cn` → **404**（可达） | 同上 | 需 key |
| Google Gemini | `generativelanguage.googleapis.com` → **000（不可达）** | — | 网络不通 |

**但我不建议把它当主力**：①要 key、要花钱；②这类模型给的是"这段在讲什么"的粗描述，**给不了"手势在第几秒、讲完一个要点停顿多久"这种量化细节**；③课程视频属付费内容，上传第三方有合规顾虑（与 R6 版权口径冲突）。

### 路线 C：本地视频理解模型（离线，但性价比低）

`Qwen2.5-VL-7B` / `MiniCPM-V` 走 hf-mirror 下载（5–15 GB），4050 6 GB 显存需 int4 量化，推理慢、精度也不如"抽帧 + 我自己读"。
**结论**：除非要求全程离线且不许我看图，否则没必要。

## 4. 我要"学"什么（这才是目标，不是抽帧本身）

| 层 | 从视频里提取什么 | 怎么取 | 落到哪 |
|---|---|---|---|
| **画面层** | 版式（板书/讲师/字幕各占多少）、配色、字号、表格与流程图的画法、道具与高亮习惯 | 每 30–45 秒抽 1 帧 + 场景切点 | 库内《教学画面渲染规范》修订 + 我的场景组件参数 |
| **语言层** | 单句长度、一个要点讲多久、提问频率与停顿、口头禅、举例密度 | ASR 全文 + 时间戳统计（可算百分比分布） | 微课 7 段式的**时长占比**从"拍脑袋"改成"实测" |
| **动作层** | 手势类型（指板/数数/强调/摊手）、身体幅度、表情变化频率 | 每 2–3 秒抽 1 帧，连成小序列 | `gesture/expression` **触发词库**（R2 的验收依据） |
| **结构层** | 引入/概念/例题/易错/小结 的真实时间分配 | ASR 段落 + 帧变化密度 | 讲稿模板的段长上限与检查点位置 |

**样本策略**（不做全量，先 3 集）：
`白宁·2022 p02`（板书派）+ `桐哥·2027 p06`（PPT+红笔派）+ `刘文超·p05`（公式/计算派）——三位老师、三种画面形态。
每集 120 帧（约 19 张 contact sheet）+ 1 集全量 ASR，产出《讲解风格量化报告 v1》。

## 8. 首轮实测观察（`TG2027-p06` 12 帧，样本有限，先给出可用结论）

> 素材：`contactsheet_TG2027-p06_3x4.png`（12 帧，覆盖 90 分钟）+ 两帧全分辨率（`frame_…000200.png`、`frame_…003800.png`）。全部在 `docs/plans/assets/AI讲师_视频风格/`。

| # | 观察到的事实 | 对设计的直接含义 |
|---|---|---|
| 1 | **一页一主题、标题恒定**：每帧顶部都是「调查取证——传唤」，蓝色警徽角标 + 右上角讲师水印/印章，版式 16:9 全屏、无讲师出镜 | 与库内《渲染规范》一致：**标题栏固定 + 页脚一致**；不需要"讲师占位大图"，讲师应是**小尺寸角标/旁白角色**（重要修正） |
| 2 | **红笔手写标注是主要教学手段**：圈关键词、下划线划重点、侧边竖排写结论（"暂扣""继续盘问"）、箭头连线 | `gesture` 动作库里必须有一类 **`annotate`（圈/划/箭头）**，且是"逐步出现"而非整页一次显示；对应 DSL 的 `board[].reveal: step` |
| 3 | **底部有"人话字幕"**：白字黑边大字，内容是口语强调句（"你结果传唤人家啊""我凭我去派出所的人""你觉得查封人家游戏厅"） | 这正是"卡通 + 正式并存"的现实版本：**书面 PPT + 口语字幕**。DSL 需要两个独立文本通道：`board.text`（书面）与 `speech.subtitle`（口语） |
| 4 | **真实文书样例 + 现场填注**：把空白《传唤证》放上屏幕，用红笔写"2027年1月10日10时5分到…15时45分"、圈出签名处 | 新增场景类型 **`document`（文书/表格实物）**，并支持"手写笔迹逐字出现"的动效——这是本学科最有效的讲法，我的 `scene.kind` 里缺这一类 |
| 5 | **表格与对比表是主力画面**：口头 vs 书面、治安传唤 vs 刑事传唤、易混情形对照 | 印证 `scene.kind` 必须有 `compare`；且表格要有"逐行高亮"能力（他不是整表一次给，是逐行讲） |
| 6 | **粒度比想象细**：90 分钟覆盖约 10 个页面 → 平均 **4–5 分钟/页**，远短于我方案里的"一节 6–10 分钟" | 微课单节应 **3–5 分钟**，7 段式各段时长要按此重算；检查点频率应提高到"每 2–3 页一次" |

> **注意**：以上只是 1 位老师、1 集、12 帧的观察。三集样本（白宁/桐哥/刘文超）跑完后才写正式《讲解风格量化报告 v1》，届时会给出：语速（字/分）、段长分布、标注密度（处/分钟）、场景切换频率、字幕长度分布。

## 9. 三件套（ffmpeg / OCR / ASR）到底能解决什么、解决不了什么

> 结论先说：**三件套解决「感知层」——看得见、听得见、存得下、搜得到；解决不了「内容层 / 代码层 / 数据层 / 合规层」。**
> 对 `AI讲师_限制与缺口清单_v2.md` 的 28 项（8 环境 + 20 资产）做逐条映射：**完全解决 7 项、部分解决 5 项、无关 16 项**（另有 2 条不可逆项 X-01/X-02，与组件无关）。

### 9.1 各自的能力与硬边界

| 组件 | 它能给你什么 | 它给不了什么（硬边界） | 已知风险 |
|---|---|---|---|
| **ffmpeg** | 抽帧、场景切分、按时间码切片、拼图、抽音频、静音/响度分析（语速与停顿）、**合并 `.part` 分片**、后期录屏导 MP4 | ①不理解画面内容（它只给像素）②不区分"有效板书帧"与"翻页空帧"③不能替代我读图 | 90 min 视频整片解码慢（实测：整片 `fps` 滤镜跑了 2 分钟没完）；**逐点 `-ss` keyframe 抽取才是对的**（12 帧几十秒） |
| **OCR** | 把**印刷体**板书/表格批量转成可检索文本，产出"每页文字 + 时间码"的结构化 JSON，便于全库搜索与对齐 | ①**红笔手写标注基本识别不了**（细笔画 + 压在印刷体上）②表格结构/合并单元格还原差 ③图示、箭头、圈选的**语义**完全没有 ④4 个纯音频集无画面可用 | 版式复杂时行序错乱，需要人工/我读图校对 |
| **ASR** | 带时间戳的逐句台词、语速（字/分）、停顿分布、"一个问题讲多久"的量化；可做切片台账的语义锚点 | ①**法条名与条号易错**（"第九十六条"→"九十六条"、法名简称不一）②同音专业词错（传唤/拘传、盘问/盘查）③无标点/断句需后处理 ④**给不了语气、重音、指代（"这里""这个"指什么）** | 需**领域热词表**（法名+条号+术语）+ 与法条库交叉校验，否则错字会污染讲稿 |

### 9.2 对缺口清单的覆盖率（v2 的 28 项）

| 覆盖度 | 项 | 说明 |
|---|---|---|
| ✅ **完全解决（7）** | L-01 ffmpeg 未装｜L-02 无 ASR｜A-04 讲义初稿（"转写稿 → 讲义骨架"）｜A-06 切片台账｜A-07 转写｜A-08 视频↔考点映射（有台词就能推主题）｜A-09 合并缺失集 | 都是"把素材变成文本/图片/时间码"的活 |
| 🟡 **部分解决（5）** | A-01 知识点卡｜A-02 考点卡｜A-03 法条卡｜A-05 错因卡｜A-14 题库（487 个 PDF 里**图片型页**可 OCR 取字，文本型页本来就能取） | 三件套是**原料机**，不是**作者**：能供料，不能成文 |
| ❌ **无关（16）** | L-03~L-08（网络与 Python 环境，已有替代路径）｜A-10 zip/part 清理（要的是记账+删除决策）｜A-11/A-12 图谱与考点入库（后端契约）｜A-13 名称别名表（人工确认）｜A-15 topic 层（设计）｜A-16 形象/音色（SVG 参数 / TTS）｜A-17 专利交底书（写作）｜A-18 播放器（前端代码）｜A-19 三端/埋点/金币｜A-20 版权口径成文 | 这些是**内容生产、代码、数据、合规**问题，装什么组件都不解决 |
| （另计 2 条不可逆） | X-01 生产题库不在本机｜X-02 课程版权 | 见 v2 清单 §4，与组件无关 |

### 9.3 还缺的"第 4、5 个组件"（你没列但很关键）

| # | 缺什么 | 为什么必须 | 补法 |
|---|---|---|---|
| C1 | **领域热词表 + 后处理** | ASR 的错字若直接进讲稿，会把"拘传"讲成"传唤"——这是**法律错误**，比没转写更糟 | 从法条库/题库术语抽 300–500 个词，写 `hotwords.txt`；转写完按"法名+条号"正则复核 |
| C2 | **强制对齐（word-level timestamps）** | 我要把"这句话"对到"这一帧板书"，只有句级时间戳不够 | `faster-whisper` 自带词级时间戳即可，先不引入 whisperX |
| C3 | **我的读图预算（真正的瓶颈）** | 90 min 一集约 5400 帧，我不可能全看；全看也不经济 | 压缩策略：场景切分去重 → 每 30–45 s 一帧 → 24 帧/张拼图；**动作层**只取 2–3 段 30 秒高密度序列（10 fps）做样本 |
| C4 | （后期）TTS 配音 | P2 才需要 | edge-tts（端点 400 可达）或 piper 离线 |

### 9.4 30 分钟最小验证（批了 E1/E2/E3 就跑，出 3 个数字）

| 验证 | 方法 | 达标线 |
|---|---|---|
| 帧可读性 | 已做（12 帧拼图）→ 再抽 1280 宽单帧 | 标题/表格文字我能读全（已达成） |
| OCR 产率 | 对 10 页印刷体板书跑 OCR，对比我读图结果 | 印刷体字符准确率 ≥95%；手写标注识别率接受 <40%（本来就用我读图） |
| ASR 质量 | 对 `TG2027-p06` 前 5 分钟转写，抽 20 句人工核对 | 通用字 CER ≤10%；**法律术语+条号**经热词表后 CER ≤5% |
| 结论 | 三项达标 → 三件套确认可用；不达标 → 调模型（medium→large-v3）/加热词/改用云 ASR | — |

### 9.5 一句话总结

**三件套能让 AI 讲师"看得见老师怎么讲"，但不能替它"决定讲什么、写得对不对、上不上得了线"。**
真正决定 P1 成败的仍是那三件事：**知识点/考点内容生产、讲稿 DSL 与播放器代码、以及题库与版权的数据前提**——三件套只是让这三件事的**素材成本**从"不可能"降到"可接受"。

## 10. 环境落地记录（E1/E2/E3 已批准执行，2026-11-05）

### 10.1 踩坑与结论：为什么"装三个组件"会卡 20 分钟

| 现象 | 根因（实测） | 处置 |
|---|---|---|
| `winget install Gyan.FFmpeg` 卡住/失败 | winget 的安装包**从 github releases 下载**（日志里明写 `github.com/GyanD/codexffmpeg/releases/...`），而本机 `github.com` 实测 **000 不可达** | 弃用 winget，改 **pypi `imageio-ffmpeg`**（wheel 内含 ffmpeg 9.0.2 二进制） |
| `uv pip install` 20+ 分钟下不完约 100 MB | **uv 不读 pip 的镜像配置**（`uv pip config list` 为空、`UV_DEFAULT_INDEX` 未设）→ 全部走 `pypi.org` / `files.pythonhosted.org`，本机到该 CDN 吞吐极低 | 加 `--default-index https://pypi.tuna.tsinghua.edu.cn/simple` → **faster-whisper 37.9 s、rapidocr+imageio-ffmpeg 15.1 s，合计 53 s** |
| 以为"只有三个组件" | 实际是**三棵依赖树**：faster-whisper 带 `ctranslate2` 19.5 MB + `av` 26.3 MB + `onnxruntime` 14.2 MB + `numpy` 12 MB；rapidocr 带 `opencv` 50 MB + `shapely` + `pyclipper`；imageio-ffmpeg wheel 37 MB（解出 100 MB 二进制） | 分阶段安装 + 每阶段看日志，不再串成一个大后台作业 |
| 还有个"隐形大件" | **模型**：faster-whisper `medium` 约 1.5 GB，首跑时从 `hf-mirror.com` 下（hf 主站 000） | 先下 `medium` 做准确性基准；批量阶段再评估 `small`/`distil` |
