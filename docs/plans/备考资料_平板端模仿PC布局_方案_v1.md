## 1. 现状 vs 目标

| 维度 | 现在（平板） | 目标（模仿 PC） |
|---|---|---|
| 版式 | 手机版**单卡栈** + 「上一页 / 翻转看要点 / 下一张」三按钮 | PC 版**卡片网格**：一行多张，点击卡片原地 3D 翻转 |
| 顶部 | 只有返回 / 标题 / ＋创建 | PC 的 `.hero`：科目大标题 + 一句描述 + 学习进度条 |
| 一屏信息量 | 1 张卡 | 768 宽 **3 列 × 2 行 ≈ 6 张**；1024 宽 **4 列 × 2 行 ≈ 8 张** |
| 翻页 | 上一页/下一页（PC 没有） | 网格滚动（PC 行为） |
| 卡片比例 | 600×307（1.95，横条） | 按平板等比：**约 220×180（1.22）**，接近 PC 的 150×170 竖卡 |

PC 实测依据：`.vtj/vue/materials_shenlun.vue`
- 结构：`.top-bar`（返回首页 / 只看收藏）→ `.hero`（标题+描述+进度）→ 分区块（视频横滑 / 文章列表 / **知识卡片网格**）
- 网格：`grid-template-columns: repeat(auto-fill, minmax(150px,1fr)); gap:14px`
- 卡片：`.flip{perspective:900px;height:170px}`，`.flip.flipped .inner{rotateY(180deg)}`，**点击原地翻转、无翻页按钮**
- 数据：`/api/materials?subject=&type=&page_size=50`、`/api/materials/progress-summary?subject=`

## 2. 三种可选做法（我推荐 A）

### A. 同一页按断点两套布局（推荐）
`src/views/student/mobile/mobile_materials.vue` 内加 `isTabletLayout`（`matchMedia('(min-width:700px)')`）：
- `v-if="isTabletLayout"` 渲染 **PC 式**：hero + 科目胶囊 + `card-grid`（点击翻转、卡内「查看配图」）
- `v-else` 保留现有手机卡片栈（**手机零改动**，20/20 断言不动）
- 单文件、单数据源，符合 R12「同页按 platform 适配」，无需新路由

### B. 平板专属页 `src/views/student/tablet/tablet_materials.vue`
新增页面 + `/tablet/materials` 改指向它。好处是互不干扰；代价是逻辑复制（fetch/过滤/翻转/进度），R12 不鼓励。

### C. 平板直接走 PC 页 `/materials/shenlun`
最省事，但 PC 页是 VTJ 页（R3 不能改模板），768 下实测卡片 702×**1340**、一屏只看到标题，且没有「＋创建 / 返回」等手写能力 → 不建议。

## 4. 验收标准（平板 768×1024 与 1024×768 各跑一遍）

1. 768 宽：网格 **3 列**，卡片宽 210–240、高 180（比例≈1.2）；1024 宽：**4 列**
2. 无「上一页/下一页」按钮；点击任意卡片原地翻转，再点翻回
3. 卡内「查看配图（N）」仍可直接开全图（含双指缩放/滑动）
4. 横向溢出 0px；卡片数 = 该科目卡片总数（滚动可见）
5. 手机 390：**仍是卡片栈 + 翻页**，20/20 断言不回退
6. `gate_all` 10/10、vitest 全绿、vue-tsc 0

## 5. 你的三条决定（已按此实施）

1. **布局 → A**：在 `mobile_materials.vue` 内按 `matchMedia('(min-width:700px)')` 切换，手机继续用卡片栈。
2. **保留「上一页/下一页」**：网格按「列数 × 2 行」分页（768 宽 6 张/页、1024 宽 8 张/页），按钮保留原名。
3. **要 hero 学习进度**：调用 `/api/materials/progress-summary?subject=`（PC 同款接口，未新增端点）。

## 6. 实施结果（2026-11-02，实测）

| 项 | 实测 |
|---|---|
| 768×1024 | `layout=grid`、**3 列**、6 张/页、卡片 **236×260（比例 0.91）**、`1 / 7 页 · 共 37 张` |
| 1024×768 | `layout=grid`、**4 列**、8 张/页、卡片 **237×215（比例 1.10）**、`1 / 5 页 · 共 37 张` |
| hero | 标题「行测 · 行政职业能力测验」+ 描述 + `学习进度 23.7%（已完成 9/38）` |
| 翻页 | 点「下一页」→ `1 / 7 页` → `2 / 7 页` |
| 翻转 | 点卡片 → `.g-card.flipped` 生效，终态 `matrix3d(-1,0,0,0,…)`（180°） |
| 查看配图 | 网格卡片右下「查看配图（N）」→ 全图，手势 9/9 通过 |
| 手机 390 | 仍是卡片栈 + 上一张/下一张，**20/20 断言不回退** |
| 横向溢出 | 768 与 1024 均 **0px** |
| 其他资料 | 平板上卡片已进网格，下方列表只留视频/文章（实测 1 条「行测科目说明」），不重复 |
| 门禁 | vitest **34 文件 471**、vue-tsc 0、gate_all **10/10** |

实现要点（`mobile_materials.vue`）：
- `isTabletLayout` / `isWideLayout` 用 `matchMedia('(min-width:700px)')` 与 `(min-width:1000px)` 驱动，列数与 `perPage` 严格一致（3×2 / 4×2），避免「CSS 4 列但一页 6 张」错位。
- 网格卡片复用 3D 翻转（`.g-inner{preserve-3d}` + `.g-face.back{rotateY(180deg) translateZ(1px)}`），点击整卡翻转、按钮 `@click.stop` 不触发翻转。
- 卡片高度 `clamp(210px, 28vh, 260px)`，竖屏得到 0.91 的竖卡比例，贴近 PC 的 150×170（0.88）。
- 科目切换 / 新建卡片后 `gridPage` 归零，避免停在越界页。

## 7. 已知不足

1. 平板上没有复刻 PC 的「视频横滑 / 文章列表 / 只看收藏」分区——只做了卡片网格 + hero；要全量复刻需补区块与接口。
2. 网格卡片正文（`card_front` 短）会有较多留白，靠标题垂直居中缓解；PC 端同样是短文本卡片，观感一致。
3. 遮挡窗口下 CSS 过渡不插值，翻转只能验「类名 + 终态矩阵」，截图为静态帧。
4. 触摸事件在窗口被遮挡时会挂住（本轮在脚本里加 `Page.bringToFront` + `Emulation.setFocusEmulationEnabled` 才稳定）。
