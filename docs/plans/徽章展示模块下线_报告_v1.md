## 1. 必须先说清楚的边界：删的是「展示层」，不是「成就/金币引擎」

实测发现「徽章」在本项目里横跨两套东西，删错会连带废掉成就系统：

| 组件 | 归属 | 本报告处置 | 依据（代码事实） |
|---|---|---|---|
| `/api/badges/*` 六个端点、徽章页、徽章墙、精选、徽章 SVG/档位卡片 | **徽章展示层** | **删除** | 只被 `badges.py` / `badges.vue` / 徽章组件引用 |
| `badge_task` 表 | 成就引擎 | **保留** | `achievement_judge.py:101,217` 用它算任务进度；`checkin_service.py` 复用它做每日奖励 |
| `badge_name_bank` 表 + `init_badge_names.py` | 成就命名 | **保留** | `growth/achievements.py:148-153` 管理员建成就时取未用名 |
| `badge_service.py`（`tier_of`/`total_score`/`progress_to_next`/`shape_of`） | 成就奖励档位 | **保留** | `achievement_reward.py:92-95` 发奖时算档位 |
| `badge_title` / `user_title` 表 + `Title`/`UserTitle` 模型 | 称号（金币商城商品） | **保留** | `deliverable_service.py:15,29` 购买称号后发放 `UserTitle` |
| `20261029_001_badge_tier_snapshot.sql`（给 `user_achievement` 加 `tier_snapshot`） | 成就引擎 | **保留** | 迁移内容与徽章页无关 |
| `user_badge_top` 表 + `UserBadgeTop` 模型 | 徽章展示层（主页精选） | **删除** | 仅 `badges.py` 与徽章页使用 |

> 一句话：**徽章页/徽章墙/精选没了，成就、金币、称号照常。**

## 6. 已知不足（如实记录）

1. **历史验收脚本仍引用徽章**：`tablet_audit_shots.mjs`、`tablet_landscape_preview.mjs`、`pc_on_tablet_preview.mjs`、`three_device_shots.mjs`、`auth_login_shots.mjs`、`mobile_create_and_pin.mjs` 里还有 `/badges` 或 `.badges-page` 断言。它们不属于 10 层门禁、也不在本次验收链里，**未逐条改**（跑起来会失败，属历史脚本）。
2. **`/badges` 现在没有路由**：实测访问 `#/badges` 会被路由守卫退回上一个页面（hash 不变），不会白屏；若希望显式 404 或重定向到首页，需要额外加一条 redirect，本次未加。
3. **历史文档仍描述徽章**：`docs/plans/`、`docs/superpowers/` 下多份文档写着徽章页/徽章墙/徽章精选，本次**未回头改历史记录**，以本报告为准。
4. **需求⑥「成就金币/徽章联动」现状**：成就解锁、金币发放、称号购买链路完好；徽章**展示**（我的徽章页/主页徽章墙/精选置顶）已下线。若后续要重做，按 §5 回滚或按本报告清单反向补齐。
5. **`user_badge_top` 已 DROP**：本地库不可逆（有 JSON 备份）；其他环境（另一台机器/服务器）如果还有这张表，需要在那边单独执行 `DROP TABLE user_badge_top`，否则会残留空表。
