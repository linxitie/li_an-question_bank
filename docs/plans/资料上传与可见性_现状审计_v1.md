# 资料上传机制与「学生可见性」现状审计 v1

> 你问：「管理员端资料上传机制是否已比较完善，是否上传后所有学生都可以看到了」。
> 一句话回答：**上传不等于学生可见**——默认落「未上架」，管理员点一次「上架（=审批）」后才**全员**可见；且「全员」是唯一的粒度，没有按班级/个人下发。
> 本文每条结论都有实测输出或代码位置，未验证的地方明确标注。

---

## 1. 实测：上传 → 学生能不能看到（真跑了一遍）

用一份 3 KB 讲义 PDF，管理员走新页的「批量导入资料」链路（`POST /api/materials/admin/files/upload`）：

| 步 | 动作 | 实测结果 |
|---|---|---|
| ① | 上传 | 200，`created=true`，`material_id=128`；库里 **`status=0`**、`type=lecture`、原件 `primary` 3,094 字节 |
| ② | 学生刷资料页 | `GET /api/materials?subject=gongzhuan&type=lecture` → **`total=0`**；直接开详情 → **404 资料不存在或已下架** |
| ③ | 管理员点「上架」 | `PUT /api/materials/admin/128/status {status:1}` → 200，`paper_sync: skipped=not_paper` |
| ④ | 学生再刷 | 列表 **`total=1` 且含该条**；详情 **200**；原件下载 **200 / 3,094 字节 / `%PDF-`** |
| ⑤ | 管理员点「下架」 | 学生详情立刻 **404**、列表不再返回 |

> 探针数据已清理（删行 + 删磁盘原件），跑前跑后「公专·讲义可见条数」都是 0。

**结论**：机制是「上传 → 待上架 → 上架（审批）→ 全员可见」。设计写死在代码注释里：`src/views/admin/materials.vue:477`「P0 裁定：上传默认未上架，**上架这一个动作就是审批**」，上传弹窗也明说「导入后为『未上架』，需再点上架」（`MaterialBatchUpload.vue:11`）。

## 4. 三个真问题（代码级证据）

**D1｜三个入口的默认值不一致（有安全隐患）**

| 入口 | 默认状态 | 依据 |
|---|---|---|
| 新页「批量导入资料 / 上传试卷」`POST /admin/files/upload` | **0 未上架** | `materials.py:2035` `status=0` |
| 老页智能导入 `POST /admin/import/{id}/confirm` | **0 未上架**（提示语「成功创建 N 条资料（下架态）」） | `materials.py:2815` `status=(1 if publish else 0)`，前端不传 `publish` |
| `POST /api/materials/admin`（创建文章/卡片） | **1 立刻上架**，且**传 `status:0` 被忽略** | `_validate_material_body` 白名单不含 `status`（`materials.py:966-968`）；实测两次创建都是 `status=1`，学生立刻可见 |

即：**上传文件是安全的（默认不公开），直接建资料却是"创建即公开"**。这是最容易出事的一处。

**D2｜`publish` 参数有后端没前端**
`import confirm` 支持 `publish=true` 直接上线（`materials.py:2724`），但老页 `admin_materials.vue:614` 的 body 只有 `subject/type/category`，新页上传组件也没有开关 → 这个能力事实上不可达。

**D3｜教师看不到待上架资料**
上架=审批，但审批前教师自己也没法在资料详情里预览（只有管理员能 `admin/{id}/preview`）。如果以后要「教师上传 → 管理员审批」，这条必须先放开（与 D9 教师预览试卷同口径：`role_level>=1` 放行未上架）。

## 5. 「所有学生」这件事的边界

- ✅ 只要 `status=1`：**全体学生 + 游客（详情端点允许匿名）+ 三端**都能看到，无任何额外限制；
- ❌ 没有「只发给某班/某人」「先给 VIP」这类中间粒度 —— 仓里没有 `material_target` 表（方案 v2 §7 明确推迟），要做得新增表 + 列表/详情/下载三处过滤 + 管理端选择器，估 **1.5–2 天**。

## 6. 需要你拍板（三选一或组合）

| 选项 | 内容 | 工作量 | 风险 |
|---|---|---|---|
| **A 保持现状** | 上传→人工上架。这就是 P0 裁定 | 0 | 无；但管理员容易漏点上架，学生"看不到"会被当成 bug |
| **B 加上传即上架开关** | 上传弹窗加「上传后立即上架」勾选（默认关），`files/upload` 支持 `status`；顺手修 D1（创建接口默认 0） | 0.3–0.5 天 | 误勾会把半成品直接公开；需默认关 + 二次确认 |

## 8. 追加三问（2026-11-08 下午补测）

### 8.1 上架后"所有学生"都能看到吗？讲义/文章在哪看？

**接口层：能，且范围比"学生"更宽。** 学生资料列表 `GET /api/materials` 的过滤条件只有 `subject + status==1`（`materials.py:138-139`），用 `get_optional_user` **不做登录校验也不按用户过滤**；详情 `GET /api/materials/{id}` 同样只要 `status==1`（`materials.py:750-751`），**匿名游客也能打开**。所以：上架 = 全体学生 + 游客 + 三端同时可见。

**页面层：只有 4 类资料有展示位，讲义和试卷没有。** 三个科目页的分区写死为（`materials_gongzhuan.vue:151-158`，xingce/shenlun 同）：

```js
[ { key:'video_intro',    title:'入门讲解视频' },
  { key:'video_advanced', title:'深度拓展视频' },
  { key:'article',        title:'备考指南'   },
  { key:'card',           title:'知识卡片'   } ]
```

| 类型 | 学生端入口 | 实测 |
|---|---|---|
| 文章 article | ✅ PC「备考资料 → 备考指南」区，点开弹窗渲染 `content`（`v-html`）；平板 `/tablet/materials` **重定向到同一页** | 公专已上架文章 1 条（`type=article` total=1），可正常读 |
| 卡片 card | ✅「知识卡片」3D 翻转 | 36 条可见 |
| 视频 | ✅ 两个视频区，弹窗 `<video>` 播放 | — |
| **讲义 lecture** | ❌ **PC/平板无分区**；手机 `/mobile/materials` 不传 type，**会把讲义混进列表**，但详情只渲染 `content`/`card_back`，而讲义上传后 `content` 为空（实测 0 字）→ **点开是空白页** | 上架 2 条讲义后：手机口径 total 含 2 条；详情 `content 长度=0` |
| **试卷资料 paper** | ❌ 同上，资料页无分区。学生"考卷"走「考试」页 `/student/papers`（那是 `exam_paper`，不是资料） | `type=paper` total=3，但学生端资料页从不请求它 |

**外加一条：学生详情接口不返回 `files` 字段**（`material_detail` 只补 `content/card_back/video_url`，`materials.py:780-783`），前端也没有任何一处调用 `/api/materials/files/{id}/download`（原件下载只存在于**管理端预览抽屉** `MaterialPreviewDrawer`）→ **即使上架，学生也拿不到讲义/试卷的原件文件**。

### 8.2 所有资料都能批量上传吗？

| 资料类型 | 批量上传 | 入口/实现 | 实测/依据 |
|---|---|---|---|
| 讲义 lecture | ✅ | 管理端「批量导入资料」→ `MaterialBatchUpload.vue` 多选队列 | 单批 ≤50 文件、合计 ≤2GB（`utils/batchUploadPlan.ts:14,16`），逐文件调 `POST /admin/files/upload` |
| 试卷 paper | ✅ | 管理端「上传试卷」按钮（同组件，preset=paper） | 同上；同名 docx+pdf 自动合成一条（docx 主 + pdf 附件） |
| 文章 article | ⚠️ API 支持（`type=article`），**UI 没有"上传文章"按钮** | — | 组件按 preset 只开了 paper / lecture 两种 |
| 卡片 card | ✅（另一条链路） | 老页「智能导入」xlsx 词库 → 列映射（正面列/背面列/分类列）批量建卡；`POST /api/materials/admin/batch`（JSON 数组）也可批量建 | `admin_materials.vue:226-239`、`materials.vue:668` |
| 卡片配图 | ✅ | `POST /admin/cards/batch-image`（≤9 张） | — |
| 视频 | ❌ 不走文件上传 | 视频走 `video_resource`/`video_id`，资料表只存引用 | `video_url="/api/video/{id}/stream"` |

**结论**：文件类（讲义/试卷）有批量；卡片有 xlsx 批量与 JSON 批量；文章只有单条/API；视频无批量（不需要）。

### 8.3 去重 / 同名不同内容 / 格式不符，每个入口都有吗？

| 入口 | 同内容去重 | 同名不同内容 | 格式/大小拦截 |
|---|---|---|---|
| `POST /admin/files/upload`（批量/单文件上传） | ✅ `sha256` 命中 → `duplicate=true`、复用原资料不建新行（实测：同文件再传返回 id=128，与首次相同） | ⚠️ **不会覆盖，但会新建第二条**（实测：同名不同字节 → id=129；列表出现两条同名资料，无任何提示） | ✅ 扩展名白名单 docx/doc/xlsx/xls/pdf（`.txt` → 400「仅支持…原件」）；✅ magic 校验（假 docx → 400「文件实际格式与扩展名不符」）；✅ 单文件 20MB、单批 50 个/2GB |
| `POST /admin/import/upload` + `/confirm`（智能导入解析） | ✅ 同文件（名+大小+sha256）→ 409 带旧记录号；确认时 `content_hash` 命中 → 409，`force=true` 才放行（B3） | 同上，靠"同内容"而非"同名"判断 | ✅ 仅 docx/xlsx/pdf（≤20MB） |
| `POST /api/materials/admin`（建文章/卡片） | ❌ **无去重**（实测：同标题+同正文连建两次 → 两条独立行） | ❌ 同上 | 仅卡片文本规则（正面≤120 字、背面≤600 字、禁 script/iframe 等）+ HTML bleach 消毒 |
| `POST /api/materials/admin/batch`（批量建） | ❌ **无去重**（实测：同批两条完全相同 → `created: 2`） | ❌ 同上 | 逐条走 `_validate_material_body` |

**结论**：**文件通道有完整的三道防线**（同内容去重 / 格式+magic+大小拦截 / 同名不覆盖）；**"传同名不同内容"目前只是"不覆盖"，没有合并/提示**；**JSON 创建通道（建文章、批量建）完全没有去重**。
