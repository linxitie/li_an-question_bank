## §0 需求

在**每个端口的发帖弹窗**里增加选项「是否允许 AI 自动总结标题」：

- **不允许**：按原格式发布（标题空就落 `(无标题)`），不调用模型；
- **允许**：自动生成标题；
- 生成结果不满意 → 可点「重新生成」；
- 仍不满意 → 用户自己手填。

现状（v3 已实现的部分）：标题为空且有正文时，**发布后由后台任务**自动补标题，
用户看不到、也不能拒绝——这正是本次要解决的「强制 AI」问题。

## §2 交互设计（推荐方案）

弹窗内在「可见范围」上方新增一行：

```
AI 自动总结标题            [开关]  ⓘ 关闭后按原样发布，不调用大模型
标题：[________________________]  [AI 生成标题]
```

- 开关**默认开**（见 D2 可改）。
- 开关打开且标题为空 → 显示「AI 生成标题」按钮；
- 点击 → 调 `POST /api/forum/ai-title/suggest` → 建议标题**填入标题输入框**（可继续编辑）；
- 已有建议后按钮文案变「重新生成」，旁边显示「已生成 · 可修改或重新生成」；
- **用户手动编辑过**标题后，按钮仍可点（重新生成会覆盖，需二次确认见 D6）；
- 开关关闭 → 隐藏生成按钮，发布时**不携带** AI 意图，后端跳过生成。

手机端发帖页沿用同一套控件（竖排），行为一致。

## §3 后端改动

### 3.1 新增「建议标题」接口（供「生成/重新生成」用）

```
POST /api/forum/ai-title/suggest     （需登录）
body: { content: str, content_format?: "TEXT"|"HTML" }
resp: { title: str } | { title: null, reason: "no_content"|"llm_unavailable" }
```

- 复用 `generate_forum_title()`，不新增模型调用逻辑；
- 正文先走 `strip_html` + 有效文字量门槛（≥8），不足直接 `reason=no_content`；
- **限流**：每用户每小时 30 次（内存计数，重启清零）；超限返回 429 + 提示；
- 不落库、不写审计（属预览行为）。

### 3.2 发布接口增加两个表单字段

```
ai_title_enabled: bool = Form(True)   # 默认 True，向后兼容老客户端
title_from_ai:    bool = Form(False)  # 标题是否直接来自模型建议（未手动改写）
```

- `ai_title_enabled=False` → **跳过**后台生成任务（即使标题为空）；
- `title_from_ai=True` 且标题非空 → 落库时 `ai_title=1`（帖子标题前显示「AI生成」）；
- 二者都保留旧行为：不传 `ai_title_enabled` 时与现在完全一致。

### 3.3 是否记录用户选择（D5）

- 若不记录：零 schema 变更，最省事；
- 若记录：`forum_post.ai_title_enabled TINYINT DEFAULT 1`，便于管理员看板统计
  「有多少人关掉了 AI」。代价是一次迁移。

## §6 风险与回滚

| 风险 | 对策 |
|---|---|
| 被刷接口烧 token | 每用户每小时 30 次 + 有效文字量门槛 + 登录必需 |
| 用户误以为「不关就会改我的标题」 | 默认展示说明文案「仅在你没填标题时生效」；开关标签明确 |
| 老客户端不带新字段 | 后端默认 `True + False`，行为与现在一致 |
| 手机端与 PC 行为不一致 | 同一服务与同一文案，三端共用一套交互规则 |

## §8 实施记录（2026-11-04）

### 落地情况

| 项 | 实际做法 |
|---|---|
| 弹窗交互 | `PostComposer` 标题行右侧「AI 生成标题 / 重新生成」+ 下方开关行；覆盖前 `window.confirm`；单窗 5 次上限 |
| 手机端 | `mobile_forum_create.vue` 同款开关与按钮（竖排） |
| suggest 接口 | `POST /api/forum/ai-title/suggest`，需登录、进程内每用户每小时 30 次、正文不足 8 个有效字直接 `no_content` |
| 发布字段 | `ai_title_enabled` / `title_from_ai`；`forum_post.ai_title_enabled` 记录选择；标题原样来自模型才标 `ai_title=1` |
| 草稿 | `forum_draft.ai_title_enabled` + `DraftPayload.ai_title_enabled`，重开弹窗恢复开关 |
| 三端透传 | 学生页 / 教师页 / 管理端均把两字段传给接口 |

### 调试中发现的一个真坑（值得留档）

**这版 FastAPI 对「缺省的 bool Form 字段」一律解析成 `False`**，连 `bool = Form(True)` 和
`Optional[bool] = Form(None)` 的默认值都不生效（用最小 app 隔离验证过）：
`{missing, explicit_true, explicit_false}` → `{False, True, False}`。

后果很严重：老客户端不传该字段 = 被当成「用户明确关闭 AI」。
所以改成 `str = Form("true")` + 显式字符串判定（`false/0/no/off` 才算关闭），
并在代码注释里写清原因，避免以后有人「顺手」改回 bool。
