### 2.1 页面策略：新建手写页，替换路由指向（**不改 `.vtj` 模板**）

现状 `/admin/materials` 指向 `.vtj/vue/admin_materials.vue`（低代码页，**R3 禁止改模板**）。本轮要加的东西太多（预览列、发布者列、6 种类型、试卷卡片、批量双格式、侧栏冻结），在 `.vtj` 模板上做不了。

**方案**：新建手写页 `src/views/admin/materials.vue`，把路由 `/admin/materials` 的 `component` 指向它。
- `.vtj/vue/admin_materials.vue` **不删不改**（R1 允许，仅不再被路由使用；设计器仍可打开）；
- 这是纯 `src/router` 改动，符合 R3；与平板路由 `redirect` 同一类做法。
- 回滚：把路由改回 `$vtj/vue/admin_materials.vue` 即可。

要点：
- **类型徽标**用颜色区分（卡片=紫、文章=蓝、讲义=青、试卷=橙、视频=灰）；

- **试卷/讲义**行额外显示：试卷 → `2024·国考·题本·25 题·100 分`；讲义 → `12 章 · 1.2 万字`。

### 2.3 上传时间列（功能规格，本方案正式收录）

#### 2.3.1 语义与口径（先分清两个时间）

| 时间 | 含义 | 来源 | 本方案如何用 |
|---|---|---|---|
| **上传时间** | 文件被拖进导入队列的那一刻 | `material_import_record.create_time`（每次上传一条记录） | 预览抽屉里显示「文件上传于 …」，作为**辅助信息** |
| **入库时间** | 解析/预览确认后，`study_material` 落库那一刻 | `study_material.create_time` | **列表「上传时间」列取这个**（用户口语里的"什么时候传的"实际看的是这里；且与排序/追溯一致） |

> 两个时间通常相差几秒（小文件）到几十分钟（扫描件 OCR）。文档里明确：**列表列名沿用你的用词「上传时间」，实现取入库时间 `create_time`**；如你要求"以文件进入系统的那一刻为准"，见 D37。

#### 2.3.2 列表列规格

| 项 | 规定 |
|---|---|
| 列位置 | 「发布者」右侧、「浏览」左侧（与发布者组成"谁+何时"追溯链） |
| 列宽 | 140px；等宽字体（`Cascadia Mono/Consolas`） |
| 显示格式 | `YYYY-MM-DD HH:mm`（例：`2026-11-06 08:41`），时区固定 **Asia/Shanghai**（后端存 UTC 时统一转） |
| 排序 | 表头可点击，三态：默认倒序（最新在上）→ 正序 → 取消；`order=created_desc|created_asc` |
| 精确到秒 | hover 显示 tooltip：`2026-11-06 08:41:37`（title 属性） |
| 空值 | `create_time IS NULL` 显示 `—`，排序时排最后 |
| 今日高亮 | 24 小时内的时间用主色（`#4054e0`）显示，便于看"刚传的" |
| 移动端/平板 | 列隐藏，改为卡片第二行的次要信息（避免横向溢出） |

#### 2.3.3 接口与字段（不改表）

- 列表接口 `GET /api/materials` 的每个 item **新增** `created_at`（ISO-8601 带时区，如 `2026-11-06T08:41:37+08:00`）；
- 排序参数：`order=created_desc`（默认）/ `created_asc`；
- 可选筛选：`created_within=7d|30d`（"最近 7/30 天"，D38 待定是否需要）；
- 预览接口 `GET /api/materials/admin/{id}/preview` 同时返回 `created_at` 与 `uploaded_at`（后者来自关联的导入记录，取不到则为 null）；
- 数据库：**零迁移**（`study_material.create_time` 已存在且已有值）。

#### 2.3.4 权限与安全

- 上传时间对所有能看该资料的人可见（发布者、管理员、学生），**不属于敏感信息**；
- 不做"按上传时间反查上传人 IP/设备"的暴露（只在服务端审计日志里，前端不返回）。

#### 2.3.5 验收用例（3 条）

1. 列表每行都显示时间；`create_time` 为空的旧数据（若有）显示 `—` 且排在末尾；
2. 点表头两次能在倒序/正序间切换，刷新后保持当前排序（写进 URL query）；
3. 上传一个文件 → 确认入库 → 该行时间 = 入库时刻（与 `sqlite3` 里 `create_time` 一致，误差 <1 分钟）。

#### 2.3.6 与"发布者"列的联动

- 两列合起来支持"**按发布者 + 时间范围**"追踪：先按发布者筛（如 `ycc5678`），再点时间排序 → 教师最近上传一目了然；
- 后续可加"发布者维度统计"（某人本周上传 N 条），列为建议项，不进本轮。

### 3.2 双格式文件模型（新增 1 表）

现状：一条资料只有一个文件概念（`content` 存 HTML、`cover_image` 存图；PDF/Word 只在导入临时目录，**入库后原件没留**）。

新增 `material_file`：

| 列 | 说明 |
|---|---|
| `file_id` PK | — |
| `material_id` FK | 关联资料 |
| `format` | `pdf` / `docx` |
| `role` | `primary`（主文件）/ `alternate`（副本格式） |
| `url` | 落 `uploads/materials/files/<hash>.<ext>`（对象存储开启时走 `/media/{asset_id}`） |
| `size`、`pages`、`sha256` | 完整性/去重/页数 |
| `create_time` | — |

规则：
- **配对键 = 文件名主干**（去扩展名 + 去 `(1)`/`副本` 后缀）：`xxx.pdf` + `xxx.docx` → 同一 `material_id`；

- 重复上传：`sha256` 相同 → 跳过并提示；标题相同但内容不同 → 新建并提示"疑似重复"。

## 4. 分支设计（不合并、不碰 main）

> 依全局规则 5：**本轮所有分支都不合并 main、不推送远端 main**，只在本地分支上提交，等你批准后再谈合并。

```text
main（只读，不动）
 └─ feat/material-multi-format-import      ← 现有分支（T0/T0.2 已提交）
```

**不动 main**：本方案所有提交都在 `feat/material-admin-v2`；合并需要你另行批准（规则 5）。
