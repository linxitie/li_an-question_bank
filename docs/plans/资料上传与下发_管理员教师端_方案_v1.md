## 3. 设计

### 3.1 数据模型

**新表 `material_target`（下发对象）**

```sql
CREATE TABLE material_target (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  material_id INTEGER NOT NULL REFERENCES study_material(material_id),
  target_type VARCHAR(10) NOT NULL,          -- all | class | student
  class_id INTEGER,                          -- target_type=class，引用 banji.class_id
  class_name VARCHAR(100),                   -- 冗余快照（班级改名不影响历史）
  user_id BIGINT,                            -- target_type=student，引用 sys_user.user_id
  created_by BIGINT,
  create_time DATETIME DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_material_target_material ON material_target(material_id);
CREATE INDEX idx_material_target_user ON material_target(user_id);
CREATE INDEX idx_material_target_class ON material_target(class_id);
CREATE UNIQUE INDEX uq_material_target ON material_target(material_id, target_type, IFNULL(class_id,0), IFNULL(user_id,0));
```

**兼容规则（重要）**：`material_target` 里**没有任何记录 = 全员可见**（等价现状 107 行资料）；有记录则只按记录下发。
→ 这样不用给存量数据回填，也不用改 `study_material` 结构（迁移最小）。

**班级数据初始化（D11）**：三选一
- A 管理员在用户管理里逐人填 `class_name` + 建 `banji`（1 个教师 28 个学生，10 分钟可完成）
- B 用 Excel 名册导入（复用第 1 批的 Excel 通道，`user_no + class_name` 两列）
- C 先用 `department`/`nianji` 映射出班级（当前都为空，不可行）

### 3.2 可见性规则（唯一事实来源）

新增 `services/material_scope.py`，三处调用（列表 / 详情 / 进度）——**绝不分散写**：

```text
教师 / 管理员：不过滤（能看全部，便于管理）
游客：      仅"无 target 记录"的公开资料          ← D14
学生：      无 target 记录  OR  target.all  OR  target.class_name = 我的 class_name  OR  target.user_id = 我
            学生 class_name 为空时：只按"无 target 记录 + all"处理
```

> 实现照抄论坛 `_apply_visibility_filter` 的写法（`EXISTS` 子查询 + 中文班级名两种编码匹配），避免再造一套判据。

### 3.3 上传 → 下发流程（在 P0 链路上接一段，不改上传本身）

```text
选择文件（多选/拖拽） → 解析（页/段/行级进度） → 预览
                                                ↓
                              确认入库弹层：①科目/类型 ②下发对象 ③预览覆盖人数
                                                ↓
                       写 study_material + material_target（同一事务）
                                                ↓
                        学生端下次请求即按 §3.2 可见性过滤
```

- **批量共用**：一批 N 个文件默认共用同一组下发对象；允许"逐文件覆盖"（高级选项，P1 可不做，见 D13）
- **类型判定**：`xlsx → card`；`pdf/docx（讲义）→ article`；**试卷/真题 → `type='paper'`**（D12）

### 3.4 接口（新增 3 个 + 改造 1 个）

| 方法 | 路径 | 作用 | 权限 |
|---|---|---|---|
| GET | `/api/materials/admin/targets/classes` | 可下发的班级列表（管理员=全部；教师=`class_scope` 口径 + 人数） | staff |
| GET | `/api/materials/admin/targets/students?class_id=&keyword=&page=` | 学生检索（教师仅本班/本人管辖） | staff |
| POST | `/api/materials/admin/targets/preview` | 传 targets → 返回 `{class_count, student_count, names}`（下发前确认影响面） | staff |
| POST | `/api/materials/admin/import/{id}/confirm`（改造） | body 增 `targets: [{type, class_id?, user_id?}]`；批量确认走 `batch_id` | staff |

## 4. 分支结构

### 4.1 建议：两分支串行 + 两次合并

```text
main (1789022)
  └─ feat/material-multi-format-import   ← 现有分支（7 个 docs 提交，0 业务代码）
       P0：迁移(7列) + 队列 + 进度 + 批量 + 管理员/教师两页 + 路由 104→106
       → 合并回 main（先跑 gate_all / vitest / vue-tsc）

main（含 P0）
  └─ feat/material-distribution           ← 新分支（本方案）
       P1：material_target + material_scope + targets 三端点 + confirm 扩展 + Picker
       → 合并回 main
```

**为什么不在一个分支里做完**
1. **门禁数字只改一次**：P0 已把 104→106，P1 不再动路由计数，合并冲突面小；
2. **风险面不同**：P0 只影响"写"（上传/解析），P1 影响"读"（学生列表/详情可见性）——读路径回归要单独审；
3. **回滚粒度**：P1 出问题可单独 revert，P0 的导入能力保留。

### 4.2 若你希望"一次做完"

合并为 `feat/material-upload-distribution` 也可以，但**必须分两个 PR/两次提交批次**（P0 一批、P1 一批），否则 review 与回滚都不可控。

### 4.3 与 AI 讲师分支的冲突（提前声明）

AI 讲师恢复后会改 `src/router/index.ts` 与 L6/L7 数字（104→105）。约定：
- **本方案不改 AI 讲师相关的路由计数**（P1 无新页面）；
- 谁先合并谁先占数字，后合并的一方在自己分支里 rebase 后重跑门禁。

## 6. 写码前 11 问（全局规则 3）

| 问 | 答 |
|---|---|
| 为什么这样写？ | 复用 `class_scope` + 论坛 visibility 语义，新增的只有"个人"粒度的 `material_target`；不在 `study_material` 上堆 `class_ids` JSON（无法索引、无法统计、无法一对多查） |

| 运维？ | 下发关系是独立表，可 SQL 直查/导出；撤销下发=删记录；班级改名有 `class_name` 快照不受影响 |
| 放对文件？ | 新服务 `services/material_scope.py`（与 `class_scope.py` 同层，避免 api 域跨域引用 `Banji` 触发边界门禁）；迁移 `backend/migrations/20261105_007_material_target.sql` |
| 前端能显示？ | Picker 是手写组件，放进 P0 的两页里；学生端不改代码，仅接口过滤生效 |
| 后端字段？ | `material_target` 六列 + 唯一索引；`study_material` **不改** |

| 接口完整？ | 选班级 → 选学生 → 预览人数 → 确认入库 → 列表可见，闭环 |
| 门禁双改点？ | 本方案**不改**路由计数（仍 106）；R11 白名单 +3；边界门禁：`Banji` 只在 services 里引用 |
