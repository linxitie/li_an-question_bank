# B1 资料原件留档（material_file + 鉴权下载）交付记录 v1

- 日期：2026-11-07
- 分支：`feat/material-multi-format-import`（**未合并 main、未推送远端**）
- 对应方案：《资料管理 v3.1》§5 **B1**（用户裁定：存储 A / 权限 A / 内容寻址 A）
- 一句话：**导入的 docx/pdf 原件不再被删掉**——落盘留档、可按 sha256 对账、走鉴权接口下载，抽屉里能直接点。

---

## 1. 改前状态（问题）

- 导入流程解析完就把临时文件删了 → **库里只有正文，没有原件**；管理员想核对"当初传的是哪一版"只能靠记忆。
- 试卷原卷更是必须留档（C 批要把它挂到 `exam_paper`）。
- `/uploads` 是 `StaticFiles` **公开挂载**：把原件放进去 = 任何人拿到 URL 就能下试卷。

## 2. 三个口径（2026-11-07 用户裁定）

| 决策 | 选项 | 落地 |
|---|---|---|
| 存放位置 | **A. 不暴露在 `/uploads`，只能鉴权下载** | `settings.MATERIAL_FILES_DIR`，默认 `backend/storage/material_files/` |
| 下载权限 | **A. 管理员不限 + 学生只能下已上架** | `material_files.can_download(is_admin, status)`（纯函数） |
| 存储策略 | **A. 内容寻址，删资料不删物理文件** | 物理名 `sha256[:2]/sha256.ext`，同一内容只写一份 |

**为什么不用 `backend/data/`（初版选它，实测后改掉）**：`data/` 与 SQLite 同目录，本机仓库在 OneDrive 里，
每写一个新文件都会触发目录同步扫描，扫描期间库被锁 → 上传/导入接口偶发卡死 **30 秒**（`faulthandler` 抓到阻塞在
`_save_tmp → Path.write_bytes`）。换到独立 `storage/` 后同批用例 27 个 9 秒跑完。

### 4.4 排障记录（写清是为了下次不再踩）

现象：`test_materials_files_b1.py` 跑到第 4 个用例时整个 pytest 进程卡死 ~30 秒后直接退出，**没有 summary**，退出码 0。
定位：`-o faulthandler_timeout=8` 打出线程栈，全卡在 `materials.py::_save_tmp → pathlib.write_bytes`。
根因：仓库在 OneDrive 同步目录，写 `backend/uploads/materials/tmp/` 时被同步/杀软扫描阻塞（与用例内容无关，随机命中）。
修法：①`UPLOAD_*` 目录改为跟随 `settings.UPLOAD_DIR`（脚本化/测试可指到临时盘，也修了"写死路径与静态挂载同源"这个隐患）；
②`conftest.py` 在 import app 之前把两个目录指到 `%TEMP%`。修完 27 个用例 9.4 秒跑完。

## 7. 遗留

1. **xlsx 导入不留档**：一张表转 N 张卡，源表与单卡不是一对一；B2 批量导入会按"批次"留档。
2. **没有删除/清理脚本**：删除资料只删 DB 行，物理文件留着（按裁定 A 的取舍）；`orphan_count()` 已备好，清理脚本随 C 批回收站一起做。
3. **`uploaded_at` 仍是 `None`**：预览里的"上传时间"取的是资料入库时间；文件级时间要用 `material_file.create_time` 回填，涉及 A2 契约，随 B2 一起改。
4. **B2 复用**：批量上传直接调 `material_files.save_bytes()`；双格式配对用 `role=primary/attachment` 表达。
