## §2 数据模型（2 新表 + 1 新列，只增不删）

```sql
CREATE TABLE profile_background (
  bg_id        INTEGER PRIMARY KEY AUTOINCREMENT,
  owner_id     BIGINT REFERENCES sys_user(user_id),  -- NULL = 系统内置
  name         VARCHAR(50)  NOT NULL,
  kind         VARCHAR(16)  NOT NULL,                -- SEASON | USER
  theme        VARCHAR(16),                          -- spring/summer/autumn/winter
  image_url    VARCHAR(300) NOT NULL,                -- 系统主题存 CSS 值或图片路径
  thumb_url    VARCHAR(300),
  coin_price   INTEGER DEFAULT 0,                    -- 0 = 免费；用户创作 50–500
  status       VARCHAR(16) DEFAULT 'PENDING',        -- PENDING/APPROVED/REJECTED/OFF_SHELF
  audit_note   VARCHAR(200),
  use_count    INTEGER DEFAULT 0,
  create_time  DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE user_background (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id     BIGINT  NOT NULL REFERENCES sys_user(user_id),
  bg_id       INTEGER NOT NULL REFERENCES profile_background(bg_id),
  source      VARCHAR(16) NOT NULL,                  -- FREE | PURCHASE | SELF
  create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
  CONSTRAINT uk_user_bg UNIQUE (user_id, bg_id)
);

ALTER TABLE sys_user ADD COLUMN active_bg_id INTEGER;  -- 当前启用背景，NULL=默认
```

**迁移方式**：沿用 `main.py:207-300` 既有「探测列是否存在 → `ALTER TABLE`」幂等段，新增 1 个分支；两张新表交给 `Base.metadata.create_all()`（现有机制）。
**内置四季**：`kind='SEASON'`、`coin_price=0`、`owner_id=NULL`，由 seed 幂等写入（已存在则跳过）。

## §3 接口清单（8 个 + 1 个管理端）

| 方法 | 路径 | 说明 | 鉴权 |
|---|---|---|---|
| GET | `/api/profile/backgrounds` | 可选背景：系统四季 + **APPROVED** 的用户创作 + **本人全部（含 PENDING）**；支持 `?kind=` | 登录 |
| POST | `/api/profile/backgrounds` | 用户上传创作：png/jpg/webp ≤2MB，Pillow 重编码去元数据，落 `status=PENDING`；每人待审 ≤5 | 登录 |
| GET | `/api/profile/background` | 当前启用背景 + 我已拥有的列表 | 登录 |
| PUT | `/api/profile/background` | 启用/切换：必须「免费（SEASON）或已在 user_background」 | 登录 |
| POST | `/api/profile/backgrounds/{bg_id}/buy` | 金币购买：body 带 `request_id`；余额不足 400；重复 `request_id` 幂等 | 登录 |
| DELETE | `/api/profile/backgrounds/{bg_id}` | 作者下架自己的作品（已有他人拥有时转 `OFF_SHELF`） | 登录 |
| GET | `/api/admin/profile-backgrounds` | 管理员审核列表（按 status 过滤） | 管理员 |
| POST | `/api/admin/profile-backgrounds/{bg_id}/review` | 通过 / 驳回（写 `audit_note`） | 管理员 |

**扣费规则**：复用 `CoinExchange.request_id` 幂等 + `CoinRecord(transaction_type='SPEND', source_type='SHOP', related_id=bg_id)`；余额校验与扣减在**同一事务**内；购买成功写 `user_background(source='PURCHASE')`。
**不做**：分成/收益表、现金结算、AI 审核（P4-B）。

## §6 风险与回滚

| # | 风险 | 对策 |
|---|---|---|
| 1 | 迁移出错 | 先 `sqlite3.backup()`（R10，禁用 `copy2`）；只加表/列；回滚=恢复备份并删 `-wal`/`-shm` |
| 2 | 未审内容外泄 | 列表 SQL 层过滤：市场只 `APPROVED`，本人可见自己 `PENDING` |
| 3 | 金币刷取 | `request_id` 唯一 + 事务内余额校验 |
| 4 | 存储膨胀 | ≤2MB + Pillow 重编码 + 每人待审 ≤5 + 驳回即删文件 |
| 5 | 背景盖住文字 | 内容层强制遮罩 + 对比度下限；验收断言计算样式 |
| 6 | raw 页误改 | R3：template 不动；`vtj_check_consistency` 只校验版本 |
