# 三端论坛评论输入区统一：手机端吸底 + 单行控件 — 设计方案 v1.3

> 状态：**已批准并实施（2026-10-26，提交 12eb14e）**：三端统一单行吸底。PC 由 sticky 改为与弹窗底边对齐的 fixed（sticky 打开时不在视口内）。
> 日期：2026-10-26
> 分支：`feature/forum-personalization`（HEAD 见 `git log -1`）
> 涉及文件：`src/views/student/mobile/mobile_forum_detail.vue`（手写 SFC）、`src/views/student/tablet/tablet_forum_detail.vue`（手写 SFC）
> **不涉及** `.vtj/` 页面，因此不触发 R2/R3

---

## 0. 结论先行（含一条与预期不符的实测）

1. **手机端确实没固定**：`.comment-bar` 是 `position: relative`，实测 `top = 4110`，页面总高 `4256` —— 要向下滚约 4000px 才能看到输入框。**需要修**。
2. **平板端其实已经是固定的**：实测 `.composer` 为 `position: fixed`，`top 664 / bottom 820`，视口 820 —— 打开就在视口内。你看到"没固定"，最可能是当时平板走的是 PC 页面（设备判定 = pc，评论输入区在弹窗底部），或页面还是旧 bundle。**平板端不用改吸底**。
3. 平板端真正缺的是**同一排**：上传按钮独占一行（`top 679`），表情/输入/发送在下一行（`top 765`）。
4. 三端统一目标：`[😊] [＋] [输入框] [发送]` 一行。PC 已达成（v1.2），手机与平板按本方案补齐。

## 2. 目标

1. 手机端评论输入区**固定在屏幕底部**，滚动任意位置都能直接输入。
2. 手机端与平板端都变成**一行**：😊 → ＋ → 输入框 → 发送。
3. 上传按钮统一为 **36×36 圆形「＋」**（PC 已如此）。
4. 表情面板浮在输入区上方，不挤压布局。
5. PC 端保持现状不变。
6. 不改后端、不改 VTJ 页面、不做 DSL 同步。

## 3. 方案

### 3.1 手机端：固定底栏 + 单行

`mobile_forum_detail.vue` 是手写 SFC（非 `.vtj`），template 与 `<style>` 都可改。但**优先只用 CSS**（用 flex `order` 重排），减少回归面。

```css
/* :746 */
.comment-bar {
  position: fixed;
  left: 0;
  right: 0;
  bottom: 0;
  z-index: 30;
  display: flex;
  flex-wrap: wrap;
  align-items: center;
  gap: 8px;
  padding: 10px 12px calc(10px + env(safe-area-inset-bottom));
  background: #fff;
  border-top: 1px solid #e8ecf1;
}
/* 固定后会让出屏幕高度，正文底部补间距，否则最后一条评论被压住 */
.page { padding-bottom: 84px; }

/* 单行顺序：😊 → ＋ → 输入框 → 发送 */
.comment-bar .emoji-btn { order: 1; }
.comment-image-bar { order: 2; width: auto; flex: 0 0 auto; }
.comment-input { order: 3; flex: 1; min-width: 0; }
.comment-bar .send-btn { order: 4; }

.comment-bar .comment-picker {
  position: absolute;
  left: 12px;
  bottom: calc(100% + 8px);
  order: 0;
}

/* 上传缩成圆形＋（FileUploader 内部元素，需 :deep 穿透） */
.comment-bar :deep(.fu-add) {
  width: 36px; height: 36px; padding: 0;
  border-radius: 50%; font-size: 0; position: relative;
}
.comment-bar :deep(.fu-add::before) {
  content: '+'; font-size: 20px; line-height: 1; color: #1a2b5f;
}
.comment-bar :deep(.fu-add span) {
  position: absolute; width: 1px; height: 1px; overflow: hidden;
  clip: rect(0 0 0 0); white-space: nowrap;
}
.comment-bar :deep(.fu-thumb) { width: 36px; height: 36px; }
```

### 3.2 平板端：只做单行

`tablet_forum_detail.vue` 的 `.composer` 已是 `fixed`，只调整内部：

```css
.composer .emoji-btn { order: 1; }
.composer-uploader { order: 2; width: auto; flex: 0 0 auto; }
.composer .comment-input { order: 3; }
.composer .send-btn { order: 4; }
.composer :deep(.fu-add) { /* 同手机端 36px 圆形＋ */ }
.composer :deep(.fu-thumb) { width: 36px; height: 36px; }
/* 单行后整体变矮，内容区底部留白可相应减少 */
.content { padding-bottom: 120px; }
```

### 3.3 PC 端

不动。

## 4. 为什么这样写

| 考量 | 说明 |
|---|---|
| 为什么用 `order` 而不是改 DOM | 手机端虽是手写页可改 template，但改了 `v-model` 绑定的兄弟顺序容易踩坑；`order` 只改视觉，事件与无障碍树顺序不变 |
| `position: fixed` 的副作用 | 元素脱离文档流 → 正文最后一条会被遮。所以必须给 `.page` 补 `padding-bottom`，值 = 输入区高度（实测 146px，单行化后约 84px） |
| iOS 安全区 | `calc(10px + env(safe-area-inset-bottom))`，避免被 Home 指示条压住 |
| 键盘弹出 | Android Chrome 会缩放视口，fixed 元素随之上移；iOS Safari 亦如此。无需额外 JS |
| `:deep()` 依赖 | 与 PC 同一套：依赖 `FileUploader` 的 `.fu-add / .fu-thumb / .fu-doc` 类名。已在设计里注明，实施时在 `FileUploader.vue` 顶部加一行注释 |
| 读屏 | 「+」是伪元素，原文字用视觉隐藏保留，读屏仍念「+ 图片 / 文件」 |

## 7. 风险

| # | 风险 | 对策 |
|---|---|---|
| 1 | 手机端 fixed 后正文末条被遮 | `.page` 补 `padding-bottom`，由验收 #5 断言 |
| 2 | iOS 键盘弹起时输入区被顶出 | 用 `env(safe-area-inset-bottom)`；真机验证；必要时改 `position: sticky`（同一套断言可回归） |
| 3 | emoji 面板在小屏上超出顶部 | 面板高约 258px，输入区上方空间足够；若不够改为向下弹出（`top: 100%`） |
| 4 | `:deep()` 依赖子组件类名 | 在 `FileUploader.vue` 顶部注释声明该依赖 |
| 5 | 手机端 `order` 与未来新增控件冲突 | 注释写明 order 语义 |
