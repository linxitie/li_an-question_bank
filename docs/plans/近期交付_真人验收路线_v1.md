# 近期交付 · 真人用户视角的分阶段验收路线 v1

> 适用对象：2026-11-09 一轮连续交付（结果页文案 → 关系表归一 → `is_scored` 口径 → 三端验收清单 →
> 手机整卷考试 → 列表考试状态 → 批量一键上架 → 断点续答与倒计时 → PC 列表显示未开放）。
> 目的：**单测/门禁过了 ≠ 真人能用**。这份文档只回答一件事——**按什么顺序、在真人身上怎么验**。
> 分支 `feat/material-multi-format-import`，main 未动；下述步骤全部可回滚。

## 0. 先看：这批改动，真人会感知到什么

| 改动 | 谁能感知 | 感知形态 | 风险点 |
|---|---|---|---|
| 结果页加「分 / 题」后缀 | 学生 | 得分显示「0 / 97 **分**」、正确/错误「0 / 97 **题**」 | 视觉辨识，无逻辑 |
| 97 分卷不再显示「0 / 100」 | 学生 | 历年试卷卡片「得分 0 / **97**」 | 若别处还有硬编码 100，会不一致 |
| `is_scored` 口径 A + 3 派生字段 | 间接（学情/成绩） | 今天看不到差异；将来有主观题时"待人工评分"才体现 | 学情取数是否仍正确 |
| 手机整卷考试 | 学生（手机） | 以前点卷跳 PC 页，现在手机内开考 | 交卷、结果页口径 |
| 手机断点续答 + 倒计时 | 学生（手机） | 退出再进答案还在；顶部有倒计时；时间到自动交卷 | 计时器、自动存盘 |
| 手机/平板列表「可考 / 未开放」 | 学生 | 卡片右上角状态标 + 原因 | 不可考卷是否会被误点 |
| PC 列表显示「未开放」 | 学生（PC） | **以前看不到的卷现在看得到**，标琥珀「未开放」 | 会不会"看得到却点不动"的困惑 |
| 批量一键上架 | 管理员 | 批量建资料可一次上架，卷同步 PUBLISHED | 上架后学生真能考 |
| 交卷用时/满分修复 | 学生 | 用时 9 秒不再显示 0 秒 | — |

> 提醒：**唯一"以前看不到、现在看得到"的行为变更**是 PC 试卷列表。
> 验收时若看到"未开放"的卷，那是设计，不是 bug（点它会提示原因，不会白屏）。

## 1. 阶段 0：自检（只读，10 分钟，0 风险）

**目的**：确认基线没漂移，避免把"数据本来如此"当成 bug 上报。

```powershell
# ① 服务活着
(Invoke-RestMethod http://127.0.0.1:8001/health).status
# ② 数据基线（应完全一致）
python _run/probe_student_three_ends.py      # 学生视角资料/试卷/取题
# 期望：行测 38 / 申论 27 / 公专 41（含 4 份试卷）、试卷 4 套、#5 取题 97
# ③ 库内基线
python _run/probe_resume_saved.py            # exam_record / 明细分布
# 期望：exam_record 1 条（record 1，已交卷）；明细 97 条
```

| 判定 | 处理 |
|---|---|
| 三项与上表一致 | 进入阶段 1 |
| 数量不一致但能解释（如新增了测试卷） | 记录差异，继续 |
| 数量不一致且无法解释 | **停**，先查数据（`_run/` 下有只读探针） |

## 2. 阶段 1：单账号单端冒烟（PC，30 分钟）

**目的**：证明"看资料 → 开考 → 交卷 → 结果"这条主链在 PC 上对。

| # | 操作 | 预期 | 判据 |
|---|---|---|---|
| 1 | 学生 `202516001` 登录 → 公专资料页 | 4 张试卷卡（含「下载原卷 / 去考试」）+ 知识卡片 | 卡片数 4 |
| 2 | 点第一张卷「下载原卷」 | 下载 docx，大小与原文件一致 | 能打开、内容非空 |
| 3 | 点「去考试」→ 历年试卷页 | 4 套卷；状态标为「已完成 ✓ / 可考 / 未开放」 | 状态与 §0 描述一致 |
| 4 | 选一套**没考过的**卷「开始考试」→ 只答 2 题 → 交卷 | 结果页：得分 `0 / N 分`、正确/错误 `0 / N 题`、用时秒级 | 两个分母都 = N |
| 5 | 回试卷列表 | 该卷变「已完成 ✓」，显示「得分 0 / N」 | 满分 = 卷面分（97 或 100） |
| 6 | 点「查看错题集」 | 错题 2 条 | 条数一致 |

> 这 6 步就是"用户能否正常考一场"的最小闭环。**任何一步错，先别往下走。**

## 3. 阶段 2：跨端一致性（手机 ↔ 平板 ↔ PC，20 分钟）

**目的**：验证"同一场考试在不同设备上是同一份作答"（断点续答的核心价值）。

| # | 操作 | 预期 |
|---|---|---|
| 1 | 手机打开 `/#/mobile/student-papers` | 每张卷右上角有「可考 / 未开放」 |
| 2 | 点一套卷 → 手机内开考（**注意：不再跳 PC 页**） | 顶栏 `1 / N` + 倒计时 `mm:ss` |
| 3 | 答 2 题（第 1 题选 A，下一题选 B）→ **直接返回，不交卷** | 无报错 |
| 4 | 重新进同一套卷 | 自动跳到第 3 题；答题卡里 1、2 两格是绿色（已答）；倒计时接着走 |
| 5 | 平板打开 `/#/tablet/student-papers` → 同一套卷 | 同样能续答（同一份数据，不靠 localStorage） |
| 6 | 在手机上交卷 → 看结果页 | 得分/题数与 PC 口径一致 |

**判定**：第 4 步是本次新增能力的核心，必须"答案在、计时接着走、跳到第一道未答"。
若答案没回填 → 查 `PUT /api/exams/{id}/progress` 是否 200（防抖 1.2s，退出太快可能还没存）。

## 4. 阶段 3：管理端开关联动（15 分钟，需要管理员账号）

**目的**：验证"管理员关一下，学生端立刻能看到但不能考"。

| # | 操作 | 预期 |
|---|---|---|
| 1 | 管理端资料管理 → 某套卷「考试」列关闭 | 列表状态变「未开放」 |
| 2 | 学生端刷新试卷列表 | 该卷**仍在**，状态「未开放」；点「开始考试」→ 黄色提示「考试已关闭，暂时不能开始（历史成绩不受影响）」 |
| 3 | 管理员重开 | 学生端刷新后变「可考」，能正常开考 |
| 4 | 设置定时窗口（开始时间设为 3 分钟后） | 学生端刷新 → 「未开放」，提示带开始时间；到点后刷新 → 可考 |
| 5 | 把某套卷的题全删（或选 0 题的卷） | 学生端显示「未开放」，提示「这场考试还没有题目」 |

> 阶段 3 结束务必把自己改的开关/窗口**恢复原状**（当前 5 套卷都是 `exam_open=1`、无窗口）。

## 5. 阶段 4：边界与并发（15 分钟）

| # | 操作 | 预期 |
|---|---|---|
| 1 | 同一场考试连点两次交卷 | 第二次 400「考试已提交，不能重复提交」，不产生重复明细 |
| 2 | 手机考试中把倒计时耗到 0（可临时把卷时长改成 1 分钟） | 自动交卷 → 跳结果页，**不弹确认框** |
| 3 | 两个账号同时考同一套卷 | 各自记录互不影响；结果页各看各的 |
| 4 | 考试中管理员关闭该卷 | 已开考的可继续并交卷（S2 决策），只是不能再开新考 |
| 5 | 手机答到一半断网再点选项 | 前端不崩；恢复网络后下一次操作会把最新作答存上 |

## 7. 一句话流程

> **阶段 0 对基线 → 阶段 1 自己跑通一场 → 阶段 2 换设备续答 → 阶段 3 管理员开关联动 → 阶段 4 边界 → 阶段 5 对账**。
> 阶段 1 不过就别叫人验；阶段 2 不过说明"续答"这个卖点不成立；阶段 3 不过说明"未开放"只是贴纸。

## 8. 需要你拍板的一个体验点

阶段 3 第 2 步会出现"**看得到但点不了**"的卷。当前实现是：卡片保留、状态标「未开放」、点击弹原因。

另一种做法是**仍旧隐藏**（回到 P2 的口径，学生看不到就不会困惑）。两种都成立：
- 显示：学生知道"卷还在，只是现在不能考"（本次改动）；
- 隐藏：列表更干净，但学生会以为卷丢了。

本次按你 22 号的指示做成"显示"，若真人验收后觉得困惑，改回隐藏只需恢复 `paper_generation.py` 里那 4 行 gate 过滤。
