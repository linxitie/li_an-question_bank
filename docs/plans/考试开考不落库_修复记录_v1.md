# 考试「开始考试」不落库 → 交卷报「考试记录不存在」修复记录 v1

> 发现方式：你在 2024 真卷上**手动点「开始考试」→ 交卷**，弹「提交失败：考试记录不存在」（URL `#/paper-answer?record_id=1&paper_id=4`）。
> 结论：**不是 2024 卷的数据问题，是开考接口从来没把考试记录写进库**。修复 1 行代码 + 1 条防回归用例，已实测开考到交卷全通。

---

## 1. 现象与复现（先证明，再动手）

```text
POST /api/exams/start?paper_id=4&exam_type=SELF_TEST   → 200 {"exam_id": 1, ...100 题...}
select count(*) from exam_record;                      → 0        ← 记录根本没落库
POST /api/exams/1/submit                               → 400 考试记录不存在
```

也就是说：**接口说"考试开好了，id=1"，但库里一行都没有**。前端拿着这个假 id 一直答题（题目是真取到的），一交卷就必然撞"记录不存在"。

顺便解释一个旧现象：修复前 `exam_record` 表**一直是 0 行**——不是没人考过，是**谁都考不成**。

## 2. 根因

| 位置 | 代码 | 说明 |
|---|---|---|
| `services/exam_service.py:start_exam` | `db.add(exam_record)` → **`db.flush()`** | 只 flush 不 commit |
| `core/database.py:get_db` | `finally: db.close()` | 请求结束关会话，**未提交的 INSERT 被回滚** |
| 老路由 `POST /api/exams/{paper_id}/start`（`exams.py:294`） | `db.commit()` + `db.refresh()` | 一直是好的 |

前端 `student_papers.vue:251` 的「开始考试」走的是**新路由** `/api/exams/start`，所以只有这条链路坏；「再做一次」（`paper_result.vue:224`）走老路由，反而是好的。

**为什么长期没被发现**：单测用 `StaticPool` + 同一个 session 覆盖 `get_db`，未提交的行在同一个 session 里照样查得到，所以 `test_start_exam_*` 全绿；而生产是"一个请求一个 session，关掉即回滚"。这类 bug 只有**真点一次**才会暴露。

## 3. 修法（最小改动）

`backend/app/services/exam_service.py`，在 `flush()` 之后补两行：

```python
db.add(exam_record)
db.flush()
db.commit()                 # ★ 新增：必须落库，否则请求结束被回滚
db.refresh(exam_record)
```

不动路由、不动模型、不加端点（API 面仍 343）。

## 5. 端到端验收（真实 HTTP + 跨连接查库）

| 步骤 | 结果 |
|---|---|
| ① 开考 `POST /api/exams/start?paper_id=4` | 200，`exam_id=1`，100 题；**库里确认 `exam_record (1, user 3, paper 4, is_completed=0)`** |
| ② 交卷（第 1 题 A、第 41 题 C，其余留空） | 200 `{"total_score": 2.0, "max_score": 100.0, "scored_count": 100}` |

| ④ 成绩列表 / 成绩详情 | `GET /api/exams/records` → 200 `total=1`；`GET /api/exams/records/{id}` → 200（含卷名/得分） |
| ⑤ 清理复测数据 | 删掉这次复测记录，`exam_record` 回 **0 行**，你的验收环境干净 |

> 第 2 题得分是对得上的：100 题每题 1 分，答对 2 题 = 2.0 分。

## 6. 影响面与风险

- **只影响新路由 `/api/exams/start`**（学生端「开始考试」按钮、`student_papers.vue`）；老路由、交卷、进度保存在本次改动前就有 commit，行为不变；
- 事务边界变短：开考即落一条"进行中"记录。副作用是**点开考但没答就关页面会留一条未完成记录**——这正是原设计（`is_completed=0` 可继续、可重考，交卷后才 `is_completed=1`），与老路由行为一致；
- API 面未变（343），无需重算基线。

## 7. 顺带记一笔技术债

全仓 `db.flush()` 有 **73 处**，绝大多数后面紧跟 `commit()`（或由调用方 commit）。但"服务层 flush + 路由直接 return"这种组合天生会踩同一个坑。建议列入巡检：

```text
规则：app/services 里出现 flush() 的函数，若调用它的路由在 return 前没有 commit，视为风险。
```

本轮只修考试开考这一条（有你的实测证据），没有批量改。
