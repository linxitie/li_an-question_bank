## 1. 结论（横屏前提下）

**可以做，而且是「零版式改动」级别的可行**：电脑端资料页是 `repeat(auto-fill, minmax(150px,1fr))` 的响应式网格，横屏下自动铺开，三种 iPad 横屏尺寸**横向溢出全为 0px**。
横屏真正的矛盾不是宽度，而是**高度**：1024×768 / 1180×820 时电脑版顶部（顶栏 + 建卡条 + hero + 备考指南）占掉 474px，**首屏只剩 1 行卡片**；把顶部留白收紧（仍是同一套页面、同一区块顺序）后可到 **2 行**。

## 2. 横屏实测（三种 iPad 横屏尺寸，电脑端资料页）

| 尺寸 | 列数 | 单卡 | 卡片字号 | 网格距顶 | 首屏可见行 | 横向溢出 | <44px 触控 |
|---|---|---|---|---|---|---|---|
| 1024×768 | 6 | 152×170 | 14px | 474 | **1 行** | 0 | 5 → **0** |
| 1180×820 | 7 | 151×170 | 14px | 474 | **1 行** | 0 | 5 → **0** |
| 1366×1024 | 7 | 154×170 | 14px | 474 | **3 行** | 0 | 5 → **0** |

**触控补齐后（仅加 44px，版式不动）**：列数/卡片尺寸完全不变，`<44px` 元素 5 → **0**。
副作用：顶栏从 62px 抬到 ~88px，1366×1024 的首屏从 3 行变 2 行 —— 所以横屏下必须同时收紧顶部留白。

**紧凑版（触控 44px + 仅横屏 ≤1200px 收紧顶部）**：

| 尺寸 | 列数 | 单卡 | 网格距顶 | 首屏可见行 | 溢出 | <44px |
|---|---|---|---|---|---|---|
| **1024×768** | **5** | **179×170** | **407** | **2 行** | 0 | **0** |
| **1180×820** | **6** | 173×170 | 407 | **2 行** | 0 | **0** |
| 1366×1024 | 7 | 154×170 | 528 | 2 行 | 0 | 0 |

> 卡片反而更大（152→179 宽），因为列数从 6 降到 5；区块顺序、卡片样式、翻转交互与电脑端完全一致，只是顶部留白与副标题在窄横屏隐藏。

## 4. 竖屏怎么办（新增决策点）

你要求「横屏使用」，技术上**网页无法强制锁横屏**（Screen Orientation API 需先全屏，平板浏览器里不可靠）。三种处理：

| 方案 | 做法 | 代价 |
|---|---|---|
| **S1（推荐）** | 平板竖屏时显示一层「请横屏使用」提示（可点「继续竖屏使用」跳过） | 新增 1 个小组件 + 1 条 `orientation` 判定，约 1–2h |
| S2 | 不提示；竖屏时页面照常渲染（会变成 3 列窄版） | 0 成本，但用户可能竖着用，体验不一致 |
| S3 | 竖屏强制跳平板专用页（即上一版方案） | 与你「同一套页面」的要求冲突，不建议 |

## 5. 落地方案（在上一版 A 方案基础上按横屏修订）

1. **路由统一**：`/tablet/materials` → `redirect: '/materials/xingce'`；`/tablet/materials/detail` → `/materials/detail`；`/tablet/badges` → `/badges`（页面路由数 101 → 98，L6 同步）。
2. **全局样式**（`src/style/index.scss`，不动 `.vtj` 源码，守 R3）：
   ```css
   @media (orientation: landscape) and (max-width: 1366px) { /* 触控 44px */ }
   @media (orientation: landscape) and (max-width: 1200px) { /* 顶部收紧 → 首屏 2 行 */ }
   ```
3. **入口**：平板首页注入入口、我的页「离线下载」都改指 `#/materials/xingce`。
4. **竖屏提示**：按 S1 加一个 `TabletRotateHint` 组件（仅平板 + 竖屏 + 非 PC 显示）。
5. **清理**：删掉 `mobile_materials.vue` 的平板分支（改由电脑页承担）。
6. **验收脚本**：`tablet_landscape_preview.mjs` 固化为断言（列数/首屏行数/溢出/触控/详情两栏）。

## 6. 验收标准（9 条）

1. 1024×768 横屏：5 列、卡片 ≥170 宽、首屏见 **2 行**、溢出 0
2. 1180×820 横屏：6 列、首屏 2 行、溢出 0
3. 1366×1024 横屏：7 列、首屏 ≥2 行、溢出 0
4. 三种尺寸下 `<44px` 触控目标 = **0**

6. 上传页 860 居中、徽章页 4 列、均无溢出

9. 手机 390 仍 20/20；`pc_desktop_regression` 7/7；`gate_all` 10/10；vitest / vue-tsc 全绿

## 9. ③ 平板首页切电脑版：预期效果与实测（2026-11-02 追加）

### 9.1 先说一个硬约束

**不能让 `/tablet/home` 直接 `redirect` 到 `/home`**：`device.ts`（R4 原样保留）里 `/home → /tablet/home`，平板访问 `/home` 会被映射回去，`redirect` 会形成**死循环**。
所以 ③ 的正确做法是：**把 `/tablet/home` 这条路由的 `component` 换成 `$vtj/vue/home_page.vue`（电脑首页组件）** —— 路径不变、不碰 `.vtj` 模板、不动 `device.ts`。

### 9.2 电脑首页在 1024 横屏下会「右栏被裁」

电脑首页上层是 `.top-section { grid-template-columns: 280px 1fr 320px }`，中间栏 min-content 约 482px，所以在 1024 横屏下总宽 1122px 超出容器 953px：

| 尺寸 | 容器宽 | 三栏实际内容宽 | 右栏右边缘 | 是否溢出容器 |
|---|---|---|---|---|
| 1024×768 | 953 | **1122** | **1155（视口 1024）** | ❌ 超出 169px，考试日历被裁 |
| 1180×820 | 1109 | 1122 | 1155（视口 1180） | ❌ 轻微超出 13px |
| 1366×1024 | 1296 | 1295 | 1328 | ✅ 正常 |

### 9.3 两种适配候选（真实注入测过）

| 方案 | 1024 容器 953 | 1180 容器 1109 | 效果 |
|---|---|---|---|
| V2 两侧收窄（220 / 1fr / 260） | 内容 990 → 仍超 37px，右边缘 1023 贴边 | **内容 1109 = 容器 1109 ✅** | 适合 1180 |
| **V3 右栏下移（260 + 1fr，右栏独占一行）** | **内容 953 = 容器 953 ✅**，右边缘 986（留 32px） | 同样 ✅ | **适合 1024** |

**推荐组合**：`≥1280` 原样三栏；`1100–1280` 用 V2；`≤1100` 用 V3。触控目标 16 → **0**（首页的导航/「查看更多」/卡片按钮统一 44px）。
