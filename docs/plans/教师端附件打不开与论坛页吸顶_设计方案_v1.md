# 教师端附件打不开 + 论坛页吸顶 — 设计方案 v1

> 状态：**待批准**（只做设计与取证）
> 日期：2026-10-30
> 需求：
> 1. 教师平板端上传文件后，下载/打开异常：PDF 打不开；Word 能打开但不显示内容，一直「正在加载资源…」
> 2. 教师平板端与电脑端论坛页滚动时：顶部导航栏要固定；下方搜索/筛选栏也要固定

---

## §1 现状证据（实测）

### 1.1 附件服务端点

`backend/app/api/media_assets.py`

| 项 | 实测 |
|---|---|
| 路由 | `@router.api_route("/{asset_id}", methods=["GET","HEAD"])`，`router = APIRouter(prefix="/media")` → `GET /media/{asset_id}` |
| 鉴权 | **无**（只有 `db: Session = Depends(get_db)`）→ iframe/img 可直接访问 ✅ |
| 响应 | `StreamingResponse`，`media_type=asset.content_type`，支持 Range/ETag/304 ✅ |
| **关键** | `_base_headers()` 第 36–39 行：**只要 `kind == "forum"` 就强制 `Content-Disposition: attachment`** |

```python
if asset.kind == "forum" and asset.original_name:
    headers["Content-Disposition"] = "attachment; filename*=UTF-8''" + quote(...)
```

### 1.2 这为什么导致"打不开"

- `Content-Disposition: attachment` 会让浏览器**强制下载**而不是在页面内打开；
- 平板 WebView / 系统浏览器下载 PDF 后若无内置阅读器 → **表现为"PDF 无法打开"**；
- Word 同理：下载到本地后用 WPS/Word 打开，与系统服务无关 → 显示"正在加载资源…"是**客户端应用**的问题，服务端改 header 也解决不了。

### 1.3 前端是否有预览组件

```
grep -r "docx-preview|mammoth|正在加载资源|iframe" src/
→ 仅命中 richText.test.ts 与 questionRender.js（都是 sanitize 相关）
→ 项目目前【没有】docx/pdf 预览组件
```

即：Word 的"能打开但空白"**不是我们的前端渲染失败**，而是文件被下载后交给外部应用。

## §2 方案（附件预览）

### 2.1 服务端：把 forum 附件改为"可内联预览 + 可强制下载"

```python
# media_assets.py _base_headers
INLINE_KINDS = {"image/png", "image/jpeg", "image/gif", "image/webp", "application/pdf", "text/plain"}
disposition = "inline" if asset.content_type in INLINE_KINDS else "attachment"
# 支持 ?download=1 强制下载
if request.query_params.get("download") == "1":
    disposition = "attachment"
headers["Content-Disposition"] = f"{disposition}; filename*=UTF-8''" + quote(asset.original_name, safe="")
```

**为什么这样改**：
- 只放开"浏览器原生能渲染"的类型（PDF / 图片 / txt），**office 文档仍走下载**，避免浏览器下载一堆乱码；
- 加 `?download=1` 保留"另存为"能力，前端可显式提供下载按钮；
- 不改变鉴权（本来就是公开读），不改变缓存/ETag/Range 行为。

### 2.2 前端：附件点击行为分类型

| 类型 | 行为 |
|---|---|
| PDF / 图片 / txt | 新标签页打开（内联渲染），即 `window.open(url)` |
| Word / Excel / PPT / 压缩包 | 直接下载（`<a download>` 或 `?download=1`） |
| Word 在线预览（**可选，需第三方库**） | 引入 `docx-preview`（约 200KB）前端渲染 .docx；不支持 .doc |

**推荐**：先做 2.1 + 2.2 的前两类（零依赖），**Word 在线预览列为可选项**，等你确认是否要引入 `docx-preview`。

### 2.3 平板端 PDF 打不开的兜底

平板若没有内置 PDF 阅读器，内联打开仍可能空白。兜底方案：附件行右侧提供「下载」与「在浏览器打开」两个动作，并提示"若无法预览请下载后用 WPS 打开"。

## §3 方案（吸顶）

### 3.1 现状

| 元素 | 现状 | 位置 |
|---|---|---|
| 教师端顶部导航「砺安题库·教师端 / 工作台…」 | 页面普通流，滚动即消失 | 教师端布局组件（需定位） |
| 论坛标题「论坛管理」+ 副标题 | 普通流 | `.tf-head`（teacher_forum.vue） |
| 搜索 + 日期 + 班级 + 查询 | 普通流 | `.tf-filters` |
| 右侧三卡 | **已 sticky**（本轮已做） | `.tf-side` |
| 页面滚动容器 | `.tf-page { height:100vh; overflow-y:auto }`（本轮已做） | teacher_forum.vue |

### 3.2 方案

```css
/* 1) 顶部导航吸顶（布局层） */
.app-header, .teacher-header { position: sticky; top: 0; z-index: 100; }

/* 2) 标题行吸顶（导航下方） */
.tf-head { position: sticky; top: var(--nav-h); z-index: 30; background: #f4f6fb; }

/* 3) 筛选栏吸顶（标题行下方） */
.tf-filters { position: sticky; top: calc(var(--nav-h) + var(--head-h)); z-index: 29; background: #f4f6fb; }
```

要点：
- 需要先量出导航高度与标题行高度，用 CSS 变量固化，避免手算错位；
- 滚动容器必须是 `.tf-page`（已完成），否则 sticky 会绑到 VTJ 外壳；
- 吸顶后加背景色 + 底部细边框，避免内容透出；
- 平板端若为独立布局（`.tablet-*`），需按同一思路单独处理。

### 3.3 验收

| # | 断言 |
|---|---|
| 1 | 滚动 600px 后导航栏 top 保持 0 |
| 2 | 标题行紧随导航下沿（差值 ≤ 2px） |
| 3 | 筛选栏紧随标题行（差值 ≤ 2px） |
| 4 | 滚到底部时三卡仍固定（不回归） |
| 5 | 弹窗打开时 z-index 仍高于吸顶元素 |

## §4 风险

| 风险 | 对策 |
|---|---|
| sticky 在 VTJ 外壳下失效 | 已确认滚动容器是 `.tf-page`，沿用本轮验证过的做法 |
| 吸顶遮挡内容 | 吸顶元素加背景 + `padding`，内容区补 `scroll-padding-top` |
| 改 `Content-Disposition` 影响其他业务 | 只对 `kind == "forum"` 且白名单 MIME 生效 |
| 平板原生 PDF 阅读器缺失 | 提供下载兜底 + 文案提示 |
