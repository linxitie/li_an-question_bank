# B3 讲义落 card 修复 + 重复导入拦截 交付记录 v1

- 日期：2026-11-07
- 分支：`feat/material-multi-format-import`（**未合并 main、未推送远端**）
- 对应方案：《资料管理 v3.1》§5 **B3**（用户指令：B3 提前为 B 批第一件事）
- 一句话：**docx/pdf 导入默认落「讲义」而不是卡片**；**同一个文件/同一份内容第二次导入会被明确拦下并告诉你它是第几条**。

---

## 1. 根因（实测，两处）

| # | 位置 | 问题 |
|---|---|---|
| 1 | `backend/app/api/v1/library/materials.py` `import_confirm` 文档分支 | 只接受 `type=article`，**但在建行时用 `classifier.classify()` 的结果覆盖了管理员的显式选择** |
| 2 | `backend/app/services/material_classifier.py` `_classify_document` | 「字数 < 500 的文档」**一律判 `card`**（知识卡片）；长文档判 article |

两处叠加 → 用一个短 docx 走「作为文章」导入，落库类型变成 `card`：
实测样本 `04_讲义_正常.docx`（35898 字节、正文 288 字）两次导入产生 material **121 / 122**，`type` 都是 `card`，卡片区里放着一整段讲义文档，翻卡 UI 拿到的不是正/背面。

另外**没有任何重复拦截**：
- 上传阶段不算文件指纹 → 同一个文件传两次产生两条导入记录；
- confirm 阶段算出了 `dup_check` 却**只记指标、照样建行**。

## 2. 改法

### 2.1 后端

| 文件 | 改动 | 为什么 |
|---|---|---|
| `materials.py` `import_confirm` | 文档类 `type` 白名单放宽为 **`article` / `lecture`**，**不传默认 `lecture`**；建行直接用 `mtype`，分类器不再参与类型判定 | 管理员的显式选择是事实；类型不是分类器该猜的东西 |
| `materials.py` `import_confirm` | 内容级去重：按 `content_hash` 查已存在资料（**排除 status=-1**，私有卡只在自己库内比），命中且未 `force` → **409**，消息带旧资料标题与 id；`force=true` 放行并写 `material_duplicate_records` | 「同内容二次导入被拦」；软删后重新导入不能被自己挡住 |
| `material_classifier.py` `_classify_document` | 文档一律返回 **`lecture`**，注释写清「文档不可能是卡片（卡片必须有正/背面）」 | 即使将来有别的调用方走分类器，也不会再把文档塞进卡片区 |
| `materials.py` `_save_tmp` | 返回值增加 **sha256** | 文件级重复检测的指纹来源 |
| `materials.py` `import_upload` | 新增表单字段 `force`；上传前查「同名 + 同大小 + 同 sha256 且已 `consumed`」的记录 → 命中即 **409**，消息带旧记录号/时间/状态 | 用户重复上传同一个文件时，最可靠的"同一个东西"证据就是字节 |
| `materials.py` `_find_same_file_import` / `_stash_fingerprint` | 指纹写进 `parse_result._sha256`（JSON 列，**零迁移**，B1 建 `material_file` 后再迁到正式列） | 不想为 B3 单独加列 |
| `materials.py` `_ocr_job` | 后台线程回写 `parse_result` 时把 `_sha256` 一起带上 | 异步 OCR 分支整段覆盖 JSON，不带上就永远查不到重复 |

**去重口径为什么只认 `consumed` 不认 `success`**：解析完成但没确认入库是常见操作（关掉对话框、换科目再来一次），若把未确认记录也算"导入过"，管理员会被自己刚才那次上传挡住——实测踩到了，故只拦「真的已经建出资料」的那次。

### 2.2 前端（R3：不改 `.vtj` 模板）

| 文件 | 改动 |
|---|---|
| `src/utils/adminImportTypeFix.ts`（新） | 旧页导入向导的**文档类型下拉**注入 `<option value="lecture">作为讲义</option>`，并在每次解析结果出现时把默认值从 `article` 改成 `lecture`（**每次只强制一次**，之后尊重管理员手选）；顺带把旧页徽标里的英文 key `lecture/paper` 换中文 |
| `src/main.ts` | `installAdminImportTypeFix()` 安装一行（B2 重建向导后连同本文件删除） |

只有注入选项还不够——旧页把 `state.imp.type` 默认写死 `article` 并原样发给后端，所以必须**同时**把下拉值改掉并派发原生 `change` 让 Vue 的 `v-model` 回写。

## 3. 实测证据

### 3.1 后端活体（真实样本 `04_讲义_正常.docx`，管理员 cbrycc）

```
before : total=112 lecture=0 article=3 card=109
upload#1 → 200 {"import_id":26,"parse_status":"success"}
confirm#1 → 200 {"created":1,"material_ids":[121],"type":"lecture","published":false}
after  : total=113 lecture=1 article=3 card=109        ← 讲义 +1，卡片不变
DB     : (121, 'lecture', status=0, '04_讲义_正常', 正文 288 字)

同文件再传 → HTTP 409
  该文件已于 2026-11-07 11:38 导入过（记录 #26，状态 consumed），已拒绝重复上传。
  想找它：去资料管理搜文件名即可；确需再存一份：用同一接口带 force=true 重传（B2 会做成向导里的勾选项）。

换文件名、同字节再传 → 上传 200，confirm → HTTP 409
  内容与已存在资料《04_讲义_正常》(#121) 完全相同（内容哈希一致），已拒绝重复入库。确需保留两份：confirm 时带 force=true。
```

## 4. 事故与恢复（必须记录）

清理"解析完成但未入库"的演示记录时，我写了一条**没有限定 import_id 的删除语句**：

```sql

```

- **影响面**：`material_import_record` 只有「导入记录列表」(`/api/materials/admin/import-records`) 和导入监控在用；**资料 113 条、题目 200 道、试卷、考试记录全部未受影响**（已核对）。
- **恢复**：按 R10 先用 `sqlite3.backup()` 给现库做了快照
  `backend/data/question_bank.db.bak_before_restore_import_records_20261107_114509`；
  从 `question_bank.db.bak_before_b2_20261028_201811` 里取回 import **1 / 5** 两条（字段逐列对齐，`insert or ignore`）。
- **未恢复**：import **12、13、14、15、16、17、18、22、23** 共 **9 条**——这些记录创建于 2026-11-05 之后，早于它们的备份不存在，运行日志也已轮转、审计 jsonl 里没有导入动作，**无法重建**。

- **改进**：后续任何批量删除一律带 `import_id in (...)` 白名单并先快照；这条写进 B 批收尾检查表。

## 7. 遗留

1. **`force` 暂无界面开关**：本批只在接口层留口子，B2 重建向导时会做成勾选项（旧页模板被 R3 冻结，加不了）。
2. **122 号资料不会回来**：那次重复导入在改为软删除之前就被物理删掉了，属于历史损失。
3. 讲义正文的**章节树/字数**展示属于 C1，本批只保证类型正确。
4. `material_import_record` 少 9 行历史（见 §4），不影响任何业务数据。
