## 5 分支（一屏）

```
main
└── feat/<模块>            ← 模块工作域（新域用 feat/ 前缀）
    └── feat/<模块>-<子任务>  ← 一分支一任务（用 `-`，不能用 `/`，见 v4 §7.1）
```

```powershell
# 0) 先确认有没有 upstream（没有就别假装 pull 成功）
git rev-parse --abbrev-ref --symbolic-full-name '@{u}'   # 报错 = 无 upstream
# 1) 有 upstream 时同步父域
git fetch origin; git checkout feat/<模块>; git pull --ff-only
# 2) 开子分支（父域已是 feat/<模块> 时）
git checkout -b feat/<模块>-<子任务>
# 3) 每文件一验证
npx vitest run <spec>; npm run typecheck; cd backend; python -m pytest tests/<域> -q; cd ..
# 4) 逐文件提交
git add <精确文件>; git commit -m "feat: <简述>"
# 5) 父域有更新
git fetch origin; git rebase feat/<模块>
# 6) 收尾只向父域合并/PR，禁止直连 main
```

硬约束：B1 子分支禁连 `main`｜B2 一分支一任务｜B3 前缀只允许 feat/fix/test/refactor/docs/chore｜B6 禁 `git add -A`｜B7 大件与密钥不入提交｜B9 无 upstream 如实报。

## 6 换帽与并行

换帽必留 Handoff（≤10 行）：`FROM/TO` + 已定 + 未定 + 风险 + 证据。
并行条件：文件集不相交；同一文件禁止两角色并写。典型可并行：`SEC∥QA`、`ARCH∥DOC`、`BE∥FE`（契约已冻结）。
≥6 个独立文件的只读审计 → `workflow` 扇出，保护主上下文。
越权：立即停手 + Handoff + 回 PM。
