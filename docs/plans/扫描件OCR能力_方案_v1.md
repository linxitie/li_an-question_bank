## 0. 一句话结论

| 问题 | 回答 |
|---|---|
| 能实现吗 | **能**。"扫描件上传 → OCR 识别 → 变成可入库文本"这条链路，代码里已经留好了位置（`mineru_material_service` 的扫描件分支），只是**引擎没装**。 |
| 推荐怎么实现 | **RapidOCR 本地 sidecar**（独立 Python 3.11 环境 + 自带模型，CPU 跑），主服务只经子进程调用，不把 OCR 依赖塞进主环境。 |

## 1. 现状审计（为什么现在传不了）

### 1.1 报错从哪来（已定位到行）

你截图里的红字：**"该 PDF 为扫描图片版且系统 OCR 组件未就绪，请转存为文字版 Word 后重新上传"**
来自 `backend/app/services/mineru_material_service.py` 的 `run_mineru()`：

```python
MINERU_EXE = Path(os.environ.get("MINERU_EXE", r"C:\mineru_env\Scripts\mineru.exe"))
def mineru_available() -> bool:
    return MINERU_EXE.exists()
...
if not mineru_available():
    raise MineruError("该 PDF 为扫描图片版且系统 OCR 组件未就绪，请转存为文字版 Word 后重新上传")
```

## 2. 选型对比（为什么是 RapidOCR）

| 方案 | 准确性 | 速度（CPU，本机） | 体积/安装 | 网络依赖 | 结论 |
|---|---|---|---|---|---|
| **RapidOCR（onnxruntime）** | 印刷体中文好（AI 讲师项目实测：印刷体近乎全对，手写红笔乱码） | **≈4.6 秒/页**（10 帧 45.67s 实测） | 独立 venv ≈300–500MB；**模型随包**，无需下载 | 只需一次 pip（清华镜像可达） | ✅ **推荐** |

| 云 OCR（智谱/百度等） | 高 | 快 | 0 | **要 key、要出网、有合规问题** | ⏸ 以后可选，不纳入本期 |

## 3. 推荐架构（进程隔离，主服务零新增依赖）

```
上传扫描件 PDF
   │
   ├─ 主后端（Python 3.14）
   │    · PyMuPDF(fitz) 渲染每页 → PNG（150–200dpi）
   │    · 写入临时目录，起一个子进程（超时/内存硬隔离）
   │
   ├─ OCR sidecar（C:\ocr-env，Python 3.11 + rapidocr-onnxruntime）
   │    · 逐页识别 → 行文本（按 y 坐标合并成行/段）
   │    · 输出 {"pages":[{"no":1,"text":"..."}], "seconds":...}
   │
   └─ 回到主后端：把 OCR 文本交给**现有消费方**
        · 答案上传：answer_ingest.read_text_of() 的 PDF 分支
        · 文章/讲义：import_confirm 的正文（文字版 HTML）
        · 试卷导题：paper_ingest 的正文（P3，需人工核对）
```

**为什么这么设计**（对应全局规则 3 的自问）：

| 问题 | 回答 |
|---|---|
| 为什么放独立 venv | onnxruntime 不支持主环境的 Python 3.14；独立环境崩了也不影响后端；升级/回滚只动一个目录 |
| 为什么用子进程 | 你截图这次就是"组件缺失"被静默判死；子进程能给出**明确错误/超时**，且不会拖垮 FastAPI |
| 好处 | 主环境零依赖变更；OCR 可单独替换（以后换 Paddle/MinerU/云 OCR 只改 sidecar） |
| 安全 | 只处理本地文件、不联网；输入路径白名单 + 超时强杀；输出纯文本，`v-html` 一律消毒（沿用现有 `sanitize_html`） |
| 运维 | 一条 `--health` 命令自检；配置走环境变量（`OCR_RUNTIME`、`OCR_MAX_PAGES`、`OCR_TIMEOUT`）；失败可降级为"请转文字版" |
| 前端能显示吗 | 能：上传队列里增加"OCR 中 3/24 页"进度；完成后照常进"解析草稿/文章入库"，不需要新页面 |
| 后端字段/路由 | **不新增表、不新增端点**（沿用 `import/upload`、`answers/parse`）；只改服务层与一个 worker 脚本 |
| VTJ 版本 | 不动 `.vtj`，`vtj_version_sync --check` 不受影响 |

### 9.2 样本与逐页结果

样本就是你上传失败的那份：`题库\答案解析（不用打印）\2017年多省联考《公安专业科目》考试参考答案及解析.pdf`
——**24 页、文字层 0 字**（"请转存为文字版 Word"那句话就是因为它）。参数 dpi 200，跑**前 3 页**：

| 页 | 耗时 | 字数 | 行数 | 识别到的题号 | 平均置信度 |
|---|---|---|---|---|---|
| 1 | 9.2s | 1245 | 46 | 1、2、3、4 | 0.989 |
| 2 | 9.0s | 1377 | 47 | 5、6、7、8 | 0.992 |
| 3 | 7.6s | 1337 | 48 | 9、10、11、12、13 | 0.994 |
| **合计** | **25.8s（≈8.6s/页）** | **3959** | **141** | **13/13 全中** | — |

外推 24 页 ≈ **3.4 分钟**（比方案里估的 2 分钟慢：这份件是双栏密集小字；**以实测 8.6s/页 为准**）。仍远快于 MinerU 的 71.2s/页（24 页 ≈ 28 分钟）。

### 9.3 质量（贴真实文本，不美化）

第 1 页识别原文（节选，未经任何修正）：

```
1、正确答案是：D
解析
本题考查公安时政。
2016年5月20日，习近平总书记主持召开中央全面深化改革领导小组第二十四次会议。会议强调，深化公安执
法规范化建设，要看眼于完善公安执法权力运行机制，构建完备的执法制度体系、规范的执法办案体系、系统的
执法管理体系、实战的执法培训体系、有力的执法保障体系……
```

**最有价值的一条**：拿**现成的答案抽取逻辑**（`answer_ingest` 那套 L0–L3）直接吃 OCR 文本 —— **13 个题块 → 13 条答案**（L1「N、正确答案是：X」12 条 + L2「故正确答案为X」1 条），**0 漏、0 错位**。也就是说"扫描件 → 答案草稿"这条路，OCR 出来就能直接进现有链路，不用新建解析器。

已知错字 / 缺陷（**必须在 P1 处理或提示核对**）：

| OCR 输出 | 正确 | 影响 | P1 处置 |
|---|---|---|---|
| 要看眼于 | 要着眼于 | 解析可读性 | 提示核对，不自动纠错 |
| 驾车外出玩 | 驾车外出玩耍（漏字） | 同上 | 同上 |
| `C项错误` / `c项错误` | 大小写混 | **答案抽取器若大小写敏感会漏** | **P1 必做：大小写不敏感** |
| 按栏宽硬换行（一行 40±2 字） | 自然段 | 正文直接入库会碎 | 按题号/句号重排后再入正文 |

> 手写、红笔批注、公式、表格仍是乱码（与 11-05 AI 讲师 OCR 实测一致）。本方案**不承诺**这几类。

| 问题 | 答案 |

### 9.5 P1 的准确范围（等你批）

| 块 | 改哪里 | 内容 |
