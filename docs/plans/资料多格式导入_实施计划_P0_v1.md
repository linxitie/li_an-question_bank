## 2. 数据模型

### 2.1 迁移 `backend/migrations/20261105_006_material_import_progress.sql`

```sql
ALTER TABLE material_import_record ADD COLUMN batch_id VARCHAR(36);
ALTER TABLE material_import_record ADD COLUMN progress_percent INTEGER DEFAULT 0;
ALTER TABLE material_import_record ADD COLUMN current_phase VARCHAR(50);
ALTER TABLE material_import_record ADD COLUMN total_units INTEGER DEFAULT 0;
ALTER TABLE material_import_record ADD COLUMN done_units INTEGER DEFAULT 0;
ALTER TABLE material_import_record ADD COLUMN unit_name VARCHAR(10);
ALTER TABLE material_import_record ADD COLUMN retry_count INTEGER DEFAULT 0;
CREATE INDEX IF NOT EXISTS idx_material_import_batch ON material_import_record(batch_id);
```

> 写入必须 **LF 换行**（本仓 DDL checksum 对 CRLF 敏感，踩过坑）；字段全部可空/带默认，**向后兼容**，旧记录 `progress_percent=0, current_phase=NULL`。
> 同步更新 `migrate_study_materials.py`（`IF NOT EXISTS` 语义）与 `models.py:MaterialImportRecord`。

### 2.2 状态机（`current_phase`）

```text
pending ──enqueue──> queued ──start──> parsing ──> extracting ──> preview_ready ──confirm──> committing ──> done
                                     └──> ocr  ──┘                    │
任意态 ──错误──> failed（error_message + retry_count+1）──retry──> queued
processing/parsing/ocr 且 update_time 超过阈值（默认 30 min）──> 重置为 queued（服务重启恢复）
```

### 2.3 进度口径（前端只读这两个字段）

| 阶段 | `progress_percent` | `total_units / done_units / unit_name` |
|---|---|---|
| queued | 10 | — |
| parsing | 10 → 70（按单元比例线性） | PDF `page`、docx `para`、xlsx `row` |
| ocr | 10 → 70（按页） | `page` |
| extracting | 70 → 90 | — |
| preview_ready | 90 | — |
| committing → done | 90 → 100 | — |
| failed | 保持当时值 | 保留已完成单元数，便于"接着跑"的观感 |

## 4. 接口契约

### 4.1 `POST /api/materials/admin/import/batch`
```http
POST /api/materials/admin/import/batch   multipart/form-data
files: File[]（1..50）
→ 200 {
  "batch_id": "b_20261105_7f3a",
  "items": [{"import_id": 101, "file_name": "公专_必背考点.xlsx", "file_size": 132433, "parse_status": "queued"}],
  "limits": {"max_files": 50, "max_size_mb": {"pdf": 250, "docx": 50, "xlsx": 10}}
}
→ 400 {"error": "文件数量超过 50"} / 413 {"error": "xxx.pdf 超过 250MB"}
```

### 4.2 `GET /api/materials/admin/import/{import_id}/status`（改造，向后兼容）
```json
{"parse_status": "processing", "progress_percent": 42, "current_phase": "ocr",
 "total_units": 90, "done_units": 34, "unit_name": "page", "elapsed_seconds": 812,
 "eta_seconds": 1340, "error_message": null, "queue_position": 0}
```

### 4.3 `GET /api/materials/admin/import/batch/{batch_id}`
```json
{"batch_id": "b_…", "total": 30, "done": 12, "failed": 1, "queued": 17,
 "progress_percent": 41, "current": {"import_id": 118, "file_name": "三色笔记-申论.pdf", "progress_percent": 37},
 "items": [{"import_id": 101, "file_name": "...", "parse_status": "success", "progress_percent": 100}]}
```

### 4.4 `POST /api/materials/admin/import/{import_id}/retry`
```json
{"ok": true, "import_id": 118, "parse_status": "queued", "retry_count": 1}
```

> 权限：管理员可见全部批次；教师只能看自己 `uploader_id` 下的记录（越权返回 404，不泄露存在性）。

## 7. 写码前 11 问自检（你的全局规则 3）

| 问 | 答 |
|---|---|
| 为什么这样写？ | 后端只改 `materials.py` 单文件 + 2 个新服务文件：导入是本模块职责，另开模块会造成"两套导入"。进度用 `progress_percent` 单字段，和题目导入同名同义，前端一套映射通吃 |
| 好处？ | 单点维护、契约与题目导入一致、批量与单文件共用同一条解析链 |
| 安全问题？ | ①`_require_staff` + `uploader_id` 过滤（越权返回 404）②流式落盘避免 250 MB 进内存 ③magic bytes 校验不变 ④临时文件 finally 必清 ⑤sidecar 走内网 `app` 网络，不暴露公网 |
| 运维便利？ | 队列 worker 独立于请求；重启自动恢复；失败可在 UI 一键重试；`retry_count` 可观测；迁移可空字段可回滚（删列或留空） |
| 写在哪最合适？ | 迁移 `backend/migrations/`、服务 `backend/app/services/`、路由沿用 `library/materials.py`、前端新页 `src/views/{admin,teacher}/`（已有手写页先例 `material_rules.vue`） |
| 前端能显示吗？ | 新页是**手写 Vue 页**，不依赖设计器；进度条为纯 CSS + 轮询，三端都有；文件上限与接受格式由 `accept` 与后端双校验 |
| 后端字段完整吗？ | 7 个新字段覆盖"批次/阶段/百分比/单元/重试"；`eta_seconds`、`queue_position` 由计算得出不落库（避免冗余与漂移） |
| 路由注册了吗？ | 3 个新端点在同一 router 内注册（`materials.router`），openapi 自动出现；`test_api_surface` 白名单同步 |
| 接口完整吗？ | 上传（批量/单文件）、状态、批次汇总、预览、确认、重试、历史 6+1 条闭环；教师侧复用同一组端点 |
| 门禁双改点？ | `EXPECTED_DYNAMIC_IMPORTS` 104→106、`test_route_roles` 104→106；R11 白名单 +3（基线 343 不动） |
