## §1 现状取证（可复现）

### 1.1 手机端长标题（#1）

```
.vtj/vue/mobile_forum.vue:79   <h3 class="post-title" ...>{{ post.title }}</h3>
.vtj/vue/mobile_forum.vue:581  .post-title { font-size:16px; font-weight:600; ... }   ← 无 overflow-wrap / word-break
.vtj/vue/mobile_forum.vue:500  .post-card  { padding:16px; }                          ← 无 overflow:hidden
```

CSS 规范：CJK 会在任意字间断行，但**连续数字/拉丁串默认不断行**，所以「2345678643…」这种标题必然横向溢出。截图正是这种情况。

### 1.2 版本不一致（#2）

```
vite.config.ts:18    execSync('git rev-parse --short HEAD')   ← vite 启动时算一次
main.py:929          subprocess.run(['git','rev-parse','--short','HEAD'])  ← 后端启动时算一次
src/main.ts:58-78    backend !== frontendSha 就 ElMessage.warning
```

实测：`/health` → `revision: 77190a3`，而当时 HEAD 已是 `2e3d1fc`。**重启后端只会让后端也变新，前端 dev server 里的 SHA 仍是旧的**，于是永远不相等 → 告警不可能消失。

### 1.3 手机端热门/我的空白（#3）

## §2 逐项方案

### #1 手机端长标题不越界

**推荐（不碰 raw 页模板/样式）**：在 `src/style/index.scss` 追加作用域规则：

```scss
/* 手机端论坛：超长无空格串（纯数字/连写英文）必须换行，不能顶破卡片 */
.mobile-forum-page .post-title,
.mobile-forum-page .post-excerpt {
  overflow-wrap: anywhere;   /* 兼容性优于 word-break: break-all，且不会在正常中文处分行过碎 */
  word-break: break-word;
}
.mobile-forum-page .post-card { overflow: hidden; }
```

- 为什么放全局而不是 raw 页：R3 默认只允许改 `<script>`，全局样式是普通手写文件，零风险、可回滚、不影响其它端（作用域前缀限定 `.mobile-forum-page`）。
- 备选（需你授权）：直接改 `.vtj/vue/mobile_forum.vue` 的 `<style>`，我先备份再改。
- 验收：Playwright 手机视口 + 造一条超长标题，断言 `.post-title` 的 `scrollWidth <= clientWidth` 且卡片未被撑宽。

### #2 版本不一致

三层改动：

1. `src/main.ts`：把「强告警」限定在生产构建：
   ```ts
   const isDev = import.meta.env.DEV;
   if (isDev) { console.info('…dev 模式跳过强校验（前端 SHA 在 vite 启动时烘焙）'); return; }
   ```
2. 提示文案精确化：区分「前端旧（刷新/重启 dev server）」与「后端旧（重启 8000）」，并把两个 SHA 都打出来。
3. 保留 `window.__VERSION_MISMATCH__` 供排查。

- 为什么这样：dev 环境下 SHA 天生不同步，强告警只会制造噪音；生产构建前后端同源同提交才具备可比性。
- 验收：dev 下控制台只有 info、无 ElMessage；把后端回退一个提交后在**生产构建**下仍能告警（用 `dist` 预览验证，不改线上）。

### #3 手机端热门/我的

改 `.vtj/vue/mobile_forum.vue` 的 `<script>`（R3 允许）：

```ts
const filteredPosts = computed(() => posts.value);   // 列表集合由接口决定，前端不再二次按分类过滤
```

- 保留 `filteredPosts` 这个名字（模板不用改，零模板改动）。
- 顺带：`mine` 分支里的 `only_mine=1` 是无效参数（`my-posts` 不认识），删掉避免误导。
- 「实时更新」：页面已 `onMounted(loadPosts)`；切页签会重新拉。若要求「停留时自动刷新」，另加 `visibilitychange` + 30s 轮询（默认**不加**，避免无谓请求，除非你要）。
- 验收：Playwright 手机视口切到「今日热门」「我的帖子」，断言卡片数 > 0 且与接口 total 一致。

### #4 弹窗分层与关闭顺序

分层方案（PC `forum.vue` + 教师 `teacher_forum.vue` 同一套约定）：

| 层 | 用途 | z-index |
|---|---|---|
| 1 | 收藏 / 我的喜欢 / 今日热门查看更多 / 我的帖子查看更多 | 2000 |
| 2 | 帖子详情 + 评论区 | 2200 |
| 3 | 用户信息卡片 / 表情选择器 / 删除确认 | 2400 |

- **模板改动**（需你授权）：详情弹窗容器加 `class="modal-overlay modal-l2"`，一级加 `modal-l1`。
- **script 改动**（允许）：统一「Esc / 点遮罩」关闭**最上层**：先关二级（详情），再次触发才关一级。
- 教师端 `.tf-modal` 两处重复定义合并为一条 + `modal-l1/l2` 差异，避免后者覆盖前者导致 z-index 丢失。
- 验收：Playwright —— 打开热门查看更多 → 点帖子打开详情 → 断言详情可见且 `elementFromPoint(详情中心)` 命中详情；按 Esc 后详情消失、一级仍在；再按 Esc 一级消失。

### #5 手机端可见范围

`src/views/student/mobile/mobile_forum_create.vue`（手写页，自由改）：

- 加一组 pill：「全站可见 / 仅本班」（默认取后端规则：学生默认 CLASSES，与 PC 一致）。
- 提交时透传 `visibility` 与 `visible_classes: [本人 class_name]`；班级来源同 #6（`/api/auth/profile`）。
- 当账号无班级时：禁用「仅本班」并提示「账号未分班，可发全站帖」。
- 验收：Playwright 手机视口选「仅本班」发布 → 断言列表里显示该帖，且外班学生看不到（后端用例覆盖）。

### #6 班级候选

统一来源，避免三端各写一份：

1. 新增 `src/modules/community/classScope.ts`：`loadMyClasses()` 调 `/api/auth/profile`，读 `class_name`，做内存缓存（同一会话只请求一次），无班级返回 `[]`。
2. `PostComposer` 的 `classes` 由父页传入：学生 = `loadMyClasses()` 的结果；教师 = 现有 `classOptions`（teacher_forum 已有）。
3. 组件内增强空态文案：`[]` 时显示「当前账号未分班，仅可发全站帖」，而不是「没有可选班级」。
4. 顺手修正 `.vtj/vue/forum.vue:945` 的错误取法。

- 为什么不塞进 JWT：token 里没有班级，改 token 影响面大且需后端配合签发；`/api/auth/profile` 已是事实来源。
- 验收：学生账号打开弹窗 → 选「仅指定班级」→ 能看到「测试班」并勾选成功发布。

### #7 搜索栏缩短 + 校园/班级筛选

**后端**（`forum.py`，R11 安全：只加查询参数，不改路径）：

```python
visibility: Optional[Literal["ALL", "CLASSES"]] = Query(None, description="校园=ALL / 班级=CLASSES")
...
if visibility: query = query.filter(ForumPost.visibility == visibility)
```

顺序很重要：**先** `_apply_visibility_filter`（权限），**再** `visibility` 业务筛选，否则会绕过权限导致越权泄露。

**前端**（`.vtj/vue/forum.vue` template，需授权）：

- 搜索框宽度收窄（现占满一行，改为 `width: 260px`；窄屏 ≤1280 再降）。
- 右侧加分段筛选：`全部 / 校园论坛 / 班级论坛`（默认「全部」），选中即请求。
- 三端契约一致：平板复用同一页（`/tablet/forum` → `forum.vue`，符合 R12 不复制页面）。

- 验收：选「班级论坛」→ 请求带 `visibility=CLASSES`，列表只剩 CLASSES；选「校园论坛」只剩 ALL；与权限过滤叠加时外班帖依然不可见（后端 pytest 覆盖四种身份）。

### #8 教师端重置

`teacher_forum.vue:17` 同一行补：

```html

```

`resetFilters()` 清空关键词、日期区间、班级、排序并重新加载（保留页签名）。

### #9 富文本编辑器（本方案最大改动，含安全评审点）

**结论：复用仓库已有 wangEditor 4.7.15 + `RichTextEditor.vue`，不引入新依赖。**

#### 9.1 前端

- `PostComposer` 用 `<RichTextEditor>` 替换 textarea；工具栏菜单按图三扩到：
  `head（段落）、fontName（字体）、fontSize（字号）、bold、italic、underline、strikeThrough、color（字体颜色）、bgColor（背景色）、justify（对齐）、list、quote、emoticon、insertTable（表格）、image、link、undo、redo`
- `RichTextEditor.vue` 现状已支持动态 import + 图片走上传 + 失败降级 textarea，只需把 `menus` 配置改成 props 可配，避免影响 `admin_materials.vue` 的既有用法。
- 保留现有 `PostComposer` 的附件区、可见范围、置顶、草稿按钮（这些与正文编辑器解耦）。

#### 9.2 存储与兼容（关键设计）

- `forum_post` / `forum_comment` 各加一列 `content_format VARCHAR(8) DEFAULT 'TEXT'`（`TEXT` | `HTML`）。
  - 老数据一律 `TEXT`，渲染走现有纯文本 + `[[sticker:]]` 路径，**行为不变**；
  - 新帖写 `HTML`，渲染走消毒后 HTML 路径。
  - 用显式列而不是「正则猜 HTML」：标题/正文里出现 `<` 的纯文本不会被误判成标记。
- 迁移沿用 `main.py` 已有的 `ALTER TABLE` 探测段（幂等）。

#### 9.3 安全（必须先评审通过）

1. **写路径消毒**：`sanitize_rich_text()` 已在 `posts` 写入处被调用（需确认 forum 写路径覆盖），本次扩展白名单：
   - 只允许 `span/p/td/th` 上**受限 style**：`color`、`background-color`、`font-size`、`text-align`；
   - 值必须匹配白名单正则（颜色 `#rgb/#rrggbb/rgb()/rgba()`、字号 `12px–36px`、对齐 `left|center|right|justify`）；
   - 其余 style 与全部 `on*` 事件继续剥离；`javascript:`/`data:text/html` 继续移除。
2. **读路径**：`ForumContent` 对 `HTML` 内容使用 `v-html`，但**只在后端已消毒的前提下**；前端不加第二套解析。为防后端漏消毒，读路径再做一次轻量校验（含 `<script`/`on\w+=` 直接降级为纯文本）。
3. 图片：只允许 `http/https` 与站内相对路径；`data:` 一律拒。
4. 验收必须包含 XSS 用例：`<img src=x onerror=alert(1)>`、`<script>`、`javascript:` 链接、`style="position:fixed"` 全部被剥离。

#### 9.4 图三功能的取舍（需要你指认）

wangEditor 原生支持：段落/字体/字号/B/I/U/删除线/颜色/背景色/对齐/列表/引用/表情/表格/图片/链接/撤销重做。
**不原生支持**，需要额外工作或放弃：公式(TeX/π)、语音、音乐、视频、@用户。
