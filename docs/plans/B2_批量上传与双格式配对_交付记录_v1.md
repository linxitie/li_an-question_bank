- 一句话：新页的两个按钮不再是灰的——**一次可选 50 个文件，同名 docx+pdf 自动合成一条资料**，队列逐条显示进度/成功/重复/失败原因。

## 1. 做了什么

| 层 | 内容 |
|---|---|
| 后端 | 新端点 `POST /api/materials/admin/files/upload`（**一次一个文件**）：不带 `material_id` → 建一条未上架资料 + 原件 `primary`；带 `material_id` → 只挂 `attachment` |
| 后端 | 内容去重：同 `sha256` 且资料未删 → 直接返回 `duplicate=true` + 已存在资料 id（**不建行、不报错**，批量场景里"跳过"比"整批失败"有用） |
| 后端 | 三重校验：扩展名白名单（docx/doc/pdf/xlsx/xls）+ **magic bytes** + 单文件 20MB；`type` 白名单 article/lecture/paper；`_require_admin` |
| 编排 | `src/utils/batchUploadPlan.ts`（纯函数）：同名 base 的 **docx+pdf → 1 组**（docx 主文件、pdf 附件）、同 base 同扩展名重复只留第一个、数量 ≤50 / 总量 ≤2GB / 扩展名白名单校验、`summarize()` 汇总 |
| UI | `src/components/admin/MaterialBatchUpload.vue`：①选文件 ②入库参数（科目/类型/分类，本批统一）③导入队列（逐条状态 + 进度条 + 失败原因）+ 汇总 toast |
| 接线 | 新页「批量导入」→ 预置 **讲义**；「＋ 上传试卷」→ 预置 **试卷**；完成后自动刷新列表与统计 |

**为什么一次一个文件而不是一个 50 文件的大请求**：
· 能显示"第几条、百分之几"（大请求只能干等）；· 单条失败不影响其它，可只补传失败那条；
· 50 × 20MB = 1GB 的请求体在生产代理上极易超时。数量与总量由前端队列把关，服务端只守单文件上限。

正确命令：

```powershell
set OPENAPI_URL=http://127.0.0.1:8001/openapi.json
python backend\scripts\gates\gate_all.py
```
