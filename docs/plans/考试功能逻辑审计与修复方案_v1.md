## 0. 先回答你三个问题

### 0.1 你这场考试的"真实成绩"是什么？

库里的账是**对的**，页面显示的账是**错的**：

```
record #3（你 18:43:46 开始、18:46:05 交卷那一场）
  exam_answer_detail：97 行 → is_correct=1 共 2 行、is_correct=0 共 95 行
  exam_record：total_score=2.0 / 满分 97 · duration_used=139 秒 · answered_count=2 · is_scored=1
  Q301 你答 D（正确 D）→ 判对、得 1 分
  Q302 你答 C（正确 C）→ 判对、得 1 分
```

也就是说：**你真的答对了 2 题、得 2 分，其余 95 题空白按错计**。
页面上的「正确/错误 97 / 0」「两题都错误」是**前端渲染 bug**，不是成绩错。

### 0.2 正确答案上传了吗？

**传了，4 套卷都是 100% 覆盖**（实测）：

| 卷 | 题量 | 有答案 | 有解析 |
|---|---|---|---|
| #2 2019 北京 | 100 | **100** | 100 |
| #3 2017 江苏 | 100 | **100** | 100 |
| #4 2024 国考 | 100 | **100** | 100 |
| #5 2016 江西 | 97 | **97** | 97 |

### 0.3 以后怎么给一套卷传答案

```
管理端 → 资料管理 → 找到这套卷（类型=试卷）→ 行内「补答案」
  → 拖入答案 PDF / Excel（整套卷一份，不用按题拆）
  → 看四个数字：识别题数 / 题号覆盖 / 冲突 / 空
  → 逐题核对（可改）→「写入答案解析」
  → 只写 question_bank.answer 与 answer_analysis 两列，不动题干预其它字段
```

规则（已实现）：
- **已有答案默认保留**，勾 `overwrite` 才覆盖；
- 解析里推断出来的答案（`A 项正确` 这类）**只给建议**，不自动填；
- 题号覆盖不等于卷题数时**阻断**（防止把别的卷答案灌进来）。

## 2. 逐条证据与修法

### P0-1 弹窗「正确/错误」用错字段

**证据**：接口实测 `GET /api/exams/records/3` → `details` 里 `is_correct` 为真 2 条、假 95 条；弹窗显示 97 / 0。

**现状代码**：

```js
this.state.submitCorrect = data.data ? (data.data.scored_count || 0) : 0;   // 97（参与评分题数）
this.state.submitWrong   = this.totalQuestions - this.state.submitCorrect;  // 97 - 97 = 0
```

**修法**（后端给准数，前端别猜）：
- `POST /submit` 的 `data` 增：`correct_count`、`wrong_count`、`unanswered_count`、`question_total`（`answered_count` 已有）；
- 前端直接读这 4 个字段；`scored_count` 保留但只在"参与评分题数"语境用。

### P0-2 交卷后逐题状态恒为「错误」

**证据**：Q301（答 D、正解 D）、Q302（答 C、正解 C）都是 `is_correct=1`，页面却都显示「✗ 错误」。

**现状代码**：

```js
isCorrect(q) { return false; }   // 注释写着"考试模式下没有answer字段，无法判断"
```

**修法**：交卷成功后用**服务端结果**回填逐题状态。
- 方案 A（推荐）：`POST /submit` 的 `data` 里带 `details: [{question_id, student_answer, is_correct, correct_answer, score_obtained}]`；
- 方案 B：前端交卷后调 `GET /api/exams/records/{record_id}`（已存在，字段齐全），建 `map[question_id]`。
- 页面：`isCorrect(q)` 查 map；`isCorrectOption(q, idx)` 用 `detail.correct_answer`（多选按逗号包含判断）；
  未作答的题显示「未作答」而不是「错误」。

### P1-3 「正确率」口径混用 + 精度被四舍五入抹平（你 2026-11-11 追加确认）

**先把数学摆平**：

```
得分率 = 得分 / 满分 = 2 / 97 = 0.0206185567…
        · 写成比值（小数）：0.020619
        · 写成百分比：2.0619%  → 两位小数 2.06%，一位小数 2.1%，取整 2%
答对率（按已答）= 2 / 2 = 100%
答对率（按全卷）= 2 / 97 = 2.06%（本卷每题 1 分、满分=题数，所以它与得分率数值相同）
```

**现在三个地方三种精度，全都不等于真实值**：

| 位置 | 显示 | 实际算法 | 真实值 |
|---|---|---|---|
| 交卷弹窗 | `2%` | `Math.round(score/max*100)` 取整 | 2.06% |
| 结果页 | `2%` | `Math.round(correct/total*100)` 取整 | 2.06% |
| 成绩分析（`/api/exam-records/self`） | `2.1` | 后端 `round(...,1)` 一位小数 | 2.06% |

**结论**：你说的对 —— 2% 是被取整抹平的，得分率应该是 **2.06%**（比值 0.020619）。

**修法（B 方案 + 两位小数）**：
- 弹窗/结果页把数字拆开，并统一**两位小数**：
  `得分 2 / 97`、`得分率 2.06%`（旁边小字 `2 ÷ 97` 让口径自证）、
  `已答 2 / 97（答对 2 · 未答 95 按错计）`、`答对率（按已答）100%`；
- 后端 `accuracy` 也统一改成两位小数（`round(x, 2)`），三处同源；
- 三处（弹窗 / 结果页 / 成绩分析）**共用一份计算函数**，杜绝再各算各的；
- 标签不叫"正确率"，叫「得分率」；"正确率"只在明确写"按已答"时使用。

### P1-4 用时口径 + 计时器重置

**证据**：record #3 `duration_used=139`，弹窗 `00:00:45`；时间轴：记录 18:43:46 开始，页面显示剩 1:59:15（=已过 45 秒）→ 说明页面是中途重新进的，本地计时器从满时长重新开始。

**修法**：
- 交卷弹窗的用时**用服务端 `time_used`**（submit 回包已有）；
- 进页面先调 `GET /api/exams/records/{record_id}/resume`（手机端已在用），用它给的
  `remaining_seconds` 初始化计时器、用 `saved_answers` 回填选项；
- `totalDuration - timeLeft` 只作为兜底。

### P1-5 未答/已答不可见

弹窗与结果页都加一行：`已答 2 题 · 未答 95 题（未答按错计）`，数据来自 `answered_count` / `question_total`。

### P1-6 PC 续答落库（与手机统一）

- 自动保存：`localStorage` → 改成每 30 秒 + 切题时调 `PUT /api/exams/{record_id}/progress`（手机端已有同一接口）；
- localStorage 保留作离线兜底；
- 进页面优先服务端 resume，其次 localStorage。

### P2-7 ~ P2-11

| # | 修法 |
|---|---|
| 7 | `paper_result.vue` 去掉 `\|\| 100`，改为 `record.max_score ?? '—'`，缺字段就显示占位符而不是错数字 |
| 8 | 当 `is_scored=0` 或 `manual_pending_count>0` 时，弹窗/结果页显示「有 N 题待人工评分，当前分数不含它们」 |
| 9 | 自动交卷加 `submitting` 守卫（同一记录只提交一次；失败弹提示并停止重试） |
| 10 | 开考闸增加"答案覆盖率"判据（`answered = 0` 的卷不允许开考，或至少管理端列表标红"答案未补全"）。**这条会改变开考行为，需你单独点头** |
| 11 | `scored_count` 在回包里加注释/别名，前端不再使用；文档写清语义 |
