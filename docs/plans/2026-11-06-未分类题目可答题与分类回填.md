## 1. 需求理解

用户选择 P2 的 A 方案，并要求同时改两处：

1. **Obsidian**：补充未分类题目治理看板、回填口径、待人工分类清单。
2. **实际系统题库页面**：未分类题目必须能实际分类，或至少能进入答题并正常提交。

验收不是「页面不报错」，而是「未分类卡片点进去有题、能作答、能提交、能记进度」。

## 2. 现状实测（只读，已执行）

| 项 | 实测 |
|---|---|
| 可见题 | 3410 |
| `sub_category_id IS NULL` | 668（行测 341 / 申论 11 / 公专 316）|
| 可用旧字段或 qk 高置信回填 | 160（行测 149 / 申论 11 / 公专 0）|
| 回填后仍未分类 | 508（行测 192 / 公专 316）|
| 有子科目但 `point_id` 为空 | 758 |
| 子科目与知识点不匹配 | 4 |
| 有 qk 但 `sub_category_id` 为空 | 149 |

根因不是「没有题」，而是三条链路断开：

1. `GET /api/quick-practice/sub-categories` 返回合成「未分类」卡（id=0，total=668）。
2. 前端 `practiceBySubcard()` 用 `subcategory=未分类` 走旧接口 `/api/questions/exercise/questions`，该接口按名称查不到题，返回空。
3. `GET /api/quick-practice/questions?bySubCategory=true` 只处理正数子科目 ID；`0` 会被当成 `sub_category_id=0` 查询，必然 0 题。

补充：`point_id` 为空的 758 题其实已包含在所属子科目 `total_questions` 中，只要 fallback 按 **sub_category_id** 进入，就能作答；当前 fallback 按名称，故也答不了。

## 3. 技术方案

### 3.1 后端：让 0 号「未分类」成为合法练习范围

文件：`backend/app/api/v1/exam/quick_practice.py`

- `get_practice_questions()` 增加可选 `subjectId` 查询参数（1/2/3）。
- `bySubCategory=true` 且 `knowledge_point_ids=0` 时：
  - 查询条件改为 `QuestionBank.sub_category_id.is_(None)`；
  - 若传 `subjectId`，追加 `QuestionBank.subject_id == subjectId`；
  - 仍走 `QuestionStatsService.visible_query`，保持可见口径；
  - 仍按题干去重、`limit` 限制、随机排序。
- 正数 `sc_id` 行为不变，保证现有 343 端点契约不变。

### 3.2 前端 PC：fallback 按 ID 进入，而不是按名称

文件：`.vtj/vue/question_bank.vue`（raw 页，**只改 `<script>`，不改 template**）

- `practiceBySubcard(sub)` 改为：
  - 有 `sub.id`（含 0）时跳 `/exercise?subject=...&scId=...&subcategory=...`；
  - 没有 id 时才保留旧的名称路径。
- `startCustomPractice()` 已用 `scId`，不改。

文件：`src/views/student/shared/exercise.vue`

- `loadQuestions()` 的 `else if (scId)` 改为显式判断 `scId !== "" && scId != null`，让字符串 `"0"` 进入 `bySubCategory` 分支。
- 请求追加 `subjectId`（由 `subject` 的 xc/sl/ga 映射 1/2/3）。

### 3.3 前端手机：未分类子科目也能混合练习

文件：`.vtj/vue/mobile_practice.vue`

- `mixedPracticeCurrentSub()` 已传 `knowledge_point_ids: sc.id`；保留。
- `goAnswer` 追加 `subjectId`。

文件：`src/views/student/mobile/mobile_answer.vue`

- `fetchQuestions()` 在 `bySubCategory=true` 时把 `route.query.subjectId` 传给后端。
- 后端返回空时展示明确空态，不静默。

### 3.4 数据回填：只做高置信 160 题

新增脚本：`backend/scripts/backfill_unclassified_subcategory.py`

- 默认 dry-run；`--apply` 才写库。
- 目标：`status=1 AND sub_category_id IS NULL`。
- 映射优先级：
  1. 行测 `xingce_subcategory` 精确匹配 `sub_categories(subject_id=1,name)`；
  2. 申论 `shenlun_subcategory` 精确匹配；
  3. 公专 `gongzhuan_subcategory`（当前全为「无」，预期 0）；
  4. 已有 `question_knowledge` 且知识点有 `sub_category_id` 的，取该子科目。
- 只更新 `question_bank.sub_category_id`，**不改 point_id、不改题干、不改答案**。
- 备份：`sqlite3.backup()` 到 `backend/data/question_bank.db.bak_unclassified_<时间戳>`；禁止 `shutil.copy2`（R10）。
- 输出：回填 160、剩余 508、按科目分布、失败/歧义清单。
- 生成 `backend/data/audit/unclassified_questions_<日期>.csv`，供教研人工分类 508 题。
