# P2 · 手机端窄屏遮挡 · 复核报告 v1

> **状态**：📋 **复核完成，结论：不立项、不修**（2026-11-15）
> **起因**：我在 D6 交付时口头报过一条「手机端右侧有模板外壳（`XMask`）的悬浮操作条，会压住成绩卡」，并把它列进「下一步建议」的 P2。
> **结论**：**这条报错了**。26 个 `/mobile` 路由逐一实测：横向溢出 0、越界元素 0；原报的悬浮条在 DOM 里根本不存在，同一参数重放也复现不出来。**没有任何东西需要修**。
> **分支**：`feat/material-multi-format-import`（`main` 未动）；本报告**不含代码改动**，只归档证据与结论。

---

## 1. 我当初为什么会报这条

D6 做真机截图时，其中一张（`d6_shot_4.png`，展开逐题回顾那一次）右侧出现过三个小图标（剪刀 / 带「1」角标的放大镜 / 灯泡），位置压住成绩卡右上角。
我当时**只凭这一张截图**就推断是模板外壳 `App.vue` 里 `XMask` 的 `actions`（`message` 带 `badge: 1`，与角标「1」对得上），并写进了建议。

**当时的取证是有缺陷的**：我跑的两个 DOM 探针都因为截图脚本的参数坑（`-Out ""` 被 PowerShell 吞掉，参数整体左移，`deviceScaleFactor` 变成 13000、宽度变成 844）**测的其实不是一个正常视口**，输出是空的，我没有意识到，就把截图当结论了。

## 2. 这次怎么复核的（可复现）

| 步 | 做法 | 结果 |
|---|---|---|
| ① 干净加载 + 探针 | 每个路由新开无头 Edge（390×844@2，DPR 正常），等待 8s，量 `documentElement.scrollWidth - clientWidth` 与所有越界元素 | **26 条路由：溢出 0、越界元素 0** |
| ② 定点找悬浮条 | 在 `/mobile/home`、`/mobile/paper-result` 上取 3 个时间点快照（0.9s / 2.1s / 3.5s），并扫全站 `position: fixed/sticky` 元素 | 只有页面自己的顶栏（sticky）与底部 tab 栏（fixed）；**没有 action bar** |
| ③ 换宽度对照 | 同一页在 **1440×900** 再扫一遍 | `x-mask` 容器在、`x-mask` 里**没有任何 actions 节点**；`#vtjLink` 尺寸 0×0 |
| ④ 原样重放 | 用 D6 那张图的**完全相同参数**（seed → `mobile/paper-result?record_id=4` → 6s → 展开回顾 → 截图）重放 **2 次** | 两次都是 **290,082 B**，与干净版（`d6_shot_6.png`）**同尺寸**，图里没有任何图标 |
| ⑤ 顺带发现的越界 | `/mobile/recruit` 有 2 个分类 tab 越过可视宽度 | 复核 `.tabs`：`clientWidth 383 / scrollWidth 544 / maxScrollLeft 161` → **可横滑到底**，属于正常设计，非缺陷 |

## 4. 结论与建议

| 项 | 结论 |
|---|---|
| P2（窄屏隐藏 VTJ 悬浮条） | **不立项**：目标物不存在。原判断来自一张未取证的截图，**在此更正**，不留代码改动 |
| `/mobile/recruit` 分类条 | **不修**：可横滑；如果嫌桌面内核下滚动条难看，可做纯视觉微调（可选） |
| 残余风险 | 编辑器/开发服务器热更新期间仍可能出现瞬时残留（这正是那张图最可能的来源），但**不在产品缺陷范围**；若以后真复现，第一步先取 DOM 再下结论 |
