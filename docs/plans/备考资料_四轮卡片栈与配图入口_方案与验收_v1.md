# 备考资料 · 四轮：卡片配图入口与卡片栈 3D（方案与验收）

> 版本：v2（2026-11-02）｜分支 `feat/Study-Material-Management-r4`（父 `-r3@e9a3456`，`main` 未动）
> 范围：①「查看配图」入口从列表移到卡片上　②去掉翻页时的白色背景框与卡片白边，翻转做成真 3D
> ③翻页方向：下一页 → 当前卡向右飞走；上一页 → 上一张从右侧飞回来　④手机端 Excel 批量入口显性化

## 1. 需求与结论

| # | 你的原话 | 根因（实测） | 处理 |
|---|---|---|---|
| 1 | 手机端「查看上传图片」的按钮移到卡片上，别让人去下面列表里找 | 配图只能在列表行的「查看详情」里打开；卡片本身没有任何入口 | 卡片正面/背面底部新增「查看配图（N）」按钮（无图时显示「查看详情」），点开直接全屏看图 |
| 2 | 翻页时有一个白色背景框留在原地；去掉白框，去掉没翻页时的白边，翻页要更好的 3D | ①卡片栈是 **5 张完整白卡** 叠加（`lv1–lv4` 各自 `background:#fff` + `1px` 边框），顶层飞出时底层白卡原地不动 → 白框；②`perspective` 挂在 `.stack` 上，真正旋转的是孙级 `.card-inner`，透视没生效 → 翻转是「平的」 | ①背景改成 **3 片渐变纸片**（只露一条边，不画白卡），卡片去掉边框；②`perspective` 移到 `.stack-card`，背面加 `translateZ(1px)` 避免零厚度重影；③翻页动画期间纸片整体淡出 |
| 3 | 手机端「上一页」「下一页」翻动时卡片都向左飞；改成点「下一页」向右飞、点「上一页」从右边飞回来 | 上一页/下一页共用一个 `is-leaving`（`translateX(-118%)`，朝左），上一页没有独立动效 | 两个方向都定成「向右」：下一页 = 当前卡 `translateX(+118%) rotate(7deg)` 向右飞出；上一页 = 新卡 `sm-enter-right` 关键帧 `translateX(62%) → 0` 从右侧飞入 |
| 4 | 手机端 Excel 上传按钮在哪 | Excel 面板本身在（`#/materials/upload?tab=excel`），但入口只有一步之遥的弹层里没人会注意 | 弹层第一步「选择科目」底部加一条虚线按钮「一次要传很多张？用「Excel 批量导入」→」，点它直达 Excel 面板 |

## 2. 关键实现（v2 定稿）

第一版把背景换成「渐变纸片」，实测**仍有白框**：真正的白底来自 `.stack-card` 容器自身的
`background:#fff`（旋转的是它的子元素 `.card-inner`，容器原地不动 → 翻转时露出一整块白）。
第二版改成「后面放真卡片 + 容器透明」：

```
.stack
  .stack-card.behind ×3   真卡片（正面内容），只按 -9px/层 上移、6px/层 左右内缩
                          白色卡身被顶层卡完全盖住 → 没有白框；
                          翻转时顶层卡转开，就能看到后面卡片的正文
  .stack-card.lv0         唯一可交互卡：background: transparent（白色由 .card-face 提供）
    .card-inner           preserve-3d + perspective:900px（挂在 .stack-card 上）
      .card-face.front / .back（背面 rotateY(180deg) translateZ(1px)）
```

- 层级：`.stack-card { z-index:1 }`、后面卡 `8-i`、顶层卡 `z-index:10`（第一版曾因 `z-index` 相同导致后面的卡盖住顶层卡）。
- 卡片底部：`.card-foot` 改 flex，左「点击卡片翻转看要点」右 `.card-act` 按钮；
  按钮 `@click.stop` 不触发翻转，有图开全图、无图回退详情弹层。
- 翻页：`.is-leaving/.is-entering` 只动顶层卡，后面的真卡片保持不动 → 飞走时直接看到下一张的正文。
- **翻页方向（本轮改）**：`phase` 从 `idle | leaving | entering` 扩成 `idle | leaving | entering | entering-prev`，
  统一「向右」语义：

| 操作 | 状态 | 动效 |
|---|---|---|
| 下一页 | `leaving`（220ms）→ 换 `cardIndex` → `entering` | 旧卡 `translateX(118%) rotate(7deg)` 向右飞出；新卡 `sm-enter` 从 0.97 缩放落定 |
| 上一页 | 立刻 `cardIndex--` → `entering-prev`（280ms） | 新卡 `sm-enter-right`：`translateX(62%) rotate(-5deg)` → `translateX(0) rotate(0)`，从右侧飞入 |

  上一页之所以「先换内容再播动画」，是为了让飞进来的那张就是目标卡本身，
  而不是先飞一张再替换（那样会看到两次闪动）。
- **手机端 Excel 入口（本轮加）**：`CardCreateForm` 第一步底部 `.cc-batch-step`
  （虚线框 + 蓝色文字「一次要传很多张？用「Excel 批量导入」→」），点击 `goExcel()` →
  `#/materials/upload?tab=excel`；PC 三科资料页的 `.mat-entry` 条上另有 `Excel 批量导入` 链接。

## 3. 验收

`scripts/verify/mobile_card_stack_shots.mjs`（手机视口 390×844 + 真实登录态 + 触摸模拟）**20/20 断言通过**：

| 断言 | 实测值 |
|---|---|
| 栈顶是要看的那张卡 | 演示卡标题命中 |
| 后面叠着 3 张**真卡片**（带正文） | `申论对策题 三步成文（演示 …）` |
| 顶层卡容器透明（翻转不会露白底） | `rgba(0, 0, 0, 0)` |
| 后面卡片比顶层窄（白身被遮住，无白框） | behind=345 < top=357 px |
| 卡片无白边 | `border-top-width = 0px` |
| 卡片上有「查看配图」 | `查看配图（2）` |
| 翻转途中后面卡片文字可见 | 后卡标题非空且可见 |
| 翻转进入 3D | `matrix3d(...)` |
| 能翻回正面（不卡在背面） | `is-flipped = false` |
| 卡片按钮直接开全图 | `1 / 2` |
| 下一页：样式为向右飞出 | `translateX(118%) rotate(7deg)` |
| 下一页：离场时卡片向右移动（几何位移） | left `17px → 426px`，`Δ = 409px`，越过后面卡的 `23px` |
| 下一页：点击后进入离场动画 | `is-leaving` 全程在场、页面上只有 1 个 `.stack` |
| 翻页后切到下一张 | 序号 `1 / 33 → 2 / 33` |
| 上一页：上一张从右侧飞入 | `translateX = 222px`（=62% × 357px）、`is-entering-prev` 在场 |
| 上一页后回到上一张 | 序号 `2 / 33 → 1 / 33` |
| 手机端创建第一步就有 Excel 批量入口 | `一次要传很多张？用「Excel 批量导入」→` |
| 点入口直达 Excel 上传面板 | `#/materials/upload?tab=excel` |

> 说明：方向除读样式表外，还用**几何位移**复核（套上离场样式后量 `getBoundingClientRect().left`），
> 因为 Chrome 窗口被遮挡时浏览器不产帧、CSS 过渡不会插值，纯读 `transform` 会读到起始值（0px），
> 不能作为证据。上一页的 `62%` 来自关键帧 `fill: both` 的首帧，可稳定读到。

## 4. 顺带说明

- 列表行的「查看详情」保留（文章类资料没有卡片，仍需从列表进）；卡片类资料从此不用再往下翻。
- 无图卡片按钮文案自动变「查看详情」，行为与原来一致。
- 演示数据已清理：当前已公开 100 篇 = 97 卡片（含你自己建的 3 张：`1`、`2`、`老表`）+ 3 篇文章。

## 5. 已知不足

1. 翻转到 90° 附近仍能看到一点“卡片厚度”白边（背面 `translateZ(1px)` 造成），属双面卡片的正常投影，静止时不可见。
2. 纸片数量固定 3 片，不随剩余卡片数变化（纯装饰）。
3. 全图查看器仍未做拖拽平移/双指缩放。
4. 翻页动画是「旧卡飞走后瞬时换卡」，不是两张卡同屏滑动；若要连续滑动手感，得改成双卡叠放 + 位移同步，属下一轮。
5. 遮挡窗口下浏览器不产帧，动画过程无法截图留证；本轮的「飞走/飞入」以样式规则 + 几何位移 + 状态断言为准。
