## 0. 一句话方案

把「AI 讲师视频」做成**由讲稿脚本（DSL）驱动的网页交互播放器**：讲师形象、板书、场景、公式动画都是 SVG/CSS 动画，讲解到检查点自动暂停并在右侧弹出选择题，正误各有动画反馈；同一套播放器以后可以直接吃「题目/资料卡片」生成的脚本——这就是你要的**底座**。

本方案重点不在"先做多少视频"，而在**把契约（DSL）和播放器做对**，让内容可以源源不断地长出来。

## 2. 需求解读与边界

### 2.1 逐条对应设计

| 你的要求 | 设计里怎么落地 | 在哪一节 |
|---|---|---|
| ①先做预写知识点清单的样板 + 预留自动生成底座 | 内容来源抽象成 `LectureSource`（清单/题目/卡片三种输入最终都产出同一份 DSL）；播放器只认 DSL | §4、§10 |
| ②学真人讲解风格/逻辑/肢体动作 + 场景跳转 + 卡通&正式并存 | 「讲解逻辑模板」+「动作触发词库」+「场景库」+「画风规范」四件套 | §5、§6 |
| ③研究真人怎么拆分讲解并统一逻辑，但不要一模一样 | 微课 7 段式 + 分镜规则 + 节奏参数化（可换口吻/长度），不是复制某个老师 | §5 |
| ④检查点弹题（数量不限）+ 正误动画 | 播放器状态机内置 `checkpoint`，题目写在脚本里；反馈动画两套组件 | §7 |

### 2.2 明确不做（本期）

- ❌ 不做「上传试卷→全自动生成视频」的批量流水线（只留底座与单条生成接口）；
- ❌ 不做数字人/真人视频合成（无服务；P3 再议）；
- ❌ 不做语音（P2 接 TTS 后再开）；
- ❌ 不改 `.vtj` 页面模板（守 R3），入口用 DOM 注入或走新路由。

## 3. 总体架构

```text
┌─────────────────────── 内容生产层 ───────────────────────┐
│ 知识点清单（你给）  │  题目/资料卡片（以后）  │  手工脚本  │
│        └─────────── LectureSource 适配器 ───────────┘    │
│                          ↓（阶段2：LLM 生成 + 人工审核）   │
│                    lecture_script.json（DSL）             │
└──────────────────────────┬───────────────────────────────┘
                           │ 静态 JSON（P1）/ 接口（P2）
┌──────────────────────────▼───────────────────────────────┐
│                     播放器（前端）                         │
│  时间轴引擎 → 段调度 → 讲师层 / 板书层 / 字幕层 / 场景层    │
│                     → 检查点 → 题目面板 / 反馈动画          │
└──────────────────────────────────────────────────────────┘
```

**关键原则**：播放器**不认识**"知识点/题目/卡片"，只认识 DSL。这就是可扩展与可维护的根。

## 4. 内容模型：知识点清单 → 讲稿 DSL

### 4.1 知识点清单模板（你填这张表，我就能开工）

| 字段 | 必填 | 说明 | 示例 |
|---|---|---|---|
| `id` | ✅ | 唯一标识（英文/数字） | `xingce-binary-split` |
| `subject` | ✅ | 行测/申论/公专 | `xingce` |
| `title` | ✅ | 知识点名（板书大标题） | `二分法` |
| `one_liner` | ✅ | 一句话定义（讲师开场说这句） | `把一个事物，按一个维度分成两个部分` |
| `points[]` | ✅ | 3–6 个要点（每条 ≤ 40 字，配一条板书） | `① 找一个维度`… |
| `pitfalls[]` | ⬜ | 易错点（1–3 条，触发"严肃表情+强调"） | `维度不唯一时不能二分` |
| `scene` | ⬜ | 想要的场景跳转：`police`/`formula`/`board`/`none` | `formula` |
| `questions[]` | ⬜ | 检查点题目（题干/选项/答案/解析） | 见 4.2 |
| `duration_hint` | ⬜ | 目标时长（秒），默认 180 | `180` |
| `refs[]` | ⬜ | 引用资料卡/考点（内容可靠性追溯） | `study_material:12` |

### 4.2 题目格式（写进清单，数量不限）

```json
{
  "at": "after_point_2",         // 触发位置：after_point_N / segment_end / time:95
  "stem": "以下哪一种拆分属于二分法？",
  "options": [
    {"key": "A", "text": "电影：谍战片、动画片"},
    {"key": "B", "text": "输入法：五笔、9键"},
    {"key": "C", "text": "学生：本地生、外地生"}
  ],
  "answer": "C",
  "analysis": "电影还有喜剧片等；输入法还有26键等，都不止两类；学生只有本地/外地两类。",
  "wrong_hint": "继续努力"
}
```

### 4.3 讲稿 DSL（播放器的唯一输入）

```jsonc
{
  "schema": "lecture/1.0",
  "id": "xingce-binary-split",
  "meta": { "subject": "xingce", "title": "二分法", "total_sec": 180,
            "avatar": "female_teacher_01", "style": "cartoon-formal", "audio": null },
  "segments": [
    { "type": "intro",   "speech": "……", "board": ["二分法"], "avatar": {"gesture":"wave","expression":"smile"} },
    { "type": "concept", "speech": "……", "board": ["① 找一个维度","② 分成两部分"],
      "avatar": {"gesture":"point_board"}, "scene": {"kind":"board"} },
    { "type": "scene",   "scene": {"kind":"formula","props":["a/b","维度"],"anim":"draw"},
      "speech": "……", "duration": 20 },
    { "type": "checkpoint", "question": { "stem": "……", "options": [], "answer": "C", "analysis": "……" } },
    { "type": "summary", "speech": "……", "board": ["小结：一个维度 + 两部分"] }
  ]
}
```

**字段字典（节选，完整版落地时随代码提交）**

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `segments[].type` | enum | `intro/concept/demo/scene/checkpoint/summary` | 段类型决定渲染层组合 |
| `segments[].speech` | string | ≤ 400 字 | 字幕与（未来）TTS 文本 |
| `segments[].board[]` | string[] | ≤ 6 条，每条 ≤ 40 字 | 板书逐条出现 |
| `segments[].avatar.gesture` | enum | `idle/wave/point_board/point_scene/open_hands/count/think` | 动作库 |
| `segments[].avatar.expression` | enum | `neutral/smile/serious/surprise/encourage` | 表情库 |
| `segments[].scene.kind` | enum | `board/formula/police/custom` | 场景库 |
| `segments[].duration` | number | 5–60 秒 | 无语音时由脚本给定；有语音后由音频长度驱动 |
| `segments[].question` | object | 见 4.2 | 仅 `checkpoint` 段 |
| `meta.audio` | string\|null | URL | 有音频时填，播放器自动对齐时间轴 |

> **DSL 校验**：用 JSON Schema 校验（前端构建期 + 运行时各一次），坏脚本直接拒绝播放并降级为图文讲稿——这是内容可靠性的第一道闸。

## 5. 「学真人讲解」的方法论（要求 ②③）

### 5.1 我要如实说明的能力边界

我**无法直接观看视频**（没有视频理解能力）。所以分两条路：

1. **你给参考视频/字幕** → 我按时间轴拆「分句 → 镜头 → 动作 → 强调点 → 停顿」，产出该老师的节奏参数与动作触发词表（这是最贴你口味的方式）；
2. **不给素材** → 用成熟微课范式（下节）做基线，你再按观感逐条修订（我改模板参数，不逐帧调）。

### 5.2 讲解逻辑模板：微课 7 段式（可裁剪，不照抄任何一位老师）

| 段 | 时长占比 | 讲师在做什么 | 板书/场景 | 动作/表情 |
|---|---|---|---|---|
| 1 引入 | 10% | 抛问题/场景提问 | 标题 | 微笑、抬手 |
| 2 定义 | 15% | 一句话定义 | ≤ 20 字定义条 | 指向板书 |
| 3 拆解 | 30% | 逐条讲要点 | 要点 1..N 逐条出现 | 数数手势、开掌 |
| 4 例证/场景 | 20% | 跳到场景（执法/公式） | 场景动画 | 情境化表情（严肃/惊讶） |
| 5 易错 | 10% | 强调陷阱 | 红色标注 | 严肃、点头 |
| 6 检查点 | — | 暂停提问 | 右侧题目面板 | 鼓励表情 |
| 7 小结 | 10% | 复述 + 记忆钩子 | 汇总条 | 微笑、竖拇指 |

**给 AI 的「拆解规则」**（要求③的答案）：
- **一句一个 Action**：每句话只做 1 个主要动作/板书变化，避免"多线程"；
- **要点成组**：3–6 条要点一组，超过就再拆一集；
- **先具体后抽象**：例题/场景在前，定义在后；
- **每 60–90 秒给一次"锚点"**（重复关键词 / 板书高亮 / 提问）；
- **检查点放在"刚讲完"的位置**（不是随机），数量按知识点长度：≤3 分钟 1–2 题，3–6 分钟 2–4 题。

### 5.3 动作触发词库（讲稿里写语义标签，播放器映射到动作）

| 语义标签 | 触发词示例 | 动作 | 表情 |
|---|---|---|---|
| `point_board` | "看这里/注意这个/这条" | 右手前伸指向板书对应行 | neutral |
| `point_scene` | "假如你在现场…" | 侧身指场景 | 严肃 |
| `open_hands` | "我们先看/整体上" | 双手摊开轻摆 | smile |
| `count` | "第一…第二…" | 手指计数（1/2/3） | neutral |
| `think` | "想一想/为什么" | 手托下巴 | 疑惑 |
| `emphasis` | "一定/必须/千万" | 下压手势 + 板书放大 | 严肃 |
| `encourage` | "答得好/继续努力" | 竖拇指/点头 | 鼓励 |

## 6. 视觉体系（要求②的画风）

### 6.1 讲师形象：参数化骨架（等你给设定后定稿）

| 参数 | 默认草案（可改） | 说明 |
|---|---|---|
| 性别/年龄 | 女性 / 28–32 岁 | 亲和力优先 |
| 发型 | 深蓝短波波头 | 截图同款风格 |
| 服装 | 绿色圆形领口上衣 + 深色下装 | 正式但不呆板 |
| 配色 | 主色深靛 + 暖橙点缀，背景浅灰紫 | 与截图接近 |
| 脸型/五官 | 圆脸、简笔五官（可闭眼笑/严肃/惊讶） | 三套表情帧即可起步 |
| 姿态 | 半身、正面偏 15°，固定机位 | 动作只需上肢与头部微动 |

**实现方式**：单个 `TeacherAvatar.vue` + 若干 SVG `<g>` 图层（头/眼/眉/嘴/身/手臂），
动作 = 对若干图层做 CSS transform 关键帧；表情 = 切换眼/嘴/眉的 `<path>`。
**这样加动作/加表情不改组件结构**，只加映射表。

### 6.2 场景库（先做 3 类，画风统一）

| 场景 | 用途 | 元素 | 动效 |
|---|---|---|---|
| `board` 黑板/白板 | 定义、要点 | 板书条、粉笔线、高亮框 | 逐条出现、下划线动画 |
| `formula` 公式动画 | 行测计算/资料分析 | 公式块、数字滚动、箭头、对比条 | 逐项推导、错位高亮 |
| `police` 执法现场 | 公专法条/程序 | 警车、民警剪影、对话气泡、时间线 | 场景推入、关键节点闪光 |
| `custom` | 以后扩展 | 图片/简易动画 | — |

**画风约束**：统一圆角、统一描边粗细、统一 4 色主色板；场景允许比讲师更"扁平"，但**线宽与色板必须一致**（这是"卡通+正式并存"的落地办法）。

## 7. 交互规格（要求④，按你 3 张截图反推）

### 7.1 布局

| 端 | 布局 |
|---|---|
| 桌面（≥1024） | 左讲解区 2/3 + 右题目面板 1/3（截图就是这种） |
| 平板横屏 | 同上，题目面板变窄 320px |
| 手机竖屏 | 上下堆叠：视频上 60%，题目下方抽屉；答完再升起 |

### 7.2 播放器状态机

```text
idle → playing ──(到 checkpoint)──→ paused_dim ──(题目出现)──→ answering
                 ↑                                              │
                 │                              ┌──正确──→ feedback_correct ──(继续/1.2s后自动继续)──┐
                 │                              └──错误──→ feedback_wrong ──(看解析→播放/继续)────────┤
                 └───────────────────────────────────────────────────────────────────────────────┘
playing ──(播完)──→ ended ──(重播)──→ playing
```

### 7.3 各状态视觉

| 状态 | 讲解区 | 题目面板 | 动画 |
|---|---|---|---|
| `paused_dim` | 变暗/暂停 | 淡入题干+选项 | 面板从右滑入 200ms |
| `answering` | 保持变暗 | 选项可点（单选） | 选项 hover 轻微上浮 |
| `feedback_correct` | 保持变暗 | 选中项变绿 + 白字；下方「继续」 | 烟花粒子 800ms + 大对勾水印淡入 + 500ms |
| `feedback_wrong` | 保持变暗 | 选中项变橙红；下方出现「答案 C + 解析 + 播放按钮」 | "继续努力"字样弹入 + 抖动 200ms |
| `resume` | 恢复正常 | 面板滑出 | 遮罩淡出 200ms |

### 7.4 检查点规则

- 题目数量不限，**位置由脚本决定**（`after_point_N` / `segment_end` / `time:x`）；
- **答错不扣分、不阻断**：看完解析后"继续"即可恢复播放；
- 可选「答错重试」开关（脚本级，默认关）；
- 每题记录埋点（考点/选项/正误/耗时），为以后"讲稿优化"提供数据。

### 7.5 反馈动画规范

| 动画 | 实现 | 时长 | 降级 |
|---|---|---|---|
| 烟花粒子 | Canvas 20–30 个粒子（或 CSS 圆点），一次 1 屏 | 800ms | 低端设备关闭，仅保留对勾 |
| 大对勾水印 | SVG path 描边动画 + 淡入 | 500ms | 静态显示 |
| 答错提示 | 文案弹入 + 轻微抖动 | 300ms | 静态 |
| 面板滑入/出 | CSS transform | 200ms | 无动画 |

## 8. 前端实现设计

### 8.1 文件落位（新增，全部手写，不动 `.vtj` 模板）

```text
src/views/lecture/

  LectureStage.vue           # 左上：讲师/板书/场景舞台
  LectureQuizPanel.vue       # 右上：题目 + 选项 + 反馈
  components/
    TeacherAvatar.vue        # 参数化讲师（SVG 图层 + 动作/表情映射）
    BoardLayer.vue           # 板书逐条出现
    SubtitleLayer.vue        # 字幕（可关）
    SceneFormula.vue         # 公式动画场景
    ScenePolice.vue          # 执法现场场景
    FeedbackCorrect.vue      # 烟花 + 对勾
    FeedbackWrong.vue        # 提示 + 解析
  composables/
    useLectureTimeline.ts    # 时间轴引擎（rAF 驱动、段调度、检查点）
    useLectureQuiz.ts        # 答题状态与埋点
  lectureTypes.ts            # DSL 类型定义（与后端共享 schema）
  dslValidate.ts             # JSON Schema 校验（构建期 + 运行时）
  lectures/
    xingce-binary-split.json # 第一批脚本（静态 JSON）
```

**路由**：`/lecture/:id`（新页面 → 页面路由数 104 → 105，需同步 L6 与 `test_route_roles`）。
**入口**：资料详情页/首页加"AI 讲解"按钮——若放进 `.vtj` 页面，用 DOM 注入（R3），不改模板。

### 8.2 渲染与性能

| 关注点 | 做法 |
|---|---|
| 动画性能 | 只动 `transform/opacity`，避免 layout 抖动；SVG 节点 < 300 |
| 时间轴 | 单一 `requestAnimationFrame` 循环，段内用相对时间，切段不重建 DOM |
| 内存 | 场景组件用 `<KeepAlive>` 但要限数量；粒子用完即销毁 |
| 低端降级 | `prefers-reduced-motion` / 设备内存低 → 关粒子与过渡 |
| 首屏 | 静态 JSON 预加载 + 讲师 SVG 内联，首帧 < 1s |

### 8.3 三端适配

- ≥1024：左右分栏（截图布局）；
- 768–1023（平板横屏）：左 62% / 右 38%，选项最小高度 44px；
- <768（手机）：上下堆叠，字幕字号 ≥ 15px，选项整行可点。

## 9. 后端与数据设计

### 9.1 P1：先不写后端

脚本以静态 JSON 放 `src/views/lecture/lectures/`，前端直接 import —— **零后端改动**，最快见到效果。

### 9.2 P2：生成与存储（底座接线时才做）

| 表 | 关键字段 | 说明 |
|---|---|---|
| `lecture_script` | `id, source_type(list|question|material), source_ref, subject, title, dsl_json, version, status(draft|approved), review_status, reviewer_id, created_by, create_time` | 一份可播放脚本 |
| `lecture_job` | `id, script_id, kind(generate|tts|render), status(queued|running|done|failed), error, created_at` | 生成/配音任务 |

**端点（拟新增，届时按 R11 登记白名单）**
- `GET /api/lectures/{id}` —— 取脚本（学生可读，仅 approved）
- `POST /api/lectures/generate` —— 由知识点清单/题目/卡片生成草稿（教师/管理员）
- `POST /api/lectures/{id}/review` —— 审核通过/驳回
- `POST /api/lectures/{id}/tts` —— 生成音频（P2 之后）

### 9.3 字段完整性自检（写码前必答，对应全局规则 3）

- 后端模型字段是否覆盖 DSL 必需项？→ `dsl_json` 整存 + 常用查询列冗余（subject/title/status）；
- 路由注册是否遗漏？→ 新端点必须在 `main.py` include 且通过 `test_api_surface` 白名单；
- 前端能否显示修改？→ 静态 JSON 改动会随 Vite HMR 生效，无缓存坑（生产走构建版本号）；
- VTJ 版本是否一致？→ 本方案**不新增/不修改 `.vtj` 页面**，`vtj_version_sync --check` 保持通过。

## 10. 底座：如何从"清单"扩到"题目/卡片"

```ts
interface LectureSource {
  kind: 'list' | 'question' | 'material';
  load(id: string): Promise<KnowledgeSeed>;   // 统一成「种子」
}
// 生成器把 Seed → DSL；播放器不认识 Seed
```

- **现在**：手工/清单 → DSL；
- **以后（按题）**：题干+选项+解析 → Seed（考点=题目考点）→ LLM 生成 7 段式讲稿 → DSL → 同一播放器；
- **以后（按卡）**：卡片正反面+配图 → Seed → 同一路径。

**唯一新增的东西**是"生成器"，播放器、DSL、交互、动画全部复用——这就是"预留底座"的具体含义。

## 11. 安全与合规

| 风险 | 处置 |
|---|---|
| 讲稿/解析被注入 HTML | Vue 默认转义，**禁止 `v-html`**；DSL 校验时拒绝含 `<script` 的字段 |
| 讲师形象肖像/版权 | 纯 SVG 原创，不用真人照片；参考只学风格不复制 |
| LLM 生成内容错误（法条/公式） | `review_status` 必须 `approved` 才可播放；草稿标记明显 |
| 素材外链 | 场景素材走站内静态/媒体资产，禁止任意外链 |
| 埋点隐私 | 只记录匿名 id + 选项 + 正误，不记答题内容以外的个人信息 |
| 刷接口 | P2 端点加登录 + 频率限制（生成类限 教师/管理员） |

## 12. 运维与可观测

- **版本化**：`meta.version` + 脚本 hash，前端缓存命中可追踪；
- **灰度**：新脚本先在 `/lecture/:id?preview=1` 预览，再挂入口；
- **埋点**：`play / segment_enter / quiz_show / quiz_answer / quiz_correct / replay / drop`（用于找"讲不清的段"）；
- **降级**：DSL 校验失败 / 场景资源 404 → 自动退化为"图文讲稿"模式，不白屏；
- **回滚**：脚本是静态文件/数据库行，回滚即换版本号，无需发版。

## 16. 写码前的 7 问自检（全局规则 3 的落地，每次提交前逐条回答）

1. **为什么这样写**：播放器只依赖 DSL，不依赖内容来源 → 避免每加一类内容就改播放器；
2. **好处**：新增知识点/题目只写 JSON，不改代码；测试面收敛到"DSL + 状态机"；
3. **安全问题**：禁 `v-html`、DSL 输入校验、素材同源、生成接口鉴权限流（§11）；
4. **运维便利**：脚本版本化 + 预览参数 + 埋点，出问题换版本即可回滚（§12）；
5. **文件是否正确**：全部新增在 `src/views/lecture/`，**不动 `.vtj`**，VTJ 版本无需同步；
6. **前端能否显示效果**：静态 JSON + 手写页，Vite 直接渲染，无设计器依赖；
7. **后端字段/路由是否完整**：P1 零后端；P2 按 §9 建表 + 注册路由 + 白名单（R11）同步。
