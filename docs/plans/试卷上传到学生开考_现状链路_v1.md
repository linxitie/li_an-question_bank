# 试卷从「上传」到「学生开考」——现状链路实测（v1）

> **状态**：📋 现状说明（只读实测，**未改任何代码/数据**）
> **分支**：`feat/material-multi-format-import` ｜ 实测后端：`http://127.0.0.1:8001`（`revision e425451`）
> **实测时间**：2026-11-08 ｜ 探针脚本：`_run/p5_exam_probe.py`、`_run/p5_exam_probe2.py`（只发 GET/POST 读请求）
> **一句话结论**：**上传试卷 ≠ 学生能考**。上传只往「资料库」落一条资料 + 原件 + 编号，**不建可作答卷**；学生端考试的入场券是 `exam_paper.paper_type='PUBLISHED'`，而它与 `study_material.status` **目前没有任何联动**。

| # | 证据 | 说明 |
|---|---|---|

## 2. 现状机制全景（分 7 步，标出「谁在起作用」）

```
管理端上传试卷 ──▶ 资料库(study_material + material_file)  ← 学生端完全不读这里
                        │
                        └─ paper_code（如 GZ-2024-GK-T）
                                  ↕ 仅"编号相等"，没有外键、没有联动
题库里另建一张卷 ──▶ exam_paper(DRAFT) ──发布/审批──▶ PUBLISHED ──▶ 学生端列表/开考
                        └─ paper_question_relation（题、顺序、分值）
```

### 步骤 1：上传（管理端）

- 端点：`POST /api/materials/admin/files/upload`（`materials.py:1887` 起）
- 落库：`study_material(type='paper', status=0)` + `material_file(role='primary')`
- 顺带：C2a 从文件名解析编号 → 写 `badge` / `paper_code`（例：`GZ-2024-GK-T`）；讲义才抽 `doc_meta` 大纲
- **不落**：`exam_paper`、`paper_question_relation`、`question_bank`
- 结论：**这一步结束，学生端毫无变化**

### 步骤 2：上架（管理端，=审批通过）

- 端点：`PUT /api/materials/admin/{id}/status {status:1}`（`materials.py:2035`）
- 落库：`study_material.status = 1`
- **不落**：`exam_paper.paper_type`（**这就是 P5 缺口**）
- 结论：**上架只影响「资料库可见性」，不影响「能不能考」**

### 步骤 3：要变成"可考卷"，必须另有一条 `exam_paper`（6 条建卷链路，8 处 `ExamPaper(`）

| 链路 | 位置 | 建出来是什么态 | 谁能发布 |
|---|---|---|---|
| 教师端建卷 | `platform/teacher.py:776`、`:1243` | `DRAFT` | 教师直接发布（`teacher.py:1383`，仅 `past_paper`） |
| 管理员建卷 | `catalog/papers.py:88` | `DRAFT` | 提交审批 → `PENDING` → `admin_approval.py:245` 审批通过 = `PUBLISHED`；或 `papers.py:402` `APPROVED` → `papers.py:442` 发布 |
| AI 组卷 | `catalog/paper_generation.py:186`、`:354`、`:464` | `DRAFT` | `paper_generation.py:748` |
| **题目导入** | `catalog/question_import.py:3680` | `DRAFT`（题量 ≥5 自动建；同名复用；`ENDED` 复活为 `DRAFT`） | 仍需走上面的发布路径 |
| 标签组卷 | `catalog/tags.py:227` | `DRAFT` | 同上 |
| 小智私卷 | `exam/smart_exam.py:320` | 私有 `DRAFT`（学生看不到别人的） | 不发布 |

> **关键**：**没有一条链路是"从资料生成卷"**。唯一的桥是反方向的补录 `POST /api/materials/admin/papers/backfill`（`services/paper_backfill.py`）——它把**已发布的卷**补录成资料，并**故意置 `status=1`**，避免"学生能考但资料显示未上架"的矛盾。

### 步骤 4：卷还得真的有题

- `paper_question_relation`（`paper_id` + `question_id` + `question_order` + `question_score`）
- `GET /api/exams/{id}/questions`：关联为空 → **404「该试卷暂无题目」**（`exams.py:152-153`）
- 列表上的 `question_count` 是卷表上的冗余字段，**不一定等于真实关联题数**（建卷后再加/删题会不同步）

### 步骤 5：学生端列表（两条接口，主路径是 `/api/papers/list`）

| 接口 | 位置 | 学生可见条件 |
|---|---|---|
| **`GET /api/papers/list`**（`student_papers.vue` 在用） | `paper_generation.py:525` | `role_level<2` → 仅 `PUBLISHED`；教师看自己的 + 已发布；管理员全量 |
| `GET /api/exams/list`（旧接口，移动端/其它页可能用） | `exams.py:32` | 恒 `PUBLISHED` |

### 步骤 6：学生开考（两条开考接口，主路径是 `POST /api/exams/start`）

| 接口 | 位置 | 过滤 | 行为 |
|---|---|---|---|
| **`POST /api/exams/start?paper_id=&exam_type=SELF_TEST`**（学生页在用） | `exams.py:595` → `ExamService.start_exam`（`exam_service.py:46`） | `PUBLISHED` | 有未完成记录 → **续考**；否则建 `exam_record`（`exam_type='SELF_TEST'`）并返回题目（**不含答案**） |
| `POST /api/exams/{paper_id}/start` | `exams.py:230` | `PUBLISHED` | 同上（老版本，另有 `max_attempts` 次数校验） |

### 步骤 7：答题 → 交卷 → 成绩

```
开始考试(返回题目,不含答案) → /paper-answer 答题
   → PUT /api/exams/{exam_id}/progress   存进度（断点续答）
   → POST /api/exams/{exam_id}/submit    自动评分（客观题自动、主观题待批改）
   → GET  /api/exams/records             我的记录 / 成绩
   → 完成事件（成就·金币判据之一）
```

- 提交接口还有老版本 `POST /api/exams/{record_id}/submit`（`exams.py:302`），两套并存
- 历史记录、成绩、错题**不按 `paper_type` 过滤** → 卷下架**不影响**已有成绩（实测确认）

## 3. 三个断点（"上传了为什么学生看不到"的准确答案）

| # | 断点 | 表现 | 归属 |
|---|---|---|---|
| **A** | **上传 → 卷**：没有任何自动通道 | 上传 #127 后学生端永远看不到（实测 `/api/papers/list` total=2） | P2 题目线（题目导入自动建卷）/ 教师建卷 |
| **B** | **上架 → 可考**：不联动 `paper_type` | 下架 #125，学生照样能考 #2（因为它还是 `PUBLISHED`） | **P5**（本文档同目录的《P5_上下架联动_方案对比_v1.md》） |
| **C** | **卷 → 资料**：只有反方向可用 | 3 条试卷资料 = 2 条补录（#125/#126）+ 1 条上传（#127，无卷） | 已结（C4 补录） |

## 4. 顺带发现的一个真缺陷（已实测）

**`GET /api/exams/preview/{paper_id}` 漏判 `paper_type`**

- 路由：`exams.py:651` → `ExamService.get_exam_preview`（`exam_service.py:460-464`）
- 代码：`paper = db.query(ExamPaper).filter(ExamPaper.paper_id == paper_id).first()` —— **没有 `paper_type` 条件**
- 实测（学生 token）：
  - `GET /api/exams/preview/1`（#1 = `ENDED` 回收站）→ **HTTP 200**，`{"paper_name":"1"}`，`questions=0`（这张卷恰好没题）
  - `GET /api/exams/preview/2`（`PUBLISHED`）→ 200，`questions=100`，字段含 `question_content`/`options`，**不含** `answer`/`answer_analysis`
- 风险：任何「草稿/回收站**但已配题**」的卷，学生可直接读到**题干与选项**（不泄露答案与解析，但仍属未发布内容外泄）
- 对照：另一个同名预览口 `GET /api/papers/{id}/preview`（`catalog/papers.py:229`）**是有守卫的**（`role_level<2` 且非 `PUBLISHED` → 404）
- 处置：**✅ 已修（2026-11-08，独立小补丁，用户选 D8=单开补丁）**
  - `ExamService.get_exam_preview(db, paper_id, *, allow_unpublished=False)`：默认只认 `PUBLISHED`，失败消息改为「试卷不存在或未发布」
  - `exams.py:651` 与 `papers.py:217` 两个预览口按 `current_user.role_level >= 2` 放行内部预览（与 `papers.py:229` 原守卫口径一致：实测 `sys_user` 里 student=0 / teacher=1 / admin=3）
  - 新增 `backend/tests/test_exam_preview_visibility.py`（6 例：学生 PUBLISHED 200 / DRAFT 404 / ENDED 404 / 教师 level=1 同口径 404 / 管理员 200 / 不存在 404）
  - **线上实测**（后端重启后，`_run/p5_r8_verify.py`）：学生 `preview/1`(ENDED) **404**（修复前 200）、`preview/2`(PUBLISHED) **200** 带 100 题、管理员 `preview/1` **200**（内部预览保留）
