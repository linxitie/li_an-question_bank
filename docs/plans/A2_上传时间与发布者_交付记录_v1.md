## 2. 接口契约

```http
GET /api/materials/admin/list?created_within=7d&order=created_asc&publisher_id=3&page=1&page_size=20
Authorization: Bearer <admin>
```

| 参数 | 取值 | 说明 |
|---|---|---|
| `created_within` | `7d` / `30d` / 省略 | **滚动窗口** `create_time >= now - N 天`（不是"本周一"）；非法值 422 |
| `order` | `created_desc`（默认）/ `created_asc` | 按入库时间；`create_time` 为空的行**恒定排最后** |
| `publisher_id` | int | 只看某个发布者 |

响应 item 新增两字段（其余不变）：

```json
{
  "id": 122,
  "created_at": "2026-11-06T08:41:37+08:00",
  "publisher": { "id": 2, "name": "cbrycc", "role": "admin", "role_label": "管理员" }
}
```

- `created_at`：库里是 naive 本地时间 → 对外补 `+08:00`，前端不用猜时区；空值返回 `null`（前端显示 `—`）。
- `publisher`：`nickname` 优先、空则回退 `username`（与论坛同一规则）；`creator_id` 为空时返回 `null`。

## 6.5 统计口径修正（2026-11-07，你的裁定 A）

**你发现的问题**：统计行「已上架 103 + 未上架 11 = 114」≠「总资料 119」，差 5。

**根因（既有实现，非本批引入）**：`GET /api/materials/admin/stats` 里
`total = count(*)` 把**软删除（status=-1）也算进总数**，而 `by_status` 只取 1 / 0 两档 → 两边口径不同；
`by_type`（卡片 116）同样含着 5 条已删除；`admin_list` 不传 status 时也**不过滤 -1**，所以删掉的资料仍出现在列表里。

**修正（统一为"不含已删除"）**：

| 处 | 改法 |
|---|---|
| `admin_stats` | `total` / `by_type` / `by_subject` / `by_status` 全部加 `.filter(status >= 0)`；新增 `by_status.personal`（学生个人库 status=2，单列不混进"未上架"）与 `by_status.deleted`（已删除数，仅追溯用、不进 total） |
| `admin_list` | 不传 `status` 时默认 `.filter(status >= 0)`；**显式 `status=-1` 仍可查已删除**（留回收站口子） |

**修正后实测（真库）**：

```text
total = 114
by_type 合计 = 114   （article 3 · card 111 · lecture 0 · paper 0 · 视频 0）
by_status = published 103 / draft 11 / personal 0 / deleted 5
published + draft = 114  ✅ 与 total 相等
list total = 114      ✅ 与 stats total 相等
list?status=-1 total = 5  ✅ 已删除仍可显式查询
```

**回归**：`pytest tests/test_materials_stats_scope.py` **9 passed**（新增）；
同批回归 `admin / admin_search / a2_meta / a3_preview / my / my_card / share` **77 passed**。
截图：`docs/plans/assets/资料管理v3/06b_统计行5格_口径修正后.png`。

> 那 5 条已删除的是行测卡片（ID 16/20/25/46/47，10-28、10-29 删除）。现在它们**不出现在列表与统计**，
