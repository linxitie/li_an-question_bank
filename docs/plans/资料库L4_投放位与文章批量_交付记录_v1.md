## 2. 关键实现说明

### 2.1 为什么文章不能复用「批量导入」那条链路

`POST /admin/files/upload` 只做「原件留档 + 建未上架资料」，**不解析正文**；文章详情页读的是 `content`，走留档路径学生点开就是空白（讲义今天正是这个状态）。
所以文章批量走**解析导入**：`import/upload`（解析出 html）→ 轮询 `status` → `import/{id}/confirm {type:'article'}`（把 html 落成 `content`）。

**实测证据**（真实 HTTP，脚本 `_run/probe_l4_article_chain.py`）：

```
① POST import/upload（公专高频考点速记.docx） → 200 {import_id:27, parse_status:'success'}
② GET  import/27/status                       → success
③ POST import/27/confirm {type:'article'}     → 200 {created:1, material_ids:[128], published:false}
④ 库内校验 → (128, '_L4探针_高频考点速记', 'article', status=0, placement=NULL→library, content 长度=162)
⑤ 同文件再传 → 409「该文件已于 … 导入过（记录 #27），已拒绝重复上传」
⑥ 清理 → 资料回 122 行；导入记录 17 条
```

### 2.2 投放位在两处 UI 的一致性

- 上传弹窗：`MATERIAL_PLACEMENTS` 三选一（默认 `both`）；
- 列表徽标：`placementLabel` 短文案（考试/资料/都投）；
- 改信息弹窗：同一数组渲染，回填用 `normalizePlacement`。
三处共用一份常量与一个归一化函数，避免"考试页/仅考试/只考试"混用。

## 4. 已知边界

| # | 事项 | 说明 |
|---|---|---|
| 1 | 文章入库仍是「未上架」 | 与全站口径一致（上架=审批）；上传完需到列表点「上架」 |
| 2 | 扫描版 PDF 依赖 OCR（mineru） | 未就绪会明确失败，UI 提示转 Word |
| 3 | 批量文章不支持 xlsx 词库 | xlsx 是卡片链路（老页智能导入），文章只接受 docx/pdf |
| 4 | 投放位只在试卷上可改 | 后端对非试卷传 placement 会 400，前端也不显示 |
| 5 | 文章标题默认取文件名 | 入库后可在「改信息」里改 |
