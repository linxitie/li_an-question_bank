## 3. 数据设计（Q1）

### 3.1 sidecar：`<draft_dir>/qno_gaps.json`

```jsonc
{
  "v": 1,                    // schema 版本；将来加字段只升 v，不改库
  "dpi": 200,                // y0/y1/x0/x1 的坐标基准（与 _layout_lines 一致）
  "page_count": 41,
  "gaps": [
    { "no": 46, "page": 16, "y0": 1058.0, "y1": 1102.0, "x0": 0.0, "x1": 1424.0,
      "prev_no": 45, "next_no": 48 }
  ]
}
```

- **只写"最终仍缺"的题号**：补回收之后再算一次，已补回的（47/87）不出现；
- `x0/x1` 取该页正文列最大宽度（与 `find_number_holes` 一致），前端只用来画框，不做裁切；
- 写盘失败只 `logger.warning`，**不影响导题**（草稿照常 pending）；
- 无缺口 → **不生成文件**（与现在完全一致，便于对比排查）。

### 3.2 坐标系与换算（写死，否则框会歪）

| 层 | 单位 | 换算 |
|---|---|---|
| sidecar | 200dpi 像素（`layout_dpi`）| — |
| 后端渲染 | 150dpi 像素（`get_pixmap(dpi=150)`）| `px150 = px200 × 150/200` |
| 回给前端 | **0–1 相对坐标** | `x/width_150`、`y/height_150` |
| 前端 | CSS 百分比 | 容器宽高比 = 图宽高比，缩放不错位 |

> 为什么回相对坐标：弹窗宽度随屏幕变，百分比天然随图缩放，前端也不用再碰 DPI。

### 3.3 生命周期

| 时点 | 行为 |
|---|---|
| 导题成功（`fill_draft` 末段）| 覆盖写 `qno_gaps.json` |
| 重新导题 | `create_draft` 把旧草稿置 `discarded`，新草稿新目录 → 天然隔离 |
| 放弃草稿 | 目录保留（现状如此），sidecar 留着无害 |
| 旧草稿（本项上线前）| 无文件 → 端点 404 → 前端置灰（Q4）|

## 4. 接口设计（Q2）

### 4.1 契约

```
GET /api/materials/admin/parse-drafts/{draft_id}/page-image?no=46&dpi=150
权限：管理员（_require_admin）
```

| 参数 | 必填 | 约束 |
|---|---|---|
| `draft_id` | 是 | 路径参数，int |
| `no` | 是 | 1–999；必须在该草稿的 `gaps` 里 |
| `dpi` | 否 | 96–200，默认 150；越界 422（FastAPI Query 校验）|

成功 `200`：

```jsonc
{
  "ok": true,
  "no": 46, "page": 16, "page_count": 41, "dpi": 150,
  "image_w": 1240, "image_h": 1754,
  "image_b64": "iVBORw0KGgo…",                                  // PNG，无前缀
  "highlight": { "x0": 0.0, "y0": 0.604, "x1": 0.861, "y1": 0.629 },  // 0–1 相对
  "file_name": "2025多省联考公安《公安专业》.pdf",
  "hint": "第 46 题 · 表格区那一行的题号没被识别"
}
```

错误码（**前端逐条给不同文案**）：

| HTTP | code | 触发 | 前端文案 |
|---|---|---|---|
| 403 | `FORBIDDEN` | 非管理员 | 「当前账号无权限」|
| 404 | `DRAFT_NOT_FOUND` | 草稿不存在 | 「草稿不在了，刷新列表」|
| 404 | `FILE_MISSING` | 原件被删/路径非法 | 「原件已不在，无法渲染原页」|
| 404 | `GAP_NOT_FOUND` | 题号不在 gaps（含旧草稿无 sidecar）| 「这份草稿没有该题的定位信息（旧草稿需重新导题）」|
| 409 | `NOT_PDF` | `source_ext != pdf` | 「docx 没有"页"，无法定位原页」|
| 500 | `RENDER_FAILED` | PyMuPDF 打开/渲染异常 | 「原页渲染失败：<原因>」|

### 4.2 为什么这样设计（5 个备选对比）

| 备选 | 问题 | 结论 |
|---|---|---|
| A. 端点回 PNG 流，`<img src>` 直接用 | `<img>` 发不了 `Authorization`；改 `?token=` 会把令牌写进 URL/日志/Referer | ❌ |
| B. 端点回 JSON + base64（**本方案**）| 一页比流式多 ~33% 体积 | ✅ 局域网无感、安全、简单、一次往返 |
| C. 前端 pdf.js 自己渲染 | 57MB 下载 + 新依赖 + 41 页渲染 | ❌ 重、慢、引入新包 |
| D. 解析时把每页缩略图存草稿目录 | 41 页 ×~200KB ≈8MB/草稿，磁盘不可控 | ❌ |
| E. 只给页码文字提示 | 管理员仍要自己翻到第 16 页 | ❌ 没解决核心痛点 |

### 4.3 安全清单（逐条落实）

| 风险 | 处理 |
|---|---|
| 任意文件读取 | 只用 `draft.material_id → primary file → resolve_abs_path()`；**不接受任何前端传路径** |
| 路径穿越 | `resolve_abs_path()` 已把越界/绝对路径当不存在（`FileNotFoundError`）|
| 越权 | `_require_admin`；只按 `draft_id` 取 |
| 令牌泄露 | 不用 `?token=`；前端 `apiFetch` 带 header 取 JSON |
| 资源放大 | `dpi` 限 96–200；单页单次；不做批量接口 |
| 文件损坏 | 渲染异常 → 500 + 原因，不抛栈；只读渲染，不写回原文件 |
| 并发 | 每次现渲染、无磁盘缓存；多管理员同时点最多几页 —— **未做限流，如实标注** |

## 5. 前端设计（Q3 / Q4）

### 5.1 交互状态机

```
idle ──点 chip(有 gaps)──▶ loading ──200──▶ success(图+红框+上一题/下一题)
                              ├─404/409/500─▶ error(按 code 文案)
                              └─超时(8s)───▶ error(「渲染超时，重试」)

idle ──点 chip(旧草稿)──▶ cold(置灰提示「重新导题后可用」，不发请求)
```

### 5.2 文件落点（每处写清为什么放这）

| 文件 | 改动 | 为什么放这 |
|---|---|---|
| `backend/app/services/paper_ingest/readers.py` | `read_pdf_ocr()` 追加 `meta["qno_gaps"]` | 缺口坐标只有这层有（要 rows+starts），且它已在做页过滤/题号自洽 |
| `backend/app/services/paper_ingest/service.py` | `fill_draft()` 写 sidecar | 草稿目录与草稿生命周期的唯一责任人；写盘失败不能影响入库判定 |
| `backend/app/api/v1/library/materials.py` | 新端点（放在 `…/items` 之后）| 同一前缀族、同一鉴权风格；**静态后缀不会与动态 `{draft_id}` 冲突** |
| `src/modules/library/api.ts` | `fetchDraftPageImage(draftId, no)` | 与 11 个既有导题函数同模块，鉴权/错误封装复用 |
| `src/utils/qnoMissing.ts` | `parseMissingQnos(warning)` 纯函数 | 纯逻辑可单测、不依赖组件（与 `batchMeta.ts` 同风格）|
| `src/components/admin/ParseDraftDrawer.vue` | 告警区渲染 chips + 弹窗 | 抽屉是唯一展示体检的地方；**不碰 `.vtj/`** |

**VTJ 版本一致性**：本项只改手写组件与工具函数，**不新增 `.vtj` 页面、不改 `.vtj` 模板**；`@vtj/web` 仍锁 0.16.35，L6 会校验 8/8 版本锁定 → **不存在 VTJ 版本漂移**。

### 5.3 高亮框数学（前端）

```html
<div class="qd-imgwrap">                       <!-- position:relative；宽高比 = image_w/image_h -->
  <img :src="dataUrl" style="width:100%;display:block">
  <span class="qd-hl" :style="{ left: hl.x0*100+'%', top: hl.y0*100+'%',
                                width:(hl.x1-hl.x0)*100+'%', height:(hl.y1-hl.y0)*100+'%' }"/>
</div>
```

- 不用 `object-fit:cover`（会裁边）；用 `contain` + 容器宽高比锁定，百分比才准；
- 红框 2px 描边 + `rgba(198,40,40,.12)` 半透明底，深色扫描件上也看得见；
- 弹窗最大高 `80vh`，长页可纵向滚动，不把按钮顶出屏幕。

### 5.4 降级与文案（Q4，逐场景）

| 场景 | chips | 点击行为 | 文案 |
|---|---|---|---|
| 有 gaps | 正常（蓝底）| 请求 → 弹窗 | — |
| 旧草稿（无 sidecar）| 灰色 | **不发请求** | 「这份草稿生成于旧版本，没有定位信息；重新导题后可用」|
| docx 草稿 | 不渲染 | — | 原告警文本照旧 |
| 原件已删 | 正常 | 404 → 错误态 | 「原件已不在，无法渲染原页」|
| 渲染失败 | 正常 | 500 → 错误态 | 「原页渲染失败：<detail>」|

### 5.5 可访问性 / 操作细节

- chips 用 `<button>`（Tab 可聚焦、Enter 触发），`aria-label="查看第 46 题在原卷的位置"`；
- 弹窗 `Esc` 关闭，`←/→` 切上一题/下一题；打开后焦点移到弹窗标题；
- 同一题号 loading 中重复点击忽略（请求去重）。

## 8. 运维与可观测

| 项 | 做法 |
|---|---|
| 日志 | 成功 `INFO draft=%s no=%s page=%s ms=%s`；失败 `WARNING` 带 code（不记 base64）|
| 磁盘 | 每个有缺口的草稿 ≈1–2KB，可忽略 |
