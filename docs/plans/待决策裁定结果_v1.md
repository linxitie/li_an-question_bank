## 3. 修订 1 · D32：试卷元数据「只读文件名 + 入库后编辑」

### 3.1 四个必读字段 & 缺项处理

| 字段 | 中文 | 从文件名取？ | 取不到时 |
|---|---|---|---|
| `subject` | 科目（行测/申论/公专） | ✅ 目录名优先，其次 `《行测》《申论》《公安…》` | **留空**，列表显示 `—` |
| `year` | 年份 | ✅ `20\d{2}年` | **留空** |
| `region` | 地区（省份/直辖市/国考/联考） | ✅ 省份词表 + 常见市归省 + 国考/联考兜底 | **留空** |
| `kind` | 题本 / 答案解析 | ✅ 含「答案/解析」→ 答案；含「题本/真题/试卷/考试/题」→ 题本 | **留空**（默认按"题本"导入，可改） |
| `variant` | 卷别（副省级/地市级/乡镇卷/A 类…） | ✅ 取最后一个有效括号 | 留空（正常） |
| `count` | 题量 | ❌ **文件名里 0% 有** | 留空 → 手工填或 P2 拆题回填 |
| `score` | 满分 | ❌ 同上 | 留空 |

> **不再有"必填校验"**：四要素全空也能入库，只是列表里显示 `—`、筛选命中不到。这是你定的取舍（宁可先收进来，再补）。

### 3.2 解析规则（用真实 517 份文件名校准过）

- 词表：34 个省级行政区 + 30 个常见市（市归到省，`深圳`/`广州` 例外——单独组织考试，地区码 `SZN`/`GZH`）；国考=`全国`；多省联考=`多省`；公安院校联考=`公安院校`。
- 卷别括号排除表：`（部分）（完整版）（打印版）（含解析）（两套答案）（精选题）（市、区）（专业科目）（网友回忆版）` 不算卷别。
- 科目优先取 `《…》` 内的词（能纠正目录归错的情形：`公安题目（打印）` 目录下有一份 `《行政职业能力测验》`，实际是行测）。

**实测命中率**（`python scripts/probe_paper_filenames.py`，n=517）：

| 字段 | 命中 | 覆盖率 |
|---|---|---|
| 科目 subject | 517/517 | **100.0 %** |
| 年份 year | 517/517 | **100.0 %** |
| 地区 region | 514/517 | **99.4 %** |
| 考试类型 exam_type | 495/517 | 95.7 % |
| 题本/答案 kind | 516/517 | **99.8 %** |
| **四要素齐（可生成 paper_code）** | **513/517** | **99.2 %** |
| 题量 count | 0/517 | **0 %**（文件名里根本没有） |
| 满分 score | 0/517 | **0 %** |

- 题本/答案**成对**：246 / 264 组（93.2 %）；不成对的 18 组多为"部分""精选题""仅答案"。
- 仅 **4 份**没解析齐，全是命名特例：`2022年公安院校人民警察招录考试试题`（无省）、`…解析`（同）、`2025多省联考公安《公安专业》`（无"题"字）、`2022年7月10号公务员公安专业真题解析`（无省）→ 正是"先空着、以后改"的典型样本。

### 3.3 `paper_code` 生成（D24 人读码）

```
{科目}-{年份}-{地区}-{题本/答案}[-{卷别}]
XC=行测 SL=申论 GZ=公专   T=题本 A=答案
例（取自真实文件名的解析结果）：
  2023年国家公务员录用考试《行测》题（副省级网友回忆版）题本 → XC-2023-GK-T-FS
  2024年江苏省公务员录用考试《行测》题（A类）（网友回忆版）题本 → XC-2024-JS-T-A
  2024年广东省公考《申论》题（县镇）                      → SL-2024-GD-T-XZ
  2023年公务员多省联考《申论》题（吉林丙卷）                  → SL-2023-JL-T-C
  2019年深圳市公务员考试《司法素质测试》真题                 → GZ-2019-SZN-T
  2021年北京市…《行测》题（区级及以上卷）（网友回忆版）题本        → XC-2021-BJ-T-QQ
```
- 卷别短码表：副省级/省级=FS、地市级=DS、县乡=XX、县镇/乡镇=XZ、县级=XJ、市级/省市=SJ/SS、省直=SZ、旗县=QX、盟市=MS、区级及以上=QQ、行政执法=ZF、选调=XD、公安=GA、通用=TY、甲乙丙=A/B/C；词表外退回 `md5(卷别)[:2]`（确定性，不随入库顺序变）。
- 实测：517 份只生成出 **11 个重复 code**（最大 3 份），已抽查——多数是**同一份卷的重复件**（如 2023 国考申论副省级两份）或同一天多场联考；重复时按文件名排序追加 `-02/-03`，并在导入预览里标「疑似重复」。
- 幂等：`paper_code` 相同视为同一试卷，**不新建第二条**（除非标题/内容哈希都不同）。

| 项 | 规定 |

### 3.6 边界与失败

- 文件名解析**失败不影响导入**（这是本轮的核心取舍）；
- 同一批里 `paper_code` 重复 → 标黄「疑似重复」，默认仍导入，可在预览里取消勾选；
- 改信息把年份改成非法值 → 前端拦；后端二次校验；仍非法 → 422，**不写库**；
- 改信息把科目改成另一科 → `paper_code` 重建、`exam_paper` 迁移到新科目下，并记审计。

## 4. 修订 2 · D25：元数据表形态跟随 D32

- **原方案**：上传模板 3（7 列）→ 生成空试卷 → 再挂文件。
- **现方案**：**文件名是第一来源**；模板 3 保留为「批量补录」入口（可选）：
  - 场景：一次要给 50 份试卷补题量/满分时，用 Excel 一次刷，比逐个点弹窗快；
  - 列名与弹窗字段一致；`paper_code` 为键，**存在则更新、不存在则新建**；
  - **仍然不校验必填**（空值不覆盖已有值：只更新非空单元格）。
- 因此模板 3 不再是"上传前必须先做的表"，而是"事后批量订正的工具"。

## 5. 修订 3 · D38：筛选栏加「最近 7/30 天」

| 项 | 规定 |
|---|---|
| 位置 | 现有筛选行内、`地区` 之后、搜索框之前：`[时间范围 ▾]`（全部时间 / 最近 7 天 / 最近 30 天） |
| 参数 | `GET /api/materials?created_within=7d\|30d`（省略=全部） |
| 定义 | 滚动窗口：`create_time >= now - 7d`（不是"本周一"）；时区 Asia/Shanghai |
| 与排序 | 与 `order=created_desc` 叠加，互不冲突 |
| 与发布者 | 可叠加：`发布者=某教师 + 最近 7 天` → "他这周发了什么" |
| 空值 | `create_time IS NULL` 的旧行在选了时间范围后**不出现**（符合直觉） |
| 计数提示 | 选中后在筛选行右侧显示 `最近 7 天：12 条`（来自列表接口 `total`，不额外请求） |
| 三端 | PC/平板同一行；手机上收进「筛选」抽屉，默认折叠 |
