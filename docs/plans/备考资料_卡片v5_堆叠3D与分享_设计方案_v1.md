## 一、视觉：堆叠 + 3D 悬浮/视差

### 1.1 已定口径（效果图 v5_1 即按此绘制）

| 层 | 位置 | 缩放 | 投影 |
|---|---|---|---|
| 1（主卡） | 基准 | 1.000 | `0 6px 18px rgba(26,42,74,.10)` |
| 2 | 上移 15px · 右移 11px | 0.988 | −20% |
| 3 | 上移 30px · 右移 22px | 0.976 | −35% |
| 4 | 上移 45px · 右移 33px | 0.964 | −50% |
| 5 | 上移 60px · 右移 44px | 0.952 | −65% |

> 关键修正（本轮的坑）：**不能同时"缩小 + 下移"**——那会让后层顶部沉到主卡内部，被完全遮住（v4 就犯了这个错）。后层必须**上移 + 右移、几乎不缩放**，才能形成"一叠纸"的厚度。

### 1.2 3D 悬浮 / 视差（效果图 v5_2）

```css
.card-stack { perspective: 1200px; transform-style: preserve-3d; }
.card-1     { transform: rotateX(var(--tx)) rotateY(var(--ty)) translateZ(12px); }
.card-2..5  { /* 各自 translateZ(-20px * n) + 层间视差系数 */ }
```

- **悬停倾斜**：`pointermove` 写入 `--tx/--ty`（`rotateX ±6°`、`rotateY ±8°`），rAF 节流
- **层间视差**：鼠标横移时，第 2–5 层额外位移 `2% / 4% / 6% / 8%` 卡宽（差速 → 深度感）
- **高光**：卡片上方叠一层 `linear-gradient` 高光条，随 `--tx/--ty` 反向移动
- **性能**：只动 `transform/opacity`；`will-change: transform` 仅给主卡
- **降级**：`prefers-reduced-motion` 或 `hardwareConcurrency ≤ 4` 或无 hover → 关闭 tilt，保留层叠与翻转
- **翻转**：`backface-visibility: hidden` + `.card-back { rotateY(180deg) }`，复用 v4 的四阶段节奏

## 二、配图卡：行测 / 公专 需要图示区

行测的**判断推理（图形推理/九宫格）**、**资料分析（图表）**、以及公专的**执法场景/流程**都需要图。

### 2.1 数据层（零迁移，复用现有字段）

| 字段 | 用途 |
|---|---|
| `cover_image` | 已存在：卡片封面图（列表/堆叠态显示） |
| `content` | 卡片正文 HTML；白名单允许 `<img src="/uploads/...">`，可内嵌图 |
| `card_back` | 背面要点（可再嵌图） |

**结论**：**不需要新增表字段**。配图直接走 `cover_image`（封面）与 `content` 内嵌 `<img>`（图示区）。图示区在正文第一个 `<img>` 之上渲染，高度 `120–160px`，点击放大。

### 2.2 上传接口（已在运行，补两个能力）

| 接口 | 现状 | 需补 |
|---|---|---|
| `POST /api/materials/admin/upload/image` | ✅ 已有：扩展名白名单 + 5MB + 魔数校验 + uuid 重命名 | 支持 `?purpose=cover\|inline` 区分用途，返回宽高与是否压缩 |
| `POST /api/materials/admin/import/upload`（xlsx 卡片） | ✅ 已有 | `column_mapping` 增可选 `cover` 列（图片 URL 或站内路径） |
| **新增** `POST /api/materials/admin/cards/batch-image` | ❌ 无 | 一次上传 N 张图并返回 URL 列表，供"一卡多图" |

**新增接口契约（建议，D2 已批准新增端点需你确认；本条属新端点，需再确认）**

```
POST /api/materials/admin/cards/batch-image
Content: multipart/form-data  files=[file...]（≤ 9 张，单张 ≤5MB）
200: { "images": [{"url": "/uploads/materials/images/xxx.png", "width": 800, "height": 600}] }
400: 任一文件类型/大小/魔数不符 → 整批拒绝（原子性）
```

**为什么需要它**：`upload/image` 一次只收 1 张；配图卡常需 2–4 张，逐张上传会产生 N 次事务与 N 次审计日志。

**安全**：仍走 `_safe_image_upload` 同一实现（白名单 + 魔数 + uuid），不接受客户端文件名，落盘目录与现有 `uploads/materials/images` 一致，**不新增路径**。

## 三、三角色建卡 + 分享 → 收进我的库

### 3.1 现状（实测）

| 能力 | 现状 |
|---|---|
| 建卡权限 | `POST /api/materials/admin` 需 `_require_admin` → **仅管理员** |
| 归属字段 | `study_material.creator_id` 已存在 |
| 可见性 | `status=1` 即全体可见；无"个人库/共享库"区分 |
| 共享 | **无** |

### 3.2 设计目标

- 学生/教师/管理员**都能建卡**
- 建卡后默认进**自己的库**（不污染公共库）
- 分享后进入**共享区**，他人可「收进我的库」（复制一份，各自独立演进）
- 管理员对公共库仍有上下架权

### 3.3 数据模型（最小改动，1 张新表）

```sql
CREATE TABLE material_share (
  share_id     INTEGER PRIMARY KEY AUTOINCREMENT,
  material_id  INTEGER NOT NULL,          -- 源卡片
  owner_id     INTEGER NOT NULL,          -- 分享者
  scope        TEXT NOT NULL,             -- 'public' | 'org'（预留）
  status       INTEGER DEFAULT 1,         -- 1 可领取 / 0 已下架
  adopted_count INTEGER DEFAULT 0,        -- 被领取次数
  create_time  DATETIME DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(material_id)
);
```

> 不新建"个人库表"：用 `study_material.creator_id + status` 表达归属；
> 个人库卡片用 `status=2`（新增状态：**仅创建者可见**），共享区用 `material_share` 引用。

| status | 含义 | 谁可见 |
|---|---|---|
| 0 | 草稿/下架 | 创建者 + 管理员 |
| 1 | 公开 | 所有人 |
| **2** | **个人库（私有）** | **仅创建者 + 管理员** |

### 3.4 接口契约（新增 4 个，需你批准）

| 接口 | 方法 | 作用 | 权限 |
|---|---|---|---|
| `/api/materials/my` | POST | 建卡（写 `creator_id`，`status=2`） | student/teacher/admin |
| `/api/materials/my` | GET | 我的库（含自己建的 + 领取的） | 登录 |
| `/api/materials/{id}/share` | POST | 分享到共享区（写 `material_share`，`status→1`） | 仅创建者 |
| `/api/materials/{id}/adopt` | POST | 收进我的库（复制一条 `creator_id=我`、`status=2`，`adopted_count+1`） | 登录 |

**领取是"复制"而非"引用"**——理由：领取后自己要能改、要能加笔记/进度；引用会让源卡改动影响所有人的学习记录。复制时 `content_hash` 重新计算，**保留 `source_material_id` 便于溯源**（建议在 `study_material` 加 1 列 `source_material_id`，或放进 `extra` JSON）。

### 3.5 权限与安全

- 建卡：三角色均可，但**必须带 `creator_id=当前用户`**（服务端强制，不接受客户端传）
- 分享：仅 `creator_id == 当前用户`；管理员可强制下架分享
- 领取：同一用户对同一 `share_id` 只能领取一次（唯一索引 `(user_id, share_id)` 建议放 `material_share_log`）
- 内容安全：建卡走 `sanitize_html` 白名单（同现有）；图片走 `upload/image`
- 防刷：建卡限流（如 20 张/日/人）、领取限流

### 3.6 三端展示（已并入的效果图作为依据）

- 我的库：卡片列表加「我的」筛选 chip
- 共享区：卡片右下角显示「来自 XX 老师」+「收进我的库」按钮
- 领取成功后 toast：`已收进我的库（可在「我的」里继续编辑）`
