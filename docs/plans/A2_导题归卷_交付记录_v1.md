## 1. 解决了什么

第一批让"资料 → 卷"能建出来（#127 → `exam_paper#4 GZ-2024-GK-T`）。但**导题那一步还是断的**：

`_get_or_create_import_paper()`（`services/question_ingest/tags.py`）只有两种行为——
「同名 + 同创建者复用」或「`generate_paper_code()` 新建」。
于是"上传真题（资料侧编号 `GZ-2024-GK-T`）→ 建卷 → 导题"会生成**第二张**卷（`PAPER-xxxx`），
两侧编号对不上，学生端/资料页永远串不起来。

本批给它加了 `paper_code` 入参：

| 情况 | 行为 |
|---|---|
| 传入编号，**库里已有该卷** | 直接复用（含 `ENDED` 复活为 `DRAFT`），**不新建**、不覆盖标题 |
| 传入编号，库里没有 | 用该编号建卷（不再生成 `PAPER-xxxx`） |
| 不传编号 | 保持旧行为（同名复用 / 生成新编号），零回归 |

调用点两处都接上了：`POST /api/questions/import/batch-parsed`（前端导入主路径）与
`POST /api/questions/import/confirm`（record 确认路径），都从请求体读 `paper_code`。

## 3. 验证

### 3.1 单测（7 例）
按编号复用（不新建、标题不被覆盖）、ENDED 复活、未命中用给定编号新建、不传编号保持旧生成逻辑、**命中间不受 <5 题阈值**、**未命中仍受阈值**、<5 题不建卷。全部通过；`test_gongzhuan_regression` 等 50 条相关用例回归通过。

### 3.2 线上实测（真实卷 #4）
| 步骤 | 结果 |
|---|---|
| 导入前 | 题库 200 题 / 关系 200 行 / 卷#4 `DRAFT` 0 题 |
| `POST /api/questions/import/batch-parsed`，body 带 `paper_code="GZ-2024-GK-T"`，6 道临时题 | **200**，响应 `paper_id: 4`（**没有新建第二张卷**）；`success=1 new / 5 reused`（6 道题内容太像，去重后只落 1 道） |
| 导入后 | 题目 201 / 关系 201，**关系挂在卷 #4**，卷#4 `question_count=1` |
| 清理临时数据 | 删除 1 条关系 + 1 道题，重置 `question_count` → 回到 **200 题 / 200 关系 / 卷#4 = 0 题** |

结论：**`paper_code` 确实把题目挂到了资料对应的那张卷上**，没有另起新卷。
