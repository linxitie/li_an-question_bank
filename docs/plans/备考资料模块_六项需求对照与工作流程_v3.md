## 3. 三个架构判断（决定后面所有工作量）

### J1 分类法只有两层，第三层是空的 —— 必须先修

```
sub_categories（16 子类，唯一合法词表）
   └── knowledge_point（94 考点）
          └── study_material.point_id  ← 【不存在这一层】
```

- 卡片 `category` 存的是**子类名**，靠**标题恰好等于考点名**才被算作覆盖（35/94 是这么估出来的）
- `study_material` 无 `point_id`；`_auto_classify` 无考点级规则
- 后果：**"分类准确"无法度量**、**按考点找资料做不到**、**按考点发成就做不到**（需求1/3/6 同时受限）

**方案**（P2）：`point_id` 加列 + 导入列 + 两级自动分类（子类 + 考点）+ `category` 词表校验（非法值 400 并给最近词）。**这是本期最高优先级的设计改动。**

### J2 需求(3) 的学生端上传根本不存在

现在只有管理员能传文件。需求要求"学生端、管理员端上传…文档内容格式"。**若不做，需求(3) 无法交付**；若直接做，等于开放任意文件上传。

**方案**（P2.6）：白名单（xlsx/docx/txt/md）+ ≤10MB + ≤200 行/次 + 日配额 + 默认 `status=0` 待审 + `content_hash` 去重 + 逐行错误码回报 + 全部过 `_validate_material_body`/`_check_card_text`/`material_sanitizer`。

### J3 需求(4) 的可行边界

本机无 ffmpeg、无厂商账号。**不做边界声明，这个需求会变成无底洞**。本期做"讲稿+分镜+TTS+数字人"可演示骨架 + provider 接口 + 专利交底（§2 已详述）。
