## 2. 契约

```http
GET /api/materials/admin/{material_id}/preview
Authorization: Bearer <admin>
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` / `type` / `type_label` | int / str / str | 6 类：video_intro·video_advanced·article·card·lecture·paper |
| `title` / `summary` / `badge` / `category` | str | — |
| `subject` / `subject_label` | str | `xingce`→行测、`shenlun`→申论、`gongzhuan`→公专 |
| `status` | int | 1 已上架 / 0 未上架（管理端可预览下架资料） |
| `publisher` | object \| null | `{id,name,role,role_label}`，与列表同源 |
| `created_at` | str \| null | 入库时间，ISO +08:00 |
| `uploaded_at` | **恒 null** | 见 §4：导入记录表没有 `material_id` 外键，无法可靠反查 |
| `content_html` | str \| null | article/lecture/paper 的正文（**二次 sanitize**） |
| `card` | object \| null | `{front, back, images[]}`（images = 封面 + 正文附图） |
| `video` | object \| null | `{url}` = `/api/video/{video_id}/stream` |
| `chapters` / `files` | **[]** | C 批（讲义章节）/ B 批（pdf+docx）填 |
| `paper` | **null** | C 批（年份/地区/题数/满分）填 |

> 三个「先空着」的字段**现在就存在**：前端按「有才渲染」处理，后续批次只填数据、不改契约。

## 4. 两个设计决定（都有代价，写清楚）

**① 抽屉组件不发请求。** 组件只收 `preview / loading / error` 三个 prop，由调用方（组件库演示页、A4 列表页）负责取数。
好处：组件库能用假数据演示、A4 能复用同一份状态、测试不需要 mock axios。
代价：每个调用方都要自己管 loading/error（A4 里只有一处，成本可接受）。

**② `uploaded_at` 恒为 null。** 我查了 `material_import_record`：它只有 `uploader_id / file_name / create_time`，**没有 `material_id`**，无法把「资料」反查回「哪次上传」。硬按 `creator_id + 时间就近` 猜是错的，所以先返回 null（前端整行不渲染）。B 批建 `material_file` 时补上关联再回填，契约不用改。

## 5. 过程中的一个坑（会让人误判"改动没生效"）

截图时发现 `#/admin/dev/style` 打不开、报 `Failed to fetch dynamically imported module`，而**页面还停在旧的资料管理页**。
查 Vite 日志根因是：

```
Error: EBUSY: resource busy or locked, watch '...\src\views\admin\dev\.StylePreview.vue.<pid>.<guid>.tmpdir\StylePreview.vue.tmp'
```

**编辑器的原子写（临时目录 + 重命名）撞上了 Vite 的文件监听 → dev server 直接退出**。重启后一切正常，临时目录也已清理（`git status` 干净）。
教训：**「页面没变化」先看 dev server 还活着没**，别急着怀疑代码。后续可以给 `vite.config.ts` 的 `server.watch.ignored` 加一条 `**/.*.tmpdir/**`，属工程优化，未在本批做。
