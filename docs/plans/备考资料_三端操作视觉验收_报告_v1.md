# 三端操作视觉验收报告 v1（D2）

> 时间：2026-10-30　工具：`scripts/verify/three_device_shots.mjs`（Chrome DevTools Protocol 驱动）
> 范围：徽章详情弹层（点击后）、徽章页 + 主页墙（滚动后）、上传页
> 结论：**9 张图 0 处横向溢出**；发现并修掉 1 个自动化脚本缺陷

## 1. 方法（为什么这算"操作后"而不是静态首屏）

脚本经 CDP 直连 headless Chrome，逐设备执行：

1. `Emulation.setDeviceMetricsOverride` 设置视口 + DPR（PC 1×、平板 2×、手机 3×）
2. 打开页面 → **真的 `el.click()` 点第一张徽章卡**（触发详情弹层）或 `window.scrollTo` 滚动
3. `Page.captureScreenshot` 落盘
4. 读 `document.documentElement.scrollWidth` vs `window.innerWidth`，**实测**横向是否溢出

## 2. 结果矩阵

| 设备 | 视口 | 徽章页·详情弹层 | 徽章页·主页墙 | 上传页 |
|---|---|---|---|---|
| PC | 1440×900 @1x | ✅ 1440/1440 | ✅ 1440/1440 | ✅ 1440/1440 |

## 4. 本次发现的问题与修复

| # | 问题 | 表现 | 处理 |
|---|---|---|---|
| 1 | 同一 hash 重复 `Page.navigate` 不重载 | "主页墙"场景继承了上一场景的弹层，截到的是弹层不是墙 | 每场景先 `about:blank` 再进目标页；已修并重跑 |
| 2 | 手机端上传页右侧约 10px 裁切 | 父布局 `min-width` 所致（非上传页样式） | **未修**（属共享布局，改动影响面大），登记待办 |

## 5. 未覆盖（如实列出）

1. **真实登录页**（`/#/badges`、`/#/profile`、`.vtj` 三科目页）：headless 无登录态，本报告用的是**公开演示页 + 同一批组件**。真实页截图需 D3 方案（CDP 注入 token 或用户登录后托管）。
2. **字号三档**：只存在于 `.vtj` 手机卡片页（需登录），本轮未验。
3. **性能预算**（首屏 ≤2s / 翻页 ≥50fps）：本轮未测，需单独用 CDP `Performance` 域采样。

## 6. 复现命令

```powershell

& "C:\Program Files\Google\Chrome\Application\chrome.exe" --headless=new `
  --remote-debugging-port=9222 --disable-gpu --hide-scrollbars `
  --user-data-dir=<临时目录> about:blank
# 2) 跑脚本（dev server 需在 9527）
node scripts/verify/three_device_shots.mjs
```
