### 2.0 补充修复（2026-11-07，验收前自查发现）

**缺陷**：本页首版**没有读 `route.query`**。于是 `/admin/papers → /admin/materials?type=paper` 只是"跳对了位置"，
实测类型下拉仍是「全部类型」、列表仍是 **112 条**（A4 交付时只验了 hash 变化，没验筛选是否生效——记录在此，避免再犯）。

**改法**（3 个文件）：
- 新增 `src/utils/materialListQuery.ts`：`parseListQuery()` 纯函数 + **白名单**（subject 3 项 / type 6 项 / status `1|0|-1` / created_within `7d|30d`），非法值一律当"没传"；
- `src/views/admin/materials.vue`：setup 阶段 `syncFromQuery()` 先把 query 灌进 filters（首屏请求即带筛选），并 `watch(() => route.query)` 让页内 hash 变化也重新筛；
- 新增 `src/utils/__tests__/materialListQuery.spec.ts`：**8 例**（空 / 单参 / 组合 / 非法 / 数组 / 空格 / null）。

**实测**（无头 Chrome 读 DOM）：

| 访问 | 结果 |
|---|---|
| `#/admin/materials` | 4 个下拉全空，共 **112** 条 |
| `#/admin/materials?type=paper` | 类型下拉 = **paper**，共 **0 条**（库里暂无试卷资料，属预期） |
| `#/admin/papers` | 落到同一 hash，类型下拉 = paper，共 0 条 —— **redirect 现在真的带筛选** |
| `#/admin/materials?status=-1` | 状态下拉 = **-1**，共 **5 条**，顶部提示「回收站：只看已删除资料，点「恢复」可还原」 |
| `?type=video_x&status=9`（垃圾值） | 全部忽略，回落共 **112** 条，不报错不白屏 |
| 页内 `location.hash = '#/admin/materials?type=card'` | 类型下拉自动变 card，共 **109** 条 |

校验：`vitest` 8 例新增（全量 **553 passed**）、`typecheck` exit 0。
