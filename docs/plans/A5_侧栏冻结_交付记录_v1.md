## 1. 为什么不能继续用 `sticky`（实测，不是猜）

`src/layouts/AdminLayout.vue` 里 `.admin-sidebar` 原本就是 `position: sticky; top: 0; height: 100vh`，看起来"已经写了"。
但实测滚动 600px 后它跟着走了：`rectTop 0 → −600`。原因是 VTJ 渲染器把整页包进三层容器，**三层都带 `overflow: auto|hidden`**：

```
x-mask__inner                          overflow=auto/auto    height=4722px
x-container is-overflow-auto           overflow=auto/auto    height=4722px
x-mask                                 overflow=hidden/hidden height=4722px
```

按 CSS 规范，sticky 元素**任意祖先** `overflow != visible` 时，它就相对那个祖先（而不是视口）固定 → 侧栏必然随内容滚走。
`fixed` 不受祖先 overflow 限制，所以改用 fixed + 让位。

## 2. 改动清单（全在 `src/layouts/AdminLayout.vue`）

| # | 改动 | 说明 |
|---|---|---|
| 1 | 根节点加动态类 | `<div class="admin-layout" :class="{ 'is-collapsed': sidebarCollapsed }">`，让"折叠"能被右侧内容区感知 |
| 2 | `.admin-sidebar`：`sticky` → **`fixed`** | `left:0; top:0; height:100vh; width:220px`，加 `box-shadow: 1px 0 0 rgba(15,23,42,.06)` 与内容区区分 |
| 3 | `.admin-right`：`margin-left: 220px` | 给 fixed 侧栏让位；折叠态 `.is-collapsed` 下改 64px，带 0.3s 过渡 |
| 4 | `.admin-header`：`sticky` → **`fixed`** | `top:0; left:220px; right:0; height:56px`；折叠态 `left:64px` |
| 5 | `.admin-right` 补 `padding-top: 56px` | 顶栏 fixed 后脱离文档流，用 padding 补回同样高度 → **页面视觉位置与改动前一致** |
| 6 | 顶栏/面包屑统一令牌 | 原来 `#fff + #e8e8e8 + rgba(0,0,0,.05)`、面包屑 `#1A3C6D/600` → `var(--adm-surface)/var(--adm-line)`、面包屑 `var(--adm-text)/15px/700` |

## 3. 实施中发现并修正的一个坑

第一版只把**侧栏**改成 fixed，顶栏加的是 `position: sticky`——结果实测顶栏也照样滚走
（`headerTop: -380 → -486`），**同一个 overflow 祖先问题**。于是把顶栏也改 fixed，并用 `.admin-right` 的 `padding-top: 56px` 补偿高度。
