# 电脑端被判定为平板（登录页与登录后落地页）— 设计方案 v1

> 状态：**待批准**（本文只做设计与取证，不含代码改动）
> 日期：2026-10-26
> 上报现象：「电脑端登录后显示的是手机端的页面」（附截图 1 张）
> 涉及：`src/utils/device.ts`（判据）、`src/router/index.ts:595`（守卫）、`.vtj/vue/tablet_login.vue:242`（登录后跳转）
> 红线相关：R4（`src/utils/device.ts` 与 `resolveDevicePath()` **原样保留**）→ 本文任何改动都必须先经你批准，且默认最小化

---

## §0 结论先行（三个必须先纠正的事实）

1. **那不是手机端，是平板端。** 截图里的页面是 `.vtj/vue/tablet_login.vue`：
   - 「公安联考智能备考平台」在三个登录页里**只出现在 tablet_login.vue**（login.vue 0 次、mobile_login.vue 0 次）
   - 「海量题库，精准练习」同样只在 tablet_login.vue（1 次）
   - 「还没有账号？请联系管理员分配」在 tablet_login 与 mobile_login 各 1 次，login.vue 0 次
2. **你看到的"登录后"页面对不上，是因为平板登录页登录完直接跳平板首页**：`tablet_login.vue:242 → router.push('/tablet/home')`。
3. **根因不是布局，是设备判据把你的电脑判成了平板。**

---

## §1 证据链

### 1.1 判据源码（唯一消费方）

`src/router/index.ts:594-621` 是全局守卫，第 595 行调用 `detectDevice()`：

```ts
const device = detectDevice();
// 已有 /tablet、/mobile 前缀 → 只校验角色
// 否则 device !== 'pc' → resolveDevicePath(to.path, device) 重定向
```

`src/utils/device.ts:20-34`（平板判据，**两条任一命中即判平板**）：

```ts
if (
  /(ipad|tablet|(android(?!.*mobi))|(windows(?!.*phone)(.*touch)))/.test(userAgent) ||
  (screenWidth >= 768 && screenWidth <= 1024 && touchable)
) return 'tablet';

if (/iphone|ipod|android.*mobi|windows phone|blackberry|opera mini|iemobile/.test(userAgent) ||
    screenWidth < 768) return 'mobile';

return 'pc';
```

**致命的一条是正则里的 `windows(?!.*phone)(.*touch)`**：它的含义是"UA 含 `windows`，且后面任意位置出现 `touch`"。
→ 触摸屏笔记本、部分国产浏览器（UA 带 `Touch`）在 **1920 宽的桌面上也会被判成平板**。

### 1.2 实测复现（Playwright，真实浏览器，2026-10-26）

| 场景 | innerWidth | UA 含 touch 字样 | detectDevice 结果 | 打开 `/#/login` 后落地 | 渲染的页面 |
|---|---|---|---|---|---|
| 普通 Chrome，1440×900，无触摸 | 1440 | 否 | **pc** | `/#/login` | `.auth-page`（PC 登录） |
| **UA 追加 `Touch`**，1440×900，无触摸 | 1440 | **是** | **tablet** | **`/#/tablet/login`** | **`.tablet-login-page`（与你截图一致）** |
| 普通 Chrome，900×800，有触摸 | 900 | 否 | **tablet** | `/#/tablet/login` | `.tablet-login-page` |
| 普通 Chrome，1205×751，无触摸 | 1205 | 否 | pc | `/#/login` | `.auth-page` |

从截图推算你的视口约 1205×751 CSS px（原图 2411×1502，按 2 倍像素比折算）——**宽度不在 768–1024 区间**，所以几乎可以断定你命中的是第一条（UA 里的 `touch`），而不是宽度+触摸那条。

> 未验证项：你的浏览器实际 UA 我没有读到（无法从代码侧取得）。上面的结论是"由宽度排除法 + 复现一致"推出的，置信度约 90%。**确认办法见 §5 验收第 1 条。**

### 1.3 平板路由与页面清单

- 平板专属页面 7 个：`tablet_home / tablet_login / tablet_forum / tablet_practice / tablet_question_bank / tablet_profile / tablet_gold_purchase`
- 手机专属页面 7 个：`mobile_*` 对应同名列
- 平板登录成功后固定跳 `/tablet/home`

## §3 方案对比（4 个，可组合）

| # | 方案 | 做法 | 好处 | 代价 |
|---|---|---|---|---|
| **A** | **立即止血：手工指定端** | ①URL 支持 `?device=pc\|tablet\|mobile` ②记住到 `localStorage`，下次自动生效 ③在 `detectDevice()` 返回前优先读覆盖值 | 不改判据就能让你今天正常用 PC 版；以后任何误判都能自救 | 多一个"设备覆盖"概念，需在文档里写清优先级 |
| **B** | **收紧判据（根治误判）** | 删掉 `windows(...touch)` 这条；平板只认「UA 是 iPad/Android 平板」或「视口 ≤1024 **且** 粗指针（pointer: coarse）**且** 不可悬停（hover: none）」 | 触摸屏笔记本回归 PC；真平板仍走平板 | 部分安卓平板浏览器 `hover` 判定不一致，可能漏判（此时走 PC 版，符合你 2026-10-25 的决定） |
| **C** | **按你 2026-10-25 的决定：平板=PC** | `detectDevice()` 不再返回 `tablet`；`/tablet/*` 仅在地址栏手动输入时可达 | 最彻底：PC/平板永远同一套页面，与你上次的决定一致 | 平板触屏优化版（含刚做好的平板详情页）默认不再自动进入 |
| **D** | 增加"切换端"入口 | 页面角落加「切换到平板版 / 电脑版」 | 用户可控 | 多一处 UI，且要先定放哪 |

### 推荐组合

**A + B**（先止血、再根治），**C 作为可选**等你定平板策略。

理由：
- A 的代价最小、风险最低，且**不需要改 R4 保护文件的核心逻辑**（只是加一个"读覆盖值"的前置判断）；
- B 直接堵住把笔记本误判成平板的那条正则；
- C 涉及产品决策（平板到底用哪套页面），必须你点头。

## §4 选定方案的具体改法（A + B，待你批准后才动代码）

| # | 文件:行 | 改动 |
|---|---|---|
| 1 | `src/utils/device.ts`（`detectDevice()` 开头） | 先读覆盖：`localStorage.getItem('li_an_device')` 或 URL 的 `?device=`；命中即直接返回，不走后续判定 |
| 2 | `src/utils/device.ts:21-24` | 删除 `(windows(?!.*phone)(.*touch))` 分支 |
| 3 | `src/utils/device.ts:23` | `screenWidth <= 1024 && touchable` 改为 `screenWidth <= 1024 && matchMedia('(pointer: coarse)').matches && matchMedia('(hover: none)').matches` |
| 4 | 新增 `src/utils/deviceOverride.ts`（约 30 行） | 解析 `?device=`、写入/读取 localStorage、提供 `setDeviceOverride/clearDeviceOverride`；**不改 `resolveDevicePath()` 签名**（R4 精神） |
| 5 | `src/router/index.ts:595` 附近 | 若存在覆盖值且与当前前缀冲突（例如强制 pc 却停在 `/tablet/...`），重定向到对应 PC 路径 |

**不做什么**：不动 `/tablet/*` 与 `/mobile/*` 路由；不删任何页面；不改后端；不动 `resolveDevicePath()` 的映射表语义。

## §6 风险与回滚

| # | 风险 | 对策 |
|---|---|---|
| 1 | R4 红线：`device.ts` 被保护 | 只做"前置覆盖 + 收紧一条正则"，`resolveDevicePath()` 与映射表一字不动；改前备份 `.bak_20261026` |
| 2 | 真平板被判成 PC | 这正是你 2026-10-25 的决定（平板=PC 同一套页面）；若以后要平板专属，用 `?device=tablet` 或恢复 C 方案 |
| 3 | localStorage 覆盖后"忘了自己切过" | 提供 `?device=auto` 清除覆盖；并在控制台打印当前判定来源 |
| 4 | 守卫重定向循环 | 覆盖值参与判定后，重定向目标必须是"覆盖后的设备路径"，避免 `/login → /tablet/login → …` |

**回滚**：`git revert <提交>`；备份文件 `.bak_20261026` 可直接覆盖（先确认 dev server 未占用）。

## §7 需要你确认（2 条）

1. **平板策略**：按你 2026-10-25 的决定「平板与电脑端用同一套页面」（= C，平板永不自动进 `/tablet/*`），还是保留"真平板自动进平板版"（= A + B）？
   - 若选 C：改动更小（判据里删掉 tablet 分支），但平板触屏页只能手动访问。
   - 若选 A + B：平板仍自动进平板版，只堵住笔记本误判。
2. **是否立刻做 A（止血）**：A 只影响设备覆盖，不碰判定逻辑，可单独先上，让你今天就能用 PC 版。
