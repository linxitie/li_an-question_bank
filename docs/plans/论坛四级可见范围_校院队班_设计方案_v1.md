# 论坛四级可见范围（校 / 院 / 队 / 班）— 设计方案 v1

> 状态：**待批准**（只做设计与取证）
> 日期：2026-10-26
> 需求（用户原话要点）：
> 1. 发布范围在「全校 / 全院 / 全班」之外**再加「全队」**；
> 2. **学生端**只能发到「自己所在的 学院 / 队 / 班」，不能发到别人的区域；想大范围传播只能选「全校」；
> 3. **教师端**同理：教师可能管辖**不同学院的不同队/班**，只能在自己管辖范围内发；想大范围只能选「全校」；
> 4. 学生端与教师端都要有这套选择。

---

## §1 现状证据（实测）

| 事实 | 位置 |
|---|---|
| 用户只有 `department`（**学院/部门**，字符串）与 `class_name`（**班级**，字符串） | `backend/app/models/models.py:33-34` |
| **没有"队"字段**：全库 71 个模型中，含 dui/team 的列 **0 个** | `grep -n 'dui\|team' models.py` → 无命中 |
| 教师-班级关联表 `Banji`（有 `class_name` + `teacher_id`） | `models.py:1099-1104` |
| 论坛帖子现有 `visibility`（ALL/CLASSES）+ `visible_classes`(JSON) | P3 已建（提交 `c16bc85`） |
| 可见范围过滤集中在 `_apply_visibility_filter()` | `forum.py`（P3-03） |
| 教师管辖范围口径集中在 `services/class_scope.py` | `class_scope.py`（提交 `9091bee`） |

**结论**：要做"队"，必须先给用户补一个归属字段；否则"全队"无从判定。学院可复用现有 `department`，班级复用 `class_name`，**队是全新维度**。

---

## §2 规则矩阵（谁能发到哪一级）

| 角色 | 可发布范围 | 目标如何确定 |
|---|---|---|
| 学生 | 全校 / 本学院 / 本队 / 本班 | **只能是自己档案里的值**；后端按 `department / team_name / class_name` 派生，忽略客户端传的名字 |
| 教师 | 全校 / （所辖各学院的）全院 / 所辖队 / 所辖班 | 后端按「本人 + Banji 关联 + 本人 department/team」求并集；客户端只能从**允许集合**里挑 |
| 管理员 | 全校 + 任意范围 | 用于运营/公告（可选，默认同教师但不受限） |

**硬规则（安全核心）**：
> 除非选「全校」，否则**客户端传来的学院/队/班名称必须落在服务端算出的允许集合内**；不在集合内 → 400，且**不得**静默改成全校（避免误公开）。

**可见性规则（读）**：

```
post.visibility = ALL      → 全站可见
post.visibility = COLLEGE  → 帖子 scope_names 含 读者.department
post.visibility = TEAM     → 帖子 scope_names 含 读者.team_name
post.visibility = CLASS    → 帖子 scope_names 含 读者.class_name
教师/管理员读：始终不过滤（沿用 P3 现状：全校帖子可见，便于管理）
```

## §3 数据模型变更

```sql
-- 1) 用户补"队"（学院复用 department，班级复用 class_name）
ALTER TABLE sys_user ADD COLUMN team_name VARCHAR(100);   -- 队（如「一队」）
CREATE INDEX ix_sys_user_dept_team ON sys_user(department, team_name);

-- 2) 帖子可见范围：枚举扩一级，scope 列表复用现有 JSON 列
--    visibility: ALL | COLLEGE | TEAM | CLASS   （原 CLASSES 数据迁移为 CLASS）
ALTER TABLE forum_post ADD COLUMN visible_scope VARCHAR(16);  -- 冗余级别，便于查询/索引（可选）
-- visible_classes 继续存"名称数组"，语义泛化为 scope_names（不改列名，避免二次迁移）
```

**口径说明（避免歧义）**：
- 学院 = `sys_user.department`（已有数据）
- 队 = `sys_user.team_name`（**新增**，需填充方式，见 §8）
- 班 = `sys_user.class_name`（已有）

## §4 接口变更（全部在 `/api/forum/*`，不新增 `/api/v1`）

| 接口 | 变更 |
|---|---|
| `POST /api/forum/posts` | `visibility` 取值扩为 `ALL/COLLEGE/TEAM/CLASS`；`scope_names`（JSON 数组）仅当非 ALL 时必填；**服务端校验归属** |
| `GET /api/forum/posts` | 过滤逻辑扩展为四级；参数不变 |
| `GET /api/forum/my-posts` / `my-favorites` / `my-likes` | 同样套用四级过滤（复用同一函数） |
| `GET /api/forum/scope-options`（**新增**） | 返回"当前用户可发布的范围选项"：`[{level:'ALL'},{level:'COLLEGE', names:[...]},{level:'TEAM', names:[...]},{level:'CLASS', names:[...]}]`；前端据此渲染、后端据此校验，**同一事实来源** |

## §6 安全与权限（逐条）

| 风险 | 对策 |
|---|---|
| 学生伪造 `scope_names` 发到别的学院 | 服务端只接受**允许集合内**的名称；越界 400 |
| 教师越权发到未管辖的队/班 | 同上，允许集合 = 本人 + Banji 并集 |
| 空集合导致帖子谁都看不到 | 若某级别允许集合为空，前端禁用该级别；后端收到该级别 → 400 |
| 误把受限帖变全校 | 「非 ALL → ALL」的降级**不做**（P3 里"没有班级退回 ALL"的逻辑要**删掉**，改为报错） |
| 读侧越权 | 过滤集中在 `_apply_visibility_filter()`，四级都走同一函数 |
