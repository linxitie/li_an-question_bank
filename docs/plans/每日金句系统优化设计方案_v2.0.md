## 0 结论摘要（先看这 8 条）

1. **方向正确，体量超配**：溯源、审核、去重、图谱、多源、多模态都是对的；但当前系统是 **FastAPI 单体 + SQLite + Vue/VTJ**，为约 10³ 量级的金句引入 Neo4j + MongoDB + Milvus + MinIO 四套新存储，运维成本约为现有系统的 5–10 倍，收益在 1 万条以内不明显。
2. **Obsidian 已经是现实**：代码直接从 `D:\Obsidian仓库\每日金句知识库\01-金句素材库` 读文件（`quotes.py:29-47`），但本机该目录**不存在**、环境变量未配置；数据库只有 **10 条**种子金句，收藏 **0 条**。
3. **当前最大的问题不是"不够智能"，而是"没有事实源"**：每次请求全量扫盘（`quotes.py:113-145`）、每日金句按 `os.walk` 顺序取模（`quotes.py:148-161`）、收藏以文件名做 ID、审核状态只存在于 frontmatter。换一台机器/改一个文件名，结果就变。
4. **右尺寸方案**：**SQLite 做唯一事实源**；Obsidian 保留为"生产/审核/导出"工作台；四库降为"一库三用"（关系表 + JSON 列 + FTS5 + 本地文件）；五智能体降为**五段流水线**；云边降为**服务端三级路由**；图谱先用关系表，Neo4j 作为条件触发的选项。
5. **不改既有 343 端点**：只新增 `/api/quotes/*` 与管理端 `/api/admin/quotes/*`；现有响应字段保持兼容，前端分阶段切换。
6. **每日金句要"预生成 + 幂等"**：新增 `daily_quote(date, quote_id)`，每日 00:05 生成，三端同一天必定同一句；生成失败时 API 惰性补生成，仍然幂等。
7. **审核必须留痕**：`draft → pending → approved → published → archived` 状态机 + `quote_review` 日志 + 复用 `sys_operation_log`/`OperationLog`；人工终审一票否决。
8. **本方案预计 MVP 8–12 人日、V1 10–15 人日、V2 15–20 人日**；V3（Neo4j/向量库/端侧模型）只有在指标触发时才立项。

## 1 目标与度量

### 1.1 业务目标

| 目标 | 说明 |
|---|---|
| 每日稳定 | 同一天、三端、任意设备看到同一句；跨天自动轮换；不因文件增删而漂移 |
| 可溯源 | 每条正式金句至少一个不可编辑的来源（URL/文件/投稿人），可一键回看原文 |
| 可审核 | 机器初筛 + 人工终审；通过/拒绝/修改都有记录、责任可界定 |
| 可检索 | 按主题、科目、作者、来源、关键词检索；相似句可发现 |
| 可扩展 | 新增来源（RSS/投稿/警务素材）不改变核心模型；多模态证据可挂接 |
| 内容安全 | 政治/法律表述准确；敏感内容拦截；版权短引用 + 署名 |

### 1.2 技术指标（验收线）

| 指标 | 目标 | 测量方式 |
|---|---|---|
| 每日金句 p95 | ≤100ms（缓存命中）/ ≤300ms（回源） | 压测脚本 + 日志 |
| 列表/搜索 p95 | ≤300ms（1 万条内） | 同上 |
| 首次导入 | 1341 条 ≤60s（本机） | 导入脚本输出 |
| 收藏零丢失 | 迁移前后收藏数一致 | SQL 对账 |
| 来源覆盖 | published 金句 100% 有 source_id | SQL 校验 |
| 审核留痕 | 100% 状态变更有人/时间/原因 | 审计表校验 |
| 同日一致 | 连续 7 天三端一致 | 回归脚本 |
| LLM 成本 | 初始导入 ≤150 万 token；日常 ≤20 万 token/日 | `llm_call_log` 汇总 |

### 1.3 失败判据

以下任一出现即视为本方案失败：同一天不同端不同句；升级后收藏丢失；未审核内容被 published；来源字段为空仍上线；导入后金句总数对不上且无法解释；回滚需要重装系统。

## 2 范围与非目标

### 2.1 本期范围（MVP + V1）

- Obsidian 存量金句导入 + 增量同步（文件哈希、幂等）。
- SQLite 唯一事实源：`essay_quote` 扩展 + 来源/标签/审核/每日/任务/成本表。
- 每日金句预生成与缓存；三端展示保持兼容。
- 管理端审核 API（通过/拒绝/修改理由）+ 审核日志；审核界面分阶段（MVP 用 Obsidian 状态同步，V1 做管理端页面）。
- 精确去重 + SimHash 近似去重；标签体系与 FTS5 检索。
- 备份/回滚/监控/成本台账。

### 2.2 非目标（明确不做）

- 不引入 Neo4j / MongoDB / Milvus / MinIO（V3 条件触发）。
- 不做端侧小模型；不做设备端推理。
- 不做五个自治智能体服务；运行时是确定性流水线 + 单点 LLM 调用。
- 不做动态图谱嵌入的持续训练/灾难性遗忘研究。
- 不在本期扩大爬虫范围（先 Obsidian + 手工 + RSS 预留）。
- 不修改既有 API 路径/方法/响应外壳；不重写三端页面模板。

### 2.3 反目标

- 为了"架构先进"而增加 4 个中间件，导致备份、监控、故障域翻倍。
- 把 Obsidian 当唯一事实源，继续每次请求扫盘。
- 让 LLM 直接决定发布（必须人工终审）。

## 5 数据模型

### 5.1 设计原则

- **一个事实源**：SQLite；Obsidian 是输入/输出，不是运行时数据库。
- **稳定 ID**：`quote_uid` 不随内容/文件名变化；内容哈希只用于去重。
- **多来源一金句**：`essay_quote` 存 canonical 内容，`quote_source` 存多来源。
- **状态与可见性分离**：`review_status` 管流程，`status` 保持 1/0 管上下线（兼容既有查询）。
- **软删除**：`deleted_at`，不做物理删除；审核拒绝保留记录。

### 5.2 扩展 `essay_quote`（不破坏既有字段）

新增列：

| 列 | 类型 | 说明 |
|---|---|---|
| `quote_uid` | TEXT | 稳定 ID，如 `q_7f3a9c2e`；唯一 |
| `normalized_hash` | TEXT | 归一化文本 SHA-256 前 32 位；去重 |
| `review_status` | TEXT | `draft/pending/approved/published/rejected/archived`，默认 `published`（兼容存量） |
| `source_id` | INTEGER | 主来源，FK `quote_source` |
| `quality_score` | REAL | 0–100 |
| `sentiment` | TEXT | positive/neutral/negative |
| `language` | TEXT | 默认 zh |
| `merged_into_id` | INTEGER | 近似重复合并指向 |
| `updated_at` | DATETIME | 审核/编辑时间 |
| `deleted_at` | DATETIME | 软删除 |

保留 `status`、`category`、`source`、`author`、`create_time` 不变，保证旧接口与前端零改动。

### 5.3 新增表

| 表 | 作用 | 关键字段 |
|---|---|---|
| `quote_source` | 来源与证据链 | source_id, source_type, uri, title, author, published_at, fetched_at, trust_level, content_hash, raw_path, license |
| `tag` | 标签字典 | tag_id, name, canonical_name, tag_type(topic/scene/subject), aliases(JSON) |
| `quote_tag` | 金句-标签 | quote_id, tag_id, confidence, source(rule/llm/human) |
| `quote_relation` | 关系边（图轻量版） | from_quote_id, to_quote_id, relation_type(similar/opposite/applicable_to/duplicate_of), score, created_by |
| `quote_evidence` | 多模态证据 | evidence_id, quote_id, media_type(image/audio/video), path, sha256, ocr_text, caption, source_id |
| `quote_review` | 审核流水 | review_id, quote_id, reviewer_id, action, reason, diff_json, created_at |
| `daily_quote` | 每日下发 | quote_date(PK), quote_id, algorithm_version, fallback_used, created_at |
| `ingest_job` | 采集/导入任务 | job_id, source_id, status, attempts, stats_json, error, started_at, finished_at |
| `llm_call_log` | LLM 成本台账 | id, job_id, quote_id, provider, model, purpose, prompt_tokens, completion_tokens, cost_estimate, latency_ms |
| `quote_fts` | 全文检索（FTS5） | content, author, source（external content 表） |

### 5.4 迁移与回滚

迁移顺序（每步可独立回滚）：

1. `sqlite3.backup()` 备份到 `backend/data/quote_migration_<日期>.db`。
2. `ALTER TABLE essay_quote ADD COLUMN ...`（SQLite 支持；默认值保证存量行可读）。
3. 建新表与新索引；建 FTS5 与同步触发器。
4. 回填：`quote_uid`（存量按 `q_<hash>` 生成）、`review_status='published'`、`source_id`（Obsidian 来源）。
5. 导入 Obsidian；对账条数/哈希；生成 `daily_quote` 历史 7 天。
6. 收藏回填：`quote_favorite.obsidian_source` → 对应 `quote_id`；保留旧列。
7. 开关 `QUOTE_V2_READ=true` 切换读路径；保留旧路径 1 个版本。

回滚：关闭开关 → 恢复备份 → 回滚代码提交；不删除旧列/旧表，直到 V1 验收通过。

> 禁止 `shutil.copy2` 备份 SQLite；必须 `sqlite3.backup()`，回滚同时处理 `-wal`/`-shm`（R10）。

## 7 前端契约

### 7.1 三端展示（不改模板，只改 `<script>`）

- `quote_banner.vue`、`mobile_home.vue`、`tablet_home.vue` 的每日金句请求不变。
- 响应兼容策略：**保留 `quote_id: 0` 哨兵一个版本**，新增 `quote_uid`；前端优先用 `quote_uid` 判断收藏归属，`quote_id>0` 时走数据库收藏，否则走 `obsidian_source`。
- 收藏页 `favorites.vue` 继续调 `/api/collection/news-favorites`；后端合并逻辑改为按 `quote_id` 统一查询。
- 三端一致性回归：首页/收藏/换一句/未登录四个场景。

### 7.2 管理端审核页（V1，新增页面）

- 路由：`/admin/quotes/review`；页面 id `admin_quotes_review`。
- 列表列：摘要、来源可信度、质量分、标签、审核建议、更新时间。
- 详情抽屉：原文、来源链接、抽取结果、相似句、操作（通过/拒绝/退回+理由）。
- 模板必须由设计器生成/调整；AI 只改 `<script>`（R3）；`dryRun: true` 预览。
- 权限：`role_level>=2`；无权限路由守卫。

### 7.3 Obsidian 导出（V2）

- 单向 `DB → vault/02-已发布`；文件名 `YYYY-MM-DD-<quote_uid>.md`。
- frontmatter：uid、tags、source、review_status、quality_score。
- `[[wikilink]]` 指向作者页/主题页；Dataview 看板读取导出目录。
- 导出幂等：内容哈希比对，不覆盖人工修改；检测到外部修改则进入待审队列。

## 8 事件与数据流

### 8.1 流水线（五段，不是五个自治服务）

```
来源(Obsidian/RSS/手工/警务素材)
  → ingest（采集/解析/归一化/哈希）
  → dedupe（精确 → SimHash 近似 → 合并建议）
  → enrich（规则标签 → LLM 抽取/标签/风险）
  → review（自动质检 → 人工终审）
  → publish（status=1, review_status=published）
  → daily（预生成 daily_quote）
  → export（Obsidian，可选）
```

每段：输入/输出 JSON、幂等键、重试上限 2、失败进 `ingest_job.error`，不阻塞其他条目。

### 8.2 状态机

```
draft ──规则/LLM──> pending ──人工通过──> approved ──发布──> published
  ↑                    │                                      │
  └──退回重做──────────┴──人工拒绝──> rejected               └──下架──> archived
```

- 只有 `published` 且 `status=1` 进入每日池与列表。
- 低置信度（<0.6）强制 `pending`，不得自动发布。
- 状态变更写 `quote_review` + `sys_operation_log`/`OperationLog`（target_type=`quote`）。

### 8.3 每日生成

- 定时：每日 00:05（Asia/Shanghai）由既有 APScheduler 触发。
- 算法：取 `published` 池，排除近 30 天已用，按 `sha256(f"{date}:{quote_uid}")` 排序取首条；写入 `daily_quote`（`quote_date` 唯一）。
- 惰性补生成：API 发现当日无记录时，同一事务内生成并写入；并发用唯一键兜底。
- 读取：先查 `daily_quote`（缓存 60s），未命中回源，仍无则回退数据库种子/“暂无金句”。

### 8.4 降级

| 故障 | 行为 |
|---|---|
| Obsidian 不可用 | 不影响线上；导入任务标记失败并告警；DB 继续服务 |
| LLM 不可用 | 候选进入 `pending`（规则标签），不阻塞审核 |
| 数据库不可用 | 返回 503，不静默返回空金句 |
| 定时任务漏跑 | API 惰性补生成，保证当日有句 |

## 9 安全设计

| 威胁 | 控制 |
|---|---|
| 路径遍历（导入/导出） | 规范化路径并校验必须位于 vault 根内；文件名白名单；禁止 `..` |
| XSS（金句/来源/标签） | Vue 默认转义；禁止 `v-html`；如渲染 Markdown 用白名单 sanitizer |
| SQL 注入 | SQLAlchemy 参数化；FTS 查询参数绑定 |
| 越权审核 | `role_level>=2` + 路由守卫 + 服务端二次校验；审核日志留痕 |
| 提示注入（抓取内容） | 内容视为数据、加分隔符、禁止工具调用；输出必须过 JSON Schema |
| 密钥泄露 | LLM key 仅环境变量；日志脱敏；`check_secrets.py` 门禁 |
| 版权 | 只存短引用 + 来源/作者；不存全文；提供下架流程 |
| 内容敏感 | 来源分级（官方/权威媒体/个人）；敏感词/风险标签；人工终审 |
| 滥用 | 每日/随机接口缓存 + 限流；搜索分页上限 |
| 备份泄露 | 备份目录权限最小化；不纳入 Git |

警务场景附加要求：政治表述、法律法规条文以官方来源为准；个人投稿必须可追溯；涉及案件/人物的内容默认拒绝。

## 12 风险与回滚

| 风险 | 影响 | 缓解 |
|---|---|---|
| 导入重复/覆盖 | 数据脏 | 幂等键 + dry-run + 对账 + 备份 |
| 收藏丢失 | 用户投诉 | 迁移前备份；文件名→quote_id 映射；保留旧列一个版本 |
| 每日漂移 | 三端不一致 | `daily_quote` 预生成 + 唯一键 + 惰性补生成 |
| LLM 成本失控 | 预算超支 | 仅灰区调用、批量、日上限、成本台账 |
| 审核积压 | 内容不上线 | 质量分排序、批量通过、SLA 看板 |
| Obsidian 双向冲突 | 内容回退 | 单向导出；外部修改进待审 |
| 迁移破坏旧接口 | 三端故障 | 兼容字段 + 开关 + 双读比对 1 个版本 |
| 范围蔓延 | 延期 | 非目标清单 + 阶段门禁 |

回滚：`QUOTE_V2_READ=false` → 恢复数据库备份 → `git revert` 相关提交；不删除旧表/旧列直到 V1 稳定。

### B. 归一化与去重

- 归一化：NFKC、全角→半角、去首尾空白、合并连续空白、去包裹引号、英文小写。
- 精确：`sha256(normalized)`。
- 近似：64 位 SimHash；Hamming ≤3 自动合并建议；4–8 人工/LLM；>8 视为不同。
- 合并：保留最早 `quote_id` 为 canonical，其余 `merged_into_id` 指向；列表过滤。

### C. LLM 输出 Schema

```json
{
  "summary": "一句话释义",
  "tags": ["忠诚教育", "心理韧性"],
  "sentiment": "positive",
  "scenes": ["面试引用", "申论开头"],
  "subjects": ["申论"],
  "confidence": 0.82,
  "risk_flags": [],
  "reason": "判定依据"
}
```

约束：tags 必须命中 `tag` 字典；未命中放 `new_tag_suggestion` 并强制人工；`confidence<0.6` 强制 pending。

### D. 监控指标清单

`quote_ingest_total{status}`、`quote_pending_count`、`quote_review_duration_seconds`、`daily_quote_source{type}`、`quote_llm_tokens_total{provider}`、`quote_search_latency_seconds`、`quote_favorite_total`。

### E. 术语

- **事实源（SoR）**：唯一可信数据来源，这里是 SQLite。
- **canonical quote**：去重后保留的主记录。
- **灰区**：规则无法判定、需要 LLM/人工的候选。
- **幂等键**：重复执行不产生副作用的唯一标识（source+hash / date / uid）。
