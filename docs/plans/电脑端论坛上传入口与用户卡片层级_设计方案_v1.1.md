## 0. 结论先行

1. **评论上传入口不是缺失，是被埋在弹窗底部**：入口在 `y≈2154`，弹窗可视高 `765`、内容总高 `2388`。修法 = `.comment-input-area` 改 `position: sticky; bottom: 0`（纯 CSS）。
2. **发帖弹窗不需要吸底**：实测弹窗可视高 = 内容高 = `544`，全部内容一屏可见。真正的问题是里面**有两套上传控件**，「上传学习资料(Word/PDF/Excel)」这个旧按钮**不接受 png**，容易被误认为"没有上传图片功能"。
3. **用户卡片被盖**：两个遮罩都是 `z-index: 2000`，用户卡片在 DOM 里更早 → 被帖子详情压住。修法 = `.modal-overlay:has(.profile-card) { z-index: 2100 }`（纯 CSS）。
4. 三处改动全部落在 `<style>`，**不碰 `<template>`**，符合 R3；不执行 DSL 同步，符合 R2；后端零改动。

## 2. 目标与非目标

### 2.1 目标

1. 帖子详情打开后，**不滚动**即可看到并使用表情、图片/文件上传、输入框、发表按钮。
2. 点评论作者头像，用户卡片显示在帖子详情**之上**；关掉卡片后详情仍在。
3. 消除「发帖弹窗里上传入口让人误以为不能传图片」的认知问题。
4. 后端、接口、数据字段零改动。

### 2.2 非目标

- 不做在线预览（仍为下载）。
- 不改手机端、平板端。
- 不动上传白名单与大小限制（已对齐）。
- 不改 PC 三栏布局。

## 3. 方案（逐条已定）

### 3.1 评论输入区吸底 —— 采用，纯 CSS

`.comment-input-area`（`forum.vue:1971`）当前 `position: relative`；其滚动祖先是 `.post-detail-card`（`overflow-y: auto`，`forum.vue:1548-1557`），中间无其它 overflow 容器，因此 `sticky; bottom: 0` 可贴住弹窗可视底边。

### 3.2 用户卡片提层 —— 采用，纯 CSS

```css
@supports selector(:has(*)) {
  .modal-overlay:has(.profile-card) { z-index: 2100; }
}
```

- `:has()` 是「选中"内部含有某元素的父元素"」的 CSS 写法，Chrome 105+/Safari 15.4+ 支持。
- 用 `@supports` 包裹：老内核直接忽略该规则，**表现与今天一致（卡片仍被盖），不会更坏**。
- 为什么不改 template 加类名：R3 规定 AI 不得直接改 `.vtj` 页面的 `<template>`，那需要你在设计器里操作。纯 CSS 可以完全避开。

### 3.3 发帖弹窗吸底 —— **不做**（数据不支持）

实测弹窗不需要滚动，吸底没有可改善的内容。强行把上传区吸底还会与 `.modal-actions` 抢占底部空间，属负收益。

### 3.4 发帖弹窗两套上传控件 —— 建议合并（需你授权，默认不做）

| 选项 | 做法 | 需改 template | 结论 |
|---|---|---|---|
| A. 保留新控件，隐藏旧按钮 | `.upload-area { display: none }`（纯 CSS） | 否 | **可选**：一行 CSS，立刻消除"不能传图片"的误解；但 `newPost.attachments` 通道仍在代码里，属于死代码 |
| B. 删掉旧控件与相关方法 | 删 `forum.vue:182-200` + `triggerUpload/handleFileUpload/removeFile` | 是（R3） | 净收益最高，但需要你在设计器里删 |
| C. 什么都不做 | — | 否 | 用户继续可能误解 |

**推荐 A 作为本期最小修复**，B 作为后续清理项。默认**等你拍板**。

## 4. 详细设计（落点）

### 4.1 `forum.vue:1971` `.comment-input-area`

```css
.comment-input-area {
  margin-top: 16px;
  padding-top: 12px;
  border-top: 1px solid #f0f2f5;
  position: sticky;        /* 原 relative */
  bottom: 0;
  background: #ffffff;
  z-index: 5;
  padding-bottom: 4px;
  box-shadow: 0 -8px 16px rgba(26, 54, 93, 0.05);
}
```

### 4.2 新增（放在 `.modal-overlay` 规则之后）

```css
@supports selector(:has(*)) {
  .modal-overlay:has(.profile-card) {
    z-index: 2100;
  }
}
```

### 4.3 可选（§3.4-A，等你确认）

```css
/* 旧上传按钮与新上传控件重复，且不支持图片；先隐藏避免误导 */
.upload-area { display: none; }
```

### 4.4 不做什么

- 不执行 `vtj_sync_vue_to_dsl`（raw 页，R2）
- 不改 `<template>`（R3）
- 不改后端

## 5. 安全与运维考量

| 关注点 | 结论 |
|---|---|
| XSS | 仅布局改动，无新 HTML 注入点 |
| 上传安全 | 白名单 + magic 校验 + UUID + 大小限制均在既有实现，本次不动 |
| 性能 | sticky 只影响合成层，无重排开销 |
| 可维护性 | 每处 3-6 行，注释写清「为什么 sticky」「为什么 2100」「为什么不吸底」 |
| 回滚 | 单文件纯 CSS，revert 一个提交 |
| VTJ 一致性 | 改后跑 `vtj_check_consistency`：`forum` 为 raw，**禁止同步**，只确认版本号未变 |
| 验证方式 | 必须 Playwright 实机打开弹窗断言，不靠读代码 |

## 7. 风险

| # | 风险 | 对策 |
|---|---|---|
| 1 | sticky 未生效（出现未知 overflow 祖先） | 实施第一步先跑 §6-1/2；失败则改「吸顶工具条」方案（需 R3 授权） |
| 2 | `:has()` 老内核不支持 | `@supports` 兜底，行为与现状一致 |
| 3 | sticky 遮住最后一条评论 | `.post-detail-card` 底部补内边距，由 §6-4 断言 |
| 4 | emoji 面板被固定输入区遮挡 | 面板为 `absolute; bottom: 100%`，会浮在输入区上方；目视确认 |
| 5 | 隐藏 `.upload-area` 后误删必要通道 | 提交时 `images` 与 `attachments` 都会带上；隐藏不影响已有 `attachments` 数据回显 |
