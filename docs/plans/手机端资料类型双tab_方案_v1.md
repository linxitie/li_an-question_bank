## 2. 交互设计（两级 tab）

```
┌ 备考资料 ─────────────────────────┐
│ ←                     ＋ 创建      │
├───────────────────────────────────┤
│ [ 行测 ] [ 申论 ] [ 公专 ]   ← 一级：科目
│ [讲义] [文章] [卡片] [试卷]  ← 二级：资料类型（本批新增）
├───────────────────────────────────┤
│ 内容区（按二级 tab 渲染）：
│  · 讲义 → 纵向卡片：N 章·M 字 / 共 N 份原件 /〔在线阅读〕〔下载原件〕
│  · 试卷 → 纵向卡片：年份·地区·卷别｜题量·分值·时长｜编号 /
│           〔下载原卷〕〔去考试｜暂不可考+原因〕
│  · 卡片 → 3D 卡片栈（现有）+ 下方列表
│  · 文章 → 列表：标题 + 摘要 + 阅读时间，点开弹层读正文
│  · 空   → 「无资料」+ 具体说明
└───────────────────────────────────┘
```

| 行为 | 规则 |
|---|---|
| 切科目 | 保持当前类型 tab；若新科目该类型无数据 → 空态（不自动跳 tab，避免"我点的明明没变"） |
| 切类型 | 关闭已打开的详情弹层（避免串味），重新拉该类型列表 |
| 默认 tab | **卡片**（内容最多：37/26/36 条；若默认"讲义"则三科全空，第一眼像坏了） |
| 记住选择 | 可选（`sessionStorage`），默认不记忆，避免"上次选了空 tab，下次进来还是空"的困惑 |
| 深链 | `?subject=&type=`；非法值回落到默认（科目→行测、类型→卡片） |

## 3. 与 L3 横滑区的关系（关键决策）

L3 的两个横滑区（讲义/试卷）本质是"在一屏里同时展示全部类型"的方案。加了二级 tab 之后，**同一份资料会在横滑区和 tab 列表里各出现一次**。

| 选项 | 结果 | 我的建议 |
|---|---|---|
| **A 移除两个横滑区**，内容完全由二级 tab 决定 | 一个入口、无重复；但"一屏概览"消失 | ✅ **推荐** |
| B 保留横滑区，只在"卡片"tab 下显示 | 逻辑别扭（卡片页顶上挂讲义/试卷） | ❌ |
| C 保留横滑区，二级 tab 只过滤下面的列表 | 讲义/试卷在页内出现两次，重复且难解释 | ❌ |

## 5. 安全 / 运维 / 可维护（自检）

| 问题 | 回答 |
|---|---|
| 安全 | 纯前端过滤展示，权限仍由后端 `status=1 + placement` 决定；深链非法值只做回落，不拼 SQL/不新增接口 |
| 运维 | 二级 tab 的配置集中在一个常量（`MOBILE_TYPE_TABS`），加"视频"tab 只改数组 + 一个 case；空态文案统一由 `emptyTextOf()` 生成，不会各写一份 |
| 可维护 | 与 PC 共用同一批文案函数（`paperMetaLine/lectureMetaLine/canExam/examHint`），避免"PC 说可考、手机说不可考" |
| 前端渲染 | 全部普通 Vue 组件，`el-dialog` 已确认不可用（L2 踩过）→ 详情仍用页面自有弹层 |
| 后端字段 | 不需要新字段：`type` 已是列表查询参数；数量/空态由 `total` 判断 |
