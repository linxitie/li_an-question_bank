## §2 侧栏固定（P1）

**根因（实测证据）**：`.admin-layout` 原为 `min-height:100vh`，内容变长时 document 随之变高，滚动发生在 document 上，侧栏 `position:sticky` 在内容高度撑开的父容器里跟着走。

对照实验（Playwright 真实浏览器读数）：

| 状态 | `getComputedStyle(.admin-layout).height` | 断言结果 |
|---|---|---|
| 修复前 | **7903px**（内容高） | 失败（期望 900） |
| 修复后 | **900px**（视口高） | 通过 |

修复：`.admin-layout { height:100vh; overflow:hidden }`，`.admin-main` 保持 `overflow-y:auto` 成为唯一滚动容器。**侧栏样式未动一个像素**（按用户「保留最初的左侧导航栏样式」）。

## §3 管理员端论坛改版（P3a）

设计稿：`C:\Users\31127\WorkBuddy\2026-11-02-08-43-15\design\admin-forum-final.html`（1490 行）。
采用「CSS 视觉语言照搬 + 模板重写为静态 Vue 标记 + 真实接口驱动」的做法，未引入新依赖（图表留给 3b，用仓库已有 `@vtj/charts`）。

### 3.1 前端
- 页面骨架：`page-head`（标题+描述+导出报表）、`tabs`（内容管理 / 待复核(n) / 回收站(n)）、`filterbar`（搜索 / 班级 / 状态 / 日期区间 / 批量按钮）、`table-wrap`（复选列 + 帖子内容 + 作者 + 班级 + 状态 pill + 时间 + 行内操作）、`pager`。
- 抽屉：帖子详情 + 浏览/点赞/评论/收藏统计 + 管理操作（置顶/取消置顶、隐藏/取消隐藏、删除）+ 评论区（可删评论）。
- 弹窗：隐藏/删除/恢复/彻底删除/批量隐藏/批量删除，危险操作独立配色 + 二次确认 + 原因留痕。
- 导出报表：纯前端 CSV（BOM + 防止 Excel 乱码），不新增后端接口。

### 3.2 后端新增/扩展（`forum_moderation.py`）
| 接口 | 说明 |
|---|---|
| `POST /api/admin/forum/posts/{id}/hide` | 管理员隐藏，直接 APPROVED，不进待复核队列 |
| `POST /api/admin/forum/posts/{id}/unhide` | 取消隐藏，并把该帖残留的 PENDING 复核记录一并驳回 |
| `POST /api/admin/forum/posts/{id}/pin` | 置顶 / 取消置顶（复用已存在的 `forum_post.is_top`） |
| `POST /api/admin/forum/posts/batch` | 批量 hide/unhide/delete/restore/purge，逐条执行、单条失败跳过，返回 `affected/skipped` |
| `GET /api/admin/forum/posts` | **扩展** `date_from` / `date_to`；keyword 同时命中作者昵称/账号；返回 `classes` 供班级筛选 |
| `GET /api/admin/forum/recycle` | **扩展** `kind` / `status` / `keyword` / `offset` / `limit`，返回 `totalPosts` / `totalComments` |

**去重**：原有单条 delete/restore/purge 三处实现改为委托同一组 `_admin_*_post` 助手，避免「单条」与「批量」两条路径的软删除语义漂移。

### 3.3 数据看板（P3b，用户批准「先 3a 再 3b」后补齐）

新增聚合端点 `GET /api/admin/forum/dashboard?days=7|30|180`，一次返回 KPI / 趋势 / 班级分布 / 关键词 / 科目热度 / 违规处理 / 风险提示：

| 区块 | 口径（写进代码注释，避免「看起来对」） |
|---|---|
| KPI | 发帖量、评论量、待复核、已隐藏、已删除、覆盖班级；发帖/评论带**环比**（上期为 0 时返回 `null`，前端显示「—」，不编造无穷增长） |
| 发帖/评论趋势 | 按 `forum_post.create_time` / `forum_comment.create_time` 逐日分桶，**含已被隐藏/删除的帖子**（管理端要看「发生过什么」） |
| 班级分布 | 按作者 `sys_user.class_name` 聚合，TOP 6 + 其他 |
| 关键词 | `jieba` 分词 + 停用词 + 纯中文且长度 ≥2，TOP 22 |
| 科目热度 | 帖子标题/正文命中科目关键词的条数（帖子无科目外键，这是可解释的近似口径） |
| 违规处理量 | `forum_moderation.created_at` 按 ISO 周聚合，删除/隐藏分线，近 8 周 |
| 风险提示 | 全部由真实计数推导：超 7 天未复核 → 高；窗口内隐藏/删除 → 中；高频词集中度 → 低 |

前端：4 个页签（数据看板为默认页签，符合设计稿）、时间范围分段控件（近 7 天 / 近 30 天 / 本学期）、6 张 KPI 卡、5 个图表区（趋势/环形/词云/条形/柱状）+ 风险列表；图表用仓库既有 `@vtj/charts` 的 `XChart`，**未新增前端依赖**。

两处实现细节（都是实测踩出来的）：
1. 图表 `:key` 绑定数据版本号强制重建——ECharts 在容器完成布局前初始化会把半径算成 0，环形图会「消失」；
2. `animation: false`——否则截图/首屏抓在第 0 帧，折线与饼图看起来是空白。

**词云排版（三次迭代后的终版）**：
- 第 1 版做过「整行居中」的 flex 词云，被用户否掉——那是对齐成行的，不是词云该有的**杂乱分布**；
- 第 2 版做成随机撒点，被用户否掉——要求**热度最高的词居中、其余按热度递减由内向外散开**；
- 终版是**中心向外辐射的散点词云**：`layoutCloud()` 按词频降序逐个摆放，每个词在「以画布中心为起点、角度步进 ≈12.8°」的螺旋上找第一个不重叠的位置——所以 #1 词永远落在正中，热度越低半径越大；
- 字宽用 canvas `measureText` 实测（中英文混排不失真），字号 15–40px 按词频开方插值；放不下就缩字号重试（最多 5 档），仍放不下则丢弃该词（宁可少一个词，也不叠字）；
- 横向椭圆系数 `kx` 上限压到 **1.6**：直接按卡片宽高比拉伸会让词全部沿横向排队、上下大片留白（实测踩过）；
- 每个词的起始角用黄金角递增，避免所有词沿同一根轴对齐；窗口 resize 时防抖重排；
- 词频数字不显示，改为 `title` 悬浮提示；
- 防回归（Playwright 断言）：纵向 y 坐标离散度 > 5（证明不是整行）、字号至少 3 档、每个词外框都在画布内（不被裁切）、**词频最高的词离画布中心最近**、**后半段平均半径 > 前半段平均半径**（证明由内向外）。

**口径现状**：当前库里 34 篇帖子多为历史测试帖，所以「科目热度」四行全是 0（帖子正文没有科目词），关键词里出现「验证/预览/脚本」等测试痕迹词——**这是真实数据，不是 bug**；已把「无标题」「测试」这类结构性噪声词加入停用词。

### 4.5 回归修复（用户报障后补）

**故障 1：三端发帖弹窗上传图片全部 405 Method Not Allowed**

根因（实测取证）：`backend/app/main.py:22` 只 `from ... import image_media`，**从未 `include_router(image_media.router)`**；而 `/api/media/{asset_id}`（GET）已注册，于是 `POST /api/media/image` 路径被动态路由先匹配、方法不匹配 → **405**。这个 bug 一直潜伏（`FileUploader` 也走同一端点），本轮统一弹窗把所有图片都走这条路才暴露。

修复：`main.py` 在 `media.assets` 之前注册 `image_media.router`，并写明注释「精确路径必须在动态路径之前」。验证：`openapi.json` 中 `/api/media/image` 变为 POST 方法；学生 / 教师 / 管理员三个身份实测上传均 **HTTP 200**；学生手机端的 `FileUploader` 走的也是同一端点（全前端仅 `imageUtils.ts:49` 一处引用），一并修复。

**故障 2：管理员端「内容管理」看不到图片与表情包、不能发评论**

- 图片与表情包：重写时把「正文/附件」渲染成了纯文本摘要，丢了 `ImageGrid`/`AttachmentList`。现改为：正文去掉 `[[sticker:url]]` 后作文本摘要，图片（表情包 + 图片附件，**按 URL 去重**）交 `ImageGrid`，非图片附件交 `AttachmentList`；抽屉里同样处理。去重是必须的——同一张图既在正文当表情包、又在附件里，会重复渲染三次（实测踩到）。
- 管理员评论：抽屉里此前只能看/删评论，现补「以管理员身份评论」输入框（`POST /api/forum/posts/{id}/comments`），发送后即时刷新评论列表。
- 列表缩略图加 `max-width: 200px`：`ImageGrid` 的 `mode-post` 是三等分网格，在宽表格里会把图撑到 180px+。

## §6 环境变更与注意事项

1. **新增开发依赖** `@playwright/test@1.64.1` + Chromium 1248（118MB）。测试放 `e2e/`、配置 `playwright.config.ts`，均在 `tsconfig include("src")` 与 vitest `include("src/**")` 之外，不影响既有两道闸。
2. **新增后端依赖** `jieba==0.42.1`（已写入 `backend/requirements.txt`）。默认 PyPI 源在本机无响应，实际用清华镜像安装：`pip install -i https://pypi.tuna.tsinghua.edu.cn/simple jieba`。首次分词会构建词典缓存（约 0.5s），之后走缓存。
3. **后端启动方式**：`--reload` 会监视到 `backend/data/*.sqlite` 写入而反复重启，表现为「socket 占着、请求全挂」。本轮实为此症状，已改为**无 `--reload`**（与交接说明一致）：改后端必须手动重启 8000。
4. **dev server（9527）**：安装依赖后 Vite 预构建失效（页面 504 `Outdated Optimize Dep` → 白屏），需重启 dev server 才会恢复；仅刷新不够。
5. **工作区仍有非本轮改动**：`backend/app/services/scheduler.py`（他人 / 上一轮遗留），本轮未触碰。
