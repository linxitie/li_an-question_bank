## 3. 数据与状态语义（本方案的地基）

### 3.1 新增一个字段，不加表

```python
# models.py · StudyMaterial
placement = Column(String(10), default="library", index=True,
                   comment="投放位: exam=仅考试页 / library=仅资料页 / both=都投（仅 type=paper 有意义）")
```

- 非试卷类（article/lecture/card/video_*）恒为 `library`；
- 试卷类默认 **`both`**（迁移时按现有 3 条卷回填 `both`，行为与今天完全一致）；
- 启动期自动补列（沿用 `main.py:325` 那套 `ALTER TABLE ... ADD COLUMN` 的既有先例，零 Alembic）。

### 3.2 两把钥匙分开（关键设计）

| 问题 | 由谁决定 | 规则 |
|---|---|---|
| 学生能不能**在资料页看到/下载** | `status==1` **且** `placement ∈ {library, both}` | 列表/详情/下载三处同一判据，避免"列表有、点开 404" |
| 学生能不能**在考试页考** | `exam_paper.paper_type == 'PUBLISHED'` **且** `placement ∈ {exam, both}` | 由 P5 在"资料状态变化"时按 placement 计算，**不新增第二个发布入口** |

P5 改动就一行判断：

```python
exam_side = (getattr(material, "placement", "library") or "library") in ("exam", "both")
visible = exam_side and (material.status == 1 or _has_other_published(db, code, material.material_id))
```

> 为什么这么做：你要求的"仅考试页"意味着资料不能出现在资料库，但卷要能考；"仅资料页"意味着资料要在库、但卷不能考。**现状 P5 把两件事绑死了**，所以必须由 placement 拆开。`ENDED` 不复活、一码多资料、软删即下架这些既有语义全部保留（只多一个 `exam_side` 与条件）。

### 3.3 三种投放位的完整行为矩阵

| placement | 上传后 | 上架后 资料页 | 上架后 考试页 | 下架/删除后 |
|---|---|---|---|---|
| `exam` 仅考试 | `status=0`、留档原件 | ❌ 不出现 | ✅ 卷 PUBLISHED（需已有题） | 卷回 DRAFT（学生已考成绩不受影响） |
| `library` 仅资料 | `status=0`、留档原件 | ✅ 出现、可下载原件 | ❌ 卷保持/置 DRAFT | 资料消失 |
| `both` 都投 | 同上 | ✅ | ✅ | 两边同时收 |

**边界（要你确认，见 §8 D-L3）**：`exam` 模式下原件仍留档在 `backend/storage/material_files/`，只有管理员能下；资料页不露出。

## 4. 学生端三端页面设计

### 4.1 为什么必须是"手写新页"而不是改 `.vtj`

- R3：`.vtj` 页 `<template>` AI 不许改；
- 实测 `.vtj/files/materials_gongzhuan.json` 的 DSL 只有标题 div，与 `.vtj/vue` 里的真实模板不一致 → 即便改模板，设计器一次回存就会覆盖；
- 仓库已有先例：管理端新页 `src/views/admin/materials.vue` 就是为绕开 R3 手写的。

**做法**：新增 `src/views/student/materials.vue`，把三条既有路由的 component 换掉（路由**条数不变**，L6/L7 的 105 不受影响）：

```ts
{ path: '/materials/xingce',    name: 'MaterialsXingce',    component: () => import('@/views/student/materials.vue') },
{ path: '/materials/shenlun',    name: 'MaterialsShenlun',    component: () => import('@/views/student/materials.vue') },
{ path: '/materials/gongzhuan',  name: 'MaterialsGongzhuan',  component: () => import('@/views/student/materials.vue') },
// 旧 $vtj/vue/materials_*.vue 不删除（R1），文件仍在，回滚=路由改回去
```

### 4.2 分区结构（六个区，顺序即心智模型）

| 区 | 数据来源 | 卡片交互 |
|---|---|---|
| 入门讲解视频 | `type=video_intro` | 弹窗 `<video>`（沿用现逻辑） |
| 深度拓展视频 | `type=video_advanced` | 同上 |
| 备考指南（文章） | `type=article` | 弹窗读正文（`v-html` 消毒后） |
| **讲义（新增）** | `type=lecture` | 抽屉：元数据 + 〔在线阅读〕(有 content) + 〔下载原件〕 |
| **试卷资料（新增）** | `type=paper` 且 `placement∈{library,both}` | 抽屉：年份/地区/卷别/题量/总分/时长/编号 + 〔下载原件〕+〔去考试〕(若卷 PUBLISHED) |
| 知识卡片 | `type=card` | 3D 翻转（沿用现逻辑） |

- 每区默认折叠到 4 条 + "展开全部"，沿用现有 `sections()/list()/folded` 交互；
- 空区不渲染；整页空才显示"资料制作中"；
- 「下载原件」调用 `GET /api/materials/files/{file_id}/download`（已存在，带 token）；前端用 `fetch + blob` 触发下载（**不新增端点**）。

| 端 | 文件 | 本批改动 |

| 手机 | `src/views/student/mobile/mobile_materials.vue`（手写，可改） | 加「讲义」「试卷资料」两个横滑区 + 下载按钮；`typeName()` 补 `lecture/paper` 中文名 |

### 4.4 后端要补的响应字段（不改端点，只加字段）

| 位置 | 新增 | 用途 |
|---|---|---|
| `_item_brief` | `placement`、`has_files`、`file_count` | 列表就能决定"要不要显示下载按钮"，不必逐条拉详情 |

## 6. 文章批量上传

### 6.1 为什么走"解析导入"而不是"文件留档"

文章的学生端阅读依赖 `content`（HTML）。`POST /admin/files/upload` **只留档不解析**（B2 定位），若走它，批量传上来的文章学生点开是空白（讲义今天就是这个状态，实测 `content=0`）。解析链路能产出真正文，且自带三重保护（同文件 409 / 同内容 409 / 格式校验）。

### 6.2 实现

- 新增入口：管理端「批量上传文章」按钮 → `ArticleBatchUpload.vue`（复用 `batchUploadPlan` 的选文件编排：50 文件/2GB/去重/配对）；
- 队列里每个文件依次：
  1. `POST /api/materials/admin/import/upload`（multipart）
  2. 轮询 `GET /admin/import/{id}/status`（3s，最多 120s；扫描 PDF 会走 OCR 分支，未就绪则失败）
  3. `POST /api/materials/admin/import/{id}/confirm`，body：`{subject, type:'article', title, publish:false}`
- 结果列：成功（含 material_id）/ 跳过（重复 409）/ 失败（原因：格式、扫描件、超限、内容为空）；
- 全部完成后提示"已创建 N 条（未上架），去列表上架"。

### 6.3 已知限制（写进 UI 文案，不藏）

| 限制 | 说明 |
|---|---|
| 扫描版 PDF | 需要 OCR（mineru）；未就绪时明确失败并提示"转存为 Word 再传" |
| 单文件 20MB | 与 B2 一致 |
| 正文质量 | docx 的标题层级会尽量保留为 `<h1-3>`；纯排版复杂文档可能有折行/表格失真（现有 `material_parser` 的能力边界） |
| 每文件 2 个请求 + 轮询 | 50 个文件时约 1–3 分钟；队列逐条显示进度，不做"一个大请求" |
