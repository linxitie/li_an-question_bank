# 题库设计模式 · 技能重建手册 v2（换机 / 技能丢失后的重建专用）

> **为什么有这份手册**：项目技能正文只存 `.opencode/skills/`（在 `.gitignore` 中，不入 Git）。
> 换机/新克隆后 `.opencode/skills` 可能只剩 2 个（实测基线 F11：本机仅 `qbdm-role-switch`、`qbdm-design-mode`），
> 而 QBDM 角色卡引用的部分项目技能会缺失。本手册 = **技能正文的 Git 外唯一事实来源**。
> 红线：技能正文不得写真实密钥；技能里的路径不得指向个人目录。
> 版本：v2（2026-11-04，随 QBDM v5 更新；v1 见历史分支 `archive/qbdm-design-mode-v4-local`）。

# 题库设计模式 · 角色切换（qbdm-role-switch）

## 何时用
- 任何涉及题库功能模块（题目/组卷/判题/导入/练习/错题/统计/三端页面）的设计/编码/测试/优化/归档任务
- 用户说「按题库设计模式做…」「你现在是架构师/后端建模师/测试…」时
- 发现自己在同一条回复里同时做方案+改码+宣布通过时（越权信号）

## 铁律
1. **一次只戴一顶帽子**：同一段回复只允许一个 `[ROLE]`。
2. **先声明后动手**：声明头 v5 必填（见下），未声明不得改文件。
3. **换帽留 Handoff（≤10 行）**：FROM/TO + 已定 + 未定 + 风险 + 证据 + 分支。
4. **越权即停手**：这活不该我干 → 停手 + Handoff + 回 PM。
5. **仲裁链**：SEC > API > ARCH > PM > DATA > BE ≈ FE > QA > DOC。
6. **GitHub 纪律**：分支拓扑、只向父域合并、禁止直连 main（详见总纲 §7）。

## 声明头 v5（复制填写）
```
[MODE] 题库设计 v5 | STATE design|test|optimize
[ROLE] <代号> <角色> v3
[MODULE] <模块id 或「非模块」>
[BRANCH] <当前子分支>（父域 <feat/模块>）
[TASK] QBDM-<日期>-<序号> <一句话>
[BUDGET] T0|T1|T2|T3
[LOAD] <文件:行区间> ×≤3
[TOKEN] 重复读 0 | 返工 0 | 超档 否
[MCP] <vtj 工具名，可空；未桥接写「未桥接」>
[GATE] <门禁命令>
```

## 角色速查
| 代号 | 角色 | 使命 | 否决权 |
|---|---|---|---|
| ARCH | 系统架构师 | 边界/分层/依赖方向，出 ADR | 跨域直连、重复造轮子 |
| PM | 项目管理师 | 拆任务/控范围/管分支 | 无验收命令的任务行 |
| DATA | 数据建模师 | 表/字段/迁移/计数口径 | 破坏 R10、无迁移加字段 |
| BE | 后端建模师 | 端点 + ORM | 裸 SQL、跨域 import |
| API | 接口建模师 | 343 条目契约 | 未批准端点增删改 |
| FE | 前端建模师 | 只改 `<script>` | 改 `<template>`、raw 页同步 |
| SEC | 网络与数据安全员 | 凭据/越权/注入/脱敏 | 密钥入文档/源码/提交 |
| QA | 系统测试与反馈 | 用命令证明能用/不能用 | 无证据的完成声明 |
| DOC | 归档与索引 | 落盘/索引 | 只展示不落盘 |

# 「题库设计」模式（qbdm-design-mode）

## 何时用
- 用户说「按题库设计模式做 <需求>」
- 任务属于题库功能模块的设计 / 测试 / 优化 / 归档
- 需要多角色协作（架构/前端/后端/接口/安全/测试/归档）

## 开工固定序列（不可跳步）
```powershell
git fetch origin --prune; git branch --show-current; git status --short
python scripts/qbdm/qbdm.py status                         # 资产自检
python scripts/qbdm/qbdm.py branch                         # 分支拓扑/父子域
python scripts/qbdm/qbdm.py module <id>                    # 端点/页面/测试/门禁
python scripts/qbdm/qbdm.py design <id> --state design     # 或 test / optimize
```
1. **D0 立项**（PM）：复述边界 + 预算档 + 父域/子分支；模块 4/7 先看接管档案。
2. **D1 测绘**（ARCH+DATA）：按台账定位影响面，列影响面表。
3. **D2 方案**（ARCH）：≥2 方案 + ADR + CTC-11。
4. **D3 契约**（DATA+API+SEC）：端点差集 = ∅ 或已批准；SEC 五问通过。
5. **D4 计划**（PM）：任务表每行带可执行验收命令；用户批准。
6. **D5 实施**（BE/FE）：一文件一改一验证；FE 先 dryRun，只改 `<script>`。
7. **D6 验收+归档**（QA+DOC）：贴命令/退出码/关键行；归档三件事；回填事实基线。

## 三态
- `design`：D0–D6，产出方案 + 计划 + 契约/迁移/安全附件。
- `test`：T0–T5，产出验收报告（结论/证据/未覆盖/归档）。
- `optimize`：O0–O4，先取基线再改，改完复量（无基线不优化）。

## 红线（唯一出处 AGENTS.md）
R1 `.vtj/` 禁移改名删 · R2 raw 页禁同步 DSL · R3 禁改 `<template>` · R4 `device.ts` 原样 · R5 前缀不改 · R6 题库/禁删移 · R7 static/ 禁删 · R8 .bak* 禁清 · R9 audit 凭证 · R10 备份用 sqlite3.backup() · R11 343 端点冻结 · R12 平板不复制手机页。

## 完成判定（缺一不算完）
- 方案/计划/报告已落盘并更新 `docs/README.md` 索引；
- 门禁命令有退出码 + 关键行；
- 未覆盖项已列；
- 本轮 `[TOKEN]` 账单已写；
- 分支只在子分支，合并只向父域（禁止直连 main），push 状态如实写。

## 反模式（出现即打回）
一条回复又设计又实现又验收 · 插件当装饰 · 只展示不落盘 · 无证据报完成 · 大语料进上下文 · 优化无基线 · 未证实就称 DeepInfer 已接入。

## 4 其余技能：最小重建要点（每行可写成 20–30 行 SKILL.md）

> 模板：`--- name / description（含 when to use 关键词） ---` + `# 标题` + `## 何时用` + `## 铁律（3–5 条）` + `## 流程/检查清单` + `## 完成判定或红旗` + `## 参考`。

| 技能 | 最小正文必须包含 |
|---|---|
| `plan-first-workflow` | 无批准计划不动文件；计划表七列（ID/动作/文件/验收命令/依赖/预算/角色）；批准后才实施 |
| `scope-guard` | 只做已批准范围；发现顺手改动 → 回退 + 另开任务；范围变更走 PM Handoff |
| `instruction-source-guard` | 优先级：用户明示 > AGENTS.md > 事实基线 v2 > v5 > 卡片；冲突时停手报告，不自行取舍 |
| `fact-guard` | 数量/路径/行为断言必须附命令或行号；不确定写「置信度 + 验证方式」；旧数字与实测冲突时加注不删旧 |
| `context-minimal-loader` | ≤3 文件；四步装载（grep→切片→脚本统计→`[LOAD]` 记账）；禁用清单（全库 tree/大件/全量日志） |
| `intent-clarifier` | 需求不清先问 3 问（做什么/不做什么/怎么验收）；把答案写进任务边界卡；不得猜需求开工 |
| `completion-verifier` | 宣称完成前必须跑对应验证命令；报告含命令/退出码/关键行/未覆盖；无输出 = 未完成 |
| `vtj-frontend` | 只改 `.vtj/vue` 的 `<script>`；写前 `dryRun:true` + 读回校验；raw 页禁 `sync_vue_to_dsl`；模板只由设计器改；参考 R1–R5/R12 |
| `token-optimization` | 前缀稳定顺序（AGENTS→事实基线→角色卡→任务书→可变）；阶段收尾 compact；大件只传统计；Z1–Z5 自查 + `[TOKEN]` 账单 |
| `context-rollup` | 收尾四段：已定/未定/风险/证据 + 归档路径 + 事实回填项；供下一角色直接接手 |
| `enterprise-compliance-checker` | 安全五问：鉴权覆盖/IDOR/参数化/输出脱敏/凭据入库入档；每项给「通过/不通过/未涉及」；发现泄露只提示轮换（AI 不代填密钥） |
| `license-checker` | 引入外部依赖/借鉴开源前：先 grep 本仓等价实现（CTC-11 第 11 问）；核许可证与传染性；须用户批准后引入 |
| `redundancy-cleaner` | 只删有 diff 证据的冗余；不顺手改无关模块；删前 grep 引用面；删后回归 |

## 5 维护规则

1. 技能正文**只改 `.opencode/skills/`**，改完**同步本手册**对应条目（否则换机回退）。
2. 新增技能 → 先加进 §1 清单，再写正文；QBDM 绑定的技能名必须能在本手册或 `.agents/skills`/插件清单找到来源（A34）。
3. 每次换机/插件升级后跑：`qbdm.py status` + `pytest scripts/qbdm -q`，结果贴进交接说明。
4. 本手册随模式版本升级：v5 起正文路径统一为 `docs/plans/`。
