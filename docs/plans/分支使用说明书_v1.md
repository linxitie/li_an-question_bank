## 红线速查（开工前必读）

违反以下任一条即视为破坏性改动，必须停手并向集成负责人确认，不得“先改了再说”。

| 编号 | 红线 | 你必须怎么做 |
|---|---|---|
| **R1** | `.vtj/` 禁止移动、改名、删除 | 页面文件原地不动。`src/router/index.ts` 有 92 处 `import('$vtj/vue/<id>.vue')` 硬绑定，`git status` 出现 `.vtj` 的 `R`/`D` 一律回滚 |
| **R3** | `.vtj/vue/*.vue` 的 `<template>` 禁止 AI/开发者直接改 | 模板改动只在设计器 `http://localhost:9527/__vtj__/` 里拖拽完成；脚本改动只改 `<script>`，且先 `dryRun: true` 预览 |
| **R5** | `mobile_*`、`tablet_*` 文件名前缀禁止重命名 | 前缀是与 `.vtj/vue/` 一一对应的唯一线索，文件名零改动 |
| **R11** | `/api/v1/...` 路径冻结（343 端点） | 只允许**新增**端点；禁止改路径、改方法、改响应外壳。新增签到端点为新增路径 |
| **R12** | 平板不复刻手机页 | 不新建 `tablet_*` 重复副本；设备差异走 `meta.platform` 与 `src/utils/device.ts` |
| **版本冻结** | `@vtj/web`、`@vtj/ui`、`@vtj/charts`、`@vtj/icons`、`@vtj/utils`、`@vtj/materials`、`@vtj/pro` = **0.16.35**；`@vtj/cli` = **0.12.19** | 模块化期间不升不降；任何版本变更单独提案，不得混入模块 PR |

补充硬约束：

- `raw: true` 页面禁止调用 `vtj_sync_vue_to_dsl`（同步器提取不到手写方法，会丢代码）。
- 跨域禁止 `import` 他域外壳（见第 5 章）。
- `localStorage` 只存 UI 偏好（主题、字号、列表密度、筛选标签），禁存金币余额、错题列表、成就进度、签到状态。
- 不新建表、不改表结构（签到复用 `badge_task` 的 `t_type=daily`）。
- 不删除、不移动 `题库/`、`backend/app/static/`、`backend/data/*.bak*`、`backend/data/audit/`。

## 第一章 环境准备

目标：半天内跑通「后端 + 前端 + 设计器」三件套，并能打开 `http://localhost:9527/__vtj__/`。

### 1.1 版本基线

| 组件 | 要求 | 本项目实测 |
|---|---|---|
| Node.js | ≥ 20（建议用 LTS） | v24.14.0 |
| npm | 随 Node 安装 | 随 Node 安装 |
| Python | ≥ 3.10 | 3.13.5 |
| Git | 任意近期版本 | — |

检查命令（workspace root）：

```powershell
node -v
npm -v
python --version
git --version
```

### 1.2 克隆仓库

本地路径固定为 `D:\砺安题库\砺安题库`，不要放到其他目录（`vite.config.ts` 强制校验工作区根，从别的目录启动会直接抛错）。

```powershell
git clone <团队 Git 仓库地址> D:\砺安题库\砺安题库
cd D:\砺安题库\砺安题库
```

仓库地址由团队管理员提供。已经克隆过的同学跳过本节，直接 `git switch <基线分支>` 并 `git pull --ff-only`。

### 1.3 后端依赖与启动

```powershell
cd D:\砺安题库\砺安题库\backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python start.py
```

- 启动脚本：`backend/start.py`，内部以 `uvicorn app.main:app --host 0.0.0.0 --port 8000` 拉起服务。
- 访问地址：`http://localhost:8000`；健康检查：`http://localhost:8000/health`。
- 接口文档：`http://localhost:8000/docs`。
- 数据库：`backend/data/question_bank.db`（SQLite，WAL 模式，约 316 MB）。首次启动若库不存在会走初始化，需等待较久。`-wal` / `-shm` 是同库的一部分，**禁止手工删除或拷贝主库替代备份**（R10：备份必须用 `sqlite3.backup()`）。
- PowerShell 若禁止激活脚本，先执行 `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass`，再 `Activate.ps1`。

健康检查：

```powershell
Invoke-WebRequest http://localhost:8000/health -UseBasicParsing
```

返回 200 即后端就绪。

### 1.4 前端依赖与启动

另开一个终端（保持后端运行）：

```powershell
cd D:\砺安题库\砺安题库
npm install
npm run dev
```

- 依赖锁定场景用 `npm ci`（严格按 lock 安装，不产生版本漂移）；日常开发用 `npm install`。
- 开发服务器端口固定 **9527**（`vite.config.ts` 中 `DEV_PORT = 9527`），访问 `http://localhost:9527`。
- 前端通过 `proxy.config.ts` 把 `/api/v1` 代理到 `http://localhost:8000`，因此后端未启动时页面接口全 404 或 502。
- 生产构建：`npm run build`（内部走 `typecheck:guarded` + `vite build`）。

### 1.5 VTJ 设计器（单实例）

设计器挂在开发服务器同一端口的 `/__vtj__/` 路径下，因此**必须先起 `npm run dev`**。

首次准备并启动本地 VTJ MCP 服务：

```powershell
cd D:\砺安题库\砺安题库
npm run mcp:setup
npm run mcp:start
```

打开设计器：

```
http://localhost:9527/__vtj__/
```

约定：

- MCP 服务与设计器使用**仓库内唯一一份** `D:\砺安题库\砺安题库\vtj-mcp-server`。**不要复制到其他目录**，不要为每个人建一份副本——副本之间会争抢 `.vtj/files/` 写入，造成 DSL 节点树损坏。
- 同一时间只允许一个设计器实例写入 `.vtj/files/`。
- 确需并行编辑时，各自在本地启动同一份代码的设计器，但**只打开自己域内的页面**；不同页面写不同 `.vtj/files/<id>.json`，天然无冲突。
- 设计器启动前先 `git pull --ff-only`；关闭前确认已保存并提交。

### 1.6 常见环境错误

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动报 `Vite 必须从配置所在工作区启动：expected ... received ...` | 命令不在仓库根执行 | `cd D:\砺安题库\砺安题库` 后重跑 `npm run dev` |
| `EADDRINUSE: 9527` | 上一次 dev server 未退出 | 关闭旧终端窗口，或 `Get-NetTCPConnection -LocalPort 9527` 找到 PID 后结束进程 |
| `EADDRINUSE: 8000` | 后端已在运行或残留进程 | 复用已有后端；确需重启时先结束旧进程 |
| 页面接口 502 / 404 | 后端未启动或代理目标不可达 | 先确认 `http://localhost:8000/health` 返回 200 |
| 依赖报 `ModuleNotFoundError` | 后端依赖装到了全局 Python 或 venv 未激活 | 激活 `backend\.venv` 后重装 `requirements.txt` |
| 设计器打不开 `/__vtj__/` | dev server 未启动，或访问了错误端口 | 确认 `npm run dev` 在跑，且地址为 9527 端口 |
| `npm install` 后 VTJ 版本变了 | lock 漂移 | 立即 `git checkout -- package.json package-lock.json`，改用 `npm ci` |
| 登录后立刻被踢回登录页 | token 失效或后端 JWT 配置缺失 | 确认后端运行中、`backend/.env` 已由本人按 `.env.example` 配置（密钥值不写入任何文档、不入库） |

## 第二章 拉取与分支

### 2.1 分支模型

| 分支 | 用途 | 保护 |
|---|---|---|
| `main`（团队约定的基线分支） | 可发布基线 | **保护分支**，禁止直推，只接受 PR 合并 |
| `feat/<域>/<任务>` | 个人开发分支 | 一人一条，生命周期为单个任务 |
| `fix/<域>/<问题>` | 缺陷修复 | 同上 |

`<域>` 必须是第 3 章表中的英文短名（`identity`、`catalog`、`practice`、`records`、`papers`、`wrongbook`、`notes`、`analytics`、`community`、`news`、`calendar`、`recruitment`、`about`、`library`、`growth`、`reward`、`checkin`），不得自造别名。

命名示例：

- `feat/wrongbook/review-flow`
- `feat/growth/checkin-task`
- `fix/community/quote-pagination`

### 2.2 标准开工流程

```powershell
cd D:\砺安题库\砺安题库

# 1. 切回基线并拉取最新
git switch main
git pull --ff-only

# 2. 从最新基线切出个人分支
git switch -c feat/wrongbook/review-flow

# 3. 开发（只改自己域内的文件，见第 3 章）
git status --porcelain

# 4. 提交（信息规范见 2.3）
git add <本任务相关文件>
git commit -m "wrongbook: add review-state filter"

# 5. 合并基线到本分支（见 2.5）
git fetch origin
git merge origin/main

# 6. 推送到远端
git push -u origin feat/wrongbook/review-flow
```

### 2.3 提交信息规范

格式：`<域>: <动词> <对象>`

- 域前缀必须是英文短名，冒号后可用中文或英文。
- 示例：`wrongbook: add review-state filter`、`checkin: 新增签到状态接口`、`growth: 统一 trigger_type 常量引用`。
- 一个提交只做一件事；基础设施改动与业务改动分开提。

### 2.4 五条硬规则

1. **一人同时只保留一条活跃功能分支**，避免自己和自己冲突。
2. **分支从最新基线切出**，切出后尽快合并，生命周期建议不超过 5 个工作日。
3. **禁止 force-push**（`git push -f`），任何分支都不允许；禁止 `git reset --hard` 覆盖他人分支。
4. **禁止直推保护分支** `main`，一律走 PR。
5. **合并前必须 rebase 或 merge 基线**，禁止把落后很多的分支直接提 PR。

### 2.5 何时把基线合并进自己的分支

三种时机，缺一不可：

| 时机 | 为什么 | 命令 |
|---|---|---|
| 基线有新提交（尤其涉及共享文件）时 | 共享文件（`src/router/index.ts`、`src/stores/`、`package.json`）改动量大，拖久了冲突面扩大 | `git fetch origin; git merge origin/main` |
| 提 PR 之前 | 门禁与构建必须基于最新基线才有效 | 同上，再跑第 6 章门禁 |
| 合并前最后一次 | 确认评审期间基线没有新改动 | `git fetch origin; git log --oneline HEAD..origin/main` 为空即可 |

冲突处置见第 7 章。合并基线后必须重跑一次门禁与构建，不得沿用旧结果。

### 3.2 三条补充事实（查表前必读）

1. **页面不只在 `.vtj/vue/`。** 实测 `.vtj/vue/` 75 页，另有 19 个手写页在 `src/views/student/mobile/`、6 个在 `src/views/student/shared/`。域卡的「负责页面清单」必须同时列这两处。
2. **`.vtj/` 页面模板只能由设计器改**（R3）；`src/views/student/**` 是手写页，可改模板，但**不移动、不改名**，路由契约不变。
3. **共享页面单一主人。** 三端 `home`、`login`、「我的」归 ① 域独占；其他模块不得修改这些文件，只能通过共享 store 与事件影响首页展示。

### 3.3 「我该改哪些文件」查表方法

四步定位，禁止凭印象挑文件：

**第一步：按页面 id 找模块。** 在上表「前端页面」列搜索页面 id（如 `wrong_review`），得到模块编号 ⑥ 与域目录 `src/modules/wrongbook/`。

**第二步：确认页面物理位置。** 工作区根执行：

```powershell
Get-ChildItem .vtj/vue, src/views/student -Recurse -Filter *.vue |
  Where-Object { $_.Name -match 'wrong' } |
  Select-Object -ExpandProperty FullName
```

`.vtj/vue/` 下的页面只能改 `<script>`；`src/views/student/` 下的手写页可改模板。

**第三步：按端点找后端文件。** 查 `backend/data/refactor_baseline/api_surface.json` 确认端点归属，再定位实现：

```powershell
Get-ChildItem backend/app/api/v1 -Recurse -Filter *.py |
  Select-String -Pattern 'wrong-questions' |
  Select-Object Path, LineNumber
```

后端域目录已按 `catalog / community / content / exam / growth / identity / library / personal / platform / reward` 拆分，`api/v1` 下文件不搬家。

**第四步：对照域卡。** 打开 `src/modules/<域>/README.md`，按「负责页面清单」与「后端端点清单」逐项核对；表里没有的文件不属于你，不要顺手改。

判定归属的优先级（遇到歧义以此为准）：

1. 页面主体功能归谁，页面就归谁（`answer_page` 主体是答题，归 ③，即使它会写记录与错题）。
2. 写接口归产生数据的模块；读接口任何模块可调，但不得直接写对方表。
3. 共享页面单一主人（三端 `home`、`login`、我的 → ①）。
4. 同一 `api/v1` 文件被两个模块用到时，按「端点前缀 + 业务语义」拆分归属，消费方登记为只读。
5. 枢纽模块 ⑮ 不反向拥有业务页面。
6. ⑱⑲⑳ 现有入口在 `question_bank.vue`，该文件归 ②；三模块只拥有未来各自的独立页面与专属端点。

## 第四章 域卡模板（`src/modules/<域>/README.md`）

域卡是模块的「身份证」，七个字段缺一不可。缺字段的 PR 不予评审。

### 4.1 七个必填字段

| 字段 | 填写要求 |
|---|---|
| 负责页面清单 | 页面 id + 文件路径 + 设备端（PC / 平板 / 手机） |
| 后端端点清单 | 方法 + 路径 + 归属（拥有 / 只读） |
| store 状态契约 | 状态字段、类型、是否持久化（业务状态一律「不持久化」） |
| 发布事件清单 | 前端事件常量 + 后端 `trigger_type` |
| 订阅事件清单 | 前端事件常量 + 收到后的处理动作 |
| 测试文件位置 | 前端单测目录 + 后端 pytest 文件 |
| 三端手工验收清单 | PC / 平板 / 手机各 3..5 条可勾选动作 |

### 4.2 可复制模板

```markdown
# <域中文名>（<域英文短名>）域卡

> 模块编号：<①..⑰>　负责人：<姓名>　最后更新：<YYYY-MM-DD>
> 边界声明：本域不 import 任何其他域外壳；跨域只读共享 store 或经事件总线。

## 1. 负责页面清单

| 页面 id | 文件路径 | 设备端 | 可改范围 |
|---|---|---|---|
| <page_id> | `.vtj/vue/<page_id>.vue` | PC / 平板 / 手机 | 仅 `<script>`（模板走设计器） |
| <mobile_page> | `src/views/student/mobile/<file>.vue` | 手机 | 模板 + 脚本（不移动、不改名） |

## 2. 后端端点清单

| 方法 | 路径 | 归属 | 说明 |
|---|---|---|---|
| GET | `/api/v1/<prefix>` | 拥有 | <用途> |

## 3. store 状态契约
```

## 第五章 跨域通信规则

### 5.1 三条禁止

1. **禁止 import 他域外壳。** `src/modules/practice/` 不得 `import` `src/modules/wrongbook/` 的 `store.ts` / `api.ts` / `events.ts`。
2. **禁止跨域写。** A 域不得修改 B 域 store，也不得直接调用 B 域的写接口。正确做法：A 调自己的写接口，后端落库后通知，B 收到事件或下次拉取时自行更新。
3. **禁止组件内临时字符串事件。** 不得写 `emit('xxx')` 之类的裸字符串，事件常量必须先在 `src/stores/event-bus.ts` 登记。

### 5.2 允许的两种跨域方式

| 方式 | 用法 | 约束 |
|---|---|---|
| 读共享 store | `src/stores/auth.ts`（登录态、当前用户、角色）、`src/stores/user-profile.ts`（用户画像、金币快照） | **只读**。共享 store 的写入只能由它自己的 owner 或事件驱动完成 |
| 事件总线通知 | `src/stores/event-bus.ts` 的 `emitEvent` / `onEvent` | 只用于「已经打开着的页面」做增量刷新 |

`src/services/api/client.ts` 是**唯一** axios 实例（`baseURL` 取相对路径 `/api/v1`，走 dev 代理）。禁止任何模块 `axios.create`。

### 5.3 前端事件总线（mitt）

文件：`src/stores/event-bus.ts`。首批常量：

| 常量 | 触发方 | 语义 | 典型订阅方 |
|---|---|---|---|
| `wrong-questions:changed` | ③ 答题提交成功后 | 错题集合发生变化 | ⑥ 错题页、⑮ 成就页 |
| `reward:coins-changed` | ⑯ 兑换成功、⑮ 发放奖励后 | 金币余额变化 | ① 「我的」、⑯ 商城页、⑰ 签到结果 |
| `growth:achievement-unlocked` | ⑮ 成就解锁后 | 有新成就解锁 | ① 通知、⑮ 成就墙 |

用法（`EVENTS` 为常量表导出名，具体导出名以 `src/stores/event-bus.ts` 实际导出为准；关键是**不得写裸字符串**）：

```ts
import { emitEvent, onEvent, EVENTS } from '@/stores/event-bus'

// 发布（本域写成功后）
emitEvent(EVENTS.WRONG_QUESTIONS_CHANGED, { questionId })

// 订阅（页面挂载时注册，卸载时清理）
const off = onEvent(EVENTS.WRONG_QUESTIONS_CHANGED, () => {
  void store.refreshIncremental()
})
onUnmounted(off)
```

命名规范：`<域>:<过去式动作>`，全小写，连字符分隔，冒号仅分隔域与动作。新增常量必须在本文件登记，并在域卡「发布事件清单 / 订阅事件清单」同步。

**铁律：事件是加速器，不是正确性来源。** 任何页面 `onMounted` 必须执行一次 API 拉取；事件只做增量刷新。事件丢失、WS 断线、页面被冻结时，用户重新进入页面看到的仍是后端最新状态。

### 5.4 后端统一事件入口 `record_user_action()`

定义位置：`backend/app/services/event_consumer.py`；内部发布的事件常量为 `user.action.v1`（`events.py` 的 `EV_USER_ACTION`），由 `event_consumer.py` 长驻消费。业务模块通过它上报「我发生了什么」，**不判断「算不算成就」**。

payload 约定：

| 字段 | 含义 | 约束 |
|---|---|---|
| `user_id` | 行为主体 | 必填，来自当前登录态 |
| `trigger_type` | 行为类型，点分命名 | 必填，取值为 `app/core/trigger_types.py` 中 E1..E10 常量 |
| `session` | 会话/上下文（练习会话 id、帖子 id 等） | 可选，JSON，**只增不改**（add-only） |

十个 `trigger_type` 与来源模块：

| 事件 | 来源模块 | `trigger_type` | 成就判据示例 |
|---|---|---|---|
| E1 | ③ 答题练习 | `practice.submit` | 累计答题 N 题 |
| E2 | ④ 练习记录 | `practice.record.created` | 单日练习时长 ≥ N 分钟 |
| E3 | ⑤ 组卷 / 历年试卷 | `paper.completed` | 完成整卷 N 套 |
| E4 | ⑥ 错题集 | `wrong.reviewed` | 消灭错题 N 道 |
| E5 | ⑦ 笔记 + 收藏 | `note.created` / `favorite.added` | 笔记 N 条 / 收藏 N 条 |
| E6 | ⑨ 论坛社区 | `forum.posted` | 发帖 N 条 |
| E7 | ⑩ 每日新闻 | `news.read` | 阅读 N 篇（同篇去重） |
| E8 | ⑭ 备考资料 | `material.opened` | 学习 N 份（按资料 id 去重） |
| E9 | ⑯ 金币商城 | `shop.purchased` | 消费 N 金币 |
| E10 | ⑰ 每日签到 | `checkin.done` | 连续签到 N 天 |

调用方式（后端，常量从 `app/core/trigger_types.py` 引入，禁止写字面量）：

```python
from app.core.trigger_types import E1_PRACTICE_SUBMIT  # 常量名以 trigger_types.py 实际导出为准
from app.services.event_consumer import record_user_action

# 必须在业务事务提交之后调用，且同一业务动作只调用一次
record_user_action(user_id, E1_PRACTICE_SUBMIT, {"session": session_id})
```

使用规则：

1. **事务提交后发布。** 判分/写表在同一事务内完成，事务提交成功后再 `record_user_action`，避免发事件成功而落库回滚。
2. **`trigger_type` add-only。** 新增行为只允许追加枚举值；不修改既有值语义、不删除，历史判据才能长期稳定。
3. **幂等由消费方维护。** 去重键为 `trigger_type + session`，由成就模块维护；业务模块重复上报不应造成重复计数。
4. **⑱⑲⑳ 与纯展示模块不发事件。** ⑪ 考试日历、⑫ 招考信息、⑬ 关于砺安题库不发布、不订阅；⑱⑲⑳ 未开发，保持「功能还未开发」提醒。
5. **奖励发放单点。** 金币与成长值只由 ⑮ 发放；⑯ 的兑换扣币属于自身账务，不属于奖励发放。

### 5.5 三条非成就边

|---|---|---|---|
| E11 | ③ → ④ | 练习记录落库 | 答题提交时后端直接写记录表，写入与判分同事务，失败一起回滚；④ 只读 |

### 7.1 公共文件：只在统一窗口改

以下文件属于公共文件，多人高频改动，**只在统一窗口内修改**：

| 公共文件 | 为什么危险 |
|---|---|
| `src/router/index.ts` | 92 处 `.vtj` 动态 import，一行错位即页面 404 |
| `src/stores/auth.ts`、`src/stores/user-profile.ts`、`src/stores/event-bus.ts` | 全局契约，改动影响所有域 |
| `package.json`、`package-lock.json` | 依赖与 VTJ 版本冻结 |
| `src/main.ts` | 应用初始化（Pinia 激活顺序） |
| `src/services/api/client.ts`、`interceptors.ts`、`types.ts` | 唯一 HTTP 客户端契约 |
| `.vtj` 共享页面（三端 `home`、`login`、「我的」） | 归 ① 域独占 |

统一窗口约定：**每周二、周四 16:00–18:00**，由基础设施负责人集中受理。流程：

1. 提前一天在协作群报备「要改哪个公共文件、改什么、影响哪些域」；
2. 窗口内由该文件 owner 统一修改并提 PR；
3. 其他域在窗口后 `git merge origin/main`，重新拉取契约；
4. 窗口外发现必须紧急修改的，先找 owner 评估，不得自行改完就提 PR。

公共文件的 PR 必须单独提交（不与业务改动混合），并在描述中列出受影响的域。

### 7.2 代码冲突

```powershell
git fetch origin
git merge origin/main
# 逐个解决冲突后
git add <解决后的文件>
git merge --continue
```

规则：

- 冲突解决后**必须重跑**第 6 章门禁与构建，不得沿用冲突前的结果；
- 冲突涉及他域文件时，先联系该域负责人确认，不得凭感觉删掉对方的代码；

- 回滚一律用 `git revert <commit>`，不得为回滚而删除或重建 `.vtj/` 文件（R1）。

### 7.3 `.vtj/files` 冲突（双人改同一页面）

极端情况下两人改了同一页面（多见于联调期）：

1. 以 `.vtj/files/<id>.json` 中的 `__VERSION__` **较大者为准**；
2. 版本号相同视为冲突，必须人工比对 `nodes` 差异，由该页面所有者裁决；
3. 裁决后在设计器里重新保存一次，使 `.vue` 与 DSL 版本号一致；
4. **禁止「保留双方」手工拼接 JSON**，会造成节点树损坏；
5. 处理完必须跑 `vtj_check_consistency(id="<page_id>")`，确认版本号、方法签名、状态字段一致。

预防手段：共享页面（三端 `home`、`login`、我的）由 ① 域独占；其他域只打开自己域内的页面；编辑前先 `git pull --ff-only`。

### 7.4 lock 文件冲突

- 发生 `package-lock.json` 冲突时，**不要手工合并 lock**。
- 处理方式：`git checkout --theirs package-lock.json`（取基线版本）后，在自己的分支执行 `npm ci` 恢复，再由基础设施负责人在统一窗口把本任务确实需要的新依赖加进去。
- 依赖升级（含任何 VTJ 包、`vite`、`vue`、Element Plus）**只能走统一窗口**，并须单独提案、单独 PR，附「8 个 VTJ 版本逐项未变」或「变更项与批准记录」。
- 装完依赖后核对：`git diff package.json` 中 8 个 VTJ 版本行必须无变化。

### 7.5 冲突速查

| 冲突类型 | 处置 | 禁止 |
|---|---|---|
| 普通代码冲突 | 联系对方确认语义后手工合并，重跑门禁 | `reset --hard`、`push -f` |
| 公共文件冲突 | 找公共文件 owner 在统一窗口统一改 | 自行改公共文件后直接提 PR |
| `.vtj/files/<id>.json` 冲突 | `__VERSION__` 大者胜；相同则由页面所有者裁决；设计器重存 | 手工拼接 JSON |
| `.vue` 与 DSL 不一致 | 设计器重存一次，再 `vtj_check_consistency` | 用 `vtj_sync_vue_to_dsl` 修 `raw: true` 页面 |
| `package-lock.json` 冲突 | 取基线版本 + `npm ci`，依赖变更走统一窗口 | 手工合并 lock、随手升级 VTJ |
| 需要撤销自己的提交 | `git revert <commit>` | 删 `.vtj/` 文件后重建 |
