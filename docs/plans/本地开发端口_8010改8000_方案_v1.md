# 本地开发后端端口 8010 → 8000 —— 变更方案 v1

> 状态：**✅ 已执行并验收（2026-11-02，分支 `chore/dev-port-8000`）**
> 触发：用户「能否把本机上运行的后端改到 8000 端口」 + 上一轮门禁 L4 因默认探测 8000 而报错

---

## 0. 结论：能，而且 8000 本来就是这套工程的「默认口径」

实测三处默认值本来都是 8000，8010 只是 `scripts/dev-restart.ps1` 这一个脚本引入的：

| 位置 | 默认端口 | 说明 |
|---|---|---|
| `backend/start.py:21` | **8000** | `uvicorn … --port 8000` |
| `proxy.config.ts:5` | **8000** | `DEFAULT_BACKEND_ORIGIN = 'http://127.0.0.1:8000'` |
| `backend/scripts/gates/gate_l4_api_contract.py:7` | **8000** | `OPENAPI_URL` 默认探测地址 |
| `scripts/dev-restart.ps1:34` | **8010** | 唯一把端口改成 8010 的地方（第 132 行把它写进 `DEV_BACKEND_ORIGIN`） |

所以改成 8000 = **回到工程默认值**，顺带消掉上一轮那个「L4 必须手动带 `OPENAPI_URL`」的口径问题。

## 2. 执行步骤（批准后执行）

```text
1) git switch -c chore/dev-port-8000            # 从 main 切出，不直接改 main
2) 改 scripts/dev-restart.ps1 的 $BE_PORT
3) 批量改 16 个 verify 脚本里的 API 常量
4) 更新 2 份 ops 手册 + 加「历史文档 8010 为旧口径」注记
5) powershell -File scripts/dev-restart.ps1     # 停 8010/9527 → 起 8000/9527
6) 验证（见 §3）
7) 提交 → 合回 main（FF）
```

**中断窗口**：重启期间 9527 与 8000 各约 20–40 秒不可用（脚本自带 `/health` 等待，最多 60 秒）。

## 4. 风险与回退

| 风险 | 处置 |
|---|---|
| 8000 被别的程序占用 | 改前先探测（现测为空闲）；脚本本身有 `Stop-Port` + `Wait-PortFree` |
| 本机其它地方（浏览器收藏、桌面快捷方式、别的脚本）写死 8010 | 仓库外无法自动发现；回退只需把 `$BE_PORT` 改回 8010 并重启 |
| 历史文档里的 8010 造成误解 | ops 手册注明「旧口径」；历史报告保持原样（事后不改历史记录） |
| 重启打断你正在用的页面 | 先告知再执行；dev-restart 自带健康等待与手机端地址探测 |

回退：`git revert` 该提交 + `scripts/dev-restart.ps1` 重启即可（无数据变更，无需回滚 DB）。

### 6.3 过程踩坑（如实记录）

1. **`edit` 工具会去掉 UTF-8 BOM**：`dev-restart.ps1` 必须以「UTF-8 with BOM」保存，否则 Windows PowerShell 5.1 按 ANSI 读，中文注释直接语法报错（`Unexpected token '}'`）。本次先用 `edit` 改注释 → BOM 丢失 → 脚本报错；已用字节级补回 `EF BB BF` 并加语法检查（`[scriptblock]::Create`）确认可解析。
2. **`Start-Process` 拉起的进程会随「后台作业 shell 被终止」一起死**：第一次重启命令因工具超时被转入后台作业，随后作业被 kill，连带 uvicorn/vite 全灭（两个端口都空）。正确姿势：把脚本输出重定向到**文件**再跑（`cmd /c "... > log 2>&1"`），不要套 `| Select-Object`（管道会被子进程继承的句柄挂住，导致命令永不返回）。
3. **旧后端未被 `Stop-Port` 杀掉时会出现双后端**（8010 旧进程 + 8000 新进程同时写同一个 SQLite WAL）。本次手工核对了命令行：8000=PID 29920、8010=PID 10328，杀掉 10328 后确认 8010 释放。**教训：重启后必须核对「命令行里的 --port」而不是只看端口**，两个都活着时代理指向哪个都看不出差别。
