# 专利交底书 A：一种备考资料文档格式规范化与两级自动分类方法

> 状态：**交底书草案 v1**（供代理机构撰写申请文件用，非正式申请文本）
> 对应需求：六项需求第 (3) 项「制定一套严格的文档内容格式和系统分类机制【专利申请】」
> 技术领域：在线教育 / 教育数据处理 / 文本分类
> 撰写依据：本仓库已落地的实现（`material_format_validator.py`、`materials.py`、`material_classification_rules` 表）

---

## 1. 名称

**一种备考资料文档格式规范化与两级自动分类方法、装置及系统**

## 2. 技术领域

本发明涉及在线教育数据处理领域，尤其涉及一种面向备考资料（知识卡片、讲义、科目说明）的上传文档的**格式校验**与**分类归属**方法。

## 3. 背景技术与现有技术不足

现有在线题库/备考平台在教师或学生上传资料时，普遍存在三类问题：

| # | 现有技术 | 不足 |
|---|---|---|
| 1 | 只校验文件类型与大小（如仅允许 docx/xlsx、限 10MB） | **不校验表结构**：缺少“正面/背面”等必需列时，解析后得到全空数据，直到入库才暴露，且无法定位到具体列 |
| 2 | 逐条校验字段（标题非空、长度上限） | **先入库再报错**：批量导入时第 87 行超长会让整批回滚或产生脏数据，用户拿不到“第几行第几列错”的可操作提示 |
| 3 | 分类靠人工填 `category` 或单层关键词匹配 | **分类粒度与考纲脱节**：只到“言语理解与表达”这类**子类**，无法落到“逻辑填空”这类**考点**；一旦人工填写了考纲外的自由文本（如“方法技巧”），就形成**游离类目**，导致筛选、统计、按考点推荐全部失真 |

**核心痛点可归纳为一句**：资料上传缺少“**结构可校验、错误可定位、分类可度量**”的闭环。

## 4. 发明内容

### 4.1 技术方案总览

本发明提供一条从“上传文件”到“可检索资料”的四段式流水线：

```
① 表头归一化 → ② 分级校验（阻断/行级/警告） → ③ 两级自动分类（子类+考点）
                                                    → ④ 待审入库与词表校验
```

### 4.2 关键创新点（拟作为独立权利要求的支撑）

**创新点 1：表头别名归一 + 错误分级校验**
对表头做同义词归并（“正面/卡片正面/题目/问题/front” → 同一逻辑列），再按**错误性质分三级**处置：
- **阻断级**（缺必需列 E001、超行数 E004、扩展名/体积 E009/E010）→ 整表拒绝，不产生任何半成品数据；
- **行级**（空值 E002、超长 E003、表内重复 E005、危险标签 E008）→ **跳过该行并回报行号**，其余行正常入库；
- **警告级**（分类不在词表 E006、考点不存在 E007）→ 不阻断，回退自动分类并在响应 `warnings` 里回传行号与原值。

> 与现有技术的关键区别：同一份校验结果被**按“是否可跳过”重新归类**，从而同时满足“严格”与“不中断批量导入”两个相互冲突的需求。

**创新点 2：两级自动分类与“考点反推子类”**
分类规则同时支持**子类级**与**考点级**两种形态：

```json
{ "subject": "xingce", "category": "判断推理", "keywords": [...] }              // 子类级
{ "subject": "xingce", "category": "判断推理", "point": "图形推理", "keywords": [...] } // 考点级
```

匹配采用**两轮计分**：
1. 第一轮只匹配标题/卡片正面，得分 `(命中关键词数, 规则优先级)` 取最大；
2. 第二轮仅在某一级未命中时用“标题+正面+背面”全文兜底，避免正文偶发词把卡带偏；
3. 命中考点时**自动带出该考点所属子类**（考点 → 子类的反向映射），因此“只写考点不写子类”也是完备输入。

**创新点 3：分类法单一真源与词表闭包校验**
以 `sub_categories`（子类，16 条）与 `knowledge_point`（考点，94 条）为唯一合法词表，资料落库时强制 `category ∈ 子类词表`、`point_id ∈ 该科目考点集`；非法值返回 400 并给出**最近词建议**（编辑距离）。由此把“分类准确率”变成**可度量指标**（覆盖考点数 / 总考点数、子类命中率）。

**创新点 4：分通道的权限与状态机**
- 管理员导入：可 `publish=true` 直接上线；
- 学生上传：**强制 `status=0` 待审** + 每日次数/累计条数配额 + 内容哈希去重 + 仅本人可见，管理员审核后才公开。

### 4.3 有益效果

| 指标 | 现有技术 | 本发明 |
|---|---|---|
| 格式错误的发现时机 | 解析后/入库后 | **上传时**，且给出错误码+行号+列名 |
| 批量导入的容错 | 整批失败或产生脏数据 | 阻断级拒绝、行级跳过、警告级回退，**不会产生半成品** |
| 分类粒度 | 子类（1 级） | 子类 + 考点（**2 级**），支持考点反推子类 |
| 分类可度量性 | 无 | 考点覆盖率、子类命中率、自动分类准确率 |
| 学生上传的内容风险 | 直发公开库 | 待审 + 配额 + 去重 |

## 5. 具体实施方式

### 5.1 实施例 1：教师上传知识卡片表

输入 `cards.xlsx`（表头：正面 / 背面 / 分类 / 考点）：

| 行 | 正面 | 背面 | 分类 | 考点 |
|---|---|---|---|---|
| 1 | 图形推理 | 先看元素组成… | 判断推理 | 图形推理 |
| 2 | 逻辑填空 | 先判语境再辨词义… | （空） | （空） |
| 3 | （空） | 空正面应被跳过 | | |
| 4 | 资料分析 | 列式取数… | 方法技巧 | |

处理过程：
1. 表头归一化 → 逻辑列 `front/back/category/point`；
2. 分级校验：第 3 行触发 E002（行级）→ 跳过并记 `invalid_rows=[3]`；第 4 行分类“方法技巧”不在词表 → E006 **降级为警告**（导入场景 `category_as_warning=True`）；
3. 自动分类：第 2 行无显式分类 → 标题“逻辑填空”命中考点级规则 → 得 `point=逻辑填空`，反推 `category=言语理解与表达`；第 4 行显式分类非法 → 回退自动分类，命中“资料分析”相关考点；
4. 入库：全部 `status=0`（或按 `publish` 上线），响应返回 `created / invalid_rows / skipped / warnings`。

**实测数据（本仓库真实运行）**：94 个考点、110 条规则（16 子类 + 94 考点）；30 张真实卡片回归：**考点命中 30/30 = 100%**、**子类命中 28/30 = 93%**。

### 5.2 实施例 2：学生上传与待审

学生上传通道对同一份文件执行相同校验，但：
- 文件 ≤5MB、单次 ≤200 行、每日 ≤50 张、累计 ≤500 张；
- 所有记录 `status=0`；
- `content_hash` 与库内已有资料比对，命中则跳过该行；
- 返回 `{"created": N, "status": "pending_review", "note": "已进入待审队列…"}`。

### 5.3 数据结构（关键字段）

| 表 | 字段 | 作用 |
|---|---|---|
| `study_material` | `category`（子类名，词表约束）、`point_id`（考点 ID）、`content_hash`、`status` | 分类与去重、审核态 |
| `knowledge_point` | `point_name`、`subject_id`、`sub_category_id` | 考点 → 子类反向映射的载体 |
| `material_classification_rules` | `rule_config`（JSON：subject/category/point/keywords）、`priority`、`enabled` | 两级规则的单一真源 |
| `material_import_record` | 解析状态、结果快照 | 导入可追溯 |

### 5.4 错误码表（可并入说明书）

| 码 | 含义 | 处置 |
|---|---|---|
| E001 | 缺必需列 | 阻断 |
| E002 | 必填单元格为空 | 行级跳过 |
| E003 | 正面 >120 / 背面 >600 字 | 行级跳过 |
| E004 | 行数超上限 | 阻断 |
| E005 | 文件内重复行 | 行级跳过 |
| E006 | 分类不在子类词表 | 警告（导入）/ 拒绝（交互式） |
| E007 | 考点不在考点表 | 警告 |
| E008 | 含 `script/iframe/object/embed/style` | 行级跳过 |
| E009/E010 | 扩展名不支持 / 体积超限 | 阻断 |

## 6. 权利要求草案（供代理机构改写）

1. 一种备考资料文档格式规范化与自动分类方法，其特征在于，包括：
   S1 接收上传文件，按预设别名表将表头归一化为逻辑列；
   S2 基于归一化后的表结构执行分级校验，得到**阻断级错误**、**行级错误**与**警告级信息**三类结果；
   S3 对通过阻断级校验的记录执行两级自动分类，分别输出**子类**与**考点**；
   S4 依据分类法词表校验分类结果，并写入资料库，其中与用户角色对应的入库状态不同。
2. 根据权利要求 1 所述的方法，其特征在于，步骤 S2 中：若存在缺必需列或行数超上限，则拒绝整表入库；若存在空值、超长、表内重复或危险标签，则仅跳过对应行并回传行号；若分类或考点不在词表内，则记为警告并触发步骤 S3 的自动分类回退。
3. 根据权利要求 1 所述的方法，其特征在于，步骤 S3 的两级自动分类包括：第一轮仅以标题匹配规则并按「命中关键词数、规则优先级」排序取最优；第二轮在某级未命中时以标题与正文全文兜底；命中考点时依据考点与子类的映射关系自动补齐子类。
4. 根据权利要求 3 所述的方法，其特征在于，所述规则为 JSON 结构，可选择性地包含 `category` 与 `point` 字段，从而同一规则库同时支持子类级与考点级分类。
5. 根据权利要求 1 所述的方法，其特征在于，步骤 S4 中：管理员上传的记录可按发布标志直接上线；学生上传的记录强制为待审状态，并受每日次数、累计条数与内容哈希去重约束。
6. 一种备考资料分类装置，包括存储器与处理器，所述处理器执行所述存储器中的程序时实现权利要求 1–5 任一项所述的方法。
7. 一种计算机可读存储介质，其上存储有计算机程序，该程序被处理器执行时实现权利要求 1–5 任一项所述的方法。

## 7. 与在先技术的差异（答复审查意见时可直接引用）

1. **错误分级而非单一校验**：把“错误”按可否跳过重新归类，解决了“严格校验”与“批量容错”的矛盾；
2. **考点级分类 + 反推子类**：分类粒度下沉到考纲考点，并以此消除游离类目；
3. **分类结果可度量**：以考点覆盖率与命中率作为客观指标，可在说明书中给出实测值（100%/93%）。
