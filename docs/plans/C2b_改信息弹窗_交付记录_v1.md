# C2b「改信息」弹窗 + PATCH meta 交付记录 v1

- 日期：2026-11-08
- 分支：`feat/material-multi-format-import`（**未合并 main、未推送远端**）
- 对应方案：《资料管理 v3.1》§5 **C2b**（v3.1 新增、裁定 D32）
- 一句话：列表「改信息」不再是灰的——能改标题/分类/年份/地区/卷别/题量/总分/时长/编号，还能**给已有的 2 套真题补原件**。

---

## 1. 为什么需要它

| 现实 | 后果 |
|---|---|
| 文件名解析（C2a）只能"猜"：`扫描件_001.pdf` 什么都解析不出 | 管理员没有纠正入口 |
| 解析可能错（`2024版 2019真题` 取最后一个年份是对的，但不是所有命名都这么友好） | 错了只能改名重传 |
| 你上传的 2 套真题**只有题库里的题、没有 PDF/Word 原卷** | 抽屉「原件」区永远是空的 |

## 2. 做了什么

| # | 层 | 内容 |
|---|---|---|
| 1 | 数据 | `study_material.paper_meta`（TEXT/JSON，启动期自动补列）：存**人工订正**的 year/region/book_kind/volume/题量/总分/时长 |
| 2 | 服务 | `services/paper_meta_edit.py`：字段白名单 + 范围校验（year 1990–2100、题量 1–500、总分 0.5–1000、时长 1–600、卷次 1–20）、地区/卷别枚举、`merge_meta()`（订正 > 文件名解析）、`suggest_paper_code()` |
| 3 | 接口 | `PATCH /api/materials/admin/{id}/meta`：改 title/category/paper_code + 试卷元数据；`null`/空串 = 清除该项；编号冲突 400；已删除 404；R11 白名单 +1（基线仍 343） |
| 4 | 展示 | `services/paper_registry.paper_block()` 改为**三级合并**并新增 `source`（`edit`/`exam`）与 `override`（原始订正键值，供表单回填） |
| 5 | 补原件 | `POST /admin/files/upload` 的 `material_id` 分支：资料**还没有原件**时这份落 `primary`，已有则落 `attachment`（避免"只有附件没有主文件"的畸形数据） |
| 6 | UI | `components/admin/MaterialMetaDialog.vue`：三列表单 + 试卷区块（年份/地区下拉 33 项/卷别/卷次/题量/总分/时长）+ 「上传原件」+ 关联卷提示；保存后 toast 列出改了哪些字段 |

**合并优先级为什么是「订正 > 解析 > 可作答卷」**：
订正是人工判断必须压过机器；可作答卷的题量放最后——资料描述的是**原卷**，在线那份可能只截取了部分题。
界面上用占位符明示"留空就用可作答卷的值（100）"，并在 `source` 里标明每个数字的来源。

## 5. 边界与取舍

- **不写 `exam_paper`**：跨域写会被 L4 模块边界门禁拦（见 C2/C4 记录 §5.2），且资料描述原卷、在线卷描述考试，两者本就可能不一致。
- **编号不会被自动改掉**：`paper_code` 已成为关联键，年份/地区变更后若自动重算会打断关联。要重算就把编号清空再保存。
- **`paper_meta` 只存"订正"**：解析出来的值不回填进表单，否则保存一次就把机器结果固化成人工结论（这一点写在组件注释里）。

## 6. 现在能用它干什么

1. **给 2 套真题补原卷**：`＋上传试卷` 先传 PDF/Word 建一条新资料 → 打开新资料的「改信息」把标题/编号改成与现有 125/126 一致？——**不行**，编号会冲突。
   **正确做法**：直接在 125/126 上点「改信息」→「上传原件」（走 `material_id` 分支，落 `primary`），原件就挂到既有资料上了。
2. **纠正解析**：任何试卷资料点「改信息」填年份/地区/卷别，保存即生效（`source` 变 `edit`）。
3. **批量补信息**：目前一次一条（批量改信息未做，可后续加）。
