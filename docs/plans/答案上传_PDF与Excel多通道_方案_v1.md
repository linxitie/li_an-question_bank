# 答案上传（PDF 一等通道 + Excel/文本兜底）· 方案 v1

> 你的问题（2026-11-09）：**现有答案都是 PDF**，能否增加答案上传方式？
> 素材位置：`题库/答案解析（不用打印）/`（实测 **47 份答案 PDF**）
> 状态：📋 **待你批准**（本文只有实测与设计，未写业务代码）

## 1. 结论：能，而且比 Excel 更省事

我把 4 套已有卷对应的答案 PDF 全跑了一遍分层解析（**只读文件，不写库**），结果是：

| 卷 | 答案 PDF | 题号覆盖 | 自动识别答案 | 与题型冲突 | 解析正文中位 |
|---|---|---|---|---|---|
| `GZ-2019-BJ-T` | 2019年北京市…真题答案及解析.pdf | **100/100** | **100**（L1） | 0 | 310 字 |
| `GZ-2017-JS-T` | 2017年江苏省…真题答案及解析.pdf | **100/100** | **100**（L0 3 + L1 97） | **1 题（#87）** | 344 字 |
| `GZ-2024-GK-T` | 2024年国考《公安专业科目》真题解析.pdf | **100/100** | **100**（L0 99 + L3 1） | 0 | 255 字 |
| `GZ-2016-JX-T` | 2016江西招警…答案及解析（部分）.pdf | **97/97** | **97**（L1） | 0 | 289 字 |

**合计：题号 397/397，答案自动识别 397/397，只有 1 题需要人眼确认。**

> 「冲突」= 解析出的答案字母数与该题题型不符（单选应 1 个字母、多选应 ≥2）。
> 这不是解析失败，而是**校验把可疑处挑出来了**：#87 的原文是「A、B、C 项：正确…D 项：正确」，
> 四个选项都正确 → 正确答案应是 `ABCD`，而"题号后直给字母"那一层只抓到了开头的 `A`。

所以：**PDF 可以作为一等通道**，不必逼你先把 47 份 PDF 手工转成 Excel。

## 2. 四种通道的实测/评估

| 通道 | 你要做的事 | 实测/评估 | 建议 |
|---|---|---|---|
| **PDF 答案卷**（本次新增） | 上传那份 PDF | 上述 397/397；解析正文可一起入库 | ✅ **主通道** |
| **docx 答案卷** | 上传 Word | 与 PDF 同一套文本流规则（`python-docx` 读段落） | ✅ 顺带支持（零额外成本） |
| **Excel 一行一题** | 自己填表格 | 最稳但**要人工转录** 47 份 | ✅ 兜底（模板可下载） |
| **纯文本粘贴** | 粘贴 `1 A` 这种 | 与 Excel 同规则，适合少量补 | ✅ 兜底 |
| **表格里手填** | 在预览表格直接改 | 永远保留（任何通道最后都能改） | ✅ 必备 |

一句话：**PDF 为主、Excel/文本为备、手填为底**。三条通道最终都汇到同一个"预览→确认"页。

## 3. 关键坑（都实测踩到了，方案里逐条堵）

| # | 坑 | 实测证据 | 对策 |
|---|---|---|---|
| K1 | **幻影题号**：解析正文里的编号列表被当成题号（`2.重点环节。1 控制场所…`、`3、创造警民协作新形式；4、…`） | 2024 国考 1 处、2019 北京 1 处；若不处理，#2 的真实答案 `B` 会被解析里的 `ABC` 顶掉 | 同一题号出现多次时**保留第一次**（真实题号行总在前）+ 题号必须落在 1..卷题数 |
| K2 | **推理层不可靠**：`A项正确` 推出 4 个字母，但该题是单选 | 2024 国考若只用推理层 → **16 题**与题型不符 | 推理层（L3）**默认不自动填**，只在没有任何"字面答案"时给「建议」，并标红 |
| K3 | **"题号后直给字母"会吞掉列举式解析** | 2017 江苏 #87：`87、A、B、C 项：正确…` → 抓到 `A` | 用**题型×字母数**交叉校验抓出来（本例抓到了），冲突项默认不写入 |
| K4 | 同一份答案里可能混多套卷 / 题号从别的卷延续 | 目录里 47 份 PDF 覆盖 2016–2025 各种考试 | 只接受"题号覆盖 = 该卷题数"的文件；否则阻断并提示"这份答案可能不是这套卷" |
| K5 | 答案已存在 | 4 套卷里 #2/#3/#4 现在**已有答案**（历史导入时填的） | 默认**只填空位**；已有答案不同 → 标冲突，逐题确认；批量覆盖需显式勾选 |
| K6 | 写答案会不会影响历史成绩 | 历史记录里已存的分数是当时算的 | **不重算历史成绩**（只影响之后的新考试），并在界面写清楚 |

## 4. 设计（与「上传即导题」同构：草稿 → 预览 → 确认）

```
上传答案（PDF/docx/xlsx/txt）
  → 解析：按题号切块 → 四层取答案（L0 直给 / L1 标记 / L2 结论 / L3 推理）
  → 对齐：题号 1..N 必须与卷题数一致（否则阻断）
  → 校验：字母范围、去重排序、题型×字母数、空答案、已有答案差异
  → 落「答案草稿」（新表 paper_answer_draft，30 天保留）
  → 管理端「补答案」抽屉：逐题看 答案/来源层级/解析摘要/标记，可改可补
  → 点「确认写入」→ 只写"已确认"的题；`answer_analysis` 一起写
```

### 4.1 四层取答案（优先级从高到低）

| 层 | 规则 | 可信度 | 实测命中 |
|---|---|---|---|
| L0 | 题号后**独立字母**：`1、A 本题考查…` / `1、A` / `1.A。` | 高（要排除 `A、B、C 项` 这种列举，用题型校验兜） | 2024: 99 / 2017: 3 |
| L1 | 显式标记：`【答案】A` / `正确答案为A` / `参考答案：A` | 高 | 2019: 100 / 2016: 97 / 2017: 97 |
| L2 | 句尾结论：`故本题选A` / `答案选A` | 中高 | 本轮 0（留作其它来源的兜底） |
| L3 | 解析推断：`A项正确` 且非 `A项错误` | **中低**（K2 实测 16 题错） | 2024: 1（作为"建议"显示） |
| — | 都没命中 → 空，等人工 | — | 0 |

### 4.2 数据与接口

新表 `paper_answer_draft`（与 `paper_parse_draft` 对称）：

```
draft_id / paper_id / status(pending|applied|discarded|failed)
source_ext / source_name / item_count
items_json      [{no, answer, tier, suggestion, analysis, flags[]}]
conflict_count / empty_count
message / created_by / create_time / expires_at
```

新增 5 个管理端端点（**仍然按 R11 只登记不重算基线**）：

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/api/materials/admin/papers/{paper_id}/answers/parse` | 上传并解析（pdf/docx/xlsx/txt） |
| GET | `/api/materials/admin/answers/drafts/{draft_id}` | 预览明细（含冲突/空答案/解析摘要） |
| PUT | `/api/materials/admin/answers/drafts/{draft_id}/items` | 人工改/补（整表） |
| POST | `/api/materials/admin/answers/drafts/{draft_id}/apply` | 写入（`overwrite` 控制是否覆盖已有答案） |
| DELETE | `/api/materials/admin/answers/drafts/{draft_id}` | 放弃 |

### 4.3 界面

预期效果图：`assets/答案上传_预期效果/管理端_补答案抽屉_预期效果.png`

- 入口：管理端「资料管理」试卷行的操作列 →「补答案」（`建卷`/`导题`/`补答案`/`改信息`/`删除`，同样只在试卷行出现）；
- 抽屉上半部：拖拽上传区 + 四个体检数字（识别/冲突/缺号/解析字数中位）+「只看需确认」；
- 表格：题号 / 题型 / 答案 / 来源层级 / 解析摘要 / 标记（冲突、建议、空）；冲突行淡红底；
- 底部：`取消` / `重新解析` / **`确认写入 N 题`**；旁边一行小字写清"只填空位、覆盖需勾选、不改历史成绩"。
