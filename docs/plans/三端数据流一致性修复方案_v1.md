# 三端数据流一致性修复方案 v1

> 范围：`docs/plans/学生端、教师端和管理员端的数据流一致.md` 所列 6 项问题
> 分支：`feat/fix-bug`
> 状态：**已批准（2026-10-19）；P0-1 完成；P0-2~P4 待执行**
> 依据：2026-10-19 数据库实测 + 代码逐行核对（证据见附录 A）
> 原则：复用已有解析/匹配/分类/统计机制，去粗取精；不新建第二套解析器、匹配器或考点体系

---

## 0. 结论摘要

6 个问题不是 6 个孤立 bug，而是 4 条链路的口径与边界不一致：

| 链路 | 涉及问题 | 一句话结论 |
|---|---|---|
| A. 可见题目口径 | 学生端题量少、教师/管理员数量不一致 | 学生端按“子科目字符串列”统计、按 `question_knowledge` 取题、按题干去重；教师/管理员按 `question_bank` 行统计。三套口径必然不等 |
| B. 主观题渲染 | 申论答题卡出现 A/B/C/D 与“待补充” | `normalize_options(pad_to=4)` 对空 options 无条件补 A-D；前端选项区没有主观题分支；申论 37 题 options 全为空 |
| C. 考点展示 | 考点过度下钻、重复“其他”、大量 0/0 | `knowledge_point` 631 行 = 126 行种子 + 505 行 PDF 标签；学生端按 `sub_category_id` 平铺全部行，不过滤层级/空节点/重名；分类器只认 126 行种子词表 |
| D. 材料归属 | 申论材料缺失、复合题材料被切到上一题/解析、教师端看不到/不能编辑 | 解析器把材料当“上一题尾部文本”；落库时材料只写第一题或完全不写；`/confirm` 不消费预览 `groups`；读/写 schema 都没有材料字段 |

修复顺序建议：**先统一口径与展示（低风险）→ 再补教师材料编辑 → 再重构解析器材料归属（高风险，带开关与回归）→ 最后做存量修复与验收**。不要把 D 链路的高风险解析改动和 A/B/C 的展示修复混在一个提交里。

## 1. 目标与非目标

### 1.1 目标

1. 学生端、教师端、管理员端在**默认筛选**下看到同一批题、同一套计数；差异必须由显式开关解释（含下架/待审）。
2. 申论等主观题不再出现伪造的 A/B/C/D 选项；答题卡有符合题型的作答区与材料展示。
3. 学生端考点只展示公安联考主要考查范围，不出现重复“其他”、不出现大面积 0/0、不过度下钻到 L3/L4。
4. 教师/管理员能查看并编辑题组材料；材料永远存 `question_groups.shared_content`，不塞回题干。
5. 复合题材料有明确归属：要么属于题组共享材料，要么标记为待人工处理；不得静默留在上一题题干或答案解析中。
6. 新导入的申论/复合题在 `/confirm` 与 `/batch-parsed` 两条主路径上都能正确建组、回填 `group_id`。
7. 全部改动可回归、可回滚、可审计；不破坏 343 个既有 API 契约。

### 1.2 非目标（本方案不做）

- 不做教师端题目导入的全面重构（AGENTS.md 要求 P3B 完成后再启动；本方案只修材料归属与建组链路）。
- 不做目录分层搬迁、不做 `.vtj/` 文件移动/改名、不做数据库从 SQLite 迁移。
- 不新建另一套考点分类算法、不重新训练/重写 `QuestionClassifier`。
- 不一次性清洗全部 3357 题；存量修复只覆盖有明确证据的题组与申论卷，其余生成审计清单交人工。
- 不改 `.env`、不碰密钥、不清理 `backend/data/*.bak*`。

## 2. 统一数据口径（先定规则，再改代码）

这一节是后续所有修复的“合同”。如果口径不先定，改完仍会互相打架。

### 2.1 题目可见性

| 角色 | 默认可见 | 可选开关 |
|---|---|---|
| 学生 | `status = 1 AND audit_status = 1` | 无 |
| 教师 | `status = 1 AND audit_status = 1` | `include_offline=1`（含下架）、`mine=1`（只看自己创建） |
| 管理员 | `status = 1 AND audit_status = 1` | `include_offline=1`、`include_pending=1` |

当前实测 `audit_status` 全为 1（3357 行），所以默认口径等价于 `status=1`（3122 行）。管理员现在默认查全部 3357 行（`admin.py:506` 无 status 过滤），这是“管理员比学生多”的直接原因之一；改为默认 3122，并在页面明确显示“含下架 235 题”的开关。

### 2.2 计数单位

- **题目总数**：按 `question_id` 计数，**不按题干去重**。题干去重只用于“练习抽题避免重复”，不能用于“题库总量”。
- **子科目计数**：以 `question_bank.xingce_subcategory / shenlun_subcategory / gongzhuan_subcategory` 为准；`NULL`、空串、`'无'` 统一归入“未分类”桶。
- **考点计数**：以 `question_knowledge` 为准；同一题可关联多个考点，因此：
  - 单个考点显示“关联题次”（`COUNT(*)`）；
  - 面板合计显示“去重已关联题数”（`COUNT(DISTINCT question_id)`）；
  - 子科目内“未关联考点题数” = 子科目可见题数 − 该子科目下去重已关联题数。
- **题组计数**：题组不改变题目总数；组内小题仍是独立 `question_bank` 行。

### 2.3 材料归属

- 材料只允许存在 `question_groups.shared_content`。
- `question_bank.question_content` 只存题干/设问，不存材料正文。
- 题组必须有 `group_type`、`shared_content`、`source`；`shared_content` 为空或长度 < 20 的组视为无效组，不参与展示。
- 小题通过 `group_id` 指向题组；`sort_order` 决定展示顺序；`question_level` 只表达“是否小题”，不承担排序职责。

### 2.4 主观题判定

- 权威字段：`question_type.is_objective = 0`。
- 兜底：题型名包含 `简答/论述/写作/分析/概括/对策/应用文`，或科目为申论且 options 为空。
- **不得**用 `subject_id == 2` 硬编码作为唯一判据（公专也有 1 道简答题）。

### 2.5 一致性断言（每次改动后必须跑）

对每个科目 `s`：

```
可见总数(s) == Σ 子科目计数(s, 含未分类)
可见总数(s) == COUNT(DISTINCT question_id WHERE subject_id=s AND status=1 AND audit_status=1)
子科目未分类数(s) == COUNT(*) WHERE 子科目列为空/无
去重已关联题数(s) + 未关联考点题数(s) == 可见总数(s)
教师默认总数(s) == 管理员默认总数(s) == 学生可见总数(s)
不同题干数(s) <= 可见总数(s)
```

## 3. 分项方案

### 3.1 问题一：学生端题量比教师/管理员少

#### 根因（实测）

1. 学生端子科目面板用 `question_bank.<subject>_subcategory == sc.name` 统计，**不统计“无/空”**：行测 79 题、公专 316 题被排除；面板合计只有 150 / 2561，而可见总数是 229 / 2877。
2. 学生端考点取题走 `question_knowledge`：行测只有 137 题有考点关联、公专 2431 题；无关联的题在考点入口永远取不到。
3. 学生端练习接口按 `question_content` 去重（`quick_practice.py:254-261`），计数却按行数；同一题干多行时“显示数”和“抽题数”不一致。
4. 教师端 `teacher.py:312` 默认 `status=1`；管理员端 `admin.py:506` 默认查全部（含 `status=0`）；学生端又是另一套子科目口径。三端没有任何共享的可见性函数。
5. `question_bank.point_id` 全库 3357 行为 `NULL/0`，但教师筛选、智能组卷、组卷、薄弱点仍在用它；这些入口的结果与学生端 `question_knowledge` 口径不同。

#### 方案

**后端**

1. 在现有 `backend/app/services/question_stats.py` 增加统一入口（不新建统计服务）：
   - `visible_query(db, subject_id=None)`：`status=1 AND audit_status=1`。
   - `count_by_subcategory(db, subject_id)`：一次 `GROUP BY` 返回各子科目计数，并在 Python 侧补“未分类”桶。
   - `count_by_knowledge_point(db, subject_id)`：一次 `JOIN question_knowledge + knowledge_point + question_bank` 聚合，返回 `point_id -> (link_count, distinct_question_count)`。
   - `count_user_progress(db, user_id, question_ids)`：一次查询返回 done/correct 集合，替代逐考点两次查询。
   - `assert_consistency(db)`：跑 2.5 的断言，供脚本/测试调用。
2. 改造 `backend/app/api/v1/exam/quick_practice.py`：
   - `/sub-categories`：
     - 返回 `subject_total`、`classified_total`、`unclassified_total`。
     - 每个子科目返回 `total_questions`（该子科目字符串列计数）。
     - 追加一个合成子科目 `{id: 0, name: "未分类", is_unclassified: true}`，计数为 NULL/空/“无”。
     - 考点列表只保留 `level <= 2`、`point_name != "其他"`、在 canonical 集合内、且 `distinct_question_count > 0` 的节点（见 3.3）。
     - 追加合成考点 `{point_id: 0, point_name: "未关联考点", is_unlinked: true}`，计数 = 子科目题数 − 该子科目下去重已关联题数；为 0 时不返回。
     - 去掉逐考点 N+1 查询。
   - `/knowledge-points`：加 `include_empty=false`、`max_level=2`、`canonical_only=true` 参数；默认与面板一致。
   - `/questions`：
     - `bySubCategory=true` 时**直接查 `question_bank` 子科目列**，不再展开成 `question_knowledge`；这是“未关联考点的题也能练”的关键。
     - `kpIds` 模式仍走 `question_knowledge`。
     - 返回 `group_id`、`question_level`、`sort_order`、`question_number`、`is_subjective`。
     - 题干去重只用于抽题，响应中同时返回 `matched_total`（去重前）与 `returned_total`（去重后），不再把去重后的数当题库总量。
3. 改造 `backend/app/api/v1/catalog/questions.py` 的 `/exercise/questions`：
   - 与 `/quick-practice/questions` 共用同一套可见性/去重逻辑（抽题去重可以保留，但计数口径统一）。
   - 返回 `group_id`（已有）、`question_level`、`sort_order`、`is_subjective`。
4. 教师/管理员统计：
   - `teacher.py` 默认 `status=1 AND audit_status=1`，加 `include_offline`、`mine` 开关；`point_id` 筛选改走 `question_knowledge`。
   - `admin.py` 默认 `status=1 AND audit_status=1`，加 `include_offline`、`include_pending`；`/stats` 同时返回 `visible_total` 与 `all_total`，页面明确标注。
   - `QuestionStatsService` 的 teacher 分支目前只看 `creator_id`，改为“可见全量 + 我的创建数”，避免教师端总数天然小于学生端。
5. 新增只读校验脚本 `backend/scripts/verify_question_counts.py`：
   - 输出三端每科目计数、子科目合计、未分类、考点关联/未关联；
   - 断言 2.5 全部成立；失败退出码非 0。
6. 增加 pytest：`backend/tests/test_question_counts_consistency.py`，用测试库构造“无子科目/无考点关联/重复题干”三类边界。

**前端**

- `src/views/student/shared/exercise.vue`、`.vtj/vue/question_bank.vue`、`mobile_practice.vue`、`tablet_question_bank.vue`：
  - 面板显示“全部 / 已分类 / 未分类”；“未分类”可点击进入练习。
  - 子科目/考点计数直接使用后端字段，不在前端二次过滤或去重。
  - 空节点不渲染；0/0 节点不渲染。
- 教师/管理员题目管理页增加“含下架/待审”开关，默认关闭；开关打开时标题旁显示总数变化。

**验收**

- 行测：学生面板合计 229；教师默认 229；管理员默认 229；未分类 79；考点已关联 137 + 未关联 92 = 229（按子科目分别断言）。
- 申论：16 / 16 / 16；未分类 0；已关联 16 + 未关联 0 = 16。
- 公专：2877 / 2877 / 2877；未分类 316；已关联 2431 + 未关联 446 = 2877。
- 管理员打开“含下架”显示 3357（行测 235 / 申论 37 / 公专 3085；以最终 SQL 为准），并明确标注。

### 3.2 问题二：申论答题卡出现 A/B/C/D 与“待补充”

#### 根因（实测）

1. 全库申论 37 题 `options` 全为 `[]`；`option_utils.normalize_options` 在 `raw_options is None` 或空列表时直接 `_build_default_options(4)`，返回 A-D `(待补充)`（`option_utils.py:64-72、194-196`）。
2. `quick_practice.py:292` 对每道题无条件调用 `normalize_options`；`questions.py` 的列表/题组/详情同样无条件补全。
3. `exercise.vue:299-345` 的 `parsedOptions` 还有第二层补全：即使后端不补，前端也会补 A-D `(待补充)`。
4. 模板 `exercise.vue:102-126` 只有“多选/单选”两个分支，没有主观题分支；因此申论必然渲染选项。
5. 题型字段 `question_type_detail` 已被后端返回，但前端没有用它判断主观题。

#### 方案

**后端（统一入口，避免每个端点各写一套）**

1. `backend/app/services/option_utils.py`：
   - `normalize_options(..., is_subjective: bool = False, pad_to: int = 4)`：
     - `is_subjective=True` → 直接返回 `[]`（不补、不猜）。
     - `pad_to=0` → 不做补全（保留已有选项，仅规范化/排序/图片转换）。
   - 新增 `is_subjective_question(db, question) -> bool`：
     - 查 `question_type.is_objective`；`0` → 主观题；
     - 查不到时按 2.4 的兜底规则。
   - 新增 `format_question_options(db, question, ...)`：统一“是否主观 + normalize + 图片净化”，供所有端点调用。
2. 所有 `normalize_options` 调用点加 `is_subjective`：
   - `quick_practice.py:292`
   - `questions.py` 列表/详情/题组（`grep normalize_options` 全量核对）
   - `question_import.py` 预览/确认（预览也不要给申论补 A-D）
   - `admin.py` / `teacher.py` 的 `_format_question`
   - `smart_exam.py` / `papers.py` 等抽题端点
3. 响应字段增加 `is_subjective`（布尔）与 `question_type_detail`；前端不再猜。
4. `practice_grading.submit_answers`：
   - 主观题不参与自动判对错；`is_correct` 记为 `None`/`2`（未知），或按“已作答”计入进度，不计入正确率。
   - 避免把申论文本与 A/B/C/D 比较后判错。

**前端**

1. `exercise.vue`：
   - `parsedOptions`：若 `isSubjective` 为真直接返回 `[]`；删除“补全 A-D”逻辑（客观题也不应该在前端补假选项，缺失就显示缺失）。
   - 模板：选项区 `v-if="!isSubjective"`；新增主观题作答区：
     - 材料/要求（已有 B4 材料块 + `requirements` 展示）；
     - `<textarea>` 作答（自动保存到 `state.subjectiveAnswers[idx]`）；
     - 提交后展示“参考答案/解析”（可折叠）；
     - 明确提示“主观题不自动判分”。
   - 答题卡：主观题“已答”按文本非空判断；不再显示 A/B/C/D 选择状态。
   - 交卷统计：主观题不计入“正确/错误”，单独显示“主观题已作答 N”。
2. `mobile_answer.vue`、`mobile_practice.vue`、`tablet_practice.vue` 以及任何复用 `parsedOptions` 的答题组件：同一套 `isSubjective` 分支；抽出共享组件/组合式函数，避免四份重复。
3. 教师/管理员详情预览：
   - `is_subjective` 为真时不渲染选项区，显示“主观题”标识；
   - 材料用 `v-html` 富文本展示（现有 `renderQuestionContent`/`cleanHtmlContent` 已具备），补充段落/图片/表格样式。
4. 富文本展示：
   - 展示层复用现有 `v-html` + `sanitize_content_images`/`render_image_placeholder`；
   - 编辑层保留 HTML 文本域 + 预览（现有 `edit-preview-block`），不引入新编辑器依赖；如后续需要工具栏，再单独评估，不在本次范围扩张。

**验收**

- 申论 37 题：API 返回 `options=[]`、`is_subjective=true`；页面 0 处 A/B/C/D、0 处“(待补充)”。
- 行测/公专客观题：选项仍完整；缺选项时显示“选项缺失”，不伪造。
- 公专 1 道简答题：同样走主观题分支。
- 提交主观题不产生“错题”记录；正确率分母不含主观题。

### 3.3 问题三：考点过度下钻、重复“其他”、大量 0/0

#### 根因（实测）

1. `knowledge_point` 631 行 = 种子 126 行 + `migrate_xingce_knowledge_points.py` 新增 505 行；577 个不同名称，54 行重名。
2. 35 行 `point_name='其他'`，来自 `xingce_kao_points.json` 中 35 条以“其他”结尾的父路径；迁移脚本按完整路径建节点、非根节点不按名称去重，模型也没有唯一约束。
3. 分类器 `QuestionClassifier._taxonomy_point_names()` 只索引 126 行种子词表，并明确排除“其他”；实测 `question_knowledge` 2775 行只用到 72 个考点，559 个节点没有任何关联。
4. `/quick-practice/sub-categories` 按 `sub_category_id` 取**全部** `KnowledgePoint`，不看 `level`、不看是否有题、不按名称去重；前端 `v-for` 扁平渲染，`key=point_id`。
5. 科学推理子科目在 `question_bank` 中 0 题，但面板有 24 个考点，全部 0/0。
6. 教师筛选、智能组卷、组卷、薄弱点仍用 `question_bank.point_id`（全 NULL），与学生端 `question_knowledge` 口径不一致。

#### 方案：代码层“canonical 视图”优先，数据清洗后置

**原则**：不删除 505 行原始标签（保留可追溯性），但学生端只展示“考纲 canonical 集 + 有题节点”；重名与“其他”在 API 层收敛。这样可逆、无需先做破坏性迁移。

1. **canonical 集合**
   - 在 `backend/app/services/question_classifier.py` 暴露只读函数：
     - `canonical_point_names(subject_id, sub_category)`：合并 `SUB_CATEGORY_KP_MAP` 与 `EXAM_POINT_PARENT`，排除 `'其他'`。
     - `is_canonical_point(point_name, sub_category)`。
   - 不新建 taxonomy 文件，不复制词表。
2. **API 过滤（`quick_practice.py`）**
   - 只返回 `level <= 2` 的节点。

### 3.4 问题四：教师端申论材料预览/编辑缺失

#### 根因（实测）

1. 数据层：`#3876`（2024 安徽 C 申论）`group_id=0`、题干仅 66 字；同批 3749-3752（安徽 A）也 `group_id=0`；全库 `question_groups` 中没有包含“农药包装/Z县/城市绿化/庭院经济”的材料行。材料在导入落库阶段就没进 `question_groups`。

**读取（最小改动，复用现有 `/group/{gid}`）**

3. 教师/管理员列表已返回 `group_id`，保持不变；详情弹窗继续用 `/group/{gid}`，不改契约。

### 3.5 问题五/六：复合题材料切分错误、子题关联弱

这两个问题在代码上同源：解析器把材料当“上一题尾部”，匹配器只看入库后的题干，`/confirm` 又不做复合题识别。合并处理。

#### 根因（实测/代码）

1. 通用解析器的题块边界只由题号决定；材料没有独立字段，只能靠 `_MATERIAL_HEAD_RE` 或 `_strip_unmarked_material` 从上一题尾部“搬”。匹配不到就留在上一题 `question_content`。
2. `_MATERIAL_HEAD_RE`（`text_parser.py:1949`）覆盖不足：括号前缀、`根据材料1`、`给定材料`、`据此`、`完成`、`第X题至第Y题` 等不匹配。
3. `_strip_unmarked_material`（:2164）只在“上一题 ≥2 个选项、材料 ≥3 行或 ≥60 字、材料在选项后且答案标记前”时生效；上一题无选项、材料较短、材料在答案/解析之后时，材料留在上一题。
4. `extract_answer_from_lines` 的结论/嵌入式路径直接把整段 `full_text` 当解析，材料进入 `answer_analysis`。
5. `_mark_and_split_suspected`（:3266）二次切分按“当前题号到下一题号”切片，材料自动归前一个子题，且不再重新剥离。
6. 材料在最后一个题号之后时 `pending_spill` 永不 flush；材料在第一个题号之前时块切片从不包含。
7. 无题号/混合题号文档用 `_extract_blocks_unnumbered` 时，材料会被当作下一题前缀或独立假题。
8. 匹配器 `composite_matcher.match_group_head` 只看 `question_content`，看不到原始材料；`shared_content` 取头题题干（`question_import.py:806`），不是材料正文。
9. `/confirm` 完全不调用 `_detect_and_link_composite_groups`（只在 `/batch-parsed` 调用，`question_import.py:1299`）。
10. 重复题不进入 `ok_items`，建组时被排除；`claimed` 混用索引 `i` 和 `question_id`（`question_import.py:759-801`），导致漏挂。
11. `group_id=0` 是列默认值，部分判断用 `is None` 会失效；`question_level` 在不同路径写成 1/2，组内不一致。

#### 方案：把“材料”提升为解析块的一等字段（扩展现有函数，不新建解析器）

**目标数据结构（在现有 block dict 上增量）**

```python
{
  "question_number": 86,
  "content": "题干（不含材料）",
  "material_text": "材料正文（可含 HTML/图片占位符）",
  "material_range": (86, 89),      # 材料头声明的题号范围
  "material_source": "head|unmarked|doc|analysis",
  "options": [...],
  "answer": "...",
  "analysis": "...",
  "format": "essay|...",
  "question_level": 1,
  "sort_order": 0,
  "suspicious": False,
  ...
}
```

**解析器改动（全部扩展现有函数）**

1. `_MATERIAL_HEAD_RE` 扩展（`text_parser.py:1949`）：
   - 可选括号前缀：`（一）`、`(1)`；
   - 可选 `第X题至第Y题`、`第X-Y题`、`X—Y题`；
   - `根据(以下|下面|上述|此)?(材料|资料|情境|情景|案例|文章|图表|内容)`，允许 `材料1`/`给定资料1`/`给定材料1`；
   - `阅读(以下|下面)?(材料|文章|资料)`；
   - `回答(第)?X[-至~—－]Y题`、`完成X-Y题`；
   - 保留“不用 `$` 锚定”的现有设计（同行材料）。
2. `_strip_trailing_material`（:2211）：
   - 返回值增加“材料文本”语义：`keep` 只保留题干/选项/答案；`spill` 作为 `material_text` 交给下一块，而不是拼回下一块 `content`。
   - 搜索不再从 `i=1` 开始后遇到第一个标记就停；允许在答案/解析之后再次寻找材料头（处理“材料在答案解析后”）。
   - 增加 `next_qnum` 参数：只有材料头声明的范围与后续题号匹配时才剥离，降低误判。
3. `_strip_unmarked_material`（:2164）：
   - 增加 `allow_no_options`、`format`、`next_qnum` 参数；
   - 申论/主观题允许无选项；
   - 材料阈值改为“≥3 行或 ≥60 字”保持不变，但允许“单行 ≥120 字 + 包含材料关键词”；
   - 边界不再只停在答案标记；若材料在答案后，切到 `analysis` 之后并把尾部作为下一块 `material_text`。
4. `extract_question_blocks`（:3092-3266）：
   - 用 `pending_material` 代替“spill 拼回 content”：`_strip_trailing_material` 返回的 spill 存起来，下一块创建时写入 `block['material_text']`，不写入 `content`。
   - 材料在最后一个题号之后：循环结束 flush `pending_material`；若存在题组头则挂到该组，否则在结果中标记 `orphan_material`，交预览页人工处理（不静默丢弃）。
   - 材料在第一个题号之前：作为 `doc_material` 挂到第一块（申论）或第一组头（其他）。
5. `_mark_and_split_suspected`（:3266）：
   - 切分后对每个子块重新跑 `_strip_trailing_material`；spill 写入下一个子块的 `material_text`；
   - 重新计算 `content`、`options`、`answer`、`analysis`；
   - 传播 `format`、`requirements`、`question_level`、`sort_order`、`parent_id`；
   - 第一个子块开头若是材料，移到 `material_text`。
6. `_extract_blocks_unnumbered`（:2079）：
   - 检测“无题号、无选项、长文本、含材料关键词”的段落，挂到下一块 `material_text`，不生成假题；末尾孤立材料标 `orphan_material`。
7. `_parse_essay_document`（:2906-3092）：
   - `_ESSAY_MATERIAL_ANCHOR_RE` 接受 `给定资料1`、`给定材料1`、`材料1`；
   - `hits < 2` 的硬门槛改为“材料锚点 + ≥1 题”即可进入申论体例；题号样式/分值作为辅助，不再作为唯一门槛；
   - `material_text` 写到文档级字段（`doc_material`），不再只写 `blocks[0]`；
   - `material_titles` 从材料正文的 `^材料\s*\d+` 实际提取，不用 `['材料1','材料2',...]` 占位。
8. 新增 `_strip_material_from_analysis(block)`：
   - 在 `extract_question_blocks` 末尾对每块跑一次；若 `analysis` 含材料头，切出尾部作为下一块 `material_text`，`analysis` 只保留答案解析；
   - 这是对 `extract_answer_from_lines` 的包裹式修复，不改其签名，避免影响其他调用方。
9. 回归保护：
   - 用现有 `backend/tests/` 的解析测试 + `gate_l1_parser.py` 指纹；
   - 新增 `backend/tests/test_material_ownership.py`，覆盖 6 个真实案例：
     - 第 85 题尾部混入“五、根据以下情境材料，回答86-89题…”（现有案例）；
     - 2017 公安院校联考 85-88 无标记材料；
     - 材料在答案解析之后；
     - 材料在最后一个题号之后；
     - 材料在第一个题号之前（申论）；
     - 无题号文档中的材料段。
   - 每个案例断言：`question_content` 不含材料关键词；`material_text` 含；`analysis` 不含材料；题块数量不减少（除假题修复）。

**匹配器改动（扩展现有 `composite_matcher.py`）**

1. 新增 `match_group_head_block(block)`：
   - 优先用 `block['material_text']` + `block['content']` 匹配；
   - 返回 `(group_type, (start,end))`；
   - 保留 `match_group_head(content)` 兼容旧调用。
2. `infer_member_qnums`：
   - 优先用 `material_range`；
   - 无范围时沿用现有 `_MAX_GAP=1`、`_MAX_MEMBERS=30`；
   - 不跨 `source`/试卷边界推断。
3. `semantic_grouping`：
   - 只在没有显式范围时兜底；
   - 增加同 `source`/相邻题号约束，避免把不同试卷的题合并。
4. 组类型映射沿用现有 `_GROUP_HEAD_RULES`，不新增规则引擎。

**落库改动**

1. `_detect_and_link_composite_groups`（`question_import.py:732`）：
   - 增加 `reused_items` 参数，把重复题也纳入建组；
   - `claimed` 只存 `question_id`，不再混用 `i`；
   - `shared_content = q.get('material_text') or (head content if it contains material head else '')`；没有材料就不建组，避免“材料=题干”重复展示；
   - 组内字段：`group_id`、`question_level=2`、`sort_order` 按题号；`parent_id` 指向组头（可选，先不改变现有语义）；
   - 单成员组不建（现有 W3 逻辑保留）。
2. `_link_shenlun_material_groups`（:686）：
   - 用 `doc_material` 覆盖所有申论 item（不再只认 `format='essay'`）；
   - 重复题也通过 `id_map` 回填 `group_id`；
   - 已有 `group_id` 不覆盖。
