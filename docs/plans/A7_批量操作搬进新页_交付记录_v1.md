## 2. 关键行为

| 场景 | 行为 |
|---|---|
| 表头全选 | 只勾**当前页**；再点一次清空；半选时点=全选 |
| 换页 / 换筛选 | 自动清空勾选（避免"已选 5 条"和屏幕上的行对不上） |
| 批量上/下架 | 先过滤掉"已经是该状态"的行（不白打请求、不白写审计）；确认框文案说明**会同步影响学生端可见性与可作答卷** |
| 批量删除 | 走 `/admin/batch` → 软删（`status=-1`）+ 卷同步 DRAFT；提示"可在回收站恢复" |
| 部分失败 | **不回滚已成功的部分**，提示「成功 N 条，失败 M 条：原因1；原因2；等 K 条」 |
| 回收站视图 | 无勾选框、无批量条（保持"单条恢复"语义） |
| 按钮防连点 | 请求期间 `batchRunning` 禁用全部批量按钮 |

## 4. 顺带发现（未修，记录在案）

`POST /api/materials/admin`（管理员建资料）**忽略 `publish` 参数**：`_validate_material_body` 不认它，于是走模型默认 `status=1` → **新建即上架**。
影响面很小（新资料页没有"新建"入口，只有旧版页在建），但语义上"传了 publish=false 却被上架"是隐患。若你要求，可加 5 分钟：`admin_create` 里读 `body.get("publish")` 决定 `status=1/0`。
