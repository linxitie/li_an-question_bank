# 警考雷达——招考信息模块优化设计方案 v3.0

> 文档状态：待用户审批，未实施  
> 编制日期：2026-11-11  
> 方案范围：砺安题库系统「招考信息」模块  
> 对齐依据：
> - 现有系统：`recruitment_info`、`police_post`、`user_profile`、`question_bank`、`knowledge_point`、`UserNotification`、现有 APScheduler
> - v2.0 方案：公告/职位分层、资格卡、可解释匹配
> - 本次新增：防遗漏管家、历年考情与对比篮、AI 选岗报告、大纲异动与题库联动

---

## 0. 结论先行

v3.0 保留 v2.0 的三个基础决策：

1. **不重复建 `job_posts`、`user_profiles`**；
2. **公告与职位分层，LLM 解析保留原文证据**；
3. **匹配结论必须可解释，红黄绿之外必须有原因和免责声明**。

本次新增三大闭环：

```text
防遗漏：时间轴 + 材料清单 + 截止提醒
助决策：历年考情 + 对比篮 + AI 选岗报告
促行动：大纲异动 + 题库标签映射 + 一键刷题
```

同时明确一条红线：

> 所有 AI 报告、历年分数、报录比必须有数据来源或明确标注“暂无数据”，不得由大模型编造。

## 2. 产品结构


### 3.5 为什么不新建 `job_posts` / `user_profiles`

已有 `police_post` 和 `user_profile` 已被选岗顾问、学习计划等模块使用。新建同名概念的第三套表会导致：

- 岗位数据双份；
- 用户画像分裂；
- 题库联动和选岗顾问无法复用；
- 后续统计口径不一致。

## 4. 模块一：防遗漏管家

### 4.1 时间轴

LLM 从公告/附件提取：

```text
报名开始、报名截止
资格审查
缴费截止
准考证打印
笔试
面试/体测/体检
公示
```

每个节点保存：

```text
node_type
start_at / end_at
source_evidence
confidence
timezone
```

前端使用时间轴展示当前阶段、剩余天数、未来节点。

### 4.2 材料待办

根据职位条件生成清单模板：

```text
学信网学历证明
党员证明 / 团员证明
应届生承诺书
基层工作经历证明
退役士兵证明
体能测试承诺书
报名表 / 照片
```

生成规则：

- 条件明确要求 → 必办；
- 条件不确定 → 建议核实，不强制；
- 用户可手动增删；
- 每项可勾选完成，记录时间。

### 4.3 提醒

定时任务扫描：

```text
报名截止前 24 小时
缴费截止前 12 小时
准考证打印开始
笔试前 24 小时
```

发送渠道：

- 首选 `UserNotification` 站内信；
- 可选邮件（需用户配置）；
- 同一 `user_id + post_id + node_type` 幂等，避免重复。

提醒内容必须包含：

```text
公告标题
节点名称
截止时间
原文链接
办理入口/提示
```

## 5. 模块二：考情雷达与选岗辅助

### 5.1 历年考情

数据来源优先级：

1. 官方公开的历年进面名单/分数线；
2. 用户导入的 Excel；
3. 明确标注来源的第三方公开数据。

每条数据必须保存：

```text
province/city
employer
post_type
year
min_score / avg_score
applicants / plan_count
ratio
source_url / source_name
confidence
```

没有数据时显示“暂无历年数据”，不允许 LLM 推测。

### 5.2 对比篮

- 最多 3 个职位；
- 字段：招录人数、学历、专业、政治面貌、应届、基层、报名截止、往年最低分、报录比；
- 支持移除、清空；
- 对比表只展示已知数据，未知显示“暂无”。

### 5.3 AI 选岗报告

输入：

- 资格卡；
- 匹配原因；
- 历年数据（如有）；
- 用户偏好（地区/类型）；
- 时间节点。

输出：

```text
岗位优势
主要风险
条件缺口
建议核实事项
备考优先级
```

约束：

- 不预测录取概率；
- 不编造分数线；
- 每个结论引用输入数据或标记“暂无数据”；
- 报告保存快照，避免模型变化导致前后不一致。

## 6. 模块三：大纲异动与题库联动

### 6.1 大纲异动

需要两类材料：

```text
今年公告/大纲
往年公告/大纲
```

LLM 输出：

```text
新增考点
删除考点
表述变化
对应科目/子科目
证据片段
置信度
```

无往年材料时不生成“异动”，只展示今年考点。

### 6.2 题库映射

复用现有：

```text
question_bank.point_id / sub_category_id / tags
knowledge_point
question_bank.exam_frequency / difficulty
```

映射方式：

1. 标签精确匹配知识点；
2. 关键词/别名匹配；
3. 已有向量检索能力可用时做语义召回；
4. 结果写 `job_question_map`，保存匹配原因和分数；
5. 低置信度题目进入人工抽检，不直接进入题单。

### 6.3 一键题单

生成逻辑：

```text
岗位大纲标签
→ 映射题目
→ 按考点覆盖、难度、考试频率排序
→ 生成 20–50 题题单
→ 用户可预览/替换/开始刷题
```

跳转：

```text
/exercise?job_post_id=<id>&set_id=<id>
```

不新建题库，不复制题目；题单只保存题目 ID 列表。

## 7. 匹配引擎

### 7.1 三态

```text
🟢 完美匹配：硬性条件明确满足，无高风险未知
🟡 风险提示：专业相近、条件未知、基层/体能待核实
🔴 不可报考：学历、政治面貌、应届、性别等明确不符
```

### 7.2 原因结构

```json
{
  "field": "major",
  "result": "risk",
  "message": "岗位要求法学类，你为公安学类，建议核实专业目录",
  "evidence": "公告原文片段"
}
```

### 7.3 规则顺序

```text
学历 → 专业 → 政治面貌 → 应届 → 性别 → 基层 → 年龄 → 体能 → 其他
```

硬性不符直接红灯；未知条件黄灯；全部硬性通过绿灯。

### 7.4 免责声明

```text
本结果为资格预筛，不构成官方资格审核结论。
最终以招录单位审核为准。
```

## 10. 定时任务与通知

| 时间 | 任务 |
|---|---|
| 02:00 | 招考采集 |
| 02:10 | LLM 解析队列 |
| 02:30 | 时间轴/标签/题单候选生成 |
| 每小时 | 扫描 24h/12h 内截止节点 |
| 每日 08:00 | 当日待办汇总通知 |

幂等：

```text
job_reminder: user_id + post_id + node_type + remind_at 唯一
```

失败：

- 通知失败记录状态，重试有限次；
- 采集/解析失败保留旧数据；
- 不因单个来源或单个模型失败清空雷达。

## 11. 权限、隐私与合规

- 资格卡属于敏感个人信息，只对本人和管理员开放；
- AI 报告不预测录取概率；
- 历年数据必须有来源，没有就显示“暂无”；
- 公告解析保留原文证据；
- 采集遵守 robots、服务条款，不绕过登录/验证码；
- 管理端解析/复核操作写审计日志；
- 外部来源 URL 必须经用户确认。

## 13. 验收标准

### 数据

- 职位必须关联公告；
- 学历/专业/政治面貌/应届等字段覆盖 ≥ 90%；
- 时间节点有证据；
- 历年数据有来源，无来源不展示具体数字。

### 匹配

- 硬性规则单元测试通过；
- 专业相近标黄；
- 明确不符标红；
- 每条结论有原因和免责声明。

### 防遗漏

- 截止前 24h/12h 提醒幂等；
- 同一用户同一节点不重复发送；
- 通知失败可重试；
- 时区统一北京时间。

### 题库联动

- 题单只保存题目 ID；
- 题目必须存在且可作答；
- 低置信度映射不进入正式题单；
- 跳转后题单可正常加载。

### 前端

- 现有招考看板不回归；
- 雷达 PC/移动端可用；
- 资格卡修改后实时刷新；
- 对比篮最多 3 个。

## 14. 风险与待确认

|---|---|

6. 02:00/02:10/02:30 调度时间。

## 15. 方案结论

v3.0 将招考模块从“公告聚合”升级为：

```text
信息聚合
→ 资格匹配
→ 时间轴/材料待办/提醒
→ 历年数据/对比/AI 报告
→ 大纲标签/题库题单/刷题
```

同时坚持三条底线：

1. 不重复建表和分裂用户数据；
2. 不编造历年分数、报录比和资格结论；
3. 所有关键结论可解释、可追溯、可人工复核。

审批通过后，按 P0 → P1 → P2 → P3 实施；未批准前不修改代码、不建表、不接入新来源。
