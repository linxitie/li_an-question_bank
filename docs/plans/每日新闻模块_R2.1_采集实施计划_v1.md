## 2. 实施项

1. `NewsSourceConfig` 注册表 + 8 个配置；`news_source` 种子。
2. `NewsStorage` 抽象接口；`LocalNewsStorage` 写 `backend/uploads/news_images/`；DB 存 `uploads/news_images/...` 相对路径。
3. 通用采集器：列表页取链接 → 详情页标题/正文/日期/图片 → URL/标题/内容哈希去重 → 入库 `pending`。
4. 图片去重按 sha256；图片失败不阻断正文入库。
5. CLI `collect_news.py --source ... --limit N --dry-run/--apply`。
6. 调度：08:00、18:00 全量来源；替换原 00:00 新闻任务；单来源失败隔离。
7. 5 个重点站点 live smoke；失败记录状态码/原因，不伪造成功。

## 3. 非目标

- 不写 31 个独立爬虫；不绕过验证码/登录/付费墙。
- 不做 AI 摘要/实体/审核看板（R2.2/R2.3）。
- 不启用 MinIO/OSS；Storage 接口预留。

## 4. 验收

- 8 个 source 配置可枚举；DB `news_source` 有 8 行。
- Storage 测试：相对路径、sha256 去重、路径不可逃逸。

- 5 个重点站点 live smoke 有明确 HTTP 结果；成功站点至少入库 1 条 dry-run 解析。
- `pytest tests/test_news_storage.py tests/test_news_collector.py` 通过；L0 7/7。
