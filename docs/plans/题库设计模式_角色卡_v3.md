## 2 角色卡（装载 → 产出 → 否决 → Token 纪律）

### ARCH 系统架构师

- 否决：跨域直连、新建第 52 个 API 模块（F6 口径）、把重构塞进功能任务。
- Token：ADR 引用事实编号，不重抄数字；方案对比表 ≤2 屏。

### PM 项目管理师

- 否决：无验收命令的任务行、一分支两件事、超预算、在 main 直接干活。

### DATA 数据建模师

## 3 换帽协议（强制）

1. 换帽必留 **Handoff（≤10 行）**：`FROM/TO` + 已定 + 未定 + 风险 + 证据 + 分支。
2. 同一段回复**只允许一顶帽子**；发现越界 → 停手 + Handoff + 回 PM。
3. 跨角色并行条件：文件集不相交；同一文件禁止两角色并写；`SEC∥QA`、`ARCH∥DOC`、`BE∥FE`（契约已冻结）可并行。
4. ≥6 个独立文件只读审计 → `workflow` 扇出；**Agent Teams 仅在用户明确批准 + ≥3 条互不依赖任务时开团**。

## 4 分支一屏（v5 §7 的执行版）

```
main
└── feat/<模块>                ← 模块工作域（父域；本机 4/7 = feature/study-plan、feature/ai-assistant）
     └── feat/<模块>-<子任务>   ← 子分支（一分支一任务；用 `-` 不用 `/`，git D/F 硬约束见基线 F21）
```

```powershell
# 0) 开工先同步（无 upstream 时如实报，不伪造 pull 成功）
git fetch origin --prune; git branch --show-current; git status --short
git rev-list --left-right --count origin/main...HEAD

# 1) 父域快进（领先 0 才允许 --ff-only）
git switch feat/<模块>; git merge --ff-only origin/main

# 2) 开子分支
git switch -c feat/<模块>-<子任务>

# 3) 每文件一验证 + 提交（一逻辑一提交，逐文件 add）
python backend/scripts/gates/gate_all.py --quick
git add <精确文件>; git commit -m "feat(<模块>): <简述>"

# 4) 父域更新则 rebase；收尾只向父域合并/PR
git fetch origin; git rebase feat/<模块>
git push origin HEAD:feat/<模块>
```

硬约束：B1 子分支禁连 main｜B2 一分支一任务｜B3 前缀 feat/fix/test/refactor/docs/chore｜B6 禁 `git add -A`｜B7 大件与密钥不入提交｜B10 不在 main 直接开发｜B12 push 失败如实报。
模块 4/7 详细接管状态见 `题库设计模式_模块4_7交接档案_v1.md`。
