# 考试开关「点一下卡死」缺陷修复方案 v1（待批准）

> 日期：2026-11-12　｜　分支：`feat/material-multi-format-import`（**不动 main**）
> 你反馈（截图 + 3 句话）：管理员端点「考试（可进入）」的开关后，①显示「已关闭」但**按钮没滑回去**；②**再也点不开**；③**设置开考/结束时间也没用**。
> 本文含：真机复现证据 → 根因（三层）→ 修法（后端单一真源 + 前端合并/派生）→ 预期效果 → 测试与验收 → 风险回滚 → 工期。**未改任何代码，等你批准。**

---

## 0. 结论先说

**不是样式问题，是数据契约缺口。** 写接口的返回体比列表接口少了 `manual_open` 字段，前端拿它当"开关真值"用：

- 少了它 → `undefined !== 0` → 开关永远渲染成"开"（你说的①）；
- 少了它 → 再次点击时算出"下一步=关闭" → **永远发 `open:false`**（你说的②）；
- 定时其实**保存成功了**（真机确认 toast「已保存考试时间」+ 行内显示 `20:00-22:00 定时`），但手动闸关着且打不开，状态仍是「已关闭」→ 你感知为"设了没用"（你说的③）。

修法一句话：**让写接口和列表接口返回同一份完整状态（后端一个函数），前端改成"合并 + 派生"，任何一边缺字段都不会再把开关锁死。**

## 2. 根因（三层，逐层可验证）

### 2.1 后端：写端点绕过了 `state_of`，返回体少 3 个字段

`services/exam_gate.py` 里有两个"造状态"的入口：

```python
def state_of(db, material, now=None):        # 列表用：exam_state(...) + manual_open + paper_code + paper_id
def set_open(db, material, *, open_):        # 写端点用：直接 return contract.exam_state(...)   ← 少 3 个字段
def set_window(db, material, *, open_at, close_at):  # 同上
```

实测回包对比（同一张卷，管理员令牌）：

| 来源 | `exam` 的键 |
|---|---|
| `GET /api/materials/admin/list` | `answers_missing, close_at, known, **manual_open**, open, open_at, **paper_code**, **paper_id**, published, question_count, ready, reason, server_now` |
| `PUT /api/materials/admin/128/exam-open` | `answers_missing, close_at, known, open, open_at, published, question_count, ready, reason, server_now`（**缺 3 个**） |
| `PUT /api/materials/admin/128/exam-window` | 同上（**缺 3 个**） |

两条端点都在 `library/materials.py:2003-2013 / 2032-2043`，回包 `{"ok": True, "exam": state}`。

### 2.2 前端：整体替换，把"缺点"传染给整行

```ts
// src/views/admin/materials.vue:726
const state = await setMaterialExamOpen(row.id, nextOpen);
row.exam = state;            // ← 整体替换；state 没有 manual_open，行的 manual_open 就变 undefined
```

### 2.3 派生：三处判断都吃 `manual_open`，于是同时错

| 位置 | 代码 | `manual_open=undefined` 时 |
|---|---|---|
| 开关外观 | `:class="{ 'is-on': row.exam?.manual_open !== 0 }"` | `undefined !== 0` → **true，永远"开"** |
| 下一次动作 | `const nextOpen = row.exam?.manual_open === 0` | `undefined === 0` → **false，永远发"关闭"** |
| 副文案 | `examTimingText`: `manual_open === 0 ? '已手动关闭' : '手动开启'` | 显示**"手动开启"**（和红标签"已关闭"自相矛盾） |
| 无障碍 | `aria-label: manual_open === 0 ? '打开考试' : '关闭考试'` | 一直念"关闭考试"（对读屏用户是错的操作提示） |

**为什么之前没被发现**：刷新列表后 `state_of` 会把 `manual_open` 补回来，行就正常了 —— 只有"点完不刷新"这一瞬间能看见；P2 当时测的是"列表过滤 + 开考拦截"，没测"写回后界面状态"。

## 4. 修法（后端 1 处收敛 + 前端 3 处防御）

### 4.1 后端：写端点改为返回"完整状态"（单一真源）

`services/exam_gate.py` 增加一个内部函数，三处共用：

```python
def _enrich(state: dict, material, paper) -> dict:
    state["manual_open"] = (1 if getattr(paper, "exam_open", 1) is None
                            else int(getattr(paper, "exam_open", 1))) if paper is not None else 0
    state["paper_code"] = paper_code_of(material)
    state["paper_id"] = paper.paper_id if paper is not None else None
    return state

def state_of(db, material, now=None):        # 改为 return _enrich(contract.exam_state(...), material, paper)
def set_open(db, material, *, open_):        # 写完 attribute 后 return _enrich(contract.exam_state(paper, ...), material, paper)
def set_window(db, material, *, ...):        # 同上
```

要点：
- `_enrich` 是**唯一**给状态加"管理端字段"的地方，以后再加字段不会只加一半；
- `set_open` 仍**不 commit**（保持既有事务边界与审计同事务），只是把回包补全；
- 不改 `contract.exam_state` 的语义（它是学生/管理端共用的纯判定，不能掺管理端字段）。

### 4.2 前端：三处防御（即使后端再漏字段也不会锁死）

1. `src/utils/examGate.ts` 新增两个纯函数（可单测）：
   ```ts
   export function examSwitchOn(exam): boolean        // manual_open === 1 → true；=== 0 → false；缺省时按 reason 兜底（reason==='closed' → false）
   export function nextExamOpen(exam): boolean        // 取反，但同样对 undefined 有兜底
   ```
2. `materials.vue`
   - 模板：`is-on` 与 `aria-label` 改用 `examSwitchOn(row.exam)`；
   - `toggleExam`：`row.exam = mergeExamState(row.exam, state, nextOpen)`（合并，且当 `state.manual_open` 缺失时用本次请求意图补齐）；
   - `onExamWindowSaved`：同样合并。
3. `ExamGateDialog` 的 `@saved` 走同一个 `mergeExamState`，避免"设完定时又把开关打回原形"。

> 为什么不在前端"自己算 open"：判定口径（服务器时间/窗口）必须在后端；前端只做**缺字段兜底**，不做真相。
