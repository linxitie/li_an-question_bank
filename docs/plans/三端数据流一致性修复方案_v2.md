## 2. 统一数据口径

> 先定口径，再改代码。所有计数、筛选、前端展示必须引用同一套规则。

### 2.1 题目可见性

- 默认可见：`question_bank.status = 1 AND question_bank.audit_status = 1`。
- 下线/待审默认不计入学员端；教师/管理员通过显式开关查看。
- 统一入口：`QuestionStatsService.visible_query`（P1-1 已完成）。
- 任何新查询不得自行拼 `status`/`audit_status` 条件；必须复用该入口或同口径 helper。

### 2.2 计数单位

- 以 `question_bank` 的**可作答最小题目行**为 1 题。
- 复合题组头/纯材料行不计入题量；组内子题各计 1；若组头本身可作答，按 1 计。
- 子科目题量 = 该子科目下所有可见最小题目行之和。
- 考点题量 = 该 L3 下所有可见最小题目行之和；一题多考点时按 `question_knowledge` 关系计数，但同一题在同一 L3 只计 1 次。
- 前端显示“题量”时不得把组头与子题重复相加。

### 2.3 材料归属

- 复合题材料只存一份：`question_groups.shared_content`（图片在 `shared_content_images`）。
- 组内所有子题通过 `group_id` 共享，不复制到每个子题。
- 非复合题材料可保留在 `question_content`；但一旦建组，材料以组为准。
- 导入时材料归属由 `MATERIAL_OWNERSHIP_V2` 控制；关闭=旧行为，打开=新行为。
- 材料边界规则：材料属于“下一题/下一组”，不属于上一题；文档级材料属于整卷所有小题。

### 2.4 主观题判定

- 以 `question_type.is_objective = 0` 为准，不以“选项为空”猜测。
- 当前主观类型：申论 9-13、写作 6、简述 7、简答 8/14、论述 2；如后续新增类型，以 `is_objective` 为准。
- 主观题 API 必须返回 `is_subjective=true`、`options=[]`；前端据此渲染 textarea。
- 客观题保留 A-D/多选；不得把主观题塞入选项组件。

### 2.5 分类树口径

- canonical 节点：`status=1 AND alias_of IS NULL`。
- 层级：L2 → L3 两级；L2 可展开，L3 为叶子。
- 每个 L2 恰好 1 个 L3“其他”；不同 L2 下同名不构成重复。
- 题目归属：优先 `question_bank.sub_category_id`；其次 canonical `point_id`；都没有则“未分类”。
- “其他”L3 是真实考点节点，承接该 L2 下未细分到具体 L3 的题；“未分类”是题目层隐藏桶，不进入考点树。
- 0/0 节点不返回；L2 总数为 0 时整条 L2 不返回；L3 为 0 时不返回（“其他”同理）。

### 2.6 一致性断言

| 编号 | 断言 | 执行点 |
|---|---|---|
| A1 | 学员/教师/管理员默认总数逐子科目相等 | P1-9 / 手工验收 |
| A2 | Σ子科目可见题 + 未分类 = 全库可见题 | P1-9 |
| A3 | ΣL2 可见题 + L2“其他” + 未分类 = 子科目题量 | P1-9 |
| A4 | API 不返回 `status=0`/`alias_of` 非空节点 | P1-7 / P1-9 |
| A5 | 主观题 `options=[]` 且 `is_subjective=true` | P1-5 / P1-6 |
| A6 | 复合题子题均有 `group_id`，组有 `shared_content` | P3-13 |
| A7 | 树中无 0/0 L2、无重复同级名称、每 L2 一个“其他” | P1-7 / T-10 |
| A8 | 343 个 API 路径不变 | P1-9 / `api_surface.json` diff |
| A9 | 导入后材料不在上一题题干/解析 | P3-13 |
| A10 | 迁移前后行数、题量、关系数有 dry-run 报告 | T-11 |

## 3. 六个问题逐项方案

### 3.1 问题一：学生端题量与教师/管理员不一致

#### 3.1.1 现象与证据

- 用户原话：“在快速练习功能模块中，申论题目、行测和公专题目的数量完全不对标教师端中和管理员中的题目数量；请务必实现教师端、学生端和管理员端的通信机制顺畅、数据流保持一致。”
- v1 基线：全库 3357；学员端可见 229/16/2877；教师/管理员可见 3357。
- 583 题没有 `question_knowledge` 关系；`question_bank` 没有 `sub_category_id`，只有三个文本列：
  - `xingce_subcategory`：判断 52 / 言语 41 / 政治 21 / 资料 18 / 常识 13 / 数量 9 / 知觉 2 / 无 79。
  - `shenlun_subcategory`：议论文 10 / 归纳 10 / 综合 7 / 对策 5 / 应用文 4 / 无 1。
  - `gongzhuan_subcategory`：基础 1869 / 警务 751 / 职业 128 / 无 337。
- `quick_practice.py` 的 `bySubCategory` 仍通过 `question_knowledge` 反查；P1-2 只修了“计数含未分类桶”，题目列表仍走旧路径。

#### 3.1.2 根因

1. **列表路径与计数路径不一致**：计数走文本列/未分类桶，列表走 `question_knowledge`，未关联题在列表消失。
2. **缺少归一化子科目外键**：三个文本列是不同科目各用一列，查询/join 容易漏；没有 `sub_category_id`。
3. **三端默认口径未完全统一**：P1-1 已统一 `visible_query`，但教师/管理员端点仍可能带自己的 `status` 条件或默认参数。
4. **未关联题没有兜底**：583 题既没有知识点关系，也没有进入列表的稳定路径。

#### 3.1.3 设计

1. **新增 `question_bank.sub_category_id`**（nullable、索引），作为归一化子科目外键；保留三个文本列，兼容旧查询。
2. **回填顺序**：文本列 → canonical `point_id` 的 `sub_category_id` → 分类器预测（置信度 ≥0.15）→ NULL（未分类）。
3. **P1-3 直查**：`/quick-practice/questions?bySubCategory=...` 改为按 `sub_category_id` 查 `question_bank`，不再依赖 `question_knowledge`。
4. **P1-4 统一口径**：教师/管理员端点默认调用 `visible_query`；显式开关 `include_offline/include_pending` 才放宽。
5. **返回字段**：`group_id`、`shared_content`、`shared_content_images`、`is_subjective`、`question_type_name`、`requirements`、`score`。
6. **未分类桶**：`sub_category_id IS NULL` 的可见题计入该科目“未分类”计数；列表可单独查询，不混入 L2。
7. **P1-9 断言**：每次迁移/接口改动后跑 A1-A3、A8。

#### 3.1.4 改动文件

- `backend/app/models/models.py`：`QuestionBank.sub_category_id` 映射。
- `backend/app/api/v1/exam/quick_practice.py`：P1-3 直查 + 返回字段。
- `backend/app/api/v1/platform/teacher.py`、`backend/app/api/v1/platform/admin.py`：P1-4 口径。
- `backend/app/services/question_stats.py`：复用 `visible_query`；如需新增 helper，集中在此。
- `backend/scripts/migrate/backfill_question_sub_category.py`（新增）：回填 + dry-run + rollback。
- `backend/scripts/verify_question_counts.py`：P1-9 断言。
- `backend/tests/test_quick_practice_consistency.py`（新增）。
- 前端：`question_bank.vue`、`mobile_practice.vue`、`tablet_question_bank.vue` 的题量展示。

#### 3.1.5 验收标准

- 学员/教师/管理员默认总数逐子科目相等；教师/管理员开关打开=3357。
- 583 题中可归类的进入对应子科目；不可归类的进入“未分类”，不再“消失”。
- `bySubCategory` 不再依赖 `question_knowledge`；未挂知识点的题也能练。
- API 路径/字段名不变；仅新增字段。
- A1-A3、A8 全绿。

#### 3.1.6 风险

- 回填误判：先用 dry-run 输出每个子科目的迁移前后计数，人工抽查 30 题；可 rollback。
- 旧前端依赖 `question_knowledge` 字段：保留返回字段，新增 `sub_category_id` 不替换旧字段。
- 教师/管理员开关行为变化：默认值必须与学员端一致，开关只放宽不下收。

### 3.2 问题二：申论答题卡与行测/公专复合题展示

#### 3.2.1 现象与证据

- 截图 182518：第 1/2 题，`[写作]`，40 分，1000-1200 字；页面却渲染 A/B/C/D，选项内容为“（待补充）”；A 被选中（红色）；无文本作答框；底部“下一题”。
- `src/views/student/shared/exercise.vue`：
  - B4 复合题材料块已存在（`v-if="currentQ.group_id"`，约 lines 92-93），有 group 缓存；
  - `parsedOptions` 约 line 299 始终解析/渲染选项；
  - 选项区约 lines 108/119；笔记 textarea 在 196-201；
  - 没有 `is_subjective` 分支。
- `question_type.is_objective=0` 已存在；申论 9-13、写作 6、简述 7、简答 8/14、论述 2 均为主观。
- 复合题材料可能在 `question_groups.shared_content`，但详情/列表 API 未稳定返回。

#### 3.2.2 根因

1. 前端把“所有题”都当客观题：`parsedOptions` 无条件渲染 A-D。
2. 后端可能返回占位选项“（待补充）”，前端没有 `is_subjective` 可用。
3. 主观题没有 textarea/字数/分值/材料分段布局。
4. 复合题材料块虽有，但 `shared_content` 未随题返回或未在主观题布局中展示。
5. 富文本材料没有统一 sanitize/渲染，图片可能裸露 `<img>` 或裂图。

#### 3.2.3 设计

### 3.6 问题六：导入时复合题材料被切到上一题

#### 3.6.1 现象与证据

- 导入后，材料出现在上一题的题干/解析；下一题缺材料。
- v1 P3-1~P3-7 已定位：
  - `_MATERIAL_HEAD_RE` 只覆盖部分材料头变体；
  - `_strip_trailing_material` 未输出 `material_text`；
  - `_strip_unmarked_material` 过严，无选项/申论/答案后材料漏切；
  - `_mark_and_split_suspected` 缺二次切分；
  - `_extract_blocks_unnumbered` 材料段生成假题；
  - `_parse_essay_document` 缺锚点/文档级材料；
  - `_strip_material_from_analysis` 解析吞材料。
- P0-3 行测 L1 既有 FAIL（4/85 套分节题号区间全等）；材料指纹 364/1.0 与基线一致；说明改动必须带门禁。

#### 3.6.2 根因

1. 解析器以“题目块”为单位，材料被当作题目块尾部，而不是独立块。
2. 没有“材料属于下一题/下一组”的显式归属规则。
3. 文档级材料没有锚点，申论整卷材料无法挂到 Q1..QN。
4. 答案解析中的材料没有剥离，导致解析吞材料。
5. 无编号材料段被误判为题目，生成假题。

#### 3.6.3 设计

1. **P3-1**：扩展 `_MATERIAL_HEAD_RE`，覆盖 6 类变体；单测确保不误伤题干。
2. **P3-2**：`_strip_trailing_material` 输出 `material_text`，不再拼回上一题 `question_content`；调用方把材料写入组。
3. **P3-3**：放宽 `_strip_unmarked_material`，覆盖无选项/申论/答案后材料；用 fixture 防误伤。
4. **P3-4**：`_mark_and_split_suspected` 后处理，二次切分材料归属。
5. **P3-5**：`_extract_blocks_unnumbered` 识别材料段，不生成假题。

### 4.1 设计原则

1. **主流优先**：只保留公安联考大纲主干与高频考点；不把 505 个 PDF 词条全部展开。

### 5.3 505 个别名怎么处理

#### 5.3.1 映射优先级

1. **精确名匹配** canonical L3；
2. **人工别名表**（`taxonomy_alias_review.csv`）匹配常见变体；
3. **子科目内“其他”**：语义属于该 L2 但无法细分；
4. **隐藏 NULL**：噪声词/无法判断（如“最大”“横”“粉笔”），`status=0`、`alias_of=NULL`。

#### 5.3.2 处理规则

- 命中 canonical：原行保留，`status=0`、`alias_of=canonical_id`、`sub_category_id` 对齐 canonical。
- 未命中但属于某 L2：挂该 L2 的“其他”，`status=0`、`alias_of=其他ID`。
- 未命中且噪声：`status=0`、`alias_of=NULL`，不参与分类。
- 不物理删除；不改变原 `point_name`；不覆盖原 `id`。
- 生成 `taxonomy_alias_review.csv`：`old_id,old_name,subject,sub_category,new_id,new_name,match_type,confidence,note`，供人工抽查。

#### 5.3.3 关系迁移

- `question_knowledge.point_id` 指向别名的，改为 `alias_of`；若 `alias_of=NULL`，保留原关系但标记 `status=0`/不参与统计，或迁移到“其他”（按人工表）。
- 同一题同一 canonical 只保留一条关系；重复删除。
- `question_bank.point_id` 指向别名的，改为 `alias_of`；若为 NULL，置 NULL 或“其他”（按规则）。
- 迁移前后输出关系数、去重数、无法迁移数。

| 有三个文本列之一 | 回填 `sub_category_id` | 进入对应子科目 |
| 文本为“无”/空，但有 canonical `point_id` | 用 point 的 `sub_category_id` | 进入对应子科目 |
| 都没有，分类器置信度 ≥0.15 | 写入预测子科目 | 进入对应子科目 |
| 都不满足 | `sub_category_id=NULL` | 进入隐藏“未分类”桶 |

- “未分类”桶只用于计数/待补录；不进入考点树；前端可在子科目卡片显示“未分类 N 题（待补录）”。
- 子科目总数 = ΣL2 可见题 + L2“其他” + 未分类。
- 不把未分类题强行塞进某个 L2，避免污染考点统计。

### 5.5 316 vs 337 对账

- v1 基线写“未分类 79/0/316”；当前 `gongzhuan_subcategory='无'` 为 337。
- 差异 21 题可能来自：`status`/`audit_status` 过滤、空字符串 vs `'无'`、P1-2 未分类桶口径、旧脚本快照时间。
- v2 不硬编码 316/337；迁移脚本输出：
  - 全库 `gongzhuan_subcategory` 分布；
  - `visible_query` 下的分布；
  - `sub_category_id IS NULL` 分布；
  - 三者差异清单（question_id + 原因）。
- 验收以“同一口径下三端一致”为准，不以旧数字为准。

### 5.6 迁移步骤（T-11 执行）

1. **只读盘点**：导出 631 行知识点、3357 题、关系数、三个文本列分布、组数/成员数。
2. **生成 canonical 常量**：`seed.py` 增加 `KNOWLEDGE_TREE_V2`；不写库。
3. **生成别名 CSV**：505 行映射建议；人工抽查 ≥30 行；用户确认高风险映射。
4. **dry-run**：模拟建树/别名/关系迁移/`sub_category_id` 回填；输出：
   - 迁移前后 L2/L3/节点数；
   - 每个子科目题量；
   - 关系数/去重数/无法迁移数；
   - 与三端 API 计数的差异。
5. **备份**：`sqlite3.backup()` 生成 `question_bank.db.bak_taxonomy_v2_<timestamp>`；校验 `integrity_check`。
6. **写库**：事务内建 canonical、写别名、合并“其他”、迁移关系、回填 `sub_category_id`。
7. **验证**：A1-A10；`verify_question_counts.py`；树 API 抽样。
8. **回滚**：`--rollback` 恢复 `sub_category_id`/`alias_of`/`status`/关系；或从备份恢复；同时删 `-wal`/`-shm`。
9. **报告**：`backend/data/audit/taxonomy_migration_dryrun_<date>.json` + 验收报告。

### 5.7 为什么不新建 taxonomy 目录/JSON

- 用户明确要求“去粗取精，不要胡乱新建导致文件夹杂乱”。
- v1 已确认扩展 `question_classifier.py`，不另建分类机制。
- canonical 树是代码的一部分，放 `seed.py` 常量便于 review、diff、测试；不引入运行时读取 JSON 的新路径。
- 505 别名是数据迁移产物，放数据库 + CSV 审计，不需要独立 taxonomy 包。
- 避免“两套分类源”再次漂移：`seed.py` 是唯一 canonical 源，`question_classifier.py` 引用同一名称。

### 5.8 迁移安全红线

- 只用 `sqlite3.backup()`，禁用 `shutil.copy2`。
- 写库前必须 dry-run + 备份 + 用户确认。
- 不删除 `knowledge_point` 行、不删除 `question_knowledge` 行；只改 `status/alias_of/point_id`。
- 不改 API 路径；只新增字段。
- 迁移脚本必须幂等：重复执行不重复建节点/关系。
- 回滚必须同时处理 `-wal`/`-shm`；恢复后跑 `integrity_check`。

### 14.3 设计原则

1. **展示单一入口**：`RichTextViewer` + 升级后的 `renderQuestionContent`；所有题目内容 `v-html` 必须经过该入口。
2. **编辑单一入口**：`RichTextEditor` 封装已安装的 `wangeditor@4.7.15`；本轮不新增编辑器依赖。
3. **双端清洗**：后端写入用 `bleach` 白名单；前端渲染用 DOMPurify/白名单；不信任任何一端。
4. **存 HTML，不存“富文本 JSON”**：继续用 TEXT 字段；纯文本仍合法；编辑器输出 HTML；读取时统一 normalize。
5. **链接安全**：允许 `http/https/mailto/相对路径/#锚点`；强制 `target="_blank"` + `rel="noopener noreferrer"`；拒绝 `javascript:`、`data:text/html`、`vbscript:`。
6. **图片安全**：类型/大小限制；后端压缩；`loading="lazy"`；`onerror` 占位；不删除 `backend/app/static/`；沿用现有 static 挂载。
7. **渐进增强**：升级 `renderQuestionContent` 后，所有既有页面自动获得链接/清洗能力；命名页面再逐步换成组件。
8. **移动端优先**：查看器自适应；编辑器工具栏在窄屏折叠为“基础/更多”；答题卡不引入大工具栏。
9. **可降级**：编辑器加载失败时回退到 `<textarea>` + 实时预览，不阻断提交。
10. **不改 API 路径**：只新增可选端点；343 条既有路径不变。

### 14.9 实施前确认（RT）

1. **DOMPurify 直接依赖**：是否同意把 `dompurify@3.2.7` 从传递依赖提升为 `package.json` 直接依赖？lock 已有，不新增下载包；若不批准，只能扩展正则清洗，安全性较低（不推荐）。
2. **学生作答输入**：是否保持纯文本？本方案按“题目展示富文本、作答输入纯文本”设计；若要求作答也富文本，需增加存储/评分/字数统计/防粘贴攻击设计。
3. **题组图片上传**：是否同意新增 `POST /api/questions/groups/{group_id}/images`（仅教师/管理员，写入 `backend/app/static/question-groups/{gid}/`）？若否，走 data URI + 保存时后端 `save_images_for_group` 提取的兜底。
4. **选项编辑形态**：是否接受“每个选项一个紧凑富文本编辑器”（推荐），而不是继续用 JSON textarea？管理员端会从 JSON 源码改为结构化列表。
5. **`style` 属性**：是否允许安全子集（对齐/颜色/字号/加粗等），否则只保留语义标签？推荐允许安全子集，避免 WangEditor 对齐/颜色丢失。

### 14.10 结论

RT 是跨切面要求，不改变六个问题的编号，也不改变现有 API 路径和数据字段。核心是四件事：

1. **一个查看器**：`RichTextViewer` + 升级后的 `renderQuestionContent`，让图片、文字、HTML、链接、表格、列表在三端一致展示。
2. **一个编辑器**：`RichTextEditor` 复用已安装的 `wangeditor@4.7.15`，覆盖教师、管理员、导入三处预览/编辑。
3. **双端清洗**：后端 `bleach` 写入清洗 + 前端 DOMPurify 渲染清洗，链接/图片协议白名单，XSS 向量测试。
4. **同批落地**：RT-4 与 P1-5/P1-6、RT-5 与 P2、RT-6 与 P3-10/P3-11 同批，避免同一文件重复改模板。
