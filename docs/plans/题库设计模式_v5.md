## §0 五分钟开工清单（复制即用）

## §2 使用规则与事实纪律

1. **数字只认事实基线 v2**：任何数量/路径/行为断言，先查 `题库设计模式_事实基线_v2.md`；表里没有就现场测，测完回填并升版。
2. **旧文档数字一律当线索**：v1 §2 保留 8 项错值（2 项高风险：raw 页数、CLI 路径）作为反面凭证。
3. **不做什么优先**：方案必须先写排除项（P2），再写做法；范围外发现的问题记 Handoff + 缺口表，不当场修（scope-guard）。
4. **证据即完成**：没有命令输出的「完成」判未完成（P7）；未跑的层标「未验证 + 验证方式」。
5. **模式自身变更必须四同步**（§9.3）：文档（权威+索引）、`design_mode.json`、`AGENTS.md §8`、热加载三件。

### 3.5 DeepInfer / PTC 的诚实边界

- **PTC ≠ 本地推理**：PTC 当前指「本地进程/沙箱执行脚本」，可把大语料/题图的统计在本地算完，只回流结论；它不产出 LLM token。
- **DeepInfer 现状（六类证据全空）**：进程无、19999 未监听、8000 属系统进程、无环境变量、`~/.dsh` 与 dsh 安装目录 grep 无命中、npm 全局无相关包；仅存在于规划文档（F19）。任何「本地优先已生效」的声明必须给 endpoint + 一次真实调用日志，否则记「未验证」（A35）。
- **后端 LLM 现状（DeepInfer 落地要接的地方）**：真实客户端在 `backend/app/services/llm_client.py`（OpenAI Chat Completions 兼容 + Bearer + httpx + 重试），路由在 `backend/app/api/v1/platform/llm.py`；键名为 `LLM_API_KEY/LLM_API_URL/LLM_MODEL/LLM_TIMEOUT/LLM_MAX_HISTORY`（**不是** `DEEPSEEK_API_KEY`）。本机无真实 `.env`，真实调用未跑通（F20）。
- **契约先定**：见 §5.2；端点由用户提供后，适配器实现单独立项（G16），不夹带进业务任务。

## §5 模式分层与模型路由（标准 / 创造 / PTC + DeepInfer 契约）

### 5.1 三模式

| 模式 | 触发 | 当前实际路由（2026-11-04） | DeepInfer 就绪后的契约路由 | Token 纪律 |
|---|---|---|---|---|
| **标准** | 常规 CRUD、契约比对、测试、文档、归档 | 云端 `deepseek-flash` + compaction/pruner | 标准请求优先本地 DeepInfer，失败/超时/低置信回云端 | 云端占比目标 ≤40%（待标定，G18） |

### 5.2 DeepInfer 适配器契约 v1（端点由用户提供后实现）

> 状态：**阻塞待补**（F19）。以下契约先定，实现单独立项，不夹带进功能任务。
> **接入面（实测）**：后端 AI 调用统一走 `backend/app/services/llm_client.py`（OpenAI Chat Completions 兼容、Bearer、httpx、重试 1 次），配置键 `LLM_API_URL / LLM_MODEL / LLM_API_KEY / LLM_TIMEOUT / LLM_MAX_HISTORY`；路由在 `platform/llm.py`。**若 DeepInfer 暴露 OpenAI 兼容端点，则接入 = 改 `LLM_API_URL` 指向本地 + 在模式路由里声明，不新写 LLM 客户端。**

**协议要求（必须全部满足才可视为「可接入」）**：
1. `POST {BASE_URL}/v1/chat/completions`，OpenAI 兼容请求/响应；`stream:true` 返回 SSE。

## §6 Token 100% 协议（可审计版）

> **诚实界定**：模型不暴露「每 token 效用」，100% 使用率物理上不可直接度量。
> v5 把它操作化为 **五零指标 + 三张账单 + 每任务计量表 + 目标值**；全部达成即等价「零无效 token」。

### 6.1 五零指标（Z1–Z5）

| 指标 | 定义 | 采集方式 |
|---|---|---|
| **Z1 重复读=0** | 同一文件同一区间一次任务内不读第二遍（内容已变须注明） | `[LOAD]` 字符串逐条对账 |
| **Z2 未验证断言=0** | 每条事实断言附命令/行号或「置信度 + 验证方式」 | 断言清单抽查 |
| **Z3 返工=0** | 因「没读够就写」导致的二次修改 = 0 | `git diff` 次数 + 评审记录 |
| **Z4 超预算=0** | 单轮装载 ≤ 预算档上限 | `ctx_budget.py` 估算 + 可选 dsh-context 读数 |
| **Z5 归档遗漏=0** | 方案/计划/报告/决策 100% 落盘并进索引 | DOC 归档清单 |

### 6.2 每任务计量表（每轮回复末尾填，缺 = Z4 未达成）

```
[TOKEN] tier=T2 | loaded≈<k> | LOAD 条目=<n> | 重复读=0 | 返工=0 | 超档=否
[TOOL]  grep×<n> read×<n> pwsh×<n> mcp×<n> | 失败重试=<n>
[OUT]   新增/修改 <n> 文件 | 归档 <n> 份 | 未验证项 <n> 条
有效 token 率 = 1 - (重复读+返工+无关装载)/总装载    目标：T1/T2 ≥95%
单位产物成本 = 总装载 token / 交付物行数（或用例数）
```

> 采集：①首选 `token-meter` 投影（`tokenUsage` / `contextPressure` / `contextBreakdown`，可重放）；②取不到读数时用 `python scripts/qbdm/ctx_budget.py --tier T2 --log <账本路径> <条目…>` 估算；③长期任务把账本落 `docs/plans/QBDM_装载账本_<任务>.md`。
> **注意**：本机 dsh 命令面**没有 `/context`**（只有 `/compact`、`/feedback`、`/goal`），不得在文档/报告写「用 /context 查占用」。contextPressure 超阈值时按 §6.5 主动 compact。

### 6.3 预算分档（超档即停，先出降档方案）

| 档 | 场景 | 装载上限（估） | 写文件 | 强制产物 |
|---|---|---|---|---|
| **T0** | 问答/查证/解释 | ≤8k | 0 | 结论 + 取证 |
| **T1** | 单文件/契约比对/角色卡校准 | ≤25k | ≤2 | 改动 + 命令输出 |
| **T2** | 3–5 文件/跨层改动 | ≤60k | ≤5 | 声明头 + 计划 + 测试 |
| **T3** | 模块级/十域级 | 分 2 段，每段 ≤60k | 分段提交 | 分段计划 + 每段验收 |

降档手段：拆任务 / 只读摘要 / subagent 隔离 / PTC 本地执行 / 记忆与台账复用。

### 6.4 装载四步与禁用清单

1. **定位**：`grep`/`glob` 拿「文件:行号」清单，不读内容。
2. **切片**：`read offset/limit` 只取 30–120 行；长文件两段夹逼。
3. **摘要代理**：>500 行文件、>1MB 数据先用脚本算统计，只把统计入上下文。
4. **记账**：回帖写 `[LOAD]`。

**禁用**：全库 `tree`；读 `题库/`、`backend/app/static/` 内容（F16）；原样贴回全量测试/门禁输出（只留尾部 ≤20 行 + 退出码）；重复读同段；「为了保险」预读无关文件；读 `docs/archive/` 全文（`grep` 定位即可）。

### 6.5 省 token 的七个固定手法

1. 一次取证多处复用（一份 grep 同时喂 ARCH/API/QA）。
2. 热加载件：日常只读角色卡 v3（≤8KB）+ 模块卡 v3（≤5KB），不读总纲。
3. 门禁即证据：跑一次 `gate_all.py --quick` 就够交差，不「读代码再确认一遍」。
4. subagent 只用于隔离上下文，不为「显得努力」；文件集不相交才并行。
5. PTC/脚本只回统计数字，不回原始数据。
6. 前缀稳定（缓存友好）：固定顺序 `AGENTS → 事实基线 v2 → 角色卡 → 任务书 → 可变内容`，同一任务内不重排。
7. 阶段收尾主动 compact（D3/D6、T5、O4），记忆替代重复推导（但落地前必须用代码核验，A30）。

## §7 GitHub 分支拓扑 v5（用户规范 × git 实测 × 模块 4/7 接管）

### 7.1 用户规范（原文，最高优先级）

```
main（稳定基线）
 └── feat/<模块名>              ← 模块工作域（父分支），只接受经过测试的子分支合并
      └── feat/<模块名>/<子任务> ← 子分支，一次只做一件优化/测试任务
```
要求：开工先 `git pull` 当前子分支；子分支从父域拉出；一子分支一任务；提交前跑测试；一逻辑一提交（`feat/fix/test/refactor: <简述>`）；只向父域合并/PR；父域有更新先 rebase；合并顺序孙→子→模块域→main，永不跳层。

### 7.2 git 硬约束（实测，必须知道）

**同一仓库内，父 ref 与斜杠子 ref 不能并存**：

```
$ git branch qbdm-tmp-test; git branch qbdm-tmp-test/sub
fatal: cannot lock ref 'refs/heads/qbdm-tmp-test/sub':
'refs/heads/qbdm-tmp-test' exists; cannot create 'refs/heads/qbdm-tmp-test/sub'
```

因此「父域 + 斜杠子分支」在**单仓单命名空间**下物理不可行（远端同样受限）。本仓库既有实践已经采用连字符：`feature/study-plan` 与 `feature/study-plan-feedback`（F3/F4）。

### 7.3 三套落地方案（默认 A）

| 方案 | 命名 | 适用 | 命令要点 | 风险/备注 |
|---|---|---|---|---|
| **A（默认，单仓直推）** | 父 `feat/<模块>`；子 `feat/<模块>-<子任务>` | 本仓库多人单仓协作 | `git switch -c feat/<模块>-<子任务> feat/<模块>` | 与用户斜杠格式语义等价；git 安全；已在 origin 有先例 |
| **B（fork + PR）** | 父 `feat/<模块>`（**只在 upstream**）；子 `feat/<模块>/<子任务>`（**只在 fork**） | 跨仓 PR 协作 | fork 内从 `upstream/feat/<模块>` 开子分支；PR base = upstream 父域；本地**不建**父 ref | 单仓直推子分支会 D/F 失败；必须走 fork |
| **C（仅远端父域）** | 本地只见 `origin/feat/<模块>`；子分支用 A 的连字符名 | 只想保留父域远端指针 | `git fetch origin feat/<模块>`；子分支从 `FETCH_HEAD` 开 | 与 A 实际等价，不推荐单独使用 |

**本任务采用**：`feat/qbdm-design`（父域，新建，从 origin/main 拉出）+ `feat/qbdm-design-mode-v5`（子分支，一任务：题库设计模式 v5 创建）。

### 7.4 模块 4 / 7 接管（用户当前职责域）

| 模块 | 工作域（父） | 实测状态（F3） | 子分支命名 | 接管第一步 |

| **模块4 学习计划** | `feature/study-plan` | tip `de68f4a`（10-31）；相对 main 落后 327 / 领先 0 → 内容已全部并入 `main@d3f40492`（首个包含 merge `364b2af`） | `feature/study-plan-<子任务>` | 父域快进到 main 后再开子分支（`git merge --ff-only origin/main`，远端更新需用户批准 push） |
| **模块7 联考小智** | `feature/ai-assistant` | tip `de68f4a`（与模块 4 同 sha）；落后 327 / 领先 0 → 已并入 | `feature/ai-assistant-<子任务>` | 同上 |

### 7.5 标准命令序列（方案 A）

```powershell
# 0) 同步（父域有远端时）
git fetch origin --prune
git switch feat/<模块>
git pull --ff-only                          # 无 upstream 时如实报「本地分支未推送」，不伪造成功（B9）

# 1) 开子分支（一次只做一件事）

# 2) 干活：每文件一验证
python backend/scripts/gates/gate_all.py --quick

# 3) 提交（一逻辑一提交，逐文件 add）
git add <精确文件>; git commit -m "feat(<模块>): <简述>"

# 4) 父域有更新：rebase 到父域最新
git fetch origin; git rebase feat/<模块>

# 5) 收尾：只向父域合并/PR，禁止直连 main
git push origin HEAD:feat/<模块>            # 单仓方案；或推送子分支后开 PR（base=父域）
```

### 7.6 硬约束（B1–B12）

| # | 约束 |
|---|---|
| B1 | 禁止子分支 → `main` 的任何合并/PR；只能对父域 |
| B2 | 一子分支一任务；混入无关改动 = 打回 |
| B3 | 提交前缀 `feat/fix/test/refactor/docs/chore`；正文写清归档主题版本 |
| B4 | 提交前必须跑改动域测试；失败先修不提交 |
| B5 | 合并顺序：孙 → 子 → 模块域 → main，永不跳层 |
| B6 | 禁用 `git add -A`；逐文件精确 add |
| B7 | 大件与密钥不入提交（`题库/`、`static/`、`.env`、`backend/data/*.bak*`、`.superpowers/`、`.opencode/`） |
| B8 | 禁止本地同建父 ref 与斜杠子 ref（§7.2） |
| B9 | 无 upstream 时如实报「未推送」，不伪造 pull 成功 |
| B10 | 不在 `main` 上直接开发/提交（只允许只读 fetch） |
| B11 | 父域落后 main 时先 `--ff-only` 快进（领先 0 才允许），不制造 merge commit |
| B12 | push 失败（网络/权限）如实记录 + 重试；禁止伪造推送成功 |

| 红线/凭据 | `gate_l0_redlines.py` + `check_secrets.py` | 无密钥入库 |
| **模式/文档/台账变更** | `qbdm.py status` + `pytest scripts/qbdm -q` + `gen_module_ledger.py --check`（漂移时登记，不阻断本任务） | 资产齐全 + 模式单测全绿 |
| 任何提交前 | `python backend/scripts/gates/gate_all.py --quick` | 退出码 0（快速层 F10：L0/L1-G/L1/L1-H） |
| 合并父域前 | `gate_all.py` 全量（无 DB 环境按 F16 说明降级并标注） | 完整输出尾部 ≤20 行 + 未覆盖项 |

### 9.2 三层汇报口径（QA 强制）

3. **残留风险**：明确写「没测什么」。

## §11 产物模板

### 11.1 四类产物骨架

- **方案（spec）**：`§1 问题与边界（不做什么） / §2 事实证据（表） / §3 方案对比≥2 / §4 选定方案 / §5 影响面 / §6 验收标准 / §7 风险与回滚 / §8 CTC-11`。
- **计划（plan）**：任务表 `ID | 动作 | 涉及文件 | 验收命令 | 依赖 | 预算 | 角色`，每行可独立提交。
- **报告（report）**：`结论 / 证据（命令+退出码+关键行） / 未覆盖项 / 归档路径`。
- **技能正文（skill）**：按《技能重建手册 v2》落 `.opencode/skills/<name>/SKILL.md`（不入 Git，入手册）。

### 11.2 声明头 v5（每轮必填）

```
[MODE] 题库设计 v5 | STATE design|test|optimize
[ROLE] <代号> <角色> v3
[MODULE] <模块id 或「非模块」>
[BRANCH] <当前子分支>（父域 <feat/模块>）
[TASK] QBDM-<日期>-<序号> <一句话>
[BUDGET] T0|T1|T2|T3（已装载估计）
[LOAD] <文件:行区间> ×≤3
[TOKEN] 重复读 0 | 返工 0 | 超档 否
[MCP] <vtj 工具名，可空；未桥接写「未桥接」>
[GATE] <门禁命令>
```

### 11.3 Handoff 单（换帽必填，≤10 行）

```
FROM: <代号> → TO: <代号>   MODULE: <id>   BRANCH: <子分支>
已定：<≤3 行>
未定：<≤3 行>
风险：<1–2 行>
证据：<命令/文件:行号>
```

### 11.4 归档三件事（DOC 强制）

1. 写权威位置：设计/报告 → `docs/plans/`（或 `docs/superpowers/specs/`）；计划 → `docs/superpowers/plans/`；运维 → `docs/ops/`。
2. `solve_problems_files/` 已不存在（迁移完成）→ 只写 `docs/` 对应子目录，不再新增副本。
3. 更新索引：`docs/README.md` 活跃文档表 + 变更记录。
