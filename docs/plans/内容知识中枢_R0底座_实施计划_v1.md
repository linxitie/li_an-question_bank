# 内容知识中枢 R0 底座实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use `subagent-driven-development` (recommended) or `executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不改变既有 343 端点与三端行为的前提下，建立内容知识中枢的图谱底座：主题字典、薄边图、统一来源、金句扩展字段、通知表、三类内容回填、Obsidian 导出骨架与可回滚的迁移。

**Architecture:** SQLite 仍是唯一事实源。新增 `topic` / `kg_edge` / `kg_relation_type` / `content_source` / `content_evidence` / `user_notification` 与金句扩展列；图谱只存 `(type,id)` 指针，不复制正文。Obsidian 只做单向投影，R0 不实现回写审核。

**Tech Stack:** Python 3.14 · FastAPI · SQLAlchemy 2.x · SQLite（WAL）· pytest · APScheduler（R0 不新增任务）

**Spec:** `docs/plans/内容知识中枢设计方案_v3.0.md`（R0 章节 §16）

## Global Constraints

- 不改既有 API 路径/方法/响应外壳；只新增 `/api/kg/*`（R11）。
- 数据库备份必须 `sqlite3.backup()`；禁止 `shutil.copy2`（R10）。
- 不新增第三方依赖；不引入 Neo4j/MongoDB/Milvus/MinIO。
- 不改 `.vtj/` 模板、不移动 `.vtj/`、不新建平板重复页（R1/R3/R12）。
- 分支：`feat/content-hub/r0-foundation`（父分支 `feat/content-hub` 在远端）。
- 暂存只用显式路径；禁止 `git add -A`。
- 提交信息：`feat|fix|test|refactor: <简述>`。
- 所有新增写操作必须幂等；重复执行不产生重复边/来源/通知。
