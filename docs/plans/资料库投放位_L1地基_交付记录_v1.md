## 1. 改了什么（6 个文件）

| 文件 | 改动 | 为什么 |
|---|---|---|
| `backend/app/models/models.py` | 新增 `placement` 列（**nullable、无 Python 默认值**） | 用"NULL=按类型推断"兼容老数据；若给 `default="library"`，老代码/ORM 建的试卷行会变成"仅资料页"，上架不再发卷（实测会让 5 条既有 P5 用例失败） |
| `backend/app/main.py` | 启动期自动 `ALTER TABLE ... ADD COLUMN placement` + 建索引 + 回填 | 沿用 `list_time` 的既有先例，零 Alembic；回填口径：试卷→`both`（=改造前行为），其余→`library` |
| `backend/app/services/material_paper_sync.py` | `placement_of()`（含类型推断）+ `EXAM_PLACEMENTS`；`sync_material` 增加 `exam_side`；`_has_other_published` 只统计"含考试页"的资料 | P5 从"资料状态 → 卷状态"升级为"资料状态 × 投放位 → 卷状态"，语义仍留在服务层，考试域契约不改 |
| `backend/app/services/material_files.py` | `can_download(..., placement="library")`：非管理员要求 `placement ∈ {library,both}` | "只考试、不给原卷"必须在**下载边界**上也成立，否则知道 file_id 就能绕过 |
| `backend/app/api/v1/library/materials.py` | ①`_placement_of()` 归一化；②列表过滤 + `placement/file_count/has_files`；③详情补 `files/placement/doc_meta`；④上传收 `placement` 并校验；⑤`PATCH meta` 可改投放位并立即同步；⑥管理端预览回 `placement`；⑦下载路由传 placement | 全部是"入参/出参扩展"，**端点数量不变**（API 面仍 343） |
| `backend/tests/test_materials_placement_l1.py` | 新增 13 例 | 见 §3 |

## 2. 语义（唯一口径，前后端/测试都按这个来）

```
资料库可见 = status == 1 且 placement ∈ {library, both}      (NULL 视为 library)
考试页可考 = paper_type == 'PUBLISHED' 且 placement ∈ {exam, both}   (NULL 视为 both)
原件可下载 = 管理员 或 (status == 1 且 placement ∈ {library, both})
```

| placement | 上架后 资料库 | 上架后 考试页 | 原件（学生） | 谁来写这个值 |
|---|---|---|---|---|
| `exam` 仅考试 | ❌ 不出现（直连详情 404） | ✅ 卷 PUBLISHED | ❌ 403 | 上传试卷时选、或改信息 |
| `library` 仅资料 | ✅ 出现 | ❌ 卷保持/落回 DRAFT | ✅ | 同上 |
| `both` 都投 | ✅ | ✅ | ✅ | 同上；**试卷上传不选时的默认** |
| `NULL`（老数据/ORM 直建） | 按 library | **按 both**（= 改造前） | 按 library | 只有迁移前的历史行才会出现 |

上传参数校验（实测都符合预期）：

- 试卷：`placement` 空 → `both`；合法值 → 原样落库；非法值 → 400；
- 非试卷（article/lecture）：传 `exam`/`both` → 400「只有试卷类资料可以选投放位」；不传 → `library`。
