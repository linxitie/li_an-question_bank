## 3. P1 · 上传即建卷

### 3.1 行为

`POST /api/materials/admin/files/upload`（批量导入的单文件入口）在**新建**资料时多走一步：

```
type == paper 且 target_placement ∈ {exam, both}
   → 取编号（表单科目 + 文件名年份/地区/卷别）
   → ensure_paper_for_material(db, material, actor_id=…, paper_name=文件名去扩展名)
   → 回包多一个 paper 块；审计多一条「自动建卷」
```

- **编号合成**：`parse_paper_file_name(文件名)` 解析年份/地区/卷别；**科目解析不出来时用上传表单里选的科目兜底**。
  这条是 #128 的真实教训 —— `2016江西招警考试《人民警察基础知识》真题（部分）.docx` 年份/地区/卷别都能解析，
  只有「人民警察基础知识」不在科目关键词表里 → 以前 `build_paper_code` 直接拒绝生成编号，列表里连「建卷」都不出现。
- **卷名**：`paper_name` = 文件名去扩展名（决策 ②），不继承管理端填的展示标题（标题可能带「（精校版）」这类修饰）。
- **幂等**：以 `paper_code` 为唯一键，同编号重复上传 ⇒ `created=false`，不建第二张，也**不会把已发布的卷改回草稿**。
- **不阻断上传**：编号缺年份或地区时不建卷，资料照存，回包给可操作提示：

  ```json
  {"paper": {"created": false, "reason": "no_code",
             "hint": "文件名里没解析出「年份 + 地区」，未自动建卷；在「改信息」补编号后可点「建卷」"}}
  ```
- **审计留痕**：成功与跳过都写 `自动建卷`（跳过时 detail 记原因），便于回溯"为什么这份资料没有卷"。

### 3.2 前端

- `MaterialBatchUpload.vue`：队列行多一行回执 —— 建成显示 `已自动建卷 GZ-2019-BJ-T（0 题，导题后学生才能考）`，
  没建成显示 hint（中性色，不与失败混为一谈）。
- `UploadFileResult.paper` 类型同步（`src/modules/library/api.ts`）。

## 4. P2 · 考试开关与定时

### 4.1 数据

`exam_paper` 新增三列（启动期自动 `ALTER`，沿用 `publish_target` 先例，无需手工迁移）：

| 列 | 类型 | 语义 |
|---|---|---|
| `exam_open` | Integer，默认 1 | 手动总闸：1 开 / 0 关（NULL 兼容为开） |
| `exam_open_at` | DateTime，nullable | 定时开始（空 = 该侧不限） |
| `exam_close_at` | DateTime，nullable | 定时结束（空 = 该侧不限） |

### 4.2 判定（读取时计算，不靠 cron）

`backend/app/api/v1/exam/contract.py`：

```
exam_is_open   = exam_open==1 且 (now >= open_at 或未设) 且 (now < close_at 或未设)
exam_ready     = paper_type == 'PUBLISHED' 且 exam_is_open 且 题量 > 0
exam_state     = 原因码 ready/draft/no_questions/closed/not_started/expired/no_paper + server_now
open_conditions= 同一口径的 SQL 条件（列表分页下推，total 才准）
```

- 为什么不用定时任务：单机部署/开发机常常没有 supervisor，漏跑一次就会出现"该开的没开、该关的没关"；
  读取时计算是纯函数，天然幂等、进程重启无影响。
- **题量口径**：`question_count` 是缓存值（实测漂移过，`paper_stats.py` 注释里有「导入 110 题却写成 1」），
  所以 `question_total(db, paper)` 在缓存值 ≤0 时回落 `paper_question_relation` 实数；SQL 侧用 `EXISTS` 子查询对齐。
  这样 **既不会把"有题但计数漏更"的卷挡在门外，也不会让 0 题空卷混进学生列表**。

### 4.3 学生端三处（同一判据）

| 位置 | 行为 |
|---|---|
| `GET /api/papers/list` | `user_type == 'student'` 时叠 `open_conditions()`；教师/管理员**不过滤**（他们要能看到并管理自己关掉的卷） |
| `POST /api/exams/start` + 老路 `POST /api/exams/{paper_id}/start` | 新开一场必须 `exam_ready`，否则 400 + 人话原因（`考试已关闭…`/`考试还没到开始时间（2026-11-09 20:00 开始）`/`考试已结束（…）`/`这场考试还没有题目…`） |
| 资料详情 `paper` 块 | `answerable` = `exam_ready`；新增 `exam` 状态块 + `exam_hint`，学生端卡片「暂不可考」下方直接显示原因 |

`S2` 的落点：两个开考端点都先查"有没有未完成记录"，**有就继续**（即使考试此刻已关闭），再判开关。
实测：把 #4 关掉后，学生带着 record #1 再次进入 → 200、`exam_id` 仍是 1、`is_continuation=true`。

### 4.4 管理端 UI

- 列表新增「考试（可进入）」列（仅「试卷 + 投放位含考试页」显示）：
  开关 + 状态标签（可进入 / 已关闭 / 未开始 / 已结束 / 未发布 / 无题）+ 定时摘要（`20:00-22:00 定时` / `手动开启` / `无题（0 题）不可开`）。
- **0 题强制灰掉**开关并给出原因（打开也进不去，宁可"看起来不能用"）。
- 新组件 `ExamGateDialog.vue`（Teleport + mask，因为 Element Plus 是按需引入、`el-dialog` 全局不存在）：
  开始/结束时间 + 「快速填：今晚」（按**服务器日期**填 20:00–22:00）+ 当前状态（服务器时间）+ 保存前效果预告。
- 保存走 `PUT /admin/{id}/exam-window`（两端都空 = 取消定时），回包直接覆盖本行状态，不整表刷新。

### 4.5 接口（R11：只登记不重算基线）

| 方法 | 路径 | 说明 |
|---|---|---|
| PUT | `/api/materials/admin/{material_id}/exam-open` | `{open: bool}` → 返回 `{ok, exam}` |
| PUT | `/api/materials/admin/{material_id}/exam-window` | `{open_at, close_at}`（`YYYY-MM-DD HH:MM` 或 null） |

`backend/data/refactor_baseline/api_surface.json` 的 `materials.py` 条目按「只登记」原则追加这 2 条（20 → 22）。

## 5. 过程中修掉的 3 个真 bug（都有回归用例兜住）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| B1 | 管理端开关显示"关"但状态算成"已结束" | `int(state.get("exam_open") or 1)` —— `0 or 1` 得 1，`0` 被吞掉 | 抽 `_manual_open()` 显式判 `None`；`state_of` 同步修 |
| B2 | 有题（关系表有 20 条）但 `question_count=0` 的卷被拦 | 判定只看缓存计数 | `question_total()` 兜底 + SQL `EXISTS` |
| B3 | 1440 宽下 12 列表格把「操作」列顶出卡片 | 新增列后总宽超容器 | 固定表布局 + 标题两行截断 + 表身横向滚动兜底 |

B1 是这一轮单测抓出来的（`test_contract_exam_state_reasons` 期望 `closed` 实际拿到 `expired`）；
如果没有这条用例，线上表现会是"管理员关了考试，界面却说考试已结束"。
