## 2. 改了什么

### 2.1 ① 手机端整卷考试（`src/views/student/mobile/mobile_answer.vue`）

同一份组件按 `?paper_id=` 分流，**不新增路由**（路由条数是门禁基线 L6/L7：105 条）：

| 模式 | 入口 | 行为 |
|---|---|---|
| 练习（原有） | `/mobile/answer?knowledge_point_ids=…` | 本地判分、答后看解析 |
| 整卷考试（新增） | `/mobile/answer?paper_id=5` | 开考 → 作答 → 交卷 → 服务端评分 → `/paper-result` |

关键实现点：

1. **开考**：`POST /api/exams/{paper_id}/start` —— 直接复用现有闸门（开关/定时窗口/有题），
   400 的 `detail` 就是给学生看的人话（"考试已关闭…"），原样展示；
2. **取题**：`GET /api/exams/{paper_id}/questions`，`options` 是 `[{key,value}]`，
   交给已有的 `normalizeOptionsForDisplay()` 归一（会自动去掉「A.」前缀，字母由模板另渲染）；
3. **考试中不泄露答案**：`showResult` 在试卷模式恒为 `false`（原来末题/全答完就显示解析），
   同时隐藏「做题/记背」模式切换与本地成绩汇总；
4. **题型行去重**：原模板是 `type_label · question_type_detail` 两段拼接，考试接口只有一个
   `type_name`，两段都填会显示「单选题 · 单选题」→ 新增 `typeLine` 计算属性去重；
   但 `question_type_detail` 对多选题必须仍是 `'多选题'`（`isMulti` 靠它判断，否则多选只能单选）；
5. **交卷**：`POST /api/exams/{record_id}/submit`，**客观题每题都提交（未作答传空串）** ——
   与 PC 答题卡一致，这样 `exam_answer_detail` 条数 = 卷题数，结果页「正确/错误 0 / N 题」分母才对；
   实测只提交已答题会显示成「0 / 1」（见 §4 自曝）；
6. 交卷后 `router.replace('/paper-result?record_id=…&paper_id=…')`（结果页已按 `is_scored`
   + `answered_count` 统一口径，手机 390 宽实测可读）。

`src/views/student/mobile/mobile_student_papers.vue` 的点卷逻辑从
`/answer?paper_id=`（PC 页）改为 `/mobile/answer?paper_id=` / `/tablet/answer?paper_id=`。

### 2.2 ② 试卷列表考试状态

| 层 | 改动 |
|---|---|
| 后端 `api/v1/exam/exams.py::get_exams_list` | 每条卷附 `exam`（`contract.exam_state`，含 `ready/reason/open_at/close_at/server_now`）、`answerable`、`exam_hint`（`exam_block_message` 译成人话）。判定用**服务器本地时间**，前端不自己算 |
| 前端 `src/modules/papers/api.ts` | 新增 `PaperExamState` / `ExamPaperItem` / `fetchExamPapers()`（打 `/api/exams/list`） |
| 前端 `mobile_student_papers.vue` | 改用 `fetchExamPapers()`；卡片右上角「可考」绿标 / 「未开放」琥珀标 + 原因行；不可考时点击给提示而非无反应；补「满分」tag |

> 为什么手机列表用 `/api/exams/list` 而 PC 仍用 `/api/papers/list`：
> `/api/papers/list` 对**学生**会把"关掉/未到时间/已过期/0 题"的卷**过滤掉**（P2 口径），
> 学生看不到"为什么这套卷不在"；`/api/exams/list` 不过滤，才能显示原因。
> 这是有意为之，若后续要让 PC 也显示"未开放"，需要产品上确认放开隐藏。

### 2.3 ③ 批量一键上架

现状先讲清楚（避免重复造）：

| 通道 | 之前是否已支持上架 |
|---|---|
| 批量上传对话框（`MaterialBatchUpload.vue` → `/admin/files/upload`） | ✅ 有「立即上架」勾选，且走 P5 联动 |
| 列表多选「批量上架」（`src/views/admin/materials.vue`） | ✅ 有（逐条 PUT status，天然带联动） |
| 旧管理页 `batchPublish()` | ✅ 有 |
| **API 批量创建 `POST /admin/batch`** | ❌ **只写 status，不联动卷**，且没有 `publish` 开关 |

本轮补的正是最后一行：

```python
publish = bool(body.get("publish"))          # 一键上架：覆盖 items 里各自的 status
status  = 1 if publish else item.get("status", 0)
...
syncs = material_paper_sync.sync_materials(db, created_objs)   # P5 联动，不 commit
return {"created": …, "published": len(created_objs) if publish else 0, "paper_sync": [...]}
```

同时给批量建「试卷资料」补了 `paper_code` 与 `placement` 透传（原来被 `_validate_material_body`
白名单丢掉 → 联动取不到卷，`skipped=empty_code`，一键上架就只改了资料状态）。

## 4. 自曝一个联调中发现的坑（已修）

**现象**：第一版手机交卷后，结果页显示「正确/错误 **0 / 1** 题」，而总分是 `/97`。

**根因**：交卷体只传了"已作答的题"，后端 `question_ids = list(answers.keys())` 据此建明细 →
只建了 1 条；结果是分母变成"答了几题"。

**修法**：客观题**每题都传**（未作答传空串），与 PC 答题卡一致 →
明细 = 97 条，结果页恢复「0 / 97 题」（§3.1 图 02）。

## 5. 已知边界（未做，写清楚免得验收时踩空）

| # | 边界 | 说明 |
|---|---|---|
| 1 | 无倒计时 | PC 答题页有剩余时间提示，手机版 v1 没做；超时判定仍由后端 `duration` + `allow_late_submit` 负责 |
| 2 | 无断点续答 | 中途退出再进：`start` 会复用未完成记录，但**已选的答案不会回填**（PC 有 `save_progress`） |
| 3 | 结果页是 PC 页 | `/paper-result` 在 390 宽可读（图 02），但不是专门设计的手机布局 |
| 4 | 仅客观题自动判分 | 主观题输入框已复用，但主观题不自动判分（`is_scored` 会因待人工评分置 0） |
| 5 | 手机列表比 PC 多显示"未开放"卷 | 见 §2.2 结尾，属于有意差异 |
