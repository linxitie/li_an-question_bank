## §0 六项一览（含实测根因）

| # | 现象 | 根因（已定位） | 修法 |
|---|---|---|---|
| 1 | 手机端详情长标题顶破卡片 | 详情页根类是通用 `.page`，我上一轮的全局规则限定 `.mobile-forum-page`，**没命中**；`.post-title`（`mobile_forum_detail.vue:459`）无 `overflow-wrap` | 在详情页自身 `<style>` 补换行（该文件是手写页，不受 R3 限制） |
| 2 | 详情页点赞/收藏错乱 | PC 详情把「点赞」按钮画成了 **五角星**（`forum.vue:304` 用 `Star/StarFilled` 却调 `toggleLike`）→ 用户以为那是收藏；且详情**没有收藏按钮**；手机端详情**没有收藏按钮** | 图标归位：爱心=喜欢、五角星=收藏，两个独立按钮，状态互不影响 |
| 3 | 评论只显示「几天前」 | `formatTime()` 是相对时间（PC `forum.vue`、手机 `mobile_forum_detail.vue:311`） | 评论改为绝对日期（年月日） |
| 4 | 手机端从详情返回列表跳回顶部 | 返回时列表页重新挂载 → `onMounted(loadPosts)` 重置滚动 | 记录 `scrollTop` 到 sessionStorage，列表加载后恢复 |
| 5 | 字号/颜色发布后不显示 | **手机端列表与详情都没传 `:format`**（`mobile_forum.vue:80`、`mobile_forum_detail.vue:37/87/130`），`ForumContent` 默认按 TEXT 渲染 → HTML 被当纯文本；列表还把 `p.content`（HTML）直接当摘要 | 三端统一传 `contentFormat`；列表摘要改用「剥标签后的纯文本」 |
| 6 | 手机端发帖无富文本工具栏 | `mobile_forum_create.vue` 是纯 textarea，没有接入 `RichTextEditor` | 复用 PC 同款 `RichTextEditor`，并行文存 HTML |

## §1 逐项方案

### #1 手机端详情标题不越界

```css
/* mobile_forum_detail.vue <style> */
.post-title { overflow-wrap: anywhere; word-break: break-word; }
.page { min-width: 0; }
```
（该页面是手写 SFC，不涉及 VTJ raw 页 template，安全。）

### #2 点赞 / 收藏归位

| 位置 | 现状 | 改为 |
|---|---|---|
| PC 详情 `forum.vue` | 星形图标调用 `toggleLike`，无收藏按钮 | `❤/♡` 调 `toggleLike`；新增 `★/☆` 调 `toggleFavorite`，都带 v3 的容器动效 |
| 手机详情 `mobile_forum_detail.vue` | 只有爱心喜欢 | 爱心旁加五角星收藏（调 `toggleForumFavorite`），状态独立 |
| 手机列表 | 只有❤与★（已存在但需核对是否都走对接口） | 核对 `liked` / `favorited` 各自独立，不串 |

验收：总览点赞后进详情，爱心是亮的、五角星是灭的；反之亦然。

### #3 评论绝对日期

统一格式 **`YYYY-MM-DD HH:mm`**（如 `2026-11-04 20:30`）。
- PC 详情评论（含子回复）、手机详情评论（含子回复）；
- 帖子本身的发布时间保留现相对时间不变（用户只要求评论）。

### #4 手机端返回保持滚动位置

- 打开详情前：把列表滚动容器的 `scrollTop` 写入 `sessionStorage['mobile-forum-scroll:<tab>']`；
- 列表加载完成（`loadPosts` 成功）后：读取并 `scrollTop` 还原；
- 搜索/切页签/主动刷新时清空该记录，避免"恢复到搜索前的位置"这种错乱。

### #5 富文本在三端正确显示

- `mobile_forum.vue`：`<ForumContent :content="post.excerpt" :format="post.excerptFormat" />`；
  映射时把 `contentFormat` 带上；**列表摘要用 `stripHtml(content)`**（两行截断，不渲染大字号，避免列表高低不齐）。
- `mobile_forum_detail.vue`：正文与评论都传 `:format`。
- 顺带修：`#55` 这类「内容是 HTML 但 `content_format=TEXT`」的历史脏数据，
  前端在 `ForumContent` 增加**兜底判断**：`format==='TEXT'` 但内容看起来是 HTML 文档时，
  转义显示（保持安全，不执行标签），避免又出现 `<h1><span style=...>` 字面量。

### #6 手机端富文本编辑器

- `mobile_forum_create.vue` 用 `<RichTextEditor>` 替换 textarea（与 PC 同一组件、同一菜单）；
- 提交时 `contentFormat: 'HTML'`；
- 预览区 `<ForumContent :content="content" format="HTML" />`；
- 保持既有「表情 / 表情包」按钮可用（由 wangEditor 的 emoticon 菜单承接，或保留原按钮）。

## §6 实施记录（2026-11-04）

| 项 | 实际做法 |
|---|---|
| #1 | 手机详情页自身 `<style>` 补 `overflow-wrap`；`.page` 加 `min-width:0; overflow-x:hidden` |
| #2 | PC 详情改为「❤/♡ 喜欢 + ★/☆ 收藏」两个按钮；手机详情补收藏按钮（`toggleForumFavorite`）；都挂容器动效（喜欢红圈 / 收藏金圈） |
| #3 | 手机详情评论改 `formatDateTime`（`YYYY-MM-DD HH:mm`）；PC 详情本来就是绝对时间，无需改 |
| #4 | `.vtj/vue/mobile_forum.vue`：`viewPost` 前存 `scrollTop` → `sessionStorage`；`loadPosts` 完成后 `nextTick` 还原；切页签/搜索时清空 |
| #5 | 手机列表摘要改「剥标签纯文本」；手机详情正文与评论都传 `:format`；`ForumContent` 对 `format=TEXT` 但内容是 HTML 的脏数据做**转义兜底** |
| #6 | 手机发帖页接 `RichTextEditor`（与 PC 同一套 17 个菜单），`contentFormat='HTML'`；表情包改插 `<img class="forum-sticker">` |

### 顺手修掉的三个连带问题

1. **手机收藏弹窗点不动**：模板用 `@click="goToDetail(p)"`，但 setup 里从来没定义过 `goToDetail`
   → 现改为 `goToDetail: viewPost` 别名，点收藏项能进详情。
2. **e2e 自己把自己限流**：全局限流 `300 请求/分钟/IP`，整套用例远超此数，
   表现为「登录超时 / 列表空白」的假失败。把阈值做成可配置
   `RATE_LIMIT_PER_MINUTE`（默认仍 300），本机 `.env` 设 5000。
3. **管理端看板用例依赖真实数据**：清掉测试帖后词云为空导致断言失败。
   改为用例内自建 6 条带不同关键词的帖子、跑完 purge，使断言数据自洽。

### 测试写法上的两个坑（供后来者）

- **Playwright 的 `click()` 会先把元素滚进视野**，把测前设置的 `scrollTop` 清零；
  要测滚动保持，必须在页内 `el.click()` 点视口内的卡片。
- 手机列表是异步加载的，测滚动前必须先 `expect(.post-card).toBeVisible()`，
  否则测到的容器 `scrollHeight === clientHeight`，怎么设都滚不动。
