## 1. 本轮实测：管理员端上传资料卡片（已跑通）

用 `openpyxl` 造 3 行卡片表（`正面 / 背面 / 分类`）→ 走既有导入链路：

| 步骤 | 接口 | 结果 |
|---|---|---|
| ① 上传解析 | `POST /api/materials/admin/import/upload` | **200**，`{"import_id":1,"parse_status":"success"}`，耗时 0 s |
| ② 轮询状态 | `GET …/import/{id}/status` | `parse_status=success` |
| ③ 取预览 | `GET …/import/{id}/preview` | **200**，`file_type=xlsx`，`rows=3`，中文无损 |
| ④ 确认入库 | `POST …/import/{id}/confirm`（`column_mapping {front:0,back:1,category:2}`） | **200**，`{"created":3,"material_ids":[4,5,6]}` |
| ⑤ 上线 | `PUT /api/materials/admin/{id}/status {"status":1}` | **200 ×3**（导入默认 `status=0` 下架态） |

**当前可验收数据**：`study_material` 中 `type='card'` 共 **3 条**（`#4 逻辑填空三步排`、`#5 中心理解避坑`、`#6 同符查找怎么练`，均 `xingce` / `方法技巧` / `status=1`）。

### 1.1 顺带发现一个真缺陷（D1，待另立分支修）

导入确认时，服务端对每张卡跑 `classifier.classify()`，把 **`type` 判成了 `article`**：

```
#4 xingce type=article cat=方法技巧 front=1 back=41   ← 导入后
#4 xingce type=card    cat=方法技巧 front=1 back=41   ← 我手动 PUT type=card 后
```

**后果**：卡片会落进「备考指南」（article 分区），**翻卡 UI 完全用不上**——即"上传了卡片却看不到卡片"。

**修复方向（另开子分支，不在本分支混入）**：`materials.py` 的 xlsx 分支里，当 `column_mapping` 同时给出 front+back 时，**强制 `type='card'`**（或让 `classify` 接受 `hint_type='card'`），并加一条回归测试。

## 4. 实现方案（分三步，第 1 步不需要改模板）

### T-01 数据与分类修正（后端，无需改模板）

- 修 D1：xlsx 卡片导入强制 `type='card'`（另立子分支 `-import-card-type`，**不属于本分支**）
- 本分支只做：`card_front/card_back` 字段语义确认 + 空 `card_back` 的兜底文案

### T-02 视觉增强（**需要你在设计器拖拽**，R3）

| 效果 | 现状 | 目标 | 实现归属 |
|---|---|---|---|
| 翻转 | 已有 `flipCard` + `.face.back`（**无 3D**，是显隐切换） | 加 `perspective: 1200px` + `rotateY(180deg)` + `backface-visibility: hidden`，560ms | **CSS 由我写**（`.vtj` 的 `<style>`）+ **容器由你拖**（保证 DOM 结构在设计器里有对应节点） |
| 翻页堆叠 | 无 | 单卡聚焦模式：露边叠层 + 左右滑动 + 进度点 | 需新增 DOM（叠层容器），**你拖** |
| 字号三档 | 无 | 根变量 `--sm-font-scale`（0.9/1.0/1.15/1.3），正文 `clamp()` | **我写 script + style**，档位按钮**你拖** |

### T-03 性能与降级（我独立完成）

- 只动 `transform`/`opacity`；单卡 DOM ≤ 40 节点
- `prefers-reduced-motion: reduce` → 关闭 3D，改显隐
- `hardwareConcurrency ≤ 4` 或 `deviceMemory ≤ 2` → 关闭视差与阴影
- 首屏卡片 ≤ 20 张，图片 `loading="lazy" decoding="async"`
