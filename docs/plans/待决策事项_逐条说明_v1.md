# A 组 · 开工阻塞项（D28–D39）

## D28 · 管理页到底怎么改

**背景**：现在的 `/admin/materials` 指向 `.vtj/vue/admin_materials.vue`（VTJ 低代码页）。项目红线 R3 规定 **AI 不得改 `.vtj` 页面的 `<template>`**，只能由你在设计器里拖。而本轮要加：预览列/按钮、发布者列、上传时间列、6 类类型筛选、试卷与讲义展示、批量双格式上传——**在低代码页里靠拖拽基本做不完**。

**要决定的事**
1. 是「新建一个手写 Vue 页替代它」，还是「保留低代码页、由你在设计器里改造」；
2. 如果新建：旧页是否保留（决定回滚路径）；
3. 若选设计器改造：你能接受分几次拖、以及 AI 只能写 `<script>`（不能动模板）这个限制吗。

**选项差异**
- **A 新建手写页**：`src/views/admin/materials.vue` 全新实现；路由 `/admin/materials` 改指向它；`.vtj` 页**不删不改**（设计器仍能打开）。→ 开发快、样式完全可控、可回滚（改回路由即可）。
- **B 设计器改造**：模板由你拖，AI 只补 script。→ 需要你投入时间逐块拖，且复杂表格/抽屉在低代码里表达困难，预览抽屉、批量上传大概率做不出来。

**我的建议**：**A**。理由：本轮改动量已超出低代码页承载范围；A 不违反任何红线（路由是 `src/`，`.vtj` 文件一字节不动）。

**影响**：A 批全部任务；`src/router/index.ts`（改 component 指向）；`.vtj/vue/admin_materials.vue`（保留不动）。

## D29 · 两个新类型叫什么（键名与中文名）

**背景**：`study_material.type` 现在是字符串列（`String(20)`），后端白名单 `TYPES = {video_intro, video_advanced, article, card}`。要新增「讲义」「试卷」两类。

**要决定的事**
1. 英文键名（存库值）：`lecture` / `paper`？
2. 中文展示名：讲义 / 试卷（还是"讲义资料""真题试卷"）；
3. 是否同时把 `card` 的中文从"知识卡片"改成"卡片"（你截图里下拉是"知识卡片"，列表徽标是"卡片"，**文案不一致**）。

**选项差异**
- **A `lecture` / `paper`**：与现有 `article`/`card` 风格一致，零迁移（只改常量与前端映射）。
- **B 其它命名**（如 `handout`/`exam`）：同样零迁移，但与已有词表风格不一致，后续易混。

**我的建议**：**A**，同时统一中文为「讲义」「试卷」，并把下拉里的"知识卡片"改成"知识卡片（卡片）"或在列表徽标统一为"卡片"。

**影响**：`materials.py:30 TYPES`、`models.py` type 列注释、前端 6 项映射、统计卡片。

## D30 · PDF 与 Word 是"一条资料两份文件"还是"两条资料"

**背景**：你的素材里同一份内容常同时有 pdf 和 word（如某讲义既有排版 PDF 又有可编辑 Word）。现在一张资料只关联一个文件（`content` 存 HTML、`cover_image` 存图，**原件根本没留**）。

**要决定的事**
1. 两条格式是合成**一条资料**（列表一行、两个格式徽标），还是两条独立资料；
2. 如果合成：清理/删除时是否两份一起删；
3. 如果两条：列表会出现"同名两行"，是否接受。

**选项差异**
- **A 一条资料 + `material_file` 多行**（format=pdf/docx，role=primary/alternate）：列表干净、筛选不重复、可"下载另一格式"。
- **B 两条资料互相引用**：实现简单，但列表重复、统计口径失真、学生端出现重复卡片。

**我的建议**：**A**。新增 `material_file` 表是唯一干净解法（一资料多文件）。

**影响**：新表 `material_file`、上传配对逻辑、列表 `files` 字段、预览抽屉「下载 Word/PDF」。

## D31 · 两种格式里谁是"主文件"

**背景**：配对后要决定哪份用于**解析正文/章节**，哪份只作**原版下载**。

**要决定的事**
1. 主文件 = Word 还是 PDF；
2. 主文件解析失败时是否自动用另一份兜底；
3. 只上传一种格式时，是否允许（应该是允许）。

**选项差异**
- **A docx 主、pdf 副本**：docx 有标题样式，能切章节（讲义要求），PDF 只作原版排版与下载。
- **B pdf 主**：pdf 排版稳定但**章节切分差**（尤其扫描件），且 Word 的结构信息浪费。

**我的建议**：**A**，并在解析失败时自动回退另一份（记 warning）。

**影响**：解析路由、讲义章节数/字数、预览抽屉的默认显示。

## D32 · 试卷元数据从哪来

**背景**：试卷需要科目/年份/地区/题本还是答案/题量/满分，才能展示与筛选。现在这些信息**散在文件名和第一页**里，`exam_paper_tag.exam_province` 实测**全为 NULL**（说明以前靠猜，猜不出地区）。

**要决定的事**
1. 上传时是否**强制填表单**（7 项元数据）；
2. 是否允许从文件名自动预填（如 `公专_2024_国考_题本.pdf`）；
3. 元数据缺项时是否允许入库（建议：科目/年份/地区/类型四项必填，其余可空）。

**选项差异**
- **A 表单必填 + 文件名预填**：数据质量可控，筛选可靠；代价是上传时多填几下。
- **B 只解析文件名**：省事，但命名不规范就废；历史上已证明地区字段会全空。

**我的建议**：**A（必填）+ B（预填辅助）**。

**影响**：试卷上传弹层、`exam_paper`/`exam_paper_tag` 写入、筛选器（科目+年份+地区）。

## D33 · 申论"4 道论述题"本轮要不要拆成题目

**背景**：行测/公专全是选择题、申论是 4 道文本论述题。拆题入库（`question_bank`）是另一条链路（题目导入），现在 `question_bank` 只有 200 题且**全是公专**。

**要决定的事**
1. 本轮只把试卷当**资料**上传（原卷 PDF/Word + 元数据），还是同时拆题；
2. 若不拆题，学生端只能"看卷"，不能"做题"——是否接受；
3. 拆题放 P2 时，先做哪 3 份样例。

**选项差异**
- **A 只存原卷 + 题数**：本轮 8 天可交付，风险低；学生端"看原卷"。
- **B 本轮就拆题**：要额外 2–3 天（还要人工校对），且会与 P0 进度条/批量上传争工期。

**我的建议**：**A**（拆题归 P2，已存档 `paper_code` 关联方案）。

**影响**：C 批范围、`exam_paper` 写入时机。

## D35 · 侧栏冻结怎么实现

**背景**：管理员端左侧菜单由 `.vtj/vue/app_navigation.vue` 渲染（`.app-navigation` / `.nav-item-box`）。滚动页面时它会跟着走。

**要决定的事**
1. 用**全局 CSS**（sticky/fixed）还是改布局组件；
2. 如果滚动容器不是 `body`（而是某个 flex 内容区），需要给容器加 `height:100vh; overflow:hidden` —— 会改变页面滚动位置记忆，是否接受；
3. 平板/手机是否也冻结（建议不）。

**选项差异**
- **A 全局 CSS**：改 1 个 scss 文件，零模板改动，可回滚；但受父容器 `overflow` 影响，需要实测滚动容器。
- **B 改布局组件**：最稳，但布局在 `.vtj` 里 → **违反 R3**。

**我的建议**：**A**（先探测滚动容器，给 3 套备选 CSS）。

**影响**：`src/style/index.scss`、管理端所有页面的滚动行为。

## D37 · 「上传时间」到底取哪个时间

**背景**：列表要显示"上传时间"。系统里有两个时间：
- `material_import_record.create_time`（文件**进队列**那一刻）；
- `study_material.create_time`（确认入库那一刻，**已有且零迁移**）。
两者可能差几秒到几十分钟（扫描件 OCR 慢）。

**要决定的事**
1. 列的语义按"进系统"还是"入库"；
2. 是否新增 `uploaded_at` 列把真正的上传时间固化下来（加 1 列迁移）；
3. 预览抽屉是否同时显示两个时间。

**选项差异**
- **A 取入库时间**：零迁移、与排序/追溯一致；极端情况（OCR 1.8 小时）"上传时间"会晚很多。
- **B 取文件上传时间**：语义更准，但要加列并在 confirm 回填；迁移 + 代码更多。

**我的建议**：**A**（列名沿用"上传时间"，预览抽屉里另显示"文件上传于…"作为补充）。

**影响**：列表字段 `created_at`、排序参数、迁移（A 无迁移）。

## D39 · 执行顺序：先做 v3 前端批，还是先补导入进度迁移

**背景**：之前批准的 P0（批量+进度条+7 列迁移）还没开始；现在又加了 v3（类型/预览/发布者/双格式/试卷讲义）。两边都涉及"批量上传+进度"。

**要决定的事**
1. 先做哪个批；
2. 进度模型迁移（P0 的 7 列）是否并入 v3 的 B 批（一次迁移 vs 两次）；
3. 若先做 A 批，导入仍是旧单文件向导，是否接受"中间态"。

**选项差异**
- **A 先 A 批（前端可见）**：1–2 天就能在页面上看到"6 类型 + 发布者 + 上传时间 + 预览"效果；批量/进度在 B 批补。
- **B 先补 P0 迁移**：底层先稳，但 1–2 天内看不到页面变化。

**我的建议**：**A**，并明确"进度模型 7 列并入 B 批，只迁移一次"。

**影响**：整个排期与迁移次数。

# B 组 · 下一阶段（试卷/题目线）D21–D27

## D21 · 试卷拆题放哪期
**要决定**：拆题（PDF/Word → `question_bank`）是本轮、P2，还是永远只做整卷资料。
**差异**：本轮=工期 +2~3 天且需人工校对；P2=本轮先"能看能筛"，后续再"能做"。
**建议**：P2。

## D22 · 首批 3 份样例选哪三份
**要决定**：用哪 3 份试卷做拆题试点（决定评估的代表性）。
**建议**：公专 docx（结构化最好）+ 行测 pdf（文字型）+ 申论 pdf（主观题），覆盖三类题型与两种格式。

## D23 · 原卷与结构化题目是否双存
**要决定**：同一份试卷，原卷资料（可看排版）与题库题目（可练）是否都保留并关联。
**差异**：双存=学生端可"看原卷+做题"，但要维护关联；只存题目=原卷排版丢失。
**建议**：双存并关联（`paper_code`）。

## D24 · `paper_code` 规则
**要决定**：试卷编号用人读规则码（`GZ-2024-GK-Q`）还是继续系统随机码（`PAPER-20261026-...`）。
**差异**：人读码可幂等（同卷重复上传不新建）、可从文件名反推；随机码零改动但无法反推。
**建议**：人读码。

## D25 · 试卷元数据上传形态
**要决定**：是否在系统内提供"上传试卷元数据表（模板 3）→ 生成空试卷"，还是元数据只作为题目导入的参数、不落库。
**差异**：落库才能按年份/地区筛、才能聚合"某年真题有几套"；不落库则永远缺这些维度（现在 `exam_province` 全空就是后果）。
**建议**：系统内上传并落库。

## D26 · 题目导入页怎么加"归属试卷"选择
**背景**：题目导入页是 `.vtj/vue/question_import.vue`（170 KB，R3 禁改模板）。
**要决定**：用 DOM 注入在原页加一个下拉，还是新建一个手写页承接"选试卷 + 上传题目"。
**差异**：注入=零新页但控件易被重渲染冲掉；新页=可控但要改路由与入口。
**建议**：新建手写页。

## D27 · 原卷资料与试卷记录怎么关联
**背景**：我原先建议"复用 `study_material.source` 写 `paper_code`"，**实测该表没有 `source` 列**（列清单：`material_id/subject/type/category/title/summary/content/card_front/card_back/cover_image/.../content_hash/source_material_id/point_id`）。
**要决定**：是"新增 `paper_code` 列"，还是"把 code 塞进 `summary`/`title` 约定"。
**差异**：新增列=可查询、可索引、可校验（推荐）；塞文本=脏、不可靠。
**建议修正为**：**新增 `study_material.paper_code` 列**（唯一一处迁移）。原建议作废。
