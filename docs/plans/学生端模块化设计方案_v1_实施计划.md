## 二、背景与约束

### 2.1 方案要点（摘自规格，实施时必须一致）

1. **不改目录归属，只建立所有权**：`.vtj/`、`backend/app/api/v1/` 原地不动，模块化靠「所有权映射 + 外壳 + 事件」实现。
2. **20 个模块，17 个在范围内**：⑱⑲⑳ 功能还未开发，不实现、不发事件、不占文件所有权（入口仍在 `question_bank.vue`，归 ②）。
3. **横向星型**：⑮ 成就成长是枢纽，10 条入边（E1..E10），3 条非成就边（E11 ③→④、E12 ③→⑥、E13 ⑧→⑤）。方向单向，业务模块不 import 成就模块，成就模块不 import 任何业务模块。
4. **纵向三角色 + 三设备**：复用 `backend/app/api/v1/platform/websocket.py` 4 个端点与 `POST /ws/notify/{user_id}`，不新建推送服务。
5. **后端是唯一事实来源**：前端事件总线（mitt）只是加速器；每页 `onMounted` 必须拉取一次 API 兜底。

### 2.4 全局完成定义（DoD）

一个任务视为完成，必须同时满足：

1. 目标文件已变更且 `git status --porcelain` 只含本任务预期文件；
2. 任务行「验收标准」中的命令/检查**全部实际执行**并贴出输出（不得口头声明）；
3. 约束列列出的 C 编号全部自检通过；
4. 依赖任务已处于「已完成」状态。

一个阶段视为完成，必须满足该阶段「退出标准」+ P1-32 / P2-82 / P3-08 验证任务通过。

### 5.3 禁止的回滚方式

- 禁止 `git reset --hard` 覆盖他人分支；禁止 force push 共享分支。
- 禁止为回滚而删除或重建 `.vtj/` 文件（R1）。
- 禁止用 `shutil.copy2` 恢复 SQLite（R10）；如需恢复数据库须用 `sqlite3.backup()` 并同时处理 `-wal`/`-shm`。
- 禁止清理 `backend/data/*.bak*`、`backend/data/audit/`、`待推断题目清单_*.csv`（R8/R9）。
