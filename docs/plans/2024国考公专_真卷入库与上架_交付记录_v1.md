## 1. ① 抽图：不再靠人眼猜，用版面坐标锚定

### 1.1 方法（`backend/scripts/seed_2024_gk/attribute_figures.py`）

原做法是"我看图猜这图属于哪题"，图多必错。改成两步：

1. **机器定位**：用 PyMuPDF 取每张图的 `bbox`，同时取全文的**锚点**（题号行 `^\d+[.．、]` 共 100 个 + 情境材料段首共 8 个），把图归到"(页码, y) 不大于图片顶边的最后一个锚点"；
2. **人工只判两类**：这张是**重复件**还是**浮图**（Word 把图排到了别处）。

43 个图对象里：**4 类丢弃**（文字被切成图片的碎条：`110/113` 标题碎片、`87/89/91/92/93` 多选题说明条、`82/83/84/111/112/114/115/116/117` 行内图标）、**2 组重复件**（同一张图在 PDF 里存了两份，一高清一低清）：

| 重复对 | 判定依据 |
|---|---|
| `xref120`(1051×612) vs `xref123`(449×298) | 两张都是**雨东派出所巡逻警组位置示意图**，一字不差；120 高清 → 留 120，弃 123 |
| `xref136`(864×546) vs `xref139`(444×186) | 两张都是**电信网络诈骗高发案件类型统计图**；136 高清 → 留 136，弃 139 |

**浮图实证**：`xref120` 在版面上落在**题 74** 的题干与选项之间，但题干讲的是"房檐滴水调解"，与图毫无关系；而题 75 明写「小张立即查看了派出所 4 个警组当前位置（**见下图**）」——所以 120 属于题 75。这类"坐标对、语义错"的浮图，就是必须人工过一遍的原因。

### 1.2 结论数字

- 图对象 **43** → 真图 **23** 张（去重后）；
- 挂图题 **28 道**（题 40–50、65–70、75、86–89、94、95、97–100）；
- 反向校验："题干里提到 下图/表中/如图 却没挂图"＝**0 道**。

## 2. ② 100 题入库

### 2.1 口径

- 端点：`POST /api/questions/import/batch-parsed`（单请求、单事务、`questions` 上限 500）；
- 归卷：`paper_code=GZ-2024-GK-T` → 按编号命中卷 #4（A2 已修的"按编号复用，不受 <5 题阈值影响"）；
- 结构化：题干 HTML（情境材料 + 题干 + 图），`options` 四项 `{key,value}`，`answer`，`answer_analysis`，`question_type_detail`（单选/多选），`difficulty=3`，`score=1`，`source=2024国考公专（网友回忆版）`；
- 题型判定：优先取题干内的「（单选）/（多选）」标记，缺失时取 PDF 的 `【题型】` 段落状态机。

### 2.2 一次事故与处置（值得记下来）

首轮 **95 题成功、5 题失败**，失败原因全部是：

```
{'field': 'question_content', 'rule': 'R-LONG',
 'message': 'question_content 长度 163589 超过上限 50000'}
```

即：题 41/48/49/75/94 的图是整页大小的图表，base64 内联直接把题干撑到 7 万–16 万字符。**没有降低校验上限**（那是安全网），而是给导入脚本加 `--static-urls`：把原图复制到 `backend/app/static/questions/_seed2024/`，正文只写 `<img src="/static/questions/_seed2024/gk2024_xrefNNN.jpeg">`。原图无损、题干降到几百字符，5 题补录全部成功。

> 这也解释了库里 28 道带图题为什么有两种 src：23 张走"base64 → 链路落盘 → 回写 `/static/questions/{题号}/`"，5 张大图直接引用 `_seed2024/`。

|---|---|
| 本卷题目 | 100（题号 1–100 无缺号、无重号） |
| 题库总数 | 200 → **300** |
| 卷 #4 关系 | 0 → **100**；`exam_paper.question_count` 0 → **100** |
| 带图题 | 28（图片文件 28/28 命中，0 缺失） |

### 2.4 入库后自查抓到的真错位（已修）

对着学生预览逐题核图时发现：**题目内容没错，题序错了**。

- 现象：题 41 的图出现在预览第 97 位，`paper_question_relation.question_order` 与 `question_number` **60 条不一致**；
- 根因：首轮 95 题按题号顺序入库，5 题补录是**追加**进去的，`question_order` 拿到 96–100 → 41 之后的题全部前移一位；
- 为什么测试没拦住：单测只断言关系条数，没人断言"顺序＝题号"；
- 修法：`update paper_question_relation set question_order = cast(question_number as int) where paper_id=4`，**没有改任何题干/答案**；
- 复核：`order` 1–100 连续、去重 100、与题号 0 不一致；学生预览带图题落在 **40–50 / 65–70 / 75 / 86–89 / 94 / 95 / 97–100**，逐条对上；卷 2、卷 3 复核本来自洽（各 100 条，0 不一致）。

> 这条是"只看接口 200 就会漏"的典型：接口返回 100 题、图片都在，但顺序错的学生是按 41→42 往下做的，实际第 97 位才是 41。文档留档，后续入库脚本应默认写 `question_order = 题号`。

## 3. ③ 资料上架：样张换成真卷，联动发布

### 3.1 为什么要动资料 #127

#127 原名「2024国考·公专题本」，`type=paper`、`paper_code=GZ-2024-GK-T`、`status=1`（**早就上架**），但它的原件是一份 **36 KB 的样张 docx**（329 字、两道示例题）。也就是说：编号对得上、卷也建了，可**学生看到的"真题"是样张**。这正合你「这次是真卷，不是样张」那句。

### 3.2 五步（每步失败即停）

| 步 | 动作 | 结果 |
|---|---|---|
| 1 | `DELETE /api/materials/admin/127/files/6` | 200，`physical_deleted=true`，样张 docx 下线 |
| 2 | `POST /api/materials/admin/files/upload`（`material_id=127`, `subject=gongzhuan`, `type=paper`） | 200，真 PDF 落为 **primary** 原件（1,354,909 字节） |
| 3 | `PATCH /api/materials/admin/127/meta` | 200，`changed=[title,book_kind,book_kind_label,duration,question_count,region_code,region_name,total_score,year]` → 标题改真名、2024/国考/题本/100 题/100 分/120 分钟 |
| 4 | `PUT /api/papers/4`（`paper_name`） | 200，卷名同步为真名 |
| 5 | `PUT /api/materials/admin/127/status` `{status:1}` | 200，`paper_sync: DRAFT → PUBLISHED`（P5 上下架联动） |

**坑**：`book_kind` 只能传 `A/J/T`（答案/解析/题本），第一次传 `zhenti` 被 400「卷别只能是 ['A','J','T'] 之一」——不是缺陷，是校验在正常工作。
