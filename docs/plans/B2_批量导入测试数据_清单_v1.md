## 2. 三套验收剧本（按顺序跑，数字可对账）

> 起始基线（2026-11-08 实况）：总资料 **114**、文章/讲义 **3 / 2**、已上架/未上架 **102 / 12**。

### 剧本 A：正常批量（分三次，避免"一批只能一个类型"）

> 为什么分三次：入库参数（类型）是**整批统一**的，试卷和讲义不能混在一批里，否则试卷会被标成讲义。

| 步骤 | 操作 | 预期 |
|---|---|---|
| A-1 | 「批量导入」→ 选 **4 个试卷文件**（两个 `·题本` 的 docx+pdf）→ 类型 **试卷** → 开始导入 | 编排 `将创建 2 条资料（含 2 组双格式）`；队列 2 行「成功」；列表多 **2 条试卷**（各 2 个原件） |
| A-2 | 再开一次 → 选 **6 个文件**（两章讲义的 docx+pdf 共 4 个 + `公专高频考点速记.docx` + `申论素材积累·2024热点.docx`）→ 类型 **讲义** → 开始导入 | 编排 `将创建 4 条资料（含 2 组双格式）`；列表多 **4 条** |
| A-3 | 再开一次 → 只选 `单独一份试卷·模拟卷.pdf` → 类型 **试卷** → 开始导入 | 编排 `将创建 1 条资料`；列表多 **1 条试卷** |
| A-4 | 核对统计 | 总资料 = 114 + **7** = **121**；试卷 = **3**（2 + 1）；文章/讲义 = 3 / **6**（2 + 4） |
| A-5 | 任选一条配对资料点「预览」 | 底部「原件（2）」：`DOCX …主文件` + `PDF …附件`，两个都能下载 |
| A-6 | 任选一条单文件资料点「预览」 | 「原件（1）」，role 是主文件 |
| A-7 | 核对状态 | 每条都是**未上架**（需手动上架） |

### 剧本 C：同批同名冲突（UI 上不好构造，已由测试覆盖）

同一个 Windows 目录里放不了两个同名文件，而「选择文件」是一次替换式的（不是追加），
所以"同批两个同名同类型"在浏览器里**没法手工构造**。这条规则由单元测试锁死：

- `src/utils/__tests__/batchUploadPlan.spec.ts` →「同名同类型重复 → 只留第一个并报 repeated」
- 想手工验证：把两个文件分别传到两台目录，用接口各传一次（第二次后端会判**重复跳过**，
  这验证的是内容去重，不是同名规则）。

保留 `03_同名冲突/A|B` 这两个文件，是为了说明"同名不同内容 = 两条独立资料"（正常，不该合并）。

### 剧本 D：异常文件

| 步骤 | 操作 | 预期 |
|---|---|---|
| D-1 | 选 `04_异常用例/说明文本.txt` | 立刻出现红色提示「格式不支持」，**「开始导入」保持禁用**（不会发请求） |

## 3. 核对口径（别把正常当异常）

| 现象 | 说明 |
|---|---|
| 导入后正文区是「该类型暂无预览内容」 | 本批只留档原件，不抽正文；正文/章节树归 C1 |
| 资料都是「未上架」 | P0 裁定：批量导入默认 `status=0`，需逐条上架 |
| 文件名里的 `·` 保留原样 | 文件名即资料标题（缺省），C2 会加"文件名解析元数据" |
| 重复判定是**内容 sha256**，不是文件名 | 改个名字重传同内容仍会被判重复 |
