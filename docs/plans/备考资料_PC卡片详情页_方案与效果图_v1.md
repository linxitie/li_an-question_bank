## 2. ⚠️ 必须先说清的硬约束（R3）

`/materials/xingce` 等三科页是 **VTJ 页面**（`.vtj/vue/materials_*.vue`）。项目红线 **R3：AI 禁止修改其 `<template>`，只可改 `<script>` 且需先 `dryRun`**。

因此"把列表改成堆叠"这类**模板级改造我不能做**。合规落地两条路：

| 路径 | 做法 | 谁做 | 合规性 |
|---|---|---|---|
**A（推荐）** | 三科页只改 `<script>`：给卡片加点击 → `router.push('/materials/:subject/cards/:id')`；**新建手写详情页** `src/views/pc/material_detail.vue` + 路由 | 我（script + 新页） | ✅ 不碰 VTJ template |
**B** | 在 VTJ 设计器里由你拖出详情页容器，我写样式与逻辑 | **你**拖 + 我写 | ✅ 完全合规，但依赖你的时间 |

> 本方案按 **A** 设计；若你更想 B，告诉我，我改成"容器清单 + class 命名"给你拖。

## 3. 详情页结构（PC_2 效果图）

```
┌ 顶栏：返回 ｜ 行测 · 语句排序解题步骤 ｜ 收藏 ────────────────┐
│ 左：知识模块(7项，带张数) + 字号三档 │ 中：5层堆叠大卡(560×520)│ 右：本科目其他卡片 │
│                                     │ 正面/背面 3D 翻转        │ (5 条，当前高亮)  │
│                                     │ 底部三键 上一张/翻转/下一张 │                  │
└──────────────────────────────────────────────────────────────┘
```

**数据来源**：`GET /api/materials?subject=xx&type=card`（已含 `card_back`，实测 22 条行测卡）；细类计数由 `category` 聚合。

## 4. 交互状态机（与手机端共用逻辑）

| 状态 | 触发 | 表现 |
|---|---|---|
S1 正面 | 默认 | 标题+正文+标签，按钮「翻转看要点」 |
S2 翻转中 | 点卡片/按钮 | `rotateY 0→180°`，0.4s |
S3 背面 | 翻转完成 | 显示 `card_back`，按钮「再翻一遍 / 下一张」 |
S4 切卡 | 下一张 | 当前卡缩下飞出 → 叠底；新卡补位；`n/N` 递增 |
S5 换子类 | 点左侧模块 | 卡片栈替换为该子类第一张，进度改为"该子类 n/M" |

## 5. 验收标准

| ID | 项 | 通过标准 |
|---|---|---|
V1 | 列表页字号 | 卡片标题 ≥16px，一屏 5 列不挤 |
