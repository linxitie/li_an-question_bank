## 问题深度分析

### 根本原因
- Windows 系统默认的控制台编码为 **GBK**（`'gbk'`），而 Python 的 `logging` 模块在输出日志时，会使用 `sys.stderr` 或 `sys.stdout` 的编码来编码日志消息。
- 日志消息中包含 **Unicode 字符 `\u2713`（✓）**，该字符不在 GBK 字符集中，因此 `logging.StreamHandler` 在写入流时抛出 `UnicodeEncodeError`。
- 该错误发生在 **APScheduler** 的后台线程中，导致爬虫任务执行日志无法正常输出，影响运维监控和问题排查。

### 间接影响
- 即使爬虫功能本身成功，日志错误会导致日志记录不完整，难以追踪爬虫运行状态。
- 频繁的日志错误还可能污染日志文件，甚至影响其他正常日志的输出（因为 `logging` 的 `emit()` 异常会触发 `LoggingError`）。

---

## 完整解决方案

### 一、立即修复（修改代码/启动环境）

#### 1. 在应用入口强制设置标准流编码
在 `main.py` 或应用启动脚本的**最开头**添加以下代码，确保 `sys.stdout` 和 `sys.stderr` 使用 UTF-8 编码：

```python
import sys
import io

# 强制标准输出/错误流使用 UTF-8 编码
if hasattr(sys.stdout, 'buffer'):
    sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding='utf-8', errors='replace')
if hasattr(sys.stderr, 'buffer'):
    sys.stderr = io.TextIOWrapper(sys.stderr.buffer, encoding='utf-8', errors='replace')
```

#### 2. 配置 logging 的 Handler 明确指定编码
配置日志时，为 `StreamHandler` 指定使用 UTF-8 编码：

```python
import logging

# 创建控制台 handler，显式指定 encoding='utf-8'
console_handler = logging.StreamHandler(sys.stdout)
console_handler.setLevel(logging.INFO)
console_handler.setFormatter(logging.Formatter('%(asctime)s - %(name)s - %(levelname)s - %(message)s'))

# 写入文件（如有必要）也指定编码
file_handler = logging.FileHandler('app.log', encoding='utf-8')

# 获取根 logger 并添加 handler
root_logger = logging.getLogger()
root_logger.addHandler(console_handler)
root_logger.addHandler(file_handler)
```

#### 3. 设置环境变量 `PYTHONIOENCODING`
在启动脚本（如 `start.sh` 或 `start.bat`）中添加：

```bash
# Windows CMD
set PYTHONIOENCODING=utf-8
python main.py

# Windows PowerShell
$env:PYTHONIOENCODING="utf-8"
python main.py

# Linux/macOS
export PYTHONIOENCODING=utf-8
python main.py
```

> **推荐组合**：使用 **方法1+方法2** 最为稳妥，环境变量可作为辅助。

### 二、优化日志格式，使其美观整齐

#### 1. 统一日志格式模板
定义清晰、一致的日志格式，包含时间、模块、级别和消息：

```python
LOG_FORMAT = (
    "%(asctime)s | %(levelname)-8s | %(name)-15s | %(message)s"
)
DATE_FORMAT = "%Y-%m-%d %H:%M:%S"

formatter = logging.Formatter(LOG_FORMAT, datefmt=DATE_FORMAT)
```

**输出示例**：
```
2026-09-07 10:30:15 | INFO     | recruitment_scraper | [recruitment/公安联考] ✓ 成功: 15 条
```

#### 2. 使用结构化日志（可选）
若期望更易于解析，可采用 JSON 格式（如 `python-json-logger`），便于后续导入 ELK 或其他日志系统。

#### 3. 避免非 ASCII 字符（临时方案）
若无法立即解决编码问题，可将 `✓` 替换为 `[OK]` 或 `SUCCESS`：

```python
logger.info(f"[recruitment/{category}] [OK] 成功: {len(records)} 条")
```

但这仅是临时措施，不建议长期使用。

### 三、完整代码修改示例

#### `main.py` 或 `app/__init__.py` 启动入口：

```python
import sys
import io
import logging
from logging.handlers import RotatingFileHandler

# ----- 第一步：强制标准流为 UTF-8 -----
if hasattr(sys.stdout, 'buffer'):
    sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding='utf-8', errors='replace')
if hasattr(sys.stderr, 'buffer'):
    sys.stderr = io.TextIOWrapper(sys.stderr.buffer, encoding='utf-8', errors='replace')

# ----- 第二步：配置 logging -----
def setup_logging():
    # 日志格式
    fmt = "%(asctime)s | %(levelname)-8s | %(name)-20s | %(message)s"
    datefmt = "%Y-%m-%d %H:%M:%S"
    formatter = logging.Formatter(fmt, datefmt=datefmt)

    # 控制台 handler（明确编码）
    console = logging.StreamHandler(sys.stdout)
    console.setLevel(logging.INFO)
    console.setFormatter(formatter)

    # 文件 handler（保留 10 个备份，每个 10MB）
    file_handler = RotatingFileHandler(
        "logs/app.log",
        maxBytes=10 * 1024 * 1024,
        backupCount=10,
        encoding='utf-8'
    )
    file_handler.setLevel(logging.DEBUG)
    file_handler.setFormatter(formatter)

    # 配置根 logger
    root = logging.getLogger()
    root.setLevel(logging.DEBUG)
    root.addHandler(console)
    root.addHandler(file_handler)

# 调用设置（建议在应用启动时执行一次）
setup_logging()
```

#### 在爬虫模块中，直接使用 `logger = logging.getLogger(__name__)`，无需额外配置。

### 四、验证与排查

1. **本地验证**：执行爬虫任务，观察控制台是否正常输出带 `✓` 的日志，不报编码错误。
2. **日志文件**：检查 `logs/app.log` 是否正常写入，文件编码应为 UTF-8（可用 Notepad++ 查看编码）。
3. **Windows 特殊场景**：某些终端（如 PowerShell 或 CMD）可能仍不支持显示 UTF-8，但日志写入已成功；若控制台显示乱码，可设置终端字体为支持 Unicode 的字体（如 Consolas、Microsoft YaHei）。

### 五、长期建议

- **生产环境部署 Linux**：Linux 下默认编码为 UTF-8，无此问题。
- **使用日志聚合系统**：将日志统一收集到 Elasticsearch，前端可视化展示，避免依赖控制台。
- **定期清理日志**：配置 RotatingFileHandler 或使用 logrotate 工具，防止日志文件过大。

### 六、方案总结

| 问题点 | 解决方案 | 优点 |
|--------|----------|------|
| 编码错误 | 强制标准流 UTF-8 + 日志 Handler 指定编码 | 根治，无需修改日志内容 |
| 日志美观度 | 统一格式（时间+级别+模块+消息） | 可读性强，易于监控 |
| 日志持久化 | 使用 RotatingFileHandler 写入 UTF-8 文件 | 持久、自动轮转、不丢失 |

采用以上方案后，后端爬虫日志将稳定输出，不再出现编码异常，且日志格式整齐清晰，方便运维和问题追踪。

    format="%(asctime)s - %(name)s - %(levelname)s - %(message)s",

)
