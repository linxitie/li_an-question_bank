### 1.5 每日新闻

#### (a) 划线/笔记接入（断链修复）

**后端已完备，无需改动**：

| 能力 | 端点 |
|---|---|
| 获取笔记 | `GET /api/news/{news_id}/notes` |
| 保存笔记 | `POST /api/notes` |
| 更新笔记 | `PUT /api/notes/{note_id}` |
| 删除笔记 | `DELETE /api/notes/{note_id}` |

`news_note` 表已含 `quote_text` / `quote_position` / `color` / `line_style`。

**根因**：`mobile_news.vue:21` 用 `@touchend="handleTextSelection"`，而该函数依赖 `window.getSelection()`。**触屏上 `touchend` 时刻选区通常尚未提交，`getSelection()` 返回空**，划线永不触发。

**修复**：改用 `selectionchange` 文档级监听（触屏/鼠标统一）：

```js
const handleSelectionChange = () => {
  const sel = window.getSelection();
  const text = (sel?.toString() || '').trim();
  if (!text || text.length < 2) return;
  if (!contentEl.value?.contains(sel.anchorNode)) return;  // 仅正文内选区
  selectedText.value = text;
  quotePosition.value = computeOffset(contentEl.value, sel);
  setTimeout(() => { const r = sel.getRangeAt(0).getBoundingClientRect();
                     menuPos.value = { x: r.left, y: r.top }; }, 0);
  selectionMenuVisible.value = true;
};
onMounted(() => document.addEventListener('selectionchange', handleSelectionChange));
onBeforeUnmount(() => document.removeEventListener('selectionchange', handleSelectionChange));
```

**高亮回显**：加载时按 `quote_text` + `color` + `line_style` 在正文内包裹 `<mark>`。**必须**经 `sanitizeHtml`（`src/utils/questionRender.js` 单一真源）后再插入，**禁止**自行拼字符串（防 XSS）。

#### (b) 图片重复显示 —— **根因已锁定（数据层，非渲染 bug）**

> **重要修正**：初版方案判定"数据层无重复"是**错误**的。因当时用 `image_path` 字符串比对，
> 而重复图片的**路径不同**（`img_0.jpg` / `img_1.jpg` / `img_2.jpg`）但**内容完全相同**，
> 字符串比对无法发现。改用 MD5 内容哈希后立即定位。

**实测证据**（`news_id=1193`，用户提供截图对应文章）：

```
img_0.jpg  938781B  MD5=8736baef56192c1d1589
img_1.jpg  938781B  MD5=8736baef56192c1d1589   ← 内容相同
img_2.jpg  938781B  MD5=8736baef56192c1d1589   ← 内容相同
```

content 段落序列（同一段落重复 3 次，被 3 个标记分隔）：

```
3: [[IMG:0]]
4: 近日，内蒙古自治区包头市公安局民警走进公园、广场等人群聚集地…   ← 重复
5: [[IMG:1]]
6: 近日，内蒙古自治区包头市公安局民警走进公园、广场等人群聚集地…   ← 重复
7: [[IMG:2]]
8: 近日，内蒙古自治区包头市公安局民警走进公园、广场等人群聚集地…   ← 重复
```

**全局规模**：

| 指标 | 数值 |
|---|---|
| 受影响文章 | **546 / 2125**（25.7%） |
| 可删除冗余图片文件 | **1212** 个 |
| 含重复段落的文章 | **218** 篇 |

**爬虫根因**：`news_scraper.py` 有三条图片下载路径，**均无内容去重**：

| 函数 | 行 | 说明 |
|---|---|---|
| `_download_inline_images` | L221 | 主路径，按 `[[IMG:n]]` 顺序下载 |
| `_download_images` | L278 | 回退路径 |
| `_download_news_images` | L466 | people 源路径 |

`_should_skip_image`（L133）仅按**尺寸**与 **alt/title 关键词**过滤，无内容哈希判重。

**修复方案（三层，缺一不可）**：

**① 爬虫源头修复**（遵循"改进既有机制而非新建"）

在 `_download_inline_images` 内增内容哈希判重，**复用现有 `ordered_images` 循环结构**：

```python
def _download_inline_images(news_id, ordered_images, page_url, db, label="") -> tuple[int, set]:
    """... 返回 (saved, dropped_orders)；dropped_orders 为内容重复而被跳过的标记序号"""
    saved = 0
    seen_hash: set[str] = set()      # 本篇已保存图片的内容哈希
    dropped: set[int] = set()         # 被判重跳过的 order，供调用方清理 content 标记
    for order, src in ordered_images:
        ...
        content_hash = hashlib.md5(r.content).hexdigest()
        if content_hash in seen_hash:
            logger.info(f"[{label}] 图片内容重复，跳过: {src} (order={order})")
            dropped.add(order)       # 不落库、不写文件，由调用方移除 [[IMG:order]]
            continue
        seen_hash.add(content_hash)
        ...原落库逻辑不变...
```

**关键**：仅跳过落库会导致 `[[IMG:1]]` 解析不到图片而显示破图，
故必须把 `dropped` 回传，由调用方在 content 中一并移除对应标记与重复段落。

**② 历史数据清洗脚本**（幂等，`--dry-run`/`--apply`）

`backend/scripts/repair_news_duplicates.py`：

1. 按 MD5 分组同一新闻内图片，保留 `image_order` 最小的一张
2. 删除其余 `NewsImage` 行**及其物理文件**
3. 将被删图片对应的 `[[IMG:N]]` 标记，从 content 中移除
4. 清理 content 中重复的非空段落（保留首次出现）
5. 全程事务 + 幂等，可重复执行

**③ 前端防御性去重**（三端收敛为单一工具）

新建 `src/utils/newsRender.js`，导出 `renderNewsContent(content, images)`：

- 标记转换 + **相邻重复段落合并**
- `sanitizeHtml` 清洗（复用 `questionRender.js` 单一真源，禁止自写清洗）
- 缺失图占位兜底

> **说明**：因重复图片 URL 不同，**前端无法按 URL 去重**（`displayImages` 的 URL 去重对
> 此场景无效，这也是初版误判的原因之一）。前端去重仅能消除重复段落；
> 图片重复必须依赖 ①② 从数据与源头解决。

**文件**：`.vtj/vue/mobile_gold_purchase.vue`

#### (b) 目标完成追踪（核心缺陷）

**根因**：`StudyGoal.current_count` **无任何自动递增机制**，`goals.py` 仅提供手动 `POST /{goal_id}/progress`，故列表只能显示"完成"。

**方案**：新增服务函数

```python
# backend/app/services/goal_progress.py（新建）
def sync_goal_progress(user_id: int, db: Session) -> list[int]:
    """按当日/本周真实刷题量重算未完成目标的 current_count。"""
```

**设计决策依据**：

| 决策 | 理由 |
|---|---|
| **幂等重算而非增量累加** | 增量在并发/重试下必然漂移；重算天然可重复执行，便于运维重跑 |
| 按 `practice_date` 聚合而非 `practice_time` | 避免跨时区/跨天边界误差（历史已踩过 UTC 与本地时区混用） |
| 只更新 `is_completed == 0` 的目标 | 已完成目标不回退，保留发奖依据 |
| 触发点放在 `POST /api/practice/record` 成功后 | 与真实做题行为强绑定，不依赖客户端上报 |

**奖励科学性**：`StudyGoal` 已有 `base_reward`/`difficulty_factor`/`quality_score`/`persistence_score`/`improvement_score` 五维字段与 `reward_coins`，完成时按实际达成率计算而非固定值。

### 8.2 计划字面写法会失效的一处（§1.5(b) ③）

计划写「**相邻**重复段落合并」。但实测缺陷数据为：

```
[[IMG:0]] P [[IMG:1]] P [[IMG:2]] P
```

重复段落之间被图片标记隔开，**并不相邻**。只做相邻合并则「三张一样图片」问题**完全不会消失**。
故实现放宽为：与「上一个已输出文本段」相同即判重，并连带丢弃本轮累积的图片标记。
前端 `newsRender.js`、后端 `news_scraper.py`、清洗脚本 `repair_news_duplicates.py` **三处共用同一口径**（清洗脚本直接复用爬虫函数，不另写第三份实现）。

### 8.3 实施中发现并修复的既有 bug：FastAPI 路由遮蔽

**现象**：`GET /api/papers/list` 返回 **422**，题库页与 `/mobile/student-papers` 均显示无数据，
但 `exam_paper` 表实际有 **29 份试卷**。

**根因**：`paper_generation.py` 中路由按声明顺序匹配，参数化路径声明在字面量路径之前：

```
L500  GET /{paper_id}   <- 先声明，抢先匹配
L610  GET /list          <- 被遮蔽
```

`/api/papers/list` 先命中 `/{paper_id}`，`paper_id="list"` 无法解析为 int → 422。
（`papers.py` 的 `GET /stats` 被同文件 `L49 /{paper_id}` 同样遮蔽，属同类问题。）

**修复**：仅调整声明顺序，把字面量路径提到参数化路径之前，**不改动任何处理逻辑**。
修复后实测 `GET /api/papers/list` → **HTTP 200**。

> **为什么必须修**：`§2.1` 的 W3-a 改动以「首屏直出历年试卷列表」为前提删除顶部「历年试卷」按钮。
> 若列表接口是坏的，该改动会把原本可点击的入口换成首屏空列表，反而更糟。

### 8.4 随之修正的前端空态文案

原空态为「没有找到相关题目」。但该列表对普通用户只返回**已发布**试卷，
空列表的真实原因是「还没有已发布的试卷」，两者语义矛盾，易让用户误以为整个题库为空。
