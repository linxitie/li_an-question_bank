## 3. 设计目标与非目标

### 3.1 目标

1. 删除有入口、有二次确认、有回收站、可恢复、可彻底删除；已发布不可删。
2. 所有主按钮在任意页面状态下都可见、可读、可聚焦。
3. 右栏可拖动排序；拖完序号 1..N 连续且刷新后保持；左栏可拖到右栏指定插入位置。
4. 左栏题目可预览题干、选项、答案、解析、图片；题组题同时预览组材料。
5. 状态、科目用语义徽章区分，同时保留文字，不依赖颜色单独传达信息。
6. 保持现有 1:1 双栏、现有 API 契约、现有 DRAFT 编辑流不变。

### 3.2 非目标

- 不新增/修改后端 API、数据库表、迁移。
- 不改 `.vtj/vue/teacher_papers.vue` 或其他 raw 页 `<template>`。
- 不做批量删除、跨试卷拖动、发布/审批流改造。
- 不引入 `vuedraggable`、`SortableJS` 等第三方拖拽库。
- 不改变左侧题库列表接口的 payload（避免列表从 14.2KB 回到数百 KB）。

## 4. 方案

### D1 删除闭环（软删除 + 回收站）

**入口**

- 列表操作列：
  - `DRAFT/PENDING/APPROVED` 且 `isOwner`：显示“删除”。
  - `PUBLISHED`：显示禁用态“删除”，`title="已发布试卷不可删除，请先下架或走审批流"`。
  - `ENDED`：显示“恢复”“彻底删除”。
  - 非本人：只读，不显示删除/恢复。
- 列表状态筛选新增 `ENDED` 选项，文案“回收站”。

**交互**

1. 点击“删除” → `ElMessageBox.confirm`：
   - 标题“移入回收站？”
   - 内容“《试卷名》将从列表移入回收站，可恢复。”
   - 确认按钮“移入回收站”，取消“取消”。
2. 确认 → `DELETE /api/teacher/papers/{id}`。
3. 成功 → `ElMessage.success('已移入回收站')`；`loadPapers()`；若当前页删空且页码 > 1，页码减 1 再加载。
4. 回收站行“恢复” → `POST /api/teacher/papers/{id}/restore` → 提示“已恢复为草稿” → 刷新。
5. “彻底删除” → 二次确认，文案明确“不可恢复，关联题目关系/审批记录将一并删除” → `DELETE /api/teacher/papers/{id}/permanent` → 刷新。
6. 失败：`ElMessage.error(后端 detail 或 '操作失败，请重试')`，不改变本地列表。

**边界**

- 删除请求进行中禁用该行按钮，防重复提交。
- 当前编辑器打开的试卷被删除时，返回列表并清空编辑器状态。
- 已发布试卷即使后端拒绝，前端也不展示可点击删除，避免“点了才报错”。

### D2 空白按钮修复（CSS 级联）

**根因**

`.pw-primary` 是单类选择器；后置的 `.pw-editor-actions button`、`.pw-filters button`、`.pw-modal footer button` 是“类 + 元素”选择器，特异性更高，把 `background` 覆盖为白色，但未覆盖 `color:#fff`，形成白底白字。

**修复**

在 `<style scoped>` 末尾增加低歧义、可复用的主按钮规则：

```css
button.pw-primary {
  background: #1a3c6d;
  border-color: #1a3c6d;
  color: #fff;
}
button.pw-primary:hover:not(:disabled) {
  background: #244d86;
  border-color: #244d86;
}
button.pw-primary:focus-visible {
  outline: 2px solid #1a3c6d;
  outline-offset: 2px;
}
button.pw-primary:disabled {
  background: #9aa8bd;
  border-color: #9aa8bd;
  color: #fff;
  cursor: not-allowed;
}
```

覆盖范围：发布、筛选、创建并编辑、加入本卷等所有 `pw-primary`。不使用 `!important`。

**验收**：在列表页、编辑器、创建弹窗、删除确认弹窗逐屏检查，不存在白底白字或空矩形按钮。

### D3 拖动排序 + 左栏拖入指定位置

**启用条件**

- 试卷状态必须是 `DRAFT`。
- 右栏卷内搜索关键字为空。
- 否则拖拽手柄禁用，并在右栏顶部显示提示：“清空卷内搜索后可拖动排序”。

**数据模型**

- 右栏渲染继续用 `filteredPaperQuestions`，但序号统一由全量数组计算：
  `displayOrder(q) = paperQuestions.findIndex(item => item.question_id === q.question_id) + 1`。
- 这样搜索过滤后显示的序号仍是真实卷内序号，不会出现“搜索后从 1 开始”的错位。

**右栏内拖动**

1. 每题卡左侧增加拖拽手柄 `⠿`（`aria-label="拖动排序"`）。
2. `dragstart` 写入 `dataTransfer`：`{source:'paper', questionId}`。
3. `dragover` 阻止默认行为；根据指针在目标卡片上半区/下半区，显示上/下插入线。
4. `drop`：
   - 从 `paperQuestions` 快照开始，移除被拖题，插入到目标位置。
   - 立即乐观更新 UI，序号实时重排。
   - 调 `PUT /api/teacher/papers/{id}/questions/order`，body `{question_ids: paperQuestions.map(q => q.question_id)}`。
   - 成功：静默；失败：恢复快照、`ElMessage.error`、重新拉取详情。
5. 拖到列表末尾时允许插入到最后一项之后。

**左栏拖到右栏**

1. 左栏题目卡增加拖拽手柄；`dragstart` 写入 `{source:'bank', questionId}`。
2. 拖到右栏任意卡片上/下半区，显示插入线。
3. `drop`：
   - 先 `POST /api/teacher/papers/{id}/questions`，body `{question_ids:[questionId]}`。
   - 成功后重新拉取试卷详情（拿到新题的真实 question_id/顺序）。
   - 再 `PUT /questions/order` 把新题移动到目标位置。
   - 失败：提示并刷新，保证 UI 与后端一致。
4. 若题目已在卷内：不重复添加，提示“该题已在卷内”，并滚动到已有题目。

**题组题**

- 左侧卡片已有“题组 N”标识时，拖入单题后提示：“该题属于题组 N，建议整组加入以免材料缺失。”
- 默认只提示，不自动扩组；是否整组加入由教师决定（避免一次拖拽悄悄改变题量）。

**降级**

- 保留上移/下移按钮，作为键盘、触屏和拖拽失败时的降级路径。
- 拖拽只使用原生 HTML5 DnD，不引入依赖；触屏浏览器不支持时仍可用上移/下移。

**边缘自动滚动**

- 拖拽到右栏容器上下边缘 48px 内时，以 `requestAnimationFrame` 小步滚动，避免长试卷无法拖到视口外。

### D4 左侧题库预览

**入口**

- 左栏题目卡增加“预览”按钮，`@click.stop`，不触发整卡勾选。
- 保留整卡点击勾选行为，避免改变现有批量选择习惯。

**数据加载**

- 点击预览才请求，不改变列表接口：
  1. `GET /api/questions/{question_id}` 取完整题干/选项/答案/解析。
  2. 若 `group_id > 0`，再 `GET /api/questions/group/{group_id}` 取共享材料。
- 加载中显示骨架/“加载中…”；失败显示“加载失败，重试”按钮。

**弹窗内容**

1. 头部：题型、科目、难度、题组标识（如有）。
2. 题组材料：`shared_content` + `shared_content_images`，复用 `renderQuestionContent` 统一图片渲染。
3. 题干、选项（A/B/C/D）、正确答案、答案解析。
4. 底部“关闭”；不提供编辑，避免误改。

**交互与无障碍**

- 遮罩点击关闭、Esc 关闭、右上角关闭按钮。
- `role="dialog"`、`aria-modal="true"`、`aria-label="题目预览"`；打开时焦点移到关闭按钮。
- 弹窗打开时锁定背景滚动，关闭后恢复。
- 已知副作用：单题详情接口会 `exam_frequency += 1`，预览与点击编辑一致；本次不新增后端只读参数，若后续需要“预览不计数”再单独立项。

### D5 状态/科目语义徽章

**状态**

| 状态 | 文案 | 颜色 | 用途 |
|---|---|---|---|
| DRAFT | 草稿 | 灰 | 未提交 |
| PENDING | 待审批 | 琥珀 | 审批中 |
| APPROVED | 已通过 | 蓝 | 可发布 |
| PUBLISHED | 已发布 | 绿 | 学生可见 |
| ENDED | 回收站 | 深灰/删除线感 | 软删除 |

**科目**

| 科目 | 颜色 |
|---|---|
| 行测 | 蓝 |
| 申论 | 橙 |
| 公专 | 青 |

**规则**

- 徽章 = 浅色背景 + 深色文字 + 细边框；不使用大面积高饱和色。
- 文字必须保留，颜色只做辅助，满足色觉障碍可用性。
- 表格、编辑器头部、左栏卡片、右栏卡片使用同一套 class，不各写一套颜色。

## 5. 替代方案与取舍

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 引入 vuedraggable/SortableJS | 开箱即用、动画好 | 新依赖、包体增大、与现有原生卡片事件耦合 | 不采用 |
| 只保留上移/下移 | 零风险 | 不满足“拖动排序”要求 | 不满足 |
| 删除改为物理删除 | 简单 | 误删不可恢复，违反可逆性 | 不采用 |
| 左侧列表接口直接返回详情 | 预览无需二次请求 | 列表 payload 从 14.2KB 涨到数百 KB，重演性能问题 | 不采用 |
| 预览不计数（改后端） | 统计更准 | 超范围、需改 API | 本次不做，登记风险 |

## 6. 风险与回滚

| 风险 | 影响 | 缓解 |
|---|---|---|
| HTML5 DnD 在触屏/部分浏览器不生效 | 无法拖动 | 保留上移/下移；显示“当前浏览器不支持拖动”提示 |
| 拖拽过程中网络失败 | UI 与后端顺序不一致 | 乐观更新前快照；失败回滚 + 重新拉详情 |
| 左栏拖入后二次 PUT 失败 | 新题已在卷内但位置不对 | 失败提示 + 重新拉详情；不静默 |
| 彻底删除误操作 | 数据不可恢复 | 二次确认 + 文案明确 + 仅 ENDED 可用 |
| 预览触发 exam_frequency 自增 | 统计口径轻微偏移 | 已知并记录；后续可加只读参数 |
| 无关暂存文件被误提交 | 污染提交 | 提交前只 add 本任务文件；不碰 student_papers.vue 与 group 59 图片 |

回滚：所有改动集中在 `TeacherPaperEditor.vue` 与新增 `src/utils/paperOrder.ts`（纯函数）；回滚即还原这两个文件，不涉及数据库迁移。
