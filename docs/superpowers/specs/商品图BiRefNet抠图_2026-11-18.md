# 商品图抠像升级：接入 BiRefNet（2026-11-18）

> 需求：现有抠图（图一）保留了背景电路板、裁切错位；要求接入 BiRefNet（birefnet-matting / birefnet-general）。

## 1. 现状与问题

原实现 `backend/app/services/product_image.py` 用 **GrabCut + 洪泛** 本地算法（无模型权重也可用）。
对这本带图案背景的书，GrabCut 把背景电路板当作主体的一部分、把封面当主体裁切 → 图一的效果。

## 2. 接入方案

```text
上传接口（admin_shop.admin_upload_product_image）
  → product_image.process_product_image(raw)
      → _remove_background()
          ├─ 引擎 birefnet（rembg + onnxruntime，默认 birefnet-general）
          ├─ 兜底 grabcut（OpenCV，现有实现）
          └─ 兜底 flood（纯色背景洪泛）
      → _suppress_gray_shadow（仅经典引擎需要，BiRefNet 跳过）
      → _compose_white（600×600 白底居中）
```

### 2.1 rembg 的可用变体（实测 2.0.87）

```text
birefnet-general / birefnet-general-lite / birefnet-general-fp16
birefnet-portrait / birefnet-dis / birefnet-hrsod / birefnet-cod / birefnet-massive
```

**没有 birefnet-matting**：rembg 2.0.87 未提供该会话。实测 birefnet-general-lite
（224MB）在这张书上出现主体错位/背景粘连；birefnet-general（973MB）边缘干净、整本书完整保留，
因此默认用 general。若以后确实需要 matting（透明材质），路线是 HuggingFace 的
`ZhengPeng7/BiRefNet` + transformers 加载 matting 权重（需要另装 transformers，未做）。

### 2.2 依赖与权重

```text
pip:  rembg==2.0.87 / onnxruntime>=1.23.2,<2.0 / Pillow>=12.3.0,<13.0.0（写进 backend/requirements.txt）
权重: %USERPROFILE%\.rembg\models\birefnet-general\BiRefNet-general-epoch_244.onnx（973MB）
      md5 7a35a0141cbbc80de11d9c9a28f52697（脚本校验）
获取: powershell -ExecutionPolicy Bypass -File scripts/shop/fetch_cutout_model.ps1
      （-Variant lite 可下 224MB 版本；离线机器可直接拷贝 .rembg/models 目录）
```

模型不自动随 pip 下载：`auto` 模式下若本机没有权重，直接走 GrabCut，避免管理员上传请求里
卡一个 973MB 下载（只有设置 `SHOP_CUTOUT_ALLOW_DOWNLOAD=1` 才允许在线下载）。

### 2.3 环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `SHOP_CUTOUT_ENGINE` | `auto` | auto=有模型就用 BiRefNet；birefnet=强制（失败报错）；classic=只用本地算法 |
| `SHOP_CUTOUT_MODEL` | `birefnet-general` | 可换 `birefnet-general-lite`（快，但本书实测质量差） |
| `SHOP_CUTOUT_MAX_INPUT` | `1024` | 推理前最长边，BiRefNet 内部固定 1024 |
| `SHOP_CUTOUT_THREADS` | `min(16, CPU)` | onnxruntime intra-op 线程数 |
| `SHOP_CUTOUT_ALLOW_DOWNLOAD` | 未设置 | `1` 时允许首次调用在线下载权重 |

### 2.4 启动预热

后端 lifespan 里调用 `product_image.warmup_background()`：后台线程加载 ONNX 会话
（实测 4.8~5.3s，冷启动首次 54s），首个上传不必等模型初始化；pytest 下跳过。

## 5. 风险与后续

- 单张 12s：管理员上传商品图需等待；后续可改异步队列（上传即返回占位图，后台处理完回填）。
- 973MB 权重的机器内存占用：onnxruntime 会话常驻约 1GB 级；低配机器可设 `SHOP_CUTOUT_ENGINE=classic`
  或换 lite（质量受限）。
- 原图自带水印（“慧龙图书专营店”）会被保留，这是图像内容而非抠图错误；如需去水印另做。
- 未做 matting 变体（rembg 无此会话）；透明包装/玻璃商品目前用 general。
- 需重启后端一次生效（当前 8000 进程是 13:55 启动的旧代码）。

## 6. 追加（2026-11-18 晚）：异步队列 + 耳机盒案例复盘

### 6.1 异步队列（上传先返占位图，后台回填）

流程：

```text
POST /api/admin/shop/upload-image
  → 校验图片/清晰度（同步，不合格立即 400）
  → 写占位图到 <hash>.png，任务入队（ThreadPoolExecutor max_workers=1）
  → 立即返回 {url, engine:'queued', async:true, status_url}
  → 前端每 2s 轮询 status_url：queued → running → done / failed
  → done 后同一 URL 已是成品（后台 os.replace 原子覆盖），预览加 ?v= 时间戳刷新
```

- 状态接口：`GET /api/admin/shop/upload-image/{name}/status`（管理员；服务重启后 404）；
- 关闭异步：`SHOP_CUTOUT_ASYNC=0`（回到同步，测试默认同步）；
- 前端（`.vtj/vue/admin_shop.vue` 的 script）：上传后轮询、完成刷新预览、失败提示；保存商品时剥离 `?v=` 时间戳；
- 占位图是白底灰框 + “AI processing...”，后台失败会改成 “AI failed. Try again.”，不会一直转圈。

实测（真实模型，耳机盒图）：

```text
上传返回耗时：0.081s（engine=queued）
后台完成耗时：19.1s（冷启动，含模型加载）；status: done / engine=birefnet
```

## 7. 提交与多设备部署（2026-11-18）

### 7.1 模型不会进 Git

- 权重实际位置：%USERPROFILE%\.rembg\models\birefnet-general\birefnet-general.onnx（973MB），在仓库之外；
- 仓库内没有任何 *.onnx（实测 git ls-files 为空）；
- 已在 .gitignore 增加 *.onnx / **/.rembg/ / backend/data/models/，即使有人把权重拷进仓库也不会被提交；
- 即使强行加，GitHub 单文件上限 100MB 也会直接拒绝（973MB 需 LFS，不建议：每台机器 clone 多 1GB）。

### 7.2 其他设备怎么正常用

```powershell
# 1) Python 3.11+（rembg 2.0.87 要求 >=3.11,<4）
python -V

# 2) 依赖（含 rembg / onnxruntime / pillow）

# 3) 下载模型（973MB，校验 MD5；Windows 也可用 ps1 脚本）
```

### 7.5 部署时下载：已支持续传/校验（实测）

脚本：`scripts/shop/fetch_cutout_model.py`（跨平台）

```powershell
python scripts/shop/fetch_cutout_model.py                 # general 973MB（推荐）
python scripts/shop/fetch_cutout_model.py --check         # 只校验是否就绪（exit 0/2）
python scripts/shop/fetch_cutout_model.py --out /models   # 指定目录（容器挂载卷）
python scripts/shop/fetch_cutout_model.py --url <镜像>     # 内网镜像/加速源
python scripts/shop/fetch_cutout_model.py --force         # 强制重下
```

- **断点续传**：写 `<file>.onnx.part`，中断后重跑带 `Range` 继续；服务器忽略 Range（200）或 416 时自动从头下；
- **校验**：完成后核对大小 + MD5，不符自动删除重下；
- **网络兜底**：urllib 超时/被墙时自动改用系统 `curl -C -` 续传；也支持 `HTTPS_PROXY`；
- 实测（本地 206 服务器，5MB 文件预置 2MB）：请求头 `Range: bytes=2097152-`，仅传 3,145,728 字节，最终 MD5 一致；
- 本机 `--check` 输出 `OK .../birefnet-general.onnx`。

部署示例（Docker）：

```dockerfile
ENV REMBG_HOME=/models
RUN python scripts/shop/fetch_cutout_model.py
VOLUME ["/models"]          # 重建容器不重复下载
```

无外网构建：把 `.rembg/models` 拷进镜像/挂载卷，或 `--url` 指向内网镜像；
CI 可缓存 `/models` 目录，后续构建直接 `--check`。
