# 联考小智「功能开发中」与前后端版本一致性 排查报告

- 日期：2026-11-02
- 涉及：前端构建版本自检、`/health` 版本字段、Git 推送链路（SSH / deploy key）
- 结论：**代码本身没有「联考小智功能开发中」这条路径，你看到的是旧标签页里的旧 bundle；同伴的「请求参数验证失败」是其后端进程比前端旧。** 已加入版本自检，使「旧产物 / 旧进程」在页面上直接可见，不再靠猜。

---

## 1. 现象

| 侧 | 现象 |
|---|---|
| 本机（用户） | `localhost:9527/#/page/question_bank` 点击顶部「联考小智」后，出现 Element Plus toast「联考小智功能开发中」 |
| 同伴 | 可打开联考小智对话页（对话/工作台、心理疏导/答疑解惑/提升建议、记忆/知识库），但助手气泡返回「请求参数验证失败」 |

用户诉求：①把改动推送合并到 main；②彻底解决「我这边显示功能开发中、同伴能打开」的版本不一致。

## 2. 证据链

### 2.1 现版本没有任何代码路径会弹出该 toast

| 检查项 | 实测结果 |
|---|---|
| `.vtj/vue/navbar.vue` 的 `menuItems` | 仅 首页 / 题库 / 关于砺安题库 / 论坛，无「联考小智」 |
| `git log -S"联考小智" -- .vtj/vue/navbar.vue .vtj/vue/app_navigation.vue` | **零提交**（该菜单项从未进入仓库历史） |
| 「功能开发中」来源 | `.vtj/vue/app_navigation.vue:85` 的 `` `${item.title}功能开发中` `` |
| 题库页「联考小智」按钮 | `question_bank.vue` `handleTopAction('ai')` → `this.$router.push('/ai-assistant')`，不是 toast |
| 路由 | `src/router/index.ts:82` `path: '/ai-assistant'` → `import('$vtj/vue/ai_chat.vue')`；`origin/main` 同 |
| `ai_chat.vue` 来源 | `984a01a`（origin/feature/ai-assistant，2026-10-28） |

即：`功能开发中` 只可能由 **旧版 `app_navigation.vue`** 渲染，而旧版只存在于浏览器已加载的旧 JS chunk 中。

### 2.2 开发服务器实际下发的是新代码

| 请求 | 结果 |
|---|---|
| `GET /.vtj/vue/navbar.vue` | 「联考小智」出现 **0** 次 |
| `GET /src/router/index.ts` | 含 `/ai-assistant` |
| `GET /.vtj/vue/ai_chat.vue` | 200 |
| `dist/assets/ai_chat-*.js` | 存在（dist 构建于 11-01 11:33） |

→ 服务器、构建产物都正常，唯一解释是**用户浏览器标签页长期未整页刷新**，HMR 断连后仍跑旧 bundle。

### 2.3 同伴的「请求参数验证失败」= 后端旧进程

- `ChatRequest`（`backend/app/api/v1/platform/llm.py:37-40`）与前端 `sceneOptions` 三值一致（`psychological` / `qa` / `advice`）。
- 本机实测 `POST /api/llm/chat`：`scene=qa`、`session_id` 省略、`session_id:"1"` 三种均 **200**。
- 同伴截图里是 422，只能是其 **uvicorn 进程启动早于该后端代码**（与本次本机 404 事故同源：无 `--reload` 的旧进程）。
- 本机旧进程证据：pid 27540 启动 10:05:52，命令行无 `--reload`；而路由文件 mtime 10:06+。

## 3. 修复：让「版本不一致」自己暴露

### 3.1 前端构建戳（`vite.config.ts`）

- `resolveBuildSha()`：`git rev-parse --short HEAD`（失败回退 `unknown`）。
- `buildStamp()` 插件：`enforce: 'pre'` 的 `transform` 里把 `__BUILD_SHA__` / `__BUILD_TIME__` 替换成字面量。
- **踩坑**：先用 `config.define` 方式，dev 下不生效——`node_modules/@vtj/cli/dist/index.mjs` 的 `createViteConfig` 先构造 config 再调用 `opts.defineConfig(config)` 并直接返回，dev 服务下发的 `src/main.ts` 仍保留未替换的标识符。改为 transform 插件后 dev 下发变为 `const frontendSha = true ? "<sha>" : "dev"`。

### 3.2 后端版本（`backend/app/main.py`）

- `_resolve_app_revision()`：`git rev-parse --short HEAD`（3s 超时，异常返回 `unknown`）。
- `/health` 新增 `revision` 与 `started_at` 两字段。

### 3.3 前端比对（`src/main.ts`）

- `checkVersionConsistency()` 在 `app.mount()` 之后执行：`fetch('/health', {cache:'no-store'})` → 比对 `revision` 与 `__BUILD_SHA__`。
- 不一致时写 `window.__VERSION_MISMATCH__`、`console.warn`，并弹 `ElMessage.warning('检测到前后端版本不一致，请刷新页面（后端需重启到最新版本）')`。
- `typeof __BUILD_SHA__ === 'string'` 兜底，避免 dev 未注入时 `ReferenceError` 打断页面。
- `proxy.config.ts` 增加 `/health` 代理（否则开发态被 SPA 兜底成 index.html）。
- `src/env.d.ts` 补 `declare global` 类型声明。

## 4. 排障规约（本次踩过的坑）

1. **uvicorn `--reload` 的父子进程**：只 kill reloader 父进程时，multiprocessing 子进程仍占 `:8000`，新进程绑定失败但父进程存活 → 请求仍打到旧代码。必须 `taskkill /F /T /PID <父>` 或按命令行批量 kill。
2. **Vite 端口 9527 残留**：残留 node 进程会导致 `Port 9527 is already in use`；先确认端口无监听再启动，启动后首请求可能因 `Re-optimizing dependencies` 慢 6s。
3. **`.env` 改动不触发 `--reload`**，改完必须重启后端。
4. **浏览器**：遇到「功能开发中 / 404 / 参数验证失败」先按 `Ctrl+F5` 硬刷新；仍不一致看控制台 `[砺安题库] 前端构建 <sha>` 与 `/health` 的 `revision` 是否相同。
