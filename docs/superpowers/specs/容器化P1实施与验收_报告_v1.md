## 1. 结论

P1 的目标是“把部署态容器化的骨架落盘并验证可构建”，不是把学校生产环境切过去。

已完成：

- 新编排 `deploy/docker-compose.yml`：web + backend 为核心，parser 只在 `ocr` profile 启动；SQLite 不容器化，业务数据全部宿主 bind。
- 新前端镜像 `deploy/Dockerfile.web`：Node 22 构建 + `nginx-unprivileged` 运行，dist 进镜像，不再挂宿主机 `dist`。
- 新 `deploy/preflight.sh`：变量、密钥、数据目录、空题图、磁盘、端口、compose config、构建上下文密钥排除。
- 根 `.dockerignore`：排除题库、后端数据、上传、构建产物、`.env` 等。
- parser 镜像改非 root（uid/gid 10001），模型缓存改到 `/home/parser/.cache`。
- 根 `docker-compose.yml` 改为兼容入口，通过 Compose `include` 指向新编排，避免旧 13 服务文件继续被误用。
- web 与 backend 镜像均构建通过；staging 双容器启动 healthy，登录、题目列表、题图、开考/交卷、重启持久化实测通过。
- 构建/启动过程中发现并修复 6 个会阻断上线的问题：apt/pip/Playwright 弱网源、pydantic-settings/email-validator 漏依赖、bcrypt 5 与 passlib 不兼容、`scripts` 未 COPY 导致种子导入失败、nginx 正则 location 抢走 `/static/`、nginx `$host` 丢端口导致 307 跳到 :80。

未完成（按方案进入 P2–P6）：

- 含 Chromium 的完整生产 backend 镜像：默认 `INSTALL_PLAYWRIGHT_BROWSERS=1`，本次 staging 用 0 跳过，弱网下 191 MB 浏览器层未完成全量下载；生产构建前需在稳定网络下补验。
- TLS、镜像扫描、备份/恢复脚本、CI、生产切换；
- parser 镜像构建与 OCR 烟测。

## 4. 验证记录

### 4.1 compose config

命令：

~~~bash
docker compose -f deploy/docker-compose.yml --env-file deploy/.env.example config --quiet
~~~

结果：EXIT 0。

首轮失败与修复：

~~~text
services.web: can't set distinct values on 'pids_limit' and 'deploy.resources.limits.pids': invalid compose project
~~~

原因：同一服务同时设置顶层 `pids_limit` 与 `deploy.resources.limits.pids`。
修复：删除顶层 `pids_limit`，统一放 `deploy.resources.limits.pids`（web 128 / backend 512 / parser 512）。

解析后的绑定路径（staging 变量）：

- `deploy/runtime/data` → `/app/data`
- `backend/app/static` → `/app/app/static`
- `deploy/runtime/uploads` → `/app/uploads`
- `deploy/runtime/logs/backend` → `/app/logs`

### 4.2 preflight

通过路径：

~~~bash
bash deploy/preflight.sh
~~~

结果：7 项全绿；磁盘余量 86 GB；HTTP_PORT 8080 可用；compose config 通过；未打印密钥。

失败路径（已验证会拦截）：

- 环境文件不存在：`环境文件不存在：.../deploy/.env.development`
- `JWT_SECRET_KEY` 仍是示例占位符：`JWT_SECRET_KEY 仍是示例占位符，请由用户本人生成并填写`

### 4.3 web 镜像

命令：

~~~bash
docker compose -f deploy/docker-compose.yml --env-file deploy/.env.example build web
~~~

结果：EXIT 0。

关键输出：

- `npm ci`：998 packages，约 169.5 s；
- `typecheck-baseline`：通过，零新增错误；
- `vite build`：48.92 s，产物写入 `dist/`；
- 镜像：`ghcr.io/linxitie/li_an-question_bank-web:dev`；
- 镜像 ID：`65685cb219b8`；大小约 105 MB；
- 运行阶段只保留 `dist` 与 `deploy/nginx.conf`，不带 Node、源码或密钥。

单独 `docker run` 烟测说明：

- 只读根 + `tmpfs /tmp` + `tmpfs /var/cache/nginx` 能启动到 nginx 阶段；
- 不在 Compose 网络内时，nginx 因无法解析 upstream `backend:8000` 退出（`host not found in upstream`）。这是预期耦合，不是镜像缺陷；Compose 内由 `depends_on: backend healthy` 保证 backend 先存在。
- 已知限制：nginx 在启动时解析一次 backend IP；backend 重建换 IP 后需重启 web（P4 用 resolver/变量 upstream 解决）。

### 4.4 backend 镜像

命令：

~~~bash
docker buildx build --load --resource memory=6g --resource cpu-quota=800000 --shm-size=1g --build-arg INSTALL_PLAYWRIGHT_BROWSERS=0 -t liankao-backend:staging backend
~~~

结果：EXIT 0；镜像 liankao-backend:staging，ID b420c0f20afb，约 1.8 GB（无 Chromium）。容器以 uid/gid 1000 运行，HEALTHCHECK 命中 /health。

首次构建暴露并修复的问题：

1. **apt 阶段 OOM / 超时**：BuildKit 在 apt-get install ffmpeg libgl1 ... 跑 1594 s 后报 ResourceExhausted: ... cannot allocate memory；旧 builder 又连不上 deb.debian.org。Dockerfile 增加 APT_MIRROR（默认清华）与 Acquire::Retries/Timeout/ForceIPv4。
2. **pip 解析为空**：Could not find a version that satisfies the requirement sqlalchemy>=2.0.0 (from versions: none)。Dockerfile 增加 PIP_INDEX_URL（默认清华），海外可用 build-arg 还原。
3. **Playwright 下载受 TLS MITM/弱网阻断**：UNABLE_TO_VERIFY_LEAF_SIGNATURE，npmmirror 实测 37–47 KB/s。浏览器层改为可选 ARG，默认生产装、staging 用 0 跳过；跳过时爬虫不可用已在注释标明。
4. **启动缺依赖**：No module named 'pydantic_settings' → 补 pydantic-settings>=2.0.0；email-validator is not installed → 补 email-validator>=2.0.0；passlib 1.7.4 在 bcrypt 5 上自检抛 password cannot be longer than 72 bytes，导致登录 500 → 钉 bcrypt>=4.0,<5。
5. **种子数据 import 失败**：No module named 'scripts'（main.py:580 from scripts.admin.seed import run_seed）→ Dockerfile 增加 COPY scripts ./scripts；非 DEBUG 只 import 不执行。

已知限制：含 Chromium 的完整生产镜像未在本次弱网下完成；P5/生产构建前需在稳定网络补验。

启动命令：


| 资源 | backend 2 CPU / 2 GiB / 512 pids；web 0.5 CPU / 128 MiB / 128 pids |

| 答题页 | /#/paper-answer?paper_id=51 → 100 个 .question-block，toolbar position=fixed |
| 题图 | /static/questions/251c9b25_42_0.png → 200 image/png 16397 B；/static/question-groups/31/img_0_3e105a63.jpg → 200 image/jpeg 39155 B |
| 图片懒加载 | 滚动到首图后 naturalWidth=686，13 张图中已加载 7 张 |

| 重启持久化 | docker compose restart backend 后重新登录，GET /api/exams/51/questions 仍 200 / 100 题 |

烟测中发现并修复的两个 nginx 问题：

1. 正则 location `~* \.(js|css|...|png|jpg)$` 优先于前缀 location `/static/`，题图请求去 dist 找而 404。修复：`/static/` 改为 `^~ /static/`。
2. upstream 用 `Host $host` 丢掉端口，FastAPI 尾斜杠 307 的 Location 变成 `http://127.0.0.1/api/...`（:80）。修复：改 `$http_host`，并补 X-Forwarded-Host/Port。

## 5. 安全与红线对照

| 约束 | P1 落地 |
|---|---|
| 安全左移 / 最小权限 | 三服务 `read_only`、`cap_drop: ALL`、`no-new-privileges`；parser 非 root；backend 以 `APP_UID:APP_GID` 运行 |
| 资源与生命周期 | web 0.5 CPU/128M/128 pids；backend 2 CPU/2G/512 pids；parser 2 CPU/4G/512 pids；日志 json-file 20m×5 |
| 数据与状态 | SQLite、static、uploads、logs、foundation 全宿主 bind；命名卷只保留 parser_cache；`down -v` 不碰业务数据 |
| 网络可控 | web 仅 edge；backend edge/app/egress；parser 仅 app（internal） |
| 不可变镜像 | dist 进 web 镜像；镜像按 `IMAGE_TAG` 标记；不挂宿主 dist |
| 可观测性 | 健康检查、日志轮转已落；Prometheus/告警留 P5 |
| 协作变更 | `.env` 不入库；`deploy/runtime/` 不入库；手册见 `docs/ops/GitHub协作与容器化交付手册_v1.md` |

## 6. 回滚

P1 只新增编排文件；回滚方式：

1. 停止 staging：`docker compose -f deploy/docker-compose.yml --env-file deploy/.env.development down`（**不要加 `-v`**）。
2. 恢复旧启动：旧 `docker-compose.yml` 可从 Git 历史取回；新文件不参与旧启动。
3. 删除 `deploy/runtime/` 可丢弃 staging 数据；生产数据不在其中。
