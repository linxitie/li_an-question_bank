## 0. 结论先行

- 需求分两条线：**A 注册人物画像（7 条）**、**B 联考小智（3 条）**，外加贯穿两线的**三端补齐**。

## 2. 需求逐条方案

### A 线：注册页人物画像

#### A1 询问页样式单调 → 动画过渡
- **现状**：`profile_quiz.vue`（`.vtj` 页面，R3 约束：`<template>` 只能由用户在设计器 `http://localhost:9527/__vtj__/` 拖拽，AI 只可改 `<script>`，且先 `dryRun:true`）。
- **方案**：
  1. 参照多邻国/百词斩/不背单词：步骤卡片**横向滑动 + 淡入上浮**、顶部进度条、卡片堆叠层级、完成态打勾动效。
  2. 动效分两层：**脚本层**（AI 可做）——步骤切换状态、当前步索引、过渡类名挂载；**模板层**（用户设计器做）——卡片布局与动画元素。
  3. 复用已有 transition 习惯，不引入重型动画库；候选：Vue `<TransitionGroup>` + CSS keyframes。
- **验收**：三步以上问卷切换无跳变；PC/手机布局不错位；L6 模块化约束通过。
- **边界**：不新建平板/手机重复副本（R12）；动效不遮挡选项可点区域。

#### A2 问题单一 + 自由文本自述
- **现状**：问卷模板为固定选项；前端已有 `suggestions.ts` 固定池轮换模式可复用；画像表无自述字段。
- **方案**：
  1. **动态问题**：按问卷步骤/水平自评从问题池轮换（复用 `nextSuggestions` 环形轮换 + 去重思路），不同用户/会话起点错开；选项题与开放题穿插。
  2. **自由自述**：`UserProfile` 增加 `self_intro` Text 列（用户自述学习情况）；`ProfileUpsertRequest` 与 `_to_dict` 同步加字段；问卷模板末步加一道 free-text 题（可选填，不阻断提交）。
  3. 自述文本只做入库与回显，**不直接进 LLM 推理上下文**（二期再接 PlanAgent）。
- **验收**：提交自述后 `GET /api/profile` 可读回；空值不报错；字段计入基线核对。
- **风险**：加列属表结构变更，需走迁移/对齐（§6）；343 端点基线不变，本次只动既有 `/api/profile/upsert` 契约加可选字段。

#### A3 备考方案首页 / 「我的」不可见（内容断层）
- **现状**：后端 `/api/profile`、`/api/plan/current`、`/api/plan/today` 已存在；前端「我的」与首页均未拉取。
- **方案**：
  1. **「我的」** `shared/profile.vue`：新增「备考画像」卡片（年级/目标分/水平/每日学时/强弱项/截止日，自述摘要）+「当前备考方案」卡片（今日任务数、完成度、方案日期，入口跳 `/study-plan`）；`profile_status=0` 时显示"去补全画像"引导跳 `/profile-quiz`。
  2. **首页**：PC `home_page.vue`、`mobile_home.vue` 增加方案摘要条（今日任务 / 已完成 / 可领金币），复用 `/api/plan/today`。
  3. 数据流：前端只读既有端点；卡片组件放模块 4 域内，跨域数据走事件或直接调本域 api 封装。
- **验收**：有方案用户在「我的」与首页可见摘要；无方案用户看到空态引导；刷新后状态一致。
- **边界**：不改账号资料 `/api/auth/profile` 既有展示。

#### A4 3D 学习日历并入「每日签到」
- **现状**：签到仅两端点；PC 首页已嵌 `exam_calendar_block.vue`；日历模块 `calendar/store.ts`。
- **方案**：
  1. 签到页内嵌入日历视图（连续打卡天数、当日标记、热力月历），数据源复用 `DailyCheckin`（models.py:936）。
  2. 优先前端聚合既有签到状态；若月历/连续天数需后端聚合，再评估新增**只读**端点并登记到 `api_surface.json` 基线（R11）。
  3. 「3D」表现优先用卡片层级/光影/翻页等轻量 CSS，不引 3D 引擎；如确需三维，单列技术预研。
- **边界**：签到属成长域，本方案只做展示接入；签到写入逻辑归原模块维护。实施前与该域负责人对齐。

#### A5 番茄钟专注学习（首页小弹窗）
- **现状**：无番茄钟模块/路由/页面。
- **方案**：
  1. 新建前端模块 `src/modules/pomodoro/`（store：计时状态 / 时长配置 / 本轮完成数；纯前端本地计时为主）。
  2. 首页挂浮动按钮 → 小弹窗（倒计时、开始/暂停/重置、本轮完成提示），不打断浏览。
  3. 持久化可选一期：只存本地；二期再评估是否落库（复用 goals/tasks 或新建专注记录表）。
- **验收**：弹窗三端可用；计时关闭页面后行为明确（一期不承诺后台计时）；不污染模块 4/7 既有 store。
- **边界**：新模块命名与目录遵循现有 `src/modules/<域>/` 结构。

#### A6 遗忘曲线复习提醒（错题集）
- **现状**：错题表有 mastery_level / review_count / last_review_time / error_count，无 SM-2 的 ease/interval/next_review_at；该模块由昕蕾管理。
- **方案（建议，待对齐后启动）**：
  1. **轻量先行**：基于 `last_review_time` + `review_count` + `mastery_level` + `error_count` 算"到期该复习"排序，不立刻加 SM-2 字段。
  2. 提醒通道：复用 `study_plan/notifies` 站内提醒或通知服务，按到期错题生成提醒条目。
  3. **字段升级（二期，需对齐）**：若要标准间隔重复，再补 `ease / interval / next_review_at` 三列，并与错题模块负责人确认迁移与斩题规则兼容。
- **边界**：不直接改错题模块表结构与错题页；只提接入建议，跨域改动由负责人实施或共同评审。

#### A7 手机端 / 平板端缺失
- **现状**：画像问卷、小智、计划为单页；三端入口与布局待逐端验收。
- **方案**：随各功能批次做三端适配；优先复用既有 mobile/tablet 组件与 device.ts 映射；确无对应组件时再补手写页（放 `src/views/student/<role>/<device>/`），不建平板-手机重复副本（R12）。

### B 线：联考小智

#### B1 Obsidian 自生长知识库（搭建 / 运营 / 维护 / 使用）
- **现状**：导出/同步管线骨架在（`obsidian_export.py`、`content_hub/export_obsidian.py` 等）；vault 目录当前不存在；用户将提供**基础款 vault（人物画像 + 联考小智一起）**。
- **方案**：
  1. **vault 结构规范**（基础款落地后对齐目录）：
     - `00-MOC/` 地图与索引；`10-画像/` 用户备考画像卡片；`20-小智对话/` 会话精华沉淀；`30-弱项错题/` 自动归集；`90-附件/`。
     - 每张 md 带 YAML frontmatter（topic / subject / source / update_time / status）；双向链接 `[[考点]]`；Dataview 查询聚合待复习与弱项。
  2. **投影导出**：复用 `export_obsidian.py` 管线，把画像字段、会话提炼要点、错题弱项按结构写成 md；vault 为本地投影，不入库（`content_hub_vault/` 已 gitignore）。
  3. **自生长规则**：会话结束后由用户/确认动作提炼成卡片；弱项与错题自动建条目并回链；定期同步与冲突处理沿用 `obsidian_sync.py`。
  4. **运营维护**：MOC 定期归集、失效条目标记、附件清理规则；使用说明写入域卡文档。
- **前置**：等用户提供基础款 vault 路径与既有模板，再定目录映射与 frontmatter schema。
- **边界**：知识库内容不进 Git 仓库；导出脚本改动属模块 7 / 内容域，评审后实施。

#### B2 知识图谱框架搭建
- **现状**：静态主题图 `/api/kg` + 自生长图 `/api/knowledge/kg` 两套；`KgUserNodeState` 有 mastery/heat；前端 Panel/Modal 已合入。
- **方案**：
  1. **先盘点**：列清现有节点类型（学科/考点/题目/会话/画像）与边类型，对照题库学科与考点体系。
  2. **层级补全**：学科 → 考点 → 题目 三级为主干；用户掌握度挂在考点节点（复用 mastery/heat）；会话/弱项作为关联节点。
  3. **可视化框架**：在现有 Panel/Modal 上补图例、节点筛选、点击下钻；不重做图谱组件。
  4. 全局图与个人图分层：`/global` 看体系，`/nodes/mine` 看个人掌握。
- **边界**：图谱数据来源于题库与行为记录，不手工灌节点；新增节点/边类型需登记基线。

#### B3 小智手机 / 平板端缺失
- 同 A7：验收 `/ai-assistant` 在三端的布局、输入框、会话列表与推荐问题展示；必要时补手写适配页，复用不重复。
