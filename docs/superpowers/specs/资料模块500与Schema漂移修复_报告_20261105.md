## 1. 用户问题

浏览器控制台报：

- `/api/materials?subject=shenlun&page_size=1` → 500
- `/api/materials?subject=gongzhuan&page_size=1` → 500
- `/api/achievements/earned` → 500
- `/api/materials/admin/list?page_size=100` → 500

要求：保证管理员端「资料管理」是最新版、可以实际使用。

## 2. 根因

不是前端问题，也不是鉴权问题：**带不带 token 都 500**，错误发生在 ORM 查询阶段。

`backend/logs/app.log` 关键栈：

```
File "backend/app/api/v1/library/materials.py", line 92, in list_materials
    total = q.count()
sqlalchemy.exc.OperationalError: (sqlite3.OperationalError) no such column: study_material.point_id
```

机制：

1. `Base.metadata.create_all()` 只创建缺失的**表**，不会给已存在的表补**列**；
2. 合并后模型新增字段，但存量 SQLite 未迁移；
3. ORM SELECT 会按模型展开整表字段 → SQLite 报 `no such column`；
4. 异常在鉴权之后、业务处理之前抛出 → 500。

实库与模型比对，恰好缺 5 列：

| 表 | 缺失列 |
|---|---|
| `achievement` | `badge_tier` |
| `user_achievement` | `tier_snapshot`、`snapshot_estimated` |
| `study_material` | `point_id`、`source_material_id` |

## 3. 修复

### 3.1 启动时列自愈（代码）

新增 `backend/app/core/schema_heal.py`：

- `ensure_model_columns(engine, metadata=None) -> list[str]`
- 只处理「表已存在、模型有、库里没有」的列；
- 跳过主键、非空且无默认值的列；
- 每次启动幂等执行，不建表、不改列、不删列。

`backend/app/main.py:126` 在 `Base.metadata.create_all(bind=engine)` 之后调用；
单列失败只 warning，不阻断服务启动。

### 3.2 成就成色回填（代码）

`backend/app/services/achievement_service.py`：

- 引入 `tier_for_condition`；
- `seed_achievements` 对已有成就回填 `badge_tier`，新成就直接写入；
- 避免 `badge_tier` 补列后仍为 NULL，导致前端成色展示缺失。

## 6. 风险与后续

1. `schema_heal` 只补可空列；非空列会跳过并告警。这类列必须走正式迁移（先带 DEFAULT 回填，或先回填再收紧），避免在存量数据上 ALTER 失败。本次 5 列均可空，已全部补齐。
2. 自愈只解决「列漂移」，不替代正式迁移；复杂变更（改类型、加索引、回填数据）仍应写迁移脚本。
3. `init_material_data.py` / `init_badge_names.py` 都是幂等脚本，新环境部署后需执行一次。
