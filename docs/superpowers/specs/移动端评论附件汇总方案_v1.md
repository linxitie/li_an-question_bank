# 移动端/平板评论附件汇总方案 v1

> 状态：**仅方案，未实施**（用户要求「先出方案不动手」）。
> 触发原因：PC 端评论附件已在本轮之前改为「直接内联进正文」，不再在评论下方做附件汇总；
> 移动端 / 平板端没有内联能力，若直接删掉汇总区，用户就再也看不到评论里带的文件。

## 1. 现状实测

| 端 | 文件 | 位置 | 行为 |
|---|---|---|---|
| 移动端 | `src/views/student/mobile/mobile_forum_detail.vue` | :98-102（主评论）、:150-151（回复） | `<AttachmentList mode="comment">` 汇总渲染 |
| 移动端输入区 | 同上 | :432-447 `submitComment` | 纯文本 `commentText` + `commentImages`，附件只走 `attachments` 字段，**不插入正文** |
| 平板端 | `src/views/student/tablet/tablet_forum_detail.vue` | :84-85、:113-114、:299 | 与移动端同构 |
| PC 端 | `src/views/teacher/teacher_forum.vue` / 管理端 | 评论正文 | 附件已内联进正文，无汇总区 |

结论：移动/平板的附件汇总**不是冗余**，而是当前唯一的展示入口。

## 2. 方案对比

### 方案 A：保持现状
- 改动量 0；缺点：与 PC 观感不一致，文件多时把评论挤长。
- 适用：本轮不做，作为兜底。

### 方案 B（推荐）：折叠胶囊 + 底部抽屉
- 列表侧：评论下把 `AttachmentList` 换成一行胶囊——「📎 3 个附件」（含图片时带 3 张 32px 缩略图），高度固定 40px。
- 交互：点胶囊 → 移动端 BottomSheet（平板用居中 Modal）复用现有 `AttachmentList` 渲染 + `ImagePreview` 放大；文档项直接下载。
- 阈值：附件 ≤ 2 且全为图片时保持现有的直接内联，避免“多点一次”。
- 影响面：
  - 新增 `src/components/forum/CommentAttachmentSheet.vue`（约 120 行，含遮罩/安全区/滚动）；
  - 改 `mobile_forum_detail.vue`、`tablet_forum_detail.vue` 各 2 处（评论、回复）；
  - 后端 0 改动（`attachments` 字段与 `AttachmentList` 契约不变）。
- 验证：560px / 820px 视口截图；点胶囊出抽屉；图片放大、文档下载；`npm run typecheck` + `test:unit`。
- 估时：0.5–1 人日。

### 方案 C：移动端也改为内联
- 做法：输入区换 `RichTextEditor`，上传后 `insertHtml`，评论渲染走 `ForumContent`。
- 代价：富文本编辑器在移动端的体积与输入体验、软键盘兼容、`.vtj` 页面模板受 R3 限制不能由 AI 改（需要设计器拖拽），且平板/手机两页各要一份。不推荐本轮做。

## 3. 推荐结论

选 **方案 B**：既保住“文件必须能看到”，又把列表高度压回一行；与 PC 的差异收敛为「PC 内联 / 移动折叠」，属于同类信息的两种合理呈现。
