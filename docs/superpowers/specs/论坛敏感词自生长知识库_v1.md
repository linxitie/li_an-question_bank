# 论坛敏感词自生长知识库 设计方案 v1

> 归档：docs/superpowers/specs/论坛敏感词自生长知识库_v1.md
> 主题：论坛评论区内容安全｜版本：v1｜日期：2026-11-03
> 定位：审核即研判，研判即知识沉淀；AI 提案、人类确认、图谱可视、变更可追溯。

---

## 1. 现状实测（先测量再陈述）

| 事实 | 位置 / 证据 |
|---|---|
| 论坛发帖、评论、编辑已有 DFA 敏感词检测 | backend/app/api/v1/community/forum.py（create_post 565 行附近、create_comment 1039 行附近、update_post 1751 行附近） |
| 词库是硬编码常量，热加载等于重启 | backend/app/services/sensitive_words.py 的 SENSITIVE_WORDS 与 reload() |
| 昵称/签名也走同一过滤器 | backend/app/api/v1/identity/auth.py 463 行附近 |
| 数据库是 SQLite（WAL），不是 PostgreSQL | AGENTS.md §3；backend/app/core/database.py |
| 已有向量/图投影协议，但默认关闭 | backend/app/foundation/stores/vector.py、graph.py；VECTOR_BACKEND 默认 off |
| 已有 Obsidian 单向导出与审核回写范式 | backend/app/services/obsidian_export.py、obsidian_sync.py |
| Obsidian 工程 Vault 已存在 | docs/knowledge-vault/ |
| API 面冻结 343 条，新增需登记白名单 | backend/tests/test_api_surface.py |

结论：原文方案里的 PostgreSQL + MongoDB + Qdrant + Neo4j 四库并置，在本项目会引入四套运维负担，且与现有 SQLite 单体、foundation 投影层冲突。本方案按**实际技术栈**落地四库的职责，而不是照搬产品名。

## 2. 角色定位（与原文一致）

| 角色层 | 职责 | 自动化边界 |
|---|---|---|
| 审核层（硬约束） | 对明确违规执行阻断/打码/标记 | 高置信度自动执行 |
| 研判层（软判断） | 对擦边内容做分级建议 | 只进入人工队列，不自动处置 |
| 治理层（知识） | 把判定沉淀为词条、变体、案例、图谱 | AI 只能提案，人类确认后写入 |

必须坚持：**审核动作可以自动化，但定义什么是违规的权力不能完全交给 AI**。每次判定都带政策条款与证据链，而不是一个黑箱分数。

---

## 3. 架构落地：1 个服务入口 + 6 个逻辑角色

不拆微服务，避免在 SQLite 单体上制造分布式复杂度；角色以模块边界落地：

| 角色 | 实现 | 说明 |
|---|---|---|
| 采集与归一化 | services/content_guard/normalizer.py | NFKC 全半角、小写、去零宽/分隔符，保留原文索引映射 |
| 广谱快筛（DFA） | services/content_guard/engine.py | 从 cg_term/cg_variant 编译 DFA，O(n)；库空时回退旧词表 |
| 专项审核 | cg_term.category + cg_policy | 按违规域绑定条款，运行时换策略无需重训模型 |
| 跨模态关联 | 未实现（P2） | 当前论坛只处理文本；图片/附件暂不进入语义链路，边界见 §10 |
| 仲裁与分级 | services/content_guard/judgments.py | 最高等级优先 + 政策 priority + 置信度阈值，输出证据链 |
| 知识运营 | services/content_guard/proposals.py | 提案 → 人工审批 → 写库 → 审计；Agent 无删除权 |
| 红队 | services/content_guard/redteam.py | 生成插符号/零宽/同音/繁体/全角样本，漏放即提案 |
| 主动学习 | judgments.override_judgment | 人工确认/误判 → 调置信度；连续误判触发降级提案 |

编排策略：**条件路由**。命中 blocked 直接阻断；masked 打码并留痕；reviewed 只入人工队列；无命中零写入（不产生判定记录）。

## 4. 数据模型（cg_* 十二张表）

| 表 | 作用 | 关键字段 |
|---|---|---|
| cg_policy | 政策条款（稳定层） | code/category/level/severity/priority/legal_basis/version |
| cg_term | 词条（运行层） | term/normalized/level/category/confidence/status/policy_clause_id/命中统计 |
| cg_variant | 变体 | term_id/variant/normalized/kind/status |
| cg_judgment | 判定实例 | scene/source_id/content_hash/content_snippet/decision/confidence/hits/evidence |
| cg_task | 审核任务状态机 | pending / auto_blocked / auto_masked / approved / rejected / appealing / closed |
| cg_proposal | 知识变更提案 | kind/title/payload/evidence/proposer/status/dedupe_key |
| cg_case | 案例库 | judgment_id/verdict/narrative/tags |
| cg_audit_event | 追加式审计 | prev_hash/hash/before_hash/after_hash/action/actor |
| cg_edge | 图谱关系 | src_type/src_id/rel/dst_type/dst_id/weight |
| cg_stat_daily | 按天聚合 | stat_date/scene/total/blocked/masked/reviewed/false_positive |
| cg_redteam_sample | 红队样本 | term_id/text/kind/detected |
| cg_sync_state | 引擎版本 / 投影状态 | key/value |

模型注册在 backend/app/models/content_guard.py，由 models/__init__.py 导入，保证 create_all 解析外键。

## 5. 「四库」在真实技术栈中的职责映射

原文四库 → 本项目落地：

| 原文 | 本项目 | 职责与边界 |
|---|---|---|
| 关系库 | SQLite（cg_* 表） | 唯一事实源：词条、条款、判定、任务、提案、审计、统计 |
| 文档库 | SQLite TEXT + 审计摘要 | 政策全文、案例叙述；不另起 ES，避免双写不一致 |
| 向量库 | foundation VectorStore（默认 off，可切 local/milvus） | 只做可重建投影；当前 DFA 已覆盖精确命中，向量召回列为 P2 |
| 图库 | cg_edge（SQLite）+ Obsidian Mermaid | 三层本体与邻居查询；Neo4j 仅作为可选投影，不是强依赖 |
| 对象存储 | 论坛现有附件/图片链路 | 本方案不新增多模态对象；图片审核列为边界外 |

膨胀控制：
- cg_judgment 只存 content_hash + 脱敏摘要，不存原文；
- cg_stat_daily 日聚合，看板不扫明细；
- cg_redteam_sample 可按 detected + created_at 归档删除；
- cg_audit_event 为审计留痕，默认全量保留，归档策略见运维手册。

## 6. 三层本体

1. **政策本体（稳定层）**：policy「属于类别」「被词条引用」「优先于」；policy 是判定最终锚点。
2. **审核本体（运行层）**：judgment「触发词条」「引用条款」「被任务复核」「被案例引用」；支撑审计与可解释。
3. **舆情本体（演化层）**：category / term / variant 的关系与高频共现；当前不引入账号、事件、传播路径节点（论坛侧无事件模型），保留事件节点类型供后续扩展。

图谱查询：GET /api/v1/admin/content-guard/graph?node_type=term&node_id=1&depth=2。导出：docs/knowledge-vault/敏感词治理/04-图谱/全景.md（Mermaid + 关系统计）。

## 7. 判定与仲裁

流程：
1. normalizer.compact：归一化并保留 normalized→original 索引；
2. DFA 最长匹配（同一词多次出现全部打码，但证据只记一条）；
3. 等级归并：blocked > masked > reviewed；
4. 政策映射：取命中词条绑定条款；缺省按 category 回落；
5. 置信度：0.5×词条置信度 + 0.5×等级基线 + 命中数/变体微调，封顶 0.99；
6. 处置：blocked→block；masked→mask（置信度 < 0.62 转 review）；reviewed→review；
7. 证据链：normalize → dfa_match → policy_map → arbitration → decision 五段；
8. 落库：judgment + task + 命中统计 + 图谱边 + 日聚合 + 审计事件。

人工复核：
- confirm：案例入库，词条置信度 +0.02；
- reject：词条置信度 -0.15，false_positive_count +1；连续 3 次触发降级/停用提案；
- modify：按确认处理并记录理由。

## 8. 自生长闭环

| 信号 | 触发 | 产出 |
|---|---|---|
| 红队漏放 | 每日 03:30 定时 / 手动运行 | cg_redteam_sample + add_variant 提案 |
| 人工误判 | 判定复核 reject | 置信度下降；≥3 次生成 update_level/deprecate 提案 |
| 人工确认 | 判定复核 confirm | cg_case 案例 + 图谱边 |
| 观察词命中 | reviewed 级判定 | cg_task pending，进入 Obsidian 待审队列 |
| 对账异常 | 手动 / 定时 reconcile | consistency 提案（不自动修复） |

所有写入路径都追加哈希链审计；Obsidian 中的勾选通过受控导入执行，Agent 没有直接删除词条的 HTTP 或服务入口。

## 9. 可靠性、降级与 HITL

- **回滚开关**：设置 CONTENT_GUARD_ENABLED=false，论坛立即回退旧 sensitive_words 词表（behavior 与改造前一致）；
- **建表缺失降级**：cg_term 不存在时自动走旧过滤器，审核不 500；
- **库空降级**：cg_term 无 active 词条时用内置词表，避免「库空即全放行」；
- **置信度路由**：中低置信度转人工，不直接阻断；
- **证据链**：无政策映射时按 category 回落，仍写明依据；
- **多进程**：cg_sync_state.engine_version 作为版本号，各 worker 请求时比对并重建 DFA；
- **审计**：哈希链校验 GET /audit/verify；任何变更的 before/after 都有摘要哈希。

性能红线（按现有 SQLite 单机口径）：
- DFA 检测 1000 字 < 1ms（纯内存）；
- 单次审核额外写：1 judgment + 1 task + 1 audit + N 统计更新，均在请求事务内；
- 触发阈值：pending 任务积压 > 200 或审计链校验失败 → 告警。

## 10. 明确边界（不做什么）

- 不引入 PostgreSQL / MongoDB / Qdrant / Neo4j 作为强依赖；需要时通过 foundation 投影层切换，事实源不变；
- 不做图片 OCR、音视频转写、跨模态隐藏编码检测（论坛当前只提交文本与附件 URL）；
- 不做生成式大模型直接判定阻断；LLM 只能作为提案方，不能直接写词条；
- 不改 .vtj 模板；管理端运营台由后端以单文件 HTML 提供；
- 不重算 343 条 API 基线，只登记新增白名单。

---

## 11. 与原文方案的关键偏差（有意为之）

1. 原文要求四套数据库；本项目以 SQLite 为事实源，向量/图为可重建投影，避免双写与运维膨胀。
2. 原文要求多 Agent 流水线；本项目以服务模块隔离角色，不拆进程，延迟与故障域更可控。
3. 原文要求 Obsidian 作为知识运营界面；本项目保留其单向投影 + 受控回写，同时提供管理员 Web 运营台，避免 Obsidian 性能上限倒灌审核链路。
4. 原文的 2026 基准数据（Qdrant 4.55ms 等）未在本项目复测，因此不作为选型依据。

## 12. 接口与集成点

新增管理端（require_admin，role_level >= 2）：/api/v1/admin/content-guard/*
- overview / terms / variants / policies / judgments / tasks / proposals / audit / graph / trend / detect / redteam / obsidian / reconcile / seed / reload / console。

写入路径集成：
- 发帖：forum.create_post → guard_text(scene=forum_post) → 阻断/打码/研判 → 判定落库 → 创建成功后 bind_source；
- 评论：forum.create_comment → guard_text(scene=forum_comment, source_id=post_id)；
- 编辑：forum.update_post → guard_text(scene=forum_post_update, source_id=post_id)；
- 昵称/签名：auth.update_profile → guard_text(scene=profile)。

Obsidian 投影目录：docs/knowledge-vault/敏感词治理/（可用 CONTENT_GUARD_VAULT 覆盖）。
