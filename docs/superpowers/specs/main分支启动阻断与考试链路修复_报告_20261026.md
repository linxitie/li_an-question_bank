## 2. 根因与改动

### P0-1 / P3-1 Pydantic v2 序列化
`backend/app/schemas/schemas.py`

- `ExamRecordResponse`（原 :682）与 `ForumUserPublic`（原 :756）由
  `class Config: orm_mode = True` 改为 `model_config = ConfigDict(from_attributes=True)`。
- 原因：`orm_mode` 是 Pydantic v1 键名，v2 静默忽略；`exams.py` 返回 ORM 对象时在校验层抛
  `ResponseValidationError`，前端只看到 500。`ConfigDict` 已在文件头导入。

### P0-2 / P0-3 考试路由导入
`backend/app/api/v1/exam/exams.py`

- 顶部 models 导入补 `PaperQuestionRelation`、`QuestionType`；删除函数内重复导入（原 :53）与
  交卷路径上错误的 `from ..models import QuestionType`（原 :322，`..models` 并不存在该符号）。
- 取题、交卷两条链路此前只能靠运行时 NameError/ImportError 暴露，静态导入表看不出来，
  本次一并收敛到模块顶部。

### P1-1 日志目录导致启动阻断
`backend/app/main.py`

- 先 `os.makedirs(os.path.dirname(os.path.abspath(settings.LOG_FILE)), exist_ok=True)` 再建
  `RotatingFileHandler`；构造失败（只读盘/权限）捕获 `OSError` 后降级为纯 stdout，绝不阻断导入。
- 复现证据：在干净 main（`66ebeff`，无 `backend/logs`）跑任意 pytest，collection 阶段即
  `app\main.py:71 FileNotFoundError: ...\backend\logs\app.log`。这就是"同伴拉下来起不来"的直接原因。

### P1-3 试卷题数漂移
新增 `backend/app/services/paper_stats.py`：

- `recount_paper_questions(db, paper) -> int`：`db.flush()` 后按 `paper_question_relation` 行数写回
  `exam_paper.question_count`，作为唯一口径。
- `next_question_order(db, paper_id) -> int`：以 `MAX(question_order)+1` 续号，避免计数漂移时题序重复。

接入点：

- `catalog/question_import.py`：批量导入与 confirm 导入都改为 `order_base = next_question_order(...)`
  起编，循环结束 `recount` 重算；同时修正 `linked += 1` 缩进在循环外、导致"关联 N 题只记 1 题"的缺陷。
- `catalog/papers.py`：`add_questions` 用 `order_base + added` 编题序并 `recount`；返回文案由
  `order - paper.question_count`（恒为 0）改为真实 `added`；`remove_question_from_paper` 删除后 `recount`。

存量修复工具：`backend/scripts/repair_paper_question_count.py`

```bash
python backend/scripts/repair_paper_question_count.py                 # 只盘点，有漂移 exit 1
python backend/scripts/repair_paper_question_count.py --apply         # 先 sqlite3.backup() 快照再修正
python backend/scripts/repair_paper_question_count.py --db X.db --apply
```

遵守 R10：快照走 `Connection.backup()`，不用 `shutil.copy2`。
