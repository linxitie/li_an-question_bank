### 3.2 政策卡契约（编译器的输入）

一张卡 = frontmatter（人读元数据）+ `policy_dsl` 块标量（机读判定）+ 正文（给审核员看的解释）。

```yaml
id: P-06-002            # ^P-\d{2}-\d{3}$
status: active          # 非 active 不参与编译（记 warning）
severity: high          # critical|high|medium|low
action: "A3 隐藏"        # 必须 A0–A5 起头
domain: 06-考试与培训
review_due: 2027-02-02
policy_dsl: |-
  scope: forum.comment          # forum.post | forum.comment
  match:
    any:
      - regex: "(包过|必过).{0,6}(保过|退款)"
      - lexicon: exam_cheat_terms
  context_modifiers:
    - if: is_after_exam_discussion
      weight: -0.2
  thresholds:
    allow: "< 0.40"
    hold: "0.40 - 0.80"
    mask: "0.80 - 0.92"
    block: ">= 0.92"
```

编译期校验（任一 error 即不进入规则集，且列在 issues 里供控制台展示）：

| 校验 | 代码 | 说明 |
|---|---|---|
| id 格式 | `policy_id_invalid` | 必须是 `P-域-序号` |
| scope 白名单 | `scope_unknown` | 只认 forum.post / forum.comment |
| 算子白名单 | `match_operator_unknown` | lexicon / regex / ner_target / ner_org / keyword_all / keyword_any |
| 正则可编译 | `regex_invalid` | 编译期就报，不等到线上 |
| 上下文条件 | `modifier_condition_unknown` | 24 个 `is_*` 条件，防拼写漂移 |
| 阈值写法 | `threshold_format` | 只认 `< 0.40` / `0.40 - 0.80` / `>= 0.92[ && FLAG=1]` |
| 正反例 | `examples_insufficient`（warning） | 各至少 2 条，缺了不阻断编译 |

### 3.3 规则集哈希（为什么它重要）

`compile_ruleset()` 的哈希 = `sha256(canonical JSON of {schema_version, rules})`，
**按 id 排序、不含编译时间**。含义：

- 同样输入必得同样哈希 → 线上「本次判定用的哪版政策」可被无歧义引用；
- 改一张卡必然改哈希 → CI 可用它做「政策变更需人工确认」的闸门；
- 回滚只需切回旧哈希文件，不需要 git revert。

### 3.4 影子打分（当前的真实能力边界）

`score_text()` 只实现「规则骨架」：regex 命中记 0.85、keyword_all 0.95、keyword_any 0.75，
乘严重度权重（critical 0.95 / high 0.80 / medium 0.60 / low 0.40），再按条款阈值分档。

**lexicon 算子尚未注入词表实体**——当前 `rules_without_lexicon` 会如实返回未覆盖的规则数。
这不是缺陷，而是 M0 的诚实状态：先把「编译、校验、试判、哈希」跑通，词表与模型在 M1 接入。

另有一处硬约束已实现：`MODERATION_ENFORCE_BLOCK=False` 时，所有 `block` 档**降级为 `mask`**。
这是「首月动作上限 A2」在代码层的落实——开关没开，最重动作也到不了阻断。

## 4. 接口清单（全部 `Depends(require_admin)`）

| 方法 | 路径 | 作用 | 写盘 |
|---|---|---|---|
| GET | `/api/admin/knowledge-ops/summary` | 扫描数 / 编译数 / 跳过数 / 域 / 严重度分布 / 哈希 / 错误与告警 / 开关状态 | 否 |

| POST | `/api/admin/knowledge-ops/preview` | 影子试判一段文本，返回 score/bucket/hits | 否 |

发布写盘的三个前置条件（缺一即拒）：`MODERATION_VAULT_WRITE=1`、无编译错误、目录可写。
产物落在 `AI舆情审核知识库/产出/变更集/ruleset_<时间戳>_<哈希前8>.json`，与审计日志同目录，便于对账。

任何环境都能跑，且这些样例文件本身成为「政策卡格式」的活文档。

   均被拒。可手动删除，或被 `.gitignore` 覆盖即可（当前未纳入版本控制）。
