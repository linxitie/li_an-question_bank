## 1. 结论摘要

五项问题不是同一个模块的同一个 bug，而是**四条链路各自断开**：

| # | 用户现象 | 直接原因 | 根因层 |
|---|---|---|---|
| 1 | 管理员题库列表 ID 从 10 开始，不是 1、2、3… | 模板直接显示数据库主键 `question_id` | 展示层把“业务序号”误当“数据库主键” |
| 2 | 来源缺失，或只显示“考试/未标注” | 导入只拼“省份+考试类型”，没有使用导入文档标题；预览 item 没有 source 字段 | 导入元数据链路缺“文档标题→来源”的单一真源 |
| 3 | 题目预览选项只剩 4 个空点 | `GET /api/questions/group/{id}` 把 `{key,value}` 选项压成纯字符串；前端仍按 `o.key/o.value` 渲染 | 接口契约与消费端契约不一致 |
| 4 | 材料/题干/解析排版粘连，PDF 硬换行、图片夹在句中、材料标题不突出 | `renderQuestionContent` 对纯文本直接原样返回；材料组件只给文本节点套标签，不处理段落；各页各写一套 CSS | 缺少统一的“阅读态富文本规范化层” |
| 5 | 公专/行测选项缺失，申论“要求”缺失 | 图片选项未按 A–D 拆分；申论解析器只认行首“要求”，同行/无冒号/分值后编号都不命中 | 解析器对“非标准排版”的容错不足；落库链路本身是通的 |

**总体设计主张**：

1. **一个渲染出海口**：所有题目内容继续只走 `src/utils/questionRender.js`，在其中增加“阅读态排版规范化”，一次覆盖三端 40+ 调用点，避免逐页改 `.vtj` 模板。
2. **一个来源真源**：导入文档标题（清洗后的 `original_filename`）是 source 的单一真源；没有标题证据时输出“待补来源”，不猜。
3. **一个选项契约**：题组详情接口返回 `[{key,value}]`，前端现有 `o.key/o.value` 与 `parsedOptions` 同时兼容对象/字符串。
4. **解析器负责“拆对”**：申论要求、图片选项在解析阶段拆开；落库、预览、编辑、展示链路尽量不改契约。
5. **raw 页零模板改动**：管理员 ID 用 script DOM 重编号；requirements 用现有 `withRequirements` 展示；排版用全局 CSS；编辑弹窗用 script 注入“要求”输入框。若必须改 `.vtj` 模板，单独向用户申请，不在本方案默认范围。

## 3. 根因树（问题 → 子问题 → 子子问题）

### 3.1 问题 1：ID 不是从 1 开始

- 子问题 1.1：列表显示用的是数据库主键。
  - 1.1.1 管理员页模板直接绑定 `q.question_id`。
  - 1.1.2 后端已升序，但主键 1–9 已不存在，所以第一行是 10。
- 子问题 1.2：翻页后序号没有按页重排。
  - 1.2.1 前端有 `currentPage/pageSize`，但没有计算展示序号。
- 结论：展示序号 = `(currentPage-1)*pageSize + index + 1`；真实 ID 保留在 `title` 与操作参数中。

### 3.2 问题 2：来源缺失

- 子问题 2.1：导入器没有把文档标题写进 source。
  - 2.1.1 `_auto_detect_tags` 只产 `paper_name`，且 `paper_name` 可能被正文书名号污染。
  - 2.1.2 `_inject_source` 只拼“省份+考试类型”，两者都没有时留“考试”。
- 子问题 2.2：PDF 预览 item 不带 source，confirm 也不读文件名。
  - 2.2.1 预览 item 字段清单里没有 source。
  - 2.2.2 confirm 只 `item.get('source','')`，没有 fallback 到 `record.original_filename`。
- 子问题 2.3：历史数据没有可追溯回填口径。
  - 2.3.1 挂试卷的题可以按 `paper_question_relation → exam_paper.paper_name` 回填。
  - 2.3.2 未挂试卷的题只能按 import preview 题干指纹匹配；匹配不到必须标“待补来源”。
- 结论：source 以“清洗后的文档标题”为单一真源；历史回填分级、dry-run、可审计。

### 3.3 问题 3：预览选项缺失

- 子问题 3.1：组详情 API 丢失选项 key。
  - 3.3.1 /group 接口把 dict 压成 value 字符串。
  - 3.3.2 admin/teacher 题组小题块没调用 `parsedOptions`，直接读 `o.key/o.value`。
- 子问题 3.2：其他接口契约不能一起改。
  - 3.2.1 `_normalize_options` 返回 `"A. xxx"` 字符串，被 /random 等旧接口消费。
- 结论：只改 `/group/{id}` 为对象数组；旧接口不动；前端 `parsedOptions` 保持双兼容。

### 3.4 问题 4：排版不科学

- 子问题 4.1：纯文本没有段落化。
  - 4.1.1 `renderQuestionContent` 直接返回原字符串。
  - 4.1.2 页面 CSS `white-space: normal` 折叠换行。
- 子问题 4.2：PDF 软换行被当成硬段落。
  - 4.2.1 材料组件 `pre-wrap` 保留每个 PDF 行。
  - 4.2.2 没有“上一行未结束则合并”的规则。
- 子问题 4.3：材料标题、图片、表格没有统一块级语义。
  - 4.3.1 材料标题只靠文本节点套胶囊，遇到已格式化 HTML 会二次包裹。
  - 4.3.2 图片有的行内、有的独占一行，没有 `figure` 语义（白名单也不含 figure）。
- 子问题 4.4：三端各写一套 CSS。
  - 4.4.1 教师/管理员/学生页各自设置字体、行高、间距。
- 结论：在 `renderQuestionContent` 内做一次规范化，输出 `.qr-rich` 语义结构；全局 `rich-text.scss` 统一三端；材料组件对已格式化内容早退。

### 3.5 问题 5：选项/要求缺失

- 子问题 5.1：申论要求只在行首识别。
  - 5.1.1 同行“（15分） 要求：…”不命中。
  - 5.1.2 无冒号“要求全面、准确”不命中。
  - 5.1.3 分值后直接“（1）…”不命中。
  - 5.1.4 同行多个“（1）…（2）…”不拆条。
- 子问题 5.2：图片选项没有按图片数拆分。
  - 5.2.1 只有 A–D 文本标记才切。
  - 5.2.2 4 张图挤进最后一个 key。
  - 5.2.3 兜底逻辑生成“（见图）”，会覆盖真实四图。
- 子问题 5.3：编辑弹窗会把已有要求清空。
  - 5.3.1 弹窗没有 requirements 输入框。
  - 5.3.2 `saveEdit` 无输入时写回空数组。
- 结论：解析器修“拆对”；历史数据脚本修“已错的”；编辑弹窗修“不再清空”；预览加完整性告警。

## 4. 设计决策

### D1：统一渲染出海口，不逐页改模板

- 继续以 `src/utils/questionRender.js` 为唯一渲染入口。
- 新增 `formatRichContent`（内部函数）在 `sanitize` 之后、`attachImageFallback` 之前执行。
- 输出结构：
  - 短单行（≤80 字、无换行、无块级标签）：保持纯文本/行内，不包 `p`，避免破坏选项布局。
  - 多行/长文本：`<div class="qr-rich">` + `<p class="qr-p">`。
  - 材料/资料/给定资料标题、`（一）`、`一、`：`<div class="qr-heading">`。
  - 独占一行的图片：`<div class="qr-figure">`。
  - 列表 `（1）`、`1.`、`①`：保留在段落内或 `ul/ol`，不误判为标题。
- 不引入 `figure/figcaption`（白名单不含，会被清洗掉）。
- 已有块级 HTML 的内容只包一层 `.qr-rich`，不重排，避免破坏表格/富文本。

### D2：PDF 软换行合并规则

按行扫描，维护当前段落：

1. 空行：强制结束当前段。
2. 行首是标题/编号/列表/图片独占行：先结束当前段，再单独成块。
3. 当前行与上一行都不是标题，且上一行末字不在 `。！？!?；;：:…`：合并到当前段（PDF 软换行）。
4. 否则新起一段。
5. 段落内图片保留行内；段落只有图片时转为 `qr-figure`。

这样 group 41 的“于 / 来到 / 集团展馆”会合成一句，“……创新产品。”后才分段；group 34 的“增加1656万人。”独立成句，图片独立成块。

### D3：材料标题高亮与间距

- `.qr-heading`：浅蓝底、左侧 3px 深蓝边、圆角 6px、上下间距 20/10px；首个标题 margin-top 0。
- `材料一/材料1/给定资料N/资料N` 统一识别；保留原文编号。
- 材料正文段落间距 12px；表格/图片上下 12px。
- `materialDock.js` 的 `formatMaterialHtml` 与 `paper_answer.vue` 的 `formatMaterialBody` 在检测到 `.qr-rich`/`.qr-heading` 时**早退**，避免二次包胶囊。
- `.qm-dock-body .qr-rich { white-space: normal; }`，避免 `pre-wrap` 与 `p` 间距叠加。

### D4：题组选项对象契约

- `GET /api/questions/group/{id}` 的 `members[].options` 统一返回 `[{key, value}]`。
- 归一化规则：
  - dict：保留 key，清洗 value。
  - 字符串：`^\s*([A-H])[.、．)）:：]\s*(.*)$` 提取 key；无 key 按顺序 A/B/C/D。
  - 去重、按 key 排序。
- `_normalize_options` 保持旧字符串契约，只服务 /random 等旧接口。
- 前端 `parsedOptions` 继续双兼容；题组小题块不改模板即可恢复。

### D5：管理员列表展示序号

- 只改 `.vtj/vue/admin_questions.vue` 的 `<script>`：
  - `load()` 成功后 `await nextTick(); renumberRows()`。
  - `renumberRows()` 遍历 `.data-table tbody tr`，把第一个 `td` 文本改为 `(currentPage-1)*pageSize + index + 1`。
  - 同时写 `title="真实题目ID：xxx"` 与 `data-real-id`。
  - 不改 `questionList` 的 `question_id`，避免编辑/删除/审核参数被改。
- 若翻页/筛选后 DOM 未更新，`nextTick` + 一次 `requestAnimationFrame` 兜底。

### D6：来源以文档标题为单一真源

- 新增 `_clean_source_title(filename: str) -> str`：
  - 去路径、去扩展名；下划线转空格；压缩空白。
  - 去掉尾部“题本/答案解析/答案/解析/试卷”等附件词（仅作为独立后缀时）。
  - 去掉首尾 `-_—` 与括号噪声；长度 <5 返回空；截断 200。
- `_auto_detect_tags` 增加 `tags['source_title']`，不改 `paper_name` 语义。
- 写入优先级：
  1. 用户在导入时显式填写的 source（非泛化值）。
  2. 清洗后的文档标题。
  3. 省份+考试类型。
  4. 空（显示“未标注/待补来源”）。
- 泛化值集合：空、`考试`、`真题`、`未标注`、`模拟考试`、`省考`、`国考`、`联考`。
- 三个入口都接入：
  - PDF 预览：preview item 增加 `source`；`auto_detected_tags.source_title`。
  - `/batch-parsed`：source 优先 `source_title`，不再只拼省市。
  - `/confirm`：item 无 source 时用 `_clean_source_title(record.original_filename)`；group.source 同步。
- 历史回填脚本分级：
  - A 级：挂试卷 → `paper_question_relation → exam_paper.original_title || paper_name`；跳过“智能组卷”类虚拟试卷。
  - B 级：未挂试卷 → import preview 的题干指纹唯一匹配。
  - C 级：匹配不到 → 保持空并输出 `待补来源清单.csv`，不猜。

### D7：申论“要求”解析

- 新增 `_split_essay_requirements(text) -> (stem, requirements_list)`：
  - 先找显式“要求/作答要求”：
    `(?:作答)?要求[ \t　]*(?=[：:]|[（(]\s*\d|[一二三四五六七八九十]+[、.]|(?:准确|全面|条理|观点|分析|语言|字数|不超过|紧扣|结合|自选|自拟|联系实际|内容|结构|逻辑|格式))`
  - 找不到时，若 `（\d+分）` 后紧跟 `（1）`/`1.`，以分值后为界拆分（覆盖 3627）。
  - `before` 作为题干，`after` 去冒号后按 `（1）…（2）…` 或 `1.…2.…` 切条；保留编号。
  - 不匹配“要求你……”这类题干动词。
- `_parse_essay_document` 在 :3107-3135 调用该函数，写 `requirements`，并从 `question_content` 去掉要求段。
- `_ESSAY_REQ_LINE_RE` 扩展到同行多编号；旧逻辑保留兼容。
- 历史修复脚本 `repair_essay_requirements.py`：只处理 requirements 为空且能高置信拆分的行；默认 dry-run；`--apply` 备份；输出修改前后对照。

### D8：图片选项拆分

- 在 `_extract_options` 返回前新增后处理 `_split_image_only_options(options)`：
  - 收集所有 `[IMAGE:...]`，按出现顺序。
  - 去掉图片标记、残留 `[A-D][、.．)）]`、空白与标点后，若还有实际文字 → 不拆。
  - 总图片数 2–4：按顺序拆成 A、B、C、D；不足 4 个时只生成已有图片数。
  - 总图片数 >4：不拆，记 warning。
  - 保留原 answer（现有样本 answer 均为 A–D 有效值）。
- 移除/收紧 :3339-3357 的“（见图）”兜底：只有 options 仍 <2 且题干含“图形/如图/下图”时才生成占位。
