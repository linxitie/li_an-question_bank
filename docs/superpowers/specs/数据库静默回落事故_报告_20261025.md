# 数据库「静默回落到空库」事故报告（2026-10-25）

> 归档：`docs/superpowers/specs/数据库静默回落事故_报告_20261025.md`
> 影响：教师端/学生端/管理端全部读取到 0 题目、4 个账号的旧库；`/api/questions/` 全量 500。
> 结论：**数据没有丢失**，是后端连错了库。真库 3357 题 / 13 用户 / 1049 考点完好。

## 1. 现象

- 学生端无法登录/注册，教师端题目"被吞没"，管理端统计归零；
- `/api/questions/?page=1` 返回 `500 INTERNAL_ERROR`；
- `backend/.env` 已不存在，但服务仍"健康"（`/health` 200）。

## 2. 根因链（实测逐环）

| 环节 | 实测 |
|---|---|
| 1. 配置来源 | `app/core/config.py` 用 `env_file=".env"`（相对进程 cwd）；`backend/.env` 缺失 |
| 2. 默认值 | 旧代码默认 `SQLITE_PATH="./data/example_db.sqlite"`（main 的 `a9352ea` 才改为 `./data/question_bank.db`） |
| 3. 后果 | 启动时 `create_all` 在 `backend/data/example_db.sqlite` 上建表；该库是旧 schema（**无 `question_bank.sub_category_id`**） |
| 4. 表现 | 所有 SELECT `question_bank` 的查询报 `no such column` → 500；`sys_user` 只有 4 个 10-21/22 注册的旧账号 → 登录失败 |
| 5. 沉默 | 启动日志只打印"数据库表初始化完成"，不打印真实库路径/行数，故障被当成数据丢失 |

## 3. 证据

```
真库 backend/data/question_bank.db            317,898,752 B   question_bank=3357 sys_user=13 KP=1049
错库 backend/data/example_db.sqlite            18,493,440 B   question_bank=0    sys_user=4  （无 sub_category_id）
合并后配置 settings.SQLITE_PATH = ./data/question_bank.db
```

`TestClient` 复现：`no such column: question_bank.sub_category_id`。

## 4. 修复（已提交）

| 项 | 内容 |
|---|---|
| 默认库 | 随 `origin/main` 合入 `a9352ea`：默认指向 `./data/question_bank.db` |
| 启动守卫 | 新增 `app/core/db_guard.py`：相对路径按 **backend/** 解析（不依赖 cwd）；建表前打印真实路径与文件大小，缺文件 ERROR；建表后校验 `question_bank.sub_category_id` 等关键列与行数，空库 ERROR；`DB_GUARD_STRICT=1` 时拒绝启动 |
| 接入点 | `app/main.py` lifespan：`preflight → create_all → verify` |
| 测试 | `backend/tests/test_db_guard.py` 6 passed（缺文件/严格模式/缺列/计数） |
| 运行态 | 停掉 3 个残留 uvicorn（2 个抢 8000）→ 按 `start_system.bat` 重启 1 个 |

验证输出：

```
[db-guard] SQLite 实际路径: ...\backend\data\question_bank.db (exists=True, size=317898752)
[db-guard] schema 校验通过，行数={'question_bank': 3357, 'sys_user': 13}
/api/questions/ → 200, total=3122
/api/auth/login → 422（路由正常，仅参数校验）
```

## 5. 遗留与建议

1. `example_db.sqlite` 内含 4 个 10-21/22 注册的账号（`ycc5678`、`cbrycc`、`123456`、`ZZ20261022`）。其中前两个在真库同样存在（id 3/4），后两个是错库独有。**未自动迁移**：需用户确认是否补录。
2. 建议为 `backend/.env` 建立最小化恢复流程（模板已有 `.env.example`），并在部署检查表加入 `SQLITE_PATH` 与库行数两项。
3. 建议 CI 以 `DB_GUARD_STRICT=1` 启动一次冒烟，避免空库通过。

## 6. 防复发要点

- 任何"数据消失"先查 **真实库路径 + 行数**，不要先改数据；
- 备份必须 `sqlite3.backup()`（R10），本次已生成 `question_bank_guard_snapshot_20261025_112956.db`（317 MB）；
- 禁止删除 `backend/data/*.bak*`（R8）。
