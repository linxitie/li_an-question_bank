## 1. 摘要：我推荐的顺序与理由

```
B1 个人库与建卡权限  ──►  B2 分享与领取  ──►  B3 配图上传
        │                                        │
        └──────────►  B4 手机端卡片栈（视觉）  ◄──┘
                            │
                            └──►  B5 PC/平板 VTJ 页  ──►  B6 内容生产（申论/公专）
```

| 批次 | 内容 | 为什么排这个位置 |
|---|---|---|
| **B1** | `status=2` 个人库 + `/my` CRUD + 三角色建卡 | **一切的地基**：没有"归属"就谈不上分享；且它改的是权限与查询，改完能立刻验证"学生建的卡别人看不见" |
| **B2** | `material_share` + share/adopt | 依赖 B1 的 `creator_id + status`；B2 只加表和 2 个端点，风险低 |
| **B3** | `cards/batch-image` + `column_mapping.cover` | 可并行；但配图卡需要 B4 的图示区渲染才有意义，故排在 B4 前一步 |
| **B4** | 手机端卡片栈（堆叠 + 3D + 四阶段翻转） | **我能独立交付**（手写页不受 R3 限制），且它是用户可见价值最高的一块 |
| **B5** | PC/平板 VTJ 页 | 需用户在设计器拖 4 处容器，工期不由我单方决定，故排在 B4 之后复用组件 |
| **B6** | 申论/公专卡片内容（当前 **0 张**） | 纯内容生产，需你定选题；没有内容，B4/B5 做得再好也没东西可看 |

**替代顺序（若你更看重"马上能看到效果"）**：B4 → B1 → B2 → B3 → B5 → B6。差别是"先有画面"还是"先有地基"。

## 4. B1：个人库与三角色建卡

### 4.1 数据模型（**零新表，仅语义扩展**）

| 字段 | 变化 |
|---|---|
| `status` | 由 `0/1` 扩展为 `0 草稿 · 1 公开 · 2 私有（仅创建者+管理员可见）`，**注释需改** |
| `creator_id` | 建卡时强制写入当前用户（现有可空需在业务层强制） |
| `source_material_id`（**新增列**） | 领取时记录来源卡片；自建为 NULL。类型 `BigInteger NULL` |

**迁移**：`ALTER TABLE study_material ADD COLUMN source_material_id INTEGER;` + 索引 `(creator_id, status)`。
存量数据不动（现有 10 条 `status=1`）。

### 4.2 接口

| 接口 | 方法 | 作用 | 权限 | 备注 |
|---|---|---|---|---|
| `/api/materials/my` | **POST** | 建卡（写 `creator_id`，`status=2`） | student/teacher/admin | 复用 `_validate_material_body` + `sanitize_html` |
| `/api/materials/my` | **GET** | 我的库（`creator_id=me`，含 0/1/2） | 登录 | 分页 + `subject/type/status` 过滤 |
| `/api/materials/my/{id}` | **PUT** | 改自己的卡 | 仅创建者 | 不允许改 `creator_id` |
| `/api/materials/my/{id}` | **DELETE** | 删自己的卡（软删 `status=-1`） | 仅创建者或管理员 | 复用既有软删语义 |

> 复用 `POST /api/materials/admin` 不行——它硬绑 `_require_admin`。新增 `/my` 而不是放宽 admin 端点，**避免把管理端权限撕开**。

### 4.3 权限矩阵（服务端强制，不接受客户端传 creator_id）

| 操作 | student | teacher | admin |
|---|---|---|---|
| 建卡 | ✅ | ✅ | ✅ |
| 改/删自己的卡 | ✅ | ✅ | ✅ |
| 改/删他人的卡 | ❌ | ❌ | ✅ |
| 公开/下架（status 0↔1） | 仅自己的 | 仅自己的 | ✅ 任意 |

### 4.4 前端显示（能否达到预期）

- 手机页：卡片列表顶部加 chips「全部 / 我的 / 共享」
- PC 三科页（VTJ）：同 chips 需你在设计器拖（B5）
- 「我的」页：新增「我的资料卡」入口（列表复用现有卡片组件）

### 4.5 测试

- 学生建卡 → 别人 `GET /api/materials?subject=xingce&type=card` **看不到**（`status=2`）
- 学生改他人卡 → 403
- 管理员改任意卡 → 200
- 建卡缺 `card_front` → 400

## 5. B2：分享与领取（复制语义）

### 5.1 为什么是"复制"而不是"引用"

引用会让源卡的修改影响所有领取者的学习进度与笔记；复制后各自独立演进，且**领取者可再编辑**。溯源靠 `source_material_id`。

### 5.2 数据模型

```sql
CREATE TABLE material_share (
  share_id      INTEGER PRIMARY KEY AUTOINCREMENT,
  material_id   INTEGER NOT NULL,              -- 源卡
  owner_id      INTEGER NOT NULL,              -- 分享者
  scope         TEXT NOT NULL DEFAULT 'public',-- public | org（预留）
  status        INTEGER NOT NULL DEFAULT 1,    -- 1 可领取 / 0 已撤回
  adopted_count INTEGER NOT NULL DEFAULT 0,
  create_time   DATETIME DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(material_id)
);
CREATE TABLE material_adopt_log (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  share_id    INTEGER NOT NULL,
  user_id     INTEGER NOT NULL,
  created_id  INTEGER NOT NULL,                -- 复制出的新卡
  create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(share_id, user_id)                    -- 每人每卡限领一次
);
```

### 5.3 接口

| 接口 | 方法 | 作用 | 权限 |
|---|---|---|---|
| `/api/materials/shared` | GET | 共享区列表（`material_share.status=1` join 卡片） | 登录 |
| `/api/materials/{id}/share` | POST | 分享（`creator_id==me` 才可；`status→1`） | 仅创建者 |
| `/api/materials/{id}/unshare` | POST | 撤回（`material_share.status=0`） | 仅分享者或管理员 |
| `/api/materials/{id}/adopt` | POST | 收进我的库（复制一条，`status=2`，`source_material_id=id`） | 登录 |

**adopt 事务边界**：校验 share 有效 → 唯一日志插入（重复则 409）→ 复制卡片 → `adopted_count+1` → 同一 commit。任一步失败整体回滚。

### 5.4 安全

- 越权：分享/撤回仅 `owner_id`；adopt 校验 `material_share.status=1` 且源卡未被删
- 刷量：adopt 唯一索引天然防重复；`adopted_count` 只增，不做"取消领取"
- XSS：复制时**再跑一次** `sanitize_html`（源卡可能来自低权限用户）

## 6. B3：配图卡与上传接口

### 6.1 结论：**不加表字段**（除 B1 的 `source_material_id`）

封面 → `cover_image`；正文图示 → `content` 内 `<img src="/uploads/materials/images/...">`（`material_sanitizer` 白名单已允许 `img` 且仅 `/uploads/`）。

### 6.2 接口

| 接口 | 变化 |
|---|---|
| `POST /api/materials/admin/upload/image` | 增可选 `purpose=cover\|inline`（仅影响返回的元信息，不影响落盘） |
| `POST /api/materials/admin/cards/batch-image` | **新增**：一次 ≤9 张，原子校验（任一不合格整批拒） |
| `POST /api/materials/admin/import/upload` + confirm | `column_mapping` 增可选 `cover`（列值必须是 `/uploads/...` 或 http(s)） |

### 6.3 前端渲染规则

- 正文第一个 `<img>` 渲染为「图示区」：高 `120–160px`、圆角 12、点击放大（灯箱）
- 无图 → 图示区**自动收起**（不留白）
- 图示区之上是标题、之下是正文（行测判断推理/资料分析、公专场景图适用）

### 6.4 安全

- 复用 `_safe_image_upload`：扩展名白名单 + 5MB + 魔数校验 + uuid 重命名（**不使用原始文件名**）
- `column_mapping.cover` 只接受 `/uploads/` 前缀或 http(s)，其余丢弃并记 `invalid_cover` 计数

## 7. B4：手机端卡片栈（我能独立交付）

### 7.1 组件结构（手写页，可改 template）

```html
<div class="card-stack" :style="stackStyle">
  <div v-for="(c, i) in visible" :key="c.id" :class="['card', `card-${i+1}`]">
    <div class="card-inner" @click="flip(i)">
      <div class="card-face front">…</div>
      <div class="card-face back">…</div>
    </div>
  </div>
</div>
```

### 7.2 关键实现（对齐 v5 设计）

| 项 | 实现 |
|---|---|
| 堆叠 | 后 4 层 `translate(11px*n, -15px*n)` + `scale(1-0.012n)`，`z-index` 递减，投影递减 |
| 3D tilt | `pointermove` → `--tx/--ty`（±6°/±8°），rAF 节流；`pointerleave` 240ms 回正 |
| 层间视差 | 后层额外 `translateX(2/4/6/8%)`（差速） |
| 翻转 | `.card-inner { transform-style: preserve-3d }` + `rotateY(180deg)`，0.4s |
| 四阶段 | A 上浮 0.25s → B 翻转 0.4s → C 停留（按钮变「再翻一遍」）→ D 沉底 0.35s |
| 字号 | 根变量 `--sm-font-scale`（0.9/1.0/1.15/1.3），正文 `clamp()` |
| 降级 | `prefers-reduced-motion` / `hardwareConcurrency≤4` / 无 hover → 关 tilt，保留层叠与翻转 |
| 性能 | 只动 `transform/opacity`；`will-change` 仅主卡；首屏渲染 ≤ 5 层 |

### 7.3 无障碍

- 卡片 `role="button"` `tabindex="0"`，`Enter/Space` 翻转，`←/→` 切换
- 翻转态用 `aria-pressed`；背面内容通过 `aria-live="polite"` 播报

## 12. 风险登记册

| ID | 风险 | 影响 | 处方 |
|---|---|---|---|
| **R-1** | **全局去重会把他人私有卡当作重复**（`material_deduplicator:74` 用 `status >= 0`） | 别人无法创建与你私有卡同内容；且泄露"存在相同内容"的信息 | 去重范围改为 `status != 2 OR creator_id == 当前用户`；**必须与 B1 同批上线** |
| R-2 | `status=2` 被既有查询误纳入 | 私有卡泄漏到公共列表 | 所有公共查询已硬编码 `==1`（实测 6 处），加回归测试断言泄漏为 0 |
| R-3 | 新端点触碰 R11（343 冻结） | 违规 | 新增端点需你显式批准（Q3）；并提供 `api_surface.json` 差异报告 |
| R-4 | 复制卡导致内容重复膨胀 | 库变大、去重紊乱 | 复制时重算 `content_hash` 并写 `source_material_id`，去重排除"自己复制自己" |
| R-5 | 手机端 3D 在低端机卡顿 | 体验差 | tilt 可用 `hardwareConcurrency` 关闭；翻转仅 `transform` |
| R-6 | 图示区无图仍占位 | 版面空洞 | 无 `<img>` 时 `display:none`，已写入 B3 §6.3 |
