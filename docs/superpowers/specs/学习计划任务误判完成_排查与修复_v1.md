# AI 学习计划任务「没做却显示 100%」排查与修复 v1

- 日期：2026-11-23
- 反馈：秉瑞 —— 「AI 学习计划生成的自定义任务有点异常，任务根本没做却显示完成度 100%」
- 影响面：学习计划（模块4）的任务进度与金币发放；不涉及题库、考试、论坛等域
- 结论：**三层原因叠加**，已修复代码 + 提供历史数据回退脚本 + 修正显示文案

---

## 一、现象

任务列表（`/tasks` → `goal_card.vue`「自定义任务」tab）里，AI 学习计划生成的任务
（如「[睡前] 错题复盘-当日行测错题归类+公式/技巧默写」「[晚上] 申论-归纳概括-1道真题+范文精读1篇」）
显示 **已完成 / 完成进度 100% / 完成题目数量 1/1**，但用户并没有做。

同时「完成时间」一栏显示的是「3天4时4分 / 82天4时4分」这种**倒计时**，与"完成时间"语义不符。

---

## 二、根因（逐层定位）

### 1) 进度同步把「AI 计划任务」当成了「每日刷题目标」

`backend/app/services/goal_progress.py` 的 `sync_goal_progress()` 在每次刷题记录写入后被调用
（`api/v1/exam/practice.py:109`、`:177`），原逻辑：

```python
ranges = {"DAILY": (today, today), "CUSTOM": (today, today), "WEEKLY": ..., "MONTHLY": ...}
...
count, seconds = _resolve_by_subject(tables[gtype], goal.subject_mode or 0)
new_count = min(count, goal.target_count)
if new_count >= goal.target_count: goal.is_completed = 1 ...
```

而 AI 学习计划写入的任务是（`api/v1/growth/study_plan.py` 生成段）：

```python
goal = StudyGoal(goal_type="CUSTOM", target_count=1, current_count=0, plan_id=plan_id, ...)
```

于是 **CUSTOM + target_count=1 + 按当天刷题量** 三者叠加：用户当天随手做 **1 道题**（任何科目、任何题），
该计划任务的 `current_count` 就被算成 1 ≥ target 1 → 标记完成、写 `completed_time`、发金币。
这就是「任务根本没做却 100%」的直接原因。

### 2) 单位错配：语义任务 vs 题量目标

AI 计划任务是「写完一篇作文 / 复盘一次错题」这类**语义任务**，用人头算「做没做」；
而 `target_count` 与 `current_count` 的语义是**题量**。两者用同一套字段且 target=1 时必然误判。

### 3) 显示文案把"剩余时间"标成"完成时间"

`.vtj/vue/goal_card.vue:55-60`：

```html
<span class="deadline-label">完成时间</span>
<span class="deadline-countdown">{{ getDeadlineCountdown(goal.deadline).text }}</span>  <!-- 其实是"还剩多久" -->
```

已完成的也不显示真实 `completed_time`，所以出现「完成时间 82天4时4分」这种自相矛盾的展示。

---

## 三、修复

| # | 文件 | 改动 |
|---|---|---|
| 1 | `backend/app/services/goal_progress.py` | `sync_goal_progress` 查询目标时增加 `StudyGoal.plan_id.is_(None)`：**计划任务（plan_id 非空）只由用户勾选完成，不再被刷题量推进**；手动创建的自定义目标（plan_id 为空）保持原「按刷题量推进」逻辑 |
| 2 | `backend/app/api/v1/growth/study_plan.py` | `/plan/task/{id}/toggle` 完成时若 `target_count<=0` 自动补为 1，避免历史脏数据显示「已完成 0%」 |
| 3 | `backend/app/api/v1/growth/goals.py` | `compute_progress()`：`target_count<=0` 且已完成 → 返回 100.0（而不是 0.0） |
| 4 | `.vtj/vue/goal_card.vue` | 未完成显示「剩余时间 + 倒计时 + 结束时间」；已完成显示「完成时间 + completed_time + 结束时间」 |

### 历史数据回退脚本

`backend/scripts/fix_plan_task_false_completion.py`（默认 dry-run）：

```powershell
cd backend
python scripts/fix_plan_task_false_completion.py              # 只看，不改
python scripts/fix_plan_task_false_completion.py --days 7     # 范围
python scripts/fix_plan_task_false_completion.py --apply      # 执行
```

口径：只回退 `plan_id 非空 + status=1 + is_completed=1 + target_count<=1` 的计划任务
（`is_completed=0 / current_count=0 / completed_time=None / reward_coins=0 / coin_claimed=0`）；
**不回收已发金币**，脚本会打印领取情况供人工判断。

### 验证时又发现并修掉的一个连带 bug（同一处修复提交）

首轮冒烟时首页整体白屏，报错：

```
⚠️ 模块加载失败 Cannot read properties of null (reading 'toLowerCase')
```

定位：`.vtj/vue/goal_card.vue:35` 的 `goal.goal_type.toLowerCase()` 在 `goal_type` 为 null 的历史数据上直接抛错，
**一条脏数据会让整个任务列表（乃至首页）渲染失败**。已改为 `(goal.goal_type || 'custom').toLowerCase()`。
