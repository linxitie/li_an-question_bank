# 教师账号 ycc5678 无法登录 排查报告

- 日期：2026-11-01
- 现象：教师端账号 `ycc5678 / ycc5678` 登录失败，提示「用户名不存在: ycc5678」；管理员 `cbrycc` 正常
- 结论：**账号数据被改，不是登录代码被改坏**。`sys_user.username` 被从 `ycc5678` 改成了中文姓名 `琳叵贴`，而登录接口只按 `username` / `phone` 匹配，于是账号编号登录全部失败

## 1. 现场证据

| 检查项 | 结果 |
|---|---|
| `POST /api/auth/login`（ycc5678/ycc5678） | 401 `用户名不存在: ycc5678` |
| `POST /api/auth/login`（cbrycc/cbrycc） | 200，正常 |
| 数据库中该账号 | `user_id=3, user_no='ycc5678', username='琳叵贴', user_type='teacher', status=1, is_disabled=0` |
| 密码哈希校验 | `bcrypt.checkpw('ycc5678', hash)` → **True**（密码从未被改） |
| `register_time` | `2026-07-11 19:01:23`（账号是原始种子账号，没有被重建） |

备份对比（同一行 `user_id=3`，密码哈希与注册时间完全一致）：

| 数据库文件 | mtime | username |
|---|---|---|
| `question_bank.db.bak_taxonomy_v2_20261024_221259` | 2026-10-24 | `ycc5678` |
| `question_bank_guard_snapshot_20261025_112956` | 2026-10-25 | `ycc5678` |
| `question_bank.precount_repair_20261026_205007` | 2026-10-26 | `ycc5678` |
| 当前 `question_bank.db` | 2026-11-01 | **`琳叵贴`** |

→ 只有 `username` 一个字段被 UPDATE，其余字段未变；改动发生在 **2026-10-26 20:50 之后**。

## 2. 责任归属判断（是伙伴改动还是其他原因）

**不是登录代码回归。** 证据：

- `backend/app/api/v1/identity/auth.py` 的登录查询自文件创建起就是 `username` 或 `phone` 两个条件（`git log -L` 可查，最早见的版本即如此），本次修复前没有任何提交加过 `user_no` 匹配；
- 全仓库 `backend/app` 内没有任何代码对 `SysUser.username` 赋值（`grep -rn "\.username\s*=" backend/app` 为空），即应用接口本身改不了登录名；
- 事故前 2026-10-31 09:07 我用同一账号实测登录成功（教师端论坛返回 200），说明当时 `username` 仍是 `ycc5678`。

**是数据库里这一行账号数据被改。** 时间窗口（10-26 20:50 ~ 11-01）内，本机库经历了教师端整改（`17a7d31`、`a97bfa7` 等）与容器化 P1–P6 的联调、以及多次 `origin/main` 合并。`sys_operation_log` 最后一条停在 2026-10-13，**没有记录这次改动**，因此无法从日志指认具体操作人/脚本；但可以确定：

- 改动只影响 `user_id=3` 的 `username` 字段，是同一条源数据行上的就地更新；
- 仓库内已提交的脚本（`seed.py` 使用的正是 `username='ycc5678'`、`clean_test_users.py` 只删除 `FNL001/yyc5678`）都不会产生中文姓名；
- 因此更可能是**一次性数据修正/手工改库**（把教师登录名换成了真实姓名），而不是代码合并直接导致。

置信度：字段被改 = 100%（有备份对照）；“由哪次操作改的” = 无法确证（日志缺失），仅能排除登录代码回归与已提交脚本。

## 3. 修复

### 3.1 数据修复（立即恢复登录）

先用 `sqlite3.backup()` 做一致性快照（遵守 R10，未使用文件拷贝）：

```
backend/data/question_bank.pre_teacher_login_20261101_092204.db   # 61,054,976 B
```

```sql
UPDATE sys_user
   SET username = 'ycc5678'
 WHERE user_id = 3 AND user_no = 'ycc5678';
-- rows updated: 1
```

### 3.2 代码加固（防止再次发生）

`backend/app/api/v1/identity/auth.py` 登录查询加入 `user_no`：

```python
user = db.query(SysUser).filter(
    (SysUser.username == form_data.username) |
    (SysUser.user_no == form_data.username) |
    (SysUser.phone == form_data.username)
).first()
```

理由：`user_no` 是账号真正的唯一编号（学号/工号），展示名 `username` 不该承担登录职责。即便以后再有“把 username 改成真实姓名”的数据操作，账号编号依然可登录。

### 3.3 回归测试

新增 `backend/tests/test_login_identifier.py`（5 条，含事故复现）：

- 按 `username` 登录 → 200
- 按 `user_no` 登录（`test001` 与 `username` 不同）→ 200
- 按 `phone` 登录 → 200
- **事故复现**：`user_no='ycc5678'` + `username='琳叵贴'` 的教师，用 `ycc5678` 登录 → 200，`user_type='teacher'`
- 错误密码仍被拒 → 400/401

`pytest tests/test_login_identifier.py tests/test_identity_module.py` → **14 passed**
