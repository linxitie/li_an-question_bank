## 3. 写入链路：题目状态如何被更新（回答"会保证更新到每一题吗"）

`POST /api/practice/batch-record` → `submit_answers()`（`backend/app/services/practice_grading.py:183`）→ 逐题 `_grade_item()`（`:135`）：

1. `is_correct = grade_answer(question.answer, user_answer)`（`:150`）——**服务端按标准答案重判**，客户端传来的 `is_correct` 只在答案为空时兜底（`:147-148`）。
2. `db.add(PracticeRecord(...))`（`:153-165`）+ `db.flush()`——**追加式写入，一题一行，不去重**。
3. 错题走 `upsert_wrong_question()`（`:81`），命中已有则 `error_count += 1`、`review_count += 1`、更新 `last_review_time`（`:104-109`）。
4. 事务提交 `commit_with_retry(db)`（`:252`），随后：`sync_goal_progress`（答题目标进度）、`_broadcast_personal_sync`（**只广播给本人**，含统计量不含题干）、Outbox 事件 E1/E2（`:233`、`:300`，`session_id` 去重见 `_record_session_published`）。

结论：**每一题的状态确实会被逐题更新**（题目类型进度、知识点进度、错题本、正确率、目标进度都从 `practice_record` 派生）。但因为是追加式，**同一题重复提交会重复计数**——这是续答功能必须规避的点（§5 风险 R1）。

## 4. 新增契约（3 个只读端点 + 0 个写端点）

### 4.1 `GET /api/exams/records/{record_id}/resume`
放在 `backend/app/api/v1/exam/exams.py`（与既有 `GET /api/exams/records/{record_id}`（`:490`）同前缀）。

- 鉴权：`get_current_user`，且 `record.user_id == 当前用户`，否则 403/404。
- 返回：
```json
{"record_id": 1, "paper_id": 2, "paper_name": "2025 安徽行测", "status": "in_progress",
 "remaining_seconds": 3600, "saved_answers": {"12": "A", "15": "B"},
 "questions": [{"question_id": 12, "type_id": 1, "content": "...", "options": [...], "group_id": 0}]}
```
- 题源：`PaperQuestionRelation` 关联的题（按原卷顺序）；`saved_answers` 来自 `ExamAnswerDetail`。
- 若 `record.status != 'in_progress'` → 409 `该记录已完成`；若无 `PaperQuestionRelation` → 404 `该试卷暂无题目`（与 `GET /api/exams/{paper_id}/questions`（`:128-227`）同语义）。
- 需在 `exam_records.py`/`exams.py` 补导入：`PaperQuestionRelation`、`is_subjective_question`。

### 4.2 `GET /api/stats/subject-distribution`
- 返回 `{items:[{subject_id, subject_name, subject_code, total, correct, wrong, accuracy}]}`。
- 单条 SQL：`SELECT subject_id, COUNT(*), SUM(is_correct) FROM practice_record WHERE user_id=? GROUP BY subject_id`，再补名称。
- 下限保护：`total < 1` 的科目不返回，避免饼图出现 0 值扇区。

### 4.3 `GET /api/wrong-questions/point-stats?limit=10&subject_id=`
- 返回 `{items:[{point_id, point_name, wrong_count, total, wrong_rate}]}`，按 `wrong_count` 降序。
- 数据源：`WrongQuestionPersonal` ⋈ `QuestionBank`（子科目文本列 `xingce_subcategory`/`shenlun_subcategory`/`gongzhuan_subcategory`，与 `wrong_questions.py:302-312` `_get_subcategory()` 同口径）——**不依赖 `question_bank.sub_category_id`**（该列实测缺失，判定不补，见 §7）。

## 5. 风险与对策

- **R1 重复计数**：resume 页打开后，只提交「本次新作答的题」，已答过且答案未变的题不再提交；后端在 `_grade_item` **不新增**去重逻辑（不改既有写路径），由前端 `dirtyQuestions` 集合保证。若用户改答案后再次提交，视为一次新的作答（与现有快速练习一致）。
- **R2 静默空白**：`paper_answer.vue:315-318` 非 200 只 `console.error`。resume 调用失败必须给出可见提示（跳回列表 + toast）。
- **R3 进度丢失**：`paper_answer.vue` 已有 localStorage 进度（key `paper_progress_<recordId>`，`:311` 恢复、`:754` 保存、`:761` 读取、`:901` 交卷清除）；`.vtj/vue/answer_page.vue` **没有** localStorage——它的「保存并退出」弹窗是空承诺，需按同一 key 模式补本地草稿（只改 script）。
- **R4 设计器覆盖**：`navbar.vue` 的修复写在 `<script>`，设计器保存可能覆盖；本方案的 `.vtj` 改动一律 script-only，并在交付说明里标注。

## 13. 上线存储架构（回答 Q16 的延伸问题）

- **不要以“用户端保存”为主存储**：换设备即丢、无法统计/风控/补发，用户端只能做缓存。
- **分层**：
  | 数据 | 位置 | 现在 | 上线后 |
  |---|---|---|---|
  | 题目/账号/记录（结构化） | 服务端关系库 | SQLite（WAL，46.52 MB 主库） | MySQL 8 / PostgreSQL 16（`DB_TYPE` 已预留 `mysql+pymysql`，`config.py:221-225`） |
  | 题目图片 4.3 GB、PDF 语料 662 MB | 对象存储 + CDN | `backend/app/static/`（红线 R7 禁删） | MinIO / OSS / COS，本地保留 fallback |
  | 练习/考试记录（年增亿级） | 分区表 + 预聚合 | 单表 | 按月分区 + `daily_stats` 预聚合表 |
- **增长估算**：1 万用户 × 每天 50 题 = 500 万行/天；单行约 200 B → 约 1 GB/天、365 GB/年 → 必须分区 + 冷热分离（>1 年归档 Parquet/对象存储）。
- **草稿不进主记录表**：草稿是“未完成的中间态”，写 `practice_draft` 且带 TTL，避免污染 `practice_record` 统计口径。

## 14. `practice_draft` 表（Q16 选 B 的落地方案）

```
practice_draft
  draft_id      INTEGER PK AUTOINCREMENT
  user_id       BIGINT  NOT NULL  FK sys_user.user_id
  scope         VARCHAR(20)  NOT NULL   -- type | subject | paper
  scope_key     VARCHAR(100) NOT NULL   -- 如 "1:12"（subject_id:type_id）
  questions     TEXT     -- JSON [question_id, ...]，最多 200 条
  answers       TEXT     -- JSON {"12":"A"}，最多 64 KB
  cursor        INTEGER DEFAULT 0
  created_at    DATETIME
  updated_at    DATETIME
  expires_at    DATETIME
  UNIQUE(user_id, scope, scope_key)
  INDEX(expires_at)
```

- 写入 `POST /api/practice/draft`（upsert，按唯一键）；读取 `GET /api/practice/draft?scope=&scope_key=`；交卷后 `DELETE`。
- TTL 30 天；清理挂在既有 apscheduler 每日任务里（与“每日清理过期斩题”并列）。
- 建表由 `backend/app/main.py:117` `Base.metadata.create_all(bind=engine)` 启动幂等完成，**无需手工 DDL**；正式上线前按 R10 用 `sqlite3.backup()` 备份一次再启动。
- 试卷型未完成不走此表：直接复用 `exam_record.is_completed=0` + `exam_answer_detail`（`start_exam` 已支持复用未完成记录）。

### 15.2 实现期发现并修正的 3 个缺陷（原方案未预见）

1. **草稿保存恒 400**：`practice.py` 原先只接受**题目 ID 数组**（`[int(q) for q in questions]`），而练习页上送的是**完整题目对象**，`int(dict)` 抛 `TypeError` 被转成 400 且前端只打 console → 「继续上次练习」永不出现。改为两种存法都接受；前端 `resumeDraft()` 过滤掉裸 ID 数组（无题干无法渲染），回退到正常抽题。
2. **`Enum` 折列被误判**：`case()` 合并 `xingce/shenlun/gongzhuan_subcategory` 三列时结果类型被判为公专枚举，行测值触发校验 → 500。三处改 `cast(col, String)`；`models.py` 的枚举本身正确，勿改。
3. **`question_bank.sub_category_id` 缺列**：题库/快速练习/`type-summary` 全部 500。`main.py:324-359` 启动幂等迁移补列并按子科目名回填（匹配不到留 NULL，不写「无」）。
