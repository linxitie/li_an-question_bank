# 题目入库知识图谱与四库映射 v1

> 状态：**P0 设计已批准；P1 图片资产登记已实施（2026-10-30）**
> 日期：2026-10-29（P1 更新：2026-10-30）
> 分支：`feat/teacher-administrator`
> 关联：`docs/superpowers/specs/砺安题库终态总体架构_v2.0.md`、`docs/superpowers/specs/题库设计模式_v3.md`、`docs/superpowers/plans/复合题材料与答题页滚动修复方案_v1.md`
> 原则：**SQLite 仍是唯一事实源（SoT）；关系库、图片库、图库、文档库、向量库都是可重建投影。**
> 范围：题目域（题干/选项/答案/解析/题组材料/子题/图片/导入批次），不改答题页与教师端现有读路径。

---

## 0. 结论摘要

当前系统并不缺“四库”底座：F3 已有 `media_assets` 与对象存储，F4 已有文档投影，F5 已有图投影，F6 已有向量投影。真正缺的是**题目域的知识图谱本体**：

1. 图投影只有 `KnowledgePoint` 与 `Question`，**没有 `QuestionGroup`、材料图、题目图片、导入批次**；
2. `media_assets` 实测 **0 行**，题目图片仍只以 `<img src="/static/...">` 字符串散落在正文里，图片库没有“资产—题目—材料”的边；
3. 文档库只有 `exam_resources/import_snapshots/forum_contents`，**没有题目/题组文档集合**；
4. 向量库只索引题干（3122 题），**没有材料向量**，复合题检索会退化成“只命中子题”；
5. 导入管线已经能建组、回填材料、保留图片占位，但缺少一份**统一的 canonical 映射与入库闸门**，导致“题组关联”只能靠修复脚本事后补。

本设计把题目域从“题干单点”升级为 **六元组**：

```text
导入批次(ImportBatch) → 题组(QuestionGroup) → 材料/图片(MediaAsset)
                              ↓ HAS_MEMBER
                         子题(Question) → 知识点(KnowledgePoint)
                              ↓ HAS_*_IMAGE
                         题干/选项/解析图片(MediaAsset)
```

**不新增业务事实表**；只补图节点/边、文档集合、向量集合、图片资产登记与入库闸门。所有投影可用脚本从 SQLite 重建，失败可关闭开关回退。

## 2. 根因：不是“库不够”，而是“本体没定义”

| # | 根因 | 直接后果 |
|---|---|---|
| R1 | 图本体只定义 KnowledgePoint/Question | 题组与材料无法被图查询，智能组卷/推荐只能靠 `group_id` 硬编码 |
| R2 | 图片没有资产 ID 与归属边 | 无法回答“这道题/这个组引用了哪些图、哪些图缺失、哪些图重复” |
| R3 | 文档库没有题目/题组集合 | 题目全文检索只能回关系库；材料与子题无法作为一个文档整体被消费 |
| R4 | 向量只索引题干 | 复合题按“材料语义”检索时命中率低；材料重复题无法聚合 |
| R5 | 导入管线缺少 canonical ID 与统一闸门 | 每次修复靠脚本补组，容易出现“组建立了但材料没回填/图片没登记” |
| R6 | 没有投影对账口径 | 四库与 SoT 漂移无法被门禁发现 |

## 3. 设计原则

1. **单一事实源**：题目正文、选项、答案、解析、组材料、组成员只以 SQLite 为准。
2. **投影可重建**：图/文档/向量/图片元数据都可由脚本从 SoT 重建；禁止把投影当第二事实源。
3. **ID 稳定**：题目 `question_id`、题组 `question_groups.id`、导入 `import_id` 永不复用；图片以内容哈希为主键。
4. **完整性优先于抽取精度**：命中题组必须整组入库/整组组卷；材料缺失时保留组关系并标 `need_review`，不静默拆组。
5. **不移动存量文件**：题图继续由 `/static/...` 提供；对象存储只做可选副本，不改变现有 URL。
6. **零 raw 模板改动**：本设计只改后端/脚本/投影，不触碰 `.vtj/vue/*.vue` 的 `<template>`。

## 4. Canonical ID 与键

| 实体 | 键 | 规则 |
|---|---|---|
| Question | `q:<question_id>` | 图节点沿用现有 `Question.key=str(question_id)`，不破坏 F5 数据 |
| QuestionGroup | `g:<id>` | 新增图节点 |
| MediaAsset | `m:<sha256>` | 同一图片多题引用只建一个节点 |
| ImportBatch | `i:<source_table>:<import_id>` | 新增图节点；无可靠关联时不建边 |
| KnowledgePoint | `kp:<point_id>` | 现有图节点 key 为 `str(point_id)`，新增边沿用 |
| 文档 | `urn:li-an:<collection>:<key>` | 沿用 F4 envelope |

> 兼容策略：已有 `Question`/`KnowledgePoint` 节点 key 不改；新标签使用带前缀的 key，避免与旧 key 冲突。

## 5. 四库职责与映射

| 库 | 角色 | 题目域落点 | 是否事实源 |
|---|---|---|---|
| 关系库 SQLite | 唯一 SoT | `question_bank`、`question_groups`、`question_knowledge`、`question_import_record` | ✅ 是 |
| 图片库 | 资产台账 + 对象存储 | `media_assets` + `/static/...` + 可选 object store | ❌ 元数据可重建 |
| 图库 | 关系网络 | `foundation_graph_node/edge`（local/Neo4j） | ❌ 投影 |
| 文档库 | 聚合读模型 | `question_documents`、`group_documents`、`import_snapshots`、`exam_resources` | ❌ 投影 |
| 向量库 | 语义索引 | `text_questions`、`text_materials` | ❌ 投影 |

### 5.1 关系库字段映射

| 图谱字段 | 来源 |
|---|---|
| 题目身份 | `question_bank.question_id` |
| 科目/题型 | `subject_id` / `type_id` |
| 子科目 | `sub_category_id` + `xingce_subcategory` / `shenlun_subcategory` / `gongzhuan_subcategory` |
| 题组 | `question_bank.group_id` → `question_groups.id` |
| 组内层级/顺序 | `question_level` / `sort_order` / `question_number` |
| 材料 | `question_groups.shared_content` |
| 材料图 | `question_groups.shared_content_images` + 正文 `<img>/[IMAGE:]` |
| 题干/选项/解析图 | `question_content` / `options` / `answer_analysis` 中的 `<img>`、`[IMAGE:]` |
| 审核 | `status` / `audit_status` / `need_review` |
| 导入批次 | `question_import_record.import_id` + `preview_data.items[].question_id` |

## 6. 图模型（新增节点与边）

### 6.1 节点

| label | key | 必要 props | 来源 |
|---|---|---|---|
| `QuestionGroup` | `g:<id>` | groupType, subject, difficulty, title, memberCount, imageCount, contentHash | `question_groups` |
| `Question` | `str(question_id)` | questionId, subjectId, typeId, subCategoryId, status, difficulty, auditStatus, groupId, questionLevel, sortOrder, questionNumber, needReview, hasMaterial, year, source | `question_bank` |
| `MediaAsset` | `m:<sha256>` | assetId, sha256, objectKey, contentType, kind, sizeBytes, origin | `media_assets` + 引用扫描 |
| `ImportBatch` | `i:<source_table>:<import_id>` | importId, sourceTable, status, totalQuestions, successCount, duplicateCount | `question_import_record` |
| `KnowledgePoint` | `str(point_id)` | 沿用 F5 | `knowledge_point` |

### 6.2 边

| rel | src → dst | 来源/条件 | 不变量 |
|---|---|---|---|
| `HAS_MEMBER` | QuestionGroup → Question | `q.group_id=g.id` | 每题最多 1 个组；组内成员 `sort_order` 唯一 |
| `HAS_MATERIAL_IMAGE` | QuestionGroup → MediaAsset | 组材料正文/图片列表 | 同一组同一图只 1 条边 |
| `HAS_STEM_IMAGE` | Question → MediaAsset | 题干引用 | 记录引用位置 `loc=stem` |
| `HAS_OPTION_IMAGE` | Question → MediaAsset | 选项引用 | props 带 `optionKey` |
| `HAS_ANALYSIS_IMAGE` | Question → MediaAsset | 解析引用 | 记录 `loc=analysis` |
| `IMPORTED` | ImportBatch → Question | preview 中有可靠 qid | 无可靠映射不建边，禁止猜测 |
| `IMPORTED_GROUP` | ImportBatch → QuestionGroup | 同批次建组 | 仅导入时明确的组 |
| 既有三类 | KnowledgePoint/Question | F5 先修/并行/实例化 | 保持原语义 |

### 6.3 图查询示例

1. **取整套复合题**：`g:34` 的 `HAS_MEMBER` 邻居，按 `sortOrder` 排序，再取每题的三个图片边。
2. **图片反查**：`m:<sha256>` 反向 `HAS_*_IMAGE`，得到引用它的题/组，用于重复图与缺失图治理。
3. **按材料找题**：`QuestionGroup` 的 `contentHash`/材料向量命中 → 展开全部成员，避免只返回一道子题。
4. **导入追溯**：`ImportBatch` → 题目/题组，定位某次导入产生的全部实体。

> 实现仍复用 `foundation_graph_node/edge` 的 `(label,key,props)` 与 `(rel,src,dst,props)`，不新增图数据库表；边写入前做幂等 upsert。

## 7. 文档库集合

### 7.1 新增 `question_documents`

一题一文档，供检索/导出/审计；**不替代关系库**。

```json
{
  "@context": {"@vocab": "https://li-an.local/schema/"},
  "@id": "urn:li-an:question_documents:q:4013",
  "@type": "QuestionDocument",
  "version": 1,
  "source": {"table": "question_bank", "id": 4013},
  "payload": {
    "questionId": 4013,
    "groupId": 34,
    "subjectId": 1,
    "typeId": 15,
    "subCategoryId": 12,
    "questionLevel": 2,
    "sortOrder": 5,
    "content": "题干富文本",
    "options": [{"key": "A", "value": "..."}],
    "answer": "D",
    "analysis": "解析富文本",
    "mediaRefs": [{"sha256": "...", "loc": "stem"}],
    "needReview": 0
  }
}
```

### 7.2 新增 `group_documents`

一组一文档，材料与成员作为一个整体被消费。

```json
{
  "@id": "urn:li-an:group_documents:g:34",
  "@type": "QuestionGroupDocument",
  "payload": {
    "groupId": 34,
    "groupType": "material",
    "subject": "行测",
    "difficulty": "3",
    "title": "根据以下资料，回答 126–130 题",
    "sharedContent": "材料富文本",
    "imageRefs": [{"sha256": "...", "url": "/static/question-groups/34/img_0.jpg"}],
    "memberIds": [4001, 4002, 4003, 4004, 4013],
    "memberCount": 5,
    "contentHash": "..."
  }
}
```

### 7.3 既有集合增量

| 集合 | 增量字段 | 目的 |
|---|---|---|
| `exam_resources` | `groupRefs`：`[{groupId, memberQuestionIds, score}]` | 智能组卷/试卷导出时整组还原 |
| `import_snapshots` | `canonicalRefs`：题目/题组 ID 列表 | 导入批次可追溯到具体实体 |

> 字段只增不删；旧文档缺字段视为 `[]`，不做破坏性迁移。

## 8. 向量库集合

### 8.1 `text_questions`（保留）

- id：`str(question_id)`（保持 F6 兼容，不改已有 id）。
- text：题干 +（可选）选项键值文本；**变更文本组成必须新建集合版本**，不能原地重写导致对账全漂移。
- meta 增补：`groupId`、`questionLevel`、`hasMaterial`、`needReview`、`subCategoryId`、`year`。
- 目的：题目语义检索；命中组内题时由上层按 `groupId` 展开整组。

### 8.2 `text_materials`（新增）

- id：`g:<groupId>`。
- text：`shared_content` 去标签后的纯文本；图片替换为 `[图片]`，避免空材料。
- meta：`groupId`、`groupType`、`subjectId`、`memberCount`、`imageCount`、`contentHash`。
- 目的：按材料语义检索题组；与 `text_questions` 结果做 RRF 合并，组命中优先整组展开。

### 8.3 检索约束

1. 材料命中 → 返回 `QuestionGroup` + 成员列表，不返回孤立子题。
2. 题目命中若 `groupId>0` → 自动补全同组上下文。
3. 向量命中只用于召回，最终可见性仍由关系库 `status/audit_status` 过滤。

## 9. 图片库（MediaAsset）

### 9.1 资产登记

扫描四类引用：

1. `question_bank.question_content`
2. `question_bank.options`
3. `question_bank.answer_analysis`
4. `question_groups.shared_content` + `shared_content_images`

每个引用解析为本地路径 → 计算 SHA-256 → 幂等写 `media_assets`：

| 字段 | 规则 |
|---|---|
| `asset_id` | UUID/短哈希；同 sha256 复用 |
| `sha256` | 物理内容哈希，唯一 |
| `object_key` | 相对路径（如 `questions/04108529_130_0.png`） |
| `size_bytes` / `content_type` | 文件实测 |
| `kind` | `question_stem` / `question_option` / `question_analysis` / `group_material` |
| `status` | `active` / `missing` / `tombstone` |
| `created_by` | 系统回填用 0 或管理员 ID |

### 9.2 URL 与存储

- 不移动 `app/static/`；现有 `/static/...` 保持 200。
- 对象存储（local/MinIO）只做可选副本：`object_key` 已存在则跳过。
- 缺失文件：登记 `status=missing`，题目标 `need_review=1`，前端继续走占位图，不阻断阅读。

### 9.3 去重

- 同 sha256 只建一条资产；多个题/组通过图边引用同一节点。
- 纯图片材料不按文本指纹跨组去重（2026-10-29 已修：图片 URL 变化会导致误并组），同组内按 sha256 去重。

## 10. 严格入库闸门

### 10.1 分类优先级

```text
源文件显式标签（科目/年份/卷名）
  > 解析器分段（资料一/材料二/题型）
  > 现有 FK（subject_id/type_id/sub_category_id）
  > 规则推断（仅补空值，不覆盖显式值）
  > 未知 → need_review=1
```

禁止：
- 用题干长度猜科目；
- 用答案反推题型；
- 把无法确认的材料强行挂到相邻组；
- 跨科目共用一个 `QuestionGroup`。

### 10.2 闸门表

| 闸门 | 检查 | 级别 | 失败动作 |
|---|---|---|---|
| G0 | 导入批次、源文件、科目可识别 | 硬 | 拒绝入库 |
| G1 | `group_id` 指向存在的组；组不跨科目 | 硬 | 拒绝整组入库 |
| G2 | 组成员 `question_id` 唯一、`sort_order` 唯一 | 硬 | 拒绝整组入库 |
| G3 | 题号范围内成员连续；组内成员数在 [2,6]（行测资料分析） | 软 | 建组 + `need_review` |
| G4 | 材料非空或图片非空；图片可解析 | 软 | 建组 + `need_review`，缺图标 missing |
| G5 | 选项 JSON 可解析；key 唯一且 A–D；答案非空 | 软 | 入库 + `need_review` |
| G6 | 解析图/公式图可解析；重复图去重 | 软 | 占位 + `need_review` |
| G7 | 去重指纹（题干 + 选项 + 材料）稳定 | 硬 | 阻止重复建题 |
| G8 | 投影事件可投递；投影幂等 | 软 | 记录待重建，不阻断业务写入 |

**完整性优先**：G3/G4 失败仍保留组关系（P5 已验证），避免“材料缺失 → 子题被拆散”。

### 10.3 去重指纹

```text
fingerprint = sha256(
  normalize(subject_id, type_id, question_number)
  + normalize(question_content 去图片/空白)
  + normalize(options 按 key 排序)
  + normalize(group material 去图片/空白)
)
```

- 纯图片材料：材料指纹为空，**不参与跨组去重**（沿用 2026-10-29 修复）。
- 同一批次内题干相同但组不同：视为不同题，保留并标 `need_review`。

## 11. 入库管线（事务边界）

```text
A 解析 → B 规范化 → C 闸门 → D 关系库事务写入 → E Outbox 事件 → F 四库投影 → G 对账
```

| 阶段 | 产物 | 失败处理 |
|---|---|---|
| A 解析 | blocks + material_text + image markers | 解析失败整批 rejected |
| B 规范化 | 题组草案、成员、选项 key、图片引用 | 无法归组 → 独立题 |
| C 闸门 | G0–G8 报告 | 硬失败回滚整批；软失败写 `need_review` |
| D 写入 | `question_groups`、`question_bank`、`media_assets` | 单事务；组与成员同生同灭 |
| E 事件 | `question.imported` / `group.updated` | Outbox 同事务，失败可重放 |
| F 投影 | 图/文档/向量 | 幂等 upsert；失败进待重建队列 |
| G 对账 | 计数/哈希/边数 | 漂移 > 0 报警，不自动删除 |

**幂等键**：`import_id + question_number + fingerprint`；重复执行只更新不新增。

## 12. 分阶段实施

| 阶段 | 内容 | 产物 | 验收 |
|---|---|---|---|
| P0 | 只读盘点与设计（本文） | 基线计数、本体定义 | 用户批准 |
| P1 | 图片资产登记 | 扫描脚本 + `media_assets` 回填 + missing 清单 | 引用可解析率 ≥ 99%；缺失全部标 `missing` |
| P2 | 图投影扩展 | `QuestionGroup/MediaAsset/ImportBatch` 节点 + 5 类边 | 图计数 = SQL 计数；二次回填写入 0 |
| P3 | 文档集合 | `question_documents` / `group_documents` + 回填 | drift=0；单文档 ≤ 8 MiB |

## 14. 风险与回滚

| 风险 | 缓解 |
|---|---|
| 图片 SHA 计算耗时/大文件 | 只处理题目引用文件；批量限流；失败跳过并记 missing |
| 图节点 key 冲突 | 新标签前缀 `g:/m:/i:`；旧 Question/KP key 不改 |
| 投影写放大 | 仅变更实体增量投影；全量回填按批提交 |
| 材料去重误并组 | 纯图片材料不跨组去重；材料哈希带 groupType/subject |
| 文档库重复事实源 | 文档只读投影；写入仍走 SQLite；文档带 `source` |
| 向量模型不可用 | `VECTOR_BACKEND=off` 默认降级；不阻塞主链路 |
| 回滚 | 关闭 `GRAPH_STORE_ENABLED/DOC_STORE_ENABLED/VECTOR_STORE_ENABLED`；删除投影集合；关系库不动 |
