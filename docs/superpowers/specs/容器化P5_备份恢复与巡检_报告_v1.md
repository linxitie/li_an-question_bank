## 1. 结论

P5 把“容器会消失、数据必须有家”落成可执行脚本，而不是只写文档：

1. `deploy/checkpoint.sh` 发布前强制 `PRAGMA wal_checkpoint(FULL)`，busy 非 0 直接失败。
2. `deploy/backup.sh` 用 `scripts/admin/backup_db.py`（`sqlite3.backup()`）生成一致性备份，附 `.sha256`、manifest、`latest.json`；支持资产副本、异地副本与 `--no-checkpoint`。
3. `deploy/restore.sh` 先 dry-run 校验，再停 backend、覆盖主库、自动起服务并做 `/health` + 四表计数烟测；覆盖前自动快照。
4. `deploy/inspect.sh` 检查容器、三个健康端点、磁盘、备份年龄、`integrity_check`、日志体积；有 FAIL 返回 1，可直接接 cron/systemd。
5. `.github/workflows/container-ci.yml` 提供测试、镜像构建、tag 发布三档，parser 镜像只在手动触发时构建。

## 3. 关键设计

- **R10 合规**：数据库备份只走 `sqlite3.backup()`（`backend/scripts/admin/backup_db.py`），不使用 `cp`/`shutil.copy2` 备份主库。
- **WAL 先行**：`backup.sh` 默认先调 `checkpoint.sh`；`restore.sh` 在覆盖前由 `restore_db.py` 删除目标 `-wal/-shm`。
- **Windows/Git Bash 兼容**：脚本内 `export MSYS_NO_PATHCONV=1`，避免 `/app/data/...` 被改写成 `C:/...`；同时用 `cygpath -w` 只为 `docker compose -f/--env-file` 转 Windows 路径。
- **资产清单默认轻量**：7GB/15 万文件的逐文件统计在 Windows bind mount 上过慢，manifest 默认只记路径；`MANIFEST_DEEP=1` 才统计 files/bytes。
- **无 rsync 退化**：当前 Windows 环境没有 rsync，`--assets` 自动退化为 `cp -a`（无硬链接增量），并显式 warning；有 rsync 时支持 `LINK_DEST`。
- **不覆盖生产**：全部实测在 `deploy/runtime/` staging；生产库未触碰。

### 4.4 恢复演练

1. 在 staging 库创建 `p5_restore_marker` 并插入 1 行。
2. `bash deploy/restore.sh --latest --dry-run` → 备份校验 `ok`，明确“未停服务、未落盘”。
3. `bash deploy/restore.sh --latest --yes`：
   - 覆盖前快照 `question_bank_pre_restore_20261031_003737.db`
   - 停止 backend（web 保留）→ 恢复 → 启动 backend → `health=healthy` → `/health HTTP 200`
   - 四表计数 `{'sys_user': 13, 'question_bank': 3489, 'exam_paper': 42, 'paper_question_relation': 2360}`
4. 恢复后查询：`marker_table=0`、`q=3489`，证明覆盖确实发生且数据回到备份点。

## 5. 约束与风险

- 备份默认不含 7GB `static/` 的逐文件清单；真正迁移/归档需 `MANIFEST_DEEP=1` 或 `--assets`。
- 当前 Windows 无 rsync，`--assets` 为全量复制，占用与源资产等量磁盘；生产 Linux 建议安装 rsync 并用 `LINK_DEST`。
- `restore.sh` 停 backend 期间 web 仍运行，用户请求会 502；生产应放在维护窗口，并由网关返回维护页。
- 备份目录与资产副本默认在 `deploy/runtime/`（已被 `.gitignore` 忽略）；异地副本必须显式给 `OFFSITE_ROOT`。
- CI 未实际执行；首次 push 到 GitHub 后需观察 `pip install`（playwright 等重依赖）耗时。

## 6. 回滚

- 删除新增脚本/CI 不影响运行中的容器。
- 恢复失败时用 `restore_db.py --backup <pre_restore 快照> --yes` 回退本次恢复。
- 不执行 `docker compose down -v`；业务卷均为宿主 bind。
