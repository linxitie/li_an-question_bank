# 论坛图片上传接口 405 排查与修复报告

- 日期：2026-11-02
- 提交基线：`61f1db8`（修复前 main）
- 现象来源：用户在「论坛」发帖/附图测试时，后端日志连续输出
  `127.0.0.1:59646 - "POST /api/media/image HTTP/1.1" 405 Method Not Allowed`
- 结论：**不是 405 的"接口不存在"，而是"接口注册被合并事故丢掉了"**。`image_media.py` 模块仍被 import，但 `app.include_router(image_media.router)` 在 `60ca515` 合并 `origin/main` 时被冲突解决删除，`POST /api/media/image` 于是落到 `media_assets` 的 `GET/HEAD /api/media/{asset_id}` 兜底路由上，Starlette 判定「路径存在、方法不允许」→ **405**。

## 1. 证据链（实测，均可复现）

| # | 证据 | 命令/位置 | 结果 |
|---|---|---|---|
| 1 | 前端调用的是 `POST /api/media/image` | `src/components/forum/imageUtils.ts:49` → `url: '/api/media/image'` | 与日志一致 |
| 2 | 上传处理函数确实存在 | `backend/app/api/v1/library/image_media.py:61` `@router.post("/image")`，`:23` `APIRouter(prefix="/api/media")` | 代码在，路由没注册 |
| 3 | 模块被 import 但没被 include | `backend/app/main.py:23` `from .api.v1.library import videos, media, image_media`；全文 `grep "image_media"` 只有这一行 | 无 `include_router(image_media.router)` |
| 4 | 405 来自媒体资产兜底路由 | `backend/app/api/media_assets.py:107-108` `@router.api_route("/{asset_id}", methods=["GET","HEAD"])`，`:23` `router_api = APIRouter(prefix="/api/media")` | 路径匹配、方法不匹配 → 405 |
| 5 | 恢复前实机路由表 | `GET /openapi.json` 过滤 `/api/media` | `['POST'] /api/media/upload`、`['POST'] /api/media/import`、`['GET'] /api/media/export`、`['HEAD','GET'] /api/media/{asset_id}` —— **没有 `/api/media/image`** |
| 6 | 回归测试同样 405 | `pytest tests/test_image_media.py` | `4 failed`，全部 `assert 405 == 200/400/413` |
| 7 | 该路由曾经注册过 | `git show 6fa481c -- backend/app/main.py` | 新增 `from ... import videos, media, image_media` 与 `+app.include_router(image_media.router)` |
| 8 | 是被合并丢掉的 | `git log -m -S "image_media.router" -- backend/app/main.py` | `60ca515 (from fe11b3a) Merge remote-tracking branch 'origin/main'` 让该行消失 |

## 2. 根因

`60ca515` 解决 `backend/app/main.py` 冲突时取了我方版本（保留了 `media_assets_api` 的新增注册），
但把同伴分支里 `app.include_router(image_media.router)` 一起丢掉了。

它不会触发 ImportError（`image_media` 仍被 import）、不会 404（路径被 `/{asset_id}` 接住）、
也不会被既有测试发现——除非有人真去发一张图。这正是"版本不一致"类缺陷中最难自查的一种：
**合并后代码能启动、大部分页面能开，只有被丢的那条链路 405。**

## 3. 修复

`backend/app/main.py:876-882`（注册块）：

```python
app.include_router(media.router)
# 论坛/反馈图片上传（POST /api/media/image）。
# 2026-11-02 修复：该行在 60ca515 合并时被冲突解决丢掉，导致 POST 落到
# media_assets_api 的 GET /api/media/{asset_id} 兜底路由上，返回 405。
# 注意：注册顺序必须在 media_assets 的 /{asset_id} 通配路由之前，保证先匹配到精确路径。
app.include_router(image_media.router)
app.include_router(media_assets_api.router)
```

同时做了同类问题审计：解析 `main.py` 全部 `from ... import X` 与 `include_router(X.` 的交集，
`imported-but-never-included` 只剩 `admin`/`teacher`（其实通过 `admin_api`/`teacher_api` 别名注册）
与工具函数，**没有第二条"模块被 import 却没注册"的路由**。

## 4. 防复发

新增 `backend/tests/test_router_registration.py`：用关键路由清单直接断言 FastAPI 路由表，
覆盖历次事故点，任何一条消失立即失败：

- `POST /api/media/image`（本次 405）
- `GET /api/teacher/forum/posts`、`GET /api/admin/forum/posts`（论坛 404 事故）
- `POST /api/llm/chat`、`POST /api/plan/generate`（大模型 401/503 事故）
- `GET /api/exams/{paper_id}/questions`、`POST /api/exams/{paper_id}/start`、`POST /api/exams/{record_id}/submit`（考试 500 事故）
- `POST /api/auth/login`（教师账号事故）、`GET /health`（版本自检依赖）

合并 `main.py` / `router` 类文件时的检查要点：冲突解决后必须 diff `include_router(` 行数，
不要只看"能启动"。

## 6. 影响面与回滚

- 影响面：论坛发帖附图、反馈附图、教师/管理端论坛附件（共用 `imageUtils.uploadImage`）。
- 回滚：删除 `app.include_router(image_media.router)` 一行即可（但会恢复 405，不建议）；
  测试文件可独立删除，不影响运行。

## 7. 遗留观察

- `GET /openapi.json` 出现 `Duplicate Operation ID get_media_api_media__asset_id__get`：
  `media_assets.py` 的 `router` 与 `router_api` 共用同名函数，FastAPI 生成 OpenAPI 时告警，
  不影响功能，后续可给别名路由加 `operation_id` 前缀消除。
- `tests/test_api_surface.py` 的两条失败属既有基线漂移（`api_surface.json` 仍是 343 条冻结口径，
  而近两周新增端点未登记），与本次修复无关。
