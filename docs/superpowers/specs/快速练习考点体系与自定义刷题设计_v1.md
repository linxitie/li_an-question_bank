# 快速练习考点体系与自定义刷题设计 v1

> 状态：📋 待用户审批（2026-11-10）  
> 范围：学生端「快速练习」考点树、「其他」归集、练习记录考点、自定义刷题；含导入双写与存量回填。  
> 原则：先修口径，再做交互；旧契约保留，新契约叠加；所有数据修复默认 dry-run，写库前备份。

---

## 0. 结论摘要

「其他」并不是脏数据，而是 canonical taxonomy 中每个 L2 下的合法叶子。真正的问题有三层：

1. **导入只写关系表，不写主考点**：`_link_knowledge_points` 只写 `question_knowledge`，不写 `question_bank.point_id/sub_category_id`，导致快速练习按主考点统计时大量题落空。
2. **API 把「其他」当普通 L3 返回**：前端只能把每个 L2 下的 91 个「其他」逐个渲染，出现「其他 6/6」「其他 0/1」等重复噪音。
3. **交互没有区分「可下钻」与「可直接练」**：只有「其他」的 L2 仍显示箭头、点开只有「其他」；顶层/自定义进入答题页又没有 scopeName，标题回退成「其他」。

修复策略：

- **保留旧字段** `knowledge_points`、旧参数 `knowledge_point_ids`、旧测试契约不动。
- **新增** `display_points` 与 `scope` 契约：只暴露“具体 L2/L3 + 一个合成 other 入口”，前端脚本优先使用新字段。
- **导入双写**：分类结果同时写 `question_knowledge` 与 `question_bank.point_id/sub_category_id`；分类不到具体 L3 时允许为空，由 other 统一收留，不伪造具体考点。
- **练习记录快照 scope**：新增可空列，历史记录回退旧口径，不破坏现有测试。
- **自定义刷题独立手写页**：复用同一套 scope 与筛选元数据，不修改 raw 页模板。

## 3. 术语与唯一口径

| 术语 | 定义 |
|---|---|
| scope | 一次练习的范围：subject / subcategory / l2 / l3 / other |
| specific L3 | `point_name != '其他'` 且 `status=1` 的 L3 |
| canonical other L3 | 某 L2 下 `point_name == '其他'` 的 L3；仅作为归属容器，不在 UI 逐个展示 |
| other 题 | `point_id IS NULL` 或指向 canonical other L3 或直挂 L2 或指向已停用/不存在节点的题 |
| other 入口 | 由 API 合成的可点击练习范围，不是物理 KnowledgePoint 行 |
| display_points | 新前端契约：只含具体 L2/L3 + 每个作用域一个 other 入口 |

**计数唯一口径**：

```
subcategory.total = specific_l3_total + l2_direct_total + other_l3_total + null_total + orphan_total
other_total = l2_direct_total + other_l3_total + null_total + orphan_total
```

- 同一题只按 `question_bank.point_id` 归一次；不按 `question_knowledge` 多挂重复计数。
- 0 题节点不返回。
- other 入口只在 `other_total > 0` 时返回。

## 4. 目标契约

### 4.1 scope 对象

前端跳转与提交统一携带：

```json
{
  "type": "subject|subcategory|l2|l3|other",
  "id": 123,
  "name": "判断推理·其他",
  "subject_id": 1,
  "sub_category_id": 8,
  "l2_id": 45
}
```

- `type=subject`：id=subject_id。
- `type=subcategory`：id=sub_category_id。
- `type=l2`：id=l2 point_id，含直挂题 + 具体 L3 子题，不含 canonical other。
- `type=l3`：id=l3 point_id，仅该 L3。
- `type=other`：id=0；用 `sub_category_id` 或 `l2_id` 限定范围。

### 4.2 `display_points` 节点

在 `GET /api/quick-practice/sub-categories` 每个子科目对象上新增：

```json
{
  "display_points": [
    {
      "point_id": 45,
      "point_name": "逻辑判断",
      "level": 2,
      "total_questions": 12,
      "done_count": 3,
      "correct_count": 2,
      "accuracy": 66.7,
      "is_other": false,
      "is_direct": false,
      "other_count": 4,
      "scope": {"type": "l2", "id": 45, "name": "逻辑判断"},
      "children": [
        {
          "point_id": 101,
          "point_name": "翻译推理",
          "level": 3,
          "total_questions": 8,
          "is_other": false,
          "is_direct": true,
          "scope": {"type": "l3", "id": 101, "name": "翻译推理"},
          "children": []
        },
        {
          "point_id": 0,
          "point_name": "其他",
          "level": 3,
          "total_questions": 4,
          "is_other": true,
          "is_direct": true,
          "scope": {"type": "other", "id": 0, "l2_id": 45, "name": "逻辑判断·其他"},
          "children": []
        }
      ]
    }
  ],
  "has_specific_points": true,
  "other_count": 4,
  "filters": {
    "years": [2025, 2024, 2023],
    "types": [{"type_id": 1, "type_name": "单选题", "count": 200}],
    "difficulties": [{"level": 1, "count": 20}]
  }
}
```

规则：

- L2 有具体 L3：`total_questions` 只算具体 L3 题；直挂 L2 与 canonical other L3 合并成一个合成 other 子节点，放在 children 最后。
- L2 无具体 L3：不生成 children；节点 `is_other=true/is_direct=true`，`point_name` 用 L2 名称，点击直接练，不再显示「其他」子行。
- 子科目级 other：`point_id IS NULL` 或 orphan 的题，合成一个末位节点，`scope.type=other, sub_category_id=...`。
- 全局「未分类」卡片保留旧字段，但新增 `display_points` 一个 other 节点；文案从「未分类」改为「其他（未归类）」。
- 旧 `knowledge_points` 字段原样保留，旧测试与旧消费方不受影响。

### 4.3 `GET /api/quick-practice/questions` 新增参数

保留旧参数 `knowledge_point_ids`、`bySubCategory`、`year`、`limit`；新增：

| 参数 | 类型 | 说明 |
|---|---|---|
| `scope` | enum | subject/subcategory/l2/l3/other/custom |
| `scope_id` | int | scope 对应 id |
| `subject_id` | int | 科目 |
| `sub_category_id` | int | 子科目 |
| `l2_id` | int | L2 范围 |
| `point_id` | int | L3 范围 |
| `include_descendants` | bool | l2 是否含具体 L3，默认 true |
| `include_other` | bool | l2 是否含 other，默认 false |
| `year_from` / `year_to` | int | 年份区间 |
| `type_ids` | str | 逗号分隔题型 |
| `difficulties` | str | 逗号分隔 1–5 |
| `order` | enum | random/weak/unseen，默认 random |
| `dedupe` | bool | 按题干去重，默认 true |

旧调用不传 `scope` 时走原逻辑，保证 `test_quick_practice_consistency.py` 不变。

### 4.4 题组完整性

- 抽题后若命中 `group_id > 0`，按 `sort_order/question_id` 带入整组可见成员，避免只练半个材料组。
- 返回新增 `requested_limit`、`actual_count`、`group_expanded`；实际题数可超过 limit，前端显示「因题组完整，实际 N 题」。
- 该逻辑复用 `backend/app/services/paper_group_selector.py` 的整组展开思路，不复制一套。

## 5. 导入双写与存量修复

### 5.1 导入双写

改 `_link_knowledge_points`：

1. 分类得到 `result`。
2. 写 `QuestionKnowledge`（保持幂等）。
3. 若 `q.point_id` 为空且 `result.knowledge_point_id` 有效：写 `q.point_id`。
4. 若 `q.sub_category_id` 为空：优先 `result.sub_category_id`，否则用 `KnowledgePoint.sub_category_id` 回填。
5. 分类不到具体 L3 时**不写** `point_id`，留给 other 口径；不回退到任意「其他」L3。
6. 行测 `_upsert_xingce_question` 在 `db.flush()` 后调用 `_link_knowledge_points(db, [q])`。

### 5.2 存量回填脚本

新增 `backend/scripts/repair_quick_practice_taxonomy.py`：

- 默认 dry-run，打印：可回填题数、按科目分布、样本 20 条、跳过原因。
- `--apply` 前用 `sqlite3.backup()` 备份到 `backend/data/backups/question_bank_pre_quick_practice_repair_<ts>.db`，并 `PRAGMA integrity_check`。
- 规则：
  1. `point_id` 空且有 `question_knowledge`：优先非「其他」L3；其次 L2；最后「其他」L3。
  2. 选中点有 `sub_category_id` 且题目为空：同步回填。
  3. 选中点不存在/停用/跨科目：跳过并计入 `skipped`。
  4. 不新建 KnowledgePoint，不改 taxonomy，不删除任何关系。
- 幂等：第二次运行 `will_update=0`。

### 5.3 存量预期

- 可回填约 830 题（以 dry-run 实测为准）。
- 其余 `point_id` 空题继续归入 other，不强行分类。
- 不触碰 `question_knowledge` 多挂关系，避免破坏错题/解析链路。

## 6. 前端设计

### 6.1 快速练习树（R3 合规，script-only）

`.vtj/vue/question_bank.vue` 只改 `<script>` 与 `<style>`，不改模板：

- `currentSubCategories`：优先 `item.display_points`，缺失时回退 `item.knowledge_points`。
- `hasVisiblePoints(sub)`：优先 `sub.display_points.length > 0`。
- `toggleL2(sub, l2)`：
  - `l2.is_direct || l2.is_other` → `startScopePractice(sub, l2.scope)`；
  - 否则原展开逻辑。
- `startKnowledgePractice(sub, kp)`：统一读 `kp.scope`，构造：
  `/exercise?subject=xc&scope=l3&scopeId=101&scopeName=翻译推理&scId=8&l2Id=45`
- `startScopePractice(sub, scope)`：other 追加 `includeOther=1`；l2 追加 `includeDescendants=1`。
- `startCustomPractice`：改为 `router.push('/custom-practice')`，不再直接进 `/exercise`。
- 顶层「快速练习」：`scope=subject&scopeName=行测`。
- 子科目卡「直接练习该题型」：`scope=subcategory&scopeName=<子科目名>`。
- 视觉：注入样式给 `data-direct-only` 卡片隐藏展开箭头；若用户批准 4 行模板改动，则改为条件渲染箭头（优先 script-only，模板改动仅备选）。

### 6.2 自定义刷题新页

新增 `src/views/student/shared/CustomPractice.vue`，路由 `/custom-practice`：

- 左侧「练习范围」：

## 10. 分期与风险

### 10.1 分期

| 阶段 | 内容 | 可独立回滚 |
|---|---|---|
| P0 | 基线测试 + 只读 dry-run 脚本 | 是 |
| P1 | API `display_points` + `filters`（旧字段不动） | 是 |
| P2 | API scope 抽题 + 题组展开 | 是 |
| P3 | 前端快速练习 script-only + 答题页 scope | 是 |
| P4 | 自定义刷题新页 + 路由 | 是 |
| P5 | 导入双写 + 存量回填 apply | 是（脚本备份） |
| P6 | 练习记录 scope + knowledge-progress L2 | 是 |
| P7 | 门禁 + 三端验收 + 归档 | — |

### 10.2 风险

| 风险 | 缓解 |
|---|---|
| R3：question_bank 模板不可改 | 只改 script/style，DOM 注入 class 隐藏箭头；模板改动仅备选并需用户批准 |
| 回填把题写错考点 | 只从已有 QK 关系回填，优先非 other L3；dry-run 样本人工抽查；备份 + 幂等 |
| 旧前端/旧测试被破坏 | 保留 `knowledge_points` 与旧参数；新字段叠加 |
| 题组展开导致题数超限 | 返回 `actual_count` 与提示；自定义页预估时按组粒度计算 |
| 记录表加列失败 | `schema_heal` 只补可空列；启动异常仅 warning，不阻断 |
| 性能 | display_points 在现有 3 条 SQL 的内存结果上计算；filters 仅对可见行做 distinct，不新增 N+1 |
