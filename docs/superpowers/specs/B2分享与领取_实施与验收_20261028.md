## 2. 写码前多角度自检

| 问题 | 回答 |
|---|---|
| 为什么这样写 | 领取=复制而非引用：各自独立演进，源卡修改不影响他人进度；`source_material_id` 保留溯源 |
| 好处 | 一次事务内完成"日志+复制+计数"，失败整体回滚；重复领取由唯一索引兜底 |
| 安全 | 分享/撤回校验 `creator_id`；**复制时对 `content` 再跑一次 `sanitize_html`**（源卡可能来自低权限用户）；不能领取自己的卡（400） |
| 运维 | `_audit` 记录 share/unshare/adopt；`adopted_count` 可审计；撤回可逆 |
| 扩展 | `scope` 字段已为"同机构"预留；`source_material_id` 支持链路溯源与防环 |
| 文件位置 | ✅ `materials.py`（资料域）+ `models.py`（模型集中处） |
| 前端显示 | 共享区列表 + 「领取」按钮；手机页可加 chips（B4） |
| 后端字段 | 两表已建、索引齐；`source_material_id` 由 B1 引入 |
| 路由注册 | 4 端点均在同一 router；`/shared` 静态路径在动态路由之前，已实测 200 |
| 接口闭环 | 建卡 → 分享 → 共享区 → 领取 → 副本可编辑 → 撤回 → 不可领 |
| VTJ 版本 | 不动前端，不涉及 |
