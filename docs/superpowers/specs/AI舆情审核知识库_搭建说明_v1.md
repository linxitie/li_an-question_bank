## 1. 定位与边界（先立规矩，再谈功能）

这层知识库**不是**生产数据库，**不承载**：实时评论流、向量检索、图谱查询、审核判定执行。
它承载三件事：

1. **权威副本**：政策条款、规则 DSL、黄金集、案例的「人读版本」——系统里的 `policy`/`rule` 表是机器版本，这里是可 diff、可评审的源文。
2. **人机协同界面**：AI 只往 `收件箱/提案/` 写提案，人类在此审批、批注、驳回；审批后才落正式目录。
3. **审计与追溯**：每一次知识变更在 `变更日志.md`（人读）+ `产出/`（机读 JSONL）双轨留痕。

> 判定边界：**违规定义的权力不交给 AI**。知识库是「规则的编辑室」，不是「规则的执行者」。

## 3. 知识本体四件套（本库最核心的四个区）

| 区 | 回答什么问题 | 首版内容 |
|---|---|---|
| 政策库 | 「什么算违规」 | 7 域 9 条条款，每条含 `policy_dsl`（机读）+ 人读解释 + 2 正例 2 反例 + 优先级 + 生效期 |
| 判定与处置 | 「判了之后做什么」 | 动作梯度 A0–A5（A0 放行 … A5 阻断/封禁）、首月上限 A2（仅 HOLD）、仲裁优先级、申诉 SLA 48h |
| 模型与规则 | 「机器怎么执行」 | 规则 DSL 五顶层字段 + 8 类白名单算子 + 编译六步 + 双哈希 + 保留 10 版 + 灰度 5/25/100 |
| 案例库 | 「边界在哪」 | 3 个真实样本：谐音梗辱骂（归一化）、正常吐槽被误判（对象校验缺失）、图文拆分绕过（无 OCR 漏放） |

**政策条款 ↔ 编译产物**：条款卡的 `policy_dsl` 代码块是**唯一源**，系统侧编译器把它编译成
`ruleset.json`；条款 `version` 与产物哈希一同记录在 `产出/` 的变更集里，实现「文本—产物」双向可追。

## 5. 创新设计（8 项，均为「可执行的设计」而非口号）

| 编号 | 设计 | 解决什么 |
|---|---|---|
| I1 | **三色状态灯** `🟢active / 🟡draft / ⚪deprecated` + `review_due` | 知识有寿命；过期自动浮出，避免「半年前的规则还在生效」 |
| I2 | **政策护照卡**（同一文件内：人读段 + `policy_dsl` 机读段） | 消灭「文档与规则两份真相」；改条款即改规则 |
| I3 | **三段式收件箱**（提案 / 待归类 / 待复核）+ AI 只能写提案 | 给「自生长」装刹车：AI 有提议权、无定稿权 |
| I4 | **双轨日志**（`变更日志.md` 人读 + `产出/*.jsonl` 机读） | 人看得懂，机器查得到，审计可复算 |
| I5 | **动作梯度卡 A0–A5** 独立成卡 | 把「判多重」从「判不判」里拆出来，避免二元化误伤 |
| I6 | **术语即链接** | 术语表每条都是可跳转锚点，新人 1 次点击即达定义 |
| I7 | **知识健康度五项自检**（断链/孤儿/过期/不完整/错位） | 知识库也会腐化，把体检写成查询而不是口号 |
| I8 | **指标驾驶舱** 与「质量红线表」同页 | 指标与阈值并列，看到数字立刻知道是否越线 |

## 6. 读写契约（谁能改什么）

| 角色 | 可写 | 不可写 |
|---|---|---|
| 审核 AI（系统） | `收件箱/提案/`、`产出/` | 政策库、案例库、变更日志（只可追加提案） |
| 审核运营 | `收件箱/待复核/`、案例草稿 | 政策定稿、归档删除 |
| 知识管理员 | 全部（含 `变更日志.md`） | 删除历史（只可移入 `归档/`） |
| 只读观察者 | — | 全部 |

- 命名：提案 `T-YYYY-MMDD-NNN-简述.md`，案例 `C-YYYY-NNN-简述.md`，条款 `P-域号-序号-名称.md`。
- 任何写入必须带 `frontmatter` 11 字段；变更集必须带 `sha256` + `reviewed_by`。
- 收件箱超时：提案 7 天未处理标 stale；待复核按 P0 30min / P1 4h / P2 24h / P3 48h。
