> 对应需求：①「生成个性化周任务」自动生成、标注「知识图谱生成」、金币下调；②「今日热门」弹窗加时间快捷筛选与排序方式；③ 图谱页面归属确认。

## 1. 「生成个性化周任务」原来怎么跑

```text
图谱页按钮 / 商城图谱弹窗
  → POST /api/knowledge/kg/generate?n=2
  → kg_growth.ensure_personalized_tasks()
      - sample_nodes()：按 softmax((α·heat + β·growing_rate)/T) 选「正在长但还没掌握」的 2 个节点
      - 每个节点建一条 weekly 任务：metric=kg_node_questions、threshold=30、task_code=kg_<周>_<用户>_<考点>
      - reward_coins = 150 × (1 + 贡献度加成)   ← 旧价，生效值 195×1.2 = 234
  → 之后在任务中心 /api/tasks/overview 的 weekly 里出现（personalized_for=本人）
```

问题：不点按钮就没有任务；金币 234/条远高于普通周任务；每周新生成会把旧任务堆在列表里。

## 2. 本轮的改法

| 项 | 改法 | 文件 |
|---|---|---|
| 自动生成 | 任务中心 `GET /api/tasks/overview` 先调 `_ensure_kg_personalized_tasks()`：本周没有就生成 2 条（幂等） | `backend/app/api/v1/growth/tasks.py` |
| 周范围 | weekly 查询只保留「本周的 kg 任务 + 全站周任务」，历史 kg 任务不再堆列 | 同上 |
| 金币下调 | 基础 150 → **40**（生效值 40×1.2 = **48**，最多 52×1.2 ≈ 63）；已存在未领取的旧价任务同步为 40 | `backend/app/services/kg_growth.py` + `tasks.py` |
| 标注 | 后端 DTO 已有 `is_kg_generated`：PC 商城用徽章；手机/平板在脚本里给标题加前缀 `【知识图谱生成】`（.vtj 模板按 R3 不改） | `gold_purchase.vue`（已有徽章）、`mobile_gold_purchase.vue`、`tablet_gold_purchase.vue` |

## 3. 热门弹窗的筛选与排序

原状：`热门帖子 · 前 100 条` 弹窗只有两个日期输入 + 查询，排序写死 `sortBy: 'likes'`。

新增（.vtj 模板按 R3 不改：用脚本注入工具栏 + 改数据）：

- 时间快捷：今天 / 近 7 天 / 近 30 天 / 近半年 / 近一年（自动回填日期并重新查询）
- 排序方式：按点赞量 / 按收藏量 / 按回复量
- 数量上限仍是 100 条（请求 `limit: 100`）

后端：`GET /api/forum/posts` 的 `sort_by` 从 `time|likes|comments|views` 扩到 **+`favorites` +`replies`**；
`favorites` 用关联子查询统计 `forum_favorite`（forum_post 没收藏数列），不破坏分页与 total 口径。

实测（真库）：

```text

sort_by=replies   → 200

点「按收藏量」前 5 条收藏数 3,2,2,2,1；0 pageerror
```

顺带修：热门前 100 条里排名徽标被 flex-wrap 挤成单独一行 → 改为绝对定位在卡片左上（CSS）。

## 4. Obsidian 自生长知识库

新增导出器：`scripts/kg_vault/export_kg_vault.py`（只读打开 `backend/data/example_db.sqlite`）

产物（默认 `D:/Obsidian仓库/知识图谱自生长`）：

```text
用户/<昵称>/README.md          入口
用户/<昵称>/弱项看板.md        平均掌握度、最该补的 10 个节点、本周任务候选（与系统采样同口径）
用户/<昵称>/科目/<科目>.md     按科目分组的考点表（掌握度/热度/贡献度/题量）
用户/<昵称>/节点/<考点>.md     每考点一篇：frontmatter + 关联节点双链 + 最近行为
用户/<昵称>/历史/YYYY-MM-DD.md 每日快照（自生长轨迹）
```

自生长机制：每次运行重写节点正文（笔记=投影，数据是唯一真相）；每天跑一次即可让新节点/新边/新弱项自动出现。
每日刷新脚本：`scripts/kg_vault/每日刷新.ps1`（可注册到 Windows 计划任务）。

实测：1 个有图谱的学生 → 32 个 md、1 个 canvas、5 个目录、**0 条断链**。

### 8.4 多用户隔离模型

每个 `用户/<昵称>/` 都是一个独立 Obsidian vault（带 `.obsidian/app.json`）：

- 在 Obsidian 里「打开文件夹作为仓库」时，选择自己的 `用户/<昵称>/`；
- 原因：双链 `[[考点名]]` 在同一 vault 内全局解析，多用户同名考点会串数据；
- 外层 `知识图谱索引.md` 只列用户清单（纯路径文本），不属于任何 vault；
- 如果以后要「一个 vault 看全部用户」，追加 `--shared-vault` 模式，把双链改成带路径的 `[[用户/昵称/节点/考点]]`。

### 8.5 「注册到 Windows 计划任务」是什么

Windows 计划任务 = 系统自带的定时器：到点自动运行一条命令（类似手机闹钟），不用手动双击脚本。

对本项目的作用：每天 07:00 自动执行 `scripts/kg_vault/每日刷新.ps1` → 重新导出知识图谱笔记，
Obsidian 里打开就是最新数据；失败也只影响笔记，不影响业务库。

```powershell
# 注册（每天 07:00）
schtasks /Create /TN "砺安-知识图谱每日刷新" /TR "powershell -NoProfile -ExecutionPolicy Bypass -File \"D:\AAA项目文件\砺安题库\li_an-question_bank\scripts\kg_vault\每日刷新.ps1\"" /SC DAILY /ST 07:00 /F
# 立即测试一次
schtasks /Run /TN "砺安-知识图谱每日刷新"
# 删除
schtasks /Delete /TN "砺安-知识图谱每日刷新" /F
```

不注册的替代方案：需要时手动运行一次脚本（`python scripts/kg_vault/export_kg_vault.py`），效果一样，只是不自动。
