# 导入配对与答案卷识别修复报告（2026-10-25）

> 归档：`docs/superpowers/specs/导入配对与答案卷识别_报告_20261025.md`
> 分支：`feat/teacher-administrator-import-match` → `feat/teacher-administrator`
> 现象：教师上传「题本 + 答案解析」后两个文件计数对不上，匹配后答案/解析不能一一映射。

## 1. 根因（实测，非推测）

| 文件 | `extract_question_blocks()` | `parse_answer_text_to_map()` |
|---|---|---|
| 2025 安徽行测 题本.pdf | **125** | 0 |
| 2025 安徽行测 答案解析.pdf | **95** | **125** |

导入预览（`_build_preview_async`）对**所有** PDF 都调用 `extract_question_blocks()`。
答案卷没有题干结构，按题干切块必然少切（95 ≠ 125），前端于是显示「题目 125 / 答案 95」，
教师判定为"答案对不上"；后续按题号硬配时，缺的 30 个题号全部落空。

**答案卷不是题目文档**——这是把两种文件当成同一种来解析导致的系统性错位。

## 2. 修复

| 层 | 改动 |
|---|---|
| 角色判定 | `looks_like_answer_document(text, filename)`：文件名含 答案/解析 直接判定；否则看正文「N. 字母/正确/错误」行数与选项行数比值 |
| 答案解析 | `extract_answer_entries(text)`：题号锚点 → 嵌入式答案 → 连续序列 三源合并，输出 `{number, answer, analysis}`；解析缺失时按题号回取原文段落，并剥离「题号+字母」头行 |
| 导入预览 | 答案卷不再走题干切块：`file_role='answer'`、条目 `status='ANSWER_ONLY'`、`is_answer_doc=true`；总数与题本同口径 |
| 入库闸门 | `/confirm` 拒绝 `ANSWER_ONLY`/`is_answer_doc` 条目，避免「第N题」被当新题写库 |
| 基线工具 | `backend/scripts/probe/probe_import_match_quality.py`：逐套输出 blocks/matched/analysis/empty/bad_letter |

| 项 | 结果 |
|---|---|

1. 宁夏/福建/贵州 3 套答案条目偏多 5~6 条 → 需在 `extract_answer_entries` 增加"资料分析材料编号"过滤（下一子任务）。
2. 行测资料题 `group_id=0`（无题组）导致材料与子题断裂 → 属导入建组，需在确认入库阶段按「给定材料」建 `question_groups`。
3. `test_question_import.py` 两个 MinerU→PaddleOCR 兜底用例为既有失败，另行处理。

## 6. 行测资料分析「材料–小题」绑定（同日追加）

**实测**：22 套 2024 行测真题中，解析器只在每组材料的第一题挂 `material_text`，
`material_text` 覆盖率仅 **64/2603 块（2.5%）**，且每组只有 1 题 —— 入库后
`group_id=0`，前端每题单看，材料与小题必然断裂。

**边界依据**：资料组在原文以 `（一）（二）（三）…` 独占一行标记，
22/22 套全部命中（每套 1~6 个），资料分析每组 4~5 题。

**实现**（`extract_question_blocks_with_material_sets`）：

| 要点 | 做法 |
|---|---|
| 不重切 | 在 `extract_question_blocks` 结果上按题号区间回填，题块数/题号零漂移（重切会多 2~3 个幻影块） |
| 限定分段 | 只在 `route_xingce_sections` 判定为「资料分析」的区间内匹配标记（言语/判断也有 `（一）`，不限定会把 68 题挂同一材料） |
| 题号正则 | `\d{1,3}[.．、](?!\d)` —— 排除「40.2%」被认成第 40 题 |
| 安全阈值 | 段内题数必须落在 [2,6]，否则**宁可不挂**（漏检边界时绝不把 10~19 题挂同一材料） |
| 头部清洗 | 去掉「第五部分 资料分析」「（一）」前缀，保证同组内容哈希一致、不被拆组 |

**结果**：22 套 blocks **2603 → 2603**（不增不减）；材料组 **76 个 / 272 题绑定（10.4%）**，
无一组超过 6 题。单测 `test_xingce_material_sets.py` 4 passed。

**重要边界**：本次是**前向修复** —— 新导入的试卷会带上材料与组关系；
已入库的 235 道行测题仍为 `group_id=0`，若要修存量需重新导入或另写回填脚本（需单独批准）。
