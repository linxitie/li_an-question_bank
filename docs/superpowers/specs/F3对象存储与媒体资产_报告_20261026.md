## 2. 关键设计落地

- **事实源唯一**：媒体元数据只在 SQLite `media_assets`；字节在对象投影，可重建。业务写与 `outbox.emit("media.asset.created.v1")` 同事务，不 commit。
- **写序**：校验 → 流式算 sha256/大小 → `store.put` → 同 session 插行+outbox → 调用方 commit。对象存储失败抛 `ObjectStoreUnavailable` → HTTP 503，不落半条业务数据。
- **物理去重**：同一 sha256 只存一份字节；每次上传建一条元数据行，两个 `/media/{id}` 均可读。删除只 tombstone；同 sha 无其他 active 行才删字节。
- **URL**：`/media/{asset_id}`（uuid4 hex），ETag=sha256，`Cache-Control: public,max-age=31536000,immutable`，`X-Content-Type-Options: nosniff`；支持 HEAD/304/Range 206/416；论坛附件带 `Content-Disposition: attachment`。
- **开关**：`MEDIA_STORE_ENABLED=false` 时六个入口回旧 uploads 写路径，`/media` 读路由保留，已写 URL 不裂；`OBJECT_STORE_BACKEND=local|minio`。
- **存量不动**：`/static` 与 `/uploads` 的 `app.mount` 零改动；F3 不回填旧资产、不重写历史 URL/HTML。

## 6. 回滚

1. 新上传异常：`MEDIA_STORE_ENABLED=false` 重启，新上传回旧 `/uploads`；已写 `/media` 仍可读。
2. MinIO 异常：`OBJECT_STORE_BACKEND=local` 重启；MinIO 旧对象需切回 minio 才能读。
3. 代码回退：回退 F3 提交，保留 `media_assets` 表与对象目录；旧 uploads 完整，已写 `/media` URL 会 404；禁止删表/删字节掩盖问题。
4. 迁移失败：用 `backend/data/backups/question_bank_20261026_214603_pre_f3.db` 恢复；禁止 DROP foundation 7 表、禁止删 `backend/data/*.bak`、禁止移动 `static/` 与 `题库/`。
