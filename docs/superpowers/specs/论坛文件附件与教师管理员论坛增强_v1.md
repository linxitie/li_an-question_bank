## 0. 结论先行

1. **文件附件不需要新表**：`forum_post.attachments` 与 `forum_comment.attachments` 都是 JSON 列表，直接扩展类型白名单即可。
2. **图片与文件走两条上传通道**：图片继续用 `/api/media/image`（重编码去 EXIF），文档复用并扩展现有 `/api/forum/upload`（UUID 存储、同页下载）。
3. **教师端/管理员端论坛建议做成手写 SFC**：`src/views/teacher/teacher_forum.vue`、`src/views/admin/admin_forum.vue`，不放进 VTJ 设计器，避免 R3 模板限制。
4. **删除一律软删除**：帖子 `status=DELETED`、评论 `status=0`，保留审计与恢复能力；同时补 `deleted_by/deleted_reason/deleted_at`。
5. **教师删除范围 = 本班学生**：作者 `user_type=student` 且 `class_name` 与教师 `class_name` 相同。管理员删除范围 = **全校学生**（按你的原话）。
6. **评论排序后端已具备**（`sort_by=time|likes|replies`），缺的是 PC 端控件和“置顶优先”；本次补齐三端一致。

## 2. 目标与非目标

### 2.1 目标

1. 发帖、评论都支持常用文件：`png/jpg/jpeg/gif/webp`（图片）+ `doc/docx/pdf/xls/xlsx/ppt/pptx/txt/csv/zip`（文档）。
2. 学生/教师/管理员，PC/平板/手机，全部具备发帖、评论、上传文件能力。
3. 教师端新增论坛：浏览全校、按班级筛选、删除本班学生的不良帖子/评论。
4. 管理员端新增论坛：浏览全站、删除全校学生的不良帖子/评论、可选恢复。
5. 评论支持按点赞量、发布时间、回复数排序，置顶评论永远在最前。

### 2.2 非目标

- 不做在线预览 Office/PDF（只下载；PDF 可在新页预览的诉求本次不做）。
- 不做压缩包解压、病毒扫描（依赖后续运维）。
- 不做教师删除其他教师/管理员内容。
- 不做管理员删除教师/管理员内容（按你原话只处理学生；如需要请确认）。
- 不新建 VTJ 页面（教师/管理页面手写 SFC）。

## 3. 关键决策

### D1 文件类型与限制

| 类别 | 允许格式 | 单文件 | 数量 | 单帖/单评论总量 |
|---|---|---|---|---|
| 图片 | png/jpg/jpeg/gif/webp | ≤5MB | 不限 | ≤200MB |
| 文档 | doc/docx/pdf/xls/xlsx/ppt/pptx/txt/csv/zip | ≤20MB | 帖子 ≤10，评论 ≤3 | 帖子 ≤200MB，评论 ≤50MB |

- 明确拒绝：`exe/bat/cmd/js/html/svg` 等可执行或可注入格式。
- 文档不做重编码；只做扩展名 + MIME + 文件头校验，UUID 重命名，`Content-Disposition: attachment`。

### D2 上传通道

| 文件 | 端点 | 说明 |
|---|---|---|
| 图片 | `POST /api/media/image` | 已存在；前端按扩展名路由 |
| 文档 | `POST /api/forum/upload` | 扩展白名单到 ppt/pptx/txt/csv/zip；返回 `{name,url,size,type}` |

前端统一 `FileUploader.vue`：选文件后按扩展名分流；图片进 `ImageGrid`，文档进 `FileList`。

### D3 教师/管理员论坛形态

| 页面 | 路由 | 形态 |
|---|---|---|
| 教师论坛 | `/teacher/forum` | 手写 SFC；全校浏览 + 本班删除 |
| 管理员论坛 | `/admin/forum` | 手写 SFC；全站浏览 + 全校学生内容删除 |

- 教师导航新增「论坛」tab。
- 管理端侧边栏新增「论坛管理」。
- 复用现有 `/api/forum/posts`、`/api/forum/posts/{id}/comments` 读取；删除走新增管理端点。

### D4 删除范围

| 角色 | 可删帖子 | 可删评论 | 判定 |
|---|---|---|---|
| 教师 | 本班学生发布的帖子 | 本班学生发布的评论 | `author.user_type=student` 且 `author.class_name=teacher.class_name` |
| 管理员 | 全校学生发布的帖子 | 全校学生发布的评论 | `author.user_type=student` |
| 学生 | 自己的帖子/评论 | 自己的评论 | 已有逻辑 |

- 软删除；帖子 `status=DELETED`，评论 `status=0`。
- 同时写 `deleted_by`、`deleted_reason`、`deleted_at`，并写 `SysOperationLog`。
- 删除帖子时评论不级联删除，前台显示「该内容已被管理员/教师删除」。
- 管理员可选「恢复」：`status=NORMAL/1`，恢复计数。

### D5 评论排序

- 后端：`ORDER BY is_pinned DESC, <sort_field> <order>, create_time DESC`。
- PC 评论区新增：`时间 / 点赞 / 回复` + `正序/倒序`。
- 手机已有；平板详情复用手机详情，自动获得。
- 默认：`时间 desc`（最新在前），可切换点赞降序。

> 只加列，不建新表；迁移前 `sqlite3.backup()`，并在 `main.py` 自动迁移清单补列。

| deleted_by | BIGINT | 删除人 |

**`forum_comment`**
| 字段 | 类型 | 说明 |
|---|---|---|
| deleted_by | BIGINT | 删除人 |
| deleted_reason | VARCHAR(200) | 删除原因 |

### 5.3 教师端

| 方法 | 路径 | 权限/范围 |

### 5.4 管理员端

| 方法 | 路径 | 权限/范围 |
|---|---|---|

| DELETE | `/api/admin/forum/posts/{id}` | 全校学生帖子 |
| DELETE | `/api/admin/forum/comments/{id}` | 全校学生评论 |

| POST | `/api/admin/forum/comments/{id}/restore` | 恢复软删除（可选） |

## 7. 安全、性能、运维

### 7.1 安全

| 风险 | 处置 |
|---|---|
| 可执行文件上传 | 扩展 + MIME + 文件头三重校验；拒绝 exe/bat/js/html/svg |
| 路径穿越 | UUID 文件名；不信任原始文件名 |
| XSS | 文档只下载不内联；文件名转义；不存 HTML |
| 越权删除 | 后端校验作者班级/角色；前端只做显示控制 |
| 误删 | 软删除 + 原因 + 审计；管理员可恢复 |
| 压缩包炸弹 | zip ≤20MB；后续可接病毒扫描 |
| 磁盘占满 | 单帖/评论总量限制；每日上传额度（可配） |

### 7.2 性能

- 附件只存 JSON 元数据，列表不读文件内容。
- 文档 chip 不加载预览，点击才请求。
- 教师/管理列表分页 20 条；筛选走索引 `forum_post.status/create_time`。

### 7.3 运维

- 迁移前 `sqlite3.backup()`；回滚删 `-wal/-shm`（R10）。
- 删除/恢复写 `SysOperationLog`（module=forum）。
- 文件目录：`backend/uploads/forum/<yyyyMM>/`，与现有图片目录兼容。
- 提供 `backend/scripts/verify/verify_forum_moderation.py` 校验范围权限。

## 9. 风险与回滚

| 风险 | 处置 |
|---|---|
| 教师 `class_name` 为空/不准确 | 前端提示；后端 403；管理员可在用户管理修正 |
| 误删 | 软删除 + 恢复 + 审计 |
| 文件类型绕过 | 三重校验；拒绝危险扩展 |
| 旧前端不识别 `className` | 可选字段，不影响旧逻辑 |
| `.vtj` 模板改动 | 改前备份；只做增量 |
| 管理端菜单/路由 | 手写 SFC，不动 VTJ |

回滚：代码按期 revert；数据层新列可空，旧代码不受影响；软删除可恢复。

## 10. 待你确认

1. **文件类型**：`doc/docx/pdf/xls/xlsx/ppt/pptx/txt/csv/zip` 是否够？要不要加 `rar/7z`？

## 11. 交付顺序

```text
P2.5 文件附件 + 评论排序
  → P3 教师端论坛
  → P4 管理员端论坛
```

理由：文件与排序是三端共用底座；教师/管理论坛依赖同一套附件与删除语义，先底座后管理页。
