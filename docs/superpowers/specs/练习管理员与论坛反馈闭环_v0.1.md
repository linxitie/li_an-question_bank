# 「练习管理员」入口与论坛反馈闭环 — 思路稿 v0.1

> 性质：方向讨论稿；本文不含代码改动。
> 基线：现有 `backend/app/api/v1/platform/feedback.py`、`community/forum.py`、`identity/auth.py`。

---

## 1. 问题定义

学生做题时发现题目错误、解析错误、功能异常，目前只能：
- 走「意见反馈」表单（与具体题目脱节）；
- 或去论坛发帖（没有处理状态，容易沉底）。

需要一条**可追踪、可回复、可统计**的通道，并给一个**权限受限**的「练习管理员」来处理，而不是把全部压力丢给超级管理员。

---

## 2. 角色设计：练习管理员

**不做新角色，先做「权限集」。** 现有 `SysUser.user_type` 只有 student/teacher/admin，新增角色会牵动登录、路由、权限三处；更稳的做法是给教师/管理员叠加一个能力包。

| 能力 | 权限码 | 说明 |
|---|---|---|
| 查看反馈 | `feedback:read` | 只看练习相关反馈 |
| 回复/关闭反馈 | `feedback:handle` | 不能删除反馈 |
| 论坛巡版 | `forum:moderate` | 隐藏/删除帖子与评论、置顶、加精 |
| 查看处理统计 | `feedback:stats` | 响应时长、解决率、高频错题 |

边界（明确不做）：
- 不能改题库、不能改用户、不能发金币。
- 不能看到学生手机号/身份证等敏感字段。
- 论坛操作必须写审计日志（复用 `SysOperationLog`）。

落点：`backend/app/core/security.py` 的 `Permission` 增加上述常量；`get_current_user` 之外增加 `require_permission(...)` 依赖。

---

## 3. 学生端入口

三处入口，统一跳同一个反馈页，但带不同上下文：

1. **做题页/解析页**：题目卡片底部「报错/反馈」按钮，自动带上 `questionId`、`practiceRecordId`、当前选项、截图。
2. **练习记录页**：某次练习的「反馈这次练习」。
3. **论坛**：发帖分类增加「问题反馈」，发帖时可选关联题目；论坛反馈与工单双向可见。
4. **我的-设置**：保留通用「意见反馈」入口。

表单字段（建议）：
- 类型：题目内容错误 / 答案错误 / 解析错误 / 功能异常 / 其他
- 关联：题目 ID、练习记录 ID（自动填，可隐藏）
- 描述：≤500 字
- 图片：≤3 张，单张 ≤2MB（复用现有上传能力，新增反馈图片目录）
- 联系方式：默认取账号，不额外收集

提交后返回工单号，学生可在「我的反馈」看到状态与管理员回复。

## 4. 管理员端入口

### 4.1 PC 管理端

新增一级菜单「练习管理」，下挂两个页面：

1. **反馈处理台**
   - 列表：状态、类型、题目、提交人（脱敏）、提交时间、处理人、SLA 剩余时间。
   - 筛选：待处理/我处理的/已解决/已驳回；按类型、科目、时间。
   - 详情：题目原文 + 学生描述 + 截图 + 快捷操作（确认错误/驳回/转交/回复）。
   - 批量：批量标记已解决、批量转交。
2. **论坛巡版**
   - 帖子列表：状态、举报数、作者、分类、时间。
   - 操作：隐藏/恢复/删除、置顶、加精、关闭评论。
   - 评论管理：按帖子展开，支持删除单条。
   - 举报队列：学生举报 → 管理员判定。

### 4.2 手机端管理入口

练习管理员不可能一直坐在电脑前。建议手机端只做**轻量处理**：
- 「待处理反馈」列表 + 快捷回复模板；
- 「举报帖子」列表 + 隐藏/忽略；
- 不做批量操作与复杂筛选。

入口放在「我的」页，仅对有 `feedback:handle` 的用户显示。

## 5. 数据模型（增量）

现有 `Feedback` 表（`platform/feedback.py`）字段不足，建议增量：

| 字段 | 用途 |
|---|---|
| `category` | 题目内容/答案/解析/功能/其他 |
| `question_id` / `practice_record_id` | 关联题目与练习 |
| `attachments` JSON | 截图列表 |
| `status` | pending/claimed/replied/resolved/rejected |
| `handler_id` | 处理人 |
| `claimed_at` / `replied_at` / `resolved_at` | SLA 统计 |
| `priority` | low/normal/high（按类型与重复次数自动升） |
| `ticket_no` | 对学生可见的工单号 |
| `reply_content` | 管理员回复（可多条则拆子表） |

论坛侧复用现有 `ForumPost.status`（NORMAL/DELETED/BLOCKED），新增：
- `ForumReport`：举报人、目标类型、目标 ID、原因、状态。
- `ForumModerationLog`：操作人、动作、目标、原因、时间（或复用 `SysOperationLog`）。

## 6. 状态机与 SLA

```
pending → claimed → replied → resolved
                  ↘ rejected
```

- 认领：同一工单只能一个处理人，`claimed` 加乐观锁。
- 超时：pending 超过 24h 自动标红并提醒；超过 72h 升级给超级管理员。
- 重复反馈：同一题目 7 天内 ≥3 条同类型反馈，自动合并并升优先级。
- 回复即通知：站内信 + WebSocket `sync`（复用现有 `scheduler._broadcast_personal_sync`）。

---

## 7. 与论坛的关系

两条通道不要做成两套系统：

| 场景 | 走哪条 |
|---|---|
| 具体题目错误 | 反馈工单（带题目上下文，可统计） |
| 学习方法/资料分享 | 论坛普通帖 |
| 对平台的意见 | 反馈工单「功能异常/其他」 |
| 公开讨论某题 | 论坛「问题反馈」分类，可关联题目 ID |

论坛「问题反馈」分类的帖子，管理员可一键「转为工单」，避免遗漏；工单解决后可在帖子下自动回复「已修复」。

---

## 8. 权限与安全

- 学生只能看自己的反馈；管理员按权限看全部。
- 反馈内容走敏感词过滤；截图做类型/大小校验。
- 管理操作全部审计，禁止物理删除（软删除 + 日志）。
- 练习管理员不能看到学生完整手机号；列表默认脱敏。
- 防刷：同一用户 10 分钟内最多 5 条反馈；同一题目重复提交合并。

## 9. 分期落地

| 阶段 | 内容 | 依赖 | 风险 |
|---|---|---|---|
| P0 | 复用现有反馈提交/我的反馈；加 `category/question_id/status` | 无 | 低 |
| P1 | 反馈处理台（列表/详情/回复/状态） | P0 | 中 |
| P2 | 做题页「报错」入口 + 截图上传 | P0 | 中 |
| P3 | 论坛巡版 + 举报队列 | 论坛已有 status | 中 |
| P4 | 手机端轻量处理入口 | P1/P3 | 中 |
| P5 | SLA、重复合并、统计看板 | P1 | 低 |

**建议先做 P0+P1**：先把「学生能提、管理员能回、状态可追踪」跑通，再补入口和巡版。
