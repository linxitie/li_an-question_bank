3. 知识骨架完全沿用公安联考三科大纲：3 科目 → 16 知识域 → 55 个周任务主题 → 165 个任务模板 → 216 个任务实例。

8. 边界：Obsidian 是设计态与审批态，不是学生运行时；不直接写数据库，不替代 FastAPI / SQLite。

## 1. 需求与边界

### 1.1 用户目标

- 以历年公安联考大纲为知识图谱主框架，知识点层沿用 科目—知识域—知识点—考点。

- 周任务最终对接题库系统「个人小任务」与「金币购 · 任务」，需要稳定、支持大数据流、流畅的 API 接口层。
- 交付完整基础框架，便于合作伙伴长期使用、运营、维护。

### 1.2 本轮做了什么

- 搭建完整 Obsidian 子库与 10 区目录。

## 3. 知识框架：大纲 → 主题 → 模板 → 实例

### 3.1 四层映射

~~~text
科目（3）→ 知识域（16）→ 周任务主题（55）→ 任务模板（165）→ 任务实例（216×N 学生）
~~~

- 主题层是「一周内可教、可练、可审」的颗粒度，不等同于知识点。
- 行测 31 个主题来自 31 个分组；公专基础知识 11 个主题来自 11 个分组；申论 5 个主题对应 5 个域；公专职业素养/基本能力 8 个主题为任务型自定义主题。
- 每个主题固定 3 个模板：基础、强化、冲刺（具体名称以卡片为准），共 165 个。
- 模板只描述任务 DNA（题量、难度、分钟、金币、形态），不复制题目内容。
- 实例是「某周某日某学生要做的一件事」，由模板 + 周计划 + 日批生成。

### 3.2 大纲依据

- `02-大纲框架/01-行测大纲映射.md`：行测模块与题量、时限、分值。
- `02-大纲框架/02-申论大纲映射.md`：归纳概括、综合分析、提出对策、应用文、议论文。
- `02-大纲框架/03-公专大纲映射.md`：职业素养、基础知识、基本能力。
- `02-大纲框架/04-三科配比与权重.md`：每周 行测 7 / 申论 4 / 公专 7 的依据。
- `02-大纲框架/05-任务主题映射总表.md`：55 个主题逐条挂大纲条目与知识域。
- 大纲变化走 `02-大纲框架/07-大纲变更流程.md`，不直接改任务卡。

### 3.3 与「快速练习知识分层」的关系

- 分类层库：`D:/Obsidian仓库/快速练习知识分层`，446 张规范卡，回答「知识怎么分」。
- 任务层库：`D:/Obsidian仓库/周任务设计分配`，220 张任务卡，回答「一周练什么、怎么批」。
- 任务卡通过 `快速练习知识分层/...` 双链回挂知识点与考点；两库分治，不互相复制。

## 4. 周任务生成与配比

### 4.1 12 周节奏

| 阶段 | 周次 | 重点 | 难度 |
|---|---|---|---|
| 基础 | 第 1—4 周 | 高频域、基础题型、低门槛 | 1—2 |
| 强化 | 第 5—8 周 | 跨域组合、限时训练 | 2—3 |
| 冲刺 | 第 9—12 周 | 整卷节奏、错题回炉 | 3—4 |

- 每周 18 个任务，行测 7、申论 4、公专 7。
- 每天 2—3 个任务，总时长 40—110 分钟；三任务日 95—110 分钟，两任务日 40—50 分钟。
- 每日金币 20—30，按任务数与难度浮动。
- 随机不是无约束随机：先锁三科配比，再锁难度梯度，再做相邻周去重，最后人工审批。

### 4.2 去重与供给

- 相邻周重复主题 33 个：允许复现，但必须换模板形态或换难度，不能原样重复。
- 6 个模板可试点：已有足够题目供给，可直接进入发布包。
- 159 个模板待补题：允许生成计划，但不进入发布包，状态保持「待补题」。
- 看板 `08-视图/05-供给看板.md` 按主题列出可试点/待补题，补题后自动变色。

## 5. 每日审批闭环（Obsidian 内）

### 5.1 三层入口

1. 首页审批铃：`首页.md` 顶部 `[!approval]` 橙色 callout，显示待批天数、最早日期、审批动作。
2. 今日任务栏：`01-入口/00-今日任务栏.md`，按日期列出待批日批与跳转。
3. 日批卡：`05-日批/第NN周-周X-YYYY-MM-DD.md`，含审批动作、快速勾选、今日任务表、时间金币表、任务明细。

### 5.2 审批动作

~~~text
看三科配比 → 看难度 → 看题量/时长 → 改状态为「已批准」→ 发布 → 学生可见
~~~

- 周计划状态：计划中 → 待审批 → 已批准 → 已发布 → 已归档。
- 日批状态：未到窗口 → 待周批 → 待审批 → 生效。
- 实例状态：未开始 → 进行中 → 已提交 → 已领币；超时转 expired。
- 审批人、审批意见、版本号必须填写；撤回不删卡，追加变更日志。

### 5.3 通知

- 库内：首页审批铃 + 今日任务栏 + 日批看板，打开 Obsidian 即见。
- 库外：`09-治理/工具/每日审批提醒.ps1` 只读扫描 `05-日批`，统计 `状态: "待审批"`，弹 Windows 通知。
- 已实测：`-Test` 输出「待审批日批：7」，对应第 01 周 7 天。
- 可放入 Windows 任务计划程序，每天 09:00 执行；不修改任何笔记。

## 7. API 契约：个人小任务 / 金币购

### 7.1 命名空间

~~~text
/api/v1/weekly-tasks/catalog/*    只读目录
/api/v1/weekly-tasks/plans/*      周计划
/api/v1/weekly-tasks/batches/*    日批
/api/v1/weekly-tasks/my/*         学生动作
/api/v1/weekly-tasks/admin/*      发布回滚
/api/v1/weekly-tasks/events/*     通知
~~~

### 7.2 五条铁律

1. 写接口必须带 Idempotency-Key。
2. 可变资源带 version，写请求带 If-Match。
3. 列表用 cursor，不深翻页。
4. 状态变化写 outbox，SSE 只做通知。
5. SSE 失败回退 30 秒轮询。

### 7.3 数据模型

- 六张新表：weekly_theme、weekly_template、weekly_instance、weekly_plan、weekly_batch、weekly_progress；外加 weekly_reward 与 weekly_outbox。
- 旧表只增不改：study_goal 加可空 source_type/source_ref；badge_task 不改表；user_notify 加 WEEKLY_TASK 枚举；coin_ledger 用 ref=wt:<instanceId>。
- 容量：12 周 × 18 × 1 万 = 216 万实例/学期；按 task_date 归档，进度保留 90 天。
- 性能目标：my/today P95 ≤ 120 ms；plans/{id} ≤ 200 ms；18 实例一次查完，禁止 N+1。

### 7.4 与现有系统

- 复用 `reward.contract.grant_coins`，source_type=TASK，不另起金币账本。
- 旧 `/api/plan/today` 与 `/api/plan/task/{goal_id}/claim` 保持可用。
- 新增独立 router，不动既有 343 个端点。
- 发布包：`07-编译产出/07-发布包/清单.json` + Graph Plan + SQL patch；先 dry-run，再 apply，apply 前 sqlite3.backup()。

## 9. 使用、运营、维护

### 9.1 每日

1. 打开 Obsidian，进首页看审批铃。
2. 进今日任务栏，点最早待批日批。
3. 看三科配比、难度、题量/时长；改状态为已批准，填审批人。
4. 发布；学生端第二天可见。

### 9.2 每周

1. 周计划看板检查下一周 18 个任务配比。
2. 供给看板确认可试点模板数。
3. 重复主题检查：相邻周是否原样重复。
4. 周批通过后，生成/更新日批。

### 9.3 每月

1. 运营月报：审批时效、试点数、补题数、覆盖变化。
2. 健康度看板：断链、孤立、重复、缺口。
3. 合作伙伴单域试点复盘；只改一个域，避免全局漂移。

### 9.4 维护边界

- 可以改：03-任务库、04-周计划、05-日批、02-大纲框架、08-视图。
- 受控改：06-接口契约、09-治理、10-模板；改动需版本号与变更日志。
- 不可直接改：07-编译产出（由构建器生成）、99-归档（只追加）。
- 不可做：删除任务卡、直接写数据库、把 Obsidian 当运行时、绕过审批发布。

## 11. 限制与风险

1. 供给不足：159/165 模板待补题；当前只能试点 6 个。
2. 考点缺口：42/55 主题暂无考点；任务能做，但溯源到考点会断。
3. 重复风险：33 个相邻周重复主题，若不换形态会变成刷题疲劳。
4. 审批仍是人工改 Markdown 状态；没有表单校验、没有权限控制，P2 需要脚本或插件兜底。
5. Windows 通知脚本依赖 PowerShell 与 Windows 通知中心；非 Windows 环境需替换。
6. 5 张 Canvas 数据完整、断链 0；14 号在窄窗口需 Shift+1 自适应，其余 4 张未逐张截图验收。
7. Obsidian 不是运行时：不承担学生调度、并发、金币结算；这些必须由 API 层实现。
