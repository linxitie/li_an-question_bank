## 0. 一页摘要

### 0.1 定位一句话

**评论区实时内容安全的第一道自动化防线 + 舆情态势的持续感知器 + 治理决策的可解释建议者。**
审核动作可自动，**"定义什么是违规"的权力不交给 AI**。

### 0.2 五个关键判断（与第一版方案的分水岭）

| # | 判断 | 依据 |
|---|---|---|
| J1 | 不新建"四套生产数据库"，而是**扩展现有「1 事实源 + 4 类可重建投影」** | 终态架构 §5.1 已落地 F1–F6；实测 graph 已有 3,823 节点 / 4,354 边 |
| J2 | 在线链路**不是自由多 Agent 群聊**，而是确定性 DAG + 专业 worker；多 Agent 只用于离线治理与研发协作 | 2 秒级同步预算容不下多轮 LLM；审核必须可复现、可回放 |
| J3 | **LLM 不直接决定阻断**：规则/小模型定动作，LLM 只做语境研判与解释 | 幻觉不可用"更谨慎"消除，只能靠架构隔离 |
| J4 | Obsidian 是**可审计知识副本 + 人审界面**，运行时只读"编译后的规则集"，不读 vault | Obsidian 无 RBAC/事务；库不可用不能拖垮审核 |
| J5 | 先**影子运行 2 周**再开阻断；所有策略上线前必须过黄金集回归 | 误杀成本 > 漏放成本（校园场景、可申诉） |

### 0.3 六项创新（第 12 章展开）

1. **动作/解释双引擎分离**：LLM 永不直接 BLOCK，最多"升/降一级 + 证据链"。
2. **决策指纹与离线回放**：任一判定可用 (policy_ver, ruleset_hash, model_ver, input_hash) 重放并对比。
3. **Policy-as-Markdown 编译闭环**：审批通过的 Obsidian 政策笔记 → 规则集 JSON → 沙箱回归 → 灰度。
4. **风险势能 + 协同行为检测**：不只看单条评论，按线程/话题/账号聚合，SimHash 近重复聚类识别"水军式"协同。
5. **对抗变异红队 + 逃逸召回指标**：同音/拆字/零宽/图文拆分变异夜跑，量化"当前规则的盲区"。
6. **无模型也能用**：零 LLM 时规则 + 哈希去重仍可完整运行；模型是增量，不是前提。

### 1.1 三条由基线直接推出的硬约束

1. **体量不支持分布式多库**：6 帖 / 2 评论 / 24 用户的系统上 Qdrant+Neo4j+Mongo+MinIO 四件套，是运维负债而非能力。
2. **写路径必须唯一**：论坛写入已走 outbox 同事务；AI 审核若另起写路径，必然与 F2b/F4 打架。
3. **没有 embedding 模型**：任何"先建向量库再审核"的方案在当前环境不可运行；语义能力必须是可插拔增量。

## 3. 角色定位与权责边界

### 3.1 三层角色（权重不同，不是并列）

| 层 | 职责 | 自动化边界 | 失败代价 |
|---|---|---|---|
| 审核层（硬） | 明确违规的阻断/遮蔽/降权/标记 | L0/L1 可全自动；L2 进人工 | 误杀 → 申诉、教师复核 |
| 研判层（软） | 语境、意图、传播势能、协同行为 | 只出分级建议，不执行 | 误判 → 预警噪音 |
| 治理层（知识） | 规则、案例、图谱、报告沉淀 | AI 只提议，人确认 | 知识污染 → 规则劣化 |

### 3.2 动作梯度（**本方案的核心约束**）

| 级别 | 动作 | 触发者 | 是否可自动 | 可回滚 |
|---|---|---|---|---|
| A0 | ALLOW（放行） | 规则/模型 | 是 | — |
| A1 | MASK（遮蔽敏感片段） | 规则 | 是 | 是（原文保留） |
| A2 | HOLD（仅作者可见，待复核） | 规则/小模型 | 是（默认动作） | 是 |
| A3 | HIDE（对他人隐藏） | 小模型 + 双人复核或教师确认 | 半自动 | 是 |
| A4 | BLOCK（拒绝发布） | 规则命中 + 人工确认；**LLM 无此权** | 否（首月） | 否（仅重发） |
| A5 | 账号级处置 / 移交 | 管理员 | 否 | 人工 |

> 首月默认上限 A2。这是把"AI 审核"从"会删帖的黑箱"变成"会拦一下、会解释、可申诉的助手"。

### 3.3 不可自动化的边界（写进 policy，不靠模型自觉）

定义违规、封号、跨校通报、涉法涉诉移交、涉及未成年人保护的特殊处置、对教师/管理员的处置 —— **一律人工**。

### 3.4 合规要点

- 自动化决策需**告知 + 可解释 + 可申诉**（《个人信息保护法》第 24 条思路）；
- 最小必要：审核只用内容 + 必要元数据，不建"学生画像"；
- 展示脱敏：图谱与知识库中的账号一律 Actor#hash，不落真名；
- 留存与删除：低风险原文 30 天，处罚证据 2 年，审计 3 年；用户注销触发关联内容匿名化。

### 4.1 四条不可协商的规则

1. **唯一写路径**：审核状态与业务行同事务；投影只经 outbox。
2. **运行时与知识库解耦**：审核读 ruleset.json（带 sha256），不读 Obsidian 文件。
3. **每个判定可回放**：缺 policy_ver / ruleset_hash / model_ver / input_hash 的判定视为无效。
4. **开关必须能一键回滚**：FORUM_AI_MODERATION=off 时行为与今天完全一致。

### 4.2 开关矩阵（默认全关，逐级放量）

| 开关 | 默认 | 作用 |
|---|---|---|
| FORUM_AI_MODERATION | off | 总开关 |
| FORUM_AI_SHADOW | on（总开关开时） | 只记录不处置 |
| FORUM_AI_LLM | off | L3 是否调用 LLM |
| FORUM_AI_BLOCK | off | 是否允许 A4 |
| MODERATION_VAULT_WRITE | off | 是否允许写 Obsidian 收件箱 |

## 5. 审核流水线（状态机 + 预算）

### 5.1 状态机

~~~
RECEIVED ──L0/L1──> ALLOW / MASK / HOLD ──复核──> HIDE / BLOCK / RESTORE
   │                     │                          │
   └──L2/L3──> REVIEW ───┘                     APPEAL ──> UPHELD / OVERTURNED
~~~

- 幂等键：sha256(target_type|target_id|content_hash|policy_ver)；重复投递只更新，不重复处置。
- 编辑触发重审：内容哈希变化 → 新判定版本，旧判定置 superseded。
- 删除/隐藏后：保留判定与证据，不级联删（审计需要）。

### 5.2 时延与成本预算

| 级别 | 内容 | 预算 | 失败策略 |
|---|---|---|---|
| L0 | 归一化 + DFA + 白名单 | P99 ≤ 5 ms | 异常即放行并告警（保守） |
| L1 | 轻量打分（长度/重复/链接/图片占比/历史） | P99 ≤ 20 ms | 降级为 L0 |
| 同步总 | L0+L1+决策+写库 | P99 ≤ 80 ms | 超时 → HOLD（不阻断） |
| L2 | 线程语境 + 先例检索 | ≤ 3 s | 跳过，保留 REVIEW |
| L3 | 单次 LLM（JSON，输入 ≤2k tokens，输出 ≤300） | ≤ 8 s（可配） | 超时 → REVIEW，不 BLOCK |
| 离线 | 知识提案/红队/对账 | 分钟–小时 | 次日重试，不影响在线 |

> 成本控制：L3 只接 **HOLD/REVIEW 且非缓存命中** 的流量（预估 ≤5%）。同内容 SimHash 命中直接复用判定。每日 token 预算硬上限，超限自动降级为 REVIEW 队列。

## 6. 多 Agent 分工（回答"要不要 Agents"）

### 6.1 三种形态的取舍

| 形态 | 延迟 | 成本 | 可复现 | 适用 |
|---|---|---|---|---|
| 单模型一把梭 | 低 | 中 | 差 | ❌ 不可解释 |
| 多 Agent 自由辩论/投票 | 高（多轮） | 高 | 差 | ❌ 在线审核 |
| **确定性 DAG + 专业 worker** | 可控 | 可控 | **强** | ✅ 在线 |
| **离线多 Agent（治理/红队）** | 无要求 | 中 | 中 | ✅ 知识运营 |

结论：**在线用 worker，离线用 Agent，研发期用 AgentTeams**。

### 6.2 在线 worker 清单（8 个，全部结构化输入输出）

| Worker | 输入 | 输出 | 实现 | 失败降级 |
|---|---|---|---|---|
| Orchestrator | 事件信封 | 路由决策 | 纯代码 | 直接 HOLD |
| Normalizer | 原文/附件 | 归一化文本 + 特征 | 规则 | 用原文 |
| PreScreen | 归一化文本 | 命中词/等级 | DFA | 放行 + 告警 |
| RiskScorer | 特征 + 历史 | 0–1 分 + 因子 | 规则/小模型 | 用规则分 |
| ContextAnalyst | 线程 + 作者近况 | 语境标签 | 规则 + 可选 LLM | 跳过 |
| CaseRetriever | 文本向量 | Top-K 先例 | F6 检索 | 空先例 |
| Arbiter | 各 worker 输出 | 动作 + 证据链 | 政策优先级 + 校准 + 先例 | HOLD |
| Explainer | 判定 + 证据 | 人话解释 | LLM（异步） | 模板文案 |

**关键**：Arbiter 的动作由**代码**按政策优先级计算，LLM 只写解释。仲裁不是投票：

~~~
priority: 违法 > 暴恐 > 色情 > 侮辱 > 广告 > 引战 > 无关
规则冲突时取最高优先级；同级取置信度高者；
置信度 < 阈值 或 先例冲突 → 降级为 REVIEW（宁停勿错）
~~~

### 6.3 离线 Agent（可独立开关）

| Agent | 职责 | 产出 |
|---|---|---|
| KnowledgeSteward | 聚类人工复核信号 → 规则/案例提案 | 写入 Obsidian 收件箱/提案 |
| RedTeam | 变异生成规避样本，测漏放 | 对抗样本集 + 逃逸率报告 |
| TrendAnalyst | 话题/事件聚合，传播势能 | 日报/周报 + 图谱事件节点 |
| ReconcileAuditor | 跨库对账、漂移检测 | 异常提案（不自动修） |

### 6.4 研发期 AgentTeams（本项目落地方式）

按终态架构 §10 的拓扑：Lead 中立 + ARCH/DATA/BE/API/FE/QA 六角色；任务粒度按本文档 M0–M5 拆分；每个任务必须带验收命令与回滚开关。**这不是运行时架构**，避免混淆。

## 7. 知识图谱框架

### 7.1 三层本体

| 层 | 节点 | 边 | 变更频率 | 权威 |
|---|---|---|---|---|
| 政策层（稳定） | PolicyDocument / PolicyClause / RiskCategory / Action | HAS_CLAUSE / DEFINES / APPLIES_TO / SUPERSEDES | 月 | SoT 表 + Obsidian 政策笔记（编译源） |
| 判定层（运行） | ModerationCase / Decision / Appeal / Evidence | BASED_ON / ABOUT / OVERTURNED_BY / CITES | 秒/分 | SoT 表 |
| 舆情层（演化） | Topic / Event / Thread / Actor#hash / Campaign | MENTIONS / PARTICIPATES_IN / NEAR_DUPLICATE_OF / ESCALATES | 分/时 | SoT 薄边 + 图投影 |

### 7.2 与现有底座的对接

- 薄边仍走 **kg_edge**（models.py:2305，只存 (type,id) 指针，不复制正文）；
- 图查询走 **F5 GraphStore** 投影（stores/graph.py:64，local 递归 CTE / Neo4j 可选）；
- 本体注册走 **kg_relation_type**（models.py:2294）：新增关系只加一行，不改代码。

### 7.3 三个必答查询

~~~cypher
// Q1 某判定依据了哪些条款、被谁推翻
MATCH (d:Decision {key:$id})-[:BASED_ON]->(c:PolicyClause)
OPTIONAL MATCH (d)-[:OVERTURNED_BY]->(a:Appeal) RETURN c, a

// Q2 某话题下违规判定的类别分布（治理看板）
MATCH (t:Topic {key:$topic})<-[:ABOUT]-(d:Decision)-[:BASED_ON]->(c:PolicyClause)
RETURN c.category, count(*) ORDER BY count(*) DESC

// Q3 近重复聚类（协同行为）
MATCH (c1:Comment)-[:NEAR_DUPLICATE_OF]->(c2:Comment)
MATCH (c1)-[:AUTHORED_BY]->(a1), (c2)-[:AUTHORED_BY]->(a2)
WHERE a1 <> a2 RETURN a1, a2, count(*) ORDER BY count(*) DESC LIMIT 20
~~~

### 7.4 图谱质量门（防"垃圾图谱"）

1. Schema 校验：节点/边必须在 kg_relation_type 注册；
2. 孤儿检查：判定节点必须有 ABOUT 边，政策条款必须有 HAS_CLAUSE；
3. 去重：同 (src,dst,rel) 只保留最高置信度，其余合并权重；
4. 生命周期：Decision 节点 30 天热存，之后仅保留聚合边；Actor 只留哈希；
5. 容量：节点上限 200 万，超限先归档低中心性子图（PageRank < 阈值）。

## 8. 四库适配（"1 + 4"，不是 5 套数据库）

> 先纠正口径：用户所说"四库"实际列了关系/文档/向量/图片/图五类。工程上准确的表述是
> **1 个事实源（关系库）+ 4 类可重建投影（文档/对象/向量/图）**。图片属于对象库 + 关系库元数据。

### 8.1 职责矩阵

| 库 | 现有实现 | 存什么 | **不存什么** | 重建 |
|---|---|---|---|---|
| 关系（SQLite） | WAL 单文件 | 判定/案件/政策/申诉/审计索引/状态机 | 原文大字段、向量、图遍历结果 | 否（SoT） |
| 文档（F4） | local → Mongo | 判定证据包（输入快照、各 worker 输出、解释、先例） | 全量放行记录 | 是 |
| 对象（F3） | local → MinIO | 图片/视频帧/OCR 文本/归档包 | 审核结论 | 是（按指纹） |
| 向量（F6） | local → Milvus | 政策条款、案例摘要的嵌入 | 原始评论（隐私+成本） | 是 |
| 图（F5） | local → Neo4j | 本体投影与查询 | 正文、大属性 | 是 |

### 8.2 关系库新增表（只增不改，草案）

| 表 | 粒度 | 关键字段 | 保留 |
|---|---|---|---|
| moderation_case | 一次送审 | target_type/id, content_hash, status, risk_level, action, policy_ver, ruleset_hash, model_ver, created_at | 2 年（非 ALLOW） |
| moderation_decision_log | 一次判定 | case_id, worker, score, labels_json, latency_ms | 1 年 |
| moderation_policy | 政策条款 | policy_id, version, category, severity, action, status, effective_from | 永久 |
| moderation_rule | 编译后的机器规则 | ruleset_hash, dsl_json, compiled_at, approved_by | 永久 |
| moderation_appeal | 申诉 | case_id, user_id, reason, status, handled_by, sla_due | 3 年 |
| moderation_signal | 轻量信号 | target_type/id, level, score, created_at | 30 天 |
| moderation_golden | 黄金集样本 | text_hash, label, source, split | 永久 |
| moderation_media_fp | 图片指纹 | media_id, phash, simhash, first_seen | 永久（指纹） |
| moderation_metric_daily | 日聚合 | date, total, allow, hold, hide, block, appeal, overturn | 永久 |

> ALLOW 不落 case，只落 signal（30 天滚动）+ 日聚合。这是容量与隐私的第一道闸门。

### 8.3 容量模型（按 DAU 3,000 假设，可调）

假设：300 帖/日、6,000 评论/日、800 图/日；送审率 100%，ALLOW 95%。

| 库 | 行/对象 | 单条 | 年增 | 热集（保留期） | 阈值/动作 |
|---|---|---|---|---|---|
| 关系 case | 109,500/年（5%） | ≈600 B | ≈63 MB | 2 年 ≈126 MB | 库 >512 MB → 归档评审 |
| 关系 signal | 2.19 M/年 | ≈60 B | ≈126 MB | **30 天 ≈10 MB** | 滚动删除 + 日聚合 |
| 关系 审计/申诉 | 少量 | — | <20 MB | 3 年 | — |
| 文档 case bundle | 109,500/年 | ≈8 KB（<8 MB 上限） | ≈0.84 GB | 高风险 2 年，低风险 30 天 | >20 GB 或 >50 万对象 → 归档 |
| 对象 图片 | 292,000/年 | ≈250 KB | ≈70 GB（去重前） | 180 天 | 去重 30%→≈49 GB；>50 GB 告警 |
| 向量 政策+案例 | 2k + 5 万抽样 | 1024×4 B | ≈210 MB | 全量 | >5 万/集合 → 切 Milvus |
| 图 判定节点 | 109,500/年 | ≈300 B | ≈33 MB | 30 天热，之后聚合 | >200 万节点 → 精简 |

**结论**：真正会击穿的是**图片对象**，不是关系库。因此 F3 必须有 pHash 去重 + 180 天保留 + 归档清单；关系库按终态架构 §17.2 的 256 MB/512 MB/1 GB 三档预警执行。

### 8.4 防膨胀五道闸

1. **入库前**：去重（文本 SimHash、图片 pHash、URL 归一）；
2. **入库时**：分级保留字段（ALLOW 不落大字段）；
3. **滚动**：signal 30 天、图节点 30 天、case 2 年；
4. **归档**：过期数据 → JSONL.gz + manifest 写入对象库，关系库只留索引；
5. **对账**：每日校验 5 项（case↔doc、case↔graph、media↔object、signal 总量、策略版本一致性），不一致**只提案不自动修**。

### 8.5 何时才真正切库（触发式，不提前）

任一条满足：主库 >1 GB 或连续 3 月月增 >100 MB；写 QPS 峰值 >30；需要 ≥2 写进程；向量 >5 万/集合；图 >200 万节点；对象 >50 GB。切换顺序：先 MySQL（DB_TYPE 已预留）→ 再 Milvus/Neo4j/Mongo。

## 11. 可靠性与长期稳定（需求 7）

### 11.1 SLO

| 指标 | 目标 | 测量 |
|---|---|---|
| 同步审核 P99 | ≤ 80 ms | 埋点 |
| 审核可用性 | ≥ 99.9%（降级也算可用） | 5xx + 超时率 |
| 误杀率（申诉推翻/送审） | ≤ 0.5%，首月 ≤ 1% | 申诉表 |
| 漏放率（黄金集） | ≤ 3% | 回归 |
| 案件积压 | < 200 件且无 >24h | 队列 |
| 规则发布回滚 | ≤ 5 分钟 | 演练 |

### 11.2 降级矩阵（L1–L3）

| 级别 | 触发 | 动作 | 保证 |
|---|---|---|---|
| L1 | LLM 超时/限流 | 关闭 L3，只走 L0/L1 | 同步审核不受影响 |
| L2 | DB 写延迟高 | 只写 signal，case 异步补 | 不阻塞发帖 |
| L3 | 库/磁盘告警 | 关闭图片审核与知识写入 | 保留文本阻断 |

**降级优先级**：阻断 > 预警 > 知识沉淀 > 报告。

### 11.3 长期稳定七件套

1. **黄金集回归**：≥2,000 条（申诉推翻 + 红队 + 人工标注），策略发布门禁；
2. **影子对照**：新策略先双跑，比较差异；
3. **漂移监控**：分数分布 PSI（周）、类别占比偏移、误杀率趋势；
4. **红队夜跑**：变异算子（同音/拆字/零宽/标点/图片文字/谐音英文）；
5. **对账**：case↔doc↔graph↔vector 每日 5 项；
6. **备份**：sqlite3.backup()（R10 硬规），备份链不自动删（R8）；
7. **演练**：季度故障演练（LLM 挂、库只读、vault 不可用、磁盘满）。

### 11.4 观测指标（驾驶舱）

审核量/分布、P50/P99 延迟、各 worker 命中率、LLM 调用量与 token、缓存命中、积压、申诉率与推翻率、规则版本与哈希、容量（库/对象/图/向量）、vault 漂移。
