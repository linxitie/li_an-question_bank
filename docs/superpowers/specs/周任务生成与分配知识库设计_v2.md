| 缺口 | 实测证据 | 影响 | 处理 |

### 3.2 锚点映射方案

```text
知-<科目>-<四位序号>   ← 任务层编号（稳定、可跨版本）
        │ 映射表（07-编译产出/06-锚点映射.json）
        ▼
knowledge_point.point_id  ← 题库层主键（会变）
```
规则：① 锚点只增不改，退役进 99-归档；② 映射表允许一对多（一个锚点挂多个知识点）；
③ 未映射的锚点进收件箱，不阻断任务，只阻断「考点溯源」统计。

## 4. 周任务生成与随机发配（核心算法）

### 4.1 配额

| 科目 | 任务数/周 | 分钟预算/周 | 占比（分钟） |
|---|---|---|---|
| 行测 | 8 | 220 | 40.0% |
| 申论 | 3 | 150 | 27.3% |
| 公专 | 7 | 180 | 32.7% |
| 合计 | 18 | 550 | 100% |

> 分钟数是按现有模板实测校准的（行测 A/B 交替 25/30 分钟、申论固定 B 形态 50 分钟、公专 6A+1B），
> 不是拍脑袋的比例；示例见附录 D。

每日任务数：3/2/3/2/3/2/3（每日 40—110 分钟）。基础期行测 +15%、申论 −10%；冲刺期行测 +10%、申论 +5%、公专 −5%。

### 4.2 六条约束（随机不是随便）

1. **科目配额**：每周任务数必须等于 8/3/7（可阶段浮动 ±1）；
2. **日容量装箱**：每天 2—3 个任务，时长 40—110 分钟；
3. **难度梯度**：基础 1—2 / 强化 2—3 / 冲刺 3—4；
4. **去重**：同一主题相邻周可复现，但必须换形态（A→B→C）或换难度，不允许原样重复；
5. **供给门**：supply=待补题 的模板不进发布包，也不生成学生可见实例；
6. **审批门**：未批准批次对所有学生不可见。

### 4.3 算法（确定性随机 + 装箱）

```text
输入：week_key、userId（个性化时）、stage、供给池、上周已用主题、薄弱域权重
seed = hash(week_key + ':' + userId)          # 同一周同一用户结果稳定，可复现
rng  = Random(seed)
1) 科目内配额：按大纲模块权重 + 薄弱 boost 分配「主题名额」
   weight(m) = outline_weight(m) × (1 + λ·(1 - mastery(m)))    λ=0.5
2) 每个名额抽主题：w = weight × (上周用过的主题 ? 0.35 : 1)
   抽到后扣掉已有该主题形态，避免同周同主题重复
3) 每个主题选模板：按 stage 选难度带，再在带内等概率抽 A/B/C
4) 装箱：7 天 × 每天 2—3 个，容量 110 分钟；先放长任务（申论 40—50）再填空
5) 校验：科目配额、难度带、日上限、去重规则；任一不满足回到 2) 重抽（最多 200 次）
6) 输出：18 条实例（日期、主题、模板、分钟、金币）+ 审计日志（seed、命中规则）
```

复杂度：55 主题 × 18 名额 × 200 次重抽上限，单用户单周 < 1 ms；一万用户预热可离线批量算。

### 4.4 个性化与公平性

- 薄弱 boost 只影响「科目内部选哪个域」，**不改变科目配额与总时长**，避免学生只刷弱项、放弃强项；
- 供给不足时的降级顺序：换同域同难度模板 → 换同域邻近难度 → 降低该名额为「复习本周错题」并标注；
- 审计：每条实例写 seed 与命中规则，出现争议可复算。

### 4.5 与现有实现的衔接

现库 12 周是**全站同一套**计划（weekly_task_plan + instance），还没有按用户随机发配。落地方案：

| 阶段 | 做法 | 表 |
|---|---|---|
| P1 | 先按现库 216 实例发布，学生只看「今天的实例」 | 复用 weekly_task_instance |
| P2 | 引入「班级/学生覆盖层」：同一条实例可按用户替换模板 | 新增 weekly_task_assign（user_id, instance_id, template_id） |
| P3 | 全随机：不再预生成 216 条，按需生成（seed 可复算），只落学生当周 18 条 | 新增 weekly_task_progress + 缓存 |

## 5. 分科目周任务设计

### 5.1 行测（每周 8 个任务 / 220 分钟）

| 模块 | 题库主题数 | 每周任务名额 | 依据 |
|---|---|---|---|
| 知觉速度与准确性 | 3 | 1 | 60 题、机考独立计时，练手速 |
| 判断推理 | 4 | 2 | 40 题，占比最高，必须两次 |
| 言语理解与表达 | 3 | 1—2 | 30 题 |
| 资料分析 | 3 | 1—2 | 20 题，重速算 |
| 常识判断 | 7 | 1 | 20 题 + 政治理论并入 |
| 数量关系 | 2 | 1 | 10 题，性价比低但不可放弃 |
| 政治理论 | 5 | 0—1 | 与常识轮转 |
| 科学推理 | 4 | 0—1 | 扩展模块，按年份出现 |

### 5.2 申论（每周 3 篇 / 150 分钟）

| 题型 | 每周 | 说明 |
|---|---|---|
| 归纳概括 | 1 | 基础功，材料定位 |
| 综合分析 / 提出对策 | 1（轮转） | 双题合并练 |
| 应用文写作 | 1（隔周） | 公文格式 + 场景 |
| 议论文写作 | 1（隔周） | 与上一条交替，保证两周覆盖一次大作文 |

申论是人工批改瓶颈，周任务只到「写 + 自评 + 对照要点」，批改走教师端评阅，不进周任务金币。

## 7. 人工每日审批闭环

### 7.1 状态机

```text
周计划：计划中 → 待审批 → 已批准 → 已发布 → 已归档
日批：  未到窗口 → 待周批 → 待审批 → 生效
实例：  未开始 → 进行中 → 已提交 → 已领币；超时 → 已失效
```

### 7.2 三层通知（库内）+ 一层库外

1. 首页审批铃（approval callout）：待审批周计划数、待周批天数、可试点模板数；
2. 今日任务栏：Dataview 表 + 无插件静态索引 + 审批记录块；
3. 日批卡：今日任务表、三科配比、锚点、审批勾选与审批人；
4. 库外：`09-治理/工具/每日审批提醒.ps1` 只读扫描 status，弹 Windows 通知（支持 -Test 只看不弹）。

### 7.3 审批验收口径

| 检查 | 通过线 |
|---|---|
| 每日 2—3 任务 | 是 |
| 每日 40—110 分钟 | 是 |
| 三科分钟比 | 40/30/30 ±5 个百分点 |
| 供给 | 全部 可试点 |
| 去重 | 与上周无原样重复 |
| 审批留痕 | 审批人 + 时间 + 结论 |

## 8. 自生长闭环

```text
行为事件（答题/错题/笔记）
  → KgUserNodeState / KgUserEdge 更新（掌握度、热度、边权）
  → 薄弱域排序（kg_growth.sample_nodes / contribution）
  → 候选任务（主题×模板）→ 00-收件箱 提案（AI 起草，人审）
  → 日批/周计划审批 → 07-编译产出/发布包
  → 系统导入 weekly_task_* → 学生端今日任务
```

边界：**AI 只写收件箱**，不改正式卡、不发布、不写库；生长的是「候选」，落地必须人工审批。

## 9. 可视化与创新实用性

| 创新点 | 解决什么 |
|---|---|
| 无插件兜底 | Dataview 装不上也能审批（构建时生成静态表），合作方换电脑不崩 |
| 锚点映射层 | 任务编号与题库主键解耦，题库重建不炸任务卡 |
| 供给门 / 审批门双闸 | 「有题可练」与「批准可见」分开，避免发给学生空任务 |
| seed 可复现随机 | 发配争议可复算，教研能复现某个学生的 18 个任务 |
| 配额按分钟对齐官方权重 | 不是按任务数拍脑袋，避免申论/公专挤占行测 |
| 日批粒度 | 一周 7 张日批卡，审批动作小、可回滚 |
