## 0. 结论先行

1. **文件附件不需要新表**：`forum_post.attachments` 与 `forum_comment.attachments` 都是 JSON 列表，直接扩展类型白名单即可。
2. **图片与文件走两条上传通道**：图片继续用 `/api/media/image`（重编码去 EXIF），文档复用并扩展现有 `/api/forum/upload`（UUID 存储、同页下载）。
3. **教师端/管理员端论坛建议做成手写 SFC**：`src/views/teacher/teacher_forum.vue`、`src/views/admin/admin_forum.vue`，不放进 VTJ 设计器，避免 R3 模板限制。
4. **删除一律软删除**：帖子 `status=DELETED/BLOCKED`、评论 `status=0/2`，保留审计与恢复能力；补 `deleted_by/deleted_reason/deleted_at`。
5. **教师删除 = 先隐藏 + 进管理员复核队列**：教师删除后内容立即对学生不可见，但状态为“待管理员复核”；管理员确认后才转为最终删除，也可以驳回恢复。
6. **管理员可删除任何角色的内容**（学生/教师/管理员），并拥有回收站与恢复权。
7. **评论排序后端已具备**（`sort_by=time|likes|replies`），缺的是 PC 端控件和“置顶优先”；本次补齐三端一致，默认最新在前。

## 2. 目标与非目标

### 2.1 目标

1. 发帖、评论都支持常用文件：`png/jpg/jpeg/gif/webp`（图片）+ `doc/docx/pdf/xls/xlsx/ppt/pptx/txt/csv/zip`（文档）。
2. 学生/教师/管理员，PC/平板/手机，全部具备发帖、评论、上传文件能力。
3. 教师端新增论坛：浏览全校、按班级筛选、删除本班学生的不良帖子/评论。
4. 管理员端新增论坛：浏览全站、删除全校学生的不良帖子/评论、可选恢复。
5. 评论支持按点赞量、发布时间、回复数排序，置顶评论永远在最前。

### 2.2 非目标

- 不做在线预览 Office/PDF（只下载；PDF 可在新页预览的诉求本次不做）。
- 不做压缩包解压、病毒扫描（依赖后续运维）。
- 不做教师删除其他教师/管理员内容。
- 不做管理员删除教师/管理员内容（按你原话只处理学生；如需要请确认）。
- 不新建 VTJ 页面（教师/管理页面手写 SFC）。

## 3. 关键决策

### D1 文件类型与限制

| 类别 | 允许格式 | 单文件 | 数量 | 单帖/单评论总量 |
|---|---|---|---|---|
| 图片 | png/jpg/jpeg/gif/webp | ≤5MB | 不限 | ≤200MB |
| 文档 | doc/docx/pdf/xls/xlsx/ppt/pptx/txt/csv/zip/rar/7z | ≤20MB | 帖子 ≤10，评论 ≤3 | 帖子 ≤200MB，评论 ≤50MB |

- 明确拒绝：`exe/bat/cmd/js/html/svg` 等可执行或可注入格式。
- 文档不做重编码；只做扩展名 + MIME + 文件头校验，UUID 重命名，`Content-Disposition: attachment`。

### D2 上传通道

| 文件 | 端点 | 说明 |
|---|---|---|
| 图片 | `POST /api/media/image` | 已存在；前端按扩展名路由 |
| 文档 | `POST /api/forum/upload` | 扩展白名单到 ppt/pptx/txt/csv/zip；返回 `{name,url,size,type}` |

前端统一 `FileUploader.vue`：选文件后按扩展名分流；图片进 `ImageGrid`，文档进 `FileList`。

### D3 教师/管理员论坛形态

| 页面 | 路由 | 形态 |
|---|---|---|
| 教师论坛 | `/teacher/forum` | 手写 SFC；全校浏览 + 本班删除 |
| 管理员论坛 | `/admin/forum` | 手写 SFC；全站浏览 + 全校学生内容删除 |

- 教师导航新增「论坛」tab。
- 管理端侧边栏新增「论坛管理」。
- 复用现有 `/api/forum/posts`、`/api/forum/posts/{id}/comments` 读取；删除走新增管理端点。

### D4 删除范围与复核流程

| 角色 | 可删帖子 | 可删评论 | 判定 |
|---|---|---|---|
| 教师 | 本班学生发布的帖子 | 本班学生发布的评论 | `author.user_type=student` 且 `author.class_name` ∈ 教师班级（`Banji.teacher_id` 关联的班级 + `teacher.class_name`） |
| 管理员 | 任何角色的帖子 | 任何角色的评论 | 学生/教师/管理员均可 |
| 学生 | 自己的帖子/评论 | 自己的评论 | 已有逻辑 |

**教师删除流程（已确认）**

```
教师填写原因
  → 内容立即隐藏（帖子 status=BLOCKED，评论 status=2）
  → 写入 forum_moderation（PENDING）
  → 管理员端「待复核」看到该条
      → 确认：转为最终删除（帖子 DELETED，评论 0）
      → 驳回：恢复（帖子 NORMAL，评论 1）
```

- 教师不能跳过原因；原因 ≤200 字。
- 内容隐藏期间，普通学生看不到；作者本人看到「已被教师隐藏，等待管理员复核」。
- 管理员删除不进入复核（管理员本身是最终审核人），直接进入回收站。

**管理员删除流程**

```
管理员填写原因（可选）
  → 直接软删除（帖子 DELETED，评论 0）
  → 进入回收站
  → 可在回收站恢复
```

### D5 评论排序

- 后端：`ORDER BY is_pinned DESC, <sort_field> <order>, create_time DESC`。
- PC 评论区新增：`时间 / 点赞 / 回复` + `正序/倒序`。
- 手机已有；平板详情复用手机详情，自动获得。
- **默认：时间 desc（最新在前）**；点赞排序为降序。

### D6 管理员审核与回收站

管理员论坛页分 3 个视图：

| 视图 | 内容 | 操作 |
|---|---|---|
| 内容管理 | 全站正常内容 | 删除（进回收站） |
| 待复核 | 教师删除的内容 | 确认删除 / 驳回恢复 / 查看原因 |
| 回收站 | 所有软删除内容 | 恢复 / 彻底删除（仅超级管理员） |

- 「待复核」与「回收站」都显示：作者、班级、删除人、原因、时间、原内容快照。
- 审核动作写 `SysOperationLog`。

### D7 教师班级来源

教师可管理班级 = `Banji.teacher_id = teacher.user_id` 的 `class_name` 集合，加上 `teacher.class_name`（兼容旧数据）。
- 若两者都为空，教师端显示「未绑定班级」提示，不显示隐藏按钮。
- 学生必须填写 `class_name` 才会进入教师的可管理范围。
- 管理员不受班级限制。

### D8 回收站定期审计

- 每日 **03:30（CST）** 由 APScheduler 执行一次审计。
- 统计：已删帖子、隐藏帖子、已删评论、隐藏评论、待复核、超 7 天未复核。
- 写入 `SysOperationLog`（operation_type=`论坛回收站审计`），不自动删除任何内容。
- 管理端「回收站」页展示同一套统计；超 7 天未复核标红。
- 彻底删除仍只允许超级管理员手动执行。

## 5. API 设计

### 5.1 文件

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/media/image` | 已有 |
| POST | `/api/forum/upload` | 扩展白名单：doc/docx/pdf/xls/xlsx/ppt/pptx/txt/csv/zip |

### 5.2 评论排序

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/forum/posts/{id}/comments` | `sort_by=time|likes|replies`、`order=asc|desc`；置顶优先 |

### 5.3 教师端

| 方法 | 路径 | 权限/范围 |
|---|---|---|
| GET | `/api/teacher/forum/posts` | 全校列表；支持 keyword/category/class_name/status |
| GET | `/api/teacher/forum/posts/{id}/comments` | 同现有评论接口 |
| POST | `/api/teacher/forum/posts/{id}/hide` | 本班学生帖子；body `{reason}`；立即隐藏 + 建 PENDING 复核 |
| POST | `/api/teacher/forum/comments/{id}/hide` | 本班学生评论；body `{reason}`；同上 |

> 教师**没有**最终删除权；`reason` 必填（1-200 字），缺失返回 422。

### 5.4 管理员端

| 方法 | 路径 | 权限/范围 |
|---|---|---|
| GET | `/api/admin/forum/posts` | 全站列表；支持 keyword/category/class_name/status/author_type |
| GET | `/api/admin/forum/comments` | 全站评论列表 |
| DELETE | `/api/admin/forum/posts/{id}` | 任何角色帖子；body `{reason?}`；直接软删除进回收站 |
| DELETE | `/api/admin/forum/comments/{id}` | 任何角色评论；同上 |
| GET | `/api/admin/forum/moderation` | 复核队列；`status=PENDING/APPROVED/REJECTED` |
| POST | `/api/admin/forum/moderation/{id}/approve` | 确认教师删除 → 最终删除 |
| POST | `/api/admin/forum/moderation/{id}/reject` | 驳回教师删除 → 恢复 |
| GET | `/api/admin/forum/recycle` | 回收站：已删除/隐藏内容 |
| POST | `/api/admin/forum/posts/{id}/restore` | 从回收站恢复帖子 |
| POST | `/api/admin/forum/comments/{id}/restore` | 从回收站恢复评论 |
| DELETE | `/api/admin/forum/posts/{id}/purge` | 彻底删除（仅超级管理员 role_level≥3） |
| DELETE | `/api/admin/forum/comments/{id}/purge` | 彻底删除（仅超级管理员） |

> 所有删除/复核/恢复接收 `reason`（≤200 字），写 `SysOperationLog`。

## 7. 安全、性能、运维

### 7.1 安全

| 风险 | 处置 |
|---|---|
| 可执行文件上传 | 扩展 + MIME + 文件头三重校验；拒绝 exe/bat/js/html/svg |
| 路径穿越 | UUID 文件名；不信任原始文件名 |
| XSS | 文档只下载不内联；文件名转义；不存 HTML |
| 越权删除 | 后端校验作者班级/角色；前端只做显示控制 |
| 误删 | 软删除 + 原因 + 审计；管理员可恢复 |
| 压缩包炸弹 | zip ≤20MB；后续可接病毒扫描 |
| 磁盘占满 | 单帖/评论总量限制；每日上传额度（可配） |

### 7.2 性能

- 附件只存 JSON 元数据，列表不读文件内容。
- 文档 chip 不加载预览，点击才请求。
- 教师/管理列表分页 20 条；筛选走索引 `forum_post.status/create_time`。

### 7.3 运维

- 迁移前 `sqlite3.backup()`；回滚删 `-wal/-shm`（R10）。
- 删除/恢复写 `SysOperationLog`（module=forum）。
- 文件目录：`backend/uploads/forum/<yyyyMM>/`，与现有图片目录兼容。
- 提供 `backend/scripts/verify/verify_forum_moderation.py` 校验范围权限。

## 9. 风险与回滚

| 风险 | 处置 |
|---|---|
| 教师 `class_name` 为空/不准确 | 前端提示；后端 403；管理员可在用户管理修正 |
| 误删 | 软删除 + 恢复 + 审计 |
| 文件类型绕过 | 三重校验；拒绝危险扩展 |
| 旧前端不识别 `className` | 可选字段，不影响旧逻辑 |
| `.vtj` 模板改动 | 改前备份；只做增量 |
| 管理端菜单/路由 | 手写 SFC，不动 VTJ |

回滚：代码按期 revert；数据层新列可空，旧代码不受影响；软删除可恢复。

| # | 问题 | 结论 |
