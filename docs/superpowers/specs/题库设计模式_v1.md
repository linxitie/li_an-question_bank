> 简称 **QBDM**（Question Bank Design Mode）。本文只回答四个问题：**谁来做**（角色）、**按什么顺序做**（流程）、**凭什么证据算做完**（门禁）、**花多少 token**（预算）。

## §0 适用与不适用

| 场景 | 走法 |
|---|---|
| 题库任一功能模块（题目/组卷/判题/导入/练习/错题/统计/三端页面）的设计、编码、测试、文档 | 全流程 Q0→Q6 |
| 单文件、单函数、零影响面的小改 | 裁剪 Q1，保留 Q2/Q5/Q6，预算 T1 |
| 纯问答、只读咨询 | T0 档，不产生写操作，不建分支 |
| 无仓库上下文的通用技术咨询 | 本文不适用 |

**判定口决**：改动面 >1 文件，或触及 `/api/v1/`、`models/`、`.vtj/`、门禁脚本、数据库结构 —— 必须全流程。

## §2 六条设计原则

| 原则 | 含义 | 违反的可观测症状 |
|---|---|---|
| **P1 事实先行** | 任何数量/路径/行为断言必须附取证命令或"路径:行号"；不确定就写"置信度 60%，验证方式=…" | 出现"大约""应该""我记得" |
| **P2 单角色独占** | 一次只戴一顶帽子；换帽必须留 Handoff 单（§5.3） | 同一段回复里既改前端又改后端又改契约，无交接 |
| **P3 最小装载** | 默认装载 ≤3 个文件；先 `grep/glob` 定位再 `read offset/limit` 切片 | 出现整目录读取、`tree` 全库、贴回 3000 行日志 |
| **P4 契约冻结** | 先定接口再写实现；343 端点只增不改；新增必须显式批准 | 改字段名当作"顺手统一" |
| **P5 证据闭环** | 无验证输出 = 未完成。禁止"应该没问题" | 报告完成但无命令输出 |
| **P6 角色不越权** | 前端建模师不得改后端；QA 不得改实现（只能提缺陷单） | 一个角色把全栈都写了 |

## §3 九角色总矩阵

> 角色 ≠ 人格扮演的花活。每个角色 = 一组**独占的读写权限 + 专属门禁 + 专属输出格式**。

| 代号 | 角色 | 一句话使命 | 主导阶段 | 核心产出 | 否决权（可否决什么） | 专属门禁 | 预算档 |
|---|---|---|---|---|---|---|---|
| **ARCH** | 系统架构师 | 定边界、定分层、定依赖方向 | Q2 | 架构决策记录（ADR）+ 模块边界图 | 跨域直连、破坏分层、引入重复能力的方案 | `check_module_boundary` | T2 |
| **PM** | 项目管理师 | 拆任务、控范围、控节奏、管分支 | Q0/Q6 | 实施计划（任务表+验收列）、分支计划 | 范围蔓延、无验收标准的任务 | 计划完整性自检 | T1 |
| **DATA** | 数据建模师 | 表/字段/索引/迁移/三端可见性口径 | Q2/Q3 | Schema 变更单 + 回滚脚本 + 计数口径定义 | 破坏 R10（copy2 备份）、无迁移的字段新增 | `db_tables.json` 差异比对 | T2 |
| **BE** | 后端建模师 | 把规则落成可测端点与 ORM | Q4 | 代码 + `pytest` 输出 | 绕过 ORM 的裸 SQL、跨模块 import api 层 | `gate_l4_api_contract` + 域内 pytest | T2 |
| **API** | 接口建模师 | 保 343 端点契约不破、请求响应两端对齐 | Q3/Q5 | 契约比对报告（差集表） | 任何未批准的端点增删改 | `gate_l4` + `api_surface.json` diff | T1 |
| **FE** | 前端建模师 | 只改 `<script>`，DSL 同步走工具 | Q4 | 代码 + `dryRun` 预览 + 页面自测记录 | 直改 `<template>`、对 raw 页做同步 | `gate_l5_frontend_contract` + VTJ 预览 | T2 |
| **SEC** | 网络安全检测与保障员 | 凭据、越权、注入、脱敏 | Q3/Q5 | 安全清单（含"未发现"结论） | 任何将密钥写入 .md/源码/提交信息的动作 | `check_secrets` | T1 |
| **QA** | 系统测试与问题反馈员 | 用命令证明"能用/不能用" | Q5 | 验收报告（命令+输出+结论）+ 缺陷单 | 无证据的"完成"声明 | `gate_all.py` + pytest | T2 |
| **DOC** | 归档与索引官 | 落盘、双写、更新索引、版本号 | Q6 | 归档路径清单 | "只展示不落盘" | 归档三件事清单（§10.5） | T0 |

**仲裁链**：`SEC > API > ARCH > PM > DATA > BE ≈ FE > QA > DOC`。
理由：安全与契约是不可逆损失，功能可返工。

## §4 角色卡（切换时按此执行，不必重读全站）

> 每张卡只列"该角色独有"的内容；通用红线见 `AGENTS.md`。

### R-ARCH 系统架构师
- **触发词**：分层、边界、耦合、要不要新建模块、目录结构、依赖方向、技术选型。
- **必读最小集**（≤3）：`backend/app/api/v1/` 目标域目录、`backend/data/refactor_baseline/coupling.json`（按需切片）、`docs/superpowers/specs/` 同主题既有方案（防重复造轮子）。
- **输出模板**：ADR 四段 —— 现状证据 / 可选方案 ≥2 / 选定方案与代价 / 不做什么（显式排除项）。
- **红线补充**：不得新增第 38 个 API 模块；十域（catalog/community/content/exam/growth/identity/library/personal/platform/reward）是既定边界。
- **反模式**：把"顺便重构"塞进功能任务；用"最佳实践"替代实测。

### R-PM 项目管理师
- **触发词**：拆任务、排期、验收标准、分支、提交、合并、范围。
- **必读最小集**：`docs/plans/` 同主题计划、`git log --oneline -5`、本模式 §8 分支规则。
- **输出模板**：任务表（ID / 动作 / 涉及文件 / 验收命令 / 依赖 / 预算档），每行必须有可执行验收命令。
- **否决权**：拒绝无验收标准的任务行；拒绝"一个分支混两件事"。
- **反模式**：把"再想想"写成任务；任务粒度 > 1 天。

### R-DATA 数据建模师
- **触发词**：表、字段、索引、迁移、统计口径、计数不一致、软删除、可见性。
- **必读最小集**：`backend/app/models/models.py` 目标 class 区间（`grep -n "^class "` 定位后 read）、`db_tables.json` 目标表项、`table_usage.json` 该表条目。
- **输出模板**：变更单 —— 表/字段/类型/默认值/是否可空/索引/迁移 SQL/回滚 SQL/影响端点清单/计数口径（谁算"可见题"）。
- **红线**：R10 备份必须 `sqlite3.backup()`，回滚删 `-wal`+`-shm`；禁止 `shutil.copy2`。
- **专属检查**：三端计数口径必须同源（同一函数/同一筛选子句），禁止各端各写 WHERE。

### R-BE 后端建模师
- **触发词**：接口逻辑、校验、事务、分页、异常码、路由注册、权限依赖。
- **必读最小集**：目标 `api/v1/<域>/<模块>.py`、`main.py` 对应 `include_router` 段、目标 model class 区间。
- **输出模板**：CTC 11 问（§7.3）→ 代码 → `pytest` 输出 → 路由注册证据（`grep include_router`）。
- **红线**：R11 端点冻结；不得跨域 `import app.api.v1.other`；`/api/v1` 前缀不可改。
- **门禁**：`python backend/scripts/gates/gate_all.py --quick` + `python -m pytest tests/<域> -q`。
- **反模式**：整读 1969 行 models；在多个模块复制同一校验；改字段名"统一命名"。

### R-API 接口建模师
- **触发词**：契约、请求体、响应体、字段名、兼容、版本、343、api_surface。
- **必读最小集**：`api_surface.json` 目标模块项、目标 api 文件的目标函数、前端调用点（`grep` 路径字符串）。
- **输出模板**：契约比对表（端点 / 方法 / 变更类型 / 前端调用方 / 兼容策略 / 批准人）。变更类型只有三种：`不变` / `只增` / `破坏性`；`破坏性` 一律阻止。
- **门禁**：`gate_l4_api_contract` 必须 PASS 且端点数 = 343（或 343+已批准增量）。

### R-FE 前端建模师
- **触发词**：页面、按钮、弹窗、显示不对、响应式、路由、VTJ、DSL、`<script>`。
- **必读最小集**：目标 `.vtj/vue/<page>.vue`（只读 `<script>` 段）、`.vtj/files/<id>.json` 对应 state/methods、`src/router/index.ts` 对应路由行。
- **强制前置**：`skill vtj-frontend`；写前 `dryRun: true` 预览；改后读回确认。
- **红线**：R1 不移动/改名/删除 `.vtj/`；R2 raw 页禁 `vtj_sync_vue_to_dsl`；R3 禁直改 `<template>`；R4 `device.ts` 原样；R5 不改 `mobile_*/tablet_*` 前缀；R12 不复制平板页。
- **门禁**：`gate_l5_frontend_contract` + 页面在 `http://localhost:9527/__vtj__/` 可开。
- **反模式**：用"改 template 更快"绕过设计器；对 raw 页调同步工具。

### R-SEC 网络安全检测与保障员
- **触发词**：密钥、token、权限、越权、注入、XSS、脱敏、日志、CORS、上传。
- **必读最小集**：目标文件中的鉴权依赖（`Depends(...)`）、`check_secrets` 输出、`.gitignore`。
- **输出模板**：五问清单 —— 鉴权是否覆盖每个新端点 / 是否存在 IDOR（拿别人 id 直接查）/ 入参是否参数化 / 输出是否脱敏 / 凭据是否入库或入档。每条给"通过/不通过/未涉及"。
- **红线**：真实密钥禁止入 .md/源码/提交信息；`.env` 禁止入库；发现泄露只能轮换（改写历史是附加项）。
- **已知待办**：`backend/.env` 的 `JWT_SECRET_KEY` 待用户轮换——AI 不得代填密钥值，只能提示。

### R-QA 系统测试与问题反馈员
- **触发词**：测试、验证、回归、跑一下、验收、是否通过。
- **必读最小集**：`backend/tests/` 目标域测试文件、门禁脚本入口、实施计划中的验收列。
- **输出模板**：验收报告 —— 命令 / 退出码 / 关键输出摘录（≤20 行）/ 结论（PASS/FAIL）/ 未覆盖项。
- **铁律**：失败就报失败；不确定就标"未验证"。禁止用"应该/理论上"结案。
- **门禁**：`gate_all.py --quick`（快） / 全量（提交前）；改动域对应的 pytest 子集。

### R-DOC 归档与索引官
- **触发词**：落盘、归档、存档、索引、README、版本号。
- **执行三件事**（`AGENTS.md` §1.4）：①写权威位置 ②写归档副本（判 `solve_problems_files/` 是否存在）③更新 `docs/README.md` 活跃文档索引。
- **命名**：`<中文主题>_v<版本>.md`，禁止代号；方案/计划/手册三类后缀固定。
- **反模式**：只在对话里贴方案不落盘；事后补档。

## §5 角色切换协议

### 5.1 切帽三要素
1. **帽**：显式声明 `[ROLE] <代号> <角色名> v1`。
2. **境**：装载该角色"必读最小集"，并在回复中列出**读了什么、读到哪一行**。
3. **证**：说明本角色要对哪条门禁负责（`[GATE] gate_l4 + pytest tests/exam`）。

### 5.2 标准声明头（复制即用）

```
[ROLE] BE 后端建模师 v1
[TASK] QBDM-20261025-01 组卷接口按知识点过滤
[BUDGET] T2 (≤60k)
[LOAD] api/v1/exam/papers.py:1-120 | models.py:grep class Paper | main.py:include_router(exam)
[GATE] gate_l4_api_contract + pytest tests/exam -q
[OUT] CTC-11 → 代码 → 命令输出 → 归档
```

### 5.3 Handoff 交接单（换帽必填，≤10 行）

```
FROM: ARCH  TO: BE
已定: 过滤在 SQL 层完成，不在 Python 侧过滤（理由: 题量 10k+ 级）
未定: 知识点是否多级递归（留给 DATA）
风险: 与 smart_exam 现有过滤逻辑可能重复 → BE 必须先 grep 复用
证据: coupling.json 显示 exam→content 单向依赖，允许直连
```

### 5.4 并行规则
- 两个角色可并行 **当且仅当** 文件集不相交，且无读写依赖。
- 并行时各自独立产出，由 PM 合并；**同一文件禁止两角色并写**。
- 可并行的典型组合：`SEC ∥ QA`（只读）、`ARCH ∥ DOC`（不同文件）、`BE ∥ FE`（契约已冻结时）。

### 5.5 越权处置
任一角色发现"这活不该我干" → 立即停手 + 出 Handoff 单 + 回 PM。**不得先改了再说。**

## §6 Token 零浪费契约（把"100%"变成可验证指标）

> 诚实界定：**"token 使用率 100%"在物理上不可度量**（模型不暴露每 token 的效用）。本模式把它操作化为**可审计的五个零指标**；达成即等价于"零无效 token"。

### 6.1 五个零指标

| 指标 | 定义 | 采集方式 |
|---|---|---|
| **Z1 重复读=0** | 同一文件同一行区间在一次任务内不读第二遍（读第二遍必须说明"内容已变"） | 自检：装载日志 |
| **Z2 未验证断言=0** | 每条事实断言附命令/行号，或标"置信度+验证方式" | 自检：断言清单 |
| **Z3 返工=0** | 因"没读够就写"导致的二次修改次数 = 0 | git diff 统计 |
| **Z4 超预算=0** | 单轮装载 token ≤ 预算档上限 | 装载清单 |
| **Z5 归档遗漏=0** | 方案/计划/报告 100% 落盘并进索引 | 归档清单 |

### 6.2 预算分档

| 档 | 场景 | 装载上限 | 允许写操作 | 强制产物 |
|---|---|---|---|---|
| **T0** | 问答、查证、解释 | ≤8k | 0 | 结论 + 取证 |
| **T1** | 单文件改动 / 单点查证 / 契约比对 | ≤25k | ≤2 文件 | 改动 + 命令输出 |
| **T2** | 3–5 文件 / 跨层改动 | ≤60k | ≤5 文件 | CTC + 计划 + 测试 |
| **T3** | 模块级 / 十域级 | 分 2 段，每段 ≤60k | 分段提交 | 分段计划 + 每段验收 |

超档即停：先出"降档方案"（拆任务 / 只读摘要 / 委派 subagent），经 PM 确认再继续。

### 6.3 装载协议（四步，禁止跳步）

1. **定位**：`grep` 关键词 / `glob` 文件名 → 得到"文件:行号"清单，**不读内容**。
2. **切片**：`read offset/limit` 只取相关 30–120 行；长文件用两段夹逼。
3. **摘要代理**：>500 行的文件、>1MB 的数据，用脚本先算统计（行数/类数/键数/端点差集），只把统计结果入上下文。
4. **记账**：在回复里列出`[LOAD]`清单，便于 Z1/Z4 审计。

### 6.4 明文禁用清单

- ❌ `tree` 全库 / `Get-ChildItem -Recurse` 全仓列举
- ❌ 读取 `题库/`（662MB）、`backend/app/static/`（4.3GB）的任何文件内容
- ❌ 把 pytest/gate 全量输出原样贴回（只贴尾部 20 行 + 退出码）
- ❌ 重复读同一段落（改完读回验证除外，且只读改动区）
- ❌ "为了保险"预读 10 个不相关文件

### 6.5 前缀稳定性（缓存友好）
固定顺序：**角色声明头 → 事实基线（§1）→ 任务书 → 可变内容**。
稳定前缀命中 prompt cache，等价于把固定开销摊薄到 0。

## §7 工作流骨架 Q0–Q6

| 阶段 | 主导 | 动作 | 退出条件（可命令验证） | 不可跳 |
|---|---|---|---|---|
| **Q0 立项** | PM | 复述任务边界、影响面、预算档；建子分支 | 用户确认 + 分支已建 | 否 |
| **Q1 事实测绘** | ARCH/DATA | grep 定位、装载切片、读基线资产 | `[LOAD]` 清单齐 + 影响文件列表确定 | 小改可裁剪 |
| **Q2 方案** | ARCH + 领域角色 | ≥2 方案对比、ADR、CTC-11 前置思考 | 方案落盘 + 用户批准 | **是** |
| **Q3 契约冻结** | API + SEC + DATA | 端点差集、字段变更单、安全五问 | 差集=∅ 或已批准；SEC 无阻断项 | **是** |
| **Q4 实施** | BE/FE | 一文件一改一验证；`dryRun` 先行 | 每文件改后自检通过 | **是** |
| **Q5 验证** | QA（+SEC 复核） | 跑门禁 + 域内 pytest + 页面实测 | 退出码 0 且关键用例 PASS | **是** |
| **Q6 归档与合并** | DOC + PM | 落盘三件事、提交、向父分支发起合并 | 索引已更新 + PR 指向模块域 | **是** |

### 7.1 与 `li-an-workflow` 五步法的对齐

| li-an-workflow | QBDM |
|---|---|
| ① 规划 | Q0 + Q2 |
| ② 复述 | Q0（复述即边界确认） |
| ③ VTJ 技能 | Q4（FE 角色的强制前置） |
| ④ 逐步验证 | Q4 + Q5 |
| ⑤ 输出摘要归档 | Q6 |

**结论**：QBDM 未新增流程，只把五步法展开成可验证阶段并补上契约/安全/数据三个缺口。

### 7.2 阶段裁剪规则
- 单文件且不触红线：Q1 合并进 Q0，直接 Q2。
- 纯文档任务：Q3/Q4 可合并（无契约、无代码）。
- **Q5、Q6 永远不可跳。**

### 7.3 CTC 11 问的落位
CTC 属于 Q2→Q3 的**放行闸**，由主导角色逐条作答，未答不放行。第 11 问（开源借鉴）必须先 `grep` 本仓是否已有等价实现，再谈外部项目；引入外部依赖须走 `license-checker` 并经用户批准。

## §8 分支拓扑执行细则

### 8.1 模型

```
main                    稳定基线，只接模块域
└── feat/<模块>             模块工作域（如 feat/teacher-administrator），只接子分支
    └── feat/<模块>-<子任务>  子分支（如 feat/teacher-administrator-qbdm-glossary），一分支一任务
```

### 8.2 命名约定（2026-10-25 统一，以此为准）

- **模块工作域**：`feat/<模块>`，如 `feat/teacher-administrator`（仓库既有约定，远端在 `origin`）。
- **子分支**：`feat/<模块>-<子任务简述>`，用 `-` 连接，如 `feat/teacher-administrator-qbdm-glossary`；**不再用 `/` 嵌套**。
- **历史说明**：2026-10-25 曾按 `feature/<模块>/<子任务>` 建过 5 个 QBDM 子分支，已全部合并且改名为 `feat/teacher-administrator-qbdm-*`。此后一律用本约定。

### 8.3 标准命令序列（PowerShell）

```powershell
# 1) 同步父域
git fetch origin
git checkout feat/<模块>
git pull --ff-only
# 2) 开子分支
git checkout -b feat/<模块>-<子任务简述>
# 3) 工作 + 验证（每文件一验证）
python backend/scripts/gates/gate_all.py --quick
cd backend; python -m pytest tests/<域> -q; cd ..
# 4) 提交（一个逻辑变更一个提交）
git add <精确文件>
git commit -m "feat: <简述>"
# 5) 父域有更新时
git fetch origin; git rebase feat/<模块>
# 6) 收尾：只向父域发起合并/PR，禁止直接对 main
```

### 8.4 硬约束

| # | 约束 |
|---|---|
| B1 | 禁止子分支 → `main` 的任何合并/PR |
| B2 | 一子分支一任务；混入无关改动 = 打回 |
| B3 | 提交信息前缀只允许 `feat/fix/test/refactor/docs/chore` |
| B4 | 提交前必须跑改动域测试；失败先修不提交 |
| B5 | 合并顺序：孙 → 子 → 模块域 → main，永不跳层 |
| B6 | `git add -A` 禁用（易带入无关/生成物），必须逐文件 |
| B7 | 大件与密钥不得进提交（`题库/`、`static/`、`.env`） |

## §9 门禁与验收矩阵

| 改动类型 | 必跑门禁 | 必跑测试 | 附加证据 |
|---|---|---|---|
| 后端 API 逻辑 | `gate_l4_api_contract` + `check_module_boundary` | `pytest tests/<域>` | 端点数 = 343（或已批准增量） |
| 题库导入/解析 | `gate_l1_parser` + `gate_l1h_composite_material` + `gate_l3_ingest` | `pytest tests` 相关子集 | 样本题目导入前后对照 |
| 匹配/判题算法 | `gate_l2_matching` | 算法用例 | 命中率/误判率数字 |
| 字段/表结构 | `gate_l1g_field_fingerprint` | 迁移脚本 dry-run | `db_tables.json` 差异 |
| 前端页面 | `gate_l5_frontend_contract` | 页面可开 + 交互自测 | `dryRun` 预览记录 |
| 任何提交前 | `gate_all.py --quick` | 改动域子集 | 退出码 0 |
| 合并到模块域前 | `gate_all.py` 全量 | 全量 pytest | 完整输出尾部 20 行 |

> ⚠️ **全量 pytest 会挂起**（实测：`pytest tests -q` CPU 5 分钟仅 +1.2s 且无输出）。判定"能否合并"时改用
> `python scripts/qbdm/test_sweep.py --suite tests --timeout 90`，拿到 **OK / FAIL / HANG** 三态清单再决策。

### 9.1 三层汇报口径
- **一句话结论**：PASS / FAIL / 部分通过（附未覆盖项）。
- **证据表**：命令 | 退出码 | 关键行。
- **残留风险**：明确列出"没测什么"。

## §12 与 dsh 的映射（工具层）

### 12.1 角色 → subagent 编排

| 场景 | 编排 |
|---|---|
| 单角色单任务 | 内联（不派 subagent，省 token） |
| 两个无共享文件的独立任务 | `subagent` × 2 并行，各带独立角色声明头 |
| 需要本会话上下文的续作 | `subagent_fork` |
| 只读巡查（SEC 扫描 / QA 复核） | subagent 只读，产出报告，不改文件 |

**原则**：subagent 用于**隔离上下文**，不是用于"显得努力"。能内联解决的不派。

### 12.2 技能 ↔ 角色绑定

| 角色 | 必绑技能 |
|---|---|
| PM | `li-an-workflow`、`plan-first-workflow`、`scope-guard`、`writing-plans` |
| ARCH | `brainstorming`、`codebase-design`、`open-source-finder` |
| DATA | `domain-modeling`、`fact-guard` |
| BE | `tdd`/`test-driven-development`、`completion-verifier` |
| API | `fact-guard`、`requesting-code-review` |
| FE | `vtj-frontend`（强制）、`agent-browser`（自测） |
| SEC | `enterprise-compliance-checker`、`license-checker` |
| QA | `completion-verifier`、`systematic-debugging` |
| DOC | `context-rollup`、`token-optimization` |
| 全员 | `context-minimal-loader`、`token-budget-controller`、`instruction-source-guard` |

### 12.3 模型路由

| 模式 | 触发 | 路由 | 约束 |
|---|---|---|---|
| 标准 | 常规 CRUD/重构/文档 | 本地 DeepInfer 优先，云端兜底 | 开 session compaction |
| 创造 | 新架构、组卷/判题算法 | 云端强模型 | 产出必须归档到 `docs/superpowers/specs/` |
| PTC | 语料清洗、题图索引、压测 | 本地沙箱执行 | **大文件绝不入上下文，只传统计结果** |

### 12.4 现状限制（诚实标注）

- MCP 只有 vtj 一个服务；**backend / test / security 三类 MCP 不存在**。当前替代方案 = 直接调 CLI（`gate_all.py`、`pytest`、`check_secrets`），**功能等价，无需等 MCP**。
- dsh 默认模型 `deepseek-flash` + `reasoningEffort: low`：复杂架构讨论建议临时提高档位。
- 宿主级 MCP 的 `cwd` 固定指向本仓库；在别的工作区打开仍会读写本仓。
