## 1. 执行摘要

六个问题不是六件事，而是**同一条链路上的七处断点**：导入把题目塞进 91 个叫「其他」的三级节点 → 接口把 0 题的节点过滤掉、把有题的节点混在 L2 里 → 前端只能展开出满屏「其他」→ 答题时又不把考点写回练习记录 → 记录页只能显示「其他」。

因此本方案的顺序是：**先修数据归属，再修接口语义，最后才改界面**。界面改动一律不改 .vtj 页面的 template（红线 R3），只有两种合规落地路径，见 §9 决策点 D1。

七处断点与对应方案：

| # | 断点（实测） | 方案 | 章节 |
|---|---|---|---|
| R1 | 91 个 L3「其他」承担了 2735 道题的兜底，L2 直挂题几乎为 0 | 新增 is_fallback 标记 + 每科目 1 个「其他（未分类）」收容节点，收 point_id 为 NULL 的 630 题 | M1 |
| R2 | 接口把「其他」当成可下钻子节点返回，前端逐个展开 | 接口返回 drillable 标志；前端无真实子节点时点击直答 | M1/M2 |

| R4 | 知识点进度接口按 L3 聚合，91 个「其他」各占一行 | 过滤 is_fallback，聚合为每科目 1 行 | M4 |
| R5 | docx 里以「下划线格式空白」承载的填空横线在导入时丢失（实证题 3666 只剩一个空格） | 导入侧保留占位符 + 渲染侧 .qr-blank + 存量 30 题人工确认 | M3 |

## 3. 根因链（为什么「一次修复覆盖全部相关」是可能的）

    [导入] 分类失败 → 不写 NULL，而写 L3「其他」 (91 个兜底桶)
         ↓
    [接口] 0 题节点被丢弃 / 有题节点混入 L2 层 / 两条题源口径不同
         ↓
    [前端] 每个 L2 展开 → 子项全叫「其他」；知识点进度 → 每科目几十行「其他」
         ↓
    [答题] 提交时不带考点上下文 → practice_record.scope_* 全 NULL
         ↓
    [记录] 记录页无真实考点可显示 → 回退文案「其他」

关键结论：**「其他」不是显示问题，是分类学问题。** 只改前端文案（把「其他」改成「未分类」）不会让任何一道题变得可下钻。

同理，下划线不是渲染器 bug：渲染器 questionRender.js 全程没有删除下划线的逻辑，实证题 3666 的原始文本里就已经没有横线了。**是数据在导入时丢了。**

错题图片不是接口 bug 单独造成的：键格式不匹配（代码） + 13 个文件确实不存在（数据） + 无尺寸约束（样式），三者叠加。

## 4. 方案正文

### M1 分类治理：把「其他」从兜底桶变成一级收容所

#### M1.1 设计原则（三条，写在代码注释里）

1. **不合并、不改名。** 91 个 L3「其他」已被 question_knowledge 2992 行引用，也已被 220 条错题、318 条练习记录引用。改名或合并会静默改变用户历史进度的归属。
2. **只标记，不搬运。** 给知识加点新增 is_fallback 位，判定为兜底的节点在接口层降级为「不可下钻」，但 id 不变、名称不变。
3. **每科目一个真收容所。** point_id 为 NULL 的 630 道题目前没有家，需要建 3 个科目级「其他（未分类）」节点承接，这才是用户能点进去答题的入口。

#### M1.2 数据变更（幂等、可回滚）

    -- 1) 标记位（无损）
    ALTER TABLE knowledge_point ADD COLUMN is_fallback INTEGER NOT NULL DEFAULT 0;

    -- 2) 判定规则 A：L3 且名称='其他' → is_fallback=1（91 条）
    UPDATE knowledge_point SET is_fallback=1 WHERE level=3 AND name='其他';

    -- 3) 判定规则 B：L3 且名称='其他' 且其 L2 父节点下只有这 1 个子节点 → 该 L2 也是兜底（父节点只有「其他」说明整个子分类没建）
    UPDATE knowledge_point SET is_fallback=1 WHERE level=2 AND id IN (
      SELECT parent_id FROM knowledge_point WHERE is_fallback=1
      GROUP BY parent_id HAVING COUNT(*)=1
    );

    -- 4) 新建 3 个科目级收容节点（parent_id 指向该科目 L2 根或 NULL，取决于现有树）
    INSERT INTO knowledge_point (name, level, subject_id, parent_id, is_fallback, sort_order)
    VALUES ('其他（未分类）', 3, 1, <行测L2根id>, 1, 9999);

真正把 630 道 NULL 题挂上去的动作**不写死**：由 backend/scripts/migrate_v5_classification.py 执行，--dry-run 先打印「将影响 N 题 / N 考点」的对照表，人工核对后才 --apply，并在 apply 前自动调用 sqlite3.backup() 生成 backups/pre_v5_YYYYMMDD_HHMMSS.db（红线 R10）。

回滚：脚本同时输出 rollback_v5.sql（DROP COLUMN 用建新表法 + DELETE 三条 INSERT），文档内贴出完整语句。

#### M1.3 接口语义改造（quick_practice.py）

GET /api/quick-practice/sub-categories?subjectId=  返回结构新增 4 个字段，**旧字段全部保留**（前端可灰度）：

    {
      "id": 14, "name": "治安管理", "level": 2,
      "question_count": 812,
      "drillable": false,            // 新增：false = 该节点下没有可下钻的真实考点
      "fallback_count": 706,          // 新增：其中属于兜底节点的题量
      "children": [                   // 新增：一次性返回三级，前端不再二次请求
        { "point_id": 920, "name": "其他", "question_count": 706,
          "is_fallback": true,  "drillable": false },
        { "point_id": 1006, "name": "治安处罚程序", "question_count": 106,
          "is_fallback": false, "drillable": true }
      ]
    }

四条改动规则：
1. :234 的 if not l3_question_ids: continue 改为——仅当 is_fallback=0 时才跳过；兜底节点即使 0 题也返回（保证「其他」始终可见可点）。
2. :240-246 的 L2 题量拆成 question_count（真实可下钻题）与 fallback_count（兜底题），避免 812 这个数字误导用户以为可以按知识点分层。
3. :269-285 合成的「未分类」条目保留，但改名为「其他（未分类）」并与 3 个新收容节点对齐 id，不再出现两个「其他」。
4. :360-391 统一题源：bySubCategory=true 时先按 sub_category_id 查，再 UNION point_id IN (该子分类下所有 point_id) 的题，最后按 question_id 去重。这样「点科目直答」和「点考点直答」拿到的是同一批题。

#### M1.4 前端表现规则（三条，写进组件注释）

| 节点情形 | 表现 | 交互 |
|---|---|---|
| drillable=true（有真实子考点） | 显示「展开」箭头 + 「N 个考点」 | 点击展开列表，再点考点开始练习 |
| drillable=false 且 question_count>0 | 显示徽标「综合练习 N 题」，不显示箭头 | **点击即答题**（整段练习） |
| question_count=0 | 弱化显示 + 「暂无题目」 | 不可点（aria-disabled） |

一句话：**能下钻的下钻，不能下钻的直接答**。用户永远不会再看到「点开一层全是其他」。

#### M1.5 导入侧兜底（防止问题复发）

backend 的题目导入链路增加一个分类判定函数 classify_or_fallback(...)：
- 能匹配到具体 L3 → 写 point_id + sub_category_id。
- 匹配不到 → point_id 写该科目的「其他（未分类）」id，**绝不写 NULL**，并把原始分类字符串留在 question_bank.raw_category（新增列，仅用于审计与后续人工归类）。
- 同时写一条 audit 记录到 backend/data/audit/fallback_YYYYMMDD.csv（红线 R9 目录），供你随时抽查。

这部分只加函数与调用点，不改既有导入脚本的 CLI（避免破坏你的既有流程）。

### M2 快速练习重构 + 自定义刷题重构

#### M2.1 快速练习：三级真下钻 + 直答

信息架构（从「科目 → 子科目 → 一堆其他」改为「科目 → 子科目 → (考点 | 综合练习)」）：

    行测 / 申论 / 公安专业科目
      └─ 子科目卡片
           ├─ 真实考点列表（可下钻，显示题量）      → 选考点 → 开始练习
           └─ 其他（未分类，N 题）                  → 直接开始练习

性能与稳定性三条硬约束：
1. 每次展开只发 1 个请求（M1.3 已把 children 一次性返回），不出现 N 个并行请求。
2. 展开状态、滚动位置写入 sessionStorage（key: qb.quick.expanded），刷新不丢。
3. 任一请求失败只影响该卡片，展示「加载失败，点击重试」，不整页白屏（三态：加载 skeleton / 空 muted / 错误 badge danger）。

#### M2.2 自定义刷题：从 5 个控件到「可解释的出题器」

现有 5 个控件全部保留（老用户肌肉记忆），新增 5 组，共 10 组，分两屏（基础 / 精准）：

| # | 控件 | 取值 | 说明 |
|---|---|---|---|
| 1 | 练习科目 | 行测/申论/公安 | 保留 |
| 2 | 出题年份 | 近3年/近5年/不限 | 保留 |
| 3 | 子科目 | 动态 | 保留 |
| 4 | 练习数量 | 5–100，默认 20 | 保留 |
| 5 | 练习时间 | 5–180 分钟，0=不限 | 保留 |
| 6 | 题型 | 单选/多选/判断/填空/简答（多选） | 新增 |
| 7 | 难度 | 简单/中等/困难（多选） | 新增 |
| 8 | 考点 | 树形多选（来自 M1 改造后的考点树，兜底节点可选） | 新增 |
| 9 | 题目来源 | 真题/模拟/全部 | 新增 |
| 10 | 智能偏好 | 只练未做过 / 错题优先 / 随机（三选一） | 新增 |

底部固定「出题预估」条：实时调用 GET /api/quick-practice/estimate 显示「当前条件命中 0 / 37 / 200+ 题」，0 题时把按钮置灰并指出是哪一项条件过窄（例如「近3年 + 困难 + 填空 命中 0 题，建议放宽难度」）。这条**是本次改造的核心体验点**——用户不再点了按钮才发现没题。

参数透传链路（必须一次打通，否则又是「其他」）：

    question_bank.vue (customConfig)
      → router.push({ path:'/exercise', query:{ mode:'custom', ...序列化 } })
      → src/views/student/shared/exercise.vue 解析 query
      → GET /api/quick-practice/questions 支持 pointIds/types/difficulties/years/sources/onlyUndone/wrongFirst
      → POST /api/practice/submit 携带 scope（见 M4）

接口新增（向后兼容，参数全可选）：

    GET /api/quick-practice/questions
      ?knowledgePointIds=920,1006   (逗号分隔，含兜底 id 合法)
      &types=1,2  &difficulties=1,2,3  &year=3  &source=all
      &onlyUndone=true  &wrongFirst=false  &limit=20  &bySubCategory=false

    GET /api/quick-practice/estimate  → 同上参数，返回 { count, breakdown:{byType,byDifficulty}, narrowHint }

稳定性三条：
- 出题去重：同一 question_id 在一次练习内不重复，SQL 层用 ROW_NUMBER() 或应用层 set 去重（SQLite 3.x 支持窗口函数）。
- 兜底降级：命中 0 题时，若用户勾了「错题优先」但错题不足，自动补足普通题并在结束页说明「已为你补充 N 道常规题」。
- 参数校验：数量 5–100、时间 0–180，非法值后端 clamp 并返回 usedParams，前端展示实际生效值。

### M3 答题卡填空横线（数据问题，不是样式问题）

#### M3.1 定性

实测：真下划线题 2 道；提到「横线/划线」32 道，其中 30 道原文里**根本没有横线占位符**。题 3666 的入库文本是「…这是编译人员在岗位上 的写照。…填入划横线部分最恰当的一项是：」，横线位置只剩一个空格。
结论：docx 解析器（提问里的「题目需要划线」）在把 Word 的「下划线格式空白 / 带下划线制表位」转文本时把它吞掉了。这是**导入期数据丢失**，渲染器无责（questionRender.js 全文无删横线逻辑）。

置信度说明：题 3666 已逐字核对，置信度高；其余 30 题按同一模式推断（同一批 docx 同一解析器），置信度中——M3.3 要求人工确认。

#### M3.2 修复三件事

1. **渲染侧先兜住**：questionRender.js 增加空白占位增强——连续 ≥2 个空格且位于「填空语境」（前文出现 填入/横线/划线/最恰当/依次填入）时，替换为 span class=qr-blank，CSS 为 inline-block + min-width:3em + border-bottom:1.5px solid currentColor + vertical-align:baseline。这样即使数据只有空格，视觉上也出现横线。
2. **导入侧不再丢**：docx 解析保留下划线 run 的占位，统一写成下划线标记（八位下划线或专用占位符），并写一个 normalize_blank(text) 函数集中处理，避免各导入脚本各写一套。

#### M5.4 艾宾浩斯复习提醒

新表（新建，不动既有表）：

    CREATE TABLE wrong_review_schedule (
      id INTEGER PRIMARY KEY AUTOINCREMENT,
      user_id INTEGER NOT NULL,
      wrong_id INTEGER NOT NULL,
      stage INTEGER NOT NULL DEFAULT 0,        -- 0..6，对应 1/2/4/7/15/30/60 天
      next_review_date DATE NOT NULL,
      last_reviewed_at DATETIME,
      review_count INTEGER DEFAULT 0,
      correct_streak INTEGER DEFAULT 0,
      is_mastered INTEGER DEFAULT 0,
      created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
      UNIQUE(user_id, wrong_id)
    );
    CREATE INDEX idx_wrs_due ON wrong_review_schedule(user_id, is_mastered, next_review_date);

间隔序列：1、2、4、7、15、30、60 天（stage 0–6）。答对 streak+1 并升一级；答错 stage 回 0（次日再来），streak 清零；stage 到 7 判定 is_mastered=1 并停止提醒。

触发点：
- 写入时机：题目首次进错题集时创建 schedule（next_review = 次日）；复习答对/答错后更新。
- 生成时机：不跑定时任务（避免多进程重复触发），改为**查询时惰性补算**——GET /api/wrong-questions/review-due 时按 next_review_date <= today 取，并顺带把过期未复习的记录 computed_stage 展示为「延迟 N 天」。
- 提醒通道（分阶段）：① 错题集页面顶部横幅「今天有 N 道待复习」；② 题库页/首页角标；③ 站内消息（复用现有通知表，若无则先只做横幅）。**不做短信/邮件**（无通道，避免假功能）。

接口：

    GET  /api/wrong-questions/review-due?date=2026-11-14
         → { count, items:[{wrong_id, question_id, stage, due_date, overdue_days}] }
    POST /api/wrong-questions/{wrong_id}/review   body:{ is_correct }
         → { stage, next_review_date, correct_streak, is_mastered }

## 6. 验收标准（可量化，不达标即未完成）

### 6.1 数据层

| # | 标准 | 验证命令 |
|---|---|---|
| A1 | 题量守恒：迁移前后 question_bank 总数均为 3750 | SELECT COUNT(*) FROM question_bank; |
| A2 | point_id 为 NULL 的题从 630 降为 0 | SELECT COUNT(*) FROM question_bank WHERE point_id IS NULL; |
| A3 | 兜底节点数：is_fallback=1 的 L3 由 91 个「其他」收敛为「≤91 存量标记 + 3 个新建收容节点」，且 3 个收容节点题量之和 = 630 | SELECT point_id, COUNT(*) FROM question_bank WHERE point_id IN (新增3个id) GROUP BY 1; |
| A4 | 脏引用仍为 0（point_id 不存在于 knowledge_point） | SELECT COUNT(*) FROM question_bank q LEFT JOIN knowledge_point k ON q.point_id=k.id WHERE q.point_id IS NOT NULL AND k.id IS NULL; |

### 6.2 接口层

| # | 标准 |
|---|---|
| B1 | /sub-categories 对每个科目返回的 children 中，is_fallback=true 的节点数 ≤ 1（每子科目），且 drillable=false |
| B2 | /questions 与 /questions?bySubCategory=true 对同一子科目返回的 question_id 集合完全一致（去重后） |
| B3 | /estimate 的 count 与 /questions 实际返回条数一致（limit ≥ count 时） |
| B4 | 提交练习后 practice_record.scope_name 非空率 = 100%（新数据） |
| B5 | 错题详情对含材料的题返回 material.shared_content，长度与 question_groups 一致 |
| B6 | 图片接口返回的 image_map 键与题干 [IMAGE:hash_seq_idx] 的 hash_seq 完全匹配率 = 100% |
| B7 | /review-due 按 next_review_date 正确筛选；答对升 stage、答错回 0 |
| B8 | /study-calendar 返回的 days 长度 = 当月天数，签到的 checked_in 与 daily_checkin 一致（抽样 5 天核对） |

### 6.3 界面层（手工走查清单，逐条截图留证）

1. 快速练习：进入任一科目 → 子科目卡片显示「N 个考点」或「综合练习 N 题」→ 后者点击直接进入答题，**不出现点击后全是「其他」**。
2. 自定义刷题：选「近3年 + 困难 + 填空」→ 预估显示 0 并给出放宽建议 → 放宽后预估 >0 → 开始答题。
3. 答题卡：题 3666（编译工作那道）横线可见；题干长图不溢出。
4. 练习记录：考点列显示真实名称，无满屏「其他」。
5. 错题集：申论错题（wrong_id 164）能看到材料区 + 「暂无解析」提示；图片缺图显示占位块而非裂图；搜索框输入关键词能过滤。
6. 联考小智：PC 题库页点击 → 进入聊天页，能发一条消息并收到回复（或 503 友好提示）。
7. 学习日历：题库页卡片显示连续签到、本月热度、考试倒计时，点签到就地生效。

## 8. 需要你审批的决策点（D1–D6）

### D1 题库页新模块怎么落地（最关键）

题库页 question_bank.vue 是 .vtj 页面，template 禁止 AI 直改。三条路径：

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A | 你在设计器里拖拽出占位容器，我改 script 对接 | 最合规 | 需要你操作，节奏受你时间 |
| **B（推荐）** | 我通过 vtj_write_dsl_file 只**插入一个节点**（学习日历卡片容器 + 自定义刷题扩展区），等价于设计器拖拽的 JSON 结果，先 dryRun 再应用，应用后你在设计器复核一次 | 我能一次做完，不占用你时间 | 属于「等价改 template」，需你明确授权，且复核不可省 |
| C | 新建手写页 /practice-hub 承载日历与新出题器，题库页只加一行 script 跳转 | 零 template 风险 | 用户要「在题库页面中显示」，整页跳转削减体验 |

**我的建议：B + C 混合**——日历卡片与出题器用 B 插入节点（少量、结构简单），复杂交互（热力图、材料区）用 C 独立手写页，避免大块结构改动。

### D2 「其他」治理强度

| 选项 | 做法 | 影响 |
|---|---|---|
| **D2-a（推荐）** | 只标记不合并（本方案 M1），630 道 NULL 题进 3 个收容节点 | 91 个「其他」保留在数据里，但前端按 drillable 隐藏，用户看不到满屏其他；零迁移风险 |
| D2-b | 把 91 个「其他」合并为每科目 1 个，630 题与 2735 题全部归并 | 数据最干净 | 需重写 question_knowledge 2992 行引用，历史进度归属会变，风险高 |

### D3 艾宾浩斯参数

建议 1/2/4/7/15/30/60 天，答错回 0 级。你若有教研侧的既定参数（例如只到 30 天），我按你的来。

### D4 是否允许真实 LLM 联通验证

根 .env 已有 DEEPSEEK_API_KEY。允许 → 我跑 1 次真实对话验证联考小智端到端可用（消耗少量 token）；不允许 → 只做 mock 验证 + 密钥缺失降级路径验证。

### D5 历史 318 条练习记录是否回填 scope

回填 → 记录页历史数据也显示真实考点（按题目反查）；不回填 → 历史显示「未分类（历史数据）」，只有新数据准确。建议**回填**（可 dry-run 看覆盖率）。

### D6 错题集是否替换为手写新页

现状 wrong_questions.vue 2801 行、96767B。方案：先在其 script 内改造（P5），若改造中发现模板结构限制导致材料区/热力区塞不进去，则新建 /wrong-book 手写页并保留旧页一个版本周期。请你预先授权这个 fallback。

## 9. 明确不做的事（防止范围蔓延）

1. 不动 .vtj/ 目录结构、不改 mobile_*/tablet_* 文件名（红线 R1/R5）。
2. 不删除题库/ 与 backend/app/static/（红线 R6/R7）。
3. 不改 /api/v1 已有路径（只加可选参数与新端点，红线 R11）。
4. 不代写申论答案、不代补缺失图片。
5. 不做短信/邮件/微信推送提醒（无通道）。
6. 不重构目录分层（那是 P3B 的活，与本方案并行会冲突，AGENTS.md §6）。
7. 不为了「看起来 AI」而造假数据：掌握度样本 <3 时明确写「样本不足」。
