# 容器化 P6 生产切换准备 报告 v1

## 1. 结论

P6 的目标是「把 staging 已验证的编排变成可交付给学校服务器的生产切换包」，不是在本机完成真实生产上线。本轮已交付：生产环境模板、发布/回滚脚本、占位符与密钥预检、生产切换 Runbook，并用临时 production env 完成 `release.sh --dry-run` 与 `docker compose config` 验证。

未执行的部分必须明确：未连接真实 registry 拉取生产镜像，未在 `/srv/liankao` 做真实迁移，未在真实域名/学校网关上切换，未实测 RTO/RPO。

## 2. 交付物

| 文件 | 作用 |
|---|---|
| `deploy/.env.production.example` | 生产环境模板：`/srv/liankao` 数据根、`IMAGE_TAG`、JWT、TLS 模式、OCR 开关 |
| `deploy/release.sh` | 发布入口：preflight → checkpoint → backup → pull/build → up → healthy → smoke，失败回滚上一 tag |
| `deploy/preflight.sh`（增强） | 拒绝 `latest`/`CHANGE_ME*`/`REPLACE_*` 的 `IMAGE_TAG` 与 JWT；compose 路径用 `cygpath` 兼容 Git Bash |
| `docs/ops/容器化生产切换Runbook_v1.md` | 切换前检查、数据迁移、首次启动、烟测、DNS、24h 观察、回滚、RTO/RPO、禁止事项 |

复用的既有资产：`deploy/docker-compose.yml`、`deploy/Dockerfile.web`、`backend/Dockerfile`、`deploy/nginx.conf`、`deploy/nginx.tls.conf`、`deploy/docker-compose.tls.yml`、`deploy/{checkpoint,backup,restore,inspect}.sh`、`.github/workflows/container-ci.yml`。

## 3. 设计决策

1. **生产仍为 web + backend 两容器**：SQLite 不容器化，数据根固定 `/srv/liankao`；parser 仅 `--profile ocr` 启动。
2. **镜像 tag 强制显式**：禁止 `latest`，回滚才能确定；模板值 `CHANGE_ME_VERSION` 会被 preflight 拒绝。
3. **发布前强制 checkpoint + backup**：`release.sh` 默认调用 `checkpoint.sh` 与 `backup.sh`；`--skip-backup` 仅用于演练并会打印警告。
4. **失败自动回滚镜像 tag**：`deploy()` 失败时用 `PREV=$(current_tag)` 重新 `up` 并烟测；数据回滚不自动执行，必须人工确认后 `restore.sh`。
5. **TLS 默认交给学校网关**：`TLS_MODE=gateway`，容器只监听 8080；需要容器内 TLS 时叠加 `docker-compose.tls.yml` 与证书目录。
6. **配置外置**：`.env.production` 与证书私钥均被 `.gitignore` 忽略；镜像内不含密钥。

### 4.2 预检失败路径

- 无 `deploy/.env.production` 时：`环境文件不存在`，退出 2。
- JWT 为示例占位符（`your-...`）时：`JWT_SECRET_KEY 仍是示例占位符`。
- `IMAGE_TAG=latest` 或 `CHANGE_ME_VERSION` 时：release 在 preflight 前即拒绝。

### 4.3 dry-run 成功路径

用临时 `deploy/.env.production`（`IMAGE_TAG=20261031-p6test`、`HTTP_PORT=18080`、JWT 为临时随机值、数据目录指向 staging）执行：

## 5. 与七条硬约束的对应

| 约束 | P6 落实 |
|---|---|
| 安全左移/默认不信任 | preflight 拒绝占位符；密钥外置；容器 read_only/cap_drop/no-new-privileges 沿用 |
| 资源与生命周期 | compose limits 沿用；parser 仅 profile；禁止 `down -v` 写入 Runbook |
| 数据与状态 | 数据根 `/srv/liankao`；迁移用 `sqlite3.backup()`；发布前 checkpoint |
| 网络可控 | 仅 web 暴露 HTTP_PORT；backend/parser 走 internal；TLS 由网关或 overlay |
| 不可变交付 | 镜像 tag 显式；配置外置；`release.sh` 只 `up` 不现场改容器 |
| 可观测 | 复用 `/health`、`/healthz`、`/health/foundation`、`inspect.sh`；Runbook 规定 24h 观察 |
| 协作变更 | GitHub 手册 + CI；发布脚本与 Runbook 固化流程 |

## 6. 风险

| # | 风险 | 等级 | 缓解 |
|---|---|---|---|
| P6-R1 | 首次迁移直接 `cp` 数据库导致 WAL 丢事务 | 高 | Runbook 强制 `sqlite3.backup()`；发布前 checkpoint |
| P6-R2 | 目录属主不是 1000，backend 无法写库 | 高 | preflight 检查可写；Runbook §3 |
| P6-R3 | 无 registry，服务器只能本地构建 | 中 | `release.sh --build`；或离线 `docker save/load` |
| P6-R4 | 学校网关未保留 Host/上传大小/超时 | 中 | Runbook §8 明确 200 MB、900s、Host 透传 |
| P6-R5 | 回滚只回镜像不回数据 | 中 | 数据损坏时人工 `restore.sh`；Runbook §10.2 |
| P6-R6 | `HTTPS_PORT` 在 gateway 模式下未使用 | 低 | 模板注释说明；overlay 才发布 8443 |

## 7. 回滚

- 代码/文档：P6 为新增文件与文档，回滚即 `git revert` 本提交。
- 运行：`IMAGE_TAG=<上一版本> docker compose ... up -d --no-build web backend`。
- 数据：`ENV_FILE=.env.production bash deploy/restore.sh --latest --yes`，恢复前自动快照。
