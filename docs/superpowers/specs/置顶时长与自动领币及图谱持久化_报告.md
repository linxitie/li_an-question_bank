## 2. 接口契约

```
POST /api/teacher/forum/posts/{post_id}/pin
  body { pinned: bool = true, days?: int 0..365 }   # 0/缺省 = 永久；1/3/7/30 由前端给
  200 { success, isTop, pinUntil, pinDays }
  403 只能置顶自己的帖子或本班学生的帖子 / 非教师
  404 帖子不存在

GET  /api/knowledge/kg/layout?mode=mine|global
  200 { mode, total, nodes:[{point_id,x,y}] }
PUT  /api/knowledge/kg/layout
  body { mode: mine|global, nodes:[{point_id,x,y}], reset?: bool }
  200 { success, mode, reset, saved|deleted, total }
  400 nodes 为空且未传 reset / 超过 3000 节点

POST /api/plan/task/{goal_id}/toggle
  200 { goal_id, is_completed, coin_claimed, auto_claimed_coins, balance }
```

## 3. 影响面与设计取舍

1. **三端 DTO**：_serialize_post() 早已输出 isTop + pinUntil，学生端（PC/平板/手机）无需改契约即可继续显示「置顶」徽标；教师列表额外拿到 canPin（后端算好，避免前端硬编码权限）。学生端**不显示到期日**——那需要改 .vtj 模板，按 R3 由设计器处理。
2. **权限**：教师可置顶「自己的帖子 / 本班学生的帖子」，管理员不限；学生调用返回 403（require_teacher_or_admin 拦在入口）。
3. **幂等**：计划任务靠 coin_claimed，取消勾选再勾选不会重复发币（有测试）；图谱坐标靠 (user_id, mode, point_id) 唯一键 upsert。
4. **存储**：kg_node_layout 由启动时 Base.metadata.create_all 自动建表（新表，无需 ALTER 迁移）；不设 knowledge_point 外键，避免知识点被清理后布局写入失败（孤儿行无害）。
5. **兜底窗口**：自动补发只回溯 **30 天**内的已完成任务，避免一次性把历史任务全刷成金币。
6. **教师端是否保留「永久置顶」**：保留（与管理端同一套档位）。若要收紧为「永久置顶只给管理员」，前端去掉一档 + 后端对教师 days<=0 返回 403，本轮**未做**，等你拍板。
