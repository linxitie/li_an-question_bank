## 3. 写码前 11 问（本批的实际回答）

| 问题 | 回答 |
|---|---|
| 为什么这样写 | 新增 `/my` 而非放宽 admin 端点，权限边界不混；建卡走同一个 `_validate_material_body` 与 sanitizer，不产生第二套校验 |
| 好处 | 三角色可建卡但不影响管理端权限；`status=2` 让"我的库"零新表实现 |
| 安全 | `creator_id` 服务端强制；改/删校验 `creator_id` 或 admin；私有卡不进公共查询（`==1` 已硬编码） |
| 运维便利 | 软删可追溯；`_audit` 记录 my_create/update/delete；索引 `(creator_id,status)` 支撑"我的库"分页 |
| 未来扩展 | `source_material_id` 已为 B2 分享/领取预留；`scope` 留给"同机构" |
| 文件位置 | ✅ `materials.py`（资料域唯一入口）+ `material_deduplicator.py`（去重唯一入口） |
| 前端能否显示 | 手机页加「我的」chips 即可见；PC 需 B5 拖 chips |
| 后端字段 | 已补齐 `status` 语义与 `source_material_id`；迁移脚本已提供 |
| 路由注册 | 5 个端点均在既有 router 下，随 `include_router` 生效；已实测 200 |
| 接口闭环 | 建 → 列 → 改（含 publish）→ 删 四件齐；配图：批量上传 → 拿到 URL → 写入 `cover_image`/`content` |
| VTJ 版本 | 本批不动前端框架，不涉及 |

```
8) 非图片:   400 仅支持 png/jpg/webp 图片      ← 原子校验生效
9) 清理:     200 {"ok": true}（软删 status=-1）
```
