# 管理员端头像与回收站批量注销体验设计 v1

- 状态：✅ 已实施并验收（2026-11-03）
- 适用模块：管理员端「用户与权限」工作台
- 关联需求：m12579（回收站批量彻底删除、真实头像、创新交互、合并 main）
- 关联红线：R7（`backend/app/static/` 禁止误删）、R10（数据库备份）

## 1. 问题与根因

| 现象 | 根因 | 证据 |
|---|---|---|
| 用户列表头像只有首字母 | 后端 `_format_user` 未返回 `avatar`，前端模板固定渲染首字母，未使用该字段 | `backend/app/api/v1/platform/admin.py:168`、`src/views/admin/pc/AdminUsersWorkspace.vue:108` |
| 回收站不能批量彻底删除 | 批量端点 allowed 集合无 `purge`；前端回收站批量栏只有恢复 | `backend/app/api/v1/platform/admin.py:920-925`、WorkSpace:75-84 |
| 生产题图被每日任务误删 | 清理函数只按文件名形态 + mtime 删除 `app/static/questions` 根目录，没有数据库引用保护 | `backend/app/services/question_ingest/images.py:517-552`、`scheduler.py:237-250` |

## 2. 目标与非目标

目标：
1. 有头像的用户显示真实图片，加载失败/无头像时回退首字母，绝不裂图。
2. 回收站支持批量彻底注销（匿名化），带影响面预览与二次确认。
3. 头像可点开资料卡，集中查看角色、院系、联系方式、最近登录。
4. 修复暂存图清理误删生产图，保证 R7。

非目标：
- 不引入对象存储或新表。
- 不做物理删除用户行；保留 user_id 墓碑，保证题目/试卷/考试记录不悬空。
- 不改变现有角色/权限模型。

## 3. 设计决策

### D1 头像：数据库为唯一真源，前端双保险
- API 继续使用 `sys_user.avatar`，值可能是 `/uploads/...` 或外链。
- 前端 `<img>` 加载成功显示；`@error` 标记该用户+URL 失败并回退首字母。
- 头像点击打开资料卡，避免离开列表即可核对账号。

### D2 批量彻底注销：只对回收站、只超管、不可逆
- 新增 batch action `purge`，仅 `role_level >= 3`；目标必须 `is_deleted == 1`。
- 复用单用户 purge 的匿名化逻辑：username/user_no 改 `deleted_{id}`，清 PII/设备/头像，撤销权限覆盖，`is_deleted=2`。
- 前端批量栏在回收站态显示「批量彻底删除」；弹窗必须输入固定词「彻底删除」+ 原因（≥2 字）。
- 展示已选人数、其中管理员人数；服务端再次校验数量、越级、本人、最后超管。

### D3 影响面预览与审计
- 批量弹窗显示：已选 N 人 / 管理员 M 人 / 不可逆说明。
- 审计记录包含 action、人数、原因、batch_id。
- 失败整批拒绝，避免部分成功。

### D4 暂存图清理：数据库引用保护
- 清理前收集题目 stem/options/answer_analysis 与题组 shared_content/shared_content_images 中出现的
  `/static/questions/*.png` 与 `[IMAGE:*]` 文件名。
- 命中引用的文件一律跳过；收集失败则整轮不删除（fail-closed）。
- 仅删除未被引用且超过 7 天的扁平暂存图。

### D5 无障碍与一致性
- 头像按钮有 `aria-label`；资料卡与批量弹窗用 `role="dialog"` + `aria-modal`。
- 所有可交互元素保留 `:focus-visible` 焦点环；危险按钮仅超管可见。
- 不新增硬编码颜色，沿用页面 CSS 变量。

## 4. 交互流程

1. 列表加载 → 头像 `<img>` 或首字母；点击头像 → 资料卡。
2. 勾选用户 → 回收站态批量栏出现「批量恢复」「批量彻底删除」。
3. 点击彻底删除 → 弹窗显示影响面 → 输入原因 + 「彻底删除」→ 提交。
4. 成功 → toast + 刷新列表；失败 → 展示服务端原因，不关闭弹窗。
