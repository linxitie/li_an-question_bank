# 学习计划「大模型返回错误（401）」与 `POST /api/plan/generate 503` 修复报告

- 日期：2026-10-31
- 模块：学习计划智能推荐（`backend/app/api/v1/growth/study_plan.py`）+ 大模型客户端（`backend/app/services/llm_client.py`）
- 结论：**配置读取缺陷**——后端拿不到 DeepSeek 密钥，带着 `Bearer None` 请求上游，DeepSeek 回 401，路由层把任何 `LLMClientError` 都映射为 503

## 1. 现象

| 层 | 现象 |
|---|---|
| 前端 | 「大模型返回错误（401）」 |
| 后端访问日志 | `"POST /api/plan/generate HTTP/1.1" 503 Service Unavailable` |
| 响应体 | `{"success":false,"detail":"大模型返回错误（401）","error":{"code":"SERVICE_UNAVAILABLE"}}` |

## 2. 根因（三层叠加）

1. **密钥名不匹配**：仓库根 `.env` 里存的是 `DEEPSEEK_API_KEY=sk-…`（实测有效，`GET https://api.deepseek.com/models` 返回 200），
   而 `backend/app/core/config.py` 只声明 `LLM_API_KEY`（`env="LLM_API_KEY"`）→ 两者互不相认。
2. **文件位置不匹配**：`Settings.Config.env_file = ".env"` 只读启动目录下的 `.env`；后端从 `backend/` 启动，
   因此只找 `backend/.env`，而该文件当时**不存在**（只有 `.env.example`）→ 根目录那份 `.env` 永远不会被加载。
3. **默认值自相矛盾（历史遗留）**：`config.py` 里「大模型配置」块出现两次，后一块覆盖前一块默认值
   （`http://localhost:8080/api/v1/chat` 被改成 `https://api.deepseek.com/v1`）。改前一处不生效，排查时极易误判。

链路：`settings.LLM_API_KEY is None` → `llm_client._post` 发送 `Authorization: Bearer None` → DeepSeek 返回 **401** →
`LLMClientError("大模型返回错误（401）")` → `study_plan.generate_plan` 统一 `raise HTTPException(503, e.message)`。

## 3. 修复内容

| 文件 | 改动 |
|---|---|
| `backend/app/core/config.py` | ① `LLM_API_KEY` 改用 `AliasChoices("LLM_API_KEY", "DEEPSEEK_API_KEY")`，两种密钥名都认；② `env_file = (".env", "../.env")`，同时读 `backend/.env` 与仓库根 `.env`（两种启动目录都覆盖，文件缺失时 pydantic 忽略、不报错）；③ 删除重复的大模型配置块，只留一处；④ 默认 `LLM_API_URL` 统一为 `https://api.deepseek.com/v1` |
| `backend/app/services/llm_client.py` | ① 发请求前校验密钥：缺失/仍是 `<占位符>` 时直接抛 `LLMClientError("未配置大模型密钥…", "llm_no_key")`，不再把 `Bearer None` 打到上游；② 上游 401/403 单独映射为 `llm_unauthorized`，文案指明「API Key 无效、过期或无权限」，与通用 `llm_bad_status` 区分 |
| `backend/tests/test_llm_client_config.py`（新增） | 4 条回归：缺密钥 → `llm_no_key`；占位符密钥 → `llm_no_key`；上游 401 → `llm_unauthorized`；正常密钥 → `Authorization: Bearer <key>` 且返回内容 |

## 4. 验证（实测输出）

| 检查 | 结果 |
|---|---|
| 根 `.env` 密钥有效性（不打印密钥） | `GET api.deepseek.com/models` → **200** |
| `settings.LLM_API_KEY` 加载 | `loaded: True, len: 35, prefix: sk-***` |
| `settings.LLM_API_URL` | `https://api.deepseek.com/v1` |
| 注册学生 → 登录 → `POST /api/plan/generate`（exam_date=2026-12-20、行测、2h、入门） | **200**，返回 `plan_id`、`days_left=49`、`task_count=4`、3 个阶段与任务列表 |
| `pytest tests/test_llm_client_config.py` | **4 passed** |

## 5. 运行态注意

- **必须重启后端**：`Settings` 在导入期求值，改 `.env`/`config.py` 后 uvicorn 需重启；本机已按 `--reload` 启动（`start_system.bat` 亦已补 `--reload`）。
- 密钥来源：本次复用仓库根 `.env` 中**用户自己**的 `DEEPSEEK_API_KEY`，未新增、未复制、未打印密钥值；`.env` 已被 `.gitignore` 排除。
- 容器部署：`deploy/docker-compose.yml` 通过 `env_file` 注入，需在部署环境变量中提供 `LLM_API_KEY`（或 `DEEPSEEK_API_KEY`），镜像内不读仓库根 `.env`。

## 6. 遗留风险

| 项 | 说明 |
|---|---|
| `JWT_SECRET_KEY` 仍为默认占位值 | `backend/.env` 不存在，`config.py` 落到 `"your-secret-key-here-must-be-at-least-32-characters"`；同时 `DEBUG=True` 会启用弱口令演示账号。建议用户本人生成并写入 `backend/.env`（命令见 `.env.example` 第 20 行注释） |
| `.env.example` 中含历史泄露的 `JWT_SECRET_KEY` 值 | 该值注释标明「已泄露并轮换」，仍留在模板文件中，属二次暴露面；建议后续替换为占位符 |
| 上游 401 之外的其他非 200 | 仍走 `llm_bad_status`（503），属预期；如需区分 429 限流，可再细分 |
