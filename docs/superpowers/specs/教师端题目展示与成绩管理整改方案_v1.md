## 0. 结论摘要

本轮问题不是单点样式问题，而是 **四条链路同时断开**：

1. **导入解析链路**：申论“要求”已解析但编辑层丢失；多题页面被章节标题正则误切，只入库 1 题。
2. **内容渲染链路**：图片、公式、表格、答案解析没有统一渲染契约；部分页面用 v-html，部分用 textarea 原样显示 <img src="data:...">。
3. **材料组织链路**：材料以整块 material_text 存储，未按“材料1/资料2”切段；材料面板只在部分页面注入，未形成统一组件。
4. **教师工作台链路**：成绩管理与数据分析是两页、两套口径；试卷编辑器左右栏未 1:1、左栏只取 50 题、题型/知识点筛选与真实数据不一致。

**本方案的选择**：

- **不改任何 raw 页面 template**（R3）。布局级改造用**新建手写页**；只读展示用**脚本挂载 + 统一渲染器**。
- **新增 2 个手写页**：TeacherScoresWorkspace.vue（成绩管理合并）、TeacherPaperEditor.vue（1:1 试卷编辑工作台）。
- **新增 1 个共享渲染层**：QuestionRenderService + MaterialBlock + AnswerAnalysisBlock，教师/管理/学生三端共用。
- **新增 1 条 OCR 审阅管线**：图片先落资产、再识别、再人工确认，原位替换，不静默改题。
- **零新表**；OCR 缓存用 backend/data/ocr_cache/<sha256>.json，避免迁移风险。

**推荐审批组合**：基础整改 P0–P7 全做；创新点 I1–I5、I7 先做，I6/I8 作为第二阶段，I9/I10 观察后再定。

## 4. 设计决策（ADR）

### D1：raw 页零模板改动，布局改造走新页

**备选**：
- 方案 A：申请一次性修改 raw 模板（快，但违反 R3，设计器回存会覆盖）。
- 方案 B：全部新建手写页（干净，但工作量大）。
- 方案 C（选定）：**只读展示用脚本挂载；布局级改造新建 2 个手写页**。

**理由**：R3 是硬红线；脚本挂载对只读展示足够；成绩合并与 1:1 编辑器属于布局级，必须新页。新页可独立测试、可回退，不与 VTJ 设计器冲突。

### D2：统一渲染契约，禁止页面各自拼 HTML

新增 src/utils/questionRenderService.js（或扩展现有 questionRender.js）：

~~~
renderField(kind, raw, options) -> { html, plain, images, formulas, warnings }
kind: question | option | answer | analysis | material | requirement
options: { role: 'teacher'|'admin'|'student', stripInlineOption, highlightMaterial, maxImageWidth }
~~~

所有页面只消费该函数；禁止 v-html="q.answer_analysis" 直接输出。

### D3：材料按“语义块”切分，不按固定字数

切分规则（按优先级）：

1. 行首 材料[一二三四五六七八九十0-9]+[：:、.．]? / 资料[一二三四五六七八九十0-9]+ / 给定资料[一二三四五六七八九十0-9]+。
2. 行首 （[一二三四五六七八九十]+） 且后接材料正文。
3. 连续空行 + 长度 > 80 字的段落。
4. 无标记时整块作为“材料”。

输出结构：

~~~json
{
  "segments": [
    { "key": "材料1", "title": "材料1", "html": "...", "plain": "...", "anchor": "mat-1" }
  ],
  "hasMarkers": true,
  "warnings": []
}
~~~

视觉规范：标题胶囊高亮（主色 #1A3C6D 底/白字或浅底深字，按角色主题）、段间 16px、材料间 24px、首行缩进 2em、图片最大宽 100%、表格可横向滚动。

### D4：“要求”是一等字段

- 数据：requirements 存数组；兼容历史字符串。
- 编辑：导入预览/教师/管理编辑弹窗都提供“要求”多行编辑器（按行拆数组）。
- 保存：saveEdit 必须回写 requirements；父组件 payload 带 requirements。
- 展示：题干下方独立“要求”块，不拼进题干。
- 存量：脚本从 question_content 尾部“要求：…”反向拆出，dry-run 后 apply。

### D5：图片先资产化，再 OCR，再人工确认

流程：

~~~
原始内容
  → 提取 <img>/[IMAGE:]/data URI
  → 落盘 /static/questions/...（已有 images.py）
  → 分类：文字小图 / 公式 / 表格 / 图表 / 装饰图
  → OCR（recognize_image_enhanced）
  → 生成审阅项（原图 + 识别文本 + 置信度 + 位置）
  → 教师确认/修改
  → 原位替换为文本/公式/表格；图表默认保留图片
~~~

**不静默替换**：置信度 < 0.9、文本 > 200 字、公式/表格一律人工确认。原图保留在 media_assets，可回退。

### D6：成绩管理合并为单页 + Tab

TeacherScoresWorkspace.vue：

- 顶部作用域：全校 / 本班（教师带班） / 指定班级。
- Tab：总览、班级对比、知识点、错题、学生。
- 总览：参考人数、平均分、及格率、优秀率、最高/最低；分数段柱状图。
- 班级对比：班级平均分柱状图 + 班级选择；点击柱下钻学生表。
- 知识点：雷达图 + 掌握度条；悬浮显示考点、题量、正确率、代表题。
- 错题：主要错题类型 TOP5 + 代表题 + 错误率。
- 学生：表格 + 单学生趋势/各题正确率。
- 建议卡：规则模板（如“知识点 X 正确率 42%，低于年级 18 个百分点，建议 10 分钟讲评题 1234/1235”），每条带证据链接。

### D7：试卷编辑 1:1 工作台

TeacherPaperEditor.vue：

- CSS Grid：grid-template-columns: minmax(420px, 1fr) minmax(420px, 1fr)，中间可拖拽分隔条（8px）。
- 左栏：虚拟列表（每屏 ≤ 60 DOM 节点），分页 50/次，滚动到底自动加载；显示题干摘要、题型、难度、知识点、组徽标。
- 右栏：本卷题目，粘性统计条（题数/总分），支持上下移、删除、换一题、分组显示、分数编辑。
- 添加：单击勾选 + 批量添加；若题属于题组，弹窗询问“整组加入/仅此题”，默认整组。
- 筛选：科目/题型/难度/知识点（来自 /api/questions/taxonomy，全量 level 2/3/4，与学生端同源）；删除填空题/情境题；题型从 DB distinct 生成。
- 搜索历史：localStorage 最近 10 条；筛选预设 5 条。
- 预览抽屉：统一渲染题干、材料、选项、答案、解析、图片；支持打印。

### D8：题型/知识点以数据库与学生端同源为准

- /api/teacher/question-types 改为查 question_type distinct，不再硬编码。
- /api/teacher/knowledge-points 改为复用 /api/questions/taxonomy 的全量考点（level 2/3/4 + 父子关系），不再只返回“有可见题的 L3”。
- 前端筛选显示“全部知识点”时先加载全量，按科目懒加载。
