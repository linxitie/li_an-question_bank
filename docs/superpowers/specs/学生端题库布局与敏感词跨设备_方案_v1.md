## 1. 结论先行

1. 题库没有稳定信息架构：PC 用旧补丁把任务/工具塞进左栏，平板又是另一套三栏。目标是“左任务、中操作+分类、右统计”，卡片参数沿用现有值。

## 4. 任务列表口径修复

### 4.1 根因

- 计划任务用 goal_type=CUSTOM 且 target_count=1；
- GoalCard 不区分来源；
- 进度服务把计划任务当每日目标自动完成；
- 历史数据已写坏（同一秒批量完成、100% 与练习量不符）。

### 4.2 修复

1. 后端分源：`GET /api/goals/` 增加 `scope=user|plan|all`（默认 user，排除 `plan_id IS NOT NULL`）；返回补 `source/plan_id/task_date`。计划任务只由 `/api/plan/current` 和 `/api/plan/task/{id}/toggle` 管理。

3. 前端：GoalCard 的“自定义任务”只请求 scope=user，改名“我的目标”；新增“学习计划”入口；计划任务卡片隐藏 +1/标记完成，改为“去计划页勾选”。
4. 数据修复（需批准）：新增 `backend/scripts/maintenance/fix_goal_completion_20261123.py`，默认 dry-run；识别 `plan_id IS NOT NULL AND is_completed=1 AND reward_coins > coin_reward`（旧自动完成特征），重置完成态但保留 coin_claimed 和已发金币；写前用 `sqlite3.backup()` 备份。
5. 普通 DAILY 目标先出审计报表：按 `practice_record.practice_date` 重算 expected_current，列出 current 不一致项；本轮不自动改，等你确认口径。

## 5. 敏感词知识库跨设备

### 5.1 目标

任一设备新增/修改词条后，导出快照 → 提交 Git → 其他设备拉取 + 导入生效；本机手工修改不被静默覆盖；导入后 DFA 立即 reload。

### 5.2 方案

1. 快照文件：`backend/data/content_guard/lexicon_snapshot.json`（随仓库）
   - `{schema_version, generated_at, revision, policies:[...], terms:[{term,normalized,level,category,weight,confidence,status,note,policy_code,variants:[...]}]}`；
   - 不含命中统计/判定/审计。
2. 服务：`backend/app/services/content_guard/snapshot.py`
   - export_snapshot：确定性排序 + sha256 revision；
   - import_snapshot(mode=merge)：缺啥补啥，不删除、不覆盖本机已有等级；模式 sync（管理员显式）才覆盖 level/category/status；
   - 变体按 (term, normalized) 幂等；导入后 reload_engine。
3. 入口：
   - CLI：`scripts/content_guard/export_snapshot.py` / `import_snapshot.py --mode merge|sync`；
   - 管理端：`GET /api/admin/content-guard/snapshot`、`POST /api/admin/content-guard/snapshot/import`（R11 登记）；
   - 启动钩子：`lifespan` 中 `snapshot.sync_if_changed()`（按文件 hash 幂等，默认开启，`CONTENT_GUARD_SNAPSHOT_SYNC=0` 可关）；只 merge。
4. 多设备流程：设备 A 加词 → 导出快照 → commit/push；设备 B git pull → 重启或点导入 → 日志显示 +N terms/+M variants → DFA reload；离线拷贝 JSON 导入。
5. 安全：仓库已含敏感词治理投影；快照同样只有治理词，无密钥。若不想公开词表可改私有部署文件，需确认。

### 6.4 创新但可落地

- 学习驾驶舱：稳定三列骨架；任务显示来源（我的目标/学习计划/周任务）。
