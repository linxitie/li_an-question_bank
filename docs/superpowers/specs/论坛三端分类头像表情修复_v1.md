# 论坛三端分类、头像、表情修复设计方案 v1

- 日期：2026-10-23
- 分支：`feature/forum-category-avatar-emoji`（父分支 `feature/forum`）
- 关联旧方案：`docs/superpowers/specs/论坛个性化与自生长知识库周任务激励_v0.1.md`

## 1. 用户诉求

1. 帖子分类（学习讨论 / 经验分享 / 答疑解惑 / 资料分享）只有手机端有，平板、PC 没有。
2. 手机帖子详情没有头像；平板只显示通用图标；PC 只显示用户名首字。希望显示用户自定义头像。
3. 三端评论/聊天输入框旁没有表情选择按钮，希望像微信一样可选 emoji / 表情包。

### 2.2 真实缺口

| # | 缺口 | 证据 |
|---|---|---|
| G1 | 后端分类枚举没有「答疑解惑」 | `models.py:643` 仅 `EXPERIENCE/RESOURCE/DISCUSSION/FEELING`；`forum.py:413` 校验元组同 |

| G4 | 平板分类 key 与后端枚举不一致，count 为假数据 | `tablet_forum.vue:263-269` |
| G5 | PC 完全没有分类入口 | `.vtj/vue/forum.vue` 全文无 category / shareType |

数据库事实：`backend/data/example_db.sqlite` 中 `forum_post.share_type` 为 `VARCHAR(10)`，**无 CHECK 约束**；当前仅 4 条帖子且全部为 `EXPERIENCE`；3 个用户中仅 1 个设置过头像。因此新增 `QUESTION` 不需要表结构迁移。

## 3. 方案

### 3.1 分类：一套 key，三端同一份定义

- 新增 `src/modules/community/categories.ts`：
  - `FORUM_CATEGORY_TABS`：`all / DISCUSSION / EXPERIENCE / QUESTION / RESOURCE / FEELING`，中文名分别为 全部 / 学习讨论 / 经验分享 / 答疑解惑 / 资料分享 / 心情打卡。
  - `toShareTypeParam(key)`：`all` → `''`，其余原样返回。
- 后端枚举与校验补 `QUESTION`。
- 三端统一改为**服务端筛选**（带 `share_type` 请求参数），不再对当前页做本地过滤。
- `FEELING`（心情打卡）保留为第 6 个分类：发帖页本来就提供该类型，若列表不展示会导致这类帖子只能出现在「全部」里。

### 3.2 头像：沿用已有回退规则，补齐平板与 PC 覆盖面

- 不新建头像组件，沿用 `avatarInitial()` + `<img @error>` 的现有模式，避免与已合并的评论头像改造产生两套实现。
- 平板列表：映射时补 `avatar`，模板改为真图 + `avatarInitial` 回退。
- PC 列表首字回退改用 `avatarInitial`（纯数字学号不再显示「2」）。
- 头像 URL 使用后端返回的相对路径 `/uploads/avatars/...`，开发环境已由 `proxy.config.ts:103-105` 代理。

### 3.3 表情：复用 EmojiStickerPicker

- PC 评论输入区增加 😀 按钮与弹出面板，选中后追加到 `state.newComment`；表情包写入 `[[sticker:url]]`，与手机端一致。
- PC 评论内容与帖子摘要改用 `ForumContent` 渲染，表情包标记才会变成图片。
- 平板详情页复用 `mobile_forum_detail.vue`，已具备表情能力，无需重复实现。
- 插入位置沿用现有行为：追加到文本末尾（手机端同款），不做光标插入，保持三端一致。

## 4. 不做什么

- 不新建站内私信/聊天模块（当前仓库不存在聊天功能，本次只覆盖评论输入框）。
- 不改 `/api/v1` 路径（R11）。
- 不改 `.vtj/vue/*.vue` 的页面 id、文件名、路由（R1/R5）。
- 不做 GIF 大表情包商店、不做表情审核流程。
- 不引入新的 emoji 第三方依赖。

## 6. 风险与回滚

| 风险 | 处置 |
|---|---|
| `.vtj/vue` 模板修改（R3） | 修改前备份为 `*.bak_20261023`；仅做增量插入，不改动既有结构；改后逐端跑页面 |
| 平板/手机旧页面依赖本地 `category` 字段 | 映射时同时保留 `category` 字段并赋值为 shareType，避免其他逻辑报错 |
| 新增 QUESTION 后旧数据不受影响 | SQLite 无 CHECK 约束；写入前有白名单校验 |
| 服务端筛选后分页数量变化 | 切换分类时重置到第 1 页 |
| 表情包标记在旧数据中不存在 | `ForumContent` 无标记时按纯文本输出，向后兼容 |

回滚：`git revert` 本次提交即可；模板备份文件可直接覆盖还原。

## 7. 验收标准

1. `pytest backend/tests/test_community_module.py` 通过，新增用例覆盖 QUESTION 发帖与筛选。
2. `npx vitest run src/modules/community/__tests__/categories.spec.ts` 通过。
3. `npm run typecheck` 本任务文件无新增错误。
4. 三端论坛列表都能看到全部 6 个分类，切换后请求带 `share_type`，翻页后分类结果正确。

6. PC 评论框可打开表情面板，选中 emoji 进入输入框；表情包发送后显示为图片。
7. 平板列表头像不再是统一人形图标。
