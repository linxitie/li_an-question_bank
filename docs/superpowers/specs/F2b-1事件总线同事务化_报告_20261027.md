## 0. 一句话

20 个 record_user_action 表达式与 2 个 events.publish 已从“业务先 commit、再尽力发 Redis/同步兜底”改为“业务写与 foundation_outbox 同一事务”；Dispatcher 用同机文件锁保证单写者，用 foundation_inbox 保证幂等消费，并按用户/角色定向派生 data-changed。

## 2. 关键语义

- 默认 EVENT_OUTBOX_ENABLED=true：record_user_action 只写 outbox.emit（不 commit、不 publish）；emit 异常向上抛，业务事务回滚。
- 关闭 EVENT_OUTBOX_ENABLED 或 FOUNDATION_ENABLED：回到旧 events.publish + 同步兜底，事件失败不阻断业务。
- 稳定 session 时 dedupe_key=user_action:<uid>:<trigger>:<session_key>；重复事件由 foundation_inbox(consumer,event_id) 二次防重。
- 单写者：同机多 worker 只允许一个 Dispatcher 持锁；run_once 不加锁供测试/脚本。
- 定向：私有域只本人；学生练习/组卷通知本人+teacher/admin；论坛与试卷公共事件广播三角色；未知 trigger 只回本人。
- WS 推送失败只记日志，不回滚成就/业务事实；事件重试由 Dispatcher 负责。

## 6. 回滚

1. 新事件链路异常：EVENT_OUTBOX_ENABLED=false 重启，record_user_action 回到旧 events.publish + 同步兜底；Outbox 表与已写事件保留。
2. Dispatcher 锁异常：进程退出自动释放；必要时改 DISPATCHER_LOCK_PATH。
3. 代码回退：revert 本提交；foundation_outbox/inbox 表与 pending 事件不删。
4. 禁止：删 outbox/inbox 表、清空 pending 事件、删锁文件强行多写者。
