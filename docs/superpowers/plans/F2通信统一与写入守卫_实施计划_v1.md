## 1. 目标与边界

**目标**：把 F1 的「单进程可用」升级为「多 worker 可水平扩展 + 三端消息可去重可定向 + 全路由角色可见性有声明 + 脏数据写库前被拒」。

1. **WS 协议 v2**：统一信封，新增 `v / seq / scope / domain / entity`（只增不删），旧字段 `type/data/timestamp` 原样保留。
2. **多 worker 中继**：`WS_RELAY=redis` 时经 Redis pub/sub 扇出；`WEB_CONCURRENCY>1` 且未开中继 → 启动即失败（fail-fast）。
3. **可见性与消费补齐**：57 条未声明 `meta.roles` 的路由补全；前端从「只认 `type='sync'`」改为同时消费 `data-changed`，带 seq 去重与重连全量重同步。
4. **写入守卫 6 类**：超长 / 空必填 / 错枚举 / 坏 JSON / 外键孤儿 / 编码错乱，写库前拒绝，错误码可定位字段与规则。

**明确不做**（留给 F3/业务伙伴）：
- 不改业务功能语义、不做新业务表、不做 GC 保留期执行、不做 Outbox 批量写性能改造（无生产批量调用点）。
- 不改 `.vtj/**` 任何模板（R3）、不删改静态资源（R7）、不改 `api/v1` 路径与出入参结构（R11）。
- 不引入新依赖：`redis>=5.0.0` 已在 `backend/requirements.txt`；前端不新增包。

## 4. 分步执行

### Step 1 — 协议与序号（N1/N3）

1. `WsEnvelope` 固定键：`v=2, type, seq, scope, domain, entity, id, data, timestamp, origin`。
2. `SeqAllocator.next()`：Redis 可用 → `INCR foundation:ws:seq`；不可用 → 进程内 `max(ms, last+1)`（不持久化，重连由全量重同步兜底）。
3. scope：`domain`（周知）、`domain.entity`、`domain.entity.id`；`sync` 取 `data.scope` 或 `"global"`。
4. 旧字段保留，`data-changed` 仍带 `{domain,type,id}`。
**验证**：`pytest tests/test_foundation_ws_protocol.py -q` 全绿；commit。

### Step 2 — 中继与多 worker 守卫（N2/N4/M3/M4/M5）

1. `deliver(payload, user_ids=None, room=None)`：`WS_RELAY=redis` → `PUBLISH foundation:ws`；否则本地分发。
2. 每个 worker 跑订阅循环；收到 `origin == 本 worker` 跳过（发布者已本地投递）→ 无双发。
3. Redis 运行期故障：`publish` 异常 → 记 ERROR、回落本地、health `relay="degraded"`。
4. `validate_worker_config()`：`WEB_CONCURRENCY>1` 且 `WS_RELAY!="redis"` → 抛 `RuntimeError`（含修复命令）。
5. lifespan 建表后启动订阅；shutdown 取消订阅（吞 `CancelledError`）。
**验证**：单测通过；`WEB_CONCURRENCY=2` 无中继 10s 内非 0 退出且日志提示；`WS_RELAY=redis` 正常启动；L7-13 PASS。

### Step 3 — 统一发送出口（M1/M2）

1. `publish_data_changed` 与 `_dispatch_sync` 只调 `ws_relay.deliver()`。
2. `publish_data_changed` 补 `seq/scope`：`scope=f"{domain}.{type}"`（`paper.published` → `exam.paper.published`）。
3. 心跳：`connect` 更新 `last_seen`，心跳刷新；后台每 30s 关闭空闲 >90s 连接（码 4008）。
4. 保留 `ws_connection_manager` 供在线列表/房间接口读取。
**验证**：本地客户端收到 `data-changed` 含 `seq/scope` 且旧字段不变；超时连接被关；L7-14 PASS。

### Step 4 — 前端消费与重同步（N8/M8/M9）

1. `wsMessage.ts`：`classify()`、`acceptSeq(scope, seq)`（同 scope 丢弃 `seq<=last`）、`toPapersEvent()`。
2. `auth.ts`：`data-changed` → `__VTJ_SYNC__`（兼容旧页面）+ `papers:data-changed`（domain=exam/type=paper.published）。
3. 重连成功（非首次）→ 清空 seq 表 + 派发一次 `__VTJ_SYNC__`，补偿断线丢失。
4. 不新增 WS 地址参数，沿用 `/ws/connect?token=...`。
**验证**：`npm run test:unit -- wsMessage` 通过；`npm run typecheck` 通过；手工 A 发布试卷 B 刷新。

### Step 5 — 路由角色可见性（N5/M10）

1. 补 `src/router/index.ts`：mobile/tablet 全部 `['student']`；`/forum`、`/recruit`、`/materials/{xingce,shenlun,gongzhuan}` → `['student','teacher','admin']`。
2. 公共白名单 4 条：`/login`、`/scan`、`/unauthorized`、`/:pathMatch(.*)*`。
3. 门禁改为按 route 记录解析（path 与同对象 roles 配对），白名单外缺失即 FAIL。
4. `test_route_roles.py` 固化：92 条、白名单 4、其余 88 条全部有 roles、mobile/tablet 仅 student。
**验证**：脚本测试通过；L7-08 PASS（`0/88 未声明`）。

### Step 6 — 写入守卫 6 类（N6/N7/M6/M7）

| 规则 | 判定 | 处理 |
|---|---|---|
| R-长 | `question_content>50k`、`answer>10k`、`answer_analysis>1M`、`options>100k`、`tags>2k` | 拒绝 |
| R-空 | `question_content` 去空白为空；`type_id/subject_id` 缺失；客观题 `options` 为空 | 拒绝 |
| R-枚举 | `difficulty∉[1,5]`、`status∉{0,1}`、`audit_status∉{0,1,2}`、`score<0` | 拒绝 |
| R-JSON | `options/tags` 以 `[`/`{` 开头时必须可解析且为 list；坏 JSON | 拒绝 |
| R-FK | `type_id→question_type`、`subject_id→question_subject`、`point_id→knowledge_point`、`group_id≠0→question_groups` 必须存在 | 拒绝 |
| R-编码 | `NUL`、孤立代理项（`U+D800–DFFF`） | 拒绝；`U+FFFD` 只记 WARN |

**验证**：`pytest tests/test_foundation_validation.py` 通过（6×2 正反例 + 端点 422 且库无新行）；干跑 0 硬错误；`gate_all --quick` 4/4。

## 6. 风险与回滚

| 风险 | 缓解 |
|---|---|
| Redis pub/sub at-most-once，断线丢消息 | 客户端重连全量重同步；seq 只去重不补发 |
| 前端改 auth.ts 影响所有页面刷新 | 保留 `type='sync'` 原语义；`data-changed` 只新增桥接；typecheck + 三端冒烟 |
| 角色补全误拦 | /forum、/recruit、/materials/* 三角色全通（与现状等价）；4 个测试账号过 92 条路由 |
| 校验误杀存量格式 | 先全量干跑；不通过不强制；开关可关；批量逐条 rejected |
| 多 worker + SQLite 写竞争 | 仍单写库：WAL + `busy_timeout=30000`；建议 workers≤2 |
| 心跳超时误断 | 客户端 30s 心跳 < 90s 阈值；关闭码 4008 可重连 |
| 422 改变前端体验 | 错误码含字段名；`api_surface.json` 不变（R11） |

**回滚**：`WS_RELAY=` + `WEB_CONCURRENCY=1` 恢复单进程；`FOUNDATION_VALIDATION_ENABLED=false` 关闭守卫；代码按 Step 逆序 revert；无新表、无数据迁移。
