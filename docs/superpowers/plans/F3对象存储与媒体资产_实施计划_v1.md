## 4. 总体设计

### 4.1 数据流

    浏览器上传
        |
        v
    API（校验扩展名/大小/MIME）
        |
        v
    media_service（算 sha256、大小）
        |
        +--> ObjectStore.put(key=sha[:2]/sha, bytes)   字节投影（local/MinIO）
        |
        +--> 同一 SQLAlchemy Session：
               INSERT media_assets（元数据事实源）
               outbox.emit(media.asset.created.v1)
        |
        v
    业务行（user.avatar / ForumPost / Material / VideoResource）与上面同事务 commit

    读取：
    浏览器 GET /media/{asset_id}
        -> media_assets 查元数据
        -> ObjectStore.stream(key, Range)
        -> 200/206/304，ETag=sha256，Cache-Control immutable

设计原则：**数据库行是事实源，字节是可重建投影**。绝不双写两个数据库，绝不跨库事务；先写字节、后写数据库行，数据库失败只留下内容寻址孤儿（可 GC），不允许出现「有行无字节」。

### 4.2 新表 media_assets

迁移文件：backend/migrations/20261027_002_media_assets.sql（与 001 同日，序号 001,002 连续，满足 L7-5）。

    CREATE TABLE IF NOT EXISTS media_assets (
        asset_id      TEXT PRIMARY KEY,
        sha256        TEXT NOT NULL,
        object_key    TEXT NOT NULL,
        size_bytes    INTEGER NOT NULL,
        content_type  TEXT NOT NULL,
        kind          TEXT NOT NULL,
        original_name TEXT,
        created_by    INTEGER,
        status        TEXT NOT NULL DEFAULT 'active',
        created_at    TEXT NOT NULL,
        deleted_at    TEXT
    );
    CREATE INDEX IF NOT EXISTS ix_media_assets_sha256 ON media_assets(sha256);
    CREATE INDEX IF NOT EXISTS ix_media_assets_status ON media_assets(status);
    CREATE INDEX IF NOT EXISTS ix_media_assets_created_by ON media_assets(created_by);

字段约定：

| 字段 | 约定 |
|---|---|
| asset_id | uuid4().hex，32 位，URL 只暴露它 |
| sha256 | 小写十六进制 64 位，内容寻址键 |
| object_key | sha[:2]/sha；不对外暴露 |
| kind | avatar / forum / material_image / video；新增值只增不删 |
| status | active / deleted；删除是 tombstone，不物理删行 |
| created_by | sys_user.id 或 NULL（系统导入） |

不建外键：沿用现有 SQLite 表风格，避免历史数据与批量导入被外键卡住。
不设 sha256 UNIQUE：同一字节可以被多个用户/多条业务引用，每次上传建一条元数据行；物理字节只存一份。

### 4.3 ObjectStore 协议

新增 backend/app/foundation/stores/object.py：

    class ObjectStore(Protocol):
        backend: str
        def put(self, key, source: BinaryIO, content_type: str, *, sha256: str, size: int) -> None
        def open(self, key) -> BinaryIO
        def stream(self, key, start: int = 0, end: int | None = None) -> Iterator[bytes]
        def stat(self, key) -> ObjectStat | None
        def delete(self, key) -> bool
        def health(self) -> StoreHealth
        def list_keys(self, prefix: str = "") -> Iterator[str]   # local 必须；MinIO 可选

数据类：ObjectStat(key, size, sha256=None)、StoreHealth(backend, ok, degraded, detail)。
异常：ObjectStoreUnavailable（网络/认证/超时）、ObjectNotFound。

与 spec §5.3 的差异及理由：

| 差异 | 理由 |
|---|---|
| 不实现 signed_url | /media/{asset_id} 由后端稳定代理，不暴露 bucket；头像与论坛引用是长期 URL，presigned 短链会过期；img 标签也无法携带 Authorization |
| 增加 stream(start,end) | 视频必须 Range 流式，open() 全量读内存不可接受 |
| 增加 list_keys | 本地孤儿扫描与对账需要；MinIO 用 ListObjectsV2 可选实现 |

### 4.4 local 与 MinIO 两个适配器

local（默认，零依赖）：

- 根目录：backend/data/foundation/objects（可由 OBJECT_STORE_ROOT 覆盖，相对路径按 backend/ 解析）。
- 路径：<root>/<sha[:2]>/<sha>。
- 写入：同目录临时文件 + os.replace 原子替换；目标已存在且大小一致时直接跳过（内容寻址天然幂等）。
- 读取：open/stream 用普通文件，start/end 用 seek。
- 删除：os.remove；不存在返回 False。
- 安全：只接受 64 位小写 hex 的 key 形态，拒绝 .. 与分隔符，防止路径穿越。

MinIO（可选）：

- 仅用已有 httpx，自己实现 AWS Signature V4（path-style）。
- 支持 PUT Object、GET Object（含 Range）、HEAD Object、DELETE Object、ListObjectsV2（用于孤儿扫描，失败可降级）。
- 认证头：host、x-amz-content-sha256、x-amz-date、authorization；PUT 额外签 content-type。
- 密钥只从环境变量读取，不落日志、不写文档、不进 Git。
- 超时：连接 3 s、读 30 s；上传失败重试 2 次（指数退避 0.2/0.5 s），仍失败抛 ObjectStoreUnavailable。
- 若自研 SigV4 在两日内无法通过 fake S3 服务测试，停止并请用户批准改用 boto3；不得带着未验证签名上线。

工厂：build_object_store() 根据 OBJECT_STORE_BACKEND 返回单例；local 与 minio 都实现同一协议。

### 4.5 /media/{asset_id} 读取契约

新增 backend/app/api/media_assets.py，router = APIRouter(prefix="/media", tags=["媒体"])。

| 项 | 约定 |
|---|---|
| 方法 | GET + HEAD |
| 鉴权 | 公开只读（kind=avatar/forum/material_image/video 均是公开内容）；不要求登录 |
| 200 | Content-Type（服务端按 kind+扩展名确定，不信客户端）、Content-Length、ETag="sha256"、Accept-Ranges: bytes、Cache-Control: public, max-age=31536000, immutable、X-Content-Type-Options: nosniff |
| Range | 单区间 bytes=start-end / bytes=start- / bytes=-suffix；206 + Content-Range；非法 416 |
| 条件请求 | If-None-Match 匹配 ETag 返回 304；If-Range 可后续加，F3 不做 |
| HEAD | 与 GET 同头，无 body |
| 附件 | kind=forum 时 Content-Disposition: attachment; filename*=UTF-8''<urlencoded original_name>；文件名去 CR/LF |
| 行不存在/已删除 | 404 |
| 行存在但字节缺失 | 404 + ERROR 日志 + health degraded；不得静默回退旧路径 |
| 存储不可达 | 503 + 明确 detail；不得 404 掩盖 |
| 旧 URL | /uploads/** 与 /static/** 挂载与行为完全不变 |

asset_id 只允许 32 位 hex；非法直接 404，不查库。

### 4.6 写入顺序与事务边界

media_service 提供：

    store_bytes(session, data: bytes, *, kind, original_name, content_type,
                created_by=None, trace_id=None, dedupe_key=None) -> MediaAsset
    store_file(session, fileobj: BinaryIO, *, kind, original_name,
               content_type, created_by=None, trace_id=None) -> MediaAsset
    replace_media_url(session, old_url: str | None, new_asset: MediaAsset) -> None
    open_asset(asset_id: str) -> tuple[MediaAsset, BinaryIO]
    stream_asset(asset_id, start, end) -> Iterator[bytes]
    delete_asset(session, asset_id: str) -> bool

store_file 内部流程：

1. 读流并增量算 sha256 与 size；超过调用方上限立即抛 MediaTooLarge（不落盘）。
2. key = sha[:2] + "/" + sha。
3. ObjectStore.put；本地已存在则跳过；失败抛 ObjectStoreUnavailable。
4. session.add(MediaAsset(...))；若 FOUNDATION_ENABLED，outbox.emit(media.asset.created.v1, aggregate_type=media_asset, aggregate_id=asset_id, producer=media_service, payload={sha256,size,content_type,kind,created_by})。
5. 返回 MediaAsset；**不 commit**，由 API 与业务行一起 commit。

失败矩阵：

| 失败点 | 结果 |
|---|---|
| 校验失败 | 400，不写字节、不写行 |
| 写字节失败 | 503，不写行；临时文件清理 |
| 写行/emit 失败 | 事务回滚；字节成为内容寻址孤儿，由 GC 清理 |
| commit 失败 | 同上；业务行也不可见 |
| 读时字节缺失 | 404 + degraded；对账报告 missing_blob |

内容类型纪律：content_type 由服务端按 kind + 扩展名白名单映射（avatar/material_image 仅 jpeg/png/gif/webp；forum 仅 PDF/Word/Excel；video 仅视频格式），不直接采用客户端 Content-Type；响应统一加 nosniff。

### 4.7 去重、替换与删除

- 物理去重：同一 sha256 只存一份字节；每次上传仍建一条 media_assets 行。
- 头像替换：新资产写成功后，若旧 avatar 以 /media/ 开头，best-effort 调 delete_asset（tombstone + 可能删字节）；旧 /uploads/ 头像不动。
- 删除：status=deleted、deleted_at=now；若同 sha256 已无其他 active 行，再 ObjectStore.delete；删除失败只告警，留待 GC。
- 不物理删 media_assets 行：保留审计与 404 依据。
- 缓存注意：URL 带 immutable，但 asset_id 随每次上传变化；删除旧 URL 后浏览器可能仍显示缓存，属可接受语义（新引用不会再用旧 URL）。

## 6. 实施步骤

### Step 0：基线冻结与迁移备份（0.5 小时）

动作：
