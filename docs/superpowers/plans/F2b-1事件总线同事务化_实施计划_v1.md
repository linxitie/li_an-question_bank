## 0. 一句话

把当前“业务先 commit、再尽力发 Redis/同步兜底”的 20 个 record_user_action 调用点与 2 个 events.publish，改为“业务写与 foundation_outbox 同一事务”，由单写者 Dispatcher 幂等消费，并按用户/角色定向派生 data-changed；Redis 不可达不再丢事件。

## 1. 目标

| 编号 | 目标 | 可观测结果 |
|---|---|---|
| G1 | 写路径同事务 | 业务行与 outbox 行同时存在或同时回滚；断 Redis 不影响写入 |
| G2 | 消费幂等 | 同一 event_id 重复投递只产生一次成就/一次失效通知，foundation_inbox 有记录 |

### 4.2 写路径

record_user_action 保持 async 签名，内部按开关分支：

| 条件 | 行为 |
|---|---|
| FOUNDATION_ENABLED=true 且 EVENT_OUTBOX_ENABLED=true | 调 foundation.outbox.emit(session=业务 session, event_name=user.action.v1, aggregate_type=user_action, aggregate_id=u-<user_id>, producer=user_action, payload={user_id,trigger_type,session})；不 commit、不 publish、不同步兜底 |
| 开关关闭或 FOUNDATION 关闭 | 保留现有 events.publish + 同步 judge/grant 兜底 |

同事务语义：emit 插入失败或异常向上抛出，调用点的事务回滚，业务数据不落库；不再出现“业务成功、事件丢失”。关闭开关时恢复旧语义（事件失败不阻断业务）。

去重键：仅当 session 是稳定身份（session_id 或 wrong_id 等）时，传 dedupe_key=user_action:<user_id>:<trigger_type>:<session_key>；没有稳定身份时不传，交给 inbox 防重放。

### 4.3 Dispatcher 单写者

新增 backend/app/foundation/dispatcher_lock.py：

- Windows 用 msvcrt.locking(fd, LK_NBLCK, 1)，POSIX 用 fcntl.flock(LOCK_EX|LOCK_NB)；
- 锁文件 backend/data/foundation/dispatcher.lock，目录自动创建；文件句柄常驻，进程退出自动释放；
- acquire() 返回 bool；release() 幂等；不删除锁文件（避免 Windows 句柄竞争）；
- Dispatcher.run_forever 每轮先 acquire，失败则 sleep(interval_ms) 重试，不 fetch；run_once 不加锁（测试/脚本单次执行）。

理由：SQLite 是单机事实源，Outbox 是持久队列；文件锁只解决“同机多 worker 单写者”，不引入 Redis Stream 的第二套持久化与 consumer group 语义。

### 4.4 幂等消费者

新增 backend/app/foundation/inbox.py：

- claim(session, consumer, event)：INSERT OR IGNORE INTO foundation_inbox；返回 rowcount==1；
- 已存在返回 False，handler 直接返回，不再判成就、不再发 WS；
- claim 与业务副作用在同一 Dispatcher 事务内，失败一起回滚，重试可重新 claim。

新增 backend/app/services/event_handlers.py：

- build_handlers() -> dict[event_name, handler]；
- user.action.v1：claim inbox(consumer=user_action_consumer) → achievement_judge.judge_action → 有 newly 则 achievement_reward.grant_newly → 按 event_routes 发 publish_data_changed；handler 内不 commit；
- catalog.paper.published：claim inbox(consumer=paper_published_consumer) → publish_data_changed(roles=[student,teacher,admin])；
- WS 发送异常只 log warning，不抛出，避免“通知失败导致事件重试/成就重复”；inbox 已保证成就只判一次。

### 4.5 定向

ConnectionManager：

- connect(websocket, user_id, room=None, role=None) 记录 role；disconnect 清理；
- 新增 get_online_users_by_roles(roles) -> list[int]；未知角色的旧连接不匹配；
- websocket_connect 在 accept 后从 token payload 取 user_type 传入。

WsRelay：

- emit/deliver/_send_local 增加 roles: list[str] | None；
- 接收者集合 = user_ids ∪ roles 对应在线用户 ∪ room / 全体（仅当三者都为空）；空集合直接返回 0；
- Redis PUBLISH body 增加 roles 字段；远端 _send_local 用本地在线表解析角色，不跨进程查库；
- 信封字段不变（v2/seq/scope/domain/entity/id/data/timestamp/origin），避免破 F2 D18。

publish_data_changed 增加 roles=None 参数，旧调用点不需要改。

### 4.6 旧消费者去留

| 开关 | main 行为 |

## 9. 回滚

| 场景 | 动作 |
|---|---|
| 事件处理异常导致业务 5xx | EVENT_OUTBOX_ENABLED=false，重启；旧路径恢复，不需要改代码 |
| Dispatcher 锁异常 | 删除进程后锁自动释放；必要时设 DISPATCHER_LOCK_PATH 到新路径 |
| 迁移调用点引入回归 | git revert 单提交；outbox 表与已写事件保留，不删 |
| 消费者重复 | 停 dispatcher；inbox 已有记录可查；修复后重放 |

禁止：删 foundation_outbox/foundation_inbox 表；清空 pending 事件；删锁文件强行多写者。
