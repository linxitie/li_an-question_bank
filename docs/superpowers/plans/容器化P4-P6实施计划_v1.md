## 2. P4 前端镜像、TLS 与加固

### P4-1 OCR 文本归一化（先修 S1）

- 新增 `normalize_ocr_markdown(text)`（`backend/app/services/text_parser.py`）：
  1. 行首 ASCII `(一)`…`(十)` → 全角 `（一）`；
  2. 粘连题号断行：仅当前后文能证明是题号时动作，避免把 `1.79`、`93.37` 小数切断。
- 只在 `engine=mineru` 的 OCR 出口调用，文本型 PDF 零回归。
- 测试：新增加载真实 OCR 片段（108 粘 D 选项、111 粘句号、含小数干扰），断言 10 题、5+5 材料组、108/111 存在。

### P4-2 nginx resolver（修 S2）

- `deploy/nginx.conf`：`resolver 127.0.0.11 valid=10s ipv6=off;`，
  `set $backend http://backend:8000;`，`proxy_pass $backend;`，移除固定 upstream。
- 影响：backend 重建换 IP 后无需重启 web；保留 `Host $http_host` 与 307 修复。

### P4-3 可选 TLS

- 新增 `deploy/nginx.tls.conf`：同一 server 同时 `listen 8080` 与 `listen 8443 ssl`，
  证书从 `/etc/nginx/certs/` 读取；保留 /healthz 明文探针。
- 新增 `deploy/docker-compose.tls.yml`：只覆盖 web 的 8443 端口、证书挂载与配置挂载。
- 新增 `deploy/certs/README.md` 与 .gitignore 规则；证书不入 Git。
- 自签证书仅用于 staging 验证，生产用学校证书/网关终止。

### P4-4 镜像扫描与资源压测

- 优先 `docker scout cves`；不可用则尝试 trivy；都不可用则记录“扫描器不可用”，不伪造结果。
- 压测：上传较大文本 PDF，记录 backend 峰值内存；parser 用 4–6 页扫描件，监控 4G limit 是否 OOM。
- 记录命令、时间、峰值、结论。

**P4 验收**：OCR 10/10 题、5+5 组；backend 重建后 web 不重启仍 200；HTTPS 8443 可访问；
镜像扫描有结论；压测无 OOM。命令：
```bash
cd backend && python -m pytest tests/test_xingce_material_sets.py tests/test_ocr_markdown_normalization.py -q
docker compose -f deploy/docker-compose.yml --env-file deploy/.env.development config --quiet
curl -fsS http://127.0.0.1:8080/healthz
```

## 3. P5 备份、恢复、可观测性与 CI

### P5-1 发布前 checkpoint

- 新增 `deploy/checkpoint.sh`：对 `DATA_ROOT/question_bank.db` 执行
  `PRAGMA wal_checkpoint(FULL)`，输出 busy/log/checkpointed；失败非零退出。
- `deploy/release.sh` 在 recreate 前调用。

### P5-2 备份

- 新增 `deploy/backup.sh`：
  - 先 checkpoint；
  - 调 `backend/scripts/admin/backup_db.py --db ... --out-dir ...`（sqlite3.backup，R10）；
  - 生成 `static/uploads/foundation` 清单（文件数/字节）；
  - `--assets` 时用 rsync 增量复制，支持 `--link-dest`；无 rsync 则明确失败/警告；
  - 可选 `OFFSITE_ROOT` 异地复制；
  - 写 `latest.json` 与 `.sha256`。
- 备份目录默认 `deploy/runtime/backups`（gitignore）。

### P5-3 恢复演练

- 新增 `deploy/restore.sh`：
  - 校验备份 integrity 与关键表计数；
  - 停 backend（保留 web）；
  - 调 `restore_db.py --yes`（覆盖前自动快照）；
  - 启动 backend，等 healthy，跑只读烟测。
- 演练：复制 staging 库 → 人为改一条标记 → 恢复 → 断言标记回退、计数一致、RTO 记录。
- 恢复脚本支持 `--dry-run`。

### P5-4 巡检与告警

- 新增 `deploy/inspect.sh`：容器健康、/health、/health/foundation、磁盘、备份年龄、
  DB integrity、日志大小；任一硬指标失败退出非零，可直接接 cron/systemd。
- 不新增 Prometheus 端点（R11）；输出适合 cron 邮件/Webhook 的文本。
- 提供 systemd timer 示例（不自动安装）。

### P5-5 CI

- 新增 `.github/workflows/container-ci.yml`：
  - typecheck + targeted backend tests + gate_all --quick；
  - 构建 web/backend（staging 不装 Chromium）与 parser；
  - tag 推送才登录 GHCR 推送，PR/分支只构建不推；
  - 禁止 latest 上生产。
- 本地不执行 GitHub Actions，只做 YAML 解析与脚本语法校验；如实标注未在 GitHub 跑过。

**P5 验收**：备份成功 + 校验 ok；恢复演练成功且计数一致；inspect 正常/异常两种退出码；
CI YAML 可解析；所有脚本 `bash -n` 通过。

## 4. P6 学校服务器切换准备

- 新增 `deploy/.env.production.example`：绝对路径、TLS 变量、IMAGE_TAG 非 latest、真实域名占位。
- 新增 `deploy/release.sh`：preflight → checkpoint → backup → pull/build → up -d → 等 healthy →
  烟测 → 失败自动回滚上一 tag。
- 新增 `docs/ops/容器化生产切换Runbook_v1.md`：迁移前冻结、备份、rsync、权限、启动、
  烟测、DNS/网关切换、观察 24h、回滚、RTO/RPO、禁止 down -v。
- 本机只做 staging 演练；服务器/DNS/证书动作标注“待在生产执行”，不伪报。

**P6 验收**：production env 模板可 `docker compose config`（用测试值）；release 脚本 dry-run/语法通过；
Runbook 覆盖迁移、回滚、验收清单。

## 5. 风险与回滚

| 风险 | 缓解 |
|---|---|
| OCR 归一化误切小数 | 只对 3 位题号+年份/句末/选项末等强信号断行；单测覆盖小数 |
| nginx 变量 proxy_pass 改变 URI | 保留无 URI 的 `proxy_pass $backend`，实测 /api 与 /static |
| TLS 证书缺失导致 web 起不来 | TLS 为独立 override，默认 compose 不受影响 |
| 恢复脚本误伤 | 默认 dry-run；--yes 才执行；覆盖前自动快照；只操作 DATA_ROOT |
| CI 未在 GitHub 实跑 | 只声明 YAML/脚本本地校验通过，不声明 CI 绿 |
| 生产切换未执行 | 报告明确“待服务器执行”，不写“已上线” |
