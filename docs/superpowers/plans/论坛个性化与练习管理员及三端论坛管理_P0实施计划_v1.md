# P0：权限与数据底座 实施计划 v1

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 建立「练习管理员能力包 + 反馈工单 + 举报/通知」的数据与权限底座，为 P1~P4 提供稳定契约。

**Architecture:** 不新增用户主角色；用 `user_capability` 表做按用户授权，权限解析时与角色权限合并；反馈工单扩展现有 `user_feedback`；论坛新增举报/提及/通知表；前端路由守卫增加 `meta.permissions` 判断。

**Tech Stack:** FastAPI / SQLAlchemy / SQLite(WAL) / Pydantic / Vue 3.5 / Pinia / vitest / pytest

**Spec:** `docs/plans/论坛个性化与练习管理员及三端论坛管理_设计方案_v1.3.md`

## Global Constraints

- 分支：`feature/forum-personalization`（父分支 `feature/forum`）。
- 不改 `/api/v1/...` 既有路径（R11）；只新增端点或新增可选参数。
- 新表由 `Base.metadata.create_all` 创建；给已有表加列必须补进 `backend/app/main.py` 的自动迁移清单。
- 迁移前必须用 `sqlite3.backup()` 备份（R10）。
- 所有管理动作写 `SysOperationLog`。
- 不提交 `package-lock.json`、`.vtj` 运行时文件等无关改动。
- 后端测试从 `backend` 目录运行。

## Review Focus

- 未任命的普通教师：能浏览/回复，但调用反馈/管理接口必须 403。
- 学生骨干：能处理本班反馈，但不能处理论坛举报、不能任命任何人。
- 教师练习管理员：只能处理被授予科目的反馈，跨科目 403。
- 反馈工单：同一请求重复提交不产生重复工单；并发认领只有一人成功。
- 举报：同一人对同一目标重复举报不产生第二行。
- 通知：状态变化必须产生一条且仅一条站内信。
