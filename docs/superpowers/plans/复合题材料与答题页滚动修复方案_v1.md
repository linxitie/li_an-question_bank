## 0. 结论摘要

截图里的两个现象不是两个独立缺陷，而是 **5 条链路各自“代码已改、数据/读路径没跟上”**：

| # | 链路 | 一句话结论 |
|---|---|---|
| A | 存量数据 | 2024/2025 申论与 2025 行测的 `group_id` 全为 0；材料从未写进 `question_groups` |
| B | 导入入口 | JSON `/batch-parsed` 不带 `material_text`，静默丢组；PDF 旧 preview 也没跑新版材料切分 |
| C | 解析器 | `extract_question_blocks_with_material_sets` 只绑文本材料；`（三）[IMAGE:…]` 纯图片材料和资料二均未绑定 |
| D | 读取/组卷 | `get_paper_questions` 不返回 `group_id/shared_content`；`auto_generate_paper` 按扁平题随机抽，会把组拆散 |
| E | 答题页 | `.pa-toolbar` 虽已 sticky，但 `currentIndex` 不随滚动更新；上一题/下一题只改索引不滚动；材料块不在答题模板里 |

**关键发现（可降低风险）**：
1. `teacher_questions.vue:126` 已用 `v-html="cleanHtmlContent(groupInfo.shared_content)"` 渲染材料，**图片材料只要写进 `shared_content` 就能显示**，无需改教师端模板。
2. `paper_answer.vue` 题干也用 `v-html` 渲染。只要 exam API 返回 `shared_content`，就可在 `<script>` 里把材料 HTML 注入“组内第一题”的 `stem`，**同样无需改 raw 模板**。
3. 因此本方案 **不触碰任何 raw 页 `<template>`**，只改后端、脚本和 `.vue` 的 `<script>`，不触发 R3 红线。

## 3. 设计决策（先定合同，再改代码）

### D1 材料唯一载体

- 复合题材料只存 `question_groups.shared_content`（HTML，已过 `sanitize_rich_text`）。
- 图片材料写成 `<img src="/static/questions/<hash>_<idx>.png" class="q-img" loading="lazy">`，同时把原 token 写入 `shared_content_images`（字符串/JSON 兼容现有字段）。
- 禁止把材料复制进每个子题 `question_content`；修复时只把“已拼进题干的材料前缀”剥离，不动设问。
- 教师端 `teacher_questions.vue` 已有 `v-html` 材料块，直接复用。

### D2 raw 模板零改动

- `paper_answer.vue` 不在 `pages` 配置、仅 `__VTJ_BLOCK__: true`；仍按 R3 处理：**不改 `<template>`**。
- 材料展示：exam API 返回 `group_id/shared_content`，`<script>` 里对组内第一题 `stem = shared_content + stem`，其余子题加“本题属于第 N 组”徽标/无材料。
- 滚动联动：`<script>` 里加 `scroll` 监听 + `IntersectionObserver`/`getBoundingClientRect`，更新 `state.currentIndex`；`watch(currentIndex)` 调 `scrollIntoView`。
- 因此本方案不需要用户批准模板改动；若后续要在材料块上加折叠/目录，再单独申请。

### D3 智能组卷按组抽取

- 组卷前先把候选池按 `group_id` 聚合：`group_id=0` 视为单题组；`group_id>0` 为一组。
- 按题型配额抽样“组”，选中后整组加入；同一组只加一次。
- `PaperQuestionRelation.question_order` 按组内 `sort_order` 连续写入；组内题数计入 `question_count`。
- 若配额小于组大小，**整组加入并允许轻微超配**，优先保证材料完整；返回结果里标注 `group_expanded=true`。

### D4 存量修复以源 PDF 为准

- 只修“能从源 PDF 重新解析出材料”的卷；解析不出的标记 `need_review=1`，生成 CSV 交人工，不编造。
- 匹配键：`subject_id + year + question_number`，再用题干归一化指纹（去空白/标点/图片 token）二次校验；不按题号盲配。
- 修复脚本必须支持 `--dry-run`（默认）与 `--apply`；apply 前用 `sqlite3.backup()` 备份，禁止 `shutil.copy2`。

| 风险 | 缓解 |
|---|---|
