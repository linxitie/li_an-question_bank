## 0. 结论（一句话）

包装层把 `mask` 变 `pass` 的根因已定位到 **`content_guard/__init__.py:131-140` 的「自嘲放行」分支**：它只要求文本含「我」且不含「你/他/楼主…」就强制放行，而「加我」正好命中——**与语境无关，纯正则误伤**。同时发现另外 4 个真问题（政策层因 vault 路径错误全程静默失效、全词表 replace 会污染打码位置、链接层只存在于 stash 未接线、词表被自动生长污染）。

## 1. 根因与证据（全部本机实测）

### RC-1 自嘲分支把 mask 打成 pass（主诉）

`backend/app/services/content_guard/__init__.py:131-140`：

```python
if (policy_bucket is None and result.get("decision") == "mask"
    and _SELF_REF.search(text) and not _OTHER_REF.search(text) ...):
    result.update({"decision": "pass", "level": None, "masked_text": None, "hit": False,
                   "source": "policy_first_self_ref"})
    return result
```

`_SELF_REF=(我|自己|本人|俺)`，`_OTHER_REF=(@|你|您|他|她|楼主|同学|老师|这位|那人|这货|家伙)`。

实测（`sys.settrace` 逐行追踪 `guard_text`，非推测）：

```
TEXT: 卖黄片的加我
judgments.guard_text -> decision=mask  masked_text="卖**的加我"  words=["黄片"]  conf=0.77
执行路径: L131 -> L132 -> ... -> L138 -> L140  (RET)
wrapper 结果: decision=pass  source=policy_first_self_ref  masked_text=None
```

「加我」含「我」，不含反指代词 → 被当成自嘲 → 放行。**同一分支还会放行**「加我微信卖黄片」。

### RC-2 新闻/科普语境把 review 降成 pass

`__init__.py:127-129`：`decision=="review"` 且命中 `NEWS_EDU`（新闻/警方通报/诈骗/求助…）→ 直接 `pass`。
实测：`如何防范网络诈骗？警方通报来了` → `pass`，`source=context_news_edu`。
这与「命中即打码、不做语境放行」直接冲突，是第二个漏放口。

### RC-3 政策层（vault ruleset）在运行时全程静默失效

- `backend/app/core/config.py:253`：`MODERATION_VAULT_DIR` 默认 `D:\Obsidian仓库`
- 实测该目录 **不存在**；`backend/.env` 无 MODERATION 覆盖；8000 进程命令行无相关环境变量
- `__init__.py:241-243` 用 `except Exception: return None` 吞掉异常
- 实测异常：`FileNotFoundError: 政策库目录不存在：D:\Obsidian仓库\AI舆情审核知识库\政策库`

**结论：`_policy_signal` 永远返回 `(None,None,[])`，政策优先、vault 规则集、链接打码目前都不参与线上判定。**「知识库已接入」在编译/CLI 层面成立，在 8000 运行时**不成立**。

把路径指向真实库后实测可用：

```
vault = D:\个人知识库\AI舆情审核知识库   (存在，含子库 AI舆情审核知识库)
ruleset.hash = 1e1d7d9c29087fd1aab29f0dd788ec34bc14b19b9c841b036850363612f0297a
lexicons = 35 张，共 ~400 词
8 条样例 score_text 全部 bucket=allow（政策层不会改变这 8 例判定）
```

### RC-4 打码位置错误：全词表 replace

`__init__.py:261-266`（`_policy_signal` 内）：

```python
masked = text
for name, terms in (rs.get("lexicons") or {}).items():
    for term in terms:
        if term and term in masked:
            masked = masked.replace(term, "*" * len(term))
```

`backend/scripts/backfill_mask_forum.py:38-40` 是同一手法的另一份拷贝。

实测词表 `insult_zh_v1.yaml` 共 32 词，**被污染**：

```
- 就是
- 真是个
- 楼主就是个智障      ← 整句测试文本被当成词条
```

于是 `楼主就是个智障` 会被「就是」先替换 → `楼主**个智障` → 再替换「智障」→ **`楼主**个**`**，与用户观测完全一致（字符串替换是确定性的）。
用 backfill 的同一算法实测（正确 vault 下）：

```
REPLACED TERMS = ['楼主就是个智障']
RESULT = *******        ← 整句被吞
```

### RC-5 链接四层未接线

`git stash show -p stash@{0}`：`_link_signal` + `mask_any_hit` 只写在 stash，**guard_text 从未调用**，且 stash 里的 `mask_any_hit` 放在所有 `return` 之后（L140 已 return），永远不会执行——这就是「未生效」的原因。

## 3. 改动方案（分批，待批准）

### 批次 A（必做，修主诉）

**A1. `content_guard/__init__.py` — 删掉两处语境放行**

- 删除 L127-129（NEWS_EDU 降 pass）、L131-140（自嘲降 pass）
- 保留「低置信度降 review」逻辑（judgments 内部），它不会漏放
- 效果：词库命中后只剩 mask / review / block 三种出口，**没有任何路径能把命中降成 pass**

**A2. `content_guard/__init__.py` — 链接四层（新 `_link_signal`，接线到 guard_text）**

| 层 | 规则 | 处置 |
|---|---|---|
| L1 白名单 | 站内域名（127.0.0.1/localhost/li-an 域名）、`.gov.cn`、`.edu.cn` | 不处理 |
| L2 短链 | t.cn / bit.ly / dwz.cn / url.cn / tinyurl.com / b23.tv / suo.im / s.id | **block**（level=blocked） |
| L3 黑名单 | pornhub / xvideos / xnxx / 91porn / sehuatang 等（常量 + env 追加） | **block** |
| L4 普通外链 | 其余 http(s):// / www. / 裸域名 | **打码 + 送审** |

- 识别：`https?://…`、`www.…`、`[a-z0-9-]+\.[a-z]{2,}/…`，忽略站内路径
- L4 实现：`decision=review, level=reviewed, masked_text=…http://****…`，并调用 `judgments.record_judgment` 落 `cg_judgment + cg_task(state=pending)`，**真正进人工队列**（不是只打个标记）
- block 时 `words` 填 `["外链"]`/`["短链"]`，避免论坛报错信息出现空词表

**A3. `content_guard/__init__.py` — 修打码位置**

`_policy_signal` 不再遍历全词表：只对**触发本次判定的规则**命中的词条打码，按「长词优先 + 位置不重叠」替换；并且只替换出现在原文中的命中词。
（前提：D3 清掉污染词，否则「就是」仍会被打。）

**A4. `api/v1/community/forum.py` — review 级别也应用 masked_text**

现状只在 `level==MASKED` 时用 `masked_text`；`REVIEWED` 发原样。改为两者都应用（2 处：发帖 L631-634、评论 L1127-1129），这样「打码送审」才真的打码；block 保持拦截。

**A5. 测试（TDD，先红后绿）**

`backend/tests/test_content_guard.py` 新增：

- `test_wrapper_never_downgrades_hit`：上文 8 例参数化，断言 wrapper ≠ pass 且 masked_text 只含命中词
- `test_link_four_layers`：短链/黑名单 → block；普通外链 → review + masked + cg_task 落库；站内链接 → 不受影响
- `test_forum_review_masks_content`：发评论命中 reviewed 词，落库内容含 `*`，cg_task.state=pending
- `test_policy_mask_only_hits`：给定含「就是」的文本，断言不出现 `楼主**个**`

### 批次 B（建议同批，防复发；需单独点头）

**B1. 修 vault 路径**：`backend/.env` 增加 `MODERATION_VAULT_DIR=D:\个人知识库\AI舆情审核知识库`，重启 8000。否则 A3 永远跑不到（政策层仍静默）。风险：政策层开始参与判定——已实测 8 例 bucket 全 allow，风险低，但仍需回归。

**B2. 清词表污染**：备份 `insult_zh_v1.yaml` → 删除 `就是`、`真是个`、`楼主就是个智障` 三条。**该目录不在 git，删除不可回滚**，所以先 `.bak`。

**B3. 防复发**：`growth.propose_term` 自动批准条件加词条质量校验（无空白/标点、2–12 字、命中泛词黑名单拒绝）。另：`growth.approve_proposal` 会无视 `MODERATION_VAULT_WRITE=False` 直接写盘，建议加开关。

**B4. 修 backfill 脚本**：改用 `engine.detect()` 的 span 级打码（与线上一致），不再全词表 replace。
