## 四.5 模块详细设计（5 个模块，含代码落点 / 安全 / 运维考虑）

> 每个模块遵循用户全局要求 3：编写前思考「为什么这样写 / 有什么好处 / 安全 / 运维便利 / 文件位置正确性 / 后端字段完善 / 路由注册 / 前端显示 / vtj 版本一致」。

### 模块 1：图片端到端补全（问题 1）

**根因回顾**：
- 自动提取已实现（`_extract_and_save_images` 扫描 answer/analysis）
- 手动加图未打通答案/解析（`question_import.py:3547` 硬编码 `target in ('content','option')`）
- 前端无答案/解析加图按钮（`question_preview_list.vue` 只有题干/选项 pickImage）
- 预览态图片 sanitize 链缺失（预览数据从 preview_data 读取，未走 questions.py 的 sanitize 链）

**设计思路（为什么这样改）**：
- **单一事实来源**：手动加图复用现有 `attach-image` 端点 + `_extract_and_save_images`，只扩展 `target` 枚举，不新建图片写入逻辑。好处：复用尺寸上限/无关图过滤/压缩/路径安全，避免两套图片写入。
- **预览态 sanitize 复用**：预览端点直接复用 `image_service.sanitize_image_placeholders` + `sanitize_content_images`，与 questions.py 读取路径同源，保证预览与入库后展示一致（消除"预览和题库显示不一致"的历史痛点）。

**改动清单**：

| # | 文件 | 改动 | 为什么 |
|---|---|---|---|
| 1-1 | `question_import.py:3547` | `target` 枚举扩展为 `('content','option','answer','analysis')` | 打通答案/解析手动加图 |
| 1-2 | `question_import.py:3589-3608` | 加 `target=='answer'` → 写入 `item['answer']`；`target=='analysis'` → 写入 `item['answer_analysis']` | 与 content/option 同构回填 |
| 1-3 | `question_preview_list.vue` | 答案区(:103)解析区(:108)各加 `pickImage(idx,'answer')` / `pickImage(idx,'analysis')` 按钮 | 前端入口对齐后端 |
| 1-4 | `question_import.py` 预览端点 | 返回前对每题的 content/options/answer/analysis 走 sanitize 链 | 消除裸占位符/路径文本 |
| 1-5 | `teacher_questions.vue` 编辑弹窗 | 答案/解析加图按钮（复用 attach-image 或直接调用图片上传） | 教师端编辑补图 |

**安全性考虑**：
- `target` 扩展后，`option_key` 仅 `target=='option'` 时必填（沿用现有校验逻辑，不放松）。
- 图片落盘仍走 `_extract_and_save_images` 的 base64/URL/占位符三态 + SSRF + 路径遍历防护，零新增攻击面。
- 前端 `<img>` 渲染仍走 `renderQuestionContent` 的 sanitizeHtml 白名单，防 XSS。

**运维考虑**：
- 复用现有 `/static/questions/{qid}/` 目录与 QuestionImage 表，零新增存储目录，巡检脚本（image_health_check）自动覆盖。
- 答案/解析图片沿用 `image_type='题干图'` 语义（避免改枚举破坏既有数据，已在代码注释确认）。

**VTJ 纪律**：
- `question_preview_list.vue` 加按钮属 `<template>` 变更 → **必须在 VTJ 设计器拖拽完成**，AI 只改 `<script>`。
- `question_import.vue` 只改 `<script>`（handleAttachImage 支持新 target），不改 template。

### 模块 2：合并导入对标分离导入（问题 2）

**根因回顾**：`import_mode='combined'`（默认）与 `'separate'` 两路径并存，但 combined 在多内容格式（图片/材料题/复合题/三方校验）上弱于 separate（separate 有 `_essay_cross_validate` / `xingce_cross_validate` 三方校验）。

**设计思路（为什么这样改）**：
- **复用而非重建**：合并导入的"题目+答案+解析同文档"本质是"先切分 → 再就地配对"，与分离导入的"题本文档 + 答案文档 → 三方校验"共享同一套切分/配对/校验函数。改法是让 combined 路径在切分后**复用 separate 的校验函数**（题号对齐 + 分值对齐 + 题干指纹），而非各写一套。
- **图片/材料题/复合题**：combined 路径切分后，每个题目块照常走 `_extract_and_save_images`（含 answer/analysis）+ `composite_matcher` 材料题归组，确保与 separate 一致。

**改动清单**：

| # | 文件 | 改动 |
|---|---|---|
| 2-1 | `question_import.py` combined 切分后 | 调用 `_essay_cross_validate`（申论）或 `xingce_cross_validate`（行测）做内部三方校验，不一致即 blocked |
| 2-2 | `question_import.py` combined 路径 | 图片提取范围与 separate 对齐（content/options/answer/analysis 全覆盖） |
| 2-3 | `question_import.py` combined 路径 | 材料题/复合题归组复用 composite_matcher（与 separate 同源） |
| 2-4 | 前端 `question_import.vue` | 合并导入模式的预览展示与分离导入统一（共用 question_preview_list 组件） |

### 模块 5：历史复合题重组（问题 5）

**根因回顾**：question_groups 21 组仅 20 题带 group_id，存量复合题绝大多数未重组，三端无法完整查看。

**设计思路（为什么这样改）**：
