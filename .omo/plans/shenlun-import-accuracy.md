## 0. 一句话结论

申论导入失败**不是识别能力不足，而是三个结构性缺陷叠加**：
① 申论文法的"题号"与"要求子项"括号样式完全相同，现有基于括号的切分必然误判；
② 解析逻辑在**前端和后端各写了一套**，且两套都只懂行测/公专的选择题结构，**没有一套认识"给定资料 + 作答要求 + 参考答案"这三段式**；
③ 申论在主数据层是"不存在"的科目（无科目行、题型挂在公专名下），即使解析对了也无处正确落库。

因此本方案的重点**不是"加更强的识别算法"，而是"确立单一解析事实来源 + 补齐申论主数据 + 用强锚点重写申论切分状态机"**。这符合你 G6 的要求：不新建平行体系，在现有 `text_parser.py` / `mineru_service.py` 上做增量演进。

### 2.2 申论文法的真实结构（从语料直接提取）

形态 A 合订本为**严格三段式**：

```
一、注意事项                      ← 考试说明，必须丢弃（噪声）
二、给定材料                      ← 材料区
    材料1 / 材料2 …              ← 每个材料块
三、作答要求                      ← 问题区
    （1）根据"给定资料1"，…。（15 分）
        要求：
        （1）准确、全面；
        （2）恰当提炼，条理清晰；
        （3）不超过350 字。
    （2）…
    （5）…自拟题目…（40 分）
参考答案：                        ← 答案区（出现次数 == 题目数，天然按序配对）
    【参考答案一】 / 【参考答案二】   ← 部分卷有两套答案
参考答案说明：…                    ← 评分说明 → 应入 answer_analysis
（1）段3 中的要点④和段4 中的要点⑪⑫都属于…可考虑合并   ← 采分点 → 应入 answer_analysis
```

**关键发现 —— 这是整个病根：**

| 编号 | 事实 | 后果 |
|------|------|------|
| **A1** | 题号用 `（1）（2）`，**要求子项也用 `（1）（2）`，括号样式完全相同** | 任何基于括号的切分都必然把要求子项误判为独立题 |
| **A2** | 每题**必有分值标记** `（15 分）`，**要求子项绝不含"分）"** | ← **可用的硬锚点**，比括号可靠 |
| **A3** | 材料区标题用"**给定材料**/材料N"，题干引用用"**给定资料**N" | 术语不一致，可作二级锚点 |
| **A4** | PDF 提取插入页眉页脚噪声：`- 5 -`、`2018 年国家公考《…》`，且**插进句子中间**（`不超过400 字。 \| - 5 - \| 分）`） | 直接污染题干文本 |
| **A5** | 合订本答案按序对应题目 | 形态 A **不需要** separate-match 配对 |

### 2.3 线上失败现场（今天 07:48–07:55 的真实导入记录）

语料：`2023年公务员多省联考《申论》题（安徽A、普通选调卷）.pdf` + 同名`答案.pdf`（形态 B）

`question_import_record` id 1359–1362，每份只解析出 **4 个 item**，且**全部停在 `PREVIEW` 从未 confirm** → **`question_bank` 表申论 0 条**（实测全库 2583 条全是 `subject_id=3` 公专，行测与申论均为 0）。

| item | 实际 `question_content` | 问题 |
|------|------------------------|------|
| 1 | `根据"给定资料1"，请概括A市…（15分）\| 要求：\| （1）准确全面；` | 正确识别到题1，但被截断 |
| 2 | `（2）分条列出；` | ❌ **不是题目**，是题1的要求第2条 |
| 3 | `（3）成效与措施相对应；` | ❌ 同上 |
| 4 | `（4）不超过200字。 \| 2. 请结合"给定资料2"…` | ❌ 题1要求第4条 **+ 真题2/3/4/5 全部粘连** |

- **F1** 实际 5 题只解析出 4 项，其中 3 项是要求子项、1 项是粘连大块 → **题目召回率 0/5**
- **F2 给定资料（材料）完全丢失**：`raw_text` 有 7894 字符含材料正文，但**没有任何 item 承载材料** → 申论题脱离材料即无意义
- **F3 答案/解析 100% 为 null**：答案文档走**同一套错误切分逻辑**，`参考答案` 正文被塞进 item4 的 `question_content`（5360 字符）；item4 题型竟被判为 **`单选题`** —— 申论被误判为选择题
- **F4 分值/难度全默认值**：`score=1`（真实 15/20/25…）、`difficulty=3`；题干里的"（15分）"未被提取
- **F5 可疑标记形同虚设**：解析器**自己发现了问题** —— `suspicious=true, suspicious_reason="块内混入 3 个其他题号: [1, 2, 3]"`，但不触发自动拆分或阻断，用户点确认即写入脏数据
- 值得肯定：`auto_detected_tags` **完全正确**（`exam_year=2023, exam_province=安徽, exam_type=联考, subject_category=申论`）→ **标签层没问题，坏的是"文本切分→题目建模"层**

### 2.7 MinerU 现状（G6 关键：已有什么、缺什么、冗余在哪）

`backend/app/services/mineru_service.py`（255 行）是**独立 venv 子进程封装层**：

- **契约**：任何失败路径 `return None`，**绝不向上抛异常**；调用方静默回退 PaddleOCR（"最差不比现状差"）
- **原因**：主后端 Python 3.13.5，MinerU 在 Windows 上限 3.12，故 `MINERU_PYTHON` 指向独立 venv
- **调用**：`python -m mineru.cli.client -p in.pdf -o outdir -b pipeline`，超时 `MINERU_TIMEOUT`(300s)
- **护栏**：GPU 串行锁 `Semaphore(1)`（排队上限 60s，超时放弃）；`health_check` 10 分钟 TTL 缓存
- **配置**：`MINERU_ENABLED` / `MINERU_PYTHON` / `MINERU_TIMEOUT` / `MINERU_BACKEND`
- **既有设计文档**：`docs/superpowers/specs/2026-08-22-mineru-scanned-pdf-ocr-design.md` §5.1 与 `docs/superpowers/plans/2026-08-22-mineru-scanned-pdf-ocr.md`
- **前端超时预算**：960s，注释写明"GPU锁60s + MinerU 600s + PaddleOCR 240s = 900s"

## 3. 方案总览

### 3.1 核心设计原则

| 原则 | 落地 |
|------|------|
| **单一解析事实来源（SSOT）** | 解析逻辑**唯一**落在后端 `text_parser.py` 体系；前端删除重复实现，纯消费后端 preview。**这是本方案最大的一处"去冗余"** |
| **强锚点优先于样式猜测** | 用**分值标记 `（N分）`** 而非括号界定申论题边界（A2）；括号仅作辅助 |
| **三科共享版面层，差异只在科目解析器** | 行测/公专现有路径**一行不改**；申论作为新增分支插入既有分派点 |
| **不新建平行体系** | 复用 `question_groups`（材料）、`question_knowledge`（考点）、`mineru_service`（版面）、既有 `/confirm` 流程（预览） |
| **可验证优先** | 每处改造配"在 D1 十份语料上跑的可执行断言"，不接受"应该没问题" |

### 3.2 目标架构

```
PDF 上传
  │
  ├─ [L1 版面层] mineru_service.extract(buf) ── 扫描件 ──▶ MinerU 子进程
  │     └─ 返回 MineruResult{ markdown, images[], pages[] }   ← 本方案扩展点（M1 修复）
  │        失败 → None → 回退 [L2] PaddleOCR → [L3] PyMuPDF 文本直取
  │
  ├─ [分派] 按 subject_category 选解析器
  │     ├─ 行测 / 公专 → 现有 text_parser 路径（一行不改，回归须 PASS）
  │     └─ 申论 → ShenlunParser（本方案新增，落在 text_parser.py 体系内）
  │            ① 清洗噪声（页眉页脚/断行 A4）
  │            ② 三段式切分（一、/二、/三、 + 参考答案）
  │            ③ 分值锚点状态机切题（A1/A2 核心）

## 4. 申论切分状态机设计（方案技术核心）

### 4.1 为什么现有方法必然失败

现有实现（含前端 `extractQuestionFromBlock` 与后端切分）依赖 `（数字）` 作为块边界。而申论里：
- 题号：`（1）根据"给定资料1"…（15 分）`
- 要求子项：`（1）准确、全面；`
两者括号样式、位置、编号序列**完全一致**，任何"遇到 `（N）` 就切块"的规则都会把要求子项切成独立题 —— 这正是 F1 的成因。

### 4.2 新状态机：分值锚点优先

核心规则（按优先级）：

| 优先级 | 规则 | 说明 |
|--------|------|------|
| **P0 硬边界** | `（\s*(\d{1,3})\s*分\s*）` | 申论每题必有分值；**要求子项绝不含"分）"**。以此定位题尾，回溯到题号即为题头 |
| **P1 题号确认** | `（N）` 且**前文以 `要求：…；` 段落收尾** | 辅助确认，排除要求子项 |
| **P2 反证** | `（N）` 后紧跟要求特征词（准确全面/不超过/条理清晰/紧扣资料/字数/自选角度/观点明确/内容具体/语言流畅/逻辑清晰）且**不含分值** | 判为要求子项，归入当前题 `requirements` |
| **P3 兜底** | 无分值标记的题（如部分卷） | 退化为"题号 + 段落长度 + 动词特征（概括/分析/谈谈/撰写/写一篇）"综合判定，并置 `need_review=1` 交人工 |

### 4.3 三段式区段定位

| 区段 | 锚点 | 产出 |
|------|------|------|
| 噪声区 | `一、注意事项` ~ `二、` | 整段丢弃 |
| 材料区 | `二、给定材料`（或`给定资料`）~ `三、作答要求` | 抽为 `QuestionGroup.shared_content`；`材料N` 为块内小标题 |
| 问题区 | `三、作答要求` ~ 首个 `参考答案` | 按 §4.2 切题 |
| 答案区 | `参考答案：` / `【参考答案一】` 起 | 按序与题号配对 |

区段锚点需兼容：`二、给定材料` vs `二、给定资料`、`三、作答要求` 变体，以及无「一、」直接以「材料1」开头的卷。

### 4.4 噪声清洗（A4）

需剔除且**仅剔除**（避免误伤正文）：
- 独立成行的页码 `- 5 -`、`- 12 -`、`第 3 页`
- 页眉页脚 `20XX 年国家公考《…》`（出现在区段边界）
- PDF 提取产生的**行内**断页标记：`(不超过\d+字。)\s*-\s*\d+\s*-\s*(分）)` → 需回接
- 材料正文中的合法 `-` 与数字不得误删 → 用"两侧均为空白 + 纯数字 + 短行"三重条件

### 4.5 校验器（F5 的根治：把"标记"改成"阻断"）

`preview` 前必须全部通过，任一失败即**拒绝生成 preview** 并返回可读原因：

| 校验项 | 通过条件 |
|--------|---------|
| V-1 题目数 | 解析题数 == `三、作答要求` 区段内分值标记数 |
| V-2 题号连续 | 题号序列无跳号/无重复 |
| V-3 答案配对 | **答案段数** == 题目数。⚠️ **必须用 `参考答案：`（带全角冒号的段首）计数**，**不可用 `参考答案` 字样计数** —— 实测 D1 十份中 5 份两者不等（见 §4.6），因"参考答案说明"亦含该字样且一篇内多次出现 |
| V-4 材料覆盖 | 每道题引用的 `给定资料N` 均在材料区存在 |
| V-5 无粘连 | 任一题块内不含第二个题号 |
| V-6 分值 | 每题 `score` ∈ {10,15,20,25,30,35,40}，非 1 |
| V-7 分类 | 每题 `shenlun_subcategory` ∈ 5 个合法值，`question_knowledge` 有归属或显式标记待复核 |

**行为变更**：现有 `suspicious` 字段保留（前端已在用）但**追加 `blocked=true` + `block_reasons[]`**，前端据此禁用"确认导入"按钮。

### 4.6 全语料实测统计（254 份 PDF，修正了三条初始假设）

我对全部 254 份 PDF 做了分值锚点与图片数扫描，得到以下**必须修正方案**的事实：

| # | 初始假设 | 实测结果 | 修正 |
|---|---------|---------|------|
| **B1** | `参考答案` 字样数 == 答案数 | **不成立**。D1 十份实测：`参考答案` 字样数 / 分值锚点数 = 5/5、**7/4**、**10/5**、**14/9**、5/5、5/5、**11/5**、**11/5**、5/5、**6/3** | 答案锚点必须用 **`参考答案：`（带全角冒号的段首）**；且**校验必须允许"段数≠题数"时降级告警而非直接失败**（部分卷含多套答案或评分说明嵌套） |
| **B2** | 国考每年题量固定 | **不成立**。2019 省级分值锚点=**9**，地市级=**5**；2022 行政执法=**3** | 题数必须**动态推导**，禁止硬编码 |
| **B3** | 图片是边缘情况 | **不成立**。**254 份中有 118 份含图片（46%）** | 图片映射是**主干需求**，不是特例；§4A 图片专项必须做实 |

## 6. MinerU 改造（G6：增强现有，不新建）

{ file, 题号, 题干全文, 要求清单[], 分值, 题型, 模块(子科目), 考点,
  材料归属(材料N), 答案全文, 解析(参考答案说明+采分点), 图片列表 }
```

**这是 D2"逐字段 100%"的唯一定义来源**。没有金标准，"100% 精确"不可度量。

### 8.2 自动断言脚本

仿照现有 `parser_regression.txt` 范式，新增 `申论解析回归` 报告，逐份输出并与金标准 diff：

| 模式 | 语料 | 断言项 | 通过标准 |
|------|------|--------|---------|
| **combined** | D1 十份（合订本） | 题目数 / 题号序列 / 题干文本 / 要求清单 / 分值 / 题型 / 模块·考点 / 材料归属 / 答案配对 / 解析内容 / 图片映射 | **逐字段 100% 一致** |
| **separate** | 追加 2 组含图表卷 | 同上 + **答案覆盖率=100%** + 图片映射（图/归属/顺序） | **逐字段 100% 一致** |
| **combined** | 含图表卷（作为分离型的对照组） | 同 combined 项 | 100% |

归一化规则（比对前统一）：全角→半角标点、去页眉页脚、折叠空白、去 PDF 断行标记。归一化规则本身必须写进金标准文件，保证可复现。

### 8.3 回归护栏
