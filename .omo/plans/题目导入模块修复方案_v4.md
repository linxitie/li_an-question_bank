## 一、症状 → 根因(代码级证据)

### P1 上传卡顿(30s 超时,反复重试)

| 层 | 根因 | 证据 |
|---|---|---|
| 前端 | status 轮询写死 `fetchWithRetry(..., 30000, 2)`,即每次轮询 30s 超时 ×3 次尝试 ≈ 90s+ 才抛错 | `question_import.vue:794/809` |
| 前端 | `controller.abort(new Error('client timeout: 30000ms'))` 的拒绝 reason 是普通 Error 而非 AbortError,走错分支(:705 而非 :703),错误文案误导 | `question_import.vue:687-714` |
| 后端 | `_process_import_async` 在线程池跑,但长事务/DB 锁可能阻塞 `/status` 读查询(待实测确认 WAL 状态与事务粒度) | `question_import.py` `_process_import_async` + `/status` |

**修复**:A-1 前端超时参数下调(status 是短请求,10s 足够)+ abort 用 `DOMException('TimeoutError', 'TimeoutError')` 或 `signal.reason`;A-2 后端实测 /status 延迟,若 DB 锁则缩短写事务。

### P2 大量「解析缺失」+ 题型误判(选择题→判断题)

| 根因 | 证据 |
|---|---|
| 公专分离匹配 `smart_match_questions_answers` 纯内容题号匹配;答案 PDF「答案及解析」格式的解析不完整 → analysis 未附加 | `text_parser.py` `parse_answer_text_to_map` / `smart_match_questions_answers` |
| `_detect_question_type` 对「如图,问②代表的是」这类流程图单选题误判为判断题 | `text_parser.py:_detect_question_type` |

**修复**:C-1 答案/解析提取增强(「答案及解析」形态);B-3 题型判定规则修正。

### P3 图片全部无法展示(题干/选项/答案/解析)

| # | 根因 | 证据 |
|---|---|---|
| 主因 | 前端批量导入走 `/parse` 端点,其响应 questions **不做 `[IMAGE:]` sanitize**;前端 `questionRender.js` 把所有残留 `[IMAGE:]` 剥成空字符串 → 图片集体消失。sanitize 只存在于 `/status` 全量路径 `_sanitize_preview_images` | `question_import.py` `/parse` + `image_service.py:sanitize_image_placeholders`;`src/utils/questionRender.js:66-72` |
| 次因1 | docx **表格单元格**图片落盘但不写 `[IMAGE:]` 标记(静默丢图) | `question_ingest/docx_reader.py`(表格循环) |
| 次因2 | docx `qn_re` 把「回答第98~100题」里的「100题」误判为题号 100 → 图片归属错位 | `question_ingest/docx_reader.py:189` |

**修复**:A-2 `/parse` 响应接入 `sanitize_image_placeholders`(复用现有函数,与 `/status` 同款);A-3 docx 表格图补标记 + qn_re 排除「第\d+~\d+题」伪题号。

### P4 复合题材料串题(材料塞进第97题,子题分割)

| # | 根因 | 证据 |
|---|---|---|
| 1 | `_MATERIAL_HEAD_RE` 不匹配「根据以下情境材料，回答**第**98~100题」——正则 `回答[ \t]*(\d+)` 漏了「第」字前缀,材料头未被识别,材料文本留在 Q97 块尾 | `text_parser.py:_MATERIAL_HEAD_RE` |
| 2 | `composite_matcher` 的 range 规则同样 `回答\s*(\d+)` 不匹配「第」 | `composite_matcher.py:38-42` |
| 3 | ⚠️ `extract_question_blocks` 内 `pending_spill` 在**同一迭代**被消费(材料前置到当前块),与注释「溢出的节首材料留给下一题」矛盾——这是把材料塞进第 97 题的**直接机制** | `text_parser.py:2938-2948` |

**修复**:B-1 两处正则补 `(?:第)?` 容忍;B-2 `pending_spill` 语义修正(材料回吐给**下一题块**)。
**⚠️ B-2 位于 `extract_question_blocks` 函数体内,该函数体是 L0 SHA 红线。修复需更新 gate_l0_redlines.py 基线并经你明确批准。**

### P5 分离导入命名映射(命名明显对应却匹配不到位)

| # | 根因 | 证据 |
|---|---|---|
| 1 | 前端只传 `questions_text/answers_text` 给 `/parse`,**文件名从未上传**;`separateQuestionsFileName/AnswersFileName` 只存在前端 state 从未使用 | `question_import.vue:1563-1569`(payload)+ `:1896/1944`(state) |
| 2 | `/separate-match`、`/separate-match-xingce` 已成**死代码**——`_backendSmartMatch` 无任何调用方(commit 9ffafd3 把前端重接线到 `callBackendParse` 时孤儿化) | `question_import.vue:2207` 定义无调用 |
| 3 | 全仓无任何「文件名相似度/公共前缀」配对机制 | grep 确认 |

**修复**:C-2 前端把两个文件名传给 `/parse`;后端新增 `question_ingest/pairing.py`(文件名归一化:去扩展名、去「答案及解析/参考答案/解析/（部分）/打印」后缀 → 公共前缀 + SequenceMatcher 相似度),作为**配对信号与诊断提示**(相似度高但匹配率低 → 明确告警「疑似同一套卷,内容匹配失败」;相似度低 → 提示核对文件)。

1. 上传真实 docx/pdf **无 30s 超时**(或单次失败即给出可读错误,不空转 90s)。
