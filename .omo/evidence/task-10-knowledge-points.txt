## 2. level需 +1 映射（对齐既有约定）

既有 126 行的实测结构：

| subject_id | 行数 | 有父 | level 分布 |
|---|---|---|---|
| 1（行测） | 34 | 0 | 全部 level=2 |
| 2（申论） | 25 | 0 | 全部 level=2 |

→ **既有约定：level=2 为顶层知识点，无 level=1**（如 `行政处罚概述(L3, parent=70)`）。
故任务 5 清单的 path 深度 1 映射为 DB `level=2`，即 `db_level = depth + 1`，
以保持全库层级语义一致，而非引入全库孤立的 level=1。

## 3. 「同父同名」与「同名」的区分（判定依据）

初次检查报出「重复名 17个」（`其他`×35、`主题词`×3、`二级辨析`×3…），一度疑似重复插入。

**判定**：去重键是**完整路径**而非叶名，因此同名叶子挂在**不同父节点**下是合法层级：
```
主题词 → 父=中心理解题 1 个
主题词 → 父=特殊问法   1 个
其他   → 分散于 非首句特征/遍历/语法关系/语义/行程问题/行文逻辑 … 各 1 个
```
真正的 bug 判据是**同一父节点下同名**。实测 `group by parent_id, point_name having count>1` = **0**。

**结论：迁移正确，17 组同名属不同分支，非重复。**

## 4. 验证中发现并修复的 4 个真实缺陷

### 4.1 门禁正则过宽 → 误判既有知识点
初版用 `point_name like '%特色%'` 校验「省级私有点不得入库」，命中 2 行：
```
(1,  '习近平新时代中国特色社会主义思想')   ← "特色社会主义"里的"特色"
(65, '中国特色社会主义法治理论')           ← 同上
```
省级私有点形态是 `XX特色-值`，须匹配「特色 + 分隔符」。改为正则
`特色\s*[-－—–]` 后命中 0，数据本身自始正确。

### 4.2 rollback 校验基线取错 → KeyError
`--rollback` 用**回滚前**的当前状态（631 行）作基线比对，而应比对**迁移前**的 126 行：
```
File "migrate_xingce_knowledge_points.py", line 129
    kept = all(before[k] == after[k] for k in before)
KeyError: 127
```
改为 apply 时把迁移前基线快照写入 manifest 的 `pre_apply`，rollback 据此校验。

### 4.3 manifest 被幂等重跑覆盖 → 回滚能力被摧毁
`--apply` 每次都重写 manifest。幂等重跑时 `需新建=0`，于是
`created_point_ids` 被覆盖成 `[]`，首次 apply 的 505 个 id 全部丢失 →
后续 `--rollback` 读到空清单而「无需回滚」，**静默不回滚**（实测终态仍 631 行）。
修正为**并集合并** `sorted(set(prev_ids) | set(created))`。

### 4.4 `pre_apply` 基线被污染 → 误报 505 行「缺失」
`created_point_ids` 修好后，`pre_apply` 仍每次覆盖：幂等重跑时 `before` 已是 631 行，
基线被写成迁移后状态。rollback 用它校验回退后的 126 行库：
```
基线 631 行：缺失 505，被改 0     ← 误报
基线逐字段未变: False             ← 假失败
```
修正：基线**只在首次 apply 确立一次**（`base_out = prev_base if prev_base else ...`）。

### 4.5 `shutil.copy2` 在 WAL 模式下备份不可靠（额外发现）
`journal_mode=wal`，实测存在 6MB 的 `question_bank.db-wal`。
`shutil.copy2` 只拷主库文件，完整性无保证；且恢复时若残留旧 `-wal` 会被回放——
把126 行的基线还原成 631 行（本次实测踩中）。
改用 SQLite 官方备份 API 并**校验备份行数**，不一致即中止：
```python
src.backup(dst)
chk = sqlite3.connect(bak).execute("select count(*) from knowledge_point").fetchone()[0]
if chk != len(before): return 1   # [abort]
```
> 恢复 DB 时若用文件覆盖，必须同时删除 `-wal` / `-shm`，否则 WAL 回放会污染结果。
