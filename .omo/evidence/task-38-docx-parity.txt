Task 38 (I-3) 畸形 docx 容错链路 parity — S3 场景
=================================================

方法: 构造与真实畸形文件（2019年深圳市公安局第四批公开招聘警务辅助人员考试
《行政职业能力测验》真题.docx，word/_rels/document.xml.rels 含 Target="../NULL"）
同型的合成样本，分别调用新模块路径与 API re-export 路径。

输入:
  valid     = python-docx 生成的正常 docx（1. 测试题干内容 / A. 选项一 / B. 选项二）
  malformed = valid 重打包 + 悬空 relationship Target="../NULL"

sanity: python-docx 直接打开 malformed 抛
  KeyError: "There is no item named 'NULL' in the archive"（与线上实测一致）

_extract_text_from_docx(valid)     = '1. 测试题干内容\nA. 选项一\nB. 选项二'
_extract_text_from_docx(malformed) = '1. 测试题干内容\nA. 选项一\nB. 选项二'
via_api = from app.api.v1.question_import import _extract_text_from_docx
via_api(malformed) == _extract_text_from_docx(malformed)  # 两条路径输出逐字节相同

三级容错链日志（移动后仍完整生效）:
  [docx] 直接打开失败(KeyError: ...)，尝试清洗关系后重试
  [docx] 清洗掉 1 个悬空 relationship 后重试打开
  => 成功提取，文本不丢、长度 > 0

_sanitize_docx_rels(malformed) 返回可打开新包（非 None），
Document(io.BytesIO(fixed)) 打开成功。

结论: 畸形 docx 容错逻辑零回归；纯移动前后行为一致
（另: 移动块 SHA256 一致，见 task-38-pure-move.txt，行为一致性有构造性保证）。
