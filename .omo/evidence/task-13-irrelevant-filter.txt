## 两处「空过」陷阱（自我修正，务必记录）

第 5 节首版连续失败两次，**两次都差点被误报为 PASS**：

### 1. 候选池为 0 —— 完全空过

```
首版输出: 候选（min边>=40）图片 0 张，抽样 20 张送入过滤
          判定分布: {'keep': 0, 'suspect': 0, 'block': 0}
          [PASS] 抽样中 0 张二维码解码成功     ← 假通过
```

根因：`ROOT` 被设为**单个省目录** `国考行测`，却仍按「遍历 24 个省目录」
的模式走`os.path.isdir()`，对 PDF 文件全部为假 → **一张图都没扫到**。
「0 张二维码」在候选为 0 时是**恒真**的伪断言。

修正：遍历整棵行测树；并新增 `候选池非空（防止本节空过）` 断言兜底。

### 2. 解码数为 0 —— 仍是空过

```
修正候选池后: 候选 877 个，但 成功解码并送入过滤的图片数 = 0
             [FAIL] 确实有图片被送入过滤器（20 张级）   ← 门禁抓住了
```

根因：内层循环在**第一页后无条件 `break`**，而合格大图多在后续页；
遇到首页全是碎片时 `out` 恒为 None。

修正：扫**所有页**直到有一张解码成功才跳出，并新增
`确实有图片被送入过滤器（20 张级）` 断言（实测 20 ≥ 10 通过）。

> 教训：抽样类断言必须同时断言「候选池非空」与「实际送入数达标」，
> 否则「0 张违规」会在「0 张受检」下静默成立。
