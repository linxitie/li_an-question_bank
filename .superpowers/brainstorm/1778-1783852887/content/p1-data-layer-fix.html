🔧 修复 #2: 选项缺失问题 — 解析引擎重构

❌ 当前问题

根因定位：_extract_options() 函数

问题1: 同行多选项分割有bug
正则 (?=[A-D]\s*[.、．、．)]) 在遇到连续中文时可能漏切

问题2: 不足4个时的fallback逻辑不完善
_extract_question_blocks中的回退正则使用了DOTALL但边界匹配不够严格

问题3: 选项清理逻辑粗暴
从content_text中删除选项行时使用简单的replace(line, '', 1)，可能误删

✅ 修复方案

方案：三层回退解析策略

L1 - 结构化解析：
增强版正则：支持全角半角混排、中文标点
([A-D])\s*[.、．、．)）]\s*(.+?)(?=\s*[A-D]\s*[.、．、．)）]|$)

L2 - 段落回退：
当L1结果不足2个时，扫描连续段落查找选项模式
支持"ABCD"单行、"A/B/C/D"斜杠分隔等多格式

L3 - LLM兜底：
前两层结果不足时，调用LLM从题干文本中抽取选项
（复用已有的LLM匹配基础设施）

🖼️ 修复 #3: 图片显示 IMAGE:0_87 问题

❌ 当前问题

占位符格式：[IMAGE:0_87]

当前正则：/\[IMAGE:(\d+)_(\d+)\]/g

替换为：/static/questions/0_87.png

失败原因：
1. 图片文件实际未保存到该路径
2. 导入时图片提取逻辑不完整
3. 数据库question_image表有定义但未使用

✅ 修复方案

完整链路修复：

1. 导入时：从Word/PDF中提取图片 → 保存到 uploads/questions/{question_id}/

2. 存储时：写入 question_image 表（已定义但未使用）关联题目ID+图片类型

3. 读取时：GET /api/questions/{id} 返回 images 字段

4. 展示时：前端接收图片URL数组，按 image_type 分别渲染到题干/选项区域

向后兼容：保留 IMAGE 占位符替换作为兜底

🏷️ 修复 #4: 单选/多选题分类入库

✅ 修复：完整的数据写入链路

问题根因：question_import.py 中写入QuestionBank时，未同步创建QuestionDetailCategory记录

修复步骤：

步骤 位置 操作
1. 解析阶段 text_parser.py::_detect_question_type() 增强关键词库，新增"下列选项"、"属于"、"包括"等多选标志
2. 入库阶段 question_import.py 每题写入时同时创建QuestionDetailCategory记录，填充question_type_detail字段

4. 修复阶段 迁移脚本 对已有题目，根据answer长度和题干关键词自动回填type

📊 难度分析 — 渐进式IRT方案

三阶段渐进：冷启动 → Rasch → 2PL

❄️ 冷启动 (<30次)

难度 = max(1, min(5, round(5*(1-正确率))))

新题默认难度3（中等）

🔥 预热 (30-200次)

Rasch 1PL模型估计b参数

固定a=1, c=0

⚡ 成熟 (>200次)

2PL模型估计b+a参数

区分度a ∈ [0.3, 3.0]

实现：新增 services/difficulty.py — 核心算法约200行，使用scipy.optimize进行MLE参数估计。定时任务每100次新答题触发一次全量重估。
