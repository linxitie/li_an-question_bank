答题卡模块 — 问题诊断与优化方向

以下是当前识别出的7个问题及其影响评估

📋 问题清单

#1

选项缺失

导入解析时选项提取不完整（如只有BCD缺少A）。根因在_extract_options()对同行多选项的分割逻辑有bug

影响：🔴 严重 — 学生无法看到完整选项

#2

图片显示为 IMAGE:0_87

题干/选项中的图片占位符未被正确替换为<img>标签。正则替换逻辑存在但未覆盖所有格式

影响：🔴 严重 — 图文题目完全不可用

#3

单选题/多选题分类缺失

导入题目后question_type_detail字段未正确写入数据库，前端题型徽章显示错误

影响：🟠 中等 — 学生无法区分题目类型

#4

多选题不能多选

逻辑已支持数组型答案存储（selectOption的toggle逻辑），但UI层未区分单选/多选的视觉交互（无checkbox样式）

影响：🔴 严重 — 多选题功能不可用

#5

错题答案解析缺失

部分题目answer_analysis字段为空或未正确关联到前端显示

影响：🟠 中等 — 学生无法理解错题原因

#6

难度分析缺失

系统未对题目进行难度等级评分。数据库difficulty字段默认为3

影响：🟡 低 — 影响智能组卷和个性化推荐

#7

VTJ DSL节点设计

路由定义过于简单，部分DSL节点缺少数据源配置，接口调用未走统一的apiFetch通道

影响：🟡 低 — 影响系统的可维护性

🎯 设计优先级建议

修复策略：自底向上（数据层 → 业务层 → 展示层）
Phase 1: 数据层修复
├─ 选项解析引擎重构（修复选项缺失根因）
├─ 图片导入/存储/引用链路修复
└─ 题型分类入库逻辑修复

Phase 2: 业务逻辑层
├─ 多选题交互逻辑完善（checkbox UI + 数组存储）
├─ 答案解析关联修复
└─ 难度自动评估算法

Phase 3: 展示层优化
├─ VTJ DSL节点规范化
├─ 路由/接口调用标准化
└─ 题型徽章UI完善
