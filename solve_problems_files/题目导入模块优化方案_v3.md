## 一、背景与目标

### 1.1 背景

设计文档 `题目导入功能添加与复合题目处理.md` 第五部分（第 398~440 行）提出了一个 `SubjectClassifier`，用硬编码关键词表识别「行测/申论/公专」与分类。

经三轮代码调研 + 真实数据库核对，发现该设计**严重低估了现状**：代码库中**已经存在 4~5 套并行的科目/分类关键词字典**，若照搬设计文档的 `SubjectClassifier`，将成为第 6 套重复实现，进一步恶化「多套并行、无单一事实来源」的根因，直接违反「去粗取精、在已有基础上优化、禁止胡乱新建」。

### 1.2 目标

1. **根治多套并行**：把 4~5 套硬编码关键词字典收敛为「单一事实来源」，并对齐数据库真实 taxonomy（3 科目 / 16 子科目 / 三级考点树）。
2. **自动识别 + 用户可覆盖**：识别器只做「预填建议 + 置信度提示」，入库前教师可一键覆盖（用户已确认决策）。
3. **四层全覆盖**：行测/申论/公专 全科目、全分类、全子分类、全考点（用户已确认决策）。
4. **不回归**：L0 红线门禁全绿，既有导入回归基线不倒退。

### 1.3 范围边界

- **IN**：科目/分类/子分类/考点 的「单一事实来源」收敛、自动识别、用户覆盖、前端下拉 API 化。
- **OUT**：复合题（资料分析/材料题）的题组识别与图片链路（已在前序方案落地，另有专项）；题型判定 `_detect_question_type`（与科目分类正交，不动）。

## 三、设计决策（单一事实来源）

### 3.1 总原则

- **科目**：单一入口 `detect_subject_category()`（text_parser.py），关键词字典收敛为**一份**，科目名从 `question_subject` 表读取（不再硬编码 3 个字符串）。
- **子科目 + 考点**：单一引擎 `QuestionClassifier`（question_classifier.py），关键词字典收敛为**一份**，且 `classify()` 一律解析真实 DB id。
- **文件名启发式**：`_auto_detect_tags` 保留（文件名维度与内容维度互补），但其「文件名关键词 → 科目名」映射收敛到同一份 DB 事实。
- **手选优先**：任何自动识别结果都只是「建议值」，入库前教师手选值 > 自动识别值。

### 3.2 决策矩阵（用户已确认）

| 决策点 | 结论 |
|---|---|
| 分类器定位 | 自动识别 + 用户可覆盖（建议预填 + 置信度提示 + 一键覆盖） |
| 覆盖范围 | 全科目 + 全分类 + 全子分类 + 全考点，四层全覆盖 |
| 下钻深度 | 数据库层 / 算法层 / 接口层 / 前端层，四层详设 |
| 归档 | 新建 v3 文档 + README 索引追加 |

## 五、算法层详设

### 5.1 科目级：`detect_subject_category()` 改造（text_parser.py:4176-4210）

**现状**：硬编码 3 科目 `SUBJECT_KEYWORDS`（core/high/normal 三级权重），采样前 3000 字符打分，<0.3 回退「行测」。

**改造**（保持函数签名不变，L0 红线不涉及此函数体）：

1. 关键词字典**收敛为一份**，科目名从 `question_subject` 表读取（避免硬编码 3 个字符串）。
2. **置信度算法修正**：`confidence = 命中关键词加权和 / 理论最大加权和`。
3. **静默误分类兜底**：全 0 分 → 返回 `(subject_name='', confidence=0.0)`，由调用方决定「回退手选 + 标 `need_review`」，**不再静默回退「行测」**。
4. 返回结构新增 `matched_keywords`，供前端展示「建议依据」。

### 5.2 子科目/考点级：`QuestionClassifier` 收敛（question_classifier.py）

1. `SUB_CATEGORY_IDS`（:52-72）保留为「子科目名 → id」缓存，但**运行时从 DB 反查**，不再硬编码 id 数字。
2. `SUB_CATEGORY_KP_MAP`（:75-146）假 kp id（101-1519）**全部改为「考点名」**，`classify()` 强制走 DB 反查真实 `point_id`。
3. `classify()` 与 `classify_with_db()` 合并语义：**公开接口一律返回真实 DB id**。
4. `detect_subcategory_enhanced()`（:1235）向后兼容包装保留，`'无法分类'`→`'无'` 语义不变。

### 5.3 删除死代码

- `exam_detector.py` 全文件删除（5 科目 taxonomy 与真实 3 科目不符，全仓 0 调用方）。删除前 `grep -rn "exam_detector"` 全仓确认无 import。

### 5.4 文件名启发式：`_auto_detect_tags` 收敛（question_import.py:1491-1499）

- 保留文件名维度（上传文件名「2024公安专业科目真题.pdf」→ 公专 合理且必需）。
- 其 subjects 映射的**科目名 key 收敛到 DB 事实**（避免「公安专业考试」这种第 5 套叫法）。

### 5.5 冲突消解顺序

```
最终科目 = 教师手选值（若手选） > 文件名启发式（_auto_detect_tags） > 内容检测（detect_subject_category）
最终子科目 = 教师手选值 > 行测分节路由（route_xingce_sections） > 关键词检测（QuestionClassifier）
最终考点 = 考点归一化（_xingce_kao_normalize_map / 解析【考点】字段） > 关键词检测
```

> 关键点：**手选永远压过自动识别**，自动识别只做「预填建议」。

## 六、接口层详设

### 6.1 新增：taxonomy 查询接口（供前端下拉）

**现状**：前端科目下拉是硬编码 4 选项（`question_import.vue:84-89`），无 API 供选项。

**新增**（挂在现有 `question_import.py` router，`prefix="/api/questions/import"`）：

```
GET /api/questions/import/taxonomy
→ 200 {
  "subjects": [{"id":1,"name":"行测","code":"auto_行测"}, ...],
  "subcategories": [{"id":1,"subject_id":1,"name":"政治理论"}, ...],
  "knowledge_points": [...]  # 可懒加载，分科目返回
}
```

- 后端读三张 taxonomy 表，**不新增表**。
- 该接口是「单一事实来源」的**读出口**，前端下拉、预览建议、编辑页统一消费它。

### 6.2 改造：导入端点返回「建议 + 置信度」

在现有 `/upload`、`/parse`、`/separate-match-xingce`、`/ocr`、`/image` 的返回体里**追加**（不改既有字段，向后兼容）：

```json
{
  "subject_suggestion": {"name":"行测","confidence":0.92,"matched_keywords":["资料分析","增长率","比重"]},
  "subcategory_suggestion": {"name":"资料分析","confidence":0.88}
}
```

### 6.3 确认入库端点：手选优先

`/confirm`（`question_import.py:3716`）改造：

- 现有 `subject = _get_or_create_subject(item.subject_name or detected_subject_hint(...))` 逻辑**保留**。
- 强化：若 `item.subject_name`（手选）存在，**跳过自动识别**；若不存在，才用自动识别结果 + 标 `need_review`（低置信度时）。
