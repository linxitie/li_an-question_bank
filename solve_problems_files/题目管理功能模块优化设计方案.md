## 二、问题 1 设计：UTB 乱码清除 + 防再污染

### 2.1 根因链

```
test_batch_parsed_import.py（直连真实库）
  → 断言失败 → 清理代码（L120+）不执行
    → 10 题 + 2 试卷残留（UTB 标记 + 测试要点模板）
      → fix_utb_in_db.py 只清字符串 → 空壳题仍在
        → 前端 cleanHtmlContent 只是显示层遮丑
```

### 2.2 修复设计（三层防御）

| 层 | 动作 | 文件 | 说明 |
|---|---|---|---|
| R1 数据修复 | 新增 `repair_utb_pollution.py`：① 定位污染集（content 命中 `UTB[a-f0-9]{8,}` 或 `测试要点`）→ 删除 `question_bank` 10 行；② 删除 `exam_paper` paper_id=14/15；③ 级联清理 `paper_question_relation`、`question_import_record` 中关联行；④ **默认 `--dry-run`**，`--apply` 执行前自动备份整个 DB 至 `backend/data/backups/backup_pre_utb_{timestamp}.sqlite`；⑤ 每笔删除写入 JSONL 审计日志（表/主键/整行快照），支持 `--restore <audit.jsonl>` 一键回滚；⑥ 幂等：重跑时污染集为空则报"0 changes" | `backend/scripts/repair_utb_pollution.py`（新增） | 为什么删除而非清洗：清洗后题干残缺、选项全空，是无教学价值的空壳；测试 fixture 数据本就不该在生产库 |
| R2 测试隔离 | 测试改用**独立临时 SQLite**（pytest `tmp_path` fixture 覆写 SessionLocal 的连接）或 `SAVEPOINT` 强制回滚；清理逻辑移入 `finally`；文件头加显眼注释"禁止直连真实库" | `backend/tests/test_batch_parsed_import.py` | 防止同类污染再次发生——这是根因修复 |

## 三、问题 4 设计：题型误判修正 + 重复题去重

> 按用户批准的实施顺序，问题 4 紧随问题 1 执行。

### 3.1 根因

1. **存量误判**（7 条）：图片选项提取失败 → options=[] → `_detect_question_type` 兜底默认论述题。证据：7 条全部答案为字母、解析含"A项/B项"逐项判断。
2. **引擎缺陷**：`_detect_question_type`（text_parser.py:1781）在无选项时**不看答案形态**直接落论述兜底。
3. **前端隐患**：teacher_questions.vue 数字映射与真实库错位。
4. **重复题土壤**：同题 4~5 份副本（图片路径不同破坏精确去重），副本间题型不一致放大误判观感。

### 3.2 修复设计

| 层 | 动作 | 文件 |
|---|---|---|
| R1 存量修复 | 扩展 `repair_question_types.py` 新增规则组：`options 为空 AND（answer 归一化后为 1~4 个 A-H 字母组合 OR answer_analysis 命中 r'[A-D]项[：:]' 模式）` → 重判：单字母→单选题、多字母→多选题；**双源同步更新**（`question_bank.type_id` 映射到规范 type 行 + `question_detail_category.question_type_detail`）；dry-run 默认 + 备份 + JSONL 审计 + 幂等 | `backend/scripts/repair_question_types.py`（扩展） |
| R2 引擎修复 | `_detect_question_type`：无选项分支中**先做答案形态推断**——`canonical_answer(answer)` 为单字母→单选题，多字母→多选题；仅当答案为自由文本（长度>1 且非字母组合）才进入论述/写作关键词判定与兜底。同步检查两处调用点（question_import.py 导入链、questions.py 读路径兜底）签名一致 | `backend/app/services/text_parser.py`（1781 行区域） |
| R3 前端修复 | **删除** teacher_questions.vue 291-294 行的数字键 `'1'/'2'/'3'/'4'` 映射（保留文字键映射）；列表与详情弹窗一律使用后端返回的 `type_name`（teacher.py 已保证返回；空值时显示 '-' 而非猜测）。修改仅涉 `<script>`，改后用 vtj MCP 同步 `.vtj/files/teacher_questions.json` 的 methods 签名与 `__VERSION__` | `.vtj/vue/teacher_questions.vue` + `.vtj/files/teacher_questions.json` |
| R4 重复题去重 | 新增 `dedup_questions.py`：① 归一化题干（strip 图片标签/题号/空白后）+ 同 subject_id 分组；② 组内 `difflib.SequenceMatcher` 相似度 ≥0.95 判定为重复组；③ 每组保留"信息最全"副本（评分：解析非空 > 答案非空 > options 非空 > question_id 最小），其余标记 `status=0`（软删除，不做物理删除）；④ 关联数据（paper_question_relation、wrong_questions、exam_record 等）重定向到保留副本；⑤ **--dry-run 输出去重清单（组号/保留 qid/删除 qid/相似度）供用户确认后再 --apply**；备份+JSONL 审计+幂等 | `backend/scripts/dedup_questions.py`（新增） |

**为什么软删除而非物理删除**：重复副本可能已被学生答题记录/错题本引用，软删除保持外键完整性，且可随时恢复（status=0 不出现在任何查询中，已验证各查询均带 `status==1` 过滤）。

### 3.3 验证方式

- 修复前：7 条论述误判（diagnose_problems.py 第4节）；重复组 N 组
- 修复后：**论述误判=0**（options 空但字母答案的题全部归位单选/多选）；去重清单经用户确认后重复组=0
- 前端：教师端详情弹窗逐条核对 7 条修复题的题型徽章；任选一道 type_id=3 的单选题确认不再显示"论述题"

## 四、问题 2 设计：无关图片清理 + 导入过滤强化

### 4.1 根因

1. `_is_irrelevant_image()`（question_import.py:1073）仅尺寸启发式，二维码/推广横幅漏检。
2. 文档级推广图被逐题复制（同 MD5 多题出现）。
3. 历史清理残留 298 个空目录。

### 4.2 修复设计

| 层 | 动作 | 文件 |
|---|---|---|
| R1 存量清理 | 新增 `clean_irrelevant_images_v2.py`：**检测层（三级判定）**——<br>① **QR 解码**：`cv2.QRCodeDetector().detectAndDecode()`，decode 成功或 `detect()` 命中定位点 → 无关（OpenCV 为纯 wheel，Windows 无需外部 DLL）；<br>② **推广横幅特征**：宽高比 ≥2.5 的横幅图 + （可选轻量判定）图像上半部高对比红/黑文字块分布；<br>③ **像素统计降级**（OpenCV 不可用时）：黑白二值化后模块密度 0.35~0.65 且连通域近方形网格 → 疑似二维码；<br>**执行层**——命中图片：从 `question_content`/`options` 移除对应 `<img>` 标签 → 删除磁盘文件 → 记录 JSONL；空目录统一清除；**--dry-run 输出待删清单（qid/文件/命中原因/预览路径）供用户确认**；执行前全量备份 DB + 将待删图片移入 `data/backups/removed_images_{timestamp}/`（移动而非直接删除，可恢复） | `backend/scripts/clean_irrelevant_images_v2.py`（新增） |
| R2 导入强化 | `_is_irrelevant_image()` 增加与 R1 相同的 QR 解码分支（检测逻辑抽为共享函数 `image_filters.py` 供脚本与管线复用，**避免两套判定标准**）；OpenCV 导入失败时自动降级像素统计并打 warning 日志 | `backend/app/api/v1/question_import.py` + `backend/app/services/image_filters.py`（新增共享模块） |
| R3 映射保证 | 现有占位符→`<img>` 替换逻辑（1263-1291 行）已保证"被过滤的图片不生成标签、保留的图片标签与磁盘文件一一对应"；R2 前置过滤后**映射关系天然正确**。验收时用 `diagnose_problems.py` 的"内容引用图片但文件缺失"检查确认 0 缺失 | 验证即可，无需改动 |

### 4.3 依赖与兼容

- 新增依赖：`opencv-python`（requirements.txt 追加；纯 wheel 安装无系统依赖）。
- 降级策略：OpenCV 缺失 → 像素统计兜底（准确率略低，宁可漏杀不可误杀——**判定为"疑似"的图片只标记不删除**，进人工复核清单）。

### 4.4 验证方式

- 修复后：`diagnose_problems.py` → 空目录=0；推广图样本（5661de6d/d206d766 等）文件不存在且内容中无对应 `<img>`；"内容引用图片但文件缺失"=0
- 前端：打开原含推广图的题目详情（如 qid 1111 相关题）→ 不再显示二维码横幅；正常题目图片（如图表题）显示完好

## 五、问题 3 设计：答案解析存量回填

### 5.1 根因分层（对应用户提出的三个方向）

| 用户假设 | 验证结论 |
|---|---|
| 数据库未入库 | ✅ 成立（主体）：314 题源数据即分离，答案在独立 PDF 中 |
| 导入时未识别 | ✅ 成立：分离导入管线存在但从未对存量执行；扫描版 PDF 需 OCR |
| 映射关系不明确 | ❌ 不成立：`answer_analysis` 与题目同表同 row，映射链路完好 |

### 5.2 修复设计

| 层 | 动作 | 文件 |
|---|---|---|
| R1 存量回填 | 新增 `backfill_analysis.py`：① 遍历 `题库/答案解析（不用打印）/*.pdf` → 复用现有解析链（MinerU 引擎/文本抽取，参考 `/parse` ocr 模式与 `scripts/test_mineru.py`）；② 抽取"题号→答案+解析"映射（复用 `smart_match_questions_answers` 的题号通道 + `canonical_answer` 归一化）；③ 与存量空解析题匹配（题号 + 题干相似度双通道，同试卷年份/科目优先）；④ **置信度分级**：高置信（题号精确匹配+题干相似度≥0.8）→ `--apply` 时写入；低置信 → 输出"待人工确认清单"（CSV：qid/候选解析/相似度），**绝不盲目写入**；⑤ 每笔回填写入 JSONL 审计（qid/旧值/新值/来源 PDF/页码），支持 `--restore` 回滚；⑥ **--dry-run 输出匹配率报告**（总题数/可回填数/待人工数/无来源数）供用户审核 | `backend/scripts/backfill_analysis.py`（新增） |

### 5.3 风险与对策

- **扫描版 PDF 识别质量不可控** → 只回填高置信结果；低置信进人工清单。
- **答案文档与题目版本不对应**（同年多版本）→ 匹配时校验题量一致性与题号连续性，异常进人工清单。
- **回填错误污染数据** → JSONL 审计 + `--restore` 全量可逆。

### 5.4 验证方式

- 修复前：空解析 314 题（33%）
- 修复后：`diagnose_problems.py` → 空解析数量显著下降（目标：可回填部分全部完成），输出回填率报告；抽检 10 题回填内容与源 PDF 人工比对
