## 5. 本项目特有陷阱（踩过的坑，别再踩）

| 坑 | 现象 | 正确做法 |
|---|---|---|
| **VTJ 外壳有 overflow 祖先** | `position: sticky` 绑不到视口，元素照样随页面滚走 | 让页面自己成为滚动容器（`height:100vh` + 内层 `overflow-y:auto`），sticky 才能生效 |
| **`Set-Content` 写 `.vtj/vue/*.vue`** | 文件被 dev server 占用，写入失败但文件已被截断成 0 字节 | 一律用编辑工具（edit/apply_patch）改源码；不要用 shell 重定向写大文件 |
| **`.modal-textarea { width:100% }`** | 父容器改 flex 单行时 textarea 撑满整行导致换行 | 覆盖 `width:auto` + `flex:1 1 0` |
| **`.modal-actions` 被两处共用** | 改评论输入区会误伤发帖弹窗 | 选择器必须带父级前缀，如 `.comment-input-area .modal-actions` |
| **`:has()` 提层** | 用户卡片被帖子弹窗盖住 | `.modal-overlay:has(.profile-card){z-index:2100}`，用 `@supports selector(:has(*))` 包裹 |
| **两个 dev server** | 9527 与 5173 同源码，但某个 origin 可能存着旧 bundle，刷新也不变 | 换 origin 验证；确认是新代码再排查逻辑 |
| **5173 的 HMR 是坏的** | 页面不自动更新 | 每次改动后整页重载（或换 9527） |
| **`.vtj/` 是 raw 页** | 禁止 `vtj_sync_vue_to_dsl` | 改完只跑 `vtj_check_consistency` 检查，不执行同步 |
