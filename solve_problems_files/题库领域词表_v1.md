# 砺安题库 · 题库领域词表 v1

> **用途**：给"题目/试卷/错题/正确率"这些天天被说、却每次口径不同的词钉死一个**唯一事实来源**。
> 三端（学生/教师/管理）计数不一致的第一根因不是代码 bug，是**同一个词在三端指了不同的东西**。
> **适用**：QBDM 的 DATA 角色主责；BE/API/FE 改字段或计数前必须先查本表。

## §2 实体词典（canonical 唯一名）

| 中文词 | canonical | 唯一事实来源 | 说明 |
|---|---|---|---|
| 题目 | question | `question_bank.question_id` | 系统的最小计数单位 |
| 题干 | content | `question_bank.question_content` | 正文+设问，不含选项 |
| 选项 | options | `question_bank.options` | 存于单字段，结构随题型变化 |
| 答案 | answer | `question_bank.answer` | 对外必须经 `canonical_answer` 归一化后再比较 |
| 解析 | analysis | `question_bank.answer_analysis` | 允许为空（历史数据存在缺失） |
| 题型 | type | `question_type`(19 行) + `question_bank.type_id` | 字典表，勿在业务码里硬编码字符串 |
| 题型细分 | type_detail | `question_bank.question_type_detail` | 二级题型描述 |
| 科目 | subject | `question_bank.subject_id` | 实测 1/2/3 三值 |
| 分类 | sub_category | `sub_categories`(16 行) + `question_bank.sub_category_id` | 与 `xingce/shenlun/gongzhuan_subcategory` 三列并存，**新代码只用 `sub_category_id`** |
| 知识点 | knowledge_point | `knowledge_point`(1049 行) + `question_knowledge`(2775 行) | 多对多；`knowledge_point.alias_of` 表示同义归并 |
| 复合题 | question group | `question_groups`(23 行) + `question_bank.group_id` | 共享材料 + 多道子题 |
| 材料 | material | `question_groups.shared_content` | 复合题的共用素材 |
| 题图 | question image | `question_image.image_path` | 文件落 `backend/app/static/`（4.3GB，禁删禁读内容入上下文） |
| 审核状态 | audit_status | `question_bank.audit_status` | 审核流；**与 status 不是一回事** |
| 启用状态 | status | `question_bank.status` | 1=启用 / 0=停用（测到 235 行为 0） |
| 试卷 | paper | `exam_paper.paper_id` | 组卷产物 |
| 试卷题目关系 | paper question | `paper_question_relation` | 试卷 ↔ 题目 + 题序 + 分值 |
| 题序 | question order | `paper_question_relation.question_order` | 三端渲染顺序的唯一依据 |
| 考试记录 | exam record | `exam_record.record_id` | 一次作答会话 |
| 答题明细 | answer detail | `exam_answer_detail.record_id + question_id` | 逐题对错、耗时、得分 |
| 练习记录 | practice record | `practice_record.record_id` | 单题练习 |
| 错题 | wrong question | `wrong_question_personal.wrong_id` | 个人错题本；`is_cut`=已切除 |
| 收藏 | favorite | `favorite_question.fav_id` | 收题 |
| 导入批次 | import batch | `question_import_record.import_id` | 含 success/failed/duplicate 计数 |
| 正确率 | accuracy rate | 历史字段 `question_bank.accuracy_rate`；权威口径见 §4-D4 | 两者不可混用 |
| 考频 | exam frequency | `question_bank.exam_frequency` | 历史统计值 |

## §3 实体关系（读图顺序 = 依赖方向）

```
question_groups(1) ──< question_bank(N)      group_id 绑材料，题目是子题
knowledge_point(1) ──< question_knowledge(N) >── question_bank(N)
question_bank(1) ──< paper_question_relation(N) >── exam_paper(1)
exam_paper(1) ──< exam_record(N) ──< exam_answer_detail(N) >── question_bank
question_bank(1) ──< practice_record(N)        单题练习
question_bank(1) ──< wrong_question_personal(N) 个人错题
question_bank(1) ──< favorite_question(N) >── sys_user
question_bank(1) ──< question_image(N)          题图
question_import_record(1) ──< question_bank(N)  批次溯源（弱关联，靠 time/source）
```

## §4 计数口径（三端一致的唯一解）

> 规则：**任何"数量"出现在接口/页面上，必须能指回本节某一条**。指不回来 = 口径未定义，先定口径再写代码。

| 编号 | 口径名 | 定义（可执行） | 禁止做法 |
|---|---|---|---|
| **D1** | 题目数 | `question_bank` 中 `status=1` 的行数，按 `subject_id` 分区统计 | 用 `status` 不筛直接 count（会把 235 行停用题算进去） |
| **D2** | 复合题组数 | `count(distinct group_id)` where `group_id>0` | 用 `group_id is not null` 判断（全表非空，0 也非 null → 误判为 3357 组） |
| **D3** | 试卷题数 | `count(*) from paper_question_relation where paper_id=?` | **用 `exam_paper.question_count`**（实测 19/38 张卷不一致） |
| **D4** | 正确率 | 由 `exam_answer_detail`/`practice_record` 在声明窗口内实时聚合：`sum(is_correct)/count(*)` | 用 `question_bank.accuracy_rate` 当权威值（历史快照，口径未知）；不声明样本窗口就报百分比 |
| **D5** | 错题数 | `wrong_question_personal` 中 `status` 有效且 `is_cut=0` 的行数 | 不区分 `is_cut`（会把已切除的算回来） |
| **D6** | 可见题 | 学生端只允许 `status=1`；教师/管理端可看 `status` 全量但必须显式标注 | 三端各写一套 WHERE（必须共用同一函数/同一子句） |
| **D7** | 考点进度 | 走 `question_bank.point_id`（端点 `/api/practice/knowledge-progress` 的既有实现）。`question_knowledge` 是并行的多对多表，实测两者差 1 题（1971 vs 1972）。改口径须同时改端点与本行 | 以为 `question_knowledge` 是唯一来源就改端点（会与真实数据错位） |

**落地要求**：D1–D6 各对应**一个**后端函数（放 `backend/app/services/` 或域内 `crud`），三端只调用不重写。
这是"三端数据一致性"工作的最小可执行切口——先统一 6 个函数，再谈页面。

## §5 禁用同义词黑名单

| 禁用写法 | 改用 | 原因 |
|---|---|---|
| 试题、题项、条目、record | 题目 / question | 与"记录"混淆 |
| 题目内容、正文 | 题干 / content | 与 options 混读 |
| 正确答案、标准答案（不区分字段） | 答案 / answer | 归一化前后是两个东西 |
| 解答、点评、说明 | 解析 / analysis | 与"备注 note"混淆 |
| 考点、知识项、标签 | 知识点 / knowledge_point | `tags` 是另一列 |
| 材料题、组合题、大题 | 复合题 / question group | 与"试卷大题"冲突 |
| 状态（裸写） | 启用状态 status / 审核状态 audit_status | 二义，历史上已因此出过 bug |
| 刷题记录、做题记录 | 练习记录 / practice_record | 与 exam_record 区分 |
| 套卷、卷子 | 试卷 / paper | — |
| 准确率、命中率 | 正确率 / accuracy | 命中率属匹配算法指标 |

## §7 新增/变更流程（DATA 角色）

1. 新词条 → 先在本表登记（中文 / canonical / 唯一来源 / 禁用同义词），再写代码。
2. 新字段 → 变更单（表/类型/默认值/可空/索引/迁移 SQL/回滚 SQL/受影响端点），并按 `gate_l1g_field_fingerprint` 复核。
3. 新计数口径 → 必须新增 §4 一行 + 对应唯一函数，**禁止**在页面里直接写 SQL 聚合。
4. 端点变化 → R11 冻结，新增需批准，并在 `api_surface.json` 重新生成基线。
