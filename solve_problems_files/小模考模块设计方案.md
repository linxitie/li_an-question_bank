# “小模考”功能模块 & “管理员端试卷审批”完整设计方案


## 第一部分：小模考功能模块设计方案

### 一、用户需求与功能定位分析

**1.1 核心用户需求**

| 用户角色 | 核心诉求 | 关键场景 |
|---------|---------|---------|
| **教师** | 设计模考试卷并发布，检验教学成果 | 组卷→选择发布目标→提交审批/直接发布 |
| **管理员** | 审核模考试卷质量，把控全校考试标准 | 接收审批申请→审查试卷→通过/驳回 |
| **学生** | 在规定时间内参加全校统一模考 | 查看模考列表→在规定时间内作答→查看成绩 |

**1.2 模块定位**

“小模考”是全校统一的模拟考试功能模块，区别于“历年试卷”（学生自主练习）和“快速练习”（日常刷题），具有以下核心特征：

- **权威性**：经教师设计、管理员审批后发布，代表学校层面的考试标准
- **统一性**：所有学生在同一时间段参加同一场考试
- **严肃性**：限时作答、自动批阅、成绩计入正式学习档案

**1.3 与现有模块的关联关系**

```
教师端“试卷管理”
    ├── 发布到“历年试卷” → 学生自主练习（无需审批）
    └── 发布到“小模考” → 管理员端“试卷审批” → 审批通过 → 学生端“小模考”
                                              ↓
                                    审批驳回 → 退回教师端修改
```


### 二、详细功能设计

#### 2.1 教师端：发布试卷到小模考

在教师端“试卷管理”模块中，完成试卷设计后，提供“发布目标”选择：

| 发布目标 | 是否需要审批 | 适用场景 |
|---------|------------|---------|
| **历年试卷** | ❌ 不需要 | 学生自主练习，教师可随时发布 |
| **小模考** | ✅ 需要管理员审批 | 全校统一模拟考试 |

**发布到小模考的必填字段**：

| 字段 | 类型 | 说明 |

| 试卷名称 | 文本 | 自动继承试卷名称，教师可修改 |
| 模考科目 | 下拉选择 | 行测 / 公专 / 申论 |
| 模考开始日期 | 日期时间 | 考试开始时间 |
| 规定完成时间 | 数字（分钟） | 如120分钟，倒计时自动计算结束时间 |
| 发布范围 | 多选 | 全校 / 指定年级 / 指定班级 |
| 模考说明 | 富文本 | 可选，补充考试注意事项 |

**考试状态判断逻辑**：

```python
def get_exam_status(exam):
    now = datetime.now()
    if now < exam.start_time:
        return "未开始"
    elif exam.start_time <= now <= exam.end_time:
        return "进行中"
    else:
        return "已结束"
```

**2.3.2 小模考答题页**

- 与现有答题卡页面**保持一致的UI风格和交互方式**

## 第二部分：管理员端试卷审批设计方案

### 一、功能需求分析

管理员端“试卷审批”模块的核心目标是：**建立教师端试卷发布到学生端之间的质量把控关卡**，确保发布到“小模考”的试卷符合学校考试标准。

**核心功能需求**：

| 需求编号 | 需求描述 | 优先级 |
|---------|---------|--------|
| A1 | 展示所有待审批试卷列表，包含审批状态标识 | P0 |
| A2 | 支持按状态筛选（待审批/已批准/已驳回） | P0 |
| A3 | 点击试卷名称可查看试卷完整详情（含所有题目） | P0 |
| A4 | 支持对试卷进行“通过”或“驳回”操作 | P0 |
| A5 | 驳回时必须填写驳回理由，可具体到题目级别 | P0 |
| A6 | 支持对试卷内容进行题目级别的编辑修改 | P1 |
| A7 | 审批操作记录日志，可追溯 | P1 |
| A8 | 审批通过后自动发布到学生端小模考 | P0 |
| A9 | 不合格题目高亮提醒与标注 | P1 |


### 二、详细功能设计

#### 2.1 试卷审批列表页

**页面布局**：采用表格形式展示所有待审批/已审批试卷

| 列名 | 说明 |
|------|------|
| 试卷名称 | 点击可查看详情（弹窗或跳转） |
| 提交教师 | 显示教师姓名 |
| 提交时间 | 审批申请提交时间 |
| 模考科目 | 行测/公专/申论 |
| 模考开始时间 | 计划考试开始时间 |
| 审批状态 | 待审批 / 已批准 / 已驳回（不同颜色标签） |
| 操作 | 查看详情 / 审批通过 / 驳回 |

**筛选与搜索功能**：

| 筛选项 | 类型 | 说明 |
|--------|------|------|
| 审批状态 | 下拉 | 全部 / 待审批 / 已批准 / 已驳回 |
| 模考科目 | 下拉 | 全部 / 行测 / 公专 / 申论 |
| 提交时间范围 | 日期选择 | 开始日期 ~ 结束日期 |
| 关键词搜索 | 输入框 | 按试卷名称或教师姓名搜索 |

#### 2.2 试卷详情查看页

**点击试卷名称后弹窗或跳转至详情页**，展示内容：

**（1）试卷基本信息区域**

| 信息项 | 说明 |
|--------|------|
| 试卷名称 | 显示完整名称 |
| 提交教师 | 姓名 + 工号 |
| 提交时间 | 精确到秒 |
| 模考科目 | 行测/公专/申论 |
| 模考开始时间 | 计划开始时间 |
| 规定完成时间 | 分钟数 |
| 发布范围 | 全校/指定年级/指定班级 |
| 总分值 | 自动计算 |
| 题目总数 | 自动统计 |

**（2）试卷内容预览区域**

- 按题型分组展示（单选题/多选题/判断题/情境题等）
- 每道题显示：题号、题干（含图片）、选项（含图片）、正确答案、分值
- **不合格题目高亮提醒**：自动检测并标注存在问题的题目（如：题干不完整、选项缺失、答案格式错误、图片无法加载等）

**（3）不合格提醒规则引擎**

| 检测项 | 检测规则 | 提醒方式 |
|--------|---------|---------|
| 题干为空 | `content` 字段为空或仅含空白字符 | 红色高亮 + 错误提示 |
| 选项数量不足 | 单选题选项 < 2，多选题选项 < 2 | 黄色高亮 + 警告提示 |
| 缺少正确答案 | `correct_answer` 字段为空 | 红色高亮 + 错误提示 |
| 图片无法访问 | 图片URL返回404 | 黄色高亮 + 警告提示 |
| 分值异常 | 分值 ≤ 0 或 > 题目总分上限 | 黄色高亮 + 警告提示 |
| 题干包含敏感词 | 命中敏感词库 | 红色高亮 + 违规提示 |

**（4）审批操作区域**

| 按钮 | 触发条件 | 后续动作 |
|------|---------|---------|
| 通过 | 无不合格项或管理员确认可忽略 | 状态→已批准，自动发布到学生端小模考 |
| 驳回 | 任何时候 | 弹出驳回理由输入框（必填），状态→已驳回，通知教师端 |

#### 2.3 试卷题目编辑功能

**功能说明**：管理员在审批过程中可直接对试卷内容进行修改，适用于发现小问题（如错别字、选项顺序错误）时快速修正，避免反复提交审批。

**可编辑内容**：

| 可编辑项 | 说明 |
|---------|------|
| 题干内容 | 富文本编辑，支持修改文字 |
| 选项内容 | 支持增删改选项 |
| 正确答案 | 支持修改正确答案 |
| 题目分值 | 支持修改分值 |
| 题目顺序 | 支持拖拽调整顺序 |

**编辑权限限制**：
- 仅管理员可编辑
- 编辑操作需记录日志（谁、什么时间、修改了什么）
- 编辑后试卷版本号自动递增

#### 2.4 审批日志

**功能说明**：记录试卷从提交审批到最终决策的全过程，确保审批流程可追溯。

| 日志字段 | 说明 |
|---------|------|
| 操作时间 | 精确到秒 |
| 操作人 | 姓名 + 角色 |
| 操作类型 | 提交审批 / 通过 / 驳回 / 修改内容 |
| 操作详情 | 具体操作内容描述 |
| 备注 | 驳回理由或审批意见 |

## 第三部分：全局实现建议

### 一、开发优先级

| 优先级 | 模块 | 说明 |
|--------|------|------|
| P0 | 试卷审批列表 + 详情查看 | 最核心功能，必须优先实现 |
| P0 | 通过/驳回操作 + 状态流转 | 审批流程的核心闭环 |
| P1 | 不合格题目自动检测 | 提升审批效率的关键功能 |
| P1 | 审批日志记录 | 保证流程可追溯 |
| P2 | 试卷内容编辑 | 提升审批灵活性 |
| P2 | 通知机制 | 提升用户体验 |
| P3 | 审批统计看板 | 数据分析和优化 |

### 二、技术实现要点

1. **状态机管理**：使用明确的状态枚举和状态流转规则，避免状态错乱
2. **事务一致性**：审批通过时，需同时更新试卷状态、创建审批日志、发布到学生端，使用数据库事务保证原子性
3. **缓存策略**：待审批列表使用Redis缓存（有效期5分钟），减少数据库压力
4. **权限控制**：审批操作必须校验操作人角色为管理员，防止越权
5. **操作日志**：所有审批操作必须记录日志，便于审计追溯

### 三、前后端接口对接要点

- 教师端发布试卷到小模考时，调用 `/api/teacher/papers/{id}/submit-approval`
- 管理员端审批列表，调用 `/api/admin/approval/papers` 获取数据
- 审批通过后，前端无需额外操作，后端自动完成发布
- 学生端小模考列表，调用 `/api/student/mock-exams` 仅显示已批准的模考
