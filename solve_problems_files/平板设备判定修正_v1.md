# 平板设备判定修正 — 设计方案 v1

> 状态：**待批准**，本文只做设计，不含代码改动。
> 日期：2026-10-25
> 分支：`feature/forum-personalization`（HEAD `14c252e`）
> 触发问题：平板打开 `http://10.201.3.21:9527/` 落在 PC 首页，点「论坛」进 PC 三栏页，进不了 `/tablet/*`

---

## 0. 结论先行

1. **根因**：`detectDevice()` 判成 `pc`。它的平板条件只有两条：UA 里 `android` 且不含 `mobi`（或 ipad/tablet/windows touch），或者「宽度 768–1024 且可触摸」。用户平板宽度 > 1024、且浏览器发的是桌面 UA（「桌面版网站」），两条都不满足。
2. **修法**：补一条「触摸优先」的判据——设备是**粗指针且不支持悬停**（`pointer: coarse` 且 `hover` 不可用）且宽度 ≥ 768，判为平板。
3. **为了可测**：把判定逻辑从「直接读 window」抽成纯函数 `detectDeviceFrom(signals)`，`detectDevice()` 只负责采集信号后调用它。这样能用 vitest 覆盖 6 种设备，而不必真的开平板。
4. 只改 `src/utils/device.ts` 一个文件 + 新增一个 spec。不改路由、不改页面、不改后端。

## 2. 目标与非目标

### 2.1 目标

1. 平板（含开着「桌面版网站」、横屏宽 >1024）打开 PC 路径 `/`、`/forum`、`/login` 时，映射到对应 `/tablet/*`。
2. 真实 PC（无触摸屏）行为**完全不变**。
3. 手机（宽度 <768）仍然判 `mobile`，不被误判成平板。
4. 判定逻辑可被单测覆盖。

### 2.2 非目标

- 不改 `DEVICE_ROUTE_MAP` 的映射表内容。
- 不改路由守卫的结构与顺序。
- 不做「用户手动切换端」的开关（未来需要再说）。
- 不改手机端/平板端任何页面。

---

## 3. 方案

### 3.1 选型

| 方案 | 规则 | 结论 |
|---|---|---|
| **A 粗指针（推荐）** | 在现有 UA 判据之后加：`coarsePointer && !hoverable && width >= 768` → tablet | **选中** |
| B 字面「有触摸点」 | `maxTouchPoints > 0 && width >= 768` → tablet | 弃：带触摸屏的 Windows 笔记本、二合一平板本会被判成平板，PC 用户看到平板界面 |
| C 扩 UA 正则 | 加安卓桌面模式特征串 | 弃：桌面模式 UA 与真 PC 基本一致，无法区分 |

**为什么 A 更准**：`pointer: coarse` 表示主输入是手指这类粗粒度设备，`hover: none` 表示没有悬停能力——这是触屏优先设备的特征。带触摸屏的笔记本通常同时有触摸板/鼠标，媒体查询为 `pointer: fine` 或 `hover: hover`，因此不会被误判。

### 3.2 判定顺序（改后）

```
1. UA 命中平板特征（现有正则，不变）        → tablet
2. coarsePointer && !hoverable && width>=768 → tablet   ← 新增
3. UA 命中手机特征 或 width<768              → mobile
4. 其余                                      → pc
```

> 顺序很重要：第 2 条必须在 `width<768` 之前，但自身带 `width>=768` 条件，所以手机不会命中。

### 3.3 代码结构

`src/utils/device.ts` 拆成纯函数 + 采集器：

```ts
export interface DeviceSignals {
  userAgent: string;   // 已转小写
  width: number;       // window.innerWidth
  touchable: boolean;  // 'ontouchstart' in window || maxTouchPoints > 0
  coarsePointer: boolean; // matchMedia('(pointer: coarse)').matches
  hoverable: boolean;     // matchMedia('(hover: hover)').matches
}

export function detectDeviceFrom(signals: DeviceSignals): DeviceType  // 纯函数，可单测
export function detectDevice(): DeviceType                            // 采集 window 信号后调用上面
```

其余 `getDevicePrefix / isDevice / isMobileDevice / getHomePagePath / getLoginPagePath / resolveDevicePath` **签名与行为不变**。

### 3.4 边界

| 场景 | 期望 |
|---|---|
| iPad + 妙控键盘 | `pointer: coarse` 可能变 `fine`、`hover` 可能变 `hover` → 第 2 条不命中，回落第 1 条（UA 含 ipad）→ 仍 tablet ✅ |
| iPad 桌面模式（UA 为 Macintosh） | 第 1 条不命中；12.9 寸横屏 CSS 宽度 1366 → 第 2 条命中（iPad 无鼠标时为 coarse/none）→ tablet ✅ |
| Windows 触摸笔记本 | `hover: hover` 通常为真 → 第 2 条不命中 → pc ✅ |
| 安卓手机横屏（宽度 780，coarse） | 第 2 条命中 → tablet ❌ 误判 |
| 老浏览器无 `matchMedia` | 采集器兜底 `false`，行为退回今天的样子 ✅ |

> 表格第 4 行是这套方案的已知代价：安卓手机横屏且 UA 不含 `mobi` 的情况极少（安卓手机 UA 必带 `Mobile`），实际风险低。若要彻底避免，可在第 2 条前加「UA 不含 `mobile`」的排除项，代价是多一个分支。

### 3.5 需要拍板的一处

第 3.4 表最后一行的误判要不要现在就堵：

- **不堵**（推荐）：保持规则简单，安卓手机 UA 必带 `Mobile`，第 1 条会先把它判成 mobile 吗？——不会，第 1 条只判平板。所以横屏手机走第 2 条会变 tablet。
  - 修正说法：若加排除项，规则变为 `coarsePointer && !hoverable && width>=768 && !/mobile/.test(ua)`，横屏手机仍判 mobile。
- **堵**：多一个条件，行为更稳。

**推荐：堵**。理由：安卓手机横屏看题库是真实场景，误判成平板会直接改变整个界面。

## 4. 验证方式与验收标准

### 4.1 单测（新增 `src/utils/__tests__/device.spec.ts`）

| 用例 | 输入 | 期望 |
|---|---|---|
| 标准安卓平板 UA | android 无 mobi，width 1180，touch，coarse，!hover | `tablet` |
| 桌面模式平板 | Windows 桌面 UA，width 1366，touch，coarse，!hover | `tablet` |
| 触摸笔记本 | Windows UA，width 1440，touch，**hover** | `pc` |
| 普通 PC | Windows UA，width 1440，无 touch，fine，hover | `pc` |
| 手机竖屏 | iphone UA，width 390，touch，coarse | `mobile` |
| 手机横屏 | android **mobi** UA，width 780，touch，coarse | `mobile` |

### 4.2 端到端（Playwright，9527）

1. 安卓平板 UA + 1180×820 + 触摸 + `pointer:coarse`（用 CDP 模拟）→ 打开 `/` → `#/tablet/home`；再打开 `/#/forum` → 自动变 `#/tablet/forum`。
2. 桌面 1440×900 无触摸 → `/` 仍是 PC 首页，`/#/forum` 仍是 PC 论坛。
3. 390×844 手机 UA → `/` → `#/mobile/home`。

### 4.3 真机（用户）

平板打开 `http://10.201.3.21:9527/`：
- 地址栏应变成 `#/tablet/home`；
- 点顶部「论坛」应进入平板三栏列表（不是 PC 三栏 + 弹层）；
- 点帖子进入新做的平板详情页。

## 5. 风险与回滚

| # | 风险 | 影响 | 对策 |
|---|---|---|---|
| 1 | 带触摸屏的 Windows 笔记本被判平板 | PC 用户看到平板界面 | 依赖 `hover: hover` 排除；真机抽测一台触摸笔记本 |
| 2 | 安卓手机横屏误判 | 手机界面突变 | 3.5 的排除项（推荐加） |
| 3 | `matchMedia` 在旧内核不可用 | 判定退回旧行为 | 采集器 try/catch 兜底 false |
| 4 | 影响面被低估 | 三端入口同时变化 | 判定逻辑单点（`detectDevice`），只有 `router/index.ts:595` 一个消费方，回滚 = revert 一个文件 |

**回滚**：`git revert` 该提交即恢复原判据，无数据迁移、无接口变更。
