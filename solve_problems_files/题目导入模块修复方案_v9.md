## 1. 诊断结论（实测证据）

### 1.1 P0 —— 阻断性构建失败，第 6 轮我的回归

`admin_questions.vue:569-572` 出现**逐字重复的两行**：

```js
// 解析选项 JSON，转换失败则不传 options
let options = null;
// 解析选项 JSON，转换失败则不传 options
let options = null;      // ← 同作用域重复声明，babel 直接抛错
```

来源：commit `e0f4be0`「题目管理编辑弹窗全字段图片粘贴」。该提交在插入粘贴处理时，把
原有代码块重复粘贴了一次。

**影响面**：`admin_questions.vue` 编译失败 → Vite 整条依赖链报错 → **管理员端题目管理页
完全不可用**。这是"每一次修改都要有进步"的反面案例，我必须先认领。

**全站扫描结论**：已用 `@vue/compiler-sfc` 对 `.vtj/vue/` 下**全部 75 个 .vue** 做
`compileScript` 权威编译校验 —— **通过 75 / 失败 0**，无其他同类回归。

### 1.2 P3 —— `batch-parsed` 500 的真因（与我的改动无关）

日志（`backend/logs/app.log` 20:36:42）：

```
[batch-parsed] 试卷#53 关联1题 成功(累计1)
[batch-parsed] 提交失败: (sqlite3.IntegrityError)
  UNIQUE constraint failed: paper_question_relation.paper_id, paper_question_relation.question_id
```

**根因**：`question_import.py:1230` 用 `all_ids = ok_ids + reused_ids` 作为待关联集合，
但 `:1227` 的去重集合 `existing_rel_qids` **只查了数据库已有行，没有查本批次内部的重复**。
当 `all_ids` 自身含重复 qid 时，第二轮 `db.add` 撞唯一约束，整事务回滚。

**爆炸半径（实测）**：试卷 #53 名为「2025年安徽省公务员录用考试《行测》题（网友回忆版）」，
事务回滚后 `question_count=0`、实际关联行数 `=0` —— **该卷一道题都没入库**。
这正是你遇到的"导入失败/题目丢失"。

**与 P1 的因果关系**：P1（材料被切到上一组最后一道子题）会让同一道题在批内被重复处理，
从而在 `all_ids` 中出现重复 → 触发 P3。**修 P1 能大幅降低 P3 触发率，但 P3 的代码缺陷
独立存在，必须单独修**（不能依赖 P1 修复来兜底）。

**旁证**：库内已有跨卷复用是正常业务（q12 出现在 3 份卷），说明"同题多卷"本身合法，
出问题的是**同一批次内**的重复。

### 1.3 P1 —— 材料被切到上一组最后一道子题（行测/公专）

v8 已定位的行测材料机制：`composite_matcher.match_xingce_material_groups` 用
**字符区间** `[start, end)` 划定材料块，成员是"落在该区间内的题号"。区间上界为

```python
upper = materials[i + 1]['start'] if i + 1 < len(materials) else INF   # composite_matcher.py:364
se = sec_end.get(section)                                              # :366
if se is not None:
    upper = min(upper, se)                                             # :368
```

**缺陷 1（区间上界不含"最后一道子题的结尾"）**：材料块的下界取自
`materials[i+1]['start']`，即**下一个材料块的开头**。但当前材料块与下一个材料块之间，
若还有若干属于当前组的题（含子题选项、图表说明、跨页续写），这些内容会被算进**下一个**
材料块，或在"最后一道子题"处残留 —— 与你描述的"分割到上一道复合题目中最后一道子题目"完全吻合。

**缺陷 2（成员判定用区间而非题号区间）**：`:370-373` 的成员判定是
`m['start'] < pos < upper`，只要题号落在区间内就算成员。这会把**区间内但不属于本组**的题
（如上组末尾溢出的题）错误归入本组。

**缺陷 3（无边界护栏）**：`upper` 取 `INF` 时（最后一个材料块且无分节上界），
材料可以一直延伸到文末，缺少"遇到新分节头/新题号段必须停"的硬护栏。

### 1.4 P2 —— 行测/公专缺申论式的材料标识

实测对比（`question_groups` + `question_bank`）：

| 能力 | 申论 | 行测 | 公专 |
|---|---|---|---|
| 材料存 `question_groups.shared_content` | ✅ | ✅（v8 W2 起） | ⚠️ 21 组存的是题干 |
| 材料与题目强关联（`group_id`） | ✅ | ✅（仅新导入） | ⚠️ 单成员，无关联价值 |
| 三端统一渲染组件 | ✅ `question_preview_list.vue` 组渲染 | ❌ 未复用 | ❌ 未复用 |
| 材料标题/摘要可见 | ✅ | ❌ | ❌ |

**三端完整性缺口**：`question_bank` 表**没有材料冗余列**。材料只在 `question_groups` 一处，
任一端查询若未联表，材料即丢失。申论靠 `question_id → group_id → shared_content` 两跳拿到；
行测/公专因 `group_id` 大面积为 0，学生端/教师端/管理员端**首屏列表都拿不到材料**。

## 2. 方案总览

复用既有机制，**不新建平行算法**：

```
P0 止血（1 处删除重复行）→ 解除构建阻断
P3 加固（批内去重）      → 消除 500，且失败不再回滚已成功题
P1 修边界（区间护栏）    → 材料不再越界到相邻子题
P2 建标识（三端复用）    → 行测/公专对齐申论的材料呈现
```

分 5 个 Wave：

| Wave | 目标 | 风险面 |
|---|---|---|
| **W0** | P0 构建阻断止血 | 极低（删重复行） |
| **W1** | P3 批内去重 + 失败不整体回滚 | 中（影响导入事务） |
| **W2** | P1 材料边界护栏 | 中（影响归组准确率） |
| **W3** | P2 行测/公专材料标识与三端渲染 | 中（前端 + 后端） |
| **W4** | 存量 110 道行测题回填材料 | 中（数据写入） |

### W1 —— P3 批量入库健壮性

**改动点**：`question_import.py:1230`

```python
all_ids = ok_ids + reused_ids
```
改为批内去重（保序）：
```python
_seen, all_ids = set(), []
for _q in ok_ids + reused_ids:
    if _q not in _seen:
        _seen.add(_q); all_ids.append(_q)
```

**为什么这样写**：不引入新数据结构，`set` 保序去重是最小改动；`existing_rel_qids`
的库内去重逻辑保持不变（它是正确的，只是覆盖不全）。

**安全性**：只减少写入行数，不会写入原本不该写的关联。

**运维便利**：批量导入的 500 从"整卷回滚"降级为"跳过重复"，日志需打印被跳过的题号，
便于定位是哪道题重复。

**验收**：
- 构造含批内重复的导入 → HTTP 200，不再 500
- `paper.question_count` 与实际关联行数一致
- 门禁 3/3 + 6/6 + L1G PASS

### W2 —— P1 材料边界护栏

**改动点**：`composite_matcher.match_xingce_material_groups:364-373`

三处加固（**全部在既有函数内，不新建算法**）：

1. **上界收紧到"下一个分节头或下一个材料块，取更早者"** —— 现有 `:366-368` 已有
   分节上界逻辑，补充：当 `upper` 为 `INF`（文末）时，若当前分节有明确 `end`，
   必须用它兜底，杜绝材料无限延伸。
2. **成员判定加题号下界** —— 现有判定是纯位置 `m['start'] < pos < upper`，
   补充 `pos > m['start']` 已是隐含，额外要求题号**不小于当前材料块起始题号**，
   防止上一组末尾溢出的题被误纳。
3. **尾部护栏** —— 若 `upper - m['start']` 超过该分节题号总数的合理跨度，
   记 `logger.warning` 并截断到最后一个已识别题号位置，避免吞掉后续整段。

**为什么这样设计**：材料边界的权威信号是**分节头与题号序列**，不是纯字符距离。
复用既有的 `sections`（分节区间）与 `XINGCE_QNUM_PATTERN`（题号），不引入新解析。

**安全性**：收窄边界只会让材料**变短**，不会变长 —— 误纳风险降、漏纳风险升。
故必须配 `logger.warning` 记录截断，人工可复核。

**验收**：真实行测卷（生产缓存 `v3_a26cb4b2…`，已含 2 个 data_analysis 组、成员 5/10 题）
跑归组后，逐组打印 `材料尾部 100 字 + 末成员题号`，确认材料末尾**不越界到下一题**。
