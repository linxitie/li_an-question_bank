## 一、问题诊断（已完成深度代码审查）

### 问题1：多选题全部被错误判定为单选题

**根因定位（已确认）**：

前端 `detectQuestionType` 函数存在**致命逻辑缺陷**——第1209-1212行：

```javascript
// 当前代码（第1209-1212行）——错误逻辑
if (hasOptionMarkers) {
  if (options.length > 4) return '多选题';    // 只有超过4个选项才判定多选
  if (options.length === 4) return '单选题';  // 4个选项一律判定为单选！
}
```

**问题本质**：公安联考题库中，绝大多数多选题都是4个选项（A/B/C/D），但这个逻辑把所有4选项题目**一律判定为单选题**。

**连锁影响**：
- 第1395行（初始解析）调用 `detectQuestionType(q.question_content, q.options)` **没有传answer参数**
- 因此第1183-1188行的「答案格式判断」分支（权重最高的维度）**永远无法触发**
- 所有题目最终走到第1209行的4选项判断，被错误判定为单选题

**调用链分析**：
```
第1395行: detectQuestionType(q.question_content, q.options)          ← 无answer
  → 第1183行: if (answerText) { ... }  ← answerText为空，跳过
  → 第1209行: if (options.length === 4) return '单选题'  ← 错误！
```

**后端验证**（第1740-1749行）虽然会用 `_detect_question_type` 重新判定并覆盖前端结果，但前端判定错误会导致：
1. 用户在导入预览界面看到的题型标签全部是「单选题」（视觉误导）
2. 如果后端覆盖逻辑因异常跳过，错误类型会被写入数据库

### 问题2：答案解析缺失

**根因定位**：

1. **前端传递链路**：`answer_analysis` 字段在批量导入请求中已正确传递（第2334行 `answer_analysis: q.analysis || ''`）
2. **后端接收**：`_upsert_question_core` 函数（第1441行）已正确接收并写入 `answer_analysis`
3. **真正缺失原因**：部分题目在源Word文档中就没有解析文本，导入时解析字段为空字符串
4. **关键遗漏**：分离导入模式下，答案文档的解析文本（analysis）可能没有被正确提取和关联到对应题目

### 问题3：前端没有任何修改效果呈现

**根因定位**：

经审查VTJ框架机制，`.vtj/vue/question_import.vue` 是VTJ设计器生成的Vue SFC文件。直接修改该文件**理论上应该生效**（VTJ的raw模式文件由开发者手动维护），但需要确认：

1. VTJ设计器是否在运行时重新生成该文件覆盖修改
2. 浏览器缓存是否需要清除
3. Vite开发服务器是否需要重启热更新

## 二、优化方案设计

### 方案核心原则

1. **单一事实来源**：题型判定以后端 `_detect_question_type` 为唯一权威，前端仅做预展示
2. **双保险机制**：前端修正 + 后端强制校验，确保不会写入错误类型
3. **最小侵入**：只改必要的代码行，不重构整个导入流程

### 修改1：前端 `detectQuestionType` 逻辑重构

**文件**：`.vtj/vue/question_import.vue`
**位置**：第1178-1221行

**为什么这样编写**：
- 将「答案格式判断」提升为最高优先级（权重最高），且**必须能接收answer参数**
- 修复第1211行的致命bug：4选项+多字母答案=多选题，不是单选题
- 增加对无选项题目的关键词匹配增强

**好处**：
- 用户在导入预览界面即可看到正确题型标签，不再被误导
- 与后端 `_detect_question_type` 的判定逻辑保持一致
- 安全性：纯前端展示逻辑，不涉及数据写入

```javascript
// 替换第1178-1221行的 detectQuestionType 方法
detectQuestionType(questionContent, options, answer = '') {
  var text = questionContent || '';
  var answerText = (answer || '').trim().toUpperCase();
  
  // ===== 维度1：答案格式判断（权重最高）=====
  if (answerText) {
    // 单字母答案 → 单选题
    if (/^[A-D]$/.test(answerText)) return '单选题';
    // 多字母答案（逗号分隔或连写）→ 多选题
    if (/^[A-D]([，,][A-D])+$/.test(answerText)) return '多选题';
    if (/^[A-D]{2,}$/.test(answerText)) return '多选题';
    // 判断题标志词
    if (/^(正确|错误|对|错|TRUE|FALSE|T|F)$/i.test(answerText)) return '判断题';
    // 长文本答案 → 主观题
    if (answerText.length > 20) return '论述题';
  }
  
  // ===== 维度2：选项数量 + 答案综合判断 =====
  var optCount = (options && Array.isArray(options)) ? options.length : 0;
  if (optCount >= 2) {
    // 有选项时，结合答案判断
    if (answerText && /^[A-D]{2,}$/.test(answerText)) return '多选题';
    if (optCount === 4) {
      // 4选项：有单字母答案→单选，多字母→多选，无答案→默认单选
      if (answerText && answerText.length === 1) return '单选题';
      if (!answerText) return '单选题';  // 无答案时默认单选
    }
    if (optCount > 4) return '多选题';
    if (optCount === 2) {
      // 2选项：判断题倾向
      if (/判断|对错|是否/.test(text)) return '判断题';
      return '单选题';
    }
  }
  
  // ===== 维度3：无选项题目 —— 关键词判断 =====
  if (optCount < 2) {
    // 写作题
    if (/写作|作文|请以.*为题|写一篇|谈谈你的看法/.test(text) || text.length > 200) return '写作题';
    // 填空题
    if (/____|（）|\(\)|（\s*）/.test(text)) return '填空题';
    // 多选题关键词
    if (/多选|多项选择|不定项选择/.test(text)) return '多选题';
    // 判断题关键词
    if (/判断|对错|是否正确|正确还是错误/.test(text)) return '判断题';
    // 论述/简答题
    if (/论述|分析|简答|阐述|说明|概括|简述/.test(text) || text.length > 80) return '论述题';
    return '论述题';  // 无选项默认论述
  }
  
  // ===== 维度4：有选项时的关键词辅助判断 =====
  if (/多选|多项选择|不定项/.test(text)) return '多选题';
  if (/判断|对错|是否/.test(text)) return '判断题';
  
  // ===== 默认 =====
  if (optCount >= 3) return '单选题';
  return '论述题';
},
```

## 九、新增问题4：教师端「试卷管理」不显示已导入试卷

### 9.1 数据库诊断结果

经实际数据库查询确认：**16份试卷已入库**，但仅1套（ID=18，砺安导入试卷，PUBLISHED/100题）在前端可见。

| paper_id | 试卷名 | 状态 | DB题数 | 实际关联题数 | 前端可见 |
|----------|--------|------|--------|------------|---------|
| 18 | 砺安导入试卷 | PUBLISHED | 100 | 100 | ✅ |
| 2 | AI生成试卷 | ENDED | 0 | 13 | ❌（回收站） |
| 3-17 | 各年份真题 | ENDED | 0 | 0 | ❌（回收站） |

**核心发现**：
1. **14份试卷 `paper_type=ENDED`**（回收站），被后端API默认过滤（teacher.py第418-419行）
2. **13份试卷 `question_count=0`且 `actual_rel=0`**，即使恢复也显示0题
3. 仅paper_id=2有13题实际关联但 `question_count` 未同步

### 9.2 根因分析

**根因A：试卷状态被设为ENDED**
- 后端 `list_teacher_papers`（teacher.py第418-419行）默认过滤：`paper_type != "ENDED"`
- 用户在「全部状态」下拉框中看不到回收站试卷，需手动切换到「回收站」才可见
- **这些试卷确实存在于数据库，只是被过滤了**

**根因B：question_count未正确更新**
- `_get_or_create_import_paper`（question_import.py第1081行）创建时 `question_count=0`
- `batch_import_parsed`（第1804行）有 `paper.question_count = (paper.question_count or 0) + linked` 更新逻辑
- 但部分试卷在导入时关联逻辑未执行（可能因异常被跳过，第1808行 `except` 静默吞掉错误）

**根因C：第一阶段解析未关联题目到试卷**
- `import_document_preview`（第2165行）仅创建paper记录，不关联题目
- 题目关联发生在第二阶段 `batch_import_parsed`
- 如果用户只完成了第一阶段（解析预览），未执行第二阶段（确认入库），则paper存在但无关联题目

### 9.3 修复方案

#### 修改6：数据修复 — 恢复ENDED试卷并同步question_count

**文件**：`backend/scripts/fix_paper_status.py`（新建）

**为什么这样编写**：
- 幂等脚本，可重复执行
- 恢复所有有题目关联的ENDED试卷为DRAFT
- 从 `paper_question_relation` 表反算 `question_count` 并同步
- 不删除任何数据，仅修改状态字段

```python
"""修复试卷状态：ENDED→DRAFT + 同步question_count"""
import sqlite3, sys, os

DB_PATH = os.path.join(os.path.dirname(__file__), '..', 'data', 'question_bank.db')

def fix(dry_run=True):
    conn = sqlite3.connect(DB_PATH)
    c = conn.cursor()
    
    # 1. 统计每个paper的实际关联题目数
    c.execute('''
        SELECT paper_id, COUNT(*) as cnt 
        FROM paper_question_relation 
        GROUP BY paper_id
    ''')
    rel_map = dict(c.fetchall())  # {paper_id: actual_count}
    
    # 2. 找出所有ENDED试卷
    c.execute("SELECT paper_id, paper_name, question_count FROM exam_paper WHERE paper_type='ENDED'")
    ended_papers = c.fetchall()
    
    fixed = 0
    for pid, name, db_qcount in ended_papers:
        actual = rel_map.get(pid, 0)
        if actual > 0:
            # 有实际关联题目 → 恢复为DRAFT并同步题数
            if not dry_run:
                c.execute("UPDATE exam_paper SET paper_type='DRAFT', question_count=? WHERE paper_id=?", (actual, pid))
            print(f"  [FIX] ID={pid} '{name}' ENDED→DRAFT, question_count {db_qcount}→{actual}")
            fixed += 1
        else:
            # 无关联题目 → 保持ENDED（空试卷无意义）
            print(f"  [SKIP] ID={pid} '{name}' 无关联题目，保持ENDED")
    
    if not dry_run:
        conn.commit()
        print(f"\n已修复 {fixed} 套试卷")
    else:
        print(f"\n[DRY-RUN] 将修复 {fixed} 套试卷，去掉 --dry-run 参数执行写入")
    
    conn.close()

if __name__ == '__main__':
    dry = '--dry-run' in sys.argv
    fix(dry_run=dry)
```

#### 修改9：后端增加「统计各状态试卷数」接口

```python
@router.get("/papers/stats", summary="试卷各状态统计")
async def paper_stats(
    current_user: SysUser = Depends(get_current_teacher),
    db: Session = Depends(get_db)
):
    """教师查看各状态试卷数量"""
    from sqlalchemy import func
    rows = db.query(
        ExamPaper.paper_type, func.count(ExamPaper.paper_id)
    ).filter(
        ExamPaper.creator_id == current_user.user_id
    ).group_by(ExamPaper.paper_type).all()
    
    stats = {r[0]: r[1] for r in rows}
    return {
        "success": True,
        "total": sum(stats.values()),
        "draft": stats.get("DRAFT", 0),
        "pending": stats.get("PENDING", 0),
        "approved": stats.get("APPROVED", 0),
        "published": stats.get("PUBLISHED", 0),
        "ended": stats.get("ENDED", 0),
    }
```
