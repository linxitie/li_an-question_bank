## T5 — 重复题去重（问题4-R4）

- **目标**：同题多副本（≥0.95 相似 + 同科目）合并，保留信息最全副本。
- **新增文件**：`backend/scripts/dedup_questions.py`
- **具体逻辑**：
  1. 归一化题干：strip `<img...>`、`[IMAGE:...]`、题号前缀、空白（复用 `text_parser.clean_question_text`）；
  2. 同 `subject_id` 内两两 `difflib.SequenceMatcher.ratio() ≥ 0.95` 分组（920 题规模 O(n²) 可接受，约 40 万次比较 <5s）；
  3. 组内保留评分最高者：`answer_analysis非空 + answer有效 + options非空 + question_id最小` 依次比较；
  4. 其余副本 `status=0`（**软删除**）；`paper_question_relation`/`wrong_questions`/`exam_record` 中指向副本的 `question_id` **重定向**到保留副本（先查引用再更新，无引用则跳过）；
  5. dry-run 输出清单（组号/保留qid/副本qid/相似度/题干摘要）→ **用户确认后 --apply**；备份 + JSONL 审计 + 幂等（已软删的跳过）。
- **编码前自检**：为什么软删除？→ 答题记录/错题本外键完整性，且所有查询已带 `status==1` 过滤（实测验证），软删即"消失"；为什么 0.95 而非 0.9？→ 看图选择题题干相同但图不同是**不同题**（如不同统计图表），阈值必须极严，宁可漏合并不可错合并。
- **验证**：

- **回滚**：`--restore`（status 复位 + 引用回指，审计日志驱动）。

## T7 — 无关图片清理 + 导入过滤强化（问题2）

- **目标**：识别并清理二维码/推广图；导入管线前置同类过滤；清空孤儿目录。
- **新增文件**：

     - `is_irrelevant_image(img_data: bytes) -> tuple[bool, str]`（返回判定+原因）；
     - 三级判定：① OpenCV `cv2.QRCodeDetector().detectAndDecode()` 成功 → ('qr_code')；`detect()` 命中定位图案 → ('qr_pattern')；② 横幅特征：宽高比≥2.5 且（可选）上部高对比文字块 → ('promo_banner')；③ 降级（无 OpenCV）：灰度→二值→黑白模块密度 0.35~0.65 + 连通域方格特征 → ('qr_likely')——**仅标记不自动删**；
     - 既有尺寸启发式（<100px/极端宽高比/近纯色）**原样迁入**保持行为兼容；
     - OpenCV 导入失败 → logger.warning + 自动降级，不抛异常（不阻塞导入）。
  2. `backend/scripts/clean_irrelevant_images_v2.py`：
     - 扫描全部 920 题的 `question_content`/`options` 中 `<img src="/static/questions/...">` → 对每张图跑 `is_irrelevant_image`；
     - 命中（qr_code/promo_banner 级）：从内容移除该 `<img>` → 图片文件**移动**至 `backend/data/backups/removed_images_{timestamp}/`（可恢复）→ JSONL 审计；

     - 清理空目录（图片移走/本就为空的 `static/questions/{qid}/`）；
     - dry-run 输出待删清单（qid/文件/原因）→ 用户确认 → apply。
- **改动文件**：`backend/app/api/v1/question_import.py` 的 `_is_irrelevant_image()`（1073-1103 行）——**函数体替换为委托调用** `image_filters.is_irrelevant_image`（保持函数名与签名不变，调用点 1196/1253 行零改动——最小侵入）；`backend/requirements.txt` 追加 `opencv-python`（注明用途注释）。
