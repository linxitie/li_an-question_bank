## 二、根本原因深度分析

### 2.1 问题一、二、三：页面无法滑动（统一根因）

#### 根因：全局样式 `src/style/index.scss` 锁死了页面滚动

**文件**：[src/style/index.scss](file:///d:/砺安题库/砺安题库/src/style/index.scss)

**问题代码**（第 5-13 行）：
```scss
html,
body,
#app {
  padding: 0;
  margin: 0;
  font-size: 14px;
  height: 100%;          /* ← 锁定高度为视口高度 */
  overflow: hidden;      /* ← ★★★ 滚动根因！禁止滚动条 */
}
```

#### 影响链路

```
index.scss: overflow: hidden 应用于 html/body/#app
  ↓
body 和 #app 的高度被锁定为视口高度（100%）
  ↓
所有页面内容超出视口高度的部分被裁剪
  ↓
浏览器不显示滚动条
  ↓
用户无法上下滑动
  ↓
首页看不到"招考信息"和"备考资料"（问题一）
aside 看不到下方功能模块（问题二）
关于页看不到完整内容（问题三）
```

#### 为什么三个页面都受影响？

| 页面 | 文件 | 根容器样式 | 实际表现 |
|------|------|-----------|----------|
| 首页 | `home_page.vue` 第 318 行 | `.home-page { min-height: 100vh; }` | 内容超出被裁剪，无法滚动 |
| 题库 | `question_bank.vue` 第 879 行 | `.question-bank { min-height: 100vh; }` | aside 内容超出被裁剪 |
| 关于 | `about.vue` 第 182 行 | `.about-page { min-height: 100vh; }` | 内容超出被裁剪 |

三个页面的根容器都只设置了 `min-height: 100vh`，本身设计允许内容自然撑开滚动。**真正的滚动锁死发生在全局 `index.scss`**。

#### XMask 是否依赖 `overflow: hidden`？

**不依赖**。经调研确认：
- XMask 自身 `.x-mask` 类已设置 `width:100%; height:100%; overflow:hidden`，自成体系
- `@vtj/web/src/index.scss` 仅 5 行 `@use` 语句，无任何样式声明
- `@vtj/ui/dist/style.css` 中 body 默认**无** `overflow:hidden`（仅拖拽/dialog 显示时动态添加）
- **删除全局 `overflow: hidden` 不会影响 XMask 布局**

### 2.2 问题四："5 条日志"报错

#### 根因：浏览器对重复 console.warn 的折叠计数

**来源文件**：[question_bank.vue 第 652 行](file:///d:/砺安题库/砺安题库/.vtj/vue/question_bank.vue#L652)

**问题代码**：
```javascript
} catch(e) {
  console.warn('[fetchQuickPracticeData] 加载失败:', e);
}
```

#### 影响链路

```
question_bank.vue mounted → 调用 fetchQuickPracticeData('xc')
  ↓
fetch('/api/quick-practice/sub-categories?subjectId=1') 失败
  ↓
catch 块执行 console.warn('[fetchQuickPracticeData] 加载失败:', e)
  ↓
页面有 3 个科目（xc/sl/ga），可能调用 3 次
  ↓
加上 loadPracticeRecords 等其他失败请求
  ↓
Chrome DevTools 将重复的 console.warn 折叠显示为"5 条 [fetchQuickPracticeData] 加载失败:"
  ↓
用户看到"5 条日志"报错
```

#### 是否影响系统正常运行？

**不影响核心功能**。`fetchQuickPracticeData` 失败仅导致子科目卡片显示空数据，不影响页面其他模块。但持续的 console 输出会：
1. 干扰开发者调试（控制台噪音）
2. 给用户造成"系统有 bug"的印象

#### 修复策略

优化错误处理：保留错误记录用于调试，但避免重复输出污染控制台。

## 四、详细修复方案

### 4.1 核心修复：解锁全局滚动

**文件**：`src/style/index.scss`

**修改前**（第 5-13 行）：
```scss
html,
body,
#app {
  padding: 0;
  margin: 0;
  font-size: 14px;
  height: 100%;
  overflow: hidden;
}
```

**修改后**：
```scss
html,
body,
#app {
  padding: 0;
  margin: 0;
  font-size: 14px;
  min-height: 100%;
}
```

**多角度思考**：

| 维度 | 评估 |
|------|------|
| **为什么这样写** | `overflow: hidden` 会裁剪所有超出视口的内容，删除后浏览器恢复默认滚动行为；`height: 100%` 改为 `min-height: 100%` 保证内容能自然撑开 |
| **好处** | ① 三个页面都能正常滚动 ② XMask 布局不受影响（自身已有 overflow:hidden）③ 符合 HTML 默认行为 |
| **安全风险** | 无，仅恢复浏览器默认滚动能力 |
| **运维便利** | 未来新增页面无需单独处理滚动问题 |
| **VTJ 规则遵守** | index.scss 是手写全局样式，修改符合职责分离 |
| **XMask 兼容性** | XMask 自身 `.x-mask { overflow: hidden }` 不依赖 body 的 overflow |

### 4.2 次要修复：优化日志错误处理

**文件**：`.vtj/vue/question_bank.vue` 第 652 行

**修改前**：
```javascript
} catch(e) {
  console.warn('[fetchQuickPracticeData] 加载失败:', e);
}
```

**修改后**：
```javascript
} catch(e) {
  // 仅在开发模式输出，避免生产环境控制台噪音
  if (process.env.NODE_ENV === 'development') {
    console.warn('[fetchQuickPracticeData] 加载失败:', e);
  }
}
```

**多角度思考**：

| 维度 | 评估 |
|------|------|
| **为什么这样写** | 开发时需要看到错误便于调试，生产环境不需要污染控制台 |
| **好处** | ① 开发者仍能调试 ② 生产环境控制台干净 ③ 用户不再看到"5条日志" |
| **安全风险** | 无 |
| **运维便利** | 通过 NODE_ENV 自动切换，无需手动管理 |
| **VTJ 规则遵守** | 仅修改 `<script>` 中的错误处理逻辑，符合 VTJ 职责分离 |
