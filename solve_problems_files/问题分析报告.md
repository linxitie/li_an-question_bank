# 题目导入与试卷管理功能问题分析报告

## 一、问题现状

### 1. 题目类型识别不准确
- **表现**：系统无法精准识别题目具体内容（如选项内容）时，会错误判定为"论述题"
- **示例**：单选题被判定为多选题，选择题被判定为论述题
- **影响**：题目分类错误，影响后续的题目管理和组卷功能

### 2. 试卷文档识别后未正确保存
- **表现**：系统识别出试卷文档后，未实际将题目和答案文档合并保存到"试卷管理"
- **示例**：即使保存了，点击预览也没有题目内容
- **影响**：教师无法在试卷管理中查看和管理导入的试卷

## 二、问题根因分析

### 1. 题目类型识别逻辑问题

#### 前端识别逻辑（`question_import.vue` 第1178-1193行）
```javascript
detectQuestionType(questionContent, options) {
  var text = questionContent || '';
  // 写作题特征：包含写作关键词，或文本非常长
  if (!options || options.length < 2) {
    if (/写作|作文|请以|为题|写一篇|谈谈你的看法/.test(text) || text.length > 200) return '写作题';
    // 论述题特征：包含论述/分析/简答关键词，或文本较长
    if (/论述|分析|简答|阐述|说明|概括/.test(text) || text.length > 80) return '论述题';
    // 含填空标记 → 归入论述题（需文本输入）
    if (/____|（）|\(\)|（\s*）/.test(text)) return '论述题';
    return '单选题';
  }
  // 多选题特征：选项超过4个
  if (options.length > 4) return '多选题';
  // 默认单选题
  return '单选题';
}
```

**问题**：
1. 过于依赖选项数量，没有充分利用答案格式、关键词等信息
2. 当选项内容无法识别时，默认返回"单选题"，但实际可能不是选择题
3. 没有考虑题目中可能包含的选项标记（如A、B、C、D）

#### 后端识别逻辑（`text_parser.py` 第1788-1887行）

1. 多维度判断，考虑答案格式、选项数量、题干关键词等
2. 有置信度输出，便于人工审核
3. 清洗UTB残留，避免干扰判断

**问题**：
1. 前端没有调用后端的识别逻辑，导致前后端判断不一致
2. 后端识别逻辑可能在某些边界情况下仍有误判

### 2. 试卷保存流程问题

#### 前端保存流程（`question_import.vue` 第2244-2338行）
```javascript
async importAllParsedQuestions() {
  // 调用后端批量导入接口
  const res = await this.fetchWithRetry('/api/questions/import/batch-parsed', {
    method: 'POST',
    body: JSON.stringify({
      paper_name: this.state.batchPaperName,
      subject_category: pending[0].subject_category,
      import_mode: mode,
      match_rate: rate,
      questions: pending.map(function(q) {
        return {
          question_content: q.question_content,
          options: q.options,
          answer: q.answer || '',
          answer_analysis: q.analysis || '',
          question_type_detail: q.question_type_detail || '单选题',
          subject_category: q.subject_category,
          score: q.score || 1,
          difficulty: q.difficulty || 3
        };
      })
    })
  });
}
```

**问题**：
1. 传递给后端的`question_type_detail`可能已经是错误的类型
2. 后端接收到错误类型后，直接使用，没有重新验证

## 四、优化方向

### 1. 统一题目类型识别逻辑
- 前端调用后端识别接口，或使用相同的识别算法
- 增加题目类型识别的置信度阈值，低置信度时提示人工确认

### 2. 完善试卷保存流程
- 增加前端验证，确保传递给后端的数据完整正确
- 增加后端验证，对前端传递的题目类型进行重新验证
- 增加试卷保存后的预览功能验证

### 3. 增强错误处理和日志
- 记录详细的识别和保存日志
- 增加错误重试和回滚机制
- 提供清晰的错误提示信息
