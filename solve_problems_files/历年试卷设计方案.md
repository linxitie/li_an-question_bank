## 二、全链路数据流设计

### 2.1 教师端→学生端完整数据流

```
教师端:
  /teacher/papers
    → POST /api/teacher/papers (创建试卷, paper_type="DRAFT")
    → POST /api/teacher/papers/{id}/questions (添加题目→PaperQuestionRelation)
    → POST /api/papers/{id}/publish (发布→PUBLISHED, paper_generation.py路由优先)

批量导入自动识别（新增）:
  /question-import
    → POST /api/questions/import/upload (上传文档)
    → _auto_detect_tags() 扫描全文检测关键词
    → is_complete_paper? → _get_or_create_import_paper() 自动创建ExamPaper
    → record.paper_id = paper.paper_id
    → POST /api/questions/import/confirm (确认导入)
    → 题目入库 + PaperQuestionRelation自动关联
    → 教师可在teacher_papers查看/编辑/发布

学生端:
  /student/papers (从全局导航或题库快捷操作进入)
    → GET /api/exams/list?subject_id=&year=&keyword= (筛选, apiFetch认证)
    → 卡片展示含用户进度状态(来自GET /api/exams/records)
    → 点击"开始考试"
    → POST /api/exams/{paper_id}/start (创建ExamRecord, exam_type="SELF_TEST")
    → /paper-answer?paper_id=X&record_id=Y
      → GET /api/exams/{paper_id}/questions (加载题目, 不含答案)
      → 作答中: 每30s localStorage自动保存
      → 交卷 → POST /api/exams/{record_id}/submit {answers: {qid: "A,B"}}
      → 后端自动批阅客观题 → 返回总分
      → 成绩弹窗显示
    → "查看详情" → /paper-result?record_id=Y
      → GET /api/exams/records/{record_id}
      → 逐题回顾（正确答案高亮、解析展示）
    → "再考一次" → POST /api/exams/{paper_id}/start (允许多次)
```

### 2.4 教师端与学生端关联稳定性保障

**核心保障措施：**
1. **paper_type字段流**：DRAFT → (PENDING → APPROVED) → PUBLISHED。学生端仅显示PUBLISHED，教师可跨审批直接发布（paper_generation路由优先）
2. **exam_type一致性**：ExamRecord创建时硬编码为"SELF_TEST"，不再依赖ExamPaper.exam_type字段（修复B1）
3. **唯一约束移除**：ExamRecord唯一约束(paper_id,user_id)改为普通联合索引，允许多次考试（修复B4）
4. **认证统一**：student_papers.vue所有API调用统一使用`auth.apiFetch()`自动附加Authorization头（修复P4）
5. **实时通信**：前后端通过Vite代理(`proxy.config.ts: /api → localhost:8000, ws: true`)保持通信，WebSocket支持实时推送

### 4.2 paper_answer.vue — 全题型渲染策略

**设计原因：** 现有`smart_answer.vue`仅支持2种题型且无IMAGE处理，`answer_page.vue`有IMAGE处理但提交到错误端点。必须融合两者优点。

**题型→渲染映射表：**

| 题型 | 渲染方式 | 选择器样式 | 答案格式 | 自动批阅 |
|------|---------|-----------|---------|:---:|
| 单选题 | radio选项按钮 | `○` → 选中变`●` | "A" | ✅ |
| 多选题 / 不定项 | checkbox选项按钮 | `☐` → 选中变`☑` | "A,C" (排序后比较) | ✅ |
| 判断题 | radio(✓/✗) | 同单选 | "✓" 或 "✗" | ✅ |
| 论述题 / 简答题 / 案例分析题 | `<textarea rows=8>` | 标准文本区 | 文本字符串 | ❌ 待人工 |
| 写作题 | `<textarea rows=20>` | 大型文本区 | 文本字符串 | ❌ 待人工 |

**选项解析（4种格式兼容）：**
```javascript
function parseOptions(raw) {
    if (!raw) return ['(暂无选项)'];                          // null/undefined
    if (Array.isArray(raw) && raw.length > 0)                  // [{key,value}] 或 ["text"]
        return raw.map(o => typeof o === 'string' ? o : `${o.key}. ${o.value}`);
    if (typeof raw === 'string') {
        let parsed = raw;
        while (typeof parsed === 'string')                    // 双编码JSON
            try { parsed = JSON.parse(parsed); } catch(e) { break; }
        if (Array.isArray(parsed)) return parsed.map(...);
    }
    return ['(暂无选项)'];
}
```

**IMAGE占位替换（安全性考虑）：**
```javascript
function replaceImages(text) {
    return text.replace(/\[?IMAGE:(\d+)_(\d+)\]?/gi,
        (m, qn, idx) => `<img src="/static/questions/${qn}_${idx}.png"
            class="q-img" loading="lazy"
            onerror="this.style.display='none'" />`);
    // onerror降级：图片加载失败静默隐藏，避免破坏页面布局
    // loading="lazy"：大试卷懒加载图片，优化首屏性能
}
```

**进度保存（localStorage策略）：**
- Key: `paper_progress_{recordId}`
- Value: `{answers, markedQuestions, currentIndex, timeLeft, timestamp}`
- 有效期: 24小时（超时自动丢弃）
- 保存频率: 每30秒 + 离开页面时
- 安全性: 仅客户端临时缓存，提交后自动清除；后端timestamp校验防止超时作弊

## 五、批量导入自动识别方案

### 5.1 关键词检测引擎

**文件**: `backend/app/api/v1/question_import.py` `_auto_detect_tags()`

**检测范围扩大**（v3增强）：
```
旧: 仅扫描文件名 + 前500-2000字符文本
新: 扫描文件名 + 全文文本（不限长度）
```

**检测规则矩阵**：

| 检测项 | 方法 | 关键词/模式 |
|--------|------|-----------|
| 年份 | 正则 | `(20\d{2})` |
| 省份 | 列表匹配 | 30个省级行政区名称 |
| 考试类型 | 关键词+正则 | 国考/省考/联考/模拟考/统考/招警/事业单位/真题/考试 |
| 科目 | 关键词 | 行测/申论/公专/公安专业/行政职业能力 |
| 完整试卷判定 | 启发式 | 连续递增题号(≥5个且60%连续) + 答案区检测 |
| 试卷名称提取 | 正则 | `XXXX年XX考试行测/申论/公专` 模式 |
| 来源标记 | 关键词 | 绝密/启用前/机密 |

### 5.2 自动创建试卷流程

```
文档上传 → 文本解析 → _auto_detect_tags()
  ├── is_complete_paper = true? 或 (有年份 + 有考试类型)?
  │   └── YES → _get_or_create_import_paper()
  │        ├── 查重: 同名+同创建者 → 复用已有试卷
  │        └── 无重复 → 创建ExamPaper(composition_method="IMPORT", paper_type="DRAFT")
  │                    + 创建ExamPaperTag(年份/省份/类型/科目/is_complete)
  │                    + record.paper_id = paper.paper_id
  └── NO → 仅导入题目，不创建试卷

导入确认 → 题目入库 → 检测record.paper_id
  └── 有paper_id → 创建PaperQuestionRelation关联每道题
                   → 更新paper.question_count
```

### 5.3 去重保障

1. **题目级去重**：fuzzy_detect_duplicate（相似度≥75%视为重复），已有成熟实现
2. **试卷级去重**：同名+同创建者查重，复用已有试卷而非重复创建
3. **关联去重**：PaperQuestionRelation已有`UniqueConstraint(paper_id, question_id)`

## 十、总结

本方案覆盖了历年试卷模块从**教师创建/导入 → 发布 → 学生筛选浏览 → 限时作答（全题型+图片） → 自动批阅 → 成绩报告 → 逐题回顾 → 重考**的完整功能闭环。核心亮点：

1. **5个阻断缺陷全部修复** — exam_type枚举不匹配(B1)、答题页上下文丢失(B2)、提交错误端点(B3)、唯一约束阻止重考(B4)、无题目加载端点(B5)
2. **全题型稳定渲染** — 7种题型(单选/多选/判断/论述/简答/案例/写作) + 4种选项格式兼容 + IMAGE图片替换 + textarea文本输入
3. **批量导入自动识别** — 关键词检测+完整试卷判定+自动创建ExamPaper+题目关联，打通导入→试卷的完整链路
4. **教师-学生关联稳定** — paper_type字段流清晰、exam_type硬编码统一、认证统一apiFetch、路由无冲突
5. **VTJ规则严格遵循** — 仅修改script、同步DSL、版本一致、Options API模式
