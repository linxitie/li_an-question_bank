## 一、问题导向分析与根因定位

### 问题1：做错8道题但只录入3道

**根因分析（后端数据库存储层）：**

1. **去重逻辑导致**（[practice.py:22-47](file:///d:/砺安题库/砺安题库/backend/app/api/v1/practice.py#L22-L47)）：
   - `_auto_record_wrong` 函数查询 `existing` 条件为 `user_id + question_id + collection_type="WRONG"`
   - 如果该用户之前做错过同一题，再次做错只更新 `error_count`，不新增记录
   - **结论**：8道错题中可能有5道是之前已收录的，只新增了3道——这是正确行为，但前端无法感知"已更新"的错题

2. **`_auto_record_wrong` 内部异常被吞掉**（[practice.py:46-47](file:///d:/砺安题库/砺安题库/backend/app/api/v1/practice.py#L46-L47)）：
   ```python
   except Exception as e:
       logger.warning(f"自动收录错题失败(qid={question_id}): {e}")
   ```
   - 异常只 log 不抛出，如果某题收录失败（如 subject_id 为 None），不会中断循环但也不会重试

3. **前端提交时 `is_correct` 判断可能不准确**：
   - 快速练习前端页面在提交前自行判断答案正确性
   - 如果前端判断逻辑与后端不一致，部分错题可能被标记为 `is_correct: true` 从而不收录

4. **唯一约束冲突风险**（[models.py:471-472](file:///d:/砺安题库/砺安题库/backend/app/models/models.py#L471-L472)）：
   - 模型有 `UniqueConstraint("user_id", "question_id", "collection_type")`
   - 如果在同一 transaction 中多次 `db.add()` 同一题，会触发 IntegrityError
   - 但 `_auto_record_wrong` 先查询 existing，正常不会触发

**解决方案：**
- 后端 `_auto_record_wrong` 增加 `subject_id` 为 None 时的兜底处理
- 后端新增接口返回"本次新增+更新"的错题统计，让前端知道收录结果
- 前端提交时统一由后端判断 `is_correct`，避免前后端判断不一致

### 问题3：点击"斩"没有自动转移到"我的斩题"

**根因分析（前端+后端）：**

1. **`filteredQuestions` 计算属性没有过滤已斩题**（[wrong_questions.vue:436-462](file:///d:/砺安题库/砺安题库/.vtj/vue/wrong_questions.vue#L436-L462)）：
   ```javascript
   filteredQuestions() {
       let list = this.state.allQuestions.filter(
           (q) => q.subject === this.state.activeNav
       );
       // ❌ 没有过滤 q.chopped
       return list;
   }
   ```
   斩题后 `q.chopped = true`，但题目仍然显示在列表中。

2. **`chopQuestionDirect` 只更新了本地状态，没有从 `allQuestions` 中移除**（[wrong_questions.vue:1170-1193](file:///d:/砺安题库/砺安题库/.vtj/vue/wrong_questions.vue#L1170-L1193)）：
   - 虽然调用了 `loadZhantiList()` 刷新斩题列表数据
   - 但 `allQuestions` 中该题仍存在，`filteredQuestions` 仍显示它

3. **后端 `/zhanti/list` 接口有字段名 bug**（[wrong_questions.py:382](file:///d:/砺安题库/砺安题库/backend/app/api/v1/wrong_questions.py#L382)）：
   ```python
   'question_content': (q.content[:100] if q.content else ''),  # ❌ q.content 不存在
   ```
   应为 `q.question_content`，导致斩题列表中题目内容为空。

**解决方案：**
- `filteredQuestions` 增加 `!q.chopped` 过滤条件
- `chopQuestionDirect` 成功后从 `allQuestions` 中移除该题（或标记后依赖 computed 过滤）
- 修复后端 `q.content` → `q.question_content`
- 斩题成功后显示成功提示并自动刷新斩题列表

### 问题6：提交后需要批改结果页面+继续复习/关闭+答对3次自动斩题

**根因分析（前端+后端）：**

   - 自动调用 `_auto_record_wrong` 更新错题记录
   - 对于连续答对3次的错题，自动调用斩题逻辑（is_cut=1, auto_delete_time=10天后）

### 问题7：统一题目类型为4种，删除其他类型，设计答题行为

**根因分析（全模块扫描）：**

**后端枚举**（[models.py:797-800](file:///d:/砺安题库/砺安题库/backend/app/models/models.py#L797-L800)）：
```python
question_type_detail = Column(Enum(
    "单选题", "多选题", "不定项", "选择题", "判断题",
    "写作题", "简答题", "案例分析题", "论述题", "填空题", "无"
))
```
当前有11种题型，用户要求只保留4种：**单选题、多选题、论述题、写作题**。

**前端涉及题型识别的模块（精准定位）：**
