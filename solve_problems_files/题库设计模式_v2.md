## §0 模块层要解决什么

v1 落地后暴露三个具体问题（不是理论问题）：

1. **「这个功能归谁」靠记忆。** 20 份域卡写在 `src/modules/<域>/README.md`，但端点归属、页面归属、
   测试归属分散在三处，问一次要翻三个目录。
2. **「优化」没有基线。** 说「列表更快了」但没量 P95；说「三端一致了」但没跑
   `test_three_end_counts.py`。没有数字的优化不可验收（v1 Z2）。
3. **「测试」只跑门禁。** 门禁保契约不保业务：错题斩题 10 天过期、事件幂等、三端计数口径，
   这些只有域测 + 手工验收能覆盖，但没有一张「该测什么」的清单。

模块层的答案：**一份台账（事实）＋ 一张三段式清单（方法）＋ 一条命令（入口）**。

### 1.3 归属口径（三条，避免争论）

1. **端点**：以 `api_surface.json` 为准。同一端点被多模块消费时，只在拥有方计数，消费方在域卡登记「只读」。
2. **页面**：`.vtj/vue` 与 `src/views/**` 都算；纯组件（navbar、TeacherNavHeader）不算页面。
3. **测试**：「登记」= 域卡 §6 明文写的；「候选」= 按模块关键字从 66 个测试里匹配的，**首次认领模块必须逐条确认**。

## §2 三段式作战法（设计 → 优化 → 测试）

三段有严格顺序：设计定错边界，优化补不回来；优化没有基线，数字不可信；测试没有矩阵，回归必漏。

### 2.1 设计 D1–D10（Q2 阶段逐条作答，缺项不放行）

| # | 检查项 | 必须给出的证据 | 否决条件 |
|---|---|---|---|
| D1 | 边界：本模块拥有哪些端点/页面/事件 | 台账该模块条目 + 域卡 | 跨模块直接 `import app.api.v1.*` |
| D2 | 数据：表/字段/索引/计数口径 | 迁移单或「零迁移」结论；口径引用词表 D1–D6 | 无迁移就加字段；三端各写 WHERE |
| D3 | 契约：端点只增不改，字段两端对齐 | 契约比对表（v1 §4 R-API） | 未批准改路径/字段名 |
| D4 | 事件：发布/订阅哪些 `trigger_type`，幂等键是什么 | 事件清单（E1–E13 对得上） | 改既有 trigger_type 语义（违反 add-only） |
| D5 | 权限：端点鉴权 + 角色 + 设备端 | `Depends(...)` 证据 + 三端入口 | 新端点无鉴权 |
| D6 | 三端：PC/平板/手机入口与降级 | 复用关系（平板复用手机页） | 新建重复平板页（R12） |
| D7 | 状态：空/加载/错误三态 | 三态截图或 store 字段 | 只有成功态 |
| D8 | 失败与回滚：事务边界、失败残留 | 事务范围 + 回滚方式 | 判分/入库不在同一事务却宣称一致 |
| D9 | 可观测：审计字段、错误码、日志脱敏 | 字段与日志样例 | 日志打印 token/答案明文 |
| D10 | 不做什么：显式排除项 | 一段「本次不做」 | 范围蔓延 |

> D1–D10 是 **Q2 的放行闸**：与 v1 的 CTC-11 一起答，任何一条答不出就回 ARCH/PM 重新定方案。

### 2.2 优化 O1–O8（先量后改，改完复量）

| # | 优化项 | 先量什么（基线） | 达标线（可验收） | 必测 |
|---|---|---|---|---|
| O1 | 列表/查询性能 | 分页接口 P95、首屏时间、SQL 条数 | 与基线比有数字改善；无 N+1 | 域测 + 慢查询日志 |
| O2 | 三端计数一致性 | `test_three_end_counts.py` 差异 | 差异 = 0；同一 WHERE/同一函数 | 该测试必须跑 |
| O3 | 体验三态 | 空态/错误态是否可达 | 每页三态齐全，错误可重试 | 前端 spec + 手工 |
| O4 | 安全 | 越权/IDOR/上传解析注入面 | SEC 五问全「通过/未涉及」 | `check_secrets` + 用例 |
| O5 | 事件幂等 | 重复提交是否重复发事件/重复加币 | 重复次数 = 0 | 幂等重放用例 |
| O6 | 冗余 | 重复校验、重复请求、死代码 | 删除项有 diff 证据 | 回归子集 |
| O7 | 三端复用 | 是否存在复制页 | 无新增重复页 | `gate_l5` |
| O8 | 可维护 | 文件/函数行数 | ≤800 行 / ≤60 行 | review |

**硬规则**：O1–O5 的「达标线」必须写成命令或数字；写不出就说明还没到优化阶段（先补 D）。

### 2.3 测试 T1–T8（分层，不允许用一层冒充全部）

| 层 | 跑什么 | 通过标准 | 不通过怎么办 |
|---|---|---|---|
| T1 契约 | `gate_l4_api_contract.py` | PASS 且端点数 343（或已批准增量） | 停手，回 API 角色 |
| T2 边界 | `check_module_boundary.py` | PASS | 回 ARCH，改依赖方向 |
| T3 数据 | `db_tables.json` 差异 / 迁移 dry-run | 差异可解释 | 回 DATA |
| T4 域测 | `cd backend; python -m pytest tests -q -k "<模块关键字>"` | 全 PASS / 无 HANG | 失败报失败（v1 A1） |
| T5 前端 | `npm run test -- <模块 spec>`（vitest） | PASS | 回 FE |
| T6 页面 | `gate_l5_frontend_contract.py` + 设计器可开 | PASS + 页面可开 | 回 FE |
| T7 三端手工 | 域卡 §7 清单逐项 | 记录设备/步骤/结果 | 未测就标「未验证」 |
| T8 回归 | 事件链 E1–E13 抽查 + 幂等重放 + 计数一致性 | 无重复事件、计数差异 = 0 | 回 BE/QA |

> 全量 pytest 会挂起（v1 §9 实测）。判定「能否合并」用
> `python scripts/qbdm/test_sweep.py --suite tests --timeout 90` 拿 OK/FAIL/HANG 三态。

## §3 变更影响面算法（五步，禁止凭印象挑文件）

```powershell
# 第 1 步：定位模块（id / 编号 / 名称都行）
python scripts/qbdm/qbdm.py module wrongbook

# 第 2 步：端点点名（前缀 -> 文件 -> 函数）
python -c "import json;d=json.load(open('backend/data/refactor_baseline/api_surface.json',encoding='utf-8'));print(d['wrong_questions.py']['endpoints'])"

# 第 3 步：事件影响（谁发、谁订；E1-E13 在模块化方案 §3.3）
grep "trigger_type" backend/app/api/v1/catalog/wrong_questions.py

# 第 4 步：页面影响（.vtj 只能改 script；手写页可改模板）
#   见域卡 §1；.vtj 页改动前技能 vtj-frontend + dryRun

# 第 5 步：测试选择（登记 + 候选 + 新增）
cd backend; python -m pytest tests -q -k "wrong"
```

输出一张**影响面表**（文件 / 类型 / 归属模块 / 是否跨模块 / 验证方式），作为 Q2 方案的附件。
跨模块影响必须列出下游模块与对应负责人角色（BE/FE/QA）。

## §5 模块级验收矩阵

| 改动类型 | 必跑门禁 | 必跑测试 | 附加证据 |
|---|---|---|---|
| 题目增删改/分类 | `gate_l4` + `module_boundary` | `pytest -k "catalog or question"` | 端点数不变；分类计数差异 0 |
| 题目导入/解析 | `gate_l1_parser` + `gate_l1h` + `gate_l3` | `pytest -k "import"` | 样本导入前后对照 |
| 组卷/判题 | `gate_l2_matching` + `gate_l4` | `pytest -k "paper or practice"` | 命中率/误判率数字 |
| 错题/掌握度 | `gate_l4` | `pytest -k "wrong"` | 斩题 10 天过期用例 |
| 统计/成绩 | `gate_l4` | `test_three_end_counts.py` | 三端计数差异 0 |
| 教师/管理端 | `gate_l4` + `module_boundary` | `pytest -k "teacher or admin"` | 权限用例（越权 403） |
| 事件/通知 | `gate_l4` | 幂等重放 + `test_cross_domain_flows.py` | 重复事件数 0 |
| 前端页面 | `gate_l5` | 模块 spec + `vtj_check_consistency` | `dryRun` 预览 + 设计器可开 |
| 任意提交前 | `gate_all.py --quick` | 改动域子集 | 退出码 0 |

## §7 未开发模块准入（⑰ 签到 / ⑱ 小智 / ⑲ 机考 / ⑳ 小模考）

四项全部满足才允许建分支：

1. D1–D10 全填，且 D10「不做什么」明确；
2. 事件边登记（发布/订阅 + 幂等键），与 E1–E13 表对齐；
3. 数据方案：零迁移或迁移单 + 回滚；
4. 验收命令可复制执行（T1–T8 中适用的层）。

当前状态：⑰ 复用 `badge_task` 不建表；⑱ 仅预留 `POST /api/llm/chat`；⑲ 无端点；⑳ 复用 `/api/exams`。
