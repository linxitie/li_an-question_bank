## §2 P3 设计：收藏 / 喜欢 / 可见范围 / 搜索

### 2.1 数据模型（1 张新表 + 2 个新列）

```sql
-- 1) 论坛收藏（新表；与 /api/collection 的题目收藏互不相干）
CREATE TABLE forum_favorite (
  favorite_id INTEGER PRIMARY KEY AUTOINCREMENT,
  post_id     BIGINT  NOT NULL REFERENCES forum_post(post_id),
  user_id     BIGINT  NOT NULL REFERENCES sys_user(user_id),
  create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
  CONSTRAINT uk_post_user_favorite UNIQUE (post_id, user_id)
);
CREATE INDEX ix_forum_favorite_user ON forum_favorite(user_id, create_time DESC);

-- 2) 帖子可见范围（新增列，默认 ALL 保持向后兼容）
ALTER TABLE forum_post ADD COLUMN visibility VARCHAR(16) DEFAULT 'ALL';      -- ALL | CLASSES
ALTER TABLE forum_post ADD COLUMN visible_classes JSON;                      -- ["一班","二班"]
```

- **「喜欢」不建新表**：复用 `forum_like`，只保留 `reaction_code='like'`（T10 收敛）。
- **`collect_count` 复用**：收藏/取消时同步增减，作为展示计数。
- 迁移方式沿用 `main.py` 既有 `ALTER TABLE` 探测段（`:226-278` 现成模式），幂等。

### 2.2 接口清单（全部不新开 `/api/v1`）

| 方法 | 路径 | 说明 | 鉴权 |

```
   OR (visibility='CLASSES' AND 当前用户.class_name ∈ visible_classes) )
```

## §3 P4-A 设计：个人主页背景（需求 2）

### 3.1 目标与形态

1. **系统主题**：春/夏/秋/冬 四套（免费），管理员配置。
2. **用户创作**：学生上传自制背景 → 审核通过 → 可自用；可选择**上架出售**，定价**只用金币**。
3. **购买与使用**：金币购买 → 永久拥有 → 个人主页任选其一启用。

### 3.2 数据模型（2 张新表）

```sql
CREATE TABLE profile_background (
  bg_id        INTEGER PRIMARY KEY AUTOINCREMENT,
  owner_id     BIGINT REFERENCES sys_user(user_id),   -- NULL = 系统
  name         VARCHAR(50) NOT NULL,
  kind         VARCHAR(16) NOT NULL,                  -- SEASON | USER
  theme        VARCHAR(16),                           -- spring/summer/autumn/winter
  image_url    VARCHAR(300) NOT NULL,
  thumb_url    VARCHAR(300),
  coin_price   INTEGER DEFAULT 0,                     -- 0 = 免费
  status       VARCHAR(16) DEFAULT 'PENDING',         -- PENDING/APPROVED/REJECTED/OFF_SHELF
  audit_note   VARCHAR(200),
  use_count    INTEGER DEFAULT 0,
  create_time  DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE user_background (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id    BIGINT NOT NULL REFERENCES sys_user(user_id),
  bg_id      INTEGER NOT NULL REFERENCES profile_background(bg_id),
  source     VARCHAR(16) NOT NULL,                    -- FREE | PURCHASE | SELF
  create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
  CONSTRAINT uk_user_bg UNIQUE (user_id, bg_id)

ALTER TABLE sys_user ADD COLUMN active_bg_id INTEGER;  -- 当前启用背景
```

> 金币流水**不新建表**：直接写现有 `coin_record`（`transaction_type='SPEND'`, `source_type='SHOP'`, `related_id=bg_id`），幂等靠 `coin_exchanges.request_id` 复用同一套。

### 3.3 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/profile/backgrounds` | 可选背景（系统四季 + 已上架作品），支持 `?kind=` 过滤 |
| POST | `/api/profile/backgrounds` | 用户上传创作（**先审核**，`status=PENDING`） |
| POST | `/api/profile/backgrounds/{bg_id}/buy` | 金币购买（幂等 `request_id`；余额不足 400） |
| PUT | `/api/profile/background` | 启用/切换（必须已拥有或免费） |
| GET | `/api/profile/background` | 当前用户背景 + 拥有列表 |
| POST | `/api/admin/profile-backgrounds/{bg_id}/review` | 管理员审核（通过/驳回，复用 AI 审核队列） |

### 3.4 安全与运维要点

- **上传**：仅 png/jpg/webp、≤2MB、强制重编码去元数据（防 XSS/EXIF）；存 `settings.UPLOAD_DIR/profile_bg/`，文件名用 UUID（防路径穿越）。
- **审核**：用户创作背景**必须**过一遍 AI + 人工（复用 P4-B 知识库流程），未审不展示。
- **不可提现**：金币仅站内，不做任何现金结算（你已明确）。
- **隐私**：市场里作者显示昵称，不显示学号/班级。
- **存储**：背景图堆积会撑大 `static`（实测当前 46.5MB），需每张 ≤2MB + 上限（每人 ≤5 张待审）。

## §4 P4-B 设计：AI 审核知识库（需求 4）

### 4.1 三层结构

```
第 1 层 DFA 敏感词（已有，毫秒级，先拦死）
   ↓ 未命中
第 2 层 AI 判定（异步，接 LLM_API_URL；返回 风险等级 + 理由 + 依据规则）
   ↓ 命中或低置信
第 3 层 人工队列（现有 教师隐藏 / 管理员复核 复用）
   ↓ 人工结论回写
知识库（规则 + 样例 + 判定记录）→ 反哺第 1/2 层
```

### 4.2 数据模型（2 张新表）

```sql
CREATE TABLE moderation_rule (
  rule_id     INTEGER PRIMARY KEY AUTOINCREMENT,
  code        VARCHAR(50) NOT NULL,        -- 如 POLITICAL_SENSITIVE / ABUSE / AD
  title       VARCHAR(100) NOT NULL,
  description TEXT,                         -- 给 AI 的判定说明（提示词片段）
  examples    JSON,                         -- ["样例1","样例2"]
  severity    VARCHAR(16) DEFAULT 'REVIEWED', -- BLOCKED/MASKED/REVIEWED
  status      VARCHAR(16) DEFAULT 'ON',     -- ON/OFF
  hit_count   INTEGER DEFAULT 0,
  updated_at  DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE moderation_ai_log (
  log_id      INTEGER PRIMARY KEY AUTOINCREMENT,
  target_type VARCHAR(16) NOT NULL,         -- POST/COMMENT/BACKGROUND
  target_id   BIGINT NOT NULL,
  verdict     VARCHAR(16),                  -- PASS/REVIEW/BLOCK
  risk_level  VARCHAR(16),
  rule_codes  JSON,
  reason      TEXT,
  model       VARCHAR(50),
  latency_ms  INTEGER,
  human_verdict VARCHAR(16),                -- 人工回写：正确/误判
  create_time DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

### 4.3 判定流程（发帖/评论/背景上传）

1. **同步**：现有 DFA → blocked 直接拒；masked 打码；reviewed 记录。
2. **异步**：入队 → 调 `LLM`（复用 `platform/llm.py` 的 `requests.post(LLM_API_URL)` 模式，**新增服务层而不是改它**）→ 写 `moderation_ai_log`。
3. **分级动作**：`BLOCK` → 置 `status=BLOCKED` 并通知作者；`REVIEW` → 进管理员队列（复用 `forum_moderation.py` 的复核表）；`PASS` → 不动。
4. **降级**：`LLM_API_KEY` 为空或超时（>8s）→ 跳过 AI，退回 DFA + 人工队列，并记录 `model=unavailable`。**绝不因为 AI 挂了而放行或误杀**。
5. **知识库反哺**：人工结论写回 `human_verdict`；定期统计 `rule_codes` 命中率，更新 `moderation_rule.examples` 与提示词。

### 4.4 成本与可靠性控制

| 项 | 策略 |
|---|---|
| 调用量 | 只对「新帖/新评论/背景上传」调用，不做全量回扫（回扫单独立项） |
| 成本 | 每条 ≤1 次调用；超长文本截断到 2000 字；`temperature=0` |
| 幂等 | `(target_type,target_id)` 唯一，重复审核跳过 |
| 可解释 | 必存 `rule_codes` + `reason`，管理员能看到"为什么被判" |
| 误判处理 | 管理员一键"误判"→ 回写 `human_verdict=wrong`，并把该样例加入规则 `examples` |

## §6 验收与基线

- 每个 P3 提交前：`npx vitest run`（28 files/362）、`npm run typecheck`（≤63 条/9 文件）、`pytest tests/test_forum_*.py`。

## §7 风险与回滚

| # | 风险 | 对策 |
|---|---|---|
| 1 | 迁移出错 | `sqlite3.backup()` 先行；只加表/列不删；回滚=恢复备份并删 `-wal`/`-shm` |
| 2 | 可见范围过滤写错 → 泄露班级帖 | 过滤集中在 1 个辅助函数（单一事实来源），四类身份各一条 pytest |
| 3 | 收藏幂等 | 唯一约束 + toggle 语义，重复点击不重复计数 |
| 4 | 金币刷取 | `request_id` 幂等 + 余额校验（事务内）+ 只走 `/api/shop` 既有流水 |
| 5 | 背景图撑爆存储 | ≤2MB、每人 ≤5 张待审、审核不过自动删除 |
| 6 | AI 误杀/漏杀 | 分级动作 + 人工兜底 + 误判回写知识库；AI 不可用时降级不阻断 |
| 7 | 改 raw 页模板 | 逐次授权 + `.bak_<日期>`（SHA256 校验）+ 只改目标片段 |
| 8 | 与在途工作冲突 | 设备分册已合流；QBDM 工具不碰业务文件；本方案文件集与它们不重叠 |

## §8 CTC-11（本方案逐问）

| # | 问题 | 回答 |
|---|---|---|
| 1 | 为什么这样写 | 收藏独立成表、喜欢复用点赞表：避免一张表两种语义；可见范围放在帖子行上：一次查询即可过滤 |
| 2 | 安全 | 所有新接口走 `get_current_user`；收藏/喜欢只操作本人；可见范围过滤在 SQL 层；上传白名单+重编码 |
| 3 | 运维 | 迁移幂等可重复执行；AI 有降级开关；所有变更集中在新文件，回滚=revert |
| 4 | 文件位置 | 论坛相关进 `api/v1/community/`；背景进 `community/profile_bg.py`；AI 进 `services/` |
| 5 | 前端能显示 | 每条验收都有 Playwright 断言（选择器+样式），不靠肉眼 |
| 6 | 字段/迁移 | 3 张新表 + 3 个新列，全部有回滚 SQL |
| 7 | 路由注册 | 新模块在 `main.py` 增 `include_router`，并在验收里断言端点数 |
| 8 | 调用闭环 | 前端每个按钮都对应一条接口断言（见 §2.4） |
| 9 | VTJ 版本 | 改 raw 页只跑 `check_consistency`；`useProvider` version 不变 |
| 10 | 与既有机制冲突 | 复用既有 `collection`/`shop`/`coin`/`sensitive_words`/`forum_moderation`，不重写 |
| 11 | 开源借鉴 | 搜索先用 SQLite `LIKE`（现成）；量级上来再上 **FTS5**（实测 SQLite 3.50.4 支持）；AI 审核参考"规则+样例+回写"的成熟做法，不引入新依赖 |
