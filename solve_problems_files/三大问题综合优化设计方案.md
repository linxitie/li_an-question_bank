## 一、问题定义与根因（全部基于代码实证）

### 1.1 问题1：题目导入效率低、异常题无法定位

**症状**：导入页面显示大量题目存在答案解析缺失、选项缺失、过滤无关字段乱码、无关图片（公众号/收款/群二维码）混入；前端虽显示异常题但只闪几秒，用户无法定位到具体异常题。

**根因（代码实证）**：

| 编号 | 根因 | 证据位置 |
|------|------|---------|
| R1-1 | 匹配率"显示失真"：`separateMatchRate` 初始 0，后端未返回时前端显示 0% 而非真实状态 | `.vtj/vue/question_import.vue:525` |
| R1-2 | **异常题无法定位（核心）**：后端 `batch_import_parsed` 返回 `failed_items`（仅含 `{index, reason}` 数组下标，无题号）与 `need_confirm_count`（仅计数），前端仅 `console.warn` + 一闪而过的 `ElMessage.warning` | `question_import.py:1723-1784`、`1894-1907`；`question_import.vue:2387-2395` |
| R1-3 | 无关图过滤偏保守：`_is_irrelevant_image` 对 `qr_likely` 疑似信号一律放行（`hit != 'qr_likely'` 才拦截），且 `promo_likely` 也是疑似级 | `question_import.py:1141-1148`、`image_filters.py` |
| R1-4 | 无关字段乱码：UTB ID、内嵌"六、""八、根据以下情境材料，回答…"等大题号/材料头切分不净，清洗逻辑分散在多个文件，无单一权威 | `admin_questions.vue:337`、`teacher_questions.vue:351`、`text_parser.py` 顶部注释 |
| R1-5 | 三端渲染不统一（详见 1.3），加剧"看着乱" | 见 1.3 |

### 1.2 问题2：复合题识别弱、三端不显示

**症状**：学生/教师/管理员三端都无法显示复合题（大题套小题），复合题被拆散随意分布。

**根因（代码实证）**：

| R2-2 | 数据层已就绪但未充分使用：`QuestionGroup` 表 + `QuestionBank` 5 列（group_id/parent_id/question_level/sort_order/question_number）已建，迁移脚本已存在 | `models.py:210-214,236`、`scripts/migrate_question_groups.py` |
| R2-3 | **三端聚合渲染几乎缺失（核心）**：仅 `teacher_questions.vue` 有 group 徽标+详情弹窗；学生端 `answer_page.vue`、管理员端 `admin_questions.vue`、`mobile_practice.vue`、`tablet_practice.vue` 完全没有题组聚合渲染，小题散落平铺 | `teacher_questions.vue:58,99-101,504-516`；其余页面无 group 逻辑 |

### 1.3 问题3：三端图片缺失 / 显示路径（四方路径矛盾为核心根因）

**症状**：学生/教师/管理员端所有能显示图片的模块中，题目图片缺失或仅显示路径，题干信息不全、页面不美观。

**根因（代码实证，四方路径矛盾）**：

| 编号 | 根因 | 证据位置 |
|------|------|---------|
| R3-1 | **占位符与磁盘名无映射（核心）**：docx 提取时生成占位符 `[IMAGE:{session_id}_{qn}_{seq}]`（session_id 为临时 uuid），而磁盘最终文件名是 `img_docx_{idx}_{md5}.png`（idx=图片序号、md5=内容哈希）。二者无任何可逆映射关系 | `question_import.py:499,517`（生成占位符）、`1300-1313`（保存为 img_docx 命名） |
| R3-2 | 后端 `render_image_placeholder` 用 marker 直接拼路径 `/static/questions/{marker}.png`，但磁盘文件名是 `img_docx_{idx}_{md5}.png`，拼出的路径不存在 | `option_utils.py:28-38` |
| R3-3 | `sanitize_content_images` 的 `_extract_marker_from_src` 正则 `^([a-f0-9]+_\d+_\d+\|\d+_\d+)$` 无法匹配 `img_docx_0_5661de6d`（前缀非纯 hex），子目录兜底失效 | `image_service.py:126-139` |
| R3-4 | 前端三套各自为政的正则替换路径，均与磁盘命名不符：`answer_page.vue:429,438` 用 `/static/questions/{qn}/{qn}_{idx}.png`；`paper_answer.vue:332` 用 `/static/questions/{hash}_{idx}.png`；`wrong_questions.vue:1082` 用 `[IMAGE:([a-fA-F0-9]+)_(\d+)]`+image_map | 各文件对应行 |
| R3-5 | 大量页面用 `{{ q.question_content }}` 文本插值（不 v-html），导致显示 HTML 源码或路径字符串 | `favorites.vue`、`notes.vue`、`question_preview_list.vue`、`score_analysis.vue`、`smart_exam.vue`、`teacher_papers.vue`、`teacher_analytics.vue`、`paper_approval.vue` 等 |
| R3-6 | MinerU 实际部署在 `C:\mineru_env`（已成功），但 `config.py:69` 的 `MINERU_PYTHON` 默认值写错为 `D:\mineru-env\Scripts\python.exe`，且 `MINERU_ENABLED=False` 未启用 → MinerU 从未真正接入 | `config.py:68-69` |

**数据流断点小结**：

```
docx 提取 → [IMAGE:uuid_qn_seq] 占位符
   ↓ 入库 _extract_and_save_images  → 已替换为 <img src="/static/questions/{qid}/img_docx_{idx}_{md5}.png"> ✅（新数据路径正确）
   ↓ 但历史数据/部分路径仍残留 [IMAGE:xxx] 占位符
读路径 render_image_placeholder → 把占位符渲染成 /static/questions/{marker}.png ❌（marker 与磁盘名无映射）
   ↓ sanitize_content_images 预检失败 → 子目录兜底也失败（marker 提取失败）→ 移除标签 → 图片消失
前端各自正则再次替换 ❌（路径格式与磁盘不符）
```

## 二、总体架构：三层单一事实来源

三大问题的共同根因是**前端/后端/磁盘/数据库四方各自维护一套逻辑，无单一权威**。方案核心收敛为三层"单一事实来源"：

| 权威层 | 收敛内容 | 覆盖问题 |
|--------|---------|---------|
| **解析引擎层** | 题号提取、选项/答案/解析、复合题识别、无关字段清洗 → 全部收敛到 `text_parser.py` + 新 `composite_matcher.py` | 问题1、问题2 |
| **图片管线层** | 图片压缩、md5 去重、无关图过滤、URL 规范化 → 全部收敛到 `image_service.py` + `image_filters.py` | 问题1、问题3 |
| **渲染契约层** | 后端统一输出规范 `<img>`，前端统一 `v-html` 渲染 → 新增共享渲染函数 | 问题2、问题3 |

**设计原则**：
1. **单一权威**：每类数据（题型/答案/图片路径/题组）只在一个地方定义与计算，其余地方只引用。
2. **存储量最小**：复合题不新增冗余表（复用 5 整数列）；图片 md5 去重 + 压缩，不存向量。
3. **稳定高效**：所有算法 O(n)/O(n log n)，无外部模型依赖（OCR 除外），判定失败不抛异常不阻塞主流程。
4. **向后兼容**：新增字段带默认值，灰度开关控制，存量数据平滑迁移。

## 三、问题1 详细方案：题目导入效率与异常定位

### 3.1 匹配率真实化

**目标**：前端不再显示"0% 假值"，后端未返回时显示"解析中/待匹配"。

**改动**：
- `.vtj/vue/question_import.vue`：
  - `separateMatchRate` 初始值由 `0` 改为 `null`（表示"未匹配"）。
  - 模板中匹配率显示处改为：`{{ state.separateMatchRate === null ? '—' : state.separateMatchRate + '%' }}`。
  - `importSummary.matchRate` 同样处理 null 态。

### 3.2 异常题结构化返回 + 前端"异常题清单"定位面板（核心）

**后端改动**（`question_import.py` 的 `batch_import_parsed`）：
1. `failed_items` 每项补充 `question_number` 字段（从 `q.get('question_number')` 或题干首题号提取），由 `{index, reason}` 升级为 `{index, question_number, reason}`。
2. 新增 `need_confirm_items: List[Dict]`，每项含 `{index, question_number, reason}`，reason ∈ `缺答案`/`缺解析`/`低置信度`（当前 `need_confirm` 仅计数，需逐题收集）。
3. 响应体新增两个结构化字段（保持原 `failed_items`/`need_confirm_count` 兼容）：

```json
{
  "failed_items": [{"index": 0, "question_number": "3", "reason": "..."}],
  "need_confirm_items": [
    {"index": 1, "question_number": "5", "reason": "缺答案"},
    {"index": 2, "question_number": "8", "reason": "缺解析"}
  ],
  "need_confirm_count": 2
}
```

**前端改动**（`.vtj/vue/question_import.vue`）：
1. 新增 state：`abnormalItems: []`（合并 failed_items + need_confirm_items，含定位信息）。
2. 导入完成弹窗（`importSummary` 区域）新增"异常题清单"可展开面板：
   - 每行显示：题号、异常类型（缺答案/缺解析/低置信度/格式异常/测试模板拒绝）、原因摘要。
   - **点击行 → `scrollIntoView` 滚动到对应题目卡片**（`parsedDocsQuestions[index]` 对应的 DOM ref），并高亮该卡片。
   - 提供"就地修正"入口：修正后触发单题重校验，从异常清单移除。
3. 保留 `need_confirm_count` 汇总提示，但不再用一闪而过的 `ElMessage.warning` 作为唯一手段。

**定位实现要点**：
- `parsedDocsQuestions` 列表渲染时，为每张题目卡片加 `:ref="'qcard_' + index"`。
- 点击异常行 → `this.$refs['qcard_' + idx]?.[0]?.scrollIntoView({behavior:'smooth', block:'center'})` + 临时高亮 class。

### 3.3 无关字段清洗统一收口

**目标**：UTB ID、内嵌大题号/材料头清洗收敛到后端单一函数，前端仅消费清洗结果。

**改动**：
- `text_parser.py` 新增/强化 `clean_question_content(content)` 作为唯一清洗入口，包含：
  1. UTB ID 剔除：`UTB[a-f0-9]{8,}[\s\-]?`；
  2. 内嵌分节头剔除（升级现有尾部锚定逻辑）：`^[一二三四五六七八九十]+、` 大题标题行、"根据以下…回答X-Y题"材料头句独立识别为材料头（不入题干，供问题2复合题识别使用）；
  3. 页码/水印/社交媒体推广文案剔除（复用 ContentCleaner）。
- 前端 `admin_questions.vue`/`teacher_questions.vue` 的 `cleanHtmlContent` 仅保留"展示兜底"，与后端清洗逻辑保持一致（后端为准）。

### 3.4 无关图过滤：实锤拦截 + 疑似标记人工复核

**目标**：公众号/收款/群二维码等无关图片不再静默混入，也不误删正常图表。

**改动**（`image_filters.py` + `question_import.py`）：
1. 明确分级语义（以代码为准核实）：
   - **实锤级**（自动拦截删除）：`qr_code`（QR 解码出内容）、`promo_banner`（黑名单 md5 命中）。
   - **疑似级**（标记、入人工复核队列，不自动删除）：`qr_pattern`、`promo_likely`、`qr_likely`、`tiny`、`extreme_ratio`、`blank`。
2. `_is_irrelevant_image` 返回值由 bool 升级为 `(decision, reason)`，decision ∈ `block`/`suspect`/`keep`：
   - `block`：实锤级 → 导入时跳过该图。
   - `suspect`：疑似级 → 图片照存，但题目记入 `need_confirm_items`（reason=`疑似无关图片: {原因}`），供前端异常清单人工复核。
   - `keep`：正常。
3. 存量清理脚本 `clean_irrelevant_images_v2.py` 同步升级分级语义，`--apply` 仅删 `block`，`--list-suspect` 列出疑似供人工。

## 四、问题2 详细方案：复合题识别与三端显示

### 4.1 复合题识别引擎增强（规则引擎 + 语义增强兜底）

**新增模块**：`backend/app/services/composite_matcher.py`（增量新代码，复用现有服务）。

**算法伪代码（三层）**：

```
def detect_composite_groups(questions: List[dict]) -> List[Group]:
    groups = []
    # 层1：规则引擎（显式标识，确定性最高）
    for q in questions:
        if _match_group_head_regex(q.content):        # 现有 _GROUP_HEAD_RE 扩展
            groups.append(_build_group_by_range(q))    # 题号范围 X-Y 挂组
            continue
        if _match_explicit_marker(q.content):          # 材料一/情境/阅读以下材料/给定资料
            groups.append(_build_group_material(q))

    # 层2：语义增强兜底（规则未命中的剩余题目）
    unclaimed = [q for q in questions if not q.grouped]
    groups += _semantic_grouping(unclaimed)

    # 层3：疑似标记（仍无法判断 → 人工确认）
    for q in questions:
        if not q.grouped and _looks_like_member(q):
            q.mark_suspect_group()
    return groups
```

**层1 规则引擎扩展**（扩展 `_GROUP_HEAD_RE` 单一正则 → 规则集）：

| 规则 | 匹配模式 | 示例 |
|------|---------|------|
| 题号范围 | `根据以下…回答\s*(\d+)\s*[-～~—－]\s*(\d+)题?` | 根据以下情境材料，回答71-73题 |
| 材料标识 | `材料[一二三四五六七八九十\d]+[：:]` | 材料一：某省公安厅… |
| 情境标识 | `根据以下情境`、`情境[：:]` | 根据以下情境 |
| 文章标识 | `阅读以下文章`、`给定资料` | 申论材料题 |

**层2 语义增强兜底**（落实方案 v1.1 §4.3，复用 `similarity.py`/`structure_matcher.py`，O(n)/O(n log n)，**不存向量**）：

| 策略 | 算法 | 复用 |
|------|------|------|
| A. 上下文继承检测 | 扫描小题题干含"上题/该材料/该情境/如上所述/据此"等指示词 → 向上追溯共享内容 | 新增（轻量关键词表） |
| B. 序列模式挖掘 | 连续题号区间 + 题型/分值分布相似（滑动窗口） | `extract_question_numbers` |
| C. 选项结构一致性 | 相邻题选项 TF-IDF 词频分布余弦相似度 > 阈值 | `similarity.calculate_cosine_similarity` |
| D. 文本相似度 | 题干 TF-IDF + 余弦相似度，结合题号连续判定合并 | `similarity.py` |
| E. 共享内容推测 | 从首题题干提取长句(>50字)或含"材料/情境"段落作为候选共享内容，标记待确认 | 新增 |

**综合决策**：层1 命中 → 直接成组；否则按 A→B→C→D 顺序逐策略尝试，任一命中即合并；全部未命中且 E 推测成立 → 标记"疑似题组"待人工。

**性能与存储**：
- 全部策略 O(n)/O(n log n)，万题耗时 < 1 秒；
- 不存储任何向量/中间特征，仅写 `QuestionBank` 的 5 个整数/短字符串列（group_id/parent_id/question_level/sort_order/question_number）；
- 识别结果缓存于进程内（文档级作用域，不落盘）。

### 4.2 存储最小化

复用现有数据层，**不新增冗余表**：
- `question_groups`（已存在）存共享内容与题组元数据；
- `question_bank` 的 5 列标记归属与排序（已存在）；
- `question_group_relations` 冗余表**不创建**（方案 v1.1 已标注"可选"，本项目放弃以省存储）。

### 4.3 三端统一题组聚合渲染

**后端**：`GET /group/{group_id}` 已存在（`questions.py:566-631`），补充：
- 返回字段增加 `members[].group_id`（便于前端定位）；
- 学生端随机/练习接口 `/random`、`/exercise/questions` 返回的题目增加 `group_id` 字段（当前 `/random` 已含，`/exercise/questions` 需核实补齐）。

**前端**（新增统一聚合渲染逻辑，替换散落平铺）：

| 端 | 页面 | 改动 |
|----|------|------|
| 学生端 | `answer_page.vue` | 按 group_id 聚合：共享材料可折叠展示，小题逐题作答，进度按题组计数 |
| 学生端 | `paper_answer.vue`、`smart_answer.vue`、`wrong_questions.vue` | 详情/答题时若 group_id>0，先渲染共享材料再渲染小题 |
| 管理员端 | `admin_questions.vue` | 列表平铺保留 group 徽标；详情弹窗按题组聚合渲染（复用 teacher 端已有模式） |
| 移动/平板 | `mobile_practice.vue`、`tablet_practice.vue` | 补齐 group 聚合渲染（材料折叠 + 小题作答） |
| 教师端 | `teacher_questions.vue` | 已有 group 徽标+详情弹窗，补充"材料内嵌图片"渲染（对齐问题3） |

**统一渲染组件**（新增 `src/utils/questionRender.ts` 或复用现有 render 函数）：
- `renderQuestionGroup(groupInfo, members, mode)`：mode ∈ `answer`(学生作答)/`detail`(查看)/`review`(复习)。
- 内部复用图片渲染函数（见问题3），保证材料图 + 小题图统一渲染。

## 五、问题3 详细方案：三端图片显示

### 5.1 统一 URL 规范（核心：修复四方路径矛盾）

**目标**：建立"占位符 → 磁盘文件名"的可逆映射，后端统一输出规范 `<img>`，前端放弃各自正则。

**关键修复**（`option_utils.py` + `question_import.py` + `image_service.py`）：

1. **占位符与磁盘名建立映射**：`_extract_and_save_images` 在保存图片时，记录 `{marker_key → 最终文件名}` 到 `QuestionImage` 表（已存在）或内存映射，使 `[IMAGE:uuid_qn_seq]` 能被反查到 `img_docx_{idx}_{md5}.png`。
2. **`render_image_placeholder` 改为带映射解析**：不再盲目拼 `/static/questions/{marker}.png`，而是：
   - 若 content 已是 `<img src="/static/questions/{qid}/img_docx_xxx.png">` → 直接透传（新数据已正确）；
   - 若 content 含 `[IMAGE:xxx]` 占位符 → 通过 QuestionImage 表 + 磁盘子目录反查真实文件名 → 输出 `/static/questions/{qid}/{真实文件名}`；
   - 若都失败 → 输出占位图 `/static/images/placeholder.png`（而非移除，避免题干信息丢失）。
3. **`sanitize_content_images` 兜底修复**：`_extract_marker_from_src` 正则兼容 `img_docx_{idx}_{md5}` 命名（放宽为 `img_docx_\d+_[a-f0-9]+`），使子目录兜底能命中。

**统一输出契约**（所有读路径）：`<img src="/static/questions/{qid}/{filename}" class="q-img" loading="lazy" onerror="this.onerror=null;this.src='/static/images/placeholder.png'" />`

### 5.2 压缩 + 去重 + 统一 URL（存储量最小）

**改动**（`image_service.py` 新增统一入库函数 `process_and_store_image`）：

```
def process_and_store_image(img_bytes, question_id) -> str:
    # 1. 无关图过滤（复用 image_filters 分级）
    # 2. md5 计算 → 查全局去重表（DB 表或内存 LRU），命中则复用既有路径
    # 3. 压缩：Pillow 打开 → 长边缩放至 ≤1200px → WebP/JPEG 质量 80 → 落盘
    # 4. 落盘路径 /static/questions/{qid}/img_docx_{idx}_{md5}.webp
    # 5. 返回规范 rel_path，写入 QuestionImage 表
```

- **压缩**：Pillow（已有依赖）`Image.thumbnail((1200,1200))`，输出 WebP(质量80) 或 JPEG(质量80)，对透明图回退 PNG。
- **去重**：md5 内容哈希，全局只存一份（跨题引用同一路径），存量脚本 `migrate_images.py` 升级为去重迁移。
- **统一 URL**：所有输出走 5.1 契约。
- **灰度开关**：config 新增 `IMAGE_COMPRESSION_ENABLED=True`（默认开）、`IMAGE_DEDUP_ENABLED=True`。

## 六、安全考量

| 风险 | 对策 |
|------|------|
| v-html XSS | 题目内容由后端受控导入，但前端统一渲染函数 `renderQuestionContent` 必须做白名单标签过滤（仅保留 `<img>/<p>/<br>/<b>/<strong>/<em>/<span>/<div>/<table>` 等安全标签，剥离 `<script>/<iframe>/onerror 以外的 on*` 事件属性），图片 `onerror` 仅允许兜底占位图 |
| 图片路径穿越 | `image_service._resolve_abs_path` 已有 `..` 过滤，`normalize_image_path` 也过滤 `..`，保持并覆盖新映射逻辑 |
| SSRF（URL 图片） | `question_import.py` 已有 URL 图片 SSRF 防护，保持 |
| OCR 子进程隔离 | MinerU/PaddleOCR 均走子进程 + 超时强杀，主进程零依赖加载，崩溃不拖垮后端 |
| 压缩图片内存 | Pillow 压缩需限制单图输入尺寸上限（已有 MAX_IMAGE_SIZE），防止解压炸弹 |
| 去重表 | 去重表只存 md5+路径，不存原图，防止敏感信息泄露；md5 不可逆 |
