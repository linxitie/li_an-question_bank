## §0 结论先行

1. **两张截图分属两个页面**，我先纠错：
   - 截图 1（`公安联考智能备考平台` + `海量题库，精准练习`）→ **平板登录页 `tablet_login.vue`**

3. **改动只有 1 行**，且落在路由守卫（`src/router/index.ts:616`），**不碰 R4 保护的 `device.ts`**。合并到主干后对所有人一致生效，不存在"只在我电脑好用"。

→ 截图 1 = `tablet_login.vue`；截图 2 = `login.vue`。两张都出现，说明同一台设备/两种状态下被判定了两次不同结果。

### 1.2 误判机制（`src/utils/device.ts:20-34`，**不改它**）

```ts
if (   /(ipad|tablet|android(?!.*mobi)|windows(?!.*phone)(.*touch))/.test(userAgent)
    || (screenWidth >= 768 && screenWidth <= 1024 && touchable) ) return 'tablet';
```

正则 `windows(?!.*phone)(.*touch)` 的含义：UA 含 `windows` 且后面出现 `touch` → 判平板。
→ 触摸屏笔记本、UA 带 `Touch` 的国产浏览器，在 1920 宽桌面上也会被判成平板。

实测（Playwright）：UA 追加 `Touch`、1440×900、无触摸 → `detectDevice()` 返回 `tablet` → `/#/login` 被重定向到 `/#/tablet/login`（与截图 1 完全一致）。

### 1.3 登录后为什么"变样"

`tablet_login.vue:242` → `router.push('/tablet/home')`：平板登录页登录完固定跳平板首页。

### 1.4 唯一消费方

只有路由守卫 `src/router/index.ts:595` 调用 `detectDevice()` 做跳转判断（`getHomePagePath/getLoginPagePath/getDevicePrefix` 无外部调用点）。

## §2 为什么 v1 的方案 A 被废弃（用户意见正确）

v1 提的「`?device=pc` + localStorage 记住」本质是**本地补丁**：

- 只对点过这个开关的那台浏览器生效；
- 合并回主干后，别人的电脑如果同样被误判，仍然会看到平板页；
- 排查时会多出"这台机器有覆盖值"的隐形状态，运维更难。

**结论：不做。**

---

## §3 选定方案：只改守卫的跳转条件（1 行）

### 3.1 改哪一行

`src/router/index.ts:614-621`：

```ts
// 现状
if (device !== 'pc') {                 // ← 平板、手机都换端
  const target = resolveDevicePath(to.path, device);
  if (target) return next({ path: target, replace: true });
}

// 改为
if (device === 'mobile') {             // ← 只有真手机换端；平板与电脑同页
  const target = resolveDevicePath(to.path, device);
  if (target) return next({ path: target, replace: true });
}
```

### 3.2 为什么这样写（逐条回答你要求的思考）

| 问题 | 回答 |
|---|---|
| 为什么改这里而不是 `device.ts` | `device.ts` 是 R4 红线（原文"原样保留"）。判定结果可以保留，**是否据此跳转**由守卫决定；改守卫既满足你的产品决定，又不碰保护文件 |
| 有什么好处 | 1 行、可读、可回滚；平板/电脑/手机三种情况一眼看懂；合并回主干后对所有人一致 |
| 安全问题 | 纯路由分支，无鉴权变化、无输入、无 XSS/注入面；`/tablet/*`、`/mobile/*` 的角色校验仍在分支 1，不受影响 |
| 运维便利 | 若将来要恢复"平板进平板版"，把 `=== 'mobile'` 改回 `!== 'pc'` 即可，语义明确；不需要清缓存/清 localStorage |
| 文件位置对不对 | 该判断本来就只存在于守卫里（唯一消费方），改这里就是改在"真正决定跳转的那一行" |
| 前端能显示出来吗 | 能：守卫在 `next()` 之前生效，跳转目标变化立即可见（验收 #1/#2 用浏览器实测） |
| 后端字段/路由/接口 | **完全不动**，无字段、无迁移、无新接口 |
| vtj 版本是否一致 | 不涉及 `.vtj` 页面与 DSL，无版本同步问题 |

### 3.3 不做什么

- ❌ 不改 `src/utils/device.ts`（R4），不改 `resolveDevicePath()` 的映射表
- ❌ 不加 localStorage / `?device=` 覆盖（v1 方案 A，已废弃）
- ❌ 不删 `/tablet/*` 的 7 个页面与路由（显式访问仍可用）
- ❌ 不动后端、数据库、接口
- ❌ 不动手机端映射（`/mobile/*` 行为完全不变）
