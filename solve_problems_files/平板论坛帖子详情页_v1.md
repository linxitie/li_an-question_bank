## 0. 结论先行

1. **新增一个平板专属详情页**：`src/views/student/tablet/tablet_forum_detail.vue`，把 `/tablet/forum/:id` 指向它。手机端 `mobile_forum_detail.vue` 原样不动。
2. **版式对齐 PC 详情**：顶部返回 + 页面标题，主体是一张居中宽卡片（`max-width: 920px`），自上而下为「标题 → 作者 → 正文 → 附件 → 互动数据 → 评论排序 → 评论列表 → 评论输入栏」。
3. **逻辑零复制**：帖子与评论全部走 `useCommunityStore`（`loadPost` / `loadComments` / `submitComment`），展示与交互复用 `src/components/forum/*`。新文件里只有布局和少量视图状态。
4. **不改后端、不改接口、不改手机端、不改任何 VTJ 页面**。
5. 本条需求与 **R12**（不为平板新建手机页的重复副本）存在取向冲突，已由用户明示指令覆盖；取舍理由见 §3.1。

## 2. 目标与非目标

### 2.1 目标

1. 平板点开帖子进入**独立整页**（URL `/tablet/forum/:id`，可直接刷新、可直接分享）。
2. 版式与信息密度对齐电脑端详情：居中宽卡片，而非手机单列拉伸。
3. 评论支持：真实头像、emoji、自定义表情包、图片、PDF 等文档、排序（时间/点赞/回复，正序/倒序）、点赞、回复、置顶、举报。
4. 手机端 `/mobile/forum/:id` 行为与外观零变化。
5. 与平板列表页视觉语言一致（同一套色板、圆角、阴影）。

### 2.2 非目标

- 不改造平板列表页 `.vtj/vue/tablet_forum.vue`（VTJ raw 页，R2/R3）。
- 不做「点击头像弹出用户卡片」——PC 的 `userProfile` 弹层不在本期范围，头像仅展示。
- 不做评论楼中楼分页、不做评论编辑、不做图片预览大图。
- 不改后端接口、不加数据库字段。
- 不合并 PC 与平板的详情实现（那是方案 B/C，已弃用）。

## 3. 方案（已选定 A）

### 3.1 选型与取舍

| 方案 | 做法 | 结论 |
|---|---|---|
| **A 新建平板详情页** | 新文件 + 路由改指向 | **选中** |
| B 手机页改响应式双布局 | `mobile_forum_detail.vue` 内按断点切两套模板/样式 | 弃：单文件膨胀到 1200+ 行，手机端回归风险，两套设计塞一个组件 |
| C 复用 PC 的 `forum.vue` | `/tablet/forum/:id` 指向 2096 行 raw VTJ 页，加路由参数驱动弹层 | 弃：详情是叠在列表上的 modal，要改内部状态机；且 PC 三栏列表会被带到平板 |

**关于 R12**：R12 的初衷是「同一份逻辑不要维护两遍」。方案 A 复制的是**布局**，业务逻辑（请求、分页、排序、提交、举报、置顶）全部留在 `store` 与 `src/components/forum/*`，新页面只有模板和样式。平板详情页本来就需要与手机不同的信息密度，用同一套手机模板无法表达。用户已明确要求「平板该有自己的详情页」，按 AGENTS.md「用户明示指令优先」执行，并在此留痕。

### 3.2 文件与路由改动

| 文件 | 动作 |
|---|---|
| `src/views/student/tablet/tablet_forum_detail.vue` | **新增**（预计 420–520 行：模板 ~170、脚本 ~150、样式 ~180） |
| `src/router/index.ts:410-413` | 改 `component` 指向新文件；`path`/`name`/`meta.platform` 保持不变 |
| `mobile_forum_detail.vue` | 不动 |
| 后端 | 不动 |

路由改完后的形态：

```ts
{
  path: '/tablet/forum/:id',
  name: 'TabletForumDetail',
  component: () => import('@/views/student/tablet/tablet_forum_detail.vue'),
  meta: { platform: 'tablet' }
}
```

### 3.3 页面结构（自上而下）

```
.page                    整页，min-height:100vh，背景 #F5F7FA
├─ header.topbar         高 56px，白底 + 底部 1px 分隔
│   ├─ button.back-btn   ← 返回：history.length>1 ? router.back() : router.push('/tablet/forum')
│   └─ h1.title          帖子详情
└─ main.content          内边距 24px，内容居中
    └─ article.card      max-width 920px；白底、圆角 12px、轻阴影
        ├─ header.post-head
        │   ├─ h2.post-title（支持标题色，取自 post.titleColor）
        │   ├─ UserBadge size="md" + 昵称 + 发帖时间
        │   └─ 置顶/精华 徽标
        ├─ section.post-body     ForumContent 渲染正文
        ├─ AttachmentList mode="post"
        ├─ footer.post-stats     点赞（可点）/ 评论数 / 浏览数
        ├─ section.comments
        │   ├─ 行内标题「评论 (n)」+ CommentSortBar（左排序、右正序/倒序）
        │   ├─ 加载态 / 空态 / 失败态
        │   └─ 评论列表（两层：根评论 + 其下回复）
        │       └─ 每条：UserBadge sm + 昵称 + 时间 + 正文 + AttachmentList mode="comment"
        │                + 点赞 / 回复 / 置顶 / 举报
        └─ footer.composer     卡片底部，非固定；吸底在 920px 卡片内
            ├─ 回复提示条（replyTo 时出现，可取消）
            ├─ FileUploader v-model="commentImages" :max-docs="3"
            ├─ EmojiStickerPicker（showPicker 时展开）
            ├─ button.emoji-btn 😊
            ├─ input.comment-input
            └─ button.send-btn 发送
```

评论输入栏**吸在卡片底部**（`position: sticky; bottom: 0`），不是整页底部——这是与手机版最大的体感差异：在平板上不用滑到页面末尾才能发评论。

### 3.4 复用清单（不自建）

| 资源 | 用途 |
|---|---|
| `useCommunityStore` | `detail` / `comments` / `loadPost` / `loadComments` / `submitComment` / `reactToPost` / `reactToComment` |
| `UserBadge.vue` | 帖子作者与评论者头像（`avatar-only` + `size`） |
| `FileUploader.vue` | 评论图片与文档（`max-docs=3`，含 pdf/doc/xls/ppt/zip/rar/7z） |
| `EmojiStickerPicker.vue` | emoji + 自定义表情包，选择后写入 `commentText`（表情包写 `[[sticker:url]]`） |
| `CommentSortBar.vue` | 时间/点赞/回复 + 正序/倒序 |
| `ForumContent.vue` | 正文与评论文本渲染（含 sticker / 图片标记解析） |
| `AttachmentList.vue` | 帖子与评论附件展示与下载 |
| `pinForumComment` / `reportForumTarget` | 评论置顶、举报（与手机端同一套 API） |
| `avatarInitial` | 仅在 `<img>` 失败时由 `UserBadge` 内部回退，本页不重复实现 |

### 3.5 与手机版的差异

| 维度 | 手机版（现状） | 平板版（新） |
|---|---|---|
| 布局 | 单列，左右 12px 内边距 | 居中 920px 卡片，页边距 24px |
| 输入栏 | 页面流末端（实测 top≈2014px） | 卡片底部 sticky，始终可见 |
| 评论缩进 | 每层固定缩进 | 根评论 0，回复缩进 32px + 左侧细线 |
| 字号 | 13–14px | 14–16px，标题 22px |
| 返回 | 顶部 ←，回 `/mobile/forum` | 顶部 ←，回 `/tablet/forum` |
| 功能 | emoji/表情包/图片/文件/排序/置顶/举报 | **完全一致** |

### 3.6 边界与异常

| 场景 | 处理 |
|---|---|
| `route.params.id` 非数字 / ≤0 | 显示「帖子不存在或已被删除」+ 返回按钮 |
| 帖子 404 | 同上，不使用 `store.error` 原文（避免后端文案外泄） |
| 评论为空 | 「暂无评论，抢个沙发」 |
| 评论加载失败 | 行内错误提示 + 「重试」按钮（再次 `loadComments`） |
| 未登录点发送 | 与手机端一致：`store.submitComment` 抛错后 `ElMessage.warning('请先登录')`，输入内容不丢 |
| 上传失败 | `FileUploader` 自行提示，已成功的附件保留 |
| 超长正文 | `ForumContent` 内 `word-break: break-word`，卡片不横向溢出 |
| 平板横竖屏 | 卡片宽度自适应，最小 768px 起；≤767px 不属于本页范围（路由由 device 映射保证） |

## 4. 验收标准

必须在 **`http://10.201.3.21:9527/#/tablet/forum/4`** 上验证：

1. 页面为整页宽卡片（卡片左右有留白，非贴边单列），顶部有返回按钮与「帖子详情」标题。
2. 评论头像渲染为**图片**（`img.naturalWidth > 0`），不是文字回退。
3. 点击 😊 展开面板，能选 emoji 插入输入框；能选自定义表情包（写入 `[[sticker:...]]`）。
4. 点「+ 图片 / 文件」能选图片和 PDF，发送后评论下方出现附件并可下载。
5. 排序切换（时间/点赞/回复 + 正序/倒序）后列表顺序变化。
6. 未登录时发送给出登录提示；登录后发送成功且列表即时出现新评论。
7. `/mobile/forum/4` 外观与行为与改动前一致。
8. `npm run typecheck` 无新增错误（只统计本次改动文件）；`npx vitest run src/components/forum` 全绿。

## 6. 风险、回滚与未决

| # | 风险 | 影响 | 对策 |
|---|---|---|---|
| 1 | **「头像显示汉字」在真实平板复现，但本机四种方式均不复现** | 新页面可能同样回退成汉字 | 新页沿用同一 `UserBadge`；验收时必须真机确认。若仍复现，另开排查（设备侧缓存/旧 SW 嫌疑最大），不在本期硬修 |
| 2 | R12 精神冲突 | 未来 PC 详情改版需同步两处 | 逻辑全在 store + 共享组件，只有布局需同步；在文档中记录该债 |
| 3 | 平板横向空间大，评论内容过长 | 行宽过宽影响阅读 | 卡片 `max-width: 920px` 并设 `line-height: 1.7` 约束行宽 |
| 4 | 新增页面未覆盖移动端尺寸 | 误在手机宽访问时布局崩 | 路由 meta 已限 `platform: 'tablet'`；`device.ts` 对本机不映射手机；样式加 `min-width` 兜底 |
| 5 | 真机交互（触屏点击区域） | emoji 面板/上传按钮点不中 | 点击区域 ≥40×40，`@click` 不用 `@click.stop` 阻断冒泡 |

**回滚**：`git revert` 提交 #2 即恢复手机页复用，无数据迁移、无接口变更、无状态残留。

**未决**：评论输入栏吸底方式用 `sticky` 还是独立固定条，实施时按真机滚动手感微调，不影响验收标准。
