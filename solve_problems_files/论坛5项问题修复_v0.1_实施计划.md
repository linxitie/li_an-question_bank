# 论坛 5 项问题修复实施计划 v0.1

> 状态：**待用户审批，未执行**
> 日期：2026-10-22
> 分支：`feat/forum-personalization`（用户确认保留现分支）
> 范围：PC / 手机 / 平板论坛的 5 项问题
> 约束：不新增转发/分享功能；不改 `.vtj` 模板；不做 WebSocket 实时推送

---

## 1. 目标

1. PC 端能显示手机端快捷表情的反应明细（脚本层文本摘要）。
2. 移除手机/平板内置模拟帖，三端只展示真实数据。
3. 手机端表情/表情包能正常发送（含失败提示）。
4. 手机端点击帖子进入详情；帖子不存在时给出明确提示，不再只剩评论栏。
5. 手机详情页评论支持按时间、点赞、回复数排序，支持正序/倒序。
6. PC 论坛允许游客浏览；发帖、评论、点赞仍要求登录。

## 2. 已确认决策

| 决策 | 结论 |
|---|---|
| PC 论坛访问 | 允许游客浏览；写操作要求登录 |
| 排序口径 | 评论：时间 / 点赞 / 回复数；帖子：时间 / 点赞 / 评论数 / 浏览数 |
| PC 表情明细 | **Script-only 文本摘要**，不改模板 |
| 分支 | 保持 `feat/forum-personalization` |

## 3. 现状与根因

### 3.1 架构

- PC `/forum` → `.vtj/vue/forum.vue` + `src/modules/community/store.ts`；PC 路由守卫当前强制登录。
- 手机 `/mobile/forum` → `.vtj/vue/mobile_forum.vue`；发帖/详情为手写页 `src/views/student/mobile/mobile_forum_create.vue`、`mobile_forum_detail.vue`。
- 平板 `/tablet/forum` → `.vtj/vue/tablet_forum.vue`；创建/详情复用手机手写页。
- 后端 `backend/app/api/v1/community/forum.py`：列表/详情公开；发帖/评论/反应需登录；反应写 `forum_like.reaction_code`，同步 `like_count`；表情包走 `forum_sticker`。
- 数据流：`/api/forum/posts` → `_serialize_post` → PC `community` store → `_mapPost` → 模板；手机列表直接 `fetch` 后映射。

### 3.2 根因表

|---|---|---|---|
| 1 | 手机快捷表情 PC 看不到 | PC 不轮询/不刷新；`_mapPost` 丢弃 `reactions/myReaction`；模板只渲染星标+总数 | `.vtj/vue/forum.vue:875-892`、`:50-56`、`:516-526` |
| 2 | 只有手机显示“模拟帖”，PC 空白 | 手机列表硬编码 5 条模拟帖，仅接口非空才替换；PC 无 mock；PC 未登录被守卫跳登录 | `mobile_forum.vue:161-237`、`:257`；`tablet_forum.vue:285`；`router/index.ts:604-620` |

## 4. 方案总览

### 4.1 PC 游客浏览

- 在 `src/router/index.ts` 的 PC 守卫中，把 `/forum` 加入公开路径白名单。
- PC 论坛 `mounted` 只在已登录时加载“我的帖子”；`loadStats` 公开，正常加载。
- 发帖/评论/点赞仍由现有 `isLoggedIn()` 检查拦截，未登录提示“请先登录”。
- 旧 token（缺 `user_type`）会被 `isLoggedIn()` 判为未登录；游客可浏览，写操作需重新登录。

### 4.2 移除模拟帖

- `mobile_forum.vue`：`posts` 初始值改为 `[]`；删除 5 条 mock；接口成功时**始终**用返回数组替换（空数组也替换）；失败时清空。
- `tablet_forum.vue`：同样删除 4 条 mock，始终替换。
- 现有 `v-if="filteredPosts.length === 0"` 空状态会自然生效，无需改模板。

### 4.3 详情页 404/空状态

- `mobile_forum_detail.vue` 增加 `loading`、`loadError`。
- `store.loadPost()` 返回 `null` 时显示“帖子不存在或已删除”+“返回列表”。
- 评论区和底部评论栏只在 `post` 存在时渲染。
- 删除成功后仍按现有逻辑返回列表。

### 4.4 评论排序

- 后端 `GET /api/forum/posts/{post_id}/comments` 增加：
  - `sort_by=time|likes|replies`，默认 `time`
  - `order=asc|desc`，默认 `asc`（保持旧行为）
- 评论 `replies` 排序按“直接子评论数（status=1）”降/升序；并列按 `create_time desc`。
- 点赞排序按 `like_count`；并列按 `create_time desc`。
- 返回结果增加 `replyCount` 字段（可选，前端展示/调试用）。
- 手机详情页新增排序条：`时间` / `点赞` / `回复` + `倒序/正序`；默认“时间 + 倒序”。
- 子评论固定按时间正序展示，避免楼中楼顺序混乱。
- 本轮不实现 PC 端排序 UI（`.vtj` 模板受限）；后端/API 先支持，供后续设计器加控件。

### 4.5 帖子列表排序（后端先行）

- `GET /api/forum/posts` 增加：
  - `sort_by=time|likes|comments|views`，默认 `time`
  - `order=asc|desc`，默认 `desc`
- 置顶帖始终优先；其余按所选字段排序，并列按 `create_time desc`。
- 本轮不改 PC/手机列表模板，因此不新增列表排序 UI；API 与前端类型先就绪。

### 4.6 PC 表情文本摘要

不改模板，复用现有 `{{ post.likeCount }}` 位置：

- 新增纯函数 `src/modules/community/reactions.ts`：
  - 固定顺序：`like 👍`、`love ❤️`、`haha 😂`、`wow 😮`、`sad 😢`、`angry 😡`
  - `formatReactionSummary({like:1,love:2})` → `👍1 ❤️2`
  - 无反应 → `''`
- `.vtj/vue/forum.vue` 的 `_mapPost(p, withSummary)`：
  - 保持 `reactionTotal = p.likeCount` 供排序
  - `reactions = p.reactions || {}`
  - `myReaction = p.myReaction || null`
  - `likeCount = withSummary && summary ? summary : (p.likeCount ?? 0)`
- 列表 `loadPosts` 与详情 `loadDetail` 传 `withSummary=true`；`loadMyPosts` 保持数字，避免“❤️ 👍1”重复。
- `hotPosts` 排序改用 `reactionTotal`。
- `toggleLike` 使用接口返回的 `reactions` 重新生成摘要：
  `post.reactions = data.reactions; post.likeCount = formatReactionSummary(data.reactions) || data.likeCount;`
- 样式层给 `.meta-likes` 加 `white-space: nowrap`，防止摘要换行（只改 `<style>`，不改模板）。

### 4.7 PC 自动刷新

- `mounted` 启动 15 秒轮询（仅 `document.hidden === false` 时请求），并监听 `focus`、`visibilitychange`。
- 轮询调用 `loadPosts(true)`（静默模式，不显示 loading、不弹错误 toast）。
- `beforeUnmount` 清理定时器和监听器。
- 效果：手机端反应后，PC 最迟 15 秒或切回窗口时更新总数/摘要。

### 4.8 手机表情发送

- 已实测发布链路可用；本轮只做防御性修复：
  - `submitPost` 在 `store.createPost()` 返回 `null` 时显示 `store.error || '发布失败'`，不再静默 return。
  - 错误提示后滚动到顶部，确保用户看到“请输入标题/请先登录/发布失败”。
  - 评论发送失败时同样显示错误（当前只 `console.error`）。
- 不改变表情插入逻辑；不新增发送按钮。

## 5. 详细改动

### 5.1 后端 `backend/app/api/v1/community/forum.py`

1. 导入 `Literal`、`aliased`。
2. `get_forum_posts` 增加 `sort_by`、`order` 参数：
   ```python
   sort_by: Literal["time", "likes", "comments", "views"] = Query("time")
   order: Literal["asc", "desc"] = Query("desc")
   ```
   - 置顶优先：`ForumPost.is_top.desc()`
   - 主排序字段映射：`time→create_time`、`likes→like_count`、`comments→comment_count`、`views→view_count`
   - 并列：`ForumPost.create_time.desc()`
3. `get_post_comments` 增加 `sort_by`、`order`：
   ```python
   sort_by: Literal["time", "likes", "replies"] = Query("time")
   order: Literal["asc", "desc"] = Query("asc")
   ```
   - 用 `aliased(ForumComment)` + 相关子查询计算 `reply_count`
   - `replies` 排序使用子查询；`likes` 使用 `like_count`；`time` 使用 `create_time`
   - 并列 `create_time.desc()`
4. `_serialize_comment` 增加 `reply_count: int = 0`，返回 `replyCount`。
5. 不新增数据库字段，不做迁移。

### 5.2 前端 API / Store

- `src/modules/community/api.ts`

  - `ForumCommentItem` 增加 `replyCount?: number`
  - `fetchForumPosts` 支持 `sortBy`、`order`，映射为 `sort_by`、`order`
  - `fetchForumComments` 支持 `sortBy`、`order`
- `src/modules/community/store.ts`
  - `loadComments(postId, options?: { sortBy?: ForumCommentSortBy; order?: ForumSortOrder })`

### 5.3 PC `.vtj/vue/forum.vue`（仅 `<script>` + `<style>`）

## 6. API 契约

### 6.1 帖子列表

```
GET /api/forum/posts?sort_by=time|likes|comments|views&order=asc|desc&limit=20&offset=0
```

- 默认：`sort_by=time&order=desc`
- 置顶帖始终在最前
- 响应结构不变

### 6.2 评论列表

```
GET /api/forum/posts/{post_id}/comments?sort_by=time|likes|replies&order=asc|desc&limit=200&offset=0
```

- 默认：`sort_by=time&order=asc`（保持旧行为）
- 响应评论项新增 `replyCount`（整数）

## 7. 排序语义

| 对象 | sort_by | 排序字段 | 并列规则 |
|---|---|---|---|
| 帖子 | time | `create_time` | `create_time desc` |
| 帖子 | likes | `like_count` | `create_time desc` |
| 帖子 | comments | `comment_count` | `create_time desc` |
| 帖子 | views | `view_count` | `create_time desc` |
| 评论 | time | `create_time` | 无 |
| 评论 | likes | `like_count` | `create_time desc` |
| 评论 | replies | 直接子评论数 | `create_time desc` |

## 9. 风险与回滚

| 风险 | 处理 |
|---|---|
| `.vtj` 脚本改动影响设计器同步 | 只改 `<script>`/`<style>`，不改模板；按 R3 先 dry-run；改完请用户在设计器打开确认 |
| `likeCount` 变字符串影响排序 | 新增 `reactionTotal` 专门用于排序；`hotPosts` 全部改用 `reactionTotal` |
| 轮询导致请求过多 | 仅页面可见时 15 秒一次；focus/visibility 触发；`beforeUnmount` 清理 |
| 评论排序子查询性能 | 单帖评论量有限；按 `post_id` 过滤；后续量大再加索引/缓存 |
| PC 游客看到“我的帖子”空卡片 | 可接受；后续可用设计器隐藏，本轮不改模板 |
| 旧 token 未登录 | 游客可浏览；写操作提示重新登录，不强制跳转 |

回滚：
- 后端：revert `forum.py` 排序参数与 `replyCount`。
- 前端：revert 对应文件；无数据库迁移，无需回滚数据。
- 文档：保留归档，不删除。
