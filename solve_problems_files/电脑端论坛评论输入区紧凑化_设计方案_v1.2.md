## 0. 结论先行

1. 目标是把现在这个「表情按钮一行 / 上传框一行 / 输入框三行 / 按钮一行」的四层堆叠，压成**两行**：输入框一行，控件一行（或控件贴右）。
2. **可以纯 CSS 实现，不改 `<template>`**：靠 flex 的 `order` 重排（DOM 里控件本来就在输入框前后，顺序可调），再用 `:deep()` 把子组件 `FileUploader` 里那个 76×76 的虚线上传框缩成 36×36 的「+」圆形按钮。
3. 顺带把「支持 emoji 与自定义表情包」这行提示文字隐藏（占一行宽度、信息价值低）。
4. 风险集中在 `:deep()` 依赖子组件类名（`.fu-add`）：子组件改版会导致样式失效，但不会报错，只是回到大按钮。已在 §7 记录。

## 2. 目标布局

### 方案 A（推荐）：输入框在上，控件一行贴右下

```
┌────────────────────────────────────────────────────┐
│ 回复 @闲者 ×                                       │
│ ┌────────────────────────────────────────────────┐ │
│ │ 写下你的评论...                                │ │  44px 高
│ └────────────────────────────────────────────────┘ │
│ [😊] [＋]  [缩略图][pdf]          [关闭] [发表评论] │
└────────────────────────────────────────────────────┘
```

- 输入框单行 44px（可上下拖动改高，默认不拖）
- 左：😊、＋（上传）
- 右：关闭、发表评论
- 已选附件缩略图缩到 40×40，跟在 ＋ 后面
- 整块高度 ≈ 44 + 36 + 间距 ≈ **100px**，比现在矮约 200px

### 方案 B：控件竖排在输入框右侧

```
┌──────────────────────────────┬───────────────┐
│ ┌──────────────────────────┐ │ [😊]   [＋]   │
│ │ 写下你的评论...          │ │               │
│ └──────────────────────────┘ │ [关闭][发表]  │
└──────────────────────────────┴───────────────┘
```

- 输入框占左侧 ~420px，右侧 250px 放控件
- 缺点：680px 卡片宽度下，右侧要塞 4 个控件很挤；回复提示条与缩略图没有位置
- 结论：**不推荐**，除非你更在意纵向再省 40px

## 3. 实现方式（纯 CSS，不改 template）

### 3.1 重排：flex + order

DOM 顺序是 `toolbar → image-upload → textarea → actions`，用 `order` 把 textarea 提到第一行：

```css
.comment-input-area {
  display: flex;
  flex-wrap: wrap;
  align-items: center;
  gap: 8px;
}
.comment-input-area textarea {
  order: 1;
  flex: 0 0 100%;      /* 独占一行 */
  height: 44px;
  min-height: 44px;
  max-height: 160px;
  resize: vertical;     /* 需要长文本时仍可手动拉高 */
  padding: 10px 12px;
}
.comment-toolbar { order: 2; margin: 0; }
.comment-image-upload { order: 3; margin: 0; }
.comment-input-area .modal-actions { order: 4; margin: 0 0 0 auto; }
```

> `.modal-actions` 是发帖弹窗共用的类，因此选择器必须带 `.comment-input-area` 前缀，避免波及发帖弹窗。

### 3.2 隐藏提示文字

```css
.comment-toolbar-tip { display: none; }
```

### 3.3 上传框缩成「＋」

```css
/* FileUploader 内部元素，需用 :deep() 穿透 scoped */
.comment-input-area :deep(.fu-add) {
  width: 36px;
  height: 36px;
  padding: 0;
  border-radius: 50%;
  font-size: 0;              /* 藏掉文字，只留伪元素 */
}
.comment-input-area :deep(.fu-add::before) {
  content: '+';
  font-size: 20px;
  line-height: 1;
  color: #1a2b5f;
}
/* 文字改为视觉隐藏而非删除：读屏仍能念出「+ 图片 / 文件」 */
.comment-input-area :deep(.fu-add span) {
  position: absolute;
  width: 1px;
  height: 1px;
  overflow: hidden;
  clip: rect(0 0 0 0);
  white-space: nowrap;
}
.comment-input-area :deep(.fu-thumb) {
  width: 40px;
  height: 40px;
}
.comment-input-area :deep(.fu-doc) {
  max-width: 140px;
  padding: 6px 8px;
  font-size: 12px;
}
```

### 3.4 按钮瘦身

```css
.comment-input-area .cancel-btn,
.comment-input-area .confirm-btn {
  padding: 8px 16px;
  font-size: 13px;
}
```

## 4. 为什么这样写（决策依据）

| 问题 | 回答 |
|---|---|
| 为什么用 `order` 而不是改 DOM | 改 DOM 要动 `.vtj` 的 `<template>`，触发 R3（必须你在设计器操作）。`order` 只影响视觉顺序，DOM、事件、无障碍树顺序不变 |
| 为什么用 `:deep()` | `FileUploader` 的样式带 scoped 作用域，父组件无法直接覆盖；`:deep()` 是 Vue 官方提供的穿透方式 |
| 有没有副作用 | `.modal-actions` 与发帖弹窗共用，已用 `.comment-input-area` 前缀隔离；`.fu-add` 同类元素只在 FileUploader 内 |
| 会不会影响手机/平板 | 不会。那两端用的是 `mobile_forum_detail.vue` 与 `tablet_forum_detail.vue`，不走这个类 |
| 读屏可用性 | 「+」靠伪元素生成，但原文字用视觉隐藏保留在无障碍树里，读屏仍念「+ 图片 / 文件」 |
| 后续运维 | 全部集中在 `.comment-input-area` 一段注释块内，改动可定位；若 FileUploader 改版导致样式失效，表现是回到 76px 大框，不会坏功能 |

## 5. 安全考量

- 不新增任何 HTML/JS，无 XSS 面。
- 不改上传逻辑、白名单、大小限制。
- 不改变 `submitComment` 的附件收集路径（`state.newCommentImages`）。
- 不引入外部字体/图片。

## 7. 风险

| # | 风险 | 影响 | 对策 |
|---|---|---|---|
| 1 | `:deep()` 依赖子组件类名 | FileUploader 改版后样式失效，退回大按钮 | 在 `FileUploader.vue` 顶部加一行注释说明这些类被父组件依赖 |
| 2 | `order` 与未来新增控件冲突 | 新控件若未指定 order 会排到最后 | 注释里写明 order 语义（1 输入 / 2 表情 / 3 上传 / 4 按钮） |
| 3 | textarea 变矮后长文本不便 | 输入体验 | 保留 `resize: vertical`，用户可拖高；`max-height: 160px` |
| 4 | 缩略图 40px 看不清 | 附件识别 | 悬停时 `title` 仍显示文件名；需要可直接改回 56px |
