OpenCode 高效 AI 工作流规范（公安联考题库系统专用）
本规范为强制性执行标准，所有 AI 交互必须严格遵循。
目的：杜绝 AI 破坏系统、执行卡顿、偷工减料、子代理零调用等问题，确保高效、稳定、高质量地完成公安联考题库系统的设计与开发。

一、总则
规划与执行必须分离：任何非平凡任务（非错别字修改），必须先由规划 Agent 生成完整计划，经人工审核后，再由执行 Agent 按计划实施。

禁止通用 Agent 直接写业务代码：通用 Agent 仅用于问答、探索、简单修改，不得直接参与核心模块开发。

强制验证：每一步执行后必须进行验证（运行测试、LSP 诊断、人工审查 Git 差异），未通过验证不得进入下一步。

人工审核不可跳过：计划必须经人工确认；执行后的变更必须经人工审查。

三、标准工作流程（强制步骤）
步骤 1：需求澄清与规划（使用 Prometheus）
触发方式：在 OpenCode 中按 Tab 切换至 Prometheus 模式，或输入 @plan <需求描述>。

操作：

输入详细需求，例如：@plan 为公安联考题库系统设计金币购功能模块。
认真回答 Prometheus 的提问，直至其生成一份完整的实施计划文件。
检查计划文件内容，确保包含：任务目标、详细步骤、涉及文件、验收标准、风险点。
步骤 2：人工审核计划
必须逐条审核计划，确认：

步骤是否合理，有无遗漏或多余操作。

是否明确修改范围，避免波及无关模块。

验收标准是否可量化、可验证。

若计划不满足要求，立即要求 Prometheus 修改，直至满意。

步骤 3：执行计划（使用 Atlas）
触发方式：输入 /start-work 命令，Atlas 自动接管。

操作：

Atlas 会将任务委托给子 Agent（前端、后端、数据库等），并强制验证每一步。

执行过程中，禁止手动干预，除非出现卡死或严重错误。

监督：通过日志（%USERPROFILE%\.local\share\opencode\log）观察进度，若卡住按第五节处理。

步骤 4：人工审查变更
审查内容：

使用 git diff 查看所有代码改动。

确认改动符合计划，未引入意外破坏。

运行测试套件，确保功能正常。

若发现问题：立即回滚，并要求 Prometheus 重新规划，或由 Atlas 修正。

步骤 5：验证与交付
所有验收标准通过后，方可合并代码。

记录本次任务的计划文件、变更摘要、测试报告，归档至项目文档。

五、故障排查指南
5.1 子代理零调用
原因：委托模型（delegation.model）与主模型（model.default）不兼容。

解决：在 opencode.json 中，将委托模型设置为与主模型一致，排除 API 端点错误。

5.2 执行卡住不动
检查日志：%USERPROFILE%\.local\share\opencode\log。

禁用所有插件：临时在 opencode.json 中设置 "plugins": []，重启后观察是否恢复。

清除缓存：删除 %USERPROFILE%\.cache\opencode 目录，重启 OpenCode。

5.3 偷工减料 / 破坏系统
预防：强制使用 Prometheus 规划，禁止通用 Agent 直接写核心代码。

发现后：立即回滚，重新执行规划流程，并在计划中增加“验证步骤”。

5.4 执行效果不达预期
检查计划是否足够详细，验收标准是否明确。

要求 Prometheus 重新规划，并在计划中加入“人工审核点”。

六、禁止事项与最佳实践
禁止事项
❌ 禁止跳过规划直接让 AI 写核心代码。

❌ 禁止在未审核计划的情况下执行 /start-work。

❌ 禁止让默认 Agent 修改路由、数据库 schema、核心业务逻辑。

❌ 禁止在未运行测试的情况下合并代码。

最佳实践
✅ 每次任务开始前，先执行 @plan。

✅ 计划文件必须包含“验收标准”和“风险点”。

✅ 执行后必须进行 git diff 审查和测试。

✅ 定期清理 OpenCode 缓存和日志。

✅ 将本规范保存为项目根目录的 OPENCODE_WORKFLOW.md，每次启动 OpenCode 时自动加载。
